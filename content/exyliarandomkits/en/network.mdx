## A network group

Servers of one network share arenas, profiles, leaderboards, events and seasons when they write the
same `network-group`. One event runs at a time on the whole group, one server closes each season, and every
reward is paid once wherever the player is.

<Steps>
  <Step title="One group">
    The same `network-group` in `config.yml` on every server: lower case letters, digits and underscores, at
    most 24. Blank, the default, keeps the plain tables.
  </Step>
  <Step title="One database">
    `database.yml` on every server points at **one** MySQL, MariaDB, PostgreSQL or MongoDB database. The
    group prefixes the tables (`<group>_exyliarandomkits_arenas`), so several groups can share one database.
  </Step>
  <Step title="Redis">
    Redis enabled in that same `database.yml` on every server, with the same Redis and `key-prefix`, and a
    **different `server-id` on each server**, so an edit on one server reaches the others at once. See
    [ExyliaLib's database](/docs/exylialib/database).
  </Step>
</Steps>

Arenas are built on each server that runs them: their schematics are local. `items.yml` and `rarities.yml` are files on each server, so keep them the same where lives should roll alike. A player's arena stay never
travels either: what they carried is given back on the server they left it on.

<Callout type="warning" title="Rows written before the group">
Setting a group on a server that already has arenas and profiles in the plain tables starts the group from
empty tables. The old rows stay where they are.
</Callout>

## Balancing players

RandomKits servers are dedicated and automatic. Arenas and player data are shared across the network group,
so a second RandomKits server only needs the same `network-group`. When a server already holds `capacity`
players in its arena, a player who joins it is sent to the least full or best server of the group instead
(overflow). Each server publishes its players on a heartbeat.

<Steps>
  <Step title="ExyliaProxyUtils">
    [ExyliaProxyUtils](/docs/exyliaproxyutils/introduction) on the proxy, with the proxy's server names
    **equal to the backends' `server-id`s**.
  </Step>
  <Step title="balancing in config.yml">
    `balancing.enabled` (on by default), a `mode` and a `capacity`.
  </Step>
</Steps>

| Key | Default | What it does |
|---|---|---|
| `balancing.enabled` | `true` | Sends players between the servers of the group. Off: this server takes everyone who joins it. |
| `balancing.mode` | `FILL_FIRST` | `FILL_FIRST` puts a player on the fullest server still below its capacity, so fights stay dense; `LEAST_PLAYERS` on the emptiest. |
| `balancing.capacity` | `60` | Players this server takes in its arena before the next ones are sent elsewhere. `0` or lower never sends anyone. |

- Capacity is a preference, not a wall: when no server has room, the player joins here.
- A player already in the arena, or combat tagged, is not sent.
- The profile is saved before the move, so the server they land on reads it current.
- `%exyliarandomkits_network_players%`, `%exyliarandomkits_network_players_<arena>%` and
  `%exyliarandomkits_instances%` read the group from the last heartbeats. See
  [Placeholders](/docs/exyliarandomkits/placeholders#the-network-group).

## ExyliaDuels

With [ExyliaDuels](/docs/exyliaduels/introduction) on the same server, its challenge screen offers a
**Random kit**: both players get the same set of items, rolled once from the duel's seed and `items.yml`, each in their own saved
layout, **without upgrades, perks or luck**. In ExyliaDuels its node is `exyliaduels.kit.randomkits:random`
(it follows `exyliaduels.kit.*` while unset), and its arena flags and rules are set in `/duelsadmin` → **Kits**.

| Key | Default | What it does |
|---|---|---|
| `duels.enabled` | `true` | Offers the Random kit in the challenge screen. |

The roll is the same piece-by-piece roll as a life (see [Items and rarities](/docs/exyliarandomkits/kits)), with no luck,
bad luck protection or perks. The option is not shown when `items.yml` has no categories. For network duels RandomKits must also run on the duel
arena server, in the same group; where it does not, the option is not shown.
