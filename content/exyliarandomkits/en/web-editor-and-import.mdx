Instead of opening files on the server, you can change RandomKits from a web page: the item pool, rarities, rewards, progression, perks, missions, events and seasons, each as a form built from the file's own comments. At the end of this page you have opened a session, saved a change and seen it apply without a reload.

## Before you start

You need `exyliarandomkits.admin`, and ExyliaLib's web editor must be set up on the server. How a session works (the link, the code, applying) is explained once in [ExyliaLib's web editor](/docs/exylialib/web-editor).

## Steps

<Steps>
  <Step title="Get the link">
    Run `/rkadmin editor`. You can also open `/rkadmin` and click **Items**, or run `/exylialib editor ExyliaRandomKitsCore`. The server sends you a link to the editor on this plugin.
  </Step>
  <Step title="Pick what to edit">
    Choose a subject from the list (see the table below), for example **Items** to change the item pool.
  </Step>
  <Step title="Change it and save">
    Edit the form. The editor checks the values and gives you a code for the change.
  </Step>
  <Step title="Apply it">
    Run `/exylialib editor apply <code>` in game. It writes the change and refreshes what reads it, with no `/rkadmin reload`.
  </Step>
</Steps>

## Check that it works

Ask for the same value in game. For an **Items** change, run `/rk` and take a new life: `items.yml` is read on every roll, so the change reaches the next life. For perks, events and seasons the apply step rebuilds them: perks are reloaded and events and seasons are rescheduled.

## What you can edit

| Subject | What can be edited |
|---|---|
| **Arena** | The roll mode, spawn protection, reset interval, and the upgrades and perks switches of the server's arena. |
| **Settings** | `config.yml`. |
| **Items** | `items.yml`: the categories, their item lines and the rarity of every enchantment level. |
| **Rarities**, **Triggers**, **Progression**, **Perks**, **Missions**, **Events**, **Seasons** | `rarities.yml`, `triggers.yml`, `progression.yml`, `perks.yml`, `missions.yml`, `events.yml` and `seasons.yml`, each drawn as a form from its comments. |
| Messages and menus | Offered by ExyliaLib's discovery. See [Messages and languages](/docs/exylialib/messages-and-languages) and [Edit menus](/docs/exylialib/edit-menus). |

<Callout type="note" title="Arenas are not created here">
The editor can change the settings of the arena but can neither create nor delete one: its regions and spawns are placed in game, with `/rkadmin setup`. See [Arenas](/docs/exyliarandomkits/arenas). Spawn protection goes from 0 to 3600 seconds.
</Callout>

<Details title="Changes that wait for confirm">

Some fields can run commands as the console or widen what players may do, so the editor holds them until you confirm:

- `allowed-commands` in **Settings**, the commands players may run inside an arena.
- A reward or perk that runs a console command: `command` in **Triggers**, in the per-arena trigger overrides, in the **Perks** effects, in **Missions** rewards, and in the **Seasons** rewards.

Confirm a held change as ExyliaLib's page describes. Edits to anything else apply as soon as you run `apply`.

</Details>

## Settings in game

`/rkadmin` then **Settings** edits the values an admin tunes while the server runs, on six hand-made pages, without opening a file. Each page has a short explanation on every card.

| Page | What it holds |
|---|---|
| **Playing** | The server's arena, the Random kit in ExyliaDuels, the draft size, wait and display. |
| **Deaths and arenas** | What a death drops and for how long, and the void margin. |
| **Kills and rivals** | The assist share and damage window, the streak that counts as ended, the nemesis and rivals tracked. |
| **Arenas** | Spawn protection, placed blocks, safe box containers, the PvP box and safe box flags, and the TNT and creeper fuses with their countdown. |
| **Anti-abuse** | The same-address check, the repeat limit and window, fresh spawns and AFK victims. |
| **Stats and balancing** | How often stats save, the leaderboard refresh and size, and the balancing mode and server capacity. |

A click edits a value (numbers and durations are typed in chat); shift-right-click puts the default back. Everything else stays in `config.yml` or the web editor. See [Configuration](/docs/exyliarandomkits/configuration) for the keys behind each page.
