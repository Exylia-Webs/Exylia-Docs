An **event** is a while of something different in the arena, announced to everyone with a boss bar counting down. A **season** is a stretch of weeks with its own leaderboards and rewards for the top players. At the end of this page you can start an event, put one on a timetable, and decide how and when seasons end.

## Before you start

You need `exyliarandomkits.admin`. Events live in `events.yml` and seasons in `seasons.yml`, both in `plugins/ExyliaRandomKitsCore/`. You can edit them on disk (then run `/rkadmin reload`) or in the [web editor](/docs/exyliarandomkits/web-editor-and-import), which applies the change by itself. Times are written `30s`, `5m` or `1h30m`.

One event runs at a time on the whole [network group](/docs/exyliarandomkits/network): a timetable that fires on several servers starts it once, and every server shows the same one.

## Steps

Start an event now to see what it does.

<Steps>
  <Step title="Pick an event">
    The bundled ones are `rarity_rush`, `double_rewards`, `king`, `mythic_hunt`, `mirror`, `gold_rush` and `bloodlust`. Type `/rkadmin event start ` and press Tab to list the ids in your `events.yml`.
  </Step>
  <Step title="Start it">
    Run `/rkadmin event start <id>`, for example `/rkadmin event start double_rewards`. It is refused while another event runs.
  </Step>
  <Step title="Look at it">
    Run `/rkadmin event status` for what runs and what is next. Players see the running or next event in the `/rk` hub, in the **Event** button.
  </Step>
  <Step title="Stop it early">
    Run `/rkadmin event stop`, or `/rkadmin event stop <id>` to stop only that one.
  </Step>
</Steps>

## Check that it works

Everyone in the arena gets the announcement and a boss bar with the time left. Run `/rkadmin event status`: it names the event, its time left and the next one. With PlaceholderAPI, `%exyliarandomkits_event_active%` turns `true`; see [Placeholders](/docs/exyliarandomkits/placeholders).

## The event types

| Type | What happens | Bundled event |
|---|---|---|
| `RARITY_RUSH` | Each rarity's weight is multiplied by the numbers you write, for every piece and enchantment a life rolls. `0` takes a rarity out. | **Rarity Rush**: no commons, rares halved, epics x2, legendaries and mythics x3. 15 minutes. |
| `MULTIPLIER` | The money and XP earned in the arena are multiplied. | **Double Rewards**: x2, 30 minutes, every Saturday and Sunday at 20:00. |
| `KING_OF_THE_ARENA` | Most kills during the event wins. The live top is in the event placeholders. | **King of the Arena**: 15 minutes, Fridays at 21:00 with at least 4 players online. |
| `MYTHIC_HUNT` | One player per server is marked and glows for the others. Their killer takes the bounty and the mark. | **Mythic Hunt**: 15 minutes. |
| `MIRROR` | Every new life gets the same loadout, drawn with the `rarities` you set and changed every 5 minutes. No rerolls. | **Mirror**: commons and rares out. 15 minutes. |
| `GOLD_RUSH` | Each kill scatters gold nuggets worth `multiplier` money in all. Picking them up pays through the event's win reward (see below). | **Gold Rush**: 60 money per kill, 15 minutes. |
| `BLOODLUST` | No natural regeneration, and a kill heals the killer to full. Potions and golden apples still heal. | **Bloodlust**: 10 minutes. |

## Schedule an event

Give an event a timetable and it starts by itself.

<Steps>
  <Step title="Open the event">
    In `events.yml`, find the event under `events`, such as `king`.
  </Step>
  <Step title="Set the times and days">
    Under `schedule`, write `times` such as `20:00` (24 hours) and `days` such as `FRIDAY`. An empty `days` is every day. `min-players` is how many players must be online on that server for it to start.
  </Step>
  <Step title="Reload">
    Run `/rkadmin reload`.
  </Step>
</Steps>

```yaml
events:
  king:
    type: KING_OF_THE_ARENA
    duration: 15m
    schedule:
      times: ['21:00']
      days: [FRIDAY]
      min-players: 4
```

A time or day that cannot be read is skipped and the console says which one.

## Rotate events on their own

With `rotation.enabled: true` the events in `rotation.events` start one after another, an `interval` apart, counted from the end of one event to the start of the next. It is off by default.

When an event ends, the players online get three events as chat buttons and vote for 30 seconds on which one is next (`/rk vote <number>`; voting again changes the vote). The most voted goes next. If nobody votes, the rotation keeps its order. The vote needs at least two other events in the rotation, and the event that just ended is not offered.

<Details title="Every key of events.yml">

`events` maps an event id to:

| Key | What it does |
|---|---|
| `name` | How it is called in messages, the boss bar and menus. Blank takes the name of the language file (`lang/<code>/content.yml`, `events.<id>`). |
| `type` | One of the seven types above. |
| `duration` | How long it lasts. |
| `arenas` | The arena ids it runs in. Empty is every arena (there is one arena per server). |
| `icon` | Its item in menus. |
| `rarities` | `RARITY_RUSH` and `MIRROR`: rarity id to weight multiplier. |
| `multiplier` | `MULTIPLIER`: what money and XP are multiplied by. `GOLD_RUSH`: the money one kill scatters. |
| `schedule.times` | Times it starts at, like `20:00`. |
| `schedule.days` | Days, like `FRIDAY`. Empty is every day. |
| `schedule.min-players` | Players that must be online on this server for it to start. |

The rotation:

| Key | Default | What it does |
|---|---|---|
| `rotation.enabled` | `false` | Starts the listed events one after another. |
| `rotation.interval` | `45m` | From the end of one event to the start of the next. |
| `rotation.events` | the seven bundled ids | The events, in order. |
| `rotation.min-players` | `4` | Players that must be online on the server that starts it. |

On a network each server counts the votes of its own players, and the last server to close its vote decides.

</Details>

## Rewards

The plugin pays event rewards from `triggers.yml`, as ExyliaLib rewards, by event id (see [Configuration](/docs/exyliarandomkits/configuration#rewards-triggersyml)):

- `on-event-start-<id>` runs for everyone in the event's arenas when it starts.
- `on-event-win-<id>` runs for the king when `KING_OF_THE_ARENA` ends, for the hunter on every `MYTHIC_HUNT` bounty, and for the player who picks up gold in `GOLD_RUSH`.

```yaml
triggers:
  on-event-win-king:
    - type: ECONOMY
      amount: '5000'
  on-event-win-gold_rush:
    - type: ECONOMY
      amount: '%money%'
```

The bundled `triggers.yml` pays nothing for events, so `gold_rush` gives no money until you add the second block above (`%money%` is the value of the nuggets picked up). The king's rewards are owed once and paid wherever the player is, now or on their next join. The king needs at least one kill to be crowned.

## Seasons

A season has its own kills, deaths, best streak, KDR and XP, its own leaderboards (`/rk season`, or `/season`) and rewards by final rank, paid **exactly once** wherever the player is. Lifetime records are never touched. One server of the network group closes a season and opens the next, and every server shows the same one. Seasons are on by default and roll on their own: each lasts 30 days.

### Set the length and the ranking

<Steps>
  <Step title="Open seasons.yml">
    Find `length` for how long each season lasts, and `rank-by` for what the final ranking counts.
  </Step>
  <Step title="Choose what ranks players">
    `rank-by` is `season_kills` (default), `season_kdr`, `season_best_streak` or `season_xp`.
  </Step>
  <Step title="Set the prizes">
    `rewards` pays by final position, `from` to `to` inclusive, with the same rewards as `triggers.yml`. By default 1st gets 5000 money, 2nd to 3rd 2500, 4th to 10th 1000 and 11th to 100th 250.
  </Step>
  <Step title="Reload">
    Run `/rkadmin reload`.
  </Step>
</Steps>

### Use fixed dates instead

To run seasons with a start and an end, list them under `seasons`, written `yyyy-MM-dd HH:mm` in `timezone`. When none of them covers the moment and `length` is above `0s`, seasons roll on their own again.

```yaml
seasons:
  - id: winter
    name: Winter Season
    start: '2026-12-01 00:00'
    end: '2027-03-01 00:00'
timezone: Europe/Madrid
```

### Open and close a season by hand

| Command | What it does |
|---|---|
| `/rkadmin season status` | The season now, its number and its time left. |
| `/rkadmin season start` | Opens a season now, when none is open. |
| `/rkadmin season end` | Closes the season now and pays its rewards. A rolling season is followed by the next at once. |

### What players see

In the `/rk` hub, the **Season** button opens the season screen: its name and time left, its board by kills, KDR, best streak or XP, and an **Archive** button with the past seasons and their final tops.

<Details title="Every key of seasons.yml">

| Key | Default | What it does |
|---|---|---|
| `enabled` | `true` | Seasons on or off. |
| `name` | blank | The name of a rolling season. `%number%` is its number. Blank takes the language file (`Season %number%`). |
| `length` | `30d` | How long a rolling season lasts. |
| `seasons` | none | Fixed windows: `id`, `name`, `start`, `end`. |
| `timezone` | blank | The zone the fixed windows are written in, such as `Europe/Madrid`. Blank is the server's. |
| `rank-by` | `season_kills` | `season_kills`, `season_kdr`, `season_best_streak` or `season_xp`. |
| `rewards` | the four brackets above | By final position. |
| `archive` | `12` | Past seasons kept in the archive. |

</Details>
