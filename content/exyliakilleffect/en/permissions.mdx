## The nodes

| Permission | Grants |
|---|---|
| `exyliakilleffect.command.killeffect` | `/killeffect`, the inventory menu and the [3D selector](/docs/exyliakilleffect/3d-selector). Default: everyone. |
| `exyliakilleffect.admin` | Every subcommand of `/killeffectsadmin`, the admin hub and its settings. Default: op. |
| `exyliakilleffect.effect.<id>` | One effect, by its id in lowercase. Default: op. |
| `exyliakilleffect.effect.*` | Every effect. Default: op. |
| `exyliakilleffect.category.<id>` | Every effect in that category. Default: op. |
| `exyliakilleffect.tier.<id>` | Every effect of that rarity. Default: op. |

### Player features

Each one is held by everybody by default. Deny it to the default group and grant it to a rank, and the
feature becomes a perk of that rank. A player without the node is told so with `feature-locked`.

| Permission | Grants |
|---|---|
| `exyliakilleffect.preview` | Watching an effect on the preview stage, from the menu, the command or the API. |
| `exyliakilleffect.random` | Turning on the random choice: a different effect on every kill. |
| `exyliakilleffect.favourites` | Starring effects and opening the favourites tab. |
| `exyliakilleffect.visibility` | Choosing whose kill effect particles they see. |
| `exyliakilleffect.buy` | Buying effects in the shop. Without it, prices are not shown at all. |
| `exyliakilleffect.crate` | Opening the crate: the menu button, `/killeffect crate` and a bound crate block. |
| `exyliakilleffect.crate.max.<n>` | Opening up to `<n>` crates in one go instead of `crate.max-at-once`. The highest one held wins, seven at most. Not held by default. |

Taking an effect off, turning random off, unstarring and emptying the favourites never need a node, so
a rank that lapses never traps a player in a choice they cannot undo.

```text
/lp group default permission set exyliakilleffect.random false
/lp group vip     permission set exyliakilleffect.random true
/lp group vip     permission set exyliakilleffect.crate.max.7 true
```

An effect is granted if **any** of the four effect nodes applies: its own, the wildcard, its
category's or its rarity's. A permission is only one way of owning one — the others are winning it
out of [the crate](/docs/exyliakilleffect/crate) or buying it from the menu's
[shop](/docs/exyliakilleffect/configuration#shop), both written to the player's row instead.

## The id is the node

There is no `permission` key in `effects.yml`. The node is derived from the key, lowercased:

```text
GRIDDY       →  exyliakilleffect.effect.griddy
meme         →  exyliakilleffect.category.meme
legendary    →  exyliakilleffect.tier.legendary
```

Case is not part of it, so recapitalising a key changes nothing. Renaming one changes everything: it
is a different node, and everybody who had the old one loses the effect.

## Selling it

```text
/lp group default permission set exyliakilleffect.command.killeffect true
/lp group vip     permission set exyliakilleffect.category.meme true
/lp group mvp     permission set exyliakilleffect.effect.griddy true
/lp group elite   permission set exyliakilleffect.tier.legendary true
/lp group legend  permission set exyliakilleffect.effect.* true
```

Five categories and four rarities are what make those nodes worth selling: "every Meme effect" or
"every legendary" is one line instead of twenty.

<Callout type="tip" title="Give the menu away">
Without `exyliakilleffect.command.killeffect` the catalogue cannot be opened at all. A player who
cannot see what is for sale cannot want it.
</Callout>

## What the node is checked for

<Steps>
  <Step title="Wearing">
    Choosing an effect in the menu without its node, an unlock from the crate or a purchase is refused
    with `no-permission`. There is no switch to turn this off.
  </Step>
  <Step title="Playing what the menu chose">
    The choice is re-checked at the moment of the kill. One that no longer holds is taken off there
    and then, rather than left sitting in the menu until the next relog.
  </Step>
  <Step title="Being drawn">
    `behaviour.hide-without-permission` decides whether a locked effect is hidden in the menu or shown
    locked. Either way it can be previewed, and on the favourites tab it is always shown.
  </Step>
</Steps>

<Callout type="note" title="Tokens and weapons are never checked">
A token is a real item: it is bought, traded and lost like any other, and holding one is the proof.
Binding it asks for no node, and a bound weapon plays its effect for whoever is holding it — which is
the point of an effect you can trade. Permissions govern what a player wears out of the menu, not what
they carry in their hands.
</Callout>
