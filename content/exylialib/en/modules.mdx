Every module is reached the same way: a static class named after it, usually with an `of(plugin)`
handing back a view that belongs to your plugin.

## Foundations

| Module | Entry point | What it is for |
|---|---|---|
| Task | `Tasks.of(plugin)` | Scheduling that runs on Spigot, Paper and Folia from one call. |
| Config | `Configs.define(plugin, name, type)` | YAML files declared and read as Java records. |
| Text | `Text.of(string)` | Every player-facing string, into Adventure components. |
| Placeholders | `Placeholders.group(plugin, prefix)` | One registry for `%placeholders%`, with or without PlaceholderAPI. |
| Formats | `Formats`, `Amounts` | Numbers, money, percentages and dates a player reads — and amounts a player types. |
| Debug | `Debug.of(plugin)` | Coloured console output, with a server-wide switch. |
| Reloading | `Reloads.of(plugin)` | Named reload steps with contained failures, plus library-reload listeners. |
| Modules | `PluginModules.of(plugin, switches)` | [Switchable parts of a plugin](#plugin-modules), each with its own files, listeners, actions, menus, commands and timers. |
| Metrics | `Metrics.describe(plugin, details)` | How a plugin's setup is described to stats.exylia.net. See [Metrics](/docs/exylialib/library-config#metrics). |
| Web editor | `WebEditor.of(plugin)` | [Editing a plugin's files from the browser](/docs/exylialib/web-editor). |
| Logs | `Logs.of(plugin)` | A staff audit log every plugin records into, read with [`/exylialib logs`](/docs/exylialib/commands#staff-log). |

## Storage

| Module | Entry point | What it is for |
|---|---|---|
| Database | `Databases.of(plugin)` | Records in H2, MySQL, MariaDB, PostgreSQL or MongoDB. |
| Transfer | `Transfers.of(plugin)` | A plugin's whole database out to one file and back. |
| Redis | configuration | A shared cache that makes one database look the same from every server. |
| Snapshots | `Snapshots.of(plugin)` | A player's state kept for later, in memory or stored. |
| Proxy | `Proxy.request(module, payload)` | Talking to ExyliaProxyUtils on Velocity or BungeeCord, and every request answered. |

## Interfaces

| Module | Entry point | What it is for |
|---|---|---|
| Menus | `Menus.of(plugin)` | Menus written in configuration: lists, templates, conditions, live values. |
| Items | `Items.of(plugin)` | Items described in configuration, read once and drawn per player. |
| Actions | `Actions.of(plugin, namespace)` | Compiled, namespaced actions shared by menus and items. |
| Input | `Inputs.of(plugin)` | Asking a player for text, numbers, choices or a whole form. |
| Editors | `Editors.of(plugin)` | Screens for editing the lists a plugin configures. |
| Wizards | `Wizards.of(plugin)` | Walking a player through several questions, applied only on confirm. |
| Previews | `Previews.of(plugin)` | Showing one player an effect against an empty sky. |
| Heads | `Heads.browse(inputs, …)` | The decorative head catalogue, searchable from a menu, a page at a time. |
| Interactions | `Interactions.compile(plugin, lines)` | What clicking something in the world does: lines with click filters, commands and effect tokens. |
| Tuner | `Tuner.of(plugin, subject)` | Fine adjustment with the mouse wheel, with a boss-bar HUD and a live preview. |
| Settings | `Settings.register(plugin, setting)` | Player preferences every plugin registers into, and the one `/settings` screen. |
| Toasts | `Toasts.send(player, icon, title, frame)` | The advancement popup in the corner, with a configurable fallback. |
| Notices | `Notices.of(plugin)` | Messages left for a player: shown now, across the network, or on their next join. |
| Discord webhooks | `Webhooks.of(plugin)` | Messages to Discord written in config, with escaped values and rate limits. |

## Not a module

| Class | What it is |
|---|---|
| `net.exylia.lib.ExyliaLib` | The plugin itself: lifecycle and cleanup, nothing else. |
| `net.exylia.lib.platform.Platform` | `current()`, `isFolia()`, `isPaper()`. |
| `net.exylia.lib.api.practicebot.PracticeBots` | In the public API artifact: a bridge to the training-bot plugin, `get()` and `available()`. Empty when it is absent. |
| `net.exylia.lib.internal.*` | Internal. Free to change without notice. |
| Cleanup | No API: `plugins/ExyliaLib/cleanup.yml`. The server's `logs/` folder swept of files older than `keep-days`, a minute after startup and every six hours. |

## Reloading

```java
Reloads.of(this)
        .step("configs", () -> { settings.reload(); menus.reload(); })
        .step("arenas", () -> arenas.load())
        .run(sender);
```

Each step reports for itself: one that throws is named in the console and the sender is told how many
succeeded. A half-reloaded plugin that says nothing is worse than one that names what failed.

The `Reloads` a plugin declared last is also what runs after `/exylialib updates apply` or the
[web editor](/docs/exylialib/web-editor) writes one of its files, so the change is live without a manual
reload. Declare it once, in a field, rather than building it inside the reload command.

```java
Reloads.onLibraryReload(this, () -> menus.reload());
```

The library's own `/exylialib reload` fires that listener. The palette changing is the usual reason to
want it: every compiled menu is holding last week's colours until it is read again.

## Plugin modules

A plugin made of parts a server owner switches on and off. Each part has its own files, listeners,
actions, menus, commands and timers, and a part that is off costs nothing.

```java
modules = PluginModules.of(this, id -> settings.get().modules().switchOf(id));
modules.register(new MarketModule());
modules.register(new AuctionsModule());          // requiredModules() returns ["market"]
modules.registerActions(actions);                // before the menus are compiled
menus.load(modules.menuIds());
modules.commandHandlers().forEach(lamp::register);
modules.loadOnlinePlayers(Bukkit.getOnlinePlayers());
modules.startTimers();
```

```java
public final class AuctionsModule extends PluginModule {
    public AuctionsModule() { super("auctions"); }

    @Override protected List<String> requiredModules() { return List.of("market"); }
    @Override protected void registerConfigs() { config("modules/auctions/config", AuctionsConfig.class).load(); }
    @Override protected void onEnable() { manager = new AuctionManager(); }
    @Override protected void onDisable() { if (manager != null) manager.shutdown(); }
    @Override protected List<Object> commandHandlers() { return List.of(new AuctionsCommand()); }
    @Override protected void timers() { timer(20L, 20L, () -> manager.sweep()); }
}
```

| | |
|---|---|
| **A switch is read at startup** | A module whose id has no switch in the config stays off and is reported, so a misspelt key never fails silently. A switch changed later is only reported by `pendingRestart()`. |
| **Requirements** | `requiredPlugins()` and `requiredModules()` keep a module off, with a console line, while what it needs is missing. |
| **One module never takes the others down** | A module that throws while enabling has its new listeners removed, gets its own `onDisable`, and stays off; the rest still start. |
| **Lookups answer only for running modules** | `getModule(id)` and `isEnabled(id)` are empty for a module that is off, missing a requirement or failed. |
| **Reload** | `reloadConfigs()` reloads every running module, each on its own. `reload(id)` reloads one module in place — for an in-game editor that changed one module's settings. |
| **Commands** | `commandHandlers()` returns plain handler objects for the plugin to register with its own Lamp. `registerCommands(lamp)` is deprecated. |

On disable, `disableAll()` disables the running modules in reverse order.

## Debug output

```java
Debug debug = Debug.of(this);

debug.success("Configs loaded");
debug.warn("Arena 'main' has no schematic");
debug.error("Could not reach the database", failure);
debug.debug("Session drained: " + entries);      // only when debug is on
```

`Debug.all(true)` turns debug lines on for every plugin at once, which is the switch to reach for when
reproducing something rather than editing each plugin's config.
