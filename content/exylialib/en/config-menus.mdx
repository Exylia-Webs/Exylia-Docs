---
title: "In-game settings"
description: "Change every plugin's settings and content catalogues from a menu with /exylialib config, with no code in the plugin."
---

`/exylialib config` opens every Exylia plugin's settings as screens, drawn from the same records the
[web editor](/docs/exylialib/web-editor) edits. The plugin writes no menu code. Players only: the console is
pointed at `/exylialib editor`.

| Command | Opens |
|---|---|
| `/exylialib config` | The plugins with settings. |
| `/exylialib config <plugin>` | One plugin's settings: its only file straight away, or the list of its files. |

Clicking needs `exylialib.config` (op by default).

## The screens

1. **Plugins**: one book per plugin, marked *Problems* when its files hold any.
2. **A plugin's files**: one card per settings file and content file. Skipped with a single file.
3. **A file's pages**: one card per page, showing its first four values live. Skipped with a single page.
4. **A page**: one button per key; a nested section is a button opening its own page.

Without annotations a file is grouped the way it is written: root keys on a **General** card, each section on
a card of its own, each map or list of entries on a card that opens the list.

## Which files

Every settings file of an enabled Exylia plugin that is not a translation, is not covered by a web editor
subject and was not excluded by the plugin. Messages and menus are not shown. Content catalogues a plugin
registers with `WebEditor.of(plugin).yaml(id, path)` follow, each with its own checker that refuses only what
the plugin would not load.

## For plugin developers

A plugin can add a *Settings* button to its own admin hub and keep BACK pointing at it:

```java
ConfigMenus.of(plugin)
        .permission("myplugin.admin")   // may edit its files, besides exylialib.config
        .back(hub::open)
        .open(player);
```

Optional `Menu` annotations on the record give labels, ranges and formats. The list of every plugin always
needs `exylialib.config`.
