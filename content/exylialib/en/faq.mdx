## A plugin will not load, saying ExyliaLib is missing

Exylia plugins list ExyliaLib under `softdepend`, so they still start without it: they download
`ExyliaLib.jar` into `plugins/` and ask for a restart. Restart once and both load. If the download
cannot happen (no internet access), put `ExyliaLib.jar` in `plugins/` yourself. There is no shaded
fallback on purpose: one installed copy is the whole design.

## ExyliaLib itself will not load

It needs **PacketEvents** next to it: the library lists it under `depend`, so the server refuses to load
ExyliaLib — and every Exylia plugin with it — without it. On the very first start it also downloads its
libraries from Maven Central; a server with no internet access fails there.

## How do I change the language?

`language` in `plugins/ExyliaLib/config.yml`: `en`, `es`, `pt`, `fr`, `ru` or `tr`. Every plugin whose own
`language` is `default` follows it. See [Languages](/docs/exylialib/library-config#languages).

## An update was downloaded but nothing changed

Updates are staged in `plugins/update/` and applied on the next restart, never on a reload: every plugin is
bound to the running copy of the library. `/exylialib` shows whether auto-update is on, and
`/exylialib plugins` lists what is waiting.

## How do I stop the library from sending metrics?

`metrics.enabled: false` in `plugins/ExyliaLib/config.yml`, then restart. Nothing is sent afterwards. See
[what is reported](/docs/exylialib/library-config#metrics).

## My placeholder shows on screen instead of resolving

Three usual causes:

1. Nothing registered that name — `Placeholders.unresolved(text)` lists what did not answer.
2. The name is right but the **prefix** is not: the registered name is the group prefix, an underscore
   and the entry name.
3. Reading it through PlaceholderAPI, where the plugin's own name is the identifier in front.

## A value shows `{highlight}` as text instead of colouring

You used `with()`, which is deliberate: it inserts the value as literal text. `withFormatted()` is for
values a server owner wrote. Getting it backwards the other way lets a player named `<rainbow>`
recolour your message.

## A colour placeholder in an item name does nothing

`name: "%name_color%&l%kit_name%"` cannot work. Substitution happens on the parsed component tree — a
bare colour parses to an empty component carrying a colour, and that colour does not reach the text
beside it. Pass the whole coloured phrase, or use a named template per state.

## The menu will not open at all

Most often a `size` that disagrees with the `type`. A barrel is always twenty-seven slots whatever
`size` says, and creating an inventory whose size disagrees with its type throws before anything is
drawn.

## A button does nothing

Check the console from when the file loaded: an action that does not exist compiles into a dead button
and a reported line, and the rest of the menu still works. Also check the slot's `condition` — a slot
whose condition fails is not there at all.

## My config edits were wiped after an update

An update never rewrites a value you changed: a new default for a key you never touched waits in
[`/exylialib updates`](/docs/exylialib/library-config#changed-defaults) until you apply or keep it.

What can still go is a key no record declares any more: it is pruned on load and reported as
`UNKNOWN_KEY`. If a section was reshaped between versions, it needed a migration — `Migration.rename` or
`Configs.moveTo` moves a value rather than letting the default replace it.

## `/exylialib updates` lists changes I never made

They are defaults the plugin's authors changed, on keys still at their old default. Apply them if you
want the new value, keep them if you prefer the old one; either way they are not listed again.

## Everything crashes on Folia

Almost always a task on the wrong thread. Anything about a player belongs to `runAtEntity`; `run` is
for the server as a whole. It is invisible on Paper and fatal on Folia.

## A database call returns but my code runs on the wrong thread

Futures complete on a pool thread. Come back through `tasks.runAtEntity(player, …)` before touching
the player or the world.

## Two plugins fight over the same player

They should be using [`Sessions`](/docs/exylialib/players#one-player-one-activity). `isFree` asks,
`claim` decides atomically, and the release callback is how the current holder is told to let go.

## The clan API answers nothing

`Clans.isSupported()` is `false` when no clan plugin was detected. Detection is by reflection, so a
plugin that is installed but whose API cannot be reached is skipped with a console warning — that line
also names whichever one was picked.

## A module does nothing

Modules that lean on another plugin have an `isSupported()` and, where it makes sense, an
`unsupportedReason()`: clans need a clan plugin, client waypoints need Lunar or Feather, combat tags need
DeluxeCombat or PvPManager. They do nothing rather than throwing, which is worth checking for rather than
assuming. Schematics work without FastAsyncWorldEdit, through the library's own engine.

## The embedded database says it is damaged or read only

The embedded H2 file is checked at startup, repaired from its last good state or from a backup when it is
damaged, and backed up automatically into `backups/` next to it. A database that turns read only while the
server runs — usually a full disk or a folder the server cannot write — prints one line and needs a
restart. See [Database](/docs/exylialib/database).
