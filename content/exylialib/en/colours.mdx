Every Exylia plugin paints its messages, menus, scoreboards and holograms from one shared palette. Change a colour once and all your Exylia plugins follow, with no restart.

ExyliaLib is the library every Exylia plugin installs. The palette lives in its folder, `plugins/ExyliaLib/`, so one edit there applies to every Exylia plugin on the server (ExyliaFFA, ExyliaMines and the rest).

## Change your theme colour

<Steps>
  <Step title="Open the palette file">
    Open `plugins/ExyliaLib/colors.yml`. It is created the first time the server starts, with a comment above each colour.
  </Step>
  <Step title="Change the colours you want">
    Replace the value of `primary` (the main colour) and, to keep it looking tidy, `secondary` and `secondary-light`. Write each value as a hex colour in quotes:

    ```yaml title="plugins/ExyliaLib/colors.yml"
    primary: '#2ec4b6'
    secondary: '#5fd8cc'
    secondary-light: '#8ee6dd'
    ```
  </Step>
  <Step title="Reload">
    Save the file and run `/exylialib reload` in game or in the console (permission `exylialib.admin`). Scoreboards, holograms, boss bars and menu items repaint at once.
  </Step>
</Steps>

<Callout type="tip" title="Prefer clicking to editing?">
`/exylialib setup` opens a short setup in game with five ready-made colour themes and the server address. Pick one and it writes `colors.yml` for you. See [Setup wizard](/docs/exylialib/setup-wizard).
</Callout>

## Check that it works

Open any Exylia menu, for example `/ffaadmin` with ExyliaFFA, or look at a scoreboard. Titles and item names should now use your colour. If nothing changed, see "If a colour does not change" below.

## The palette

Each colour is a role, not just a shade. Messages say "success green" rather than a hex code, so changing the role changes every place it is used.

| Name in `colors.yml` | Used for | Default |
|---|---|---|
| `primary` | Titles, item names, key words. The main brand colour. | `#8a51c4` |
| `secondary`, `secondary-light` | Section labels and softer emphasis. | `#aa76de`, `#b48fd9` |
| `letters` | Body text. | `#e7cfff` |
| `letters-black` | Muted body text, lore guides, separators. | `#a89ab5` |
| `success`, `success-light` | Something worked. | `#8fffc1`, `#a1ffc3` |
| `error`, `error-light` | Something went wrong. | `#a33b53`, `#d4617d` |
| `warning`, `warning-light` | Caution, or something that needs attention. | `#ff9500`, `#ffd2a8` |
| `info`, `info-light` | Neutral information. | `#59a4ff`, `#7db7ff` |
| `accent` | Rare highlights. | `#ff6b9d` |
| `highlight` | Important values inside a sentence. | `#ffd700` |
| `neutral`, `muted` | Disabled or unimportant text. | `#6c757d`, `#868e96` |
| `server-ip` | Your server address (not a colour). | `exylia.net` |

<Callout type="note" title="Keep success, error, warning and info recognisable">
Players read green as "it worked" and red as "it failed". Recolour `primary` and its neighbours freely; change the four status colours only if your new ones still mean the same thing.
</Callout>

## Show your own server address

`server-ip` is the address written on every Exylia scoreboard. Set it once:

```yaml title="plugins/ExyliaLib/colors.yml"
server-ip: play.myserver.net
```

Run `/exylialib reload`. Every message or scoreboard that contains `{server-ip}` shows the new address.

## Use the colours in a message or menu

In any message, menu title or item name of an Exylia plugin, write the colour name in curly braces. Everything after it takes that colour until the next one:

```yaml
level-up: "{primary}Level up! {letters}You reached {highlight}level 5{letters}."
```

In text the names use an underscore: `{secondary_light}`, `{letters_black}`, `{error_light}`. Because messages use names and not hex codes, they follow your palette automatically.

### Hex colours and gradients

- **A fixed hex colour** works anywhere: `&#8a51c4` or `<#8a51c4>`.
- **A gradient** can use palette names inside, so it follows your theme too: `<gradient:{primary}:{secondary_light}>My shop</gradient>`.
- **The palette itself** takes one hex colour per role. A gradient cannot be a role's value; write it in the message instead.

Legacy codes such as `&a` or `&l` still work and can be mixed with the names. See [Messages and languages](/docs/exylialib/messages-and-languages) for every way to write text.

## If a colour does not change

- **You did not reload.** Run `/exylialib reload`. A plugin's own reload command does not read this file.
- **The value is not valid hex.** Use six digits after `#`, such as `#2ec4b6`. A wrong value is reported and the default colour is used, so the server never ends up with no colours.
- **You forgot the quotes.** In YAML a bare `#` starts a comment. Write `'#2ec4b6'`.
- **The line has a fixed colour.** A message written with `&a` or `<#00ff00>` keeps that colour. Replace it with a name such as `{success}`.

<Details title="Technical details">
ExyliaLib reads `colors.yml`; keys are kebab-case in the file (`secondary-light`) and snake_case in text (`{secondary_light}`). `error-light` was added in ExyliaLib 1.477.0 and is written with its default into an existing file. Palette names inside a gradient resolve to the bare hex since 1.477.0. `/exylialib reload` also re-reads `config.yml`, `formats.yml`, `economy.yml` and `input.yml`. For the developer side (the `Text` and `Colors` classes), see [Text and placeholders](/docs/exylialib/text) and [The library's own files](/docs/exylialib/library-config).
</Details>
