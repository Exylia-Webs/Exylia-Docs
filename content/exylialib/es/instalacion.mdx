## En el servidor

Coloca `ExyliaLib.jar` en `plugins/`, junto a PacketEvents. Los plugins que dependen de ella se niegan a
cargar sin ella.

En el primer arranque el servidor descarga de Maven Central las librerías que declara ExyliaLib — el
framework de comandos, Caffeine, HikariCP, los drivers de base de datos y el cliente de Redis — igual que
cada plugin de Exylia declara las suyas, y las guarda en su carpeta `libraries/`. El servidor necesita
acceso a internet en ese primer arranque; después, todos los plugins comparten esas copias.

**PacketEvents** va a su lado en todos los servidores. La librería lo declara en `depend`, así que el
servidor se niega a cargar ExyliaLib — y con ella todos los plugins de Exylia — sin él. Las funciones
por paquete de la librería — overlays, diálogos, displays por jugador — pasan por él.
Descárgalo de [Modrinth](https://modrinth.com/plugin/packetevents).

La librería de sidebars por paquetes viaja dentro del jar, relocalizada, así que hay exactamente una
copia en el servidor en vez de una por plugin.

## Plugins opcionales

Nada de esto es obligatorio. Cada uno desbloquea o mejora un módulo:

| Plugin | Qué habilita |
|---|---|
| **PlaceholderAPI** | Exponer los placeholders de este plugin a otros, y leer los suyos. |
| **FastAsyncWorldEdit** | Un motor más rápido para las esquemáticas. Sin él, la librería pega con su propio motor. |
| **Vault** o **PlayerPoints** | El módulo de economía. |
| **Un plugin de clanes** | El módulo de clanes. Se detectan ocho — ver [Jugadores](/docs/exylialib/jugadores#clanes). |
| **Lunar (Apollo)**, **Feather** o el mod de cliente de **SurvivalCore** | [Integración de cliente](/docs/exylialib/integracion-de-cliente): waypoints, equipos, temporizadores en el HUD, cooldowns. |
| **DeluxeCombat** o **PvPManager** | La respuesta del módulo de combate a "¿está peleando este jugador?". |
| **Worlds** | Crear y borrar mundos, que en Folia es la única forma de hacerlo. |

Un módulo cuyo plugin de apoyo no está hace nada **en voz alta**: `Clans.isSupported()` responde con
honestidad en vez de lanzar una excepción, así que un plugin puede ocultar lo que no puede ofrecer.

## Configurarla

La librería escribe sus propios archivos en `plugins/ExyliaLib/` en el primer arranque — idioma,
actualizaciones, métricas, colores, formatos. Ver [Los archivos de la librería](/docs/exylialib/config-de-la-libreria).

## Desde un plugin

Declara la dependencia para que el servidor cargue la librería primero:

```yaml title="plugin.yml"
name: MyPlugin
main: net.example.MyPlugin
api-version: '1.21'
depend:
  - ExyliaLib
```

Después toma las vistas de módulo que necesites en `onEnable`. Casi todos los módulos se alcanzan
igual — un `of(plugin)` estático que devuelve una vista que pertenece a tu plugin:

```java title="MyPlugin.java"
public final class MyPlugin extends JavaPlugin {

    private ConfigFile<Settings> settings;

    @Override
    public void onEnable() {
        TaskScheduler tasks = Tasks.of(this);
        PluginMenus menus   = Menus.of(this);
        PluginActions acts  = Actions.of(this);

        settings = Configs.define(this, "config", Settings.class).load();
    }
}
```

<Callout type="note" title="Por qué es por plugin">
La vista es lo que hace funcionar la propiedad: tus acciones viven en tu namespace, tus menús se
cierran cuando tu plugin se desactiva, tus placeholders se dan de baja con él, y los valores escritos
en un item se archivan bajo tu nombre y no bajo el de la librería.
</Callout>

## Limpieza

No tienes que hacerla. La librería libera las tareas, menús, acciones, placeholders y entradas de un
plugin cuando se desactiva — los menús se cierran **antes** de liberar las tareas, para que un botón
cuyo handler viene de un classloader moribundo no pueda responder un último clic.

## Los comandos de la propia librería

`/exylialib` muestra el estado de la librería; sus subcomandos la recargan, la actualizan, revisan valores
por defecto cambiados, abren el editor web y mueven datos. Ver [Comandos](/docs/exylialib/comandos).

Un plugin escucha `/exylialib reload` con `Reloads.onLibraryReload(plugin, runnable)` — el motivo habitual
es que cambie la paleta, porque cada menú compilado se queda con los colores viejos.
