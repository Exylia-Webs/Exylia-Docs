Un trabajo es un archivo en `plugins/ExyliaJobs/lang/<language>/jobs/` (una carpeta `jobs/` anterior a los idiomas se mueve allí, conservando las ediciones); cada idioma tiene su propia copia, así que nombres, descripciones, mejoras y recompensas siguen el idioma del servidor; el nombre del archivo es el id del trabajo (`a-z`, `0-9`, `-`, `_`). `/jobsadmin reload` los vuelve a leer. Una entrada incorrecta cuesta solo esa entrada y se informa en la consola.

## Los trabajos incluidos

| Trabajo | Paga por |
|---|---|
| Miner | `break`: piedra y minerales. |
| Digger | `break`: tierra, arena, grava, arcilla. |
| Woodcutter | `break` de troncos, `strip-log`, `plant` de brotes. |
| Farmer | `harvest` de cultivos maduros, `plant`, `collect` (bayas, miel, compost). |
| Fisher | `fish`. |
| Hunter | `kill` de mobs. |
| Rancher | `breed`, `shear`, `milk`, `tame`. |
| Builder | `place`. |
| Smith | `smelt`, `craft`, `repair`, `smithing`. |
| Enchanter | `enchant`. |
| Brewer | `brew`. |
| Explorer | `explore` de biomas y `villager-trade`. |

Cada uno incluye nivel máximo 50, una curva geométrica (base 100, crecimiento 1.08), tres recompensas de hito (niveles 10, 25, 50) y cinco tiers de mejoras.

## El archivo de trabajo

```yaml
name: 'Miner'            # plain text: every screen colours it
icon: IRON_PICKAXE       # a material, or a custom item id such as nexo:ruby_pickaxe
description:
  - 'Dig deep for stone and ores.'
max-level: 50
curve: {type: geometric, base: 100, growth: 1.08}
income-bonus: 0.02       # money per level above 1
xp-bonus: 0              # experience per level above 1
price-share: 0.10        # what a target with xp but no money pays, of its sell price
anti-exploit: {tnt: true}
actions:
  break:
    stone: {money: 0.02, xp: 0.25}
    '#diamond_ores': {money: 4.0, xp: 15}
rewards:
  10:
    - type: ECONOMY
      value: '250'
```

| Clave | Significado |
|---|---|
| `enabled` | `false` oculta el trabajo a los jugadores y no paga nada. El progreso se conserva. |
| `name`, `icon`, `description` | La tarjeta. Nunca pongas códigos de color en el nombre. |
| `max-level` | Por defecto `defaults.max-level` (50). Por debajo de 1 se rechaza. |
| `curve` | `linear` (`base`, `step`), `geometric` (`base`, `growth`) o `formula` (cualquier expresión de `level`, p. ej. `100 * level ^ 1.6`). Por defecto geométrica 100 x 1.1. |
| `income-bonus`, `xp-bonus` | Por nivel por encima de 1. Por defecto 0.02 y 0. |
| `price-share` | Por defecto 0.10. |
| `anti-exploit` | Sobrescribe `config.yml` clave por clave. Consulta [Anti-exploit](/docs/exyliajobs/anti-exploit). |
| `actions` | Lo que se paga. |
| `rewards` | Hitos: un nivel de 2 a `max-level` y una lista de recompensas de ExyliaLib. Una cadena suelta es un comando de consola. |
| `perks` | Consulta [Mejoras y prestigio](/docs/exyliajobs/mejoras-y-prestigio). |
| `economy: {fatigue: false}` | Desactiva la fatiga en este trabajo. |
| `integrations: {mines: ...}` | `true`, un id de mina o una lista: pagar dentro de las minas de ExyliaMines. |

Un trabajo sin acciones se carga igualmente (un trabajo en preparación) y no paga nada.

## Acciones

Cada acción se acredita a todos los trabajos que el jugador tiene y que pagan por ella.

| Acción | Se acredita cuando |
|---|---|
| `break` | Se rompe un bloque (también con el TNT de un jugador si el trabajo lo permite). Objetivo: el bloque. |
| `place` | Se coloca un bloque; una vez por posición cada `place-cooldown`. |
| `harvest` | Se rompe un cultivo **maduro**. |
| `plant` | Se planta un cultivo o un brote; una vez por ciclo de crecimiento. |
| `strip-log` | Un hacha descorteza un tronco o madera. |
| `kill` | Un jugador mata a un mob (o a un jugador). `kill-custom` se lee como `kill`. |
| `breed` | Dos animales se reproducen; una vez por pareja cada `breed-cooldown`. |
| `tame` | Un jugador doma a un animal. |
| `shear` | Un jugador esquila a una entidad. |
| `milk` | Un cubo sobre una vaca o cabra adulta, o un cuenco sobre una mooshroom; cada animal una vez cada `breed-cooldown`. |
| `fish` | Se captura algo; por el objeto, multiplicado por su cantidad. |
| `smelt` | El jugador recoge la salida del horno, según la cantidad recogida. |
| `brew` | Termina una poción, acreditada al último jugador que usó el soporte, por poción; el objetivo es el ingrediente. |
| `enchant` | Se encanta un objeto, por nivel gastado; el objetivo es el objeto. |
| `repair` | Se recoge un resultado del yunque que de verdad repara (renombrar no es reparar). |
| `smithing` | Se recoge un resultado de la mesa de herrería. |
| `craft` | Una fabricación realmente hecha con el clic. |
| `eat` | Un jugador come o bebe un objeto. |
| `collect` | Bayas dulces o luminosas recogidas, miel de una colmena llena, polvo de hueso de un compostador lleno. |
| `villager-trade` | Se hace un intercambio; el objetivo es el objeto recibido. |
| `explore` | El primer jugador que entra en un chunk generado desde que se instaló el plugin; el objetivo es el bioma. |

## Objetivos

Bajo cada acción, cada clave es un objetivo y su valor es `{money, xp}`.

| Sintaxis | Ejemplo | Significado |
|---|---|---|
| Id vanilla | `diamond_ore`, `zombie` | En minúsculas, sin `minecraft:` (`DIAMOND_ORE` y `minecraft:diamond_ore` se leen igual). |
| Etiqueta | `'#logs'`, `'#diamond_ores'` | Se expande al cargar a cada miembro, según el tipo que usa la acción (bloque, objeto, mob o bioma). Un objetivo escrito por nombre gana al mismo objetivo alcanzado mediante una etiqueta. |
| Id personalizado | `nexo:ruby_ore`, `mythicmobs:king` | Bloques personalizados de Nexo, Oraxen, ItemsAdder y CraftEngine; mobs personalizados de MythicMobs y ExyliaMobs (`exyliamobs:<id>`). Un bloque personalizado que ningún trabajo nombra vuelve a su material vanilla. |
| `*` | `'*': {money: 0.1, xp: 1}` | Cualquier cosa que los demás objetivos de la acción no nombren. |

`money` es opcional: un objetivo con `xp` pero sin `money` paga `price-share` por lo que se vende el objeto, según los precios de ExyliaLib (la lista de valor de ExyliaMarket si está instalado). El dinero y la xp no pueden ser negativos.
