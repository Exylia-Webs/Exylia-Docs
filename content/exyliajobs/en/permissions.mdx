Players can use ExyliaJobs without any setup: everyone gets `exyliajobs.use`, so everyone can join jobs and be paid. Only admins get `/jobsadmin`. Use this page to give ranks more.

## All permissions

<Permissions />

## Give a rank more job slots

By default a player holds 2 jobs (`slots` in `config.yml`). A number permission raises that. The highest number a player holds wins, and it never lowers the value in the file.

```text
/lp group vip permission set exyliajobs.slots.4 true
```

## Give a rank more work orders

The limit is 5 open orders per player (`limit` in `orders.yml`). Same rule: the highest number wins and never lowers the file.

```text
/lp group vip permission set exyliajobs.orders.limit.15 true
/lp group staff permission set exyliajobs.orders.limit.unlimited true
```

## Give a rank a higher earning cap

Earning caps are off until you turn them on in `economy.yml`. The name after `exyliajobs.caps.` is a group you wrote in that file; the shipped ones are `default` and `vip`. A player with several groups gets the most generous one, and `0` (no cap) beats any number. See [Economy guard](/docs/exyliajobs/economy-guard#caps).

```text
/lp group vip permission set exyliajobs.caps.vip true
```

<Callout type="warning" title="Without exyliajobs.use nothing pays">
A player who lacks `exyliajobs.use` gets no money and no experience, and cannot open `/jobs`. If you negate it on the default group, grant it back to the ranks that should play.
</Callout>

<Details title="Technical details">
Only `exyliajobs.use`, `exyliajobs.admin`, `exyliajobs.orders.post` and `exyliajobs.orders.limit.unlimited` are declared in the plugin's `paper-plugin.yml`. The numbered nodes (`slots`, `orders.limit`) and the cap groups are checked by name, so they exist only when you grant them.
</Details>
