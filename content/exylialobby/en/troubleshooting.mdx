Find your symptom, then follow the fix.

## The plugin does not start

ExyliaLib is required. Without it the console says where to download it and ExyliaLobby stays off until it is installed and the server restarts. See [Install ExyliaLobby](/docs/exylialobby/installation).

## Nothing happens to players

The lobby rules apply only inside the lobby areas. Open `/lobbyadmin`, **Areas**, and check that the world, box or region you stand in is listed. See [Define the lobby areas](/docs/exylialobby/areas).

## A module does nothing

`chat` and `onboarding` are off by default. Open `/lobbyadmin`, **Modules** and switch them on. See [Switch modules on and off](/docs/exylialobby/modules).

## I cannot build in the lobby

Protection applies to everyone, admins included. Run `/lobbyadmin build` (permission `exylialobby.build`) to switch build mode on, and off again when you finish.

## The hotbar buttons do not show

- ExyliaPracticeCore is installed: its own lobby hotbar stays in charge. Set `force: true` in the hotbar module to show this one.
- PacketEvents is missing: the buttons are drawn as an overlay and need it.
- The player is not inside a lobby area.
- A button that depends on a module is drawn only while that module is on.

## Everyone can see everyone

Visibility needs PacketEvents. Without it the toggle does nothing.

## The server selector shows no player counts

Counts and status come from the proxy through ExyliaLib. Check the network link in ExyliaLib, and that `server` in each entry matches the id the proxy uses. See [Install ExyliaLobby](/docs/exylialobby/installation).

## Endless parkour does nothing

It needs PacketEvents, an endless area (`/lobbyadmin parkour endlessarea <name>`) and the mode enabled under `modes`. See [Build parkour](/docs/exylialobby/parkour).

## A player lost items or effects after leaving the lobby

They should not: whatever a module changes is given back when the player leaves, quits or the module is switched off, and the state module keeps the original on the player so a crash does not lose it. If it happens, switch on `debug` in `config.yml` and report the log.
