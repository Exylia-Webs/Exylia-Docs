## Claves CUSTOM de otros plugins de Exylia

Otros plugins de Exylia anuncian lo que hacen sus jugadores, y ExyliaJourney convierte cada uno de esos
eventos en una **clave CUSTOM** que un paso o un disparador puede esperar. No hay nada que configurar: cuando
el otro plugin está instalado sus claves empiezan a dispararse; cuando no, nunca lo hacen.

Una clave nombra el plugin, lo que pasó y, cuando lo hay, a qué le pasó. Un paso o disparador que pide una
clave cuenta también cada clave más específica bajo ella: `exylia:mines:break` cuenta un bloque roto en
cualquier mina, `exylia:mines:break:gold` solo en la mina `gold`.

| Clave | Se dispara para | Cuándo |
|---|---|---|
| `exylia:mines:break:<mine>` | El jugador | Un bloque roto en una mina de ExyliaMines. |
| `exylia:crates:open:<crate>` | El jugador | Una caja abierta en ExyliaCrates. |
| `exylia:clans:create` | El jugador | Un clan creado. |
| `exylia:clans:join` | El jugador | Un clan al que se unió. |
| `exylia:classes:equip:<class>` | El jugador | Una clase de ExyliaClasses equipada. |
| `exylia:classes:ability:<class>` | El jugador | Una habilidad de clase usada. |
| `exylia:ffa:join:<arena>` | El jugador | Una arena FFA en la que entra a jugar (no a espectar). |
| `exylia:ffa:kill:<arena>` | El asesino | Una kill en una arena FFA. |
| `exylia:events:join:<event>` | El jugador | Una partida de ExyliaEvents en la que entra. |
| `exylia:events:win:<event>` | Cada ganador | Una partida de ExyliaEvents ganada. |
| `exylia:practice:queue:<ranked\|unranked>:<kit>` | El jugador | Una cola de Practice en la que entra. |
| `exylia:practice:match` | Cada jugador de la partida | Una partida de Practice terminada. |
| `exylia:practice:win` | Cada ganador | Una partida de Practice ganada. |
| `exylia:survival:kit:<kit>` | El jugador | Un kit de SurvivalCore reclamado. |
| `exylia:survival:rankup:<rank>` | El jugador | Subió a ese rango. |
| `exylia:survival:sethome` | El jugador | Un home establecido. |
| `exylia:survival:warp:<warp>` | El jugador | Un warp usado. |
| `exylia:survival:bounty` | El asesino | Una recompensa por cabeza cobrada. |
| `exylia:market:buy:<source>` | El comprador | Algo comprado en ExyliaMarket. |
| `exylia:market:sell:<source>` | El vendedor | Algo vendido en ExyliaMarket. |
| `exylia:sandbox:join` | El jugador | Un mundo sandbox en el que entra. |
| `exylia:specials:use:<item>` | El jugador | Un objeto de ExyliaSpecials usado. |
| `exylia:specials:duel-win` | El ganador | Un 1v1 ganado. |
| `exylia:totems:save` | El jugador | Un tótem salvó al jugador. |
| `exylia:tabletop:win` | El ganador | Una partida de tabletop ganada. |
| `exylia:capture:zone` | El jugador que captura | Una zona capturada en ExyliaCapture. |

Un evento cancelado no dispara nada.

### Ejemplos

```yaml
# un paso: abrir tres cajas de cualquier tipo
objective:
  type: CUSTOM
  key: exylia:crates:open
  amount: 3

# un recorrido que empieza la primera vez que un jugador se une a un clan
triggers:
  - type: CUSTOM
    key: exylia:clans:join
```

## Tus propias claves

Cualquier plugin puede disparar sus propias claves mediante la API de Exylia:

```java
ExyliaAPI.get(JourneyService.class).ifPresent(journeys -> journeys.trigger(player, "shop:opened", 1));
```

y un admin, la consola o cualquier plugin que ejecute comandos de consola, con:

```
/journeyadmin trigger <player> <key> [amount]
```

Las claves se comparan sin distinguir mayúsculas. Consulta [API](/docs/exyliajourney/api).

## Clics en NPCs

Cada NPC colocado mediante ExyliaLib cuenta para los objetivos `INTERACT_NPC` y los disparadores
`NPC_CLICK`, sin configurar nada:

| NPC | Cómo se nombra |
|---|---|
| Los del propio plugin (`npcs:` en `config.yml`; la demo escribe uno) | Su id solo: `guide`. |
| Los NPCs de ExyliaDisplays | Su id solo: `blacksmith`. |
| El NPC colocado de cualquier otro plugin | `<plugin>:<id>`. |

El campo NPC del editor lista todos los NPCs colocados en el servidor para elegir. El NPC al que apunta un
paso brilla solo para ese jugador, y el faro se alza sobre él.

La antigua línea de clic `[ACTION] exyliajourney:npc %npc%` en un NPC de ExyliaDisplays sigue funcionando y
ya no hace falta; un clic que repite se cuenta una sola vez. `/journeyadmin trigger <player> npc:<id>` cuenta
como hacer clic en ese NPC.

### Los NPCs propios del plugin

`npcs:` en `config.yml` coloca NPCs a los que pueden apuntar los recorridos, sin ningún otro plugin:

```yaml
npcs:
  guide:
    location: world,0,64,0,90   # world,x,y,z[,yaw[,pitch]]
    skin: Notch                 # un nombre de jugador, o '' para la de por defecto
    glow: '#8A51C4'             # un contorno para todos, o '' para ninguno
```

Necesitan PacketEvents.

## PlaceholderAPI

Con PlaceholderAPI los [placeholders](/docs/exyliajourney/placeholders) `%journey_...%` funcionan en cualquier
otro plugin, y cualquier placeholder de PlaceholderAPI se puede usar en `requirements.condition` y en los
objetivos `PLACEHOLDER`.

## Ajustes del jugador

Los cuatro ajustes de la guía se registran en `/settings` de ExyliaLib bajo **Journey guidance**, junto a los
de `/journey`. Consulta [Guía](/docs/exyliajourney/guia#los-ajustes-de-cada-jugador).
