Al terminar esta página, un NPC, un lugar o un comando abre una conversación: una caja en la parte baja de la pantalla, una línea por pulsación, que puede acabar en respuestas que ejecutan acciones o inician un recorrido. No necesita paquete de recursos.

Hay dos clases:

- **Diálogos independientes** en `dialogues/<id>.yml`. No forman parte de un recorrido: los abre un NPC, un lugar, una entrada, un comando u otro diálogo, y una respuesta puede iniciar un recorrido.
- **La conversación de un paso**, dentro de un recorrido. Consulta [En un paso](#en-un-paso).

## Antes de empezar

Los diálogos independientes se escriben en archivos; no hay editor en el juego para ellos. Necesitas acceso a la carpeta `plugins/ExyliaJourney/dialogues/` del servidor. Para un disparador de NPC necesitas el NPC colocado (consulta [Integraciones](/docs/exyliajourney/integraciones#clics-en-npcs)). El plugin escribe dos ejemplos, `dialogues/example.yml` y `dialogues/example_lore.yml`, con cada clave explicada en comentarios.

## Escribir un diálogo

<Steps>
  <Step title="Crea el archivo">
    Crea `dialogues/guide.yml`. El nombre del archivo es el id del diálogo: letras minúsculas, dígitos, `-` y `_`.
  </Step>
  <Step title="Escribe las líneas">
    Cada entrada de `lines` es una pulsación. `'Guide: palabras'` muestra `Guide` como quien habla, `'-: palabras'` es narración. Un nombre no lleva colores y tiene como máximo 32 caracteres. `faces` asocia el nombre de quien habla con el nombre del jugador cuya skin se dibuja junto a sus líneas.
  </Step>
  <Step title="Añade respuestas">
    `answers` salen bajo la última línea. Cada una tiene un `text` y, opcionalmente, `actions`, un `journey` que iniciar u otro `dialogue` que abrir. Sin `answers`, el diálogo se cierra en la última pulsación.
  </Step>
  <Step title="Elige qué lo abre">
    Añade `triggers`, por ejemplo `- { type: NPC_CLICK, npc: guide }`. Consulta [Disparadores](#disparadores).
  </Step>
  <Step title="Cárgalo">
    Ejecuta `/journeyadmin reload`.
  </Step>
</Steps>

```yaml
mode: screen
triggers:
  - { type: NPC_CLICK, npc: guide }
  - { type: FIRST_JOIN, mode: hud, once: true }
require: ''
faces:
  Guide: Notch
lines:
  - 'Guide: Welcome, traveller. This land is bigger than it looks.'
  - text: 'Guide: Most people get lost on their first night.'
    actions: ['[SOUND] BLOCK_NOTE_BLOCK_CHIME;0.6;1.2']
  - 'Guide: How can I help you?'
answers:
  - text: 'Show me around'
    actions: ['[MESSAGE] %prefix% {success}The guide nods and starts walking.']
    journey: example
  - text: 'Tell me about this place'
    dialogue: example_lore
  - text: 'Not now'
```

## Comprueba que funciona

Ejecuta `/journeyadmin dialogue open guide`. La caja se abre para ti; pulsa para leer cada línea y elige una respuesta. `/journeyadmin dialogue list` muestra cada diálogo cargado con su modo, líneas, respuestas y disparadores; si el tuyo no sale, `/journeyadmin reload` dice qué falla en el archivo.

## Modos

| Modo | Qué hace el jugador |
|---|---|
| `hud` (por defecto) | Sigue caminando. La rueda del ratón o las teclas numéricas eligen una respuesta y agacharse confirma. |
| `screen` | Se queda quieto y hace clic en la caja o en una respuesta. |

El `mode` del archivo es el predeterminado. El `mode` de un disparador, o el que se da al comando o a la línea `[DIALOGUE]`, manda solo para esa apertura. Un diálogo abierto por una respuesta mantiene el modo del anterior. El aviso bajo la caja ("Agáchate o haz clic en el aire para continuar", "Rueda para elegir · agáchate para responder", "Haz clic en una respuesta") sale de `messages.yml` (`dialogue.prompt`, `dialogue.choosing`, `dialogue.clicking`); para cambiarlo, consulta [Mensajes e idiomas](/docs/exylialib/mensajes-e-idiomas).

## Disparadores

`triggers` lista lo que abre el diálogo por sí solo: `NPC_CLICK` (`npc`), `REGION_ENTER` (`region`, o `location` + `radius`), `JOIN`, `FIRST_JOIN`, `JOURNEY_COMPLETE` (`journey`) y `CUSTOM` (`key`). Cada disparador puede fijar también `mode`, `cooldown` (`30s`, `10m`, `1d`) y `once`.

Reglas cuando salta algo:

- Se abre el primer diálogo, por nombre de archivo, con un disparador que coincida; los demás no.
- Solo se abre si el jugador cumple el `require` del archivo y ese disparador no está en enfriamiento.
- Nada se abre encima de otra conversación ni de una cinemática.
- `once` se guarda como un cooldown larguísimo, así que borrar los cooldowns del plugin lo abre de nuevo.

<Details title="Claves de disparadores y respuestas">
| Tipo | Clave | Se abre cuando |
|---|---|---|
| `NPC_CLICK` | `npc` | El jugador hace clic en ese NPC. Cualquier NPC de este plugin, de ExyliaDisplays o de otro plugin. |
| `REGION_ENTER` | `region`, o `location` + `radius` | El jugador entra en esa región, o se acerca a `radius` bloques (5) de `world,x,y,z`. |
| `JOIN` | ninguna | El jugador entra. |
| `FIRST_JOIN` | ninguna | El jugador entra por primera vez. |
| `JOURNEY_COMPLETE` | `journey` | El jugador completa ese recorrido. |
| `CUSTOM` | `key` | Se dispara una clave personalizada. Consulta [Integraciones](/docs/exyliajourney/integraciones). |

`npc: [guide, merchant]` al principio del archivo equivale a un disparador `NPC_CLICK` por NPC. Cualquier otro tipo de disparador se reporta y se omite.

| Clave del disparador | Qué hace |
|---|---|
| `mode` | `hud` o `screen`, solo para esta forma de abrirlo. |
| `cooldown` | Cuánto tarda este disparador en volver a abrirlo para el mismo jugador. |
| `once` | `true` lo abre por este disparador una sola vez por jugador. |

Las claves de las respuestas, todas opcionales salvo `text`, se ejecutan en este orden:

| Clave | Qué hace |
|---|---|
| `text` | Las palabras de la respuesta. |
| `require` | Muestra la respuesta solo a quien cumpla esta condición, como `'%player_level% >= 5'`. |
| `actions` | Líneas de interacción que se ejecutan al elegirla: `[MESSAGE]`, `[SOUND]`, `[MONEY]`, `[CONSOLE]`, `[ACTION]`... |
| `journey` | Inicia ese recorrido para el jugador, siempre que sus propias reglas (activado, requisitos, cooldown, no estar ya activo) lo permitan. Un id desconocido se registra. |
| `dialogue` | Abre a continuación ese diálogo. Un id desconocido se reporta al cargar los recorridos. |

Una respuesta sin ninguna de las tres últimas solo cierra la conversación. Una línea también puede ser una sección, `{ text: 'Guide: palabras', actions: [...] }`, cuyas [líneas de interacción](/docs/exyliajourney/recorridos#líneas-de-efectos) se ejecutan al empezar la línea.
</Details>

## Abrir uno a mano

<Commands group="dialogues" />

`[DIALOGUE] <id> [hud|screen]` también es una línea de interacción, usable en un menú, un holograma, un NPC o las `actions` de otro diálogo. El modo opcional vale solo esta vez.

## En un paso

Para poner una conversación dentro de un recorrido, abre el paso, pulsa **Objetivo**, elige **Conversación** como tipo y pulsa **Conversación** para escribir sus líneas. Un paso de conversación se completa cuando termina la conversación. Cualquier otro paso puede llevar también una sección `dialogue`, y sus respuestas pueden hacer avanzar.

```yaml
steps:
  - id: ask
    objective: { type: DIALOGUE }
    dialogue:
      lines: ['Guide: Which way?']
      answers:
        - { text: 'North', next: north }
        - { text: 'South', next: south, key: went-south }
  - id: north
    objective: { type: REACH, location: 'world,0,64,200' }
```

`next` envía el recorrido a ese paso (`end` lo termina), y `key` dispara un `choice:<key>` que los `branches` de un paso pueden leer (`- { choice: went-south, next: south }`). `dialogue: ['línea', ...]` es la forma corta, solo con palabras. La conversación suena una vez por visita al paso, mientras ese recorrido sea el que el jugador sigue y la guía no esté oculta; si el jugador la cierra sin terminar, se abre de nuevo en la siguiente pasada. Se retira si el paso termina de otra forma, y el panel de guía del paso permanece oculto mientras suena.

Las respuestas que inician recorridos reportan la causa `dialogue` a la [analítica](/docs/exyliajourney/analitica#exyliaanalytics).
