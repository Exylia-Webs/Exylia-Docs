By the end of this page a journey starts for the right players at the right moment, can be repeated or skipped the way you want, and pays its rewards. A journey is one file, `journeys/<id>.yml`, and everything below can be done in game with `/journeyadmin`; the file is the same either way.

## Before you start

You need a journey with at least one [step](/docs/exyliajourney/steps). If you have none, follow [Your first journey](/docs/exyliajourney/first-steps). Players only get a journey that is switched on and has a trigger.

## Create a journey

<Steps>
  <Step title="Open the list">
    Run `/journeyadmin`. Every journey file is listed with its state, steps and what starts it.
  </Step>
  <Step title="Click Create journey">
    A short wizard asks for an id (lower case, digits, `-` or `_`), a name, an icon, what starts it and the template of its first step. Nothing is written until you confirm the review at the end. A plain name is saved in the house style: primary colour, bold, upper case.
  </Step>
  <Step title="Open it">
    After the wizard you land on the journey's hub, with **Status**, **Steps**, **Start & access**, **Rewards & effects**, **Settings**, **Funnel**, **Test run**, **Copy journey** and **Delete**. **Copy journey** makes a new journey with every step and setting of this one, switched off until you enable it.
  </Step>
</Steps>

## Triggers

A trigger decides when a journey starts for a player. Open the journey, click **Start & access**, then **Triggers**. Click **Add trigger**, pick a type, and fill the card it adds: each card has a click per field, and right-click removes a trigger. A journey can have several triggers.

- **First join**: a new player's first ever entry, 3 seconds after joining.
- **Join**: every time the player enters, until they complete it.
- **Command**: nothing automatic. Only `/journeyadmin start`, the test button or another plugin starts it.
- **Enter a place**: walking into an ExyliaLib region, or a sphere around a spot. Shift-left sets the centre where you stand, shift-right the radius.
- **NPC click**: clicking one NPC. See [NPC clicks](/docs/exyliajourney/integrations#npc-clicks).
- **After a journey**: completing another journey. This is how you chain a quest.
- **Permission**: having a permission, such as a rank.
- **Custom key**: another plugin or `/journeyadmin trigger` fires a key.

<Details title="Trigger table and YAML">
A trigger is written as its bare name when it needs nothing else, or as a section.

```yaml
triggers:
  - FIRST_JOIN
  - type: REGION_ENTER
    region: spawn
  - type: REGION_ENTER
    location: world,0,64,0
    radius: 6
  - type: NPC_CLICK
    npc: guide
  - type: JOURNEY_COMPLETE
    journey: tutorial
  - type: PERMISSION
    permission: rank.member
  - type: CUSTOM
    key: exylia:crates:open
```

| Trigger | Keys | Starts when |
|---|---|---|
| `FIRST_JOIN` | none | A player joins the server for the very first time, `first-join-delay` (3 s) after joining. |
| `JOIN` | none | A player joins, every time. |
| `COMMAND` | none | Nothing automatic: only `/journeyadmin start`, the editor's test button or another plugin starts it. Marks a journey meant to be started by hand. |
| `REGION_ENTER` | `region`, or `location` + `radius` (5) | The player walks into an ExyliaLib region (by its full id or its bare name), or into a sphere. |
| `NPC_CLICK` | `npc` | The player clicks that NPC. |
| `JOURNEY_COMPLETE` | `journey` | The player completes that journey. |
| `PERMISSION` | `permission` | The player has the permission. Checked every `permission-check` (5 s) for online players, and only for a player who never had this journey. |
| `CUSTOM` | `key` | A CUSTOM key is fired for the player: by another Exylia plugin, another plugin's code or `/journeyadmin trigger`. A trigger asking for `exylia:crates:open` also fires on `exylia:crates:open:vote`. See [Integrations](/docs/exyliajourney/integrations). |

A trigger that misses its key (an `NPC_CLICK` with no `npc`) is reported and skipped; the rest of the journey loads. The creation wizard offers First join, Join, Command, NPC click, Enter a place and (once another journey exists) After a journey; pick **Command** there and no trigger is written.
</Details>

## Who may start it

When a trigger fires, the journey starts only if every rule passes, in this order:

1. The player is not already on this journey.
2. The journey is switched on (**Status** on the hub).
3. The player did not skip it before. A skipped journey never starts again from a trigger.
4. The player has not completed it, unless it is repeatable.
5. A repeatable journey's cooldown since the last completion has run out.
6. No other journey of the same group is active for the player.
7. The player has the permission and meets the condition.
8. No other plugin cancelled the start (see [API](/docs/exyliajourney/api)).

To set the permission, condition and group, click **Start & access** and use **Permission**, **Condition** and **Group**. A permission is a node such as `rank.member`. A condition is a placeholder comparison such as `%player_level% >= 5`, and it **fails closed**: a condition the plugin cannot read is reported when the journey loads and nobody meets it, and a placeholder that does not resolve to a number never passes a numeric comparison.

An admin start (`/journeyadmin start`) ignores every rule except *already active*. A journey that was **stopped** (by an admin, by a step's time limit or through the API) is as if it never started, and its triggers may start it again from the first step.

## Repeat it

Click **Settings** on the hub, then switch **Repeatable** on and set **Cooldown** (for example `1d`). A repeatable journey starts again after a completion once its cooldown has run out. By default a journey is not repeatable and has no cooldown.

## Several journeys at once

A player can run several journeys at once, one per group. Only one is **tracked**: the one whose step the guidance shows and the placeholders describe. A new journey becomes the tracked one; when it ends, the most recently tracked of the others takes over. Players switch with `/journey track <id>`, or cycle through them by clicking the journey card in `/journey`. Progress counts on every active journey.

To make two journeys exclusive, give them the same group in **Start & access**. When several trigger at once, the one with the higher **Priority** (in **Settings**) starts first and wins the group.

## Skipping

Click **Settings**, then **Skippable**. With it on, a player can skip the whole journey from `/journey` or with `/journey skip journey`, after confirming; with it off they get a refusal. A skipped journey pays nothing, is recorded as skipped and never starts again from a trigger. Clear that with `/journeyadmin reset <player> <journey>`.

Skipping single steps is the step's own setting (see [Steps](/docs/exyliajourney/steps#step-keys)). A skipped step pays nothing and the next one starts; skipping the **last** step completes the journey.

A run where **any** step was skipped gives no journey completion rewards, so skipping cannot be used to collect them; the `on-complete` lines still run. `/journeyadmin complete` still pays in full.

## Rewards

Click **Rewards & effects**, then **Rewards**. The list uses ExyliaLib's reward editor: items, money, experience, commands, messages, potions and more, paid when the journey is completed (unless a step of that run was skipped). Steps have rewards of their own, paid when that step is completed.

<Details title="Rewards in the file">
Each entry is a section with a `type` (`ITEM`, `ECONOMY`, `EXPERIENCE`, `COMMAND`, `MESSAGE`, `POTION`...) or a bare string, which runs as a console command:

```yaml
rewards:
  - type: EXPERIENCE
    value: '100'
  - type: ITEM
    itemSnapshot: TORCH
    minAmount: 8
    maxAmount: 8
  - 'give %player_name% bread 8'
```
</Details>

## Effect lines

**On start** and **On complete**, under **Rewards & effects** (and on each step under **Effects & rewards**), are lists of lines that run when the journey starts and when it is completed. They are ExyliaLib interaction lines: console or player commands (`console:`, `player:`), `[ACTION] namespace:id`, `[TELEPORT]` and every sequence token (`[MESSAGE]`, `[SOUND]`, `[TOAST]`, `[PARTICLE]`, `[FIREWORK]`, `[DELAY]`...). For colours in the lines, see [Colours](/docs/exylialib/colours).

```yaml
on-start:
  - '[SOUND] BLOCK_NOTE_BLOCK_CHIME;1;1.4'
on-complete:
  - 'console: give %player_name% bread 4'
  - '[MESSAGE] {success}Welcome aboard, {highlight}%player_name%{success}!'
```

| Placeholder | Value |
|---|---|
| `%journey%`, `%journey_id%` | The journey's name and id. |
| `%steps%` | How many steps it has. |
| `%step%`, `%step_id%` | The step's title and id (step lines). |
| `%number%` | The current step's number, from 1. |
| `%progress%`, `%percent%` | The current step's count (`3/10`) and its percentage. |
| `%time%` | How long the journey took (the journey's `on-complete`). |

Any player placeholder works too. On top of your lines, every completed step plays the feedback set in `config.yml` (a sound, a toast and a short particle burst), and every completed journey plays a celebration of fireworks and a ring of particles with a centred *JOURNEY COMPLETE* block. See [Configuration](/docs/exyliajourney/configuration#feedback).

## Check that it works

1. Click **Test run** on the journey. You play the live version from the first step; nothing is saved, counted or paid. `/journeyadmin test stop` ends it.
2. To check the trigger and the rules as a real player would meet them, do what the trigger asks (rejoin, walk into the region, click the NPC) with a test account that is not an admin. `/journeyadmin start <player> <journey>` skips those rules.
3. Run `/journey` as that player to see the card.

If nobody gets it, see [Common problems](/docs/exyliajourney/troubleshooting).

## A bad file

Nothing in a journey file stops the server. A bad trigger, step or reward is reported in the console naming the file and the path (`steps[2].objective`), and skipped; a journey left with no step is not loaded. `/journeyadmin reload` says how many problems it found. In the editor the journey's **Status** card lists them and broken steps are marked.

<Details title="All journey keys">
```yaml
name: '{primary}&lWELCOME'
icon: COMPASS
description: ['{letters}Your first minutes on the server.']
enabled: true
priority: 10            # higher starts first when several trigger at once
group: main             # one active journey per group
repeatable: false
cooldown: 0s
skippable: true
triggers:
  - FIRST_JOIN
requirements:
  permission: ''
  condition: '%player_level% >= 5'
steps:
  - id: spawn
    title: '{highlight}Find the fountain'
    objective: { type: REACH, location: 'world,0,64,0', radius: 4 }
rewards:
  - { type: EXPERIENCE, value: '100' }
  - 'give %player_name% bread 8'
on-start: []
on-complete: ['[MESSAGE] {success}Welcome aboard!']
```

| Key | Default | What it does |
|---|---|---|
| `name` | the id | Shown in messages, menus, the panel and `%journey_current%`. |
| `icon` | `COMPASS` | The material in menus. |
| `description` | none | Lines under the name in `/journey`. |
| `enabled` | `true` | A disabled journey never starts from a trigger. An admin can still start it. |
| `priority` | `0` | When several journeys trigger at once, the higher one starts first. With a shared group, it is the one that wins. |
| `group` | `main` | A player has at most one active journey per group. |
| `repeatable` | `false` | Whether it can start again after it was completed. |
| `cooldown` | `0s` | For a repeatable journey, how long after a completion it may start again. |
| `skippable` | `true` | Whether players may skip the whole journey. |
| `triggers` | none | What starts it. |
| `requirements` | none | `permission` and `condition` a player must meet. |
| `focus` | none | Keeps players on the journey: hidden players, blocked commands, interactions, drops, damage and a leash. A step may change it. See [Focus mode](/docs/exyliajourney/focus-mode). |
| `steps` | none | At least one. A journey with no readable step is reported and not loaded. |
| `rewards` | none | Paid when the journey is completed. |
| `on-start`, `on-complete` | none | Effect lines run when it starts and when it is completed. |
</Details>
