By the end of this page an NPC, a place or a command opens a conversation: a box at the bottom of the screen, one line per press, optionally ending in answers that run actions or start a journey. It needs no resource pack.

There are two kinds:

- **Standalone dialogues** in `dialogues/<id>.yml`. They are not part of a journey: an NPC, a place, a join, a command or another dialogue opens them, and an answer may start a journey.
- **A step's conversation**, inside a journey. See [In a step](#in-a-step).

## Before you start

Standalone dialogues are written in files; there is no in-game editor for them. You need access to the server's `plugins/ExyliaJourney/dialogues/` folder. For an NPC trigger you need the NPC placed (see [Integrations](/docs/exyliajourney/integrations#npc-clicks)). The plugin writes two examples, `dialogues/example.yml` and `dialogues/example_lore.yml`, with every key explained in comments.

## Write a dialogue

<Steps>
  <Step title="Create the file">
    Make `dialogues/guide.yml`. The file name is the dialogue's id: lower-case letters, digits, `-` and `_`.
  </Step>
  <Step title="Write the lines">
    Each entry of `lines` is one press. `'Guide: words'` shows `Guide` as the speaker, `'-: words'` is narration. A name has no colours in it and is at most 32 characters. `faces` maps a speaker's name to the player name whose skin is drawn beside their lines.
  </Step>
  <Step title="Add answers">
    `answers` appear under the last line. Each has a `text` and, optionally, `actions`, a `journey` to start or another `dialogue` to open. Without `answers` the dialogue closes on the last press.
  </Step>
  <Step title="Choose what opens it">
    Add `triggers`, for example `- { type: NPC_CLICK, npc: guide }`. See [Triggers](#triggers).
  </Step>
  <Step title="Load it">
    Run `/journeyadmin reload`.
  </Step>
</Steps>

```yaml
mode: screen
triggers:
  - { type: NPC_CLICK, npc: guide }
  - { type: FIRST_JOIN, mode: hud, once: true }
require: ''
faces:
  Guide: Notch
lines:
  - 'Guide: Welcome, traveller. This land is bigger than it looks.'
  - text: 'Guide: Most people get lost on their first night.'
    actions: ['[SOUND] BLOCK_NOTE_BLOCK_CHIME;0.6;1.2']
  - 'Guide: How can I help you?'
answers:
  - text: 'Show me around'
    actions: ['[MESSAGE] %prefix% {success}The guide nods and starts walking.']
    journey: example
  - text: 'Tell me about this place'
    dialogue: example_lore
  - text: 'Not now'
```

## Check that it works

Run `/journeyadmin dialogue open guide`. The box opens for you; press to read each line and pick an answer. `/journeyadmin dialogue list` shows every loaded dialogue with its mode, lines, answers and triggers; if yours is missing, `/journeyadmin reload` says what is wrong with the file.

## Modes

| Mode | What the player does |
|---|---|
| `hud` (default) | Keeps walking. The mouse wheel or the number keys pick an answer and a sneak confirms. |
| `screen` | Stands still and clicks the box or an answer. |

`mode` on the file is the default. A trigger's `mode`, or the one given to the command or the `[DIALOGUE]` line, wins for that opening only. A dialogue opened by an answer keeps the mode of the one before it. The hint under the box ("Sneak or click the air to continue", "Scroll to choose · sneak to answer", "Click an answer") comes from `messages.yml` (`dialogue.prompt`, `dialogue.choosing`, `dialogue.clicking`); to change it, see [Messages and languages](/docs/exylialib/messages-and-languages).

## Triggers

`triggers` lists what opens the dialogue on its own: `NPC_CLICK` (`npc`), `REGION_ENTER` (`region`, or `location` + `radius`), `JOIN`, `FIRST_JOIN`, `JOURNEY_COMPLETE` (`journey`) and `CUSTOM` (`key`). Each trigger may also set `mode`, `cooldown` (`30s`, `10m`, `1d`) and `once`.

Rules when something fires:

- The first dialogue, by file name, with a matching trigger opens, and the others do not.
- It opens only if the player meets the file's `require` and that trigger is not cooling down.
- Nothing opens over another conversation or over a cinematic.
- `once` is kept as a very long cooldown, so a wipe of the plugin's cooldowns opens it again.

<Details title="Trigger and answer keys">
| Type | Key | Opens when |
|---|---|---|
| `NPC_CLICK` | `npc` | The player clicks that NPC. Any NPC of this plugin, ExyliaDisplays or another plugin. |
| `REGION_ENTER` | `region`, or `location` + `radius` | The player enters that region, or comes within `radius` blocks (5) of `world,x,y,z`. |
| `JOIN` | none | The player joins. |
| `FIRST_JOIN` | none | The player joins for the first time. |
| `JOURNEY_COMPLETE` | `journey` | The player completes that journey. |
| `CUSTOM` | `key` | A custom key is fired. See [Integrations](/docs/exyliajourney/integrations). |

`npc: [guide, merchant]` at the top of the file is short for one `NPC_CLICK` trigger per NPC. Any other trigger type is reported and skipped.

| Trigger key | What it does |
|---|---|
| `mode` | `hud` or `screen`, for this way of opening only. |
| `cooldown` | How long before this trigger opens it again for the same player. |
| `once` | `true` opens it through this trigger once per player. |

Answer keys, all optional except `text`, run in this order:

| Key | What it does |
|---|---|
| `text` | The answer's words. |
| `require` | Shows the answer only to players who meet this condition, such as `'%player_level% >= 5'`. |
| `actions` | Interaction lines run when it is chosen: `[MESSAGE]`, `[SOUND]`, `[MONEY]`, `[CONSOLE]`, `[ACTION]`... |
| `journey` | Starts that journey for the player, as long as its own rules (enabled, requirements, cooldown, not already active) allow it. An unknown id is logged. |
| `dialogue` | Opens that dialogue next. An unknown id is reported when journeys load. |

An answer with none of the last three just closes the conversation. A line can also be a section, `{ text: 'Guide: words', actions: [...] }`, whose [interaction lines](/docs/exyliajourney/journeys#effect-lines) run as the line starts.
</Details>

## Open one by hand

<Commands group="dialogues" />

`[DIALOGUE] <id> [hud|screen]` is also an interaction line, usable in a menu, a hologram, an NPC or another dialogue's `actions`. The optional mode applies this time only.

## In a step

To put a conversation inside a journey, open the step, click **Objective**, pick **Conversation** as the type and click **Conversation** to write its lines. A conversation step is done when the conversation ends. Any other step may carry a `dialogue` section too, and its answers can lead on.

```yaml
steps:
  - id: ask
    objective: { type: DIALOGUE }
    dialogue:
      lines: ['Guide: Which way?']
      answers:
        - { text: 'North', next: north }
        - { text: 'South', next: south, key: went-south }
  - id: north
    objective: { type: REACH, location: 'world,0,64,200' }
```

`next` sends the journey to that step (`end` finishes it), and `key` fires a `choice:<key>` that a step's `branches` can read (`- { choice: went-south, next: south }`). `dialogue: ['line', ...]` is the short form with words only. The conversation plays once per visit to the step, while that journey is the one the player tracks and guidance is not hidden; if the player closes it unfinished it opens again on the next pass. It is taken down when the step ends some other way, and the step's guidance panel stays hidden while it plays.

Answers that start journeys report the cause `dialogue` to [analytics](/docs/exyliajourney/analytics#exyliaanalytics).
