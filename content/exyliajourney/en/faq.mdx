## Bedrock

**Do Bedrock players get journeys?** Yes, every journey, objective and reward. A Bedrock client draws display entities poorly and has no locator bar, so those players get the step in chat when it starts, an action bar line with progress and distance, a particle column over the target and particle footprints on trails. Cinematics arrive as chat subtitles and count as watched; Java players on the same server keep the full [guidance](/docs/exyliajourney/guidance#without-packetevents-and-on-bedrock).

## Performance

**What does it cost on a busy server?** Very little. Each listener first checks whether anybody waits for that kind of objective, so breaking a block costs one set lookup when nobody is on a `BREAK_BLOCK` step. Polled objectives (`LEVEL`, `PLAYTIME`, `WAIT`, `EQUIP`, `PLACEHOLDER`, and `REACH` as a safety net) are checked once a second, only for players on one of them. Progress writes are batched by `save-interval` in [Configuration](/docs/exyliajourney/configuration#general), and on Folia everything about a player runs on that player's region thread.

## Without PacketEvents

**What do players see without PacketEvents?** The same journeys with simpler guidance: the step in chat when it starts, an action bar line, particle beams and footprints. There is no floating panel, waypoint, glow, toast or NPC of the plugin's own (ExyliaDisplays NPCs still work), and cinematics keep subtitles and sounds but the camera does not move. See [Installation](/docs/exyliajourney/installation#packetevents).

## Editing a live journey

**What happens to players on a journey I edit?** They stay on it. The editor replaces the live journey at once and moves each player to the same step by its id, keeping their count; if their step was deleted they continue on the step now in its place, started afresh. If an edit leaves the journey unreadable, the last working version stays live. A hand edit followed by `/journeyadmin reload` does the same. See [Editor](/docs/exyliajourney/editor).

**I renamed a step's id. Why did its stats reset?** The funnel counts each step by its id. Change the `title` freely and keep the `id`. See [Steps](/docs/exyliajourney/steps#step-keys).

## Common questions

**A `FIRST_JOIN` journey did not start for me.** It starts only for a player who has never played on the server before, so players who joined before the plugin was installed never get it; give them a `JOIN` or `PERMISSION` trigger. To test it, use `/journeyadmin start <player> <journey>` or a fresh account. See [Common problems](/docs/exyliajourney/troubleshooting).

**A journey does not start at all.** Turn on `debug: true` in `config.yml`: the console says why each start was refused (disabled, skipped, already done, cooldown, group busy, requirements, cancelled). Also check the journey has a trigger, because one created in the editor has none until you add it. See [Journeys](/docs/exyliajourney/journeys#triggers).

**A player skipped the onboarding by mistake.** A skipped journey never starts again from a trigger. `/journeyadmin reset <player> <journey>` clears it, or `/journeyadmin start <player> <journey>` starts it anyway.

**A player skipped a step and got no journey rewards.** That is intended: a run where any step was skipped gives no journey completion rewards, so skipping cannot be used to collect them. The `on-complete` lines still run, and `/journeyadmin complete <player> <journey>` pays in full.

**Players run out of time and lose the journey.** A step's `timeout` fails the step: the whole journey stops and the step counts as abandoned. The journey's triggers can start it again from the first step, so remove the limit or make sure it has such a trigger. See [Steps](/docs/exyliajourney/steps#add-a-hint-and-a-time-limit).

**Can players farm objectives?** Not the easy ways. Blocks a player placed do not count for `BREAK_BLOCK`, placing on a spot already counted this session does not count, picking up items any player dropped does not count, and mobs from spawners, spawn eggs, dispensed eggs or built iron and snow golems do not count for `KILL_MOB`. Not covered: crafts that can be undone, `KILL_PLAYER` on a player's own alt accounts, and a `BREAK_BLOCK` step with no filter, which does not check placed blocks. Give such steps a filter, or no rewards.

**My `PLACEHOLDER` step never completes.** A placeholder that does not resolve to a number never passes a numeric comparison. Check it with PlaceholderAPI's parse command; see [Placeholders](/docs/exyliajourney/placeholders).

**Can two journeys run at the same time?** Yes, if they are in different groups. Progress counts on all of them and the guidance shows the tracked one.

**Does a cinematic hold a journey forever if it cannot play?** No. A `WATCH_CINEMATIC` step completes when the cinematic ends in any way, refused or skipped included. See [Cinematics](/docs/exyliajourney/cinematics).

**Can I keep players from wandering off during a tutorial?** Yes: [focus mode](/docs/exyliajourney/focus-mode) hides other players, blocks commands and interactions, and holds the player inside a radius, per journey or per step.

**A dialogue did not open from its trigger.** Another dialogue or a cinematic may be open (nothing opens over them), the trigger may be cooling down or already used (`cooldown`, `once`), the player may not meet the file's `require`, or an earlier dialogue by file name matched the same trigger first. `/journeyadmin dialogue list` shows the loaded ones and their triggers. See [Dialogues](/docs/exyliajourney/dialogues#triggers).
