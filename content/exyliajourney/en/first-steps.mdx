## The demo, in one command

Stand somewhere open, as an operator, and run:

```
/journeyadmin demo
```

The plugin writes a complete example around you and starts it for you at once:

| File | What it is |
|---|---|
| `journeys/demo.yml` | *First steps*, six steps, one of every common kind. |
| `cinematics/demo-orbit.yml` | Eight shots circling you, three subtitles and two sounds. |
| `routes/demo-path.yml` | A curved path from where you stand to the guide. |
| `config.yml` → `npcs.demo-guide` | A guide NPC about twenty blocks ahead of you. |

The journey then walks you through:

1. **Watch the introduction** — the cinematic plays (`WATCH_CINEMATIC`).
2. **Follow the trail** — footprints and a beacon lead to the guide (`REACH` with a trail).
3. **Talk to the guide** — right-click the NPC, which glows for you (`INTERACT_NPC`).
4. **Break three blocks** — any block counts (`BREAK_BLOCK`).
5. **Open your journey** — type `/journey` (`RUN_COMMAND`).
6. **Take a breath** — five seconds you cannot skip (`WAIT`).

Finishing it pays 50 experience and plays the celebration. The demo journey is repeatable and starts only
from a command or the `demo:start` key, so it never reaches your players on its own. Run the command again
to rebuild it where you stand.

<Callout type="note" title="Without PacketEvents">
The demo still runs, with chat and particle guidance, but the guide NPC cannot be shown: the plugin tells
you so and gives you the command that finishes that step, `/journeyadmin trigger <you> npc:demo-guide`.
</Callout>

## Your first journey

<Steps>
  <Step title="Open the editor">
    Run `/journeyadmin`. Every journey file is listed; click **CREATE JOURNEY**, type an id
    (`welcome`) and a name. The journey is created with one step, *Find the meeting point*: a `REACH`
    where you are standing.
  </Step>
  <Step title="Add the steps">
    **STEPS** → **ADD STEP**, pick an objective type, then fill the objective from its screen: the place
    (left-click **PLACE** sets where you stand), the NPC, the filter of blocks or items, the amount.
  </Step>
  <Step title="Show the way">
    On each step, **GUIDANCE**: the text panel, the beacon and its label, a trail along a recorded route,
    the waypoint, the glow and a cinematic to open the step. See [Guidance](/docs/exyliajourney/guidance).
  </Step>
  <Step title="Decide when it starts">
    **TRIGGERS** → **ADD TRIGGER**. For onboarding, `FIRST_JOIN`. A new journey has no trigger, so nobody
    gets it until you add one.
  </Step>
  <Step title="Reward it">
    **REWARDS & EFFECTS** for the journey, and **EFFECTS & REWARDS** on each step.
  </Step>
  <Step title="Test it">
    **TEST ON YOURSELF** starts the live version for you, ignoring its requirements and cooldown. **CHECK**
    lists anything the plugin could not read.
  </Step>
</Steps>

Every click is written back to `journeys/<id>.yml` and goes live at once, with no reload. See
[The editor](/docs/exyliajourney/editor).

## What a fresh install does

Nothing reaches players until you say so: `journeys/example.yml` ships with `enabled: false`, and the demo
only starts from a command. Once a journey is enabled with a trigger, players get it.

| What | Default |
|---|---|
| Who can open `/journey` | Everybody (`exyliajourney.use`) |
| Who can edit | Operators (`exyliajourney.admin`) |
| First-join journeys start | 3 seconds after joining, so the world has loaded |
| Hints | After 45 seconds idle on a step |
| A step counts as abandoned | After 7 days with no progress |
| Cinematic viewers far away | Moved next to the scene beyond 96 blocks, then put back |
