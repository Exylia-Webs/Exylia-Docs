Two different systems answer two different questions, and both have to say yes.

| System | Question | Where it lives |
|---|---|---|
| Server permissions | *May this player run this command at all?* | LuckPerms, the nodes below |
| Rank permissions | *May this member do this inside their clan?* | The clan's own ranks — see [Roles](/docs/exyliaclans/roles) |

Granting `exyliaclans.commands.kick` does not let anybody kick anybody: it lets them run the command,
which then checks their rank for `KICK`.

## Command nodes

Every node is declared in `plugin.yml`, so a permission plugin lists and tab-completes them all. Every
command node defaults to **`true`**: out of the box every player can run every `/clan` subcommand, and
what they may actually do is decided by their rank inside the clan. `exyliaclans.commands.*` is declared
too, with every command node as a child — negate it, or single nodes, to take commands away.

## The bypass

| Permission | Description |
|---|---|
| `exyliaclans.claim.bypass` | Ignore every claim protection check under `BUILTIN`: build, break, doors, containers, buckets and item frames, in anybody's claim. Defaults to `op`. |

<Callout type="danger" title="Give this to staff only, and know what it does not cover">
It is deliberately outside the `commands` branch, so `exyliaclans.commands.*` does not include it. It
also does not stop WorldGuard: under `protection-mode: WORLDGUARD` the region is what refuses the build,
and a WorldGuard bypass is what gets past it.
</Callout>

## Admin nodes

`exyliaclans.admin` is checked on `/clanadmin` itself, and every subcommand checks its own node **on top
of** it. All of them default to `op`.

<Callout type="warning" title="`exyliaclans.admin` grants every subcommand">
It is declared with every admin node as a child, so granting it alone hands out the whole of
`/clanadmin`. For a narrower staff rank, grant `exyliaclans.admin` and set the subcommands it should not
have to `false`.
</Callout>

| Permission | Description |
|---|---|
| `exyliaclans.admin` | `/clanadmin` at all — required alongside every node below, and parent of all of them |
| `exyliaclans.admin.forcekick` | Remove any player from their clan |
| `exyliaclans.admin.forcejoin` | Put an online player into any clan |
| `exyliaclans.admin.forceleader` | Make a player the leader of a clan |
| `exyliaclans.admin.disband` | Disband any clan, whatever its DTR |
| `exyliaclans.admin.rename` | Rename any clan |
| `exyliaclans.admin.setbalance` | Set, add to or take from any clan's bank |
| `exyliaclans.admin.setdtr` | Set any clan's DTR |
| `exyliaclans.admin.setexp` | Set any clan's EXP |
| `exyliaclans.admin.setlevel` | Set any clan's level |
| `exyliaclans.admin.setslots` | Grant any clan extra member slots. |
| `exyliaclans.admin.stats` | `playerstat` and `clanstat` |
| `exyliaclans.admin.addally` | Force an alliance between two clans |
| `exyliaclans.admin.removeally` | Break one |
| `exyliaclans.admin.addrival` | Force a rivalry |
| `exyliaclans.admin.removerival` | Remove one |
| `exyliaclans.admin.ban` | Ban a player from a named clan |
| `exyliaclans.admin.unban` | Unban them |
| `exyliaclans.admin.info` | Full clan info, including balance and DTR |
| `exyliaclans.admin.logs` | Any clan's audit trail |
| `exyliaclans.admin.reload` | Reload the five config files and the menus |

## A suggested setup

The command nodes need nothing: they are open by default. Staff ranks are the base node with what they
should **not** have negated:

```yaml
helper:
  - exyliaclans.admin
  - exyliaclans.admin.forcekick: false
  - exyliaclans.admin.forcejoin: false
  - exyliaclans.admin.forceleader: false
  - exyliaclans.admin.disband: false
  - exyliaclans.admin.rename: false
  - exyliaclans.admin.setbalance: false
  - exyliaclans.admin.setdtr: false
  - exyliaclans.admin.setexp: false
  - exyliaclans.admin.setlevel: false
  - exyliaclans.admin.setslots: false
  - exyliaclans.admin.stats: false
  - exyliaclans.admin.addally: false
  - exyliaclans.admin.removeally: false
  - exyliaclans.admin.addrival: false
  - exyliaclans.admin.removerival: false
  - exyliaclans.admin.ban: false
  - exyliaclans.admin.unban: false
  - exyliaclans.admin.reload: false

admin:
  - exyliaclans.admin
  - exyliaclans.claim.bypass
```

That helper keeps `info` and `logs`.

<Callout type="tip" title="Split the economy nodes from the moderation ones">
`setbalance`, `setexp` and `setlevel` hand out progression, and `stats` rewrites the leaderboard. They
belong with whoever is trusted with the economy, which is not always whoever handles reports.
</Callout>

## No permission is needed for

Being in a clan, reading clan chat, receiving mail, being invited, appearing on the leaderboard, being
coloured as a friend or an enemy, and every rank permission the clan grants you. Those are all decided
inside the clan, not by the server's permission plugin.
