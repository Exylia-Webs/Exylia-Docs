Four commands. Every subcommand checks a **server permission** (a LuckPerms node) and, where it acts on
the clan, a **rank permission** (the clan's own). Both have to pass. The forms that only leave, decline,
cancel or remove check no node at all (shown as — below), so a player can always undo what they are in.

<Callout type="note" title="Several of these open a menu rather than acting">
`/clan` opens the main menu — a different one depending on whether you are in a clan. `/clan disband`
and `/clan leave` open a confirmation, once they have checked you are in a clan and (for disband) its
leader, or (for leave) not its leader. `/clan webhook` opens the [webhook menu](/docs/exyliaclans/webhooks)
and `/clan webhook remove` its confirmation; `/clan webhook set` asks for the URL privately.
`/clan promote` and `/clan demote` both open the same **assign
rank** menu, so the two words are a convenience rather than two operations. `/clan info` and `/clan top`
open the info and leaderboard screens. `/clan war` opens the clan's war hub, and `/clan war declare` and
`accept` open the war setup and roster screens — see [Clan wars](/docs/exyliaclans/clan-wars).
</Callout>

### /clan style

The leader draws the clan's name in colour. The name players type stays the same: the styled text must
read **exactly** as the name, ignoring case, and only its colours and formats may change. A clan called
`Nova` can be styled `<gradient:#8a51c4:#59a4ff>Nova</gradient>` or `&b&lNOVA`, never `Nova!`.

```text
/clan style                    shows the usage and the name to match
/clan style <gradient:#8a51c4:#59a4ff>Nova</gradient>
/clan style reset              back to the plain name
```

What a leader may use is decided by the [style nodes](/docs/exyliaclans/permissions#style-nodes), which
default to `op`: one named colour, hex, several colours or a gradient, and bold/italic/underlined/
strikethrough each need their own. Obfuscated text, clicks, hovers and placeholders are always refused,
and the style is capped at 512 characters. The styled name is what messages and menus show; it is
stored in the `styled_name` column of `clans`, and `%exyliaclans_clan_display%` gives it to other plugins.
Staff set or clear it for any clan with `/clanadmin style` and `unstyle`.

Tab completion is contextual throughout: `/clan invite` suggests players you can actually invite,
`/clan ally accept` suggests only clans with a request pending on you, `/clan unban` suggests only players
your clan has banned.

### Anti-spam waits

Four actions that notify other players are spaced out, so a loop cannot flood chat with broadcasts and
sounds:

| Action | Wait | Key |
|---|---|---|
| `/clan create` | Per player, between two clans created | `settings.create-cooldown-seconds`, 120 |
| `/clan invite` | Per clan, before inviting the **same** player again | `settings.invite-cooldown-seconds`, 60 |
| `/clan mail send` / `sendclan` | Per player, between two mails | `mail.send-cooldown-seconds`, 30 |
| `/clan rival add` | The declared-on clan is told at most once every two minutes per declaring clan | fixed |

`0` turns any of the three configurable waits off. The waits live in memory, per server.

## /clanadmin

**Aliases:** `/cadmin` · **Base node:** `exyliaclans.admin`

The base node is checked on the command itself, and each subcommand checks its own on top. A staff member
needs **both**.

| Command | Node |
|---|---|
| `/clanadmin forcekick <player>` | `…admin.forcekick` |
| `/clanadmin forcejoin <player> <clan>` | `…admin.forcejoin` |
| `/clanadmin forceleader <player> <clan>` | `…admin.forceleader` |
| `/clanadmin disband <clan>` | `…admin.disband` |
| `/clanadmin rename <clan> <newName>` | `…admin.rename` |
| `/clanadmin style <clan> <styled name>` | `…admin.style` |

| `/clanadmin setbalance <clan> <SET\|ADD\|REMOVE> <amount>` | `…admin.setbalance` |
| `/clanadmin setdtr <clan> <SET\|ADD\|REMOVE> <value>` | `…admin.setdtr` |
| `/clanadmin setexp <clan> <SET\|ADD\|REMOVE> <value>` | `…admin.setexp` |
| `/clanadmin setlevel <clan> <level>` | `…admin.setlevel` |
| `/clanadmin setslots <clan> <SET\|ADD\|REMOVE> <amount>` | `…admin.setslots` |
| `/clanadmin playerstat <player> <KILLS\|DEATHS\|PLAYTIME> <SET\|ADD\|REMOVE> <value>` | `…admin.stats` |
| `/clanadmin clanstat <clan> <KILLS\|DEATHS\|PLAYTIME> <SET\|ADD\|REMOVE> <value>` | `…admin.stats` |
| `/clanadmin addally <clanA> <clanB>` | `…admin.addally` |
| `/clanadmin removeally <clanA> <clanB>` | `…admin.removeally` |
| `/clanadmin addrival <clanA> <clanB>` | `…admin.addrival` |
| `/clanadmin removerival <clanA> <clanB>` | `…admin.removerival` |
| `/clanadmin ban <player> <clan>` | `…admin.ban` |
| `/clanadmin unban <player> <clan>` | `…admin.unban` |
| `/clanadmin info <clan>` | `…admin.info` |
| `/clanadmin logs <clan> [amount]` | `…admin.logs` |
| `/clanadmin reload` | `…admin.reload` |
| `/clanadmin war …` | `…admin.war` |

`/clanadmin` runs from the console as well as in game, except where it needs an online player —
`forcejoin` says so explicitly.

In game, several of these open the admin menus instead of printing: `/clanadmin` alone opens a paginated
list of every clan (with a search, a button to the war setup and a **Settings** button that opens
the in-game settings hub, behind `exyliaclans.admin`), `/clanadmin info <clan>` opens that
clan's admin hub — values, members, relations, bans, logs and a disband button — and `/clanadmin disband`
asks for confirmation first. From the console, `disband` needs `confirm` as a last argument:
`/clanadmin disband <clan> confirm`. The `/clanadmin war` arena and kit commands are on the
[Clan wars](/docs/exyliaclans/clan-wars#setting-up-arenas) page.

| Detail | Behaviour |
|---|---|
| `rename` | The new name must pass the same rules as `/clan create` (length and characters), or it is refused with `errors.name-invalid`. A rename that only changes case keeps the style; any other rename drops it. |
| `style` | Same match rule as `/clan style`, but staff are not held to the style nodes. |
| `setbalance` | Floored at zero. In the currency of `bank-currency`. |
| `setdtr` | Clamped at the clan's current maximum only — there is no lower bound, so a negative value goes through. It also clears the DTR freeze. |
| `setlevel` | Sets the EXP to that level's `required-exp`. A level not in the table is refused with `admin.invalid-level`. Needs the `levels` module. |
| `setslots` | Extra member slots on top of `max-members` and the level bonus. Floored at zero. Replies with the clan's new member cap. Lowering it removes nobody: a clan over the cap just cannot recruit. |
| `playerstat` / `clanstat` | `PLAYTIME` is in seconds. Floored at zero. |
| `logs` | Defaults to 20 entries. Needs the `logs` module. |
| `forcekick` | Disbands the clan if the player kicked was its last member. |

All of these bypass rank permissions and the DTR state checks that gate the player-facing versions.

There is no `/clanadmin` command to wipe the plugin or reset a player. Every table is classified for
ExyliaLib, so `/exylialib wipe ExyliaClans <table|all>` and `/exylialib resetplayer <player> [ExyliaClans]`
cover it — see [ExyliaLib commands](/docs/exylialib/commands) and [Database](/docs/exyliaclans/database).

## Reload

`/clanadmin reload` re-reads `config.yml` and `wars.yml`, and `messages.yml`, `webhooks.yml`, `lfc.yml` and
`lfp.yml` from the language folder `config.yml` names — so a changed `language` takes effect without a
restart — rebuilds
the level table, starts the modules you switched on and stops the ones you switched off, re-reads the
recruitment categories, applies a changed `visibility-mode` to everybody online, and recompiles every
menu. `/exylialib reload` also recompiles the menus, so a palette change made through
the library reaches them.
