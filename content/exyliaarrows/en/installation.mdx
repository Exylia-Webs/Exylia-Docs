## Installing

<Steps>
  <Step title="Drop in the jars">
    `ExyliaArrows.jar` and `packetevents` into `plugins/`. `ExyliaLib` is a soft depend — the
    loader installs it on the first start if it is not there.
  </Step>
  <Step title="Start the server">
    It writes `config.yml`, `effects.yml`, `database.yml` and the `lang/` folders with the menus and
    messages in English, Spanish, Portuguese, French and Russian, and creates its tables.
  </Step>
  <Step title="Grant the permissions">
    Nothing is usable until players can open the menu and own at least one effect. See
    [Permissions](/docs/exyliaarrows/permissions).
  </Step>
</Steps>

## Files

| File | Contents |
|---|---|
| `config.yml` | The language, behaviour, projectiles, trails, the items' materials, rarities, the crate, the preview stage, showcases, feedback, visibility and the shop. |
| `effects.yml` | The six categories and the 120 effects. Hand-written, not schema-managed: your comments and your layout survive a reload. |
| `lang/<code>/messages.yml` | Every message, plus the items' names and lore, the bow lines and the menu's wording. |
| `lang/<code>/menus/effects.yml` | The main screen: tabs, grid, templates and buttons. |
| `lang/<code>/menus/crate.yml` | The crate's first screen: how many to open at once. |
| `lang/<code>/menus/crate_open.yml` | The reels falling, one column per crate. |
| `database.yml` | Where selections are stored. H2 by default. |

`<code>` is the `language` in `config.yml` — see [Configuration](/docs/exyliaarrows/configuration#language).

<Callout type="note" title="effects.yml is yours">
`config.yml` is written from a schema, so an unknown key is dropped and comments are regenerated.
`effects.yml` is not: it is a catalogue a server owner curates, and it is read exactly as written. An
update adds the effects it ships that your file does not have yet, comments included; a value you
changed is never touched, and a shipped value that changed under one you left alone is listed in
`/exylialib updates` for you to apply or keep.
</Callout>

## The tables

`arrows_players`, one row per player:

| Column | What it holds |
|---|---|
| `uuid` | The player. |
| `name` | Their last known name. |
| `effectId` | The effect they chose, or empty. |
| `particleVisibility` | `ALL`, `NONE`, `SELF_ONLY` or `OTHERS_ONLY`. |
| `favourites` | The effects they starred, comma-separated, in their own order. |
| `unlocked` / `crate_keys` | What the crate kept here up to 1.3.0. Read once per player and never written again. |
| `created_at` / `updated_at` | When the row was made and last written. |

Crate keys and the effects a player won or bought live in ExyliaLib's `exylia_crate_players`, in the
same database, one row per player per plugin. The first time a player is seen after updating, their
old `crate_keys` and `unlocked` are carried across, so nobody loses a key or an effect; the old
columns are left in place so a rollback still finds them.

Ids are stored lowercase and read back without regard to case, so a row written by an older version —
which stored them in upper case — still resolves.

A starred id the catalogue no longer declares is **kept** in the column and dropped where it is drawn,
so a typo in a reload does not empty anybody's shortlist.

## Updating

Replace the jar and restart. `/arrowsadmin reload` re-reads `config.yml`, `effects.yml`, the
messages and the menus without touching the rest of the server — it deliberately does not reload the library, which is
what `/exylialib reload` is for.
