Out of the box every player can open `/arrows` and use every feature, but nobody owns any effect until you give it to them. Admins get `/arrowsadmin`. The permission prefix is `exyliarrows`, with one "a".

## All permissions

<Permissions />

The five feature nodes and the crate node are declared in `plugin.yml` as `true`, so permission plugins list them. The effect, category and tier nodes are written by you: they do not exist until you type them.

## Sell effects

An effect is owned when any of these is true:

| Permission | Owns |
|---|---|
| `exyliarrows.effect.<id>` | One effect. The id is its key in `effects.yml`, in lowercase. |
| `exyliarrows.category.<id>` | Every effect in a category: `ember`, `frost`, `storm`, `void`, `prism` or `goofy`. |
| `exyliarrows.tier.<id>` | Every effect of a rarity: `common`, `rare`, `epic` or `legendary` by default. |
| `exyliarrows.effect.*` | Every effect. |

It is also owned if the player won it in [the crate](/docs/exyliaarrows/crate) or bought it in the shop. Those are saved on the player, not as permissions, so they survive a rank expiring.

With LuckPerms:

```text
/lp group vip   permission set exyliarrows.category.ember true
/lp group mvp   permission set exyliarrows.effect.ember_trail true
/lp group elite permission set exyliarrows.tier.legendary true
/lp group legend permission set exyliarrows.effect.* true
```

Each category holds twenty effects, so one category node sells twenty effects in one line.

<Callout type="warning" title="Renaming an effect changes its permission">
`EMBER_TRAIL` in `effects.yml` is `exyliarrows.effect.ember_trail`. Capital letters do not matter, but renaming the key creates a different node, and everybody with the old one loses the effect.
</Callout>

## Features as rank perks

Players hold the feature nodes (`preview`, `random`, `favourites`, `visibility`, `buy`, `crate`) by default. To make one a perk, deny it to the default group and grant it to the rank:

```text
/lp group default permission set exyliarrows.random false
/lp group vip     permission set exyliarrows.random true
/lp group vip     permission set exyliarrows.crate.multi.7 true
```

A player without the permission is told "Your rank does not include that function" (`feature-locked` in `messages.yml`). Taking an effect off, turning random off, unstarring and emptying favourites never need a permission.

`exyliarrows.crate.multi.<n>` lets a rank open up to `<n>` crates at once instead of `crate.max-at-once` (4 by default). The highest number a player holds wins, and the opening screen fits seven.

<Callout type="tip" title="Keep the menu open to everyone">
Without `exyliarrows.command.arrows` a player cannot open the catalogue, and a player who cannot see what is for sale cannot want it.
</Callout>

## Where permissions are checked

- **Choosing in the menu** needs the effect, or the player is told they do not have it.
- **At every shot** the choice is checked again. One the player no longer qualifies for is taken off right there.
- **`behaviour.hide-without-permission`** (default `false`) decides whether effects a player does not own are hidden in the menu or shown locked. Locked effects can still be previewed with `exyliarrows.preview`.
- **Tokens and bound bows never check permissions.** A token is an item you can sell or trade, so holding it is the proof. A bound bow plays its effect for whoever holds it.
