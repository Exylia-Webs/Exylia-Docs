## The nodes

| Permission | Default | Grants |
|---|---|---|
| `exyliarrows.command.arrows` | everyone | `/arrows`: the menu and the subcommands under it. |
| `exyliarrows.preview` | everyone | Watching an effect on the preview stage: `/arrows preview` and the classic menu's right click. |
| `exyliarrows.random` | everyone | Turning on a different effect on every shot. |
| `exyliarrows.favourites` | everyone | Starring effects and opening the favourites tab. |
| `exyliarrows.visibility` | everyone | Choosing whose arrow effects they see. |
| `exyliarrows.buy` | everyone | Buying effects in the [shop](/docs/exyliaarrows/configuration#shop). Without it no price is drawn, in either menu. |
| `exyliarrows.crate` | everyone | Opening the crate: its menu button, `/arrows crate` and a bound crate block. |
| `exyliarrows.crate.multi.<n>` | op | Opening up to `<n>` crates in one go instead of `crate.max-at-once`. The highest one held wins; the opening screen fits seven. |
| `exyliarrows.admin` | op | Every subcommand of `/arrowsadmin`, and editing the catalogue in game. |
| `exyliarrows.effect.<id>` | op | One effect, by its id in lowercase. |
| `exyliarrows.effect.*` | op | Every effect. |
| `exyliarrows.category.<id>` | op | Every effect in that category. |
| `exyliarrows.tier.<id>` | op | Every effect of that rarity. |

Every node is declared in `plugin.yml`, so a permissions plugin lists it with its description. The
prefix is `exyliarrows`, with one "a", as it always was.

An effect is owned if **any** of the four effect nodes applies: its own, the wildcard, its
category's, or its rarity's — or if the player won it from [the crate](/docs/exyliaarrows/crate) or
bought it from the menu's [shop](/docs/exyliaarrows/configuration#shop), both written to the player's
row instead.

## Features as rank perks

The feature nodes (`preview`, `random`, `favourites`, `visibility`, `buy`, `crate`) are held by
everybody. A server makes one a rank perk by denying it to the default group and granting it to the
rank:

```text
/lp group default permission set exyliarrows.random false
/lp group vip     permission set exyliarrows.random true
/lp group vip     permission set exyliarrows.crate.multi.7 true
```

A player without the node is told `feature-locked` when they try it. Giving something back never needs
one: taking an effect off, turning random off, unstarring and emptying the favourites always work.

## The id is the node

There is no `permission` key in `effects.yml`. The node is derived from the key, lowercased:

```text
EMBER_TRAIL  →  exyliarrows.effect.ember_trail
ember        →  exyliarrows.category.ember
legendary    →  exyliarrows.tier.legendary
```

Case is not part of it, so recapitalising a key changes nothing. Renaming one changes everything: it
is a different node, and everybody who had the old one loses the effect.

## Selling it

```text
/lp group default permission set exyliarrows.command.arrows true
/lp group vip     permission set exyliarrows.category.ember true
/lp group mvp     permission set exyliarrows.effect.ember_trail true
/lp group elite   permission set exyliarrows.tier.legendary true
/lp group legend  permission set exyliarrows.effect.* true
```

Six categories of twenty is what makes a category node worth selling: "every Ember effect" is one
line instead of twenty.

<Callout type="tip" title="Give the menu away">
Without `exyliarrows.command.arrows` the catalogue cannot be opened at all. A player who
cannot see what is for sale cannot want it.
</Callout>

## What the node is checked for

<Steps>
  <Step title="Wearing">
    Choosing an effect in the menu without its node, an unlock from the crate or a purchase is refused
    with `no-permission`. There is no switch to turn this off.
  </Step>
  <Step title="Playing what the menu chose">
    The choice is re-checked at the moment of the shot. One that no longer holds is taken off there
    and then, rather than left sitting in the menu until the next relog.
  </Step>
  <Step title="Being drawn">
    `behaviour.hide-without-permission` decides whether a locked effect is hidden in the menu or shown
    locked. Either way it can be previewed, and on the favourites tab it is always shown.
  </Step>
</Steps>

<Callout type="tip" title="What the crate hands over is not a node">
An effect won from the crate is written onto the player's own row, so it survives the rank they
never had and `validate` never takes it off. Rarity nodes and the crate are two ways of selling the
same shelf: one is rented with a rank, the other is kept. See [Rarities and the
crate](/docs/exyliaarrows/crate).
</Callout>

<Callout type="note" title="Tokens and bows are never checked">
A token is a real item: it is bought, traded and lost like any other, and holding one is the proof.
Binding it asks for no node, and a bound bow plays its effect for whoever is holding it — which is
the point of an effect you can trade. Permissions govern what a player wears out of the menu, not what
they carry in their hands.
</Callout>
