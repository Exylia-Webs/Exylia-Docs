Players use `/arrows`; admins use `/arrowsadmin`. Typing `/arrowsadmin` alone opens the admin hub, a menu with the catalogue, players, showcases and crate blocks. Every subcommand below is a shortcut to something the hub can also do.

A command in `<angle brackets>` is required, one in `[square brackets]` is optional. To let a rank use a command, see [Permissions](/docs/exyliaarrows/permissions).

## Player commands

Everything under `/arrows` needs `exyliarrows.command.arrows`, which everyone has by default. Preview, crate, random, favourites and visibility also check their own feature permission.

### Keys and unlocks

<Commands group="keys" />

<Commands group="unlocks" />

Keys are a number stored on the player, so they cannot be dropped or lost, and these commands run from the console. That is how a shop, a vote plugin or a rank reward hands them out. To reset everything a player owns, use ExyliaLib's [`/exylialib resetplayer`](/docs/exylialib/commands#resetting-a-player).

### Catalogue and maintenance

<Commands group="catalogue" />

<Callout type="note" title="bind, set, give and unlocks ignore permissions">
These are admin commands: a crate, a rank reward or a support ticket has already decided the player may have the effect. Permissions only decide what a player picks from the menu.
</Callout>

<Details title="What each command does exactly">
**`bow bind`** works on the main hand of the target. With an empty hand the plugin answers that you must hold the bow. A bow that already has an effect gets it replaced, and the old one is not returned as a token. A bow the effect does not fit (see `bows` in [Add and edit effects](/docs/exyliaarrows/effects)) is refused.

**`bow unbind`** strips the effect and gives nothing back. To give the token back, use a remover item instead.

**`player validate`** re-checks the player's choice against their permissions and takes it off if they no longer qualify. The same check runs on join, on the next shot and every time the menu opens. Use it to make a rank change take effect at once. An effect won from the crate or bought in the shop is never taken off by it.

**`preview location`** sets the one stage the whole server shares. Only the position is stored, and a preview always faces north. Until it is set, `/arrows preview` and the menu's right click tell the player previews are not set up.

**`refresh`** re-sends the inventory so the line under a bound bow is redrawn. It touches no file.

**`reload`** re-reads `config.yml`, `effects.yml`, `messages.yml`, the files in `menus/` and `spatial/effects.yml`, and recompiles every sequence. It does not reload ExyliaLib; that is `/exylialib reload`. If you renamed an effect key, that is a new effect: players wearing the old one lose it and bows bound to it stop playing.
</Details>
