`config.yml` se escribe desde un esquema: los comentarios se regeneran en cada arranque, las claves
desconocidas se descartan y una clave que borres vuelve con su valor por defecto. Guarda cómo se
comporta el plugin; cada palabra que lee un jugador está en `lang/<código>/messages.yml`, al final de
esta página.

## `language`

```yaml
language: default
```

De qué carpeta bajo `plugins/ExyliaArrows/lang/` se leen los menús y los mensajes. `default` sigue el
`language` puesto en el `config.yml` de ExyliaLib, así que una línea allí cambia todos los plugins de
Exylia; `en`, `es`, `pt`, `fr` o `ru` fijan solo este plugin. Cada idioma es una carpeta completa que
puedes editar:

```
plugins/ExyliaArrows/
  config.yml
  effects.yml
  lang/es/messages.yml
  lang/es/menus/effects.yml
  lang/es/menus/crate.yml
  lang/es/menus/crate_open.yml
```

El inglés es la base sobre la que se ponen los demás, así que una línea aún sin traducir llega en
inglés. Un `language` cambiado se aplica con `/arrowsadmin reload`.

<Callout type="note" title="Los servidores que usaban 1.3.0 conservan sus cambios">
En el primer arranque de 1.4.0 o posterior los `menus/` antiguos pasan a `lang/custom/`, cada mensaje,
nombre y lore de objeto, palabra del menú y respuesta de placeholder que antes guardaba `config.yml`
pasa a `lang/custom/messages.yml`, y `config.yml` apunta a ella con `language: custom`, así que no se
pierde nada de lo que el servidor editó. Pon `language` en `default` o en un código para pasar a las
traducciones incluidas.
</Callout>

## `behaviour`

```yaml
behaviour:
  mode: both
  consume-token: true
  consume-remover: true
  hide-without-permission: false
```

| Clave | Por defecto | Qué hace |
|---|---|---|
| `mode` | `both` | `player`, `bow` o `both`. Ver [Modos y fichas](/docs/exyliaarrows/modos-y-fichas). |
| `consume-token` | `true` | Si la ficha se gasta al atarla. |
| `consume-remover` | `true` | Si el removedor se gasta al quitar un efecto. |
| `hide-without-permission` | `false` | Si los efectos bloqueados se esconden en el menú en vez de mostrarse bloqueados. |

Elegir un efecto en el menú siempre necesita su nodo o un desbloqueo; una ficha, un arco atado, un
comando y la API nunca. Ver [Permisos](/docs/exyliaarrows/permisos).

## `projectiles`

Qué proyectiles lanzados llevan efecto.

```yaml
projectiles:
  all-types: false
  default-allowed-types:
    - ARROW
    - SPECTRAL_ARROW
    - TRIDENT
```

| Clave | Por defecto | Qué hace |
|---|---|---|
| `all-types` | `false` | `true` hace que cualquier proyectil lanzado lleve el efecto, incluidas las bolas de nieve, huevos, pociones y cañas que un jugador puede lanzar cada tick. |
| `default-allowed-types` | tres tipos | Solo se lee con `all-types` en `false` **y** cuando el efecto no declara `projectiles` propios. |

Estos son los valores que escribe una instalación nueva. Un servidor que ya tenía el archivo conserva
lo que tenía.

Sea cual sea lo permitido, el destello de lanzamiento de un jugador suena como mucho una vez cada
150 ms: una ballesta con multidisparo lanza tres tiros en el mismo tick, y un destello por ráfaga es
todo lo que se llega a ver.

## `trail`

```yaml
trail:
  default-interval: 1
  max-duration: 10
  max-active: 200
  max-active-per-player: 10
```

| Clave | Por defecto | Qué hace |
|---|---|---|
| `default-interval` | `1` | Ticks entre pasos de estela para un efecto sin `trail-interval` propio. |
| `max-duration` | `10` | Segundos que puede vivir una estela antes de cancelarse — una flecha perdida en un chunk descargado dibujaría para siempre. |
| `max-active` | `200` | Cuántas estelas pueden dibujarse a la vez en todo el servidor. Los disparos que pasen del límite siguen lanzando su launch y su impacto; simplemente no dejan estela. `0` quita el límite. |
| `max-active-per-player` | `10` | Cuántas de ellas puede tener dibujándose un mismo jugador, para que uno solo no gaste el límite de todo el servidor. `0` lo quita. |

<Callout type="tip" title="max-active existe por las ráfagas de ballesta">
Una estela es una tarea repetida y una ráfaga de paquetes por tick. Un lobby lleno disparando
ballestas es el caso para el que está el techo, y perder una estela se nota mucho menos que perder el
tick rate.
</Callout>

## `token-item`, `remover-item` y `key-item`

```yaml
token-item:
  material: FIREWORK_STAR
  glow: true

remover-item:
  material: SCRAPE_POTTERY_SHERD
  glow: true

key-item:
  material: TRIPWIRE_HOOK
  glow: true
```

`material` solo se usa cuando el efecto no trae icono propio — normalmente la ficha se dibuja con el
material del efecto. Cómo se llama cada objeto y qué dice su lore está en `messages.yml`.

`key-item` es la llave que se lleva en la mano: click derecho a un bloque de caja y se abre. Ver
[La caja](/docs/exyliaarrows/caja).

## `bow-lore`

```yaml
bow-lore:
  enabled: true
```

Si se dibujan las líneas bajo un arco atado. Se dibujan solo en paquetes — el objeto nunca las lleva —
y las líneas en sí son `bow-lore` en `messages.yml`.

## `tiers`

Las rarezas en las que se ordenan los efectos, y cada cuánto sale cada una de una caja. Añade,
renombra o borra las que quieras — la clave es el id que `effects.yml` escribe como `tier`.

```yaml
tiers:
  common:
    name: "Common"
    material: GRAY_DYE
    color: "{muted}"
    chance: 60.0
    priority: 1
  rare:
    name: "Rare"
    material: LIGHT_BLUE_DYE
    color: "{info}"
    chance: 25.0
    priority: 2
  epic:
    name: "Epic"
    material: PINK_DYE
    color: "{accent}"
    chance: 12.0
    priority: 3
  legendary:
    name: "Legendary"
    material: ORANGE_DYE
    color: "{highlight}"
    chance: 3.0
    priority: 4
```

| Clave | Por defecto | Qué hace |
|---|---|---|
| `name` | por rareza | Cómo la llaman los menús y los placeholders. |
| `material` | por rareza | Se sigue leyendo, pero nada lo dibuja desde que la caja pasó a ExyliaLib en 1.4.0. |
| `color` | por rareza | El color en el que se escriben su nombre y sus efectos. |
| `chance` | `60`, `25`, `12`, `3` | Un peso, no un porcentaje: las probabilidades salen de los pesos, así que borrar una rareza reparte sus tiradas. |
| `priority` | `1`-`4` | Dónde va en los menús; lo más bajo va primero. |

Cada rareza es además un nodo de permiso, `exyliarrows.tier.<id>`. Ver [Rarezas y el
caja](/docs/exyliaarrows/caja).

## `crate`

```yaml
crate:
  enabled: true
  start-keys: 0
  duplicate-refund: 1
  reward: UNLOCK
  blocks: []
  max-at-once: 4
  spin-frames: 34
  stagger-seconds: 2.0
  on-spin:
    sound:
      name: BLOCK_NOTE_BLOCK_HAT
      pitch: 1.6
  on-win:
    sound:
      name: ENTITY_PLAYER_LEVELUP
      pitch: 1.2
  on-duplicate:
    sound:
      name: BLOCK_NOTE_BLOCK_BASS
      pitch: 0.8
```

| Clave | Por defecto | Qué hace |
|---|---|---|
| `enabled` | `true` | Si la caja se puede abrir. Apagado, su botón lo dice en vez de abrir. |
| `start-keys` | `0` | Llaves que se le dan a un jugador la primera vez que se le ve, al crear su fila. |
| `duplicate-refund` | `1` | Llaves que se devuelven cuando una caja cae en un efecto que ya tenía. |
| `reward` | `UNLOCK` | Qué entrega la caja. `UNLOCK` deja el efecto en la cuenta, `ITEM` entrega solo su ficha, `BOTH` hace las dos. `ITEM` y `BOTH` quieren `behaviour.mode` en `bow` o `both`. |
| `blocks` | vacío | Los bloques que abren la caja al hacerles clic. Átalos con `/arrowsadmin crate block add`, no a mano. |
| `max-at-once` | `4` | Cuántas cajas se pueden abrir de una vez. La pantalla de apertura cabe siete. |
| `spin-frames` | `34` | Cuántas caras recorre el primer carrete antes de parar. Tope de 200, unos once segundos. |
| `stagger-seconds` | `2.0` | Cuánto tarda un carrete en parar después del anterior. `0` los para juntos. |
| `on-spin` / `on-win` / `on-duplicate` | sonidos | Bloques de efecto completos de ExyliaLib: título, action bar, boss bar, sonido, partícula y firework. `on-win` y `on-duplicate` suenan una vez por carrete, al parar. |

## `preview`

Dónde suenan `/arrows preview` y el clic derecho del menú. Al jugador se le lleva al escenario, el
efecto suena delante de él donde solo él lo ve, y vuelve exactamente a donde estaba.

```yaml
preview:
  location: ""
  distance: 5.0
  settle-ticks: 4
  linger-ticks: 20
  max-ticks: 600
```

| Clave | Por defecto | Qué hace |
|---|---|---|
| `location` | vacío | Dónde se pone el jugador, como `server,world,x,y,z,yaw,pitch`. Se fija en el juego con `/arrowsadmin preview location`. |
| `distance` | `5.0` | A qué distancia delante de él suena el efecto, en bloques. |
| `settle-ticks` | `4` | Cuánto esperar tras moverlo, para que el cliente tenga la posición nueva antes de la primera partícula. |
| `linger-ticks` | `20` | Cuánto se mantiene el escenario después de terminar el efecto. |
| `max-ticks` | `600` | Lo máximo que puede durar una vista previa, pase lo que pase. |

<Callout type="warning" title="No hay vistas previas hasta fijar el escenario">
No hay valor por defecto sensato — adivinarlo mete al jugador dentro del terreno. Hasta rellenar
`location`, `/arrows preview` y el clic derecho del menú lo dicen en vez de lanzar nada.
</Callout>

## `menu`

```yaml
menu:
  favourites-icon: "AMETHYST_SHARD"
```

El material con el que se dibuja la pestaña de favoritos. Cómo llama el menú a las cosas está en
`messages.yml`, y las pantallas en sí son `menus/effects.yml`, `menus/crate.yml` y
`menus/crate_open.yml` bajo `lang/<código>/` — ver [El menú](/docs/exyliaarrows/menu) y [Rarezas y la
caja](/docs/exyliaarrows/caja).

## `feedback`

```yaml
feedback:
  on-bind:
    sound:
      name: BLOCK_ENCHANTMENT_TABLE_USE
      volume: 1.0
      pitch: 1.2
  on-unbind:
    sound:
      name: BLOCK_GRINDSTONE_USE
```

Son bloques de efecto completos de ExyliaLib: título, action bar, boss bar, sonido, partícula y
firework están disponibles en cada uno. `on-bind` suena al atar un efecto a un arco **o** al elegirlo
en el menú.

## `particles`

```yaml
particles:
  default-visibility: "ALL"
```

La visibilidad con la que empieza un jugador: `ALL`, `NONE`, `SELF_ONLY` u `OTHERS_ONLY`. Cómo llaman
los menús y los placeholders a cada modo está en `messages.yml`.

## `showcase`

Sitios que lanzan efectos de flecha solos, una y otra vez, para quien pase: una pieza central de lobby
en vez de un disparo. Dos cuerpos con las skins de jugadores cercanos se miran a nueve bloques, uno
tensa un arco y el otro recibe la flecha, dos veces por turno. El lanzamiento suena en el arco, la
estela a lo largo del arco y el impacto donde cae.

```yaml
showcase:
  locations: []
  pause-seconds: 3.0
  radius: 24.0
  only: []
```

| Clave | Por defecto | Qué hace |
|---|---|---|
| `locations` | `[]` | Dónde están los showcases. Se ponen con `/arrowsadmin showcase add`, mirando hacia donde estará el público: la pareja se coloca a tu izquierda y a tu derecha para que el arco se vea de lado. |
| `pause-seconds` | `3.0` | El descanso entre que acaba un turno y empieza el siguiente. |
| `radius` | `24.0` | A qué distancia tiene que estar un jugador para que un showcase suene y se vea, en bloques. |
| `only` | `[]` | Los ids de efecto entre los que elige un showcase. Vacío elige entre todos. |

Solo se eligen efectos que vuelan en una flecha y dibujan estela o impacto; un lanzamiento solo es un
destello por el que nadie se pararía. No hay flecha real ni nadie recibe el golpe: el vuelo se simula
y se dibuja en paquetes, y las líneas que actúan sobre un jugador real (`[COMMAND]`, `[POTION]`,
`[TITLE]`, `[ACTION_BAR]`, `[MESSAGE]`, `[CAMERA]`) se quitan de lo que lanza un showcase. Sin nadie
dentro de `radius` no suena nada, así que un lobby vacío no cuesta nada.

## `shop`

Un efecto bloqueado se puede comprar directamente desde el menú con moneda. La fila muestra su precio
y un clic izquierdo pide confirmación al jugador antes de cobrar nada.

```yaml
shop:
  enabled: true
  tier-prices:
    common: 500
    rare: 1500
    epic: 4000
    legendary: 10000
```

| Clave | Por defecto | Qué hace |
|---|---|---|
| `enabled` | `true` | Si un efecto bloqueado se puede comprar desde el menú. |
| `tier-prices` | `500` / `1500` / `4000` / `10000` | Lo que cuesta un efecto según su rareza, en la moneda por defecto. Una rareza que falte no está a la venta. |

Un precio es un número (`500`, `2.5k`) o un bloque que nombra una moneda: `{amount: 50, currency: gems}`.
Un efecto en `effects.yml` puede poner su propio `price`, que gana al de su rareza. El dinero lo cobra
ExyliaEconomy o Vault; sin ninguno de los dos, o con la tienda apagada, los efectos bloqueados se ven
exactamente como siempre.

Un efecto comprado queda desbloqueado en la cuenta, igual que uno ganado en [la caja](/docs/exyliaarrows/caja):
sobrevive a un rango y no se puede intercambiar. Una compra que no se pudo entregar devuelve el
dinero. La confirmación y cada respuesta que envía son líneas propias de ExyliaLib, bajo `purchase` en
el `messages.yml` de ExyliaLib, compartidas por todos los plugins cosméticos.

## `messages.yml`

Todas las líneas que envía el plugin, y cada palabra que dibuja un objeto o el menú, en
`lang/<código>/messages.yml`. `prefix` es `{primary}&lE-ARROWS &8•&r ` y el resto de mensajes empieza
con `%prefix%`.

| Clave | Cuándo se envía |
|---|---|
| `bound` | Se ató un efecto a un arco. |
| `unbound` | Se desató y se devolvió. |
| `chosen` | Se eligió un efecto en el menú. |
| `cleared` | Se quitó el efecto. |
| `not-a-bow` | El objeto no puede llevar un efecto. |
| `wrong-bow` | El efecto no encaja en esa arco. |
| `unknown-effect` | El id no nombra nada declarado. |
| `already-bound` | El arco ya lleva un efecto. |
| `no-effect` | El arco no lleva ninguno. |
| `inventory-full` | Un removedor necesita un hueco libre. |
| `no-permission` | El jugador no tiene el efecto. |
| `empty-hand` | Un subcomando de mano con la mano vacía. |
| `given` / `given-remover` / `given-key` | Se dieron fichas, removedores o llaves. |
| `rewards-claimed` | Se entregaron al entrar objetos que no cabían y estaban esperando. |
| `list-header` / `list-entry` / `list-empty` | `/arrowsadmin list`. |
| `visibility-set` | Cambió la visibilidad. |
| `refreshed` | Terminó `refresh` o `validate`. |
| `menu-disabled` | Se abrió el menú en un servidor `bow`. |
| `favourite-added` / `favourite-removed` / `favourites-cleared` / `favourites-empty` | La lista de favoritos. |
| `random-chosen` | Se puso que cada disparo saque un efecto distinto. |
| `crate-won` / `crate-duplicate` / `crate-no-keys` | Una caja cayó en algo nuevo, en algo que ya tenía, o no se pudo pagar. |
| `crate-busy` / `crate-empty` / `crate-disabled` | Ya hay una caja cayendo, no hay nada que entregar, o está apagado. |
| `keys-received` / `keys-taken` / `keys-given` | Cambiaron de manos unas llaves. |
| `unlock-granted` / `unlock-already` / `unlock-revoked` / `unlocks-cleared` | `/arrowsadmin unlocks`. |
| `crate-block-*` / `crate-blocks-*` | `/arrowsadmin crate block`. |
| `preview-location-set` / `preview-unavailable` / `preview-unavailable-admin` | El escenario de vistas previas. |
| `showcase-*` / `showcases-*` | `/arrowsadmin showcase`. |

Placeholders en los mensajes: `%effect%`, `%amount%`, `%id%`, `%visibility%`, `%keys%`, `%player%`,
`%location%` y `%prefix%`.

Debajo de los mensajes, las palabras que se dibujan en vez de enviarse:

| Clave | Qué es |
|---|---|
| `token-item`, `remover-item`, `key-item` | El `name` y el `lore` de cada objeto. En la ficha, `%effect%` es el nombre del efecto y `%bows%` a qué encaja. |
| `bow-lore` | Las líneas bajo un arco atado. `%effect%` es el nombre del efecto. |
| `menu` | Cómo llama el menú a las cosas: `empty`, `tab-open`, `tab-closed`, `bows-any`, `bow-names`, `favourites-name`, `favourite-on`, `favourite-off`, `random-name`, `random-on`, `random-off`. |
| `particles` | Cómo se llama cada modo de visibilidad: `name-all`, `name-none`, `name-self-only`, `name-others-only`. |
| `placeholders` | `none`, lo que responde cualquier `%exyliarrows_...%` cuando no hay valor, y `unknown`, lo que responde uno que nombra algo que ya no existe. |

`menu.bow-names` es cómo se escribe un arco allá donde se dibuje `%bows%`, por familia (`bow`,
`crossbow`, `trident`, `ranged`) o por id de objeto. Lo que falte se escribe a partir de su id.
