Por defecto, todos los jugadores pueden llevar todas las clases que vienen con el plugin. Solo los admins tienen los dos comandos de staff. Usa esta página para restringir clases.

## Vender una clase a un rango

Cada archivo de clase nombra el nodo que necesita el jugador, en su clave `permission`. Los seis archivos incluidos usan `exyliaclasses.class.<id>` (por ejemplo `exyliaclasses.class.bard`), que todos tienen por defecto. Para vender una clase, niega su nodo al grupo por defecto y concédelo al rango. Con LuckPerms:

```text
/lp group default permission set exyliaclasses.class.bard false
/lp group default permission set exyliaclasses.class.rogue false
/lp group vip permission set exyliaclasses.class.bard true
/lp group vip permission set exyliaclasses.class.rogue true
```

Un jugador que viste la armadura sin el nodo ve el mensaje `no-permission` y no empieza ningún warmup. No está en ninguna clase, y no se prueba otra clase en su lugar.

## La clave `permission` de un archivo de clase

| Valor | Significado |
|---|---|
| `"NONE"` | Cualquiera puede llevar la clase. |
| Vacío, o sin la clave | Igual que `NONE`. |
| Cualquier otro texto | Un nodo que el jugador debe tener, comprobado tal como está escrito. |

Un servidor que ya tenía archivos de clase conserva el `NONE` que tenía. Cambia la clave en el archivo para restringir esa clase. Un nodo que te inventes para una clase propia no lo registra nada, así que elige un esquema de nombres y respétalo.

<Callout type="tip" title="Los comodines dependen de tus nombres">
`exyliaclasses.class.*` cubre todas las clases solo si todos los archivos usan ese prefijo. Un archivo que diga `permission: "ranks.premium"` se comprueba exactamente como está escrito.
</Callout>

<Callout type="warning" title="Una clase restringida es un set de armadura muerto">
Un jugador sin el nodo no puede entrar en la clase, ni en ninguna otra con esa armadura. Si dos clases pudieran compartir set, da a la gratuita un set distinto.
</Callout>
