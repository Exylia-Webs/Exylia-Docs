## Commands

| Command | Permission | What it does |
|---|---|---|
| `/classesadmin reload` | `exyliaclasses.admin.reload` | Re-reads the configuration and every class file. |
| `/classesadmin settings` | `exyliaclasses.admin.settings` | Opens the in-game settings: one page for the energy bar and one for the mark bar. |

Staff commands live under `/classesadmin`. The old spellings `/classes <command>`, `/eclasses <command>` and `/exyliaclasses <command>` still work as aliases.

<Callout type="note" title="There is nothing for players to type">
Classes are entered by wearing armour and used by right-clicking items. No command opens a menu,
grants a class or shows a list — there is no player-facing command at all.
</Callout>

## What reload covers

`/classesadmin reload` runs five steps in order:

<Steps>
  <Step title="Configuration files">
    `config.yml` and `lang/<language>/messages.yml` are re-read from disk.
  </Step>
  <Step title="The message prefix">
    Re-applied from `messages.yml`, so `%prefix%` in other Exylia plugins' text matches.
  </Step>
  <Step title="The debug flag">
    Picked up from `config.yml` without a restart.
  </Step>
  <Step title="Class definitions">
    Every `.yml` in the language's `classes/` folder is loaded again. New files appear, deleted files disappear, and any of
    the six defaults that went missing are written back.
  </Step>
  <Step title="Online players">
    Everyone online has their class removed and is then matched against the new definitions. A player
    whose armour still fits a class starts that class's warmup again.
  </Step>
</Steps>

Each step reports success or failure separately, so a broken class file names itself instead of
failing the whole reload.

<Callout type="warning" title="Reloading interrupts everyone">
Step five removes the class before re-matching, which clears energy and marks for every player online
(ability cooldowns keep running), and starts a fresh warmup for anyone whose armour still fits. Reload between
fights, not during one.
</Callout>

## Settings

`/classesadmin settings` opens a hub with one card per boss bar. Each opens a page where an admin
switches the bar on or off and picks its colour and segments (`energy-bar` and `mark-bar` in
`config.yml`); the current value and its default are on each card. Everything else (language, debug,
the class files) stays in its file.

It does not reload ExyliaLib — `/exylialib reload` is what does that.
