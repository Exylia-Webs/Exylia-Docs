ExyliaLink downloads new releases by itself and installs them for the next restart. You only restart; nothing else to do.

## How it works

<Steps>
  <Step title="It checks">
    About 30 seconds after start and every 6 hours after that, off the server's main thread, it asks GitHub for the latest release of [Exylia-Plugins/ExyliaLink](https://github.com/Exylia-Plugins/ExyliaLink/releases).
  </Step>
  <Step title="It verifies">
    A newer release of the same major version is downloaded and its SHA-256 is checked against the release's `ExyliaLink.jar.sha256`. A jar whose checksum does not match is discarded.
  </Step>
  <Step title="It installs for the restart">
    On Paper, Spigot and Folia the jar goes into the server's update folder (`plugins/update/` by default) under the running jar's file name, and the server swaps it in on the next start. On Velocity and BungeeCord the new jar replaces the running one, and the next start loads it.
  </Step>
  <Step title="It tells you">
    The console says once which version a restart applies. Players with `exylialink.admin` are told when they join.
  </Step>
</Steps>

## What it never does

- It never downgrades, and it ignores pre-releases.
- It never installs a new **major** version (2.0.0 after 1.x). A major version can change the config or the protocol, so the console and admins are only told, with the download link. Install it by hand when you are ready.
- It never runs on a server thread.

## Only be told

Set `auto-update: false` in `config.yml` and run `/linkadmin reload`. ExyliaLink still checks, but only tells admins and the console that a new version is out. See [Configuration](/docs/exylialink/configuration).

## Update by hand

Download `ExyliaLink.jar` from the [releases](https://github.com/Exylia-Plugins/ExyliaLink/releases), replace the jar and restart. Your `config.yml`, messages and `network.dat` are kept.

## Check that it works

Run `/linkadmin status`. If it reads **Update ExyliaLink**, the network no longer accepts this version: update and restart. After a restart, the console line `ExyliaLink <version> enabled` names the version running.

<Details title="When updates do not arrive">

GitHub limits unauthenticated requests. When it answers with a rate limit, ExyliaLink waits until the limit lifts (or an hour) before it checks again. A failed download is tried again at the next check. Run with `debug: true` to see the reasons in the console. See [Common problems](/docs/exylialink/troubleshooting).

</Details>
