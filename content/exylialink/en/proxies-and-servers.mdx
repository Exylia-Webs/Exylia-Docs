You can install ExyliaLink on the proxy, on the game servers, or on both. The same jar runs everywhere, and ExyliaLink works out by itself who talks to players.

## Choose where to install

| Setup | What you get |
|---|---|
| Proxy only | Linking, requirements and the dashboard presence for the whole network. The proxy also reports which backend each player is on. |
| Game servers only | Everything per server. Rewards run as console commands on the server that receives them. |
| Both | The proxy warns, reminds and blocks; the game servers stay quiet but still report presence, run rewards and answer `/link`. |

Platforms: Paper, Spigot 1.17+ and Folia on game servers; Velocity 3, BungeeCord and Waterfall on proxies.

## Who talks to players

While a proxy of the network is connected, the gateway tells every connection, and:

- **The proxy** sends the link and unlink messages, the requirement warnings and reminders, and blocks restricted commands before they reach a backend.
- **Game servers** stay silent toward players: no link or unlink messages, no warnings, no reminders, no command blocking. They still report who is online, run rewards and answer `/link` if a player reaches it.

Without a proxy, or while the state is unknown, game servers behave as if they were alone: they warn, remind and block themselves. `/linkadmin status` shows the **Role** of each install: **Proxy**, **Game server** or **Game server (the proxy talks to players)**.

## Choose a server id

`server-id` in `config.yml` is the name the dashboard uses for each install. Make it stable and different on every server and proxy.

- Left empty, the first start fills it in: with the `server-id` from ExyliaLib's Redis settings when it is set (not the shipped `server-1`), `proxy` on a proxy, or a random one such as `server-x7k2pq`.
- With more than one proxy, give each its own.
- The dashboard shows presence per id, for example "on survival via velocity".

## Connect each install

<Steps>
  <Step title="Install the jar">
    On every proxy and game server that should be on the network.
  </Step>
  <Step title="Connect it">
    Run `/linkadmin connect` on each one and approve the code on [link.exylia.net](https://link.exylia.net). See [Your first linked account](/docs/exylialink/first-steps).
  </Step>
  <Step title="Check the role">
    Run `/linkadmin status` on each and read **Role** and **Server id**.
  </Step>
</Steps>

## Rewards and the proxy

A reward rule on the dashboard has a target: game servers (console commands there) or the proxy (proxy console commands). ExyliaLink runs whatever the gateway routes to it. See [Rewards](/docs/exylialink/rewards).

## Permissions on a proxy

On proxies `exylialink.link` is granted to everyone unless your permission plugin denies it explicitly. `exylialink.admin` and `exylialink.requirements.bypass` need a grant. See [Permissions](/docs/exylialink/permissions).
