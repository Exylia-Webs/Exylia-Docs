---
title: "Comandos"
description: "Cada comando que registra ExyliaSurvivalCore, sus argumentos, sus alias, el nodo que comprueba y lo que hace."
---

Los comandos los registra al arrancar el módulo que los posee, así que un módulo apagado no tiene
comandos. Cambiar un interruptor de módulo en `config.yml` necesita un reinicio para que sus comandos
aparezcan o desaparezcan.

`<x>` es obligatorio, `[x]` opcional. El permiso escrito en un comando vale para todos sus subcomandos
salvo que el subcomando nombre el suyo. Los nodos están declarados en `plugin.yml` y se explican en
[Permisos](/docs/exyliasurvivalcore/permisos); un nodo escrito aquí sin prefijo empieza por
`exyliasurvivalcore.`.

<Callout type="note" title="Raíces de administración">
La raíz de staff del propio plugin es `/survivalcoreadmin`. Cada módulo con herramientas de staff
mantiene su propio comando de administración (`/kitadmin`, `/warpadmin`, `/rtpadmin`…), listado bajo ese
módulo más abajo.
</Callout>

Los módulos que pasaron a sus propios plugins ya no aparecen aquí: mira
[ExyliaEconomy](/docs/exyliaeconomy/introduccion), [ExyliaMarket](/docs/exyliamarket/introduccion),
[ExyliaProtections](/docs/exyliaprotections/introduccion), [ExyliaRewards](/docs/exyliarewards/introduccion),
[ExyliaCombat](/docs/exyliacombat/introduccion), [ExyliaWarzone](/docs/exyliawarzone/introduccion),
[ExyliaCrates](/docs/exyliacrates/introduccion), [ExyliaMines](/docs/exyliamines/introduccion),
[ExyliaGraves](/docs/exyliagraves/introduccion), [ExyliaPlayerVaults](/docs/exyliaplayervaults/introduccion)
y [ExyliaMobs](/docs/exyliamobs/introduccion).

## Núcleo

| Comando | Alias | Permiso | Qué hace |
|---|---|---|---|
| `/survivalcoreadmin` | `/survivalcore` | `survivalcore.admin` | Abre el hub de administración en el juego, imprime la línea de uso desde la consola |
| `/survivalcoreadmin reload` | `/survivalcore reload` | `survivalcore.admin.reload` | Recarga este plugin |
| `/survivalcoreadmin setspawn` | `/setspawn` | `spawn.set` | Pone el spawn donde estás |
| `/survivalcoreadmin itemupdater` | `/itemupdater`, `/iu` | `itemupdater.admin` | Abre el editor del actualizador de objetos |
| `/survivalcoreadmin itemupdater run` | `/itemupdater run`, `/iu run` | `itemupdater.admin` | Comprueba ahora a todos los jugadores conectados |

`reload` funciona también desde consola. Recarga las configuraciones, los ajustes de los módulos y los
menús — no los interruptores de módulo. Cuando un interruptor de `config.yml` ya no coincide con lo que
está en marcha, la respuesta nombra esos módulos como pendientes de reinicio.

### TPA

| Comando | Alias | Permiso | Qué hace |
|---|---|---|---|
| `/tpa <jugador>` | | `tpa` | Pide ir hasta un jugador, en cualquier servidor de la red |
| `/tpahere <jugador>` | | `tpa.here` | Pide a un jugador que venga contigo |
| `/tpaccept [jugador]` | `/tpaaccept`, `/tpyes` | `tpa.accept` | Acepta la petición de ese jugador, o la última |
| `/tpadeny [jugador]` | `/tpdeny`, `/tpno` | ninguno | Rechaza la petición de ese jugador, o la última |
| `/tpacancel [jugador]` | | ninguno | Retira una petición que enviaste a ese jugador, o la última |
| `/tpatoggle` | | `tpa.toggle` | Activa o desactiva recibir peticiones |
| `/tpatoggle autoaccept` | | `tpa.autoaccept` | Activa o desactiva aceptar todas las peticiones automáticamente |
| `/tpatoggle confirm` | | `tpa.confirm` | Activa o desactiva la confirmación antes de enviar una petición |
| `/autotpaaccept` | | `tpa.autoaccept` | Lo mismo que `/tpatoggle autoaccept` |

Mientras `combat-blocks-teleports` está activo, `/spawn`, `/home`, `/warp`, `/rtp`, `/back`, `/tpa` y los
portales se rechazan durante el combate. Mira [Configuración](/docs/exyliasurvivalcore/configuracion#configyml).

<Callout type="danger" title="`/stats` nunca se registra">
`/stats [jugador]` existe en el código fuente, pero a su método aún le falta `@CommandPlaceholder`, así
que Lamp nunca registra el comando. Las estadísticas llegan a los jugadores mediante
[placeholders](/docs/exyliasurvivalcore/placeholders#estadísticas).
</Callout>

## Kits y boosters

| Comando | Alias | Permiso | Qué hace |
|---|---|---|---|
| `/kit [id]` | | `kits` | Sin argumentos abre la lista de kits; con id, reclama ese kit |
| `/kit preview [id]` | | `kits.preview` | Muestra lo que contiene un kit |
| `/kit claim [id]` | | `kits` | Reclama un kit |
| `/kitadmin` | | `kits.admin` | Abre el editor de kits |
| `/kitadmin give <jugador> <kit>` | | `kits.admin` | Da un kit a un jugador |
| `/kitadmin preview <kit>` | | `kits.admin` | Previsualiza un kit |
| `/kitadmin reset <jugador> <kit>` | | `kits.admin` | Olvida el cooldown y el número de usos de un jugador para un kit |
| `/boosters` | | `boosters` | Abre tus boosters |
| `/boostersadmin` | `/boostersa` | `boosters.admin` | Abre el menú de administración de boosters |
| `/boostersadmin give <jugador> <MONEY\|XP\|DROPS> <multiplicador> <duración> [fuente]` | `/boostersa` | `boosters.admin` | Da un booster a un jugador |
| `/boostersadmin global <tipo> <multiplicador> <duración> [fuente]` | `/boostersa` | `boosters.admin` | Inicia un booster para todos |
| `/boostersadmin preset give <jugador> <preset>` | `/boostersa` | `boosters.admin` | Da a un jugador un preset configurado |
| `/boostersadmin preset global <preset>` | `/boostersa` | `boosters.admin` | Inicia un preset configurado para todos |
| `/boostersadmin clear [confirm]` | `/boostersa` | `boosters.admin` | Termina todos los boosters |

El multiplicador debe ser mayor que 1 y no superar 100. La fuente vale `*` por defecto y se pasa a
minúsculas. La duración se escribe como el plugin lee las duraciones en todas partes (`30m`, `2h`…). Los
jugadores se resuelven mediante ExyliaLib, así que vale cualquiera que la red conozca, esté conectado
aquí o no.
