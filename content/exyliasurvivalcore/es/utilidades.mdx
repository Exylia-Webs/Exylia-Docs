## Utilidades de jugador

Nueve comandos, un nodo cada uno, todos bajo `exyliasurvivalcore.playerutils.`:

| Comando | Alias | Nodo |
|---|---|---|
| `/heal` | — | `.heal` |
| `/feed` | — | `.feed` |
| `/fly` | — | `.fly` |
| `/hat` | — | `.hat` |
| `/craft` | `/workbench`, `/wb` | `.craft` |
| `/anvil` | — | `.anvil` |
| `/ec` | `/enderchest` | `.ec` |
| `/nightvision` | `/nv` | `.nightvision` |
| `/ping` | — | `.ping` |

| Ajuste | Por defecto |
|---|---|
| `night-vision-amplifier` | 0 |
| `heal-cooldown-seconds` | 0 |
| `feed-cooldown-seconds` | 0 |

El vuelo y la visión nocturna se recuerdan entre sesiones.

## Reparar

`/repair hand` repara lo que el jugador tenga en la mano; `/repair all` repara todo lo que lleve. `/fix`
y `/reparar` son alias.

| Ajuste | Por defecto |
|---|---|
| `default-hand-price` | 75.0 |
| `default-hand-cooldown` | 120 |
| `default-all-price` | 200.0 |
| `default-all-cooldown` | 120 |

`modules/repair/groups.yml` los sobrescribe por grupo de permisos. Viene **vacío**, con un ejemplo `vip`
comentado:

```yaml
groups:
  vip:
    hand: { price: 2500.0, cooldown-seconds: 60 }
    all:  { price: 5000.0, cooldown-seconds: 60 }
```

Un jugador de ese grupo necesita `exyliasurvivalcore.repair.group.vip`.

<Callout type="warning" title="Los grupos se resuelven en orden de archivo, no por precio">
Aplica el **primer** grupo del archivo cuyo nodo tenga el jugador. Alguien con dos grupos recibe el que
esté escrito más arriba, aunque el otro sea más barato. Escribe primero el mejor grupo.
</Callout>

`/repair hand <jugador>` y `/repair all <jugador>` reparan a otro, con `.repair.hand.others` y
`.repair.all.others`. `/repair lock` y `/repair unlock` protegen un objeto de ser reparado.
`exyliasurvivalcore.repair.bypass.price` y `.bypass.cooldown` se saltan los dos costes.

Un `/repair` a secas imprime la línea de uso del framework de comandos: no hay forma raíz.

## Entrada y salida

`modules/join-leave/config.yml` lleva los mensajes por defecto y el de primer login; `groups.yml` lleva
las versiones por rango.

```yaml
settings:
  counter-enabled: true
  hide-vanilla-messages: true
default-join:
  enabled: true
  chat: ""
  sound: ""
  commands: []
  actionbar: ""
  title: ""
default-quit: { … }
first-join:   { … }
```

`%player%` y `%count%` — el contador de entradas — están disponibles. Los comandos aceptan un prefijo
`console:` o `player:`.

```yaml title="modules/join-leave/groups.yml"
groups:
  vip:
    permission: survivalcore.joinleave.vip
    priority: 10
    join: { enabled: true, chat: "", sound: "", actionbar: "", title: "", … }
    quit: { … }
```

Gana el grupo de **mayor prioridad** cuyo permiso tenga el jugador. Ojo: el ejemplo que viene nombra
`survivalcore.joinleave.vip` — con el prefijo corto — así que dalo exactamente así o cambia la cadena.

Los mensajes de entrada y salida son uno de los anuncios que un jugador puede apagar en
[`/settings`](#preferencias-del-jugador).

## Comandos programados

Comandos de consola y anuncios en un temporizador.

```yaml title="modules/scheduled-commands/config.yml"
sections:
  resource_drop:
    enabled: true
    interval: 1800
    commands:
      - "broadcast <#fbbf24>[Event] A resource drop is happening now!"
    broadcast: ""
  daily_bonus:
    enabled: false
    interval: 86400
    commands:
      - "eco give @a 50"
    broadcast: "<#4ade80>Pay day! Everyone gets <#fbbf24>1000 shards!"
```

`interval` va en segundos. `broadcast` se envía a todos cuando se ejecutan los comandos; déjalo vacío para
no anunciar nada. El archivo se escribe una vez, cuando falta: nada de lo que añadas se poda, nada de lo que
borres vuelve, y un servidor que ya lo tiene conserva lo que tenía.

<Callout type="note" title="El `daily_bonus` que viene anuncia más de lo que da">
Su comando da `50` y su anuncio dice `1000 shards`. La sección viene desactivada. Corrige una de las dos
cosas antes de encenderla.
</Callout>

## Preferencias del jugador

`/settings` — alias `/preferences` y `/options` — es una pantalla que tiene cada jugador. Veintiún
interruptores deciden qué le llega.

| Ajuste | Id | Qué apaga |
|---|---|---|
| Mensajes de muerte | `death-messages` | El anuncio de muerte del plugin |
| Mensajes de entrada y salida | `join-leave-messages` | Los dos sentidos |
| Anuncios de rankup | `rankup-announcements` | Que otro suba de rango |
| Anuncios de bajas | `kill-announcements` | Los hitos de racha |
| Anuncios de recompensas | `bounty-announcements` | Recompensas puestas y cobradas |
| Anuncios de cajas | `crate-announcements` | Premios de caja de un tier que anuncia |
| Anuncios de compra | `purchase-announcements` | Los anuncios de reclaim |
| Anuncios de duelos | `duel-announcements` | Que alguien gane una [sala de duelo](/docs/exyliasurvivalcore/salas-de-duelo) |
| Anuncios de misiones | `mission-announcements` | Que alguien termine una [misión](/docs/exyliasurvivalcore/misiones-y-temporadas) semanal |
| Anuncios del mercado | `market-announcements` | Los anuncios del [mercado](/docs/exyliasurvivalcore/mercado) |
| Anuncios de subastas | `auction-announcements` | Los anuncios de la [casa de subastas](/docs/exyliasurvivalcore/mercado) |
| Anuncios de potenciadores | `booster-announcements` | Que empiece o acabe un [potenciador](/docs/exyliasurvivalcore/economia) global |
| Anuncios de votos | `vote-announcements` | Que alguien [vote](/docs/exyliasurvivalcore/recompensas-y-votos), y que empiece la fiesta de votos |
| Anuncios de temporadas | `season-announcements` | Que cierre una [temporada](/docs/exyliasurvivalcore/misiones-y-temporadas) y quién la ganó |
| Mensajes de protecciones | `protection-messages` | Los títulos y saludos al entrar y salir de [protecciones](/docs/exyliasurvivalcore/protecciones) |
| Anuncios de asaltos | `raid-announcements` | Que una protección sea [asaltada](/docs/exyliasurvivalcore/asaltos-a-protecciones), y que se abran y cierren las ventanas de asedio |
| Peticiones de TPA | `tpa-requests` | Si recibe peticiones |
| Auto-aceptar TPA | `tpa-auto-accept` | Aceptar sin preguntar |
| Confirmar TPA | `tpa-confirm` | La confirmación antes de enviar una |
| Peticiones de intercambio | `trade-requests` | Si otros jugadores pueden pedirle [intercambiar](/docs/exyliasurvivalcore/intercambio-y-baules) |
| Autoventa | `autosell` | Si lo que rompe [se vende por él](/docs/exyliasurvivalcore/economia). Solo hace algo para quien tenga `exyliasurvivalcore.sellwands.autosell`, y `/autosell` cambia el mismo interruptor |

La pantalla es una cuadrícula. Las dos filas de arriba son anuncios del servidor, los mensajes de
protecciones y los anuncios de asaltos van en la fila de debajo, y la fila de abajo es cómo te llegan otros
jugadores: los tres interruptores de TPA, las peticiones de intercambio y la autoventa. Un interruptor
encendido brilla. No hay botón de cerrar.

`modules/player-settings/menus/settings.yml` es tuyo para editar. Cada interruptor es un objeto con la acción
`survivalcore:settings_toggle <id>`, y puede leer `%<id>_state%` y `%<id>_glow%`, con los guiones del id
escritos como guiones bajos. `%<id>_glow%` vale `true` mientras el interruptor está encendido y su módulo
está cargado. Quitar un objeto quita el interruptor de la pantalla; la preferencia se queda como la dejó el
jugador.

El archivo lleva un `menu-version`, 4 en esta versión. Lo que edites se conserva entre actualizaciones.
Cuando una versión sube ese número, el archivo se sustituye y el tuyo se guarda al lado como
`settings.yml.v<versión anterior>`. Así es como un servidor con un archivo antiguo recibe la cuadrícula nueva,
con los interruptores de protecciones.

<Callout type="note" title="Todo viene encendido, y solo se guardan las excepciones">
La fila guarda los ajustes que el jugador ha **apagado**, así que una preferencia añadida en una
versión posterior está encendida para todos sin ninguna migración que ejecutar. Las tres filas de TPA
son del propio módulo tpa: no se guardan dos veces.
</Callout>

Un ajuste cuyo módulo está apagado se lee como no disponible y no hace nada. El nodo del comando es
`exyliasurvivalcore.settings`.
