## Utilidades de jugador

Nueve comandos, un nodo cada uno, todos bajo `exyliasurvivalcore.playerutils.`:

| Comando | Alias | Nodo |
|---|---|---|
| `/heal` | — | `.heal` |
| `/feed` | — | `.feed` |
| `/fly` | — | `.fly` |
| `/hat` | — | `.hat` |
| `/craft` | `/workbench`, `/wb` | `.craft` |
| `/anvil` | — | `.anvil` |
| `/ec` | `/enderchest` | `.ec` |
| `/nightvision` | `/nv` | `.nightvision` |
| `/ping` | — | `.ping` |

| Ajuste | Por defecto |
|---|---|
| `night-vision-amplifier` | 0 |
| `heal-cooldown-seconds` | 0 |
| `feed-cooldown-seconds` | 0 |

Los cooldowns de `/heal` y `/feed` también van por rango: concede
`exyliasurvivalcore.playerutils.heal.cooldown.<segundos>` o `.feed.cooldown.<segundos>` y gana el número
**más bajo** que tenga el jugador sobre el ajuste de arriba. Los cooldowns sobreviven a un relog y a un
cambio de servidor.

`/fly` se quita en combate y dentro de una protección bajo asedio, y se devuelve después. `/heal` se
rechaza en combate. `/hat` respeta la lista de objetos bloqueados.

El vuelo y la visión nocturna se recuerdan entre sesiones.

## Reparar

`/repair hand` repara lo que el jugador tenga en la mano; `/repair all` repara todo lo que lleve. `/fix`
y `/reparar` son alias.

| Ajuste | Por defecto |
|---|---|
| `default-hand-price` | 75.0 |
| `default-hand-cooldown` | 120 |
| `default-all-price` | 200.0 |
| `default-all-cooldown` | 120 |
| `currency` | vacío (la moneda por defecto) |

`currency` es cualquier id del `economy.yml` de ExyliaLib, objetos y experiencia incluidos.

`modules/repair/groups.yml` los sobrescribe por grupo de permisos. Viene **vacío**, con un ejemplo `vip`
comentado:

```yaml
groups:
  vip:
    hand: { price: 2500.0, cooldown-seconds: 60 }
    all:  { price: 5000.0, cooldown-seconds: 60 }
```

Un jugador de ese grupo necesita `exyliasurvivalcore.repair.group.vip`.

<Callout type="note" title="Gana el grupo más barato">
Un jugador con varios grupos recibe, para cada tipo de reparación, el **más barato**; el cooldown más corto
desempata. El precio de un grupo sustituye al del defecto en vez de competir con él, así que un grupo con
precio superior al de los defectos hace pagar más a sus jugadores.
</Callout>

`/repair hand <jugador>` y `/repair all <jugador>` reparan a otro, con `.repair.hand.others` y
`.repair.all.others`. `/repair lock` y `/repair unlock` protegen un objeto de ser reparado.
`exyliasurvivalcore.repair.bypass.price` y `.bypass.cooldown` se saltan los dos costes.

Un `/repair` a secas imprime la línea de uso del framework de comandos: no hay forma raíz. Quien ejecuta el comando paga y espera, también al reparar a otro.

## Entrada y salida

`modules/join-leave/config.yml` lleva los mensajes por defecto y el de primer login; `groups.yml` lleva
las versiones por rango.

```yaml
settings:
  counter-enabled: true
  hide-vanilla-messages: true
default-join:
  enabled: true
  chat: ""
  sound: ""
  commands: []
  actionbar: ""
  title: ""
default-quit: { … }
first-join:   { … }
```

`%player%` y `%count%` — el contador de entradas — están disponibles. Los comandos aceptan un prefijo
`console:` o `player:`.

```yaml title="modules/join-leave/groups.yml"
groups:
  vip:
    permission: survivalcore.joinleave.vip
    priority: 10
    join: { enabled: true, chat: "", sound: "", actionbar: "", title: "", … }
    quit: { … }
```

Gana el grupo de **mayor prioridad** cuyo permiso tenga el jugador. Ojo: el ejemplo que viene nombra
`survivalcore.joinleave.vip` — con el prefijo corto — así que dalo exactamente así o cambia la cadena.

<Callout type="note" title="ExyliaLobby toma el relevo">
Con ExyliaLobby instalado y activado, este módulo se queda apagado y ExyliaLobby gestiona los mensajes de
entrada y salida, junto a los jumpads y los portales. Pon `defer-to-exylia-lobby: false` en el `config.yml`
del plugin para conservar las versiones de este plugin y reinicia. El módulo spawn no se ve afectado.
</Callout>

Los mensajes de entrada y salida son uno de los anuncios que un jugador puede apagar en
[`/settings`](#preferencias-del-jugador).

## Comandos programados

Comandos de consola y anuncios en un temporizador.

```yaml title="modules/scheduled-commands/config.yml"
sections:
  resource_drop:
    enabled: true
    interval: 1800
    network: false
    per-player: false
    commands: []
    broadcast: "{highlight}[Event] {letters}A resource drop is happening now!"
  daily_bonus:
    enabled: false
    interval: 86400
    network: false
    per-player: true
    commands:
      - "eco give %player_name% 50"
    broadcast: "{success}Pay day! {letters}Everyone online gets {highlight}50{letters}."
```

| Clave | Qué hace |
|---|---|
| `interval` | Segundos entre ejecuciones. La última se recuerda entre reinicios, y una sección nueva se ejecuta por primera vez tras un intervalo completo |
| `broadcast` | Se envía a quien tenga activados los anuncios de eventos del servidor; déjalo vacío para no anunciar nada |
| `network` | `true` ejecuta la sección una vez para toda la red, y su anuncio llega a los jugadores de todos los servidores. `false` hace que cada servidor la ejecute por su cuenta |
| `per-player` | `true` ejecuta los comandos una vez por cada jugador conectado, rellenando `%player_name%` (o `%player%`). Se activa solo cuando una línea usa `%player_name%`. Con `network: true` son los jugadores del servidor que la ejecutó |

Un comando que falle no detiene el resto de la sección. El archivo se escribe una vez, cuando falta: nada de
lo que añadas se poda, nada de lo que borres vuelve. Los ejemplos sin tocar de versiones antiguas se
actualizan.

## Preferencias del jugador

`/settings` — alias `/preferences` y `/options` — es una pantalla que tiene cada jugador, construida sobre el
módulo de ajustes de ExyliaLib. Trece interruptores deciden qué le llega.

| Ajuste | Id | Qué apaga |
|---|---|---|
| Mensajes de muerte | `death-messages` | El anuncio de muerte del plugin |
| Mensajes de entrada y salida | `join-leave-messages` | Los dos sentidos |
| Anuncios de rankup | `rankup-announcements` | Que otro suba de rango |
| Anuncios de compra | `purchase-announcements` | Los anuncios de reclaim |
| Anuncios de misiones | `mission-announcements` | Que alguien termine una [misión](/docs/exyliasurvivalcore/misiones-y-temporadas) semanal |
| Anuncios de potenciadores | `booster-announcements` | Que empiece o acabe un potenciador global |
| Anuncios de proyectos | `project-announcements` | Que se complete un proyecto comunitario y empiece el siguiente |
| Anuncios de temporadas | `season-announcements` | Que cierre una [temporada](/docs/exyliasurvivalcore/misiones-y-temporadas) y quién la ganó |
| Anuncios de eventos del servidor | `scheduled-announcements` | Lo que anuncia una sección de [comandos programados](#comandos-programados) |
| Mensajes de protecciones | `protection-messages` | Los títulos y saludos al entrar y salir de protecciones |
| Anuncios de asaltos | `raid-announcements` | Que una protección sea asaltada, y que se abran y cierren las ventanas de asedio |
| Peticiones de TPA | `tpa-requests` | Si recibe peticiones |
| Auto-aceptar TPA | `tpa-auto-accept` | Aceptar sin preguntar |
| Confirmar TPA | `tpa-confirm` | La confirmación antes de enviar una |

<Callout type="note" title="Interruptores que se han ido">
Los interruptores de bajas, recompensas, cajas, duelos, mercado, subastas, votos, intercambio y autoventa se
fueron con sus funciones. Esas filas ya no se ofrecen aquí.
</Callout>

Los interruptores cuyas funciones viven en otro plugin (las protecciones, por ejemplo) siguen apareciendo
aquí mientras su módulo esté cargado. Un interruptor encendido brilla. No hay botón de cerrar.

<Callout type="note" title="Todo viene encendido, y solo se guardan las excepciones">
La fila guarda los ajustes que el jugador ha **apagado**, así que una preferencia añadida en una
versión posterior está encendida para todos sin ninguna migración que ejecutar. Las tres filas de TPA
son del propio módulo tpa: no se guardan dos veces.
</Callout>

Un ajuste cuyo módulo está apagado se lee como no disponible y no hace nada. El nodo del comando es
`exyliasurvivalcore.settings`.
