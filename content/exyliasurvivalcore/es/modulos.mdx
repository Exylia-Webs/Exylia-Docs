`config.yml` guarda el `language`, `debug`, tres interruptores de todo el servidor, los interruptores de
módulo y la sección `teleport` que se describe en [Configuración](/docs/exyliasurvivalcore/configuracion).
Los interruptores de módulo, en el orden en que los lista el archivo:

```yaml
debug: false
defer-to-exylia-lobby: true
combat-blocks-teleports: true
idle-after-seconds: 300
modules:
  spawn: true
  tpa: true
  homes: true
  join-leave: true
  rtp: true
  scheduled-commands: true
  rankup: true
  player-utils: true
  back: true
  farming: true
  reclaim: true
  stats: true
  portals: true
  jumpads: true
  kits: true
  item-spawners: true
  warps: true
  near: true
  repair: true
  death: true
  enchantments: true
  player-settings: true
  missions: true
  boosters: true
  seasons: true
  optimization: true
  item-updater: true
  reputation: true
  projects: true
```

`debug` añade detalle en consola, incluido con qué actor se ejecuta cada línea de comando configurada. Se
vuelve a leer con `/survivalcoreadmin reload`; los interruptores de módulo no.

| Clave | Por defecto | Qué hace |
|---|---|---|
| `defer-to-exylia-lobby` | `true` | Con ExyliaLobby activo, `jumpads`, `join-leave` y `portals` quedan apagados y los gestiona el lobby. `spawn` no se ve afectado. Ponlo en `false` para conservar las versiones de este plugin. Requiere reinicio. |
| `combat-blocks-teleports` | `true` | `/spawn`, `/home`, `/warp`, `/rtp`, `/back`, `/tpa` y los teletransportes de portal se rechazan mientras el jugador está en combate, sea cual sea el plugin que lo lleve. Los permisos que saltan la cuenta atrás no saltan esto. |
| `idle-after-seconds` | `300` | Cuánto puede estar un jugador sin moverse, mirar, escribir ni pulsar antes de que las recompensas por tiempo jugado dejen de contarlo. `0` lo desactiva. |

<Callout type="warning" title="Un interruptor de módulo necesita reinicio">
`/survivalcoreadmin reload` vuelve a leer los archivos de configuración, los ajustes de módulo y los
menús, pero nunca activa ni desactiva un módulo: sus comandos, listeners y enlaces se registran una sola
vez, al arrancar. Cuando un interruptor ya no coincide con lo que está en marcha, el reload lo dice —
*"Restart to apply module changes » …"* con los ids de esos módulos. Reinicia para aplicarlos.
</Callout>

<Callout type="note" title="`mobs` es un interruptor residual">
El registro de interruptores todavía incluye una clave `mobs`, pero ningún módulo la registra ya: los
mobs personalizados y sus generadores son ahora de [ExyliaMobs](/docs/exyliamobs/introduccion). Cambiarla
no hace nada.
</Callout>

## Qué significa "apagado"

Un módulo apagado no se construye más allá de su propio interruptor. **No registra comandos, listeners,
tablas de base de datos, placeholders ni temporizadores.** Su archivo de configuración se deja intacto en
disco, así que al volver a encenderlo continúa exactamente donde estaba.

Un id de módulo que nadie declara está simplemente apagado, y no es un error.

Dos cosas más mantienen apagado un módulo sin tocar su interruptor. Con ExyliaLobby activo y
`defer-to-exylia-lobby` encendido, `jumpads`, `join-leave` y `portals` no cargan. Mientras ExyliaJobs
esté instalado, `farming` tampoco carga: los trabajos pagan por el mismo esfuerzo.

Los módulos cargan en un orden fijo, que no es el del archivo: `missions` y `seasons` cargan después de
`stats`, cuyos contadores leen.

| `near` | Quién está cerca, con distancia y dirección | [Movimiento](/docs/exyliasurvivalcore/movimiento) |

| `repair` | `/repair hand` y `/repair all`, con precio por grupo | [Utilidades](/docs/exyliasurvivalcore/utilidades) |

| `item-updater` | Objetos desfasados sustituidos por su versión corregida al entrar, cambiar de ranura y cerrar el inventario | [Optimización](/docs/exyliasurvivalcore/optimizacion) |
| `boosters` | Potenciadores de dinero y experiencia, para un jugador o para todos | [Economía](/docs/exyliasurvivalcore/economia) |
| `reputation` | Los jugadores se puntúan tras un trato; una buena puntuación devuelve parte del impuesto de venta | [Reputación y proyectos](/docs/exyliasurvivalcore/reputacion-y-proyectos) |
| `projects` | Proyectos comunitarios: todos aportan materiales hacia una meta que paga a todos | [Reputación y proyectos](/docs/exyliasurvivalcore/reputacion-y-proyectos) |

## Qué se hacen los interruptores entre sí

Los módulos son independientes — ninguno se niega a activarse porque otro esté apagado — pero varios se
leen entre sí cuando ambos están encendidos, y algunos no sirven de mucho solos.

<Callout type="note" title="`player-settings` decide quién oye un anuncio">
Los mensajes de muerte, de entrada y salida, los ascensos de rango, las compras reclamadas, las
misiones, los potenciadores que empiezan y terminan, los hitos de proyecto, el cierre de temporadas y
los anuncios programados consultan las preferencias de cada receptor antes de enviarse, igual que los
tres interruptores de TPA (peticiones, aceptación automática y confirmación). Los mensajes de
protecciones y los anuncios de asaltos están en la misma lista para servidores con
[ExyliaProtections](/docs/exyliaprotections/introduccion).

Con `player-settings` apagado, todos los anuncios llegan a todo el mundo y todas las peticiones llegan.
</Callout>

<Callout type="note" title="`stats` guarda los contadores que leen `missions` y `seasons`">
Las misiones miden el progreso contra los contadores de estadísticas y las temporadas los clasifican. Con
`stats` apagado, ambos módulos se activan igualmente y cada uno avisa una vez al arrancar: ninguna misión
se completa nunca y ninguna temporada clasifica a nadie. Las clasificaciones también salen vacías. La
estadística `kdr` se calcula a partir de muertes y asesinatos, y la estadística `playtime` incluida se
lee a través de PlaceholderAPI.
</Callout>

<Callout type="note" title="`boosters` y la economía">
Los potenciadores de dinero se aplican a los pagos que hace el plugin en la moneda por defecto del
servidor, la que proporciona ExyliaEconomy (o Vault). Sin ninguna economía, los precios y pagos se
omiten y la consola lo dice al arrancar. Mira [Economía](/docs/exyliasurvivalcore/economia).
</Callout>

Apagar `kits`, `warps`, `portals` y el resto deja intacto en la base de datos todo lo que construyeron.
Volver a encender uno devuelve su contenido exactamente como estaba.

## Movidos a otros plugins

Antes eran módulos de este plugin y ya no están. Sus interruptores ya no existen y los datos viven ahora
en el plugin indicado.

| Qué | A dónde fue |
|---|---|
| Monedas, saldos, el registro, el puente de Vault, `/balance`, `/pay`, `/baltop`, `/wallet` | [ExyliaEconomy](/docs/exyliaeconomy/introduccion) |
| Tienda, mercado de jugadores, subastas, pedidos de compra, intercambios, varitas de venta y autoventa | [ExyliaMarket](/docs/exyliamarket/introduccion) |
| Baúles personales | [ExyliaPlayerVaults](/docs/exyliaplayervaults/introduccion) |
| Tumbas | [ExyliaGraves](/docs/exyliagraves/introduccion) |
| Cajas y llaves | [ExyliaCrates](/docs/exyliacrates/introduccion) |
| Protecciones de terreno, asaltos, bancos, mantenimiento, alquiler e importación de ProtectionStones | [ExyliaProtections](/docs/exyliaprotections/introduccion) |
| Minas | [ExyliaMines](/docs/exyliamines/introduccion) |
| Suministros, power-ups, cofres de botín, zonas de regeneración, salas de duelo y objetos prohibidos (antes objetos bloqueados) | [ExyliaWarzone](/docs/exyliawarzone/introduccion) |
| Recompensas por cabeza (bounties) | [ExyliaCombat](/docs/exyliacombat/introduccion) |
| Recompensas por muerte | Eliminadas aquí; [ExyliaCombat](/docs/exyliacombat/introduccion) tiene las suyas |
| Recompensas de menú, de tiempo jugado, votos, referidos y zonas AFK | [ExyliaRewards](/docs/exyliarewards/introduccion) |
| Mobs personalizados y generadores | [ExyliaMobs](/docs/exyliamobs/introduccion) |

<Callout type="note" title="Un `blocked-items/rules.yml` sobrante">
Si `modules/blocked-items/rules.yml` sigue en disco, el plugin imprime un aviso al arrancar: ExyliaWarzone
importa ese archivo en su módulo de objetos prohibidos y aquí nadie lo lee.
</Callout>
