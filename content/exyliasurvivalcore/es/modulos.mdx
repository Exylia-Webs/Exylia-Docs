`config.yml` guarda tres cosas: `debug`, los interruptores de módulo y la sección `teleport` que se
describe en [Configuración](/docs/exyliasurvivalcore/configuracion). Los interruptores, en el orden en
que los lista el archivo:

```yaml
debug: false
modules:
  spawn: true
  tpa: true
  homes: true
  join-leave: true
  rtp: true
  kill-rewards: true
  scheduled-commands: true
  playtime-rewards: true
  rankup: true
  player-utils: true
  back: true
  farming: true
  reclaim: true
  stats: true
  portals: true
  jumpads: true
  kits: true
  bounties: true
  afk-zones: true
  item-spawners: true
  warps: true
  near: true
  loot-chests: true
  crates: true
  repair: true
  death: true
  powerups: true
  mines: true
  regen-zones: true
  enchantments: true
  blocked-items: true
  player-settings: true
  duel-rooms: true
  missions: true
  market: true
  vaults: true
  trade: true
  graves: true
  economy: true
  shop: true
  auctions: true
  rewards: true
  boosters: true
  votes: true
  sell-wands: true
  seasons: true
  optimization: true
  orders: true
  item-updater: true
  protections: true
```

`debug` añade detalle en consola, incluido con qué actor se ejecuta cada línea de comando configurada.
Se relee con `/sc reload`; los interruptores no.

<Callout type="warning" title="Un interruptor de módulo necesita reinicio">
`/sc reload` relee los archivos de configuración, los ajustes de cada módulo y los menús, pero nunca
enciende ni apaga un módulo: sus comandos, listeners y enganches se registran una vez, al arrancar.
Cuando un interruptor ya no coincide con lo que está funcionando, la recarga lo dice —
*"Restart to apply module changes » …"* con los ids de esos módulos. Reinicia para aplicarlos.
</Callout>

## Qué significa "apagado"

Un módulo apagado no se construye más allá de su propio interruptor. No registra **ni comandos, ni
listeners, ni tablas, ni placeholders, ni temporizadores**. Su archivo de configuración se queda intacto
en disco, así que volver a encenderlo retoma exactamente donde lo dejaste.

Un id de módulo que nadie declara está simplemente apagado, y eso no es un error.

Los módulos cargan en un orden fijo, que no es el del archivo: `economy` carga el primero, porque todo
módulo que pone precios, paga o comercia lee sus monedas; `missions` y `seasons` cargan después de
`stats`, cuyos contadores leen; `graves` carga después de `death`.

## Qué se hacen entre ellos

Los módulos son independientes — ninguno se niega a arrancar porque otro esté apagado — pero varios se
leen entre sí cuando los dos están encendidos, y unos pocos no hacen nada útil solos.

<Callout type="note" title="`player-settings` decide quién oye un anuncio">
Muertes, mensajes de entrada y salida, rankups, rachas de bajas, recompensas puestas y cobradas, premios
de caja, reclaims, duelos ganados, misiones, anuncios del mercado, subastas ganadas, potenciadores
globales que empiezan y terminan, votos y la fiesta de votos, temporadas que se cierran, asaltos y
ventanas de asedio de protecciones, y protecciones abandonadas por mantenimiento comprueban las
preferencias de cada receptor antes de mandarse. También lo hacen los títulos al entrar y salir de una
protección, si a un jugador le llega una petición de intercambio y si la autoventa vende por él.

Con `player-settings` apagado, todos los anuncios van a todo el mundo, todas las peticiones de
intercambio llegan, los títulos de protección se muestran a todos y la autoventa está encendida para
cualquier jugador con `exyliasurvivalcore.sellwands.autosell` — `/autosell` responde entonces que está
encendida y no cambia nada. Los tres interruptores de TPA los guarda el módulo `tpa` y funcionan igual en
los dos casos.
</Callout>

<Callout type="note" title="`stats` guarda los contadores que leen `missions` y `seasons`">
Las misiones miden el progreso sobre los contadores de stats, y las temporadas los clasifican. Con
`stats` apagado, los dos módulos arrancan igual y cada uno avisa una vez al arrancar: ninguna misión se
completa y ninguna temporada clasifica a nadie. Los rankings también quedan vacíos. La stat `kdr` se
calcula a partir de bajas y muertes, y la stat `playtime` de serie se lee a través de PlaceholderAPI. La
racha de kill-rewards se cuenta aparte y sigue funcionando.
</Callout>

<Callout type="note" title="`economy` es de donde salen casi todas las monedas">
Tienda, mercado, subastas, órdenes e intercambio ponen precios y pagan en las monedas que tiene
registradas la economía de ExyliaLib: las que guarda el módulo `economy`, más Vault o PlayerPoints si
están instalados. Con `economy` apagado solo quedan esas dos, y `/balance`, `/pay`, `/baltop`, `/wallet`,
`/economy` y `/economyadmin` no existen. Sin ninguna moneda registrada, los precios y los pagos se
saltan y la consola lo dice al arrancar.
</Callout>

<Callout type="note" title="`boosters`, `sell-wands` y la tienda">
Los potenciadores de dinero se aplican a las ventas en la tienda, las misiones, las recompensas por baja,
el farmeo y los votos. `sell-wands` vende a través de la tienda: con `shop` apagado, una varita responde
con el mensaje de módulo desactivado y la autoventa no recoge nada.
</Callout>

<Callout type="note" title="Clanes, tumbas y muertes">
Las salas de duelo y las protecciones leen los clanes a través de ExyliaLib: ExyliaClans o SimpleClans.
En una sala de duelo, los jugadores del mismo clan o de clanes aliados no se enfrentan entre sí; sin un
plugin de clanes, todo el mundo cuenta como enemigo. Las tumbas se llevan los drops un paso antes de que
`death` los disperse, así que con los dos encendidos lo que se habría dispersado va a la tumba.
</Callout>

Apagar `crates`, `kits`, `mines`, `shop`, `protections` y los demás deja intacto en la base de datos todo
lo que construyeron. Volver a encender uno lo devuelve exactamente como estaba.
