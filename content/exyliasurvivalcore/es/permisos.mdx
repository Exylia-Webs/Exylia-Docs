---
title: "Permisos"
description: "Todos los nodos declarados en plugin.yml y su valor por defecto, los que llevan un número y los que escribes tú."
---

`plugin.yml` declara los nodos de abajo con un valor por defecto, así que nadie tiene que conceder las
funciones de jugador. Hay tres casos:

- **Jugadores** (`true`): todos tienen el nodo. Quítaselo al grupo por defecto para convertirlo en ventaja de rango.
- **Operadores** (`op`): administración, ventajas y bypasses; solo pasan los operadores hasta que los concedes.
- **Nodos numéricos o de prefijo**: no están declarados; se explican en
  [Nodos que llevan un número](#nodos-que-llevan-un-número).

Todos los nodos de abajo empiezan por `exyliasurvivalcore.` salvo que estén escritos completos.

<Callout type="warning" title="Algunos nodos de administración empiezan por `survivalcore.`">
Los nodos de administración más antiguos conservan el prefijo corto: `survivalcore.admin`,
`survivalcore.admin.reload`, `survivalcore.admin.homes`, `survivalcore.rankup.admin`,
`survivalcore.rankup.admin.set`, `survivalcore.farming.admin`, `survivalcore.farming.admin.set` y
`survivalcore.portals.admin`. Todos los demás usan `exyliasurvivalcore.`. Los dos prefijos son
intencionados.
</Callout>

### Bypasses

Todos por defecto para **op**. Un bypass se salta por completo el warmup, el precio o el cooldown, así
que los nodos numéricos de abajo no importan a quien tiene uno.

| Permiso | Se salta |
|---|---|
| `exyliasurvivalcore.spawn.bypass` | El warmup de `/spawn` |
| `exyliasurvivalcore.homes.bypass` | El warmup de los homes |
| `exyliasurvivalcore.back.bypass` | El warmup de `/back` |
| `exyliasurvivalcore.rtp.bypass` | El cooldown y el precio del RTP (no el warmup) |
| `exyliasurvivalcore.warps.bypass` | El warmup, el cooldown y el precio de un warp |
| `exyliasurvivalcore.warps.bypass.cost` | El precio de un warp |
| `exyliasurvivalcore.warps.bypass.cooldown` | El cooldown de un warp |

`combat-blocks-teleports` no es un warmup: ningún nodo de bypass se lo salta.

## Nodos que llevan un número

Estos nodos terminan en un valor en vez de una palabra y no están declarados en `plugin.yml`. Cada uno es
un ajuste que concedes por rango.

**Gana el más alto que tenga el jugador**, y si no tiene ninguno se usa el ajuste:

| Permiso | Efecto |
|---|---|
| `exyliasurvivalcore.homes.max_homes.<n>` | Cuántos homes puede poner el jugador. Sin ninguno, `max-homes` en `modules/homes/config.yml` |
| `exyliasurvivalcore.near.radius.<n>` | El radio que busca `/near`, limitado aún por `max-radius` en `modules/near/config.yml` |

**Gana el más bajo que tenga el jugador**, en segundos:

| Permiso | Efecto |
|---|---|
| `exyliasurvivalcore.homes.warmup.<n>` | Warmup de los homes |
| `exyliasurvivalcore.tpa.warmup.<n>` | Warmup del TPA |
| `exyliasurvivalcore.tpa.cooldown.<n>` | Cooldown del TPA |
| `exyliasurvivalcore.back.warmup.<n>` | Warmup de `/back` |
| `exyliasurvivalcore.spawn.warmup.<n>` | Warmup de `/spawn` |
| `exyliasurvivalcore.warps.warmup.<n>` | Warmup de los warps |
| `exyliasurvivalcore.warps.cooldown.<n>` | Cooldown de los warps |
| `exyliasurvivalcore.rtp.warmup.<n>` | Warmup del RTP |
| `exyliasurvivalcore.rtp.cooldown.<n>` | Cooldown del RTP; baja el cooldown propio de un mundo y nunca lo sube |
| `exyliasurvivalcore.playerutils.heal.cooldown.<n>` | Cooldown de `/heal` |
| `exyliasurvivalcore.playerutils.feed.cooldown.<n>` | Cooldown de `/feed` |

**Nodos de prefijo** que nombran un grupo o una sección que defines tú:

| Permiso | Efecto |
|---|---|
| `exyliasurvivalcore.repair.group.<nombre>` | Los precios y cooldowns de reparación de ese grupo, de `modules/repair/groups.yml` |
| `exyliasurvivalcore.reclaim.<sección>` | El nodo por defecto de una sección de reclaim |

```text
/lp group vip permission set exyliasurvivalcore.homes.max_homes.8 true
/lp group vip permission set exyliasurvivalcore.near.radius.500 true
/lp group vip permission set exyliasurvivalcore.tpa.warmup.1 true
/lp group vip permission set exyliasurvivalcore.repair.group.vip true
```

Un jugador con varios grupos de reparación recibe, en cada reparación, el más barato de ellos; el
cooldown más corto desempata. `groups.yml` viene vacío, así que todos pagan los valores por defecto de
`modules/repair/config.yml` hasta que añadas un grupo.

## Nodos que escribes tú

Varias cosas se protegen con un nodo que **tú** eliges, guardado junto a lo que protege y no en el código
del plugin.

| Dónde | Clave | Por defecto |
|---|---|---|
| Un warp | Su `permission`, desde `/warpadmin` | Vacío, que equivale a `exyliasurvivalcore.warps.use` |
| Un kit | Su `permission`, desde `/kitadmin` | Vacío, que equivale a todo el que tenga `exyliasurvivalcore.kits` |
| Un portal | Su `permission`, desde `/portalsadmin` | Vacío, que significa que todos pueden usarlo |
| Una sección de reclaim | `sections.<id>.permission` en `modules/reclaim/config.yml` | `exyliasurvivalcore.reclaim.<id>` |
| Un grupo de entrada / salida | `groups.<id>.permission` en `modules/join-leave/groups.yml` | El grupo `vip` incluido usa `survivalcore.joinleave.vip` |
| Un requisito de rango | El `node` de un requisito `PERMISSION`, en `ranks.yml` | Ninguno |

Las secciones de reclaim se eligen por **prioridad**: a un jugador se le da la sección de mayor
prioridad cuyo permiso tenga, así que el `vip` incluido con `priority: 1` gana a `default` con
`priority: 0` para quien tenga ambos. Igual con los grupos de entrada / salida: vale el de mayor
prioridad cuyo permiso tenga el jugador.

### Los bypasses de warmup y de RTP también son claves de configuración

```yaml title="modules/spawn/config.yml"
settings:
  permission-bypass-warmup: exyliasurvivalcore.spawn.bypass
```

La misma clave existe en `modules/homes/config.yml` y en `modules/back/config.yml`, con
`exyliasurvivalcore.homes.bypass` y `exyliasurvivalcore.back.bypass` por defecto. El RTP tiene dos
propias, ambas con `exyliasurvivalcore.rtp.bypass` por defecto, que además siempre funciona:

```yaml title="modules/rtp/config.yml"
settings:
  bypass-cooldown-permission: exyliasurvivalcore.rtp.bypass
  bypass-price-permission: exyliasurvivalcore.rtp.bypass
```

## Una configuración de partida

Sintaxis de LuckPerms; adáptala a tu plugin de permisos.

```text
# Todos ya tienen las funciones de jugador. Quítale una a default para convertirla en ventaja.
/lp group default permission set exyliasurvivalcore.homes.max_homes.3 true
/lp group default permission set exyliasurvivalcore.tpa.warmup.5 true
/lp group default permission set exyliasurvivalcore.rtp.cooldown.300 true

# VIP, encima de lo anterior
/lp group vip permission set exyliasurvivalcore.homes.max_homes.8 true
/lp group vip permission set exyliasurvivalcore.tpa.warmup.1 true
/lp group vip permission set exyliasurvivalcore.rtp.cooldown.60 true
/lp group vip permission set exyliasurvivalcore.playerutils.hat true
/lp group vip permission set exyliasurvivalcore.playerutils.craft true
/lp group vip permission set exyliasurvivalcore.playerutils.ec true
/lp group vip permission set exyliasurvivalcore.repair.group.vip true
/lp group vip permission set survivalcore.joinleave.vip true

# Staff
/lp group admin permission set survivalcore.admin true
/lp group admin permission set survivalcore.admin.reload true
/lp group admin permission set survivalcore.rankup.admin true
/lp group admin permission set survivalcore.farming.admin true
/lp group admin permission set exyliasurvivalcore.kits.admin true
/lp group admin permission set exyliasurvivalcore.warps.admin true
```

Los módulos que se movieron (economía, tienda, mercado, intercambio, baúles, tumbas, protecciones,
recompensas, bounties y el resto) llevan sus permisos en las páginas de sus propios plugins, por ejemplo
[ExyliaEconomy](/docs/exyliaeconomy/permisos) y [ExyliaMarket](/docs/exyliamarket/permisos).
