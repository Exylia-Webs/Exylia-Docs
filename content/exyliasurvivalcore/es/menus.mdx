Vienen sesenta y dos archivos de menú por idioma, en dos sitios que se comportan de forma
completamente distinta. Viven bajo `lang/<código>/`, así que cada idioma tiene su propia copia;
`<código>` es el idioma elegido en [Configuración](/docs/exyliasurvivalcore/configuracion#idiomas).

| Carpeta | Archivos | Comportamiento |
|---|---|---|
| `lang/<código>/modules/<id>/menus/`, y `lang/<código>/menus/currency_select.yml` | 26 | Se escriben si faltan y después se mantienen al día **sin deshacer tus cambios**. Tuyos. |
| `lang/<código>/menus/admin/` | 36 | La carpeta entera se reemplaza desde el jar en cada arranque, cada `/survivalcoreadmin reload` y cada `/exylialib reload`. |

<Callout type="danger" title="No edites nada en `menus/admin/`">
Todos sus archivos empiezan con `DO NOT EDIT — REGENERATED ON EVERY STARTUP`. También se regeneran en
cada recarga. Los cambios ahí se destruyen en silencio en el siguiente reinicio o recarga.

Los editores de administración que viven fuera de esa carpeta se conservan como cualquier menú de
propietario: `modules/warps/menus/warp_setup.yml`, `warp_admin_list.yml` y las pantallas de
administración de boosters `modules/boosters/menus/admin.yml`, `presets.yml`, `preset.yml`,
`running.yml` y `settings.yml`.
</Callout>

Un archivo mal formado se nombra en el registro y queda sin registrar, en lugar de cargarse vacío en
silencio.

Las pantallas de los módulos que pasaron a otros plugins (cajas, tienda, mercado, protecciones,
baúles, tumbas, recompensas, zonas AFK, economía y el resto) ya no se incluyen aquí; búscalas en la
documentación del plugin que corresponda, como [ExyliaCrates](/docs/exyliacrates/introduction) y
[ExyliaMarket](/docs/exyliamarket/introduction).

## Cómo se mantienen al día tus menús

Cada carpeta de menús de propietario se actualiza al arrancar y en cada recarga, antes de leer los
menús. Para cada archivo el plugin compara tres cosas: lo que hay en disco, lo que viene en esta
versión y los valores por defecto que tuviste la última vez, que guarda en `.defaults/files/` dentro de
la carpeta del plugin.

- **Un archivo que falta** se escribe.
- **Una clave que añade una versión** se escribe en tu archivo al momento, comentarios incluidos. Nadie
  pudo elegir algo que aún no existía.
- **Un valor por defecto que cambió** en una clave que no tocaste no se aplica. Espera en
  `/exylialib updates`, donde lo aplicas o conservas lo tuyo.
- **Todo lo que cambiaste o borraste** no se toca nunca.

Un archivo que no se puede leer se deja como está y se avisa.

### Archivos que declaran una versión

Casi todos los menús de propietario llevan un `menu-version` (hogares, kits, rangos, RTP, estadísticas,
agricultura, misiones, temporadas, proyectos, warps, boosters, TPA, cercanos y el selector de moneda).
Cuando una versión trae un número mayor que el del archivo en disco (sin la clave cuenta como `0`), el
archivo se reemplaza entero, con tus cambios, y tu archivo anterior se conserva al lado como
`<nombre>.yml.v<versión anterior>`. Se reserva para un cambio de diseño que un archivo viejo no
soporta. No toques `menu-version`.

<Callout type="warning" title="Borrar un menú ya no recupera el original">
Cuando el plugin ya instaló un archivo, uno que desaparece cuenta como borrado por ti y no se vuelve a
escribir. El menú entonces no se registra: el registro nombra el archivo que no se pudo leer y lo que
abría esa pantalla no hace nada. Para recuperar el archivo que viene, borra también su copia en
`.defaults/files/` — la misma ruta, `.defaults/files/lang/es/modules/homes/menus/homes.yml` para
`lang/es/modules/homes/menus/homes.yml` — y recarga.
</Callout>

## Las pantallas de administración

Treinta y seis archivos en `menus/admin/`, a los que se llega desde `/survivalcoreadmin` y desde el
comando de administración de cada módulo:

- **El hub** (`hub`), la búsqueda de jugadores (`players`, `player`, `player_homes`) y el pozo de RTP
  (`rtp_pool`).
- **Ajustes**: un hub de ajustes (`settings`, `settings_general`, `settings_modules`,
  `settings_modules_hub`, `settings_modules_travel`, `settings_modules_more`) y una página por módulo con
  valores ajustables: hogares, TPA, RTP, kits, rangos, reparación, boosters, reputación y optimización.
  Ver [Configuración](/docs/exyliasurvivalcore/configuracion).
- **Editores de contenido**: kits (`kits_admin_list`, `kit_admin_edit`), generadores de objetos
  (`spawner_*`, `template_*`, `chest_*` para las tablas de botín que usan), jumppads (`jumpad_*`),
  portales (`portal_*`) y actualizaciones de objetos (`item_update_*`).

Funcionan, y no deberías editarlos. El plugin reemplaza la carpeta desde el jar para que un botón añadido
en una versión llegue a los servidores que ya la tienen.

Fuera de esa carpeta, `modules/warps/menus/warp_setup.yml` es el editor de warps y
`modules/boosters/menus/` guarda las pantallas de administración de boosters. Se conservan como
cualquier menú de propietario.

## El esquema de archivo

Un archivo de menú es:

```yaml
title: "…"
size: 54
type: PAGINATION
open_sounds: ["UI_BUTTON_CLICK|1.0|1.0"]
click_sounds: []
refresh: { mode: SMART, interval: 40 }
filler:
  global: { material: GRAY_STAINED_GLASS_PANE, name: " " }
  pagination: { material: BARRIER, name: "Nada aquí" }
pagination:
  slots: '10-16,19-25,28-34'
  item_template: { material: "%icon%", name: "%name%", lore: [], actions: ["survivalcore:…"] }
  navigation:
    previous: { slot: 45, material: ARROW }
    next:     { slot: 53, material: ARROW }
items:
  close: { slot: 49, material: BARRIER, name: "Cerrar", actions: ["survivalcore:close_menu"] }
```

| Clave | Qué hace |
|---|---|
| `size` | Siempre `size`, nunca `rows` |
| `type` | Decorativo. Un menú pagina porque tiene un bloque `pagination:`, no por esto |
| `refresh` | `{mode: ON_CLICK, click_delay: 4}` o `{mode: SMART, interval: N}` |
| `filler.global` | El fondo |
| `filler.custom.<nombre>` | Un segundo relleno con sus propios `slots` |
| `filler.pagination` | Lo que se dibuja cuando la lista está vacía |
| `pagination.slots` | `'0-35'`, o un conjunto de rangos separados por comas |
| `sections` | Grupos de ranuras con nombre, con sus propias plantillas y navegación. Los usan la vista previa de kit y su pantalla de contenedor |
| `animation` | `center_out` |
| `menu-version` | Solo en los archivos que declaran una; ver arriba. No la toques |

### Plantillas de estado

Una lista paginada puede dibujar una fila distinta según su estado.
`lang/<code>/modules/kits/menus/list.yml` tiene cuatro — `item_template`, `cooldown_template`, `used_template`,
`locked_template` — y la sección de reclamo de la vista previa de kit tiene seis.

### Acciones

La clave es siempre `actions:`, una lista de cadenas. El tipo de clic es un **prefijo dentro de la
cadena**:

```yaml
actions:
  - "left: survivalcore:kit_claim %kit_id%"
  - "right: survivalcore:kit_preview %kit_id%"
```

`left:`, `right:`, `middle:`, `shift_left:`, `shift_right:` y `drop:` son los prefijos; sin prefijo
vale cualquier clic. `survivalcore:<nombre>` es una de las acciones de este
plugin; `close`, `previous_page` y `next_page` son de ExyliaLib.

### Materiales

Un material de Bukkit, un placeholder (`%kit_icon%`), `basehead-<base64>`, `playerhead-%name%` o
`playerhead:%name%`. Las dos formas de cabeza se usan en los archivos que vienen.

## Acciones que merece la pena enlazar en otro sitio

El plugin registra 123 acciones bajo el espacio `survivalcore:`, y funcionan desde **cualquier** menú
de ExyliaLib de cualquier plugin — un selector de hub, un NPC, un objeto de la barra rápida. Cada una no
hace nada mientras su módulo está apagado. Las que más conviene conocer:

| Acción | Qué abre |
|---|---|
| `survivalcore:homes_open` | Los hogares del jugador |
| `survivalcore:warp_open_list` | La lista de warps |
| `survivalcore:kit_open_list` | La lista de kits |
| `survivalcore:rankup_open` | La escalera de rangos |
| `survivalcore:stats_open` | El perfil de estadísticas del jugador |
| `survivalcore:missions_open` | Las misiones |
| `survivalcore:seasons_open` | La lista de temporadas |
| `survivalcore:projects_open` | El proyecto comunitario |
| `survivalcore:boosters_open` | Los boosters del jugador |
| `survivalcore:settings_hub` | El hub de ajustes de administración |
| `survivalcore:admin_hub` | El hub de administración |
| `survivalcore:close_menu` | Cerrar |

<Callout type="warning" title="Una acción de administración sigue comprobando su permiso">
Toda acción que cambia estado de administración vuelve a comprobar el permiso de administración de su
módulo dentro del manejador. Añadir un botón de administración a un menú de jugador no da acceso a nadie:
solo le da un botón que se niega.
</Callout>

<Callout type="note" title="Una acción registrada no tiene botón">
`survivalcore:spawner_import_from_chest` implementa el flujo "haz clic en un cofre para importar su
contenido como tabla de botín", y ningún menú que viene la llama. Enlazarla en tu propio menú es la única
forma de llegar a ella.
</Callout>
