## Antes de empezar

El plugin necesita **Paper 1.21.1 o superior** (o Folia). `ExyliaLib` es el único plugin sin el que no
puede funcionar. Está en `softdepend` a propósito — el cargador que instala ExyliaLib es el que tiene que
cargar primero para que esa instalación ocurra — pero aquí nada funciona sin él. Aporta la configuración,
los menús, la base de datos, los placeholders, los teletransportes, el planificador, los asistentes, las
entradas por chat y las fachadas que leen las economías de otros plugins. El plugin no nombra una versión
mínima de ExyliaLib: el cargador instala la librería y el actualizador de la propia librería la mantiene
al día.

`packetevents` es **opcional**: sin él el plugin funciona y solo se quedan apagados los extras dibujados
con paquetes.

## Plugins opcionales

Cada uno está declarado en `softdepend` y activa algo concreto:

| Plugin | Qué activa |
|---|---|
| `ExyliaEconomy` | Las monedas en las que el plugin cobra y paga, y el hueco de Vault. Es una dependencia blanda para que este plugin se active después. |
| `Vault` | Precios y pagos en la economía que sirva Vault, cuando ExyliaEconomy no es la que lo hace. |
| `ExyliaLobby` | Con él activo, `jumpads`, `join-leave` y `portals` quedan apagados y los aporta el lobby. Mira [Módulos](/docs/exyliasurvivalcore/modulos). |
| `PlaceholderAPI` | Los placeholders del plugin fuera de él; los requisitos `placeholder` de `ranks.yml`; las estadísticas de tipo `PAPI`, como el `playtime` incluido. |
| `WorldGuard` | Ámbitos de región en las reglas de encantamientos. |
| `Apollo` (`Apollo-Bukkit`, `Apollo-Folia`), `FeatherServerAPI` | El spawn y las casas mostrados como waypoints del cliente. |
| `Worlds` | Manejo de mundos en Folia. |
| `packetevents` | Los extras dibujados con paquetes, como el brillo de los generadores de objetos. |

`ExyliaJobs` no está en `plugin.yml`, pero importa: el módulo `farming` se queda apagado mientras esté
instalado, porque los trabajos pagan por el mismo esfuerzo.

<Callout type="note" title="Los precios necesitan una economía">
Sin ninguna economía registrada, los precios y pagos se omiten y la consola lo dice al arrancar:
`No economy is installed: prices and payouts are skipped.` Instala
[ExyliaEconomy](/docs/exyliaeconomy/introduccion) o cualquier economía de Vault.
</Callout>

## Instalar

<Steps>
  <Step title="Pon los jars">
    Copia `ExyliaSurvivalCore.jar` y `ExyliaLib.jar` en `plugins/`, más cualquier plugin opcional de la
    tabla de arriba.
  </Step>
  <Step title="Arranca el servidor">
    El primer arranque escribe `config.yml`, los archivos de idioma bajo `lang/`, una carpeta por módulo
    bajo `modules/` y las tablas de cada módulo que esté encendido.
  </Step>
  <Step title="Apaga lo que no quieras">
    Todos los interruptores de módulo vienen en `true`. Pon el resto en `false` y reinicia — mira
    [Módulos](/docs/exyliasurvivalcore/modulos).
  </Step>
  <Step title="Fija el spawn y concede los permisos">
    `/spawn set`, y luego concede a tus grupos los permisos que necesiten. Mira
    [Primeros pasos](/docs/exyliasurvivalcore/primeros-pasos).
  </Step>
</Steps>

Avisos que conviene reconocer en la consola al arrancar:

- `No economy is installed: prices and payouts are skipped.` — no hay ninguna moneda registrada.
- `Missions are on but stats are off: …` y `Seasons rank stat counters, and the stats module is off:
  nothing will be ranked.` — ambos leen los contadores de estadísticas, que solo guarda el módulo
  `stats`.
- Un aviso por un `modules/blocked-items/rules.yml` sobrante, que ahora pertenece a ExyliaWarzone.

## Archivos generados

Todos viven en `plugins/ExyliaSurvivalCore/`.

| Ruta | Contenido |
|---|---|
| `config.yml` | `language`, `debug`, los interruptores de módulo, los tres ajustes de todo el servidor y la sección `teleport`. |
| `lang/<código>/messages.yml`, `lang/<código>/modules/<id>/messages.yml` | Cada línea que envía el plugin, en el idioma que elija `config.yml`. |
| `modules/<id>/config.yml` | Uno por módulo que tenga ajustes. |
| `modules/<id>/<datos>.yml` | Las escaleras: rangos, categorías, grupos, mundos, estadísticas, misiones, reglas. |
| `lang/<código>/modules/<id>/menus/`, `lang/<código>/menus/currency_select.yml` | Los menús fuera de `menus/admin/`. **Son tuyos para editar**; se añaden claves nuevas y se conservan tus valores. |
| `lang/<código>/menus/admin/` | Las pantallas de administración. **Se reescriben desde el jar en cada arranque y cada recarga.** |
| `.defaults/files/` | Los valores por defecto que revisaste por última vez, que es como una actualización distingue tus ediciones de las suyas. |
| `database.yml` | Motor de base de datos y Redis, escrito por ExyliaLib. |

El idioma sale de la clave `language` de `config.yml`. `default` sigue el idioma del servidor fijado en el
`config.yml` de ExyliaLib; cualquier otro valor (`en`, `es`, `pt`, `fr`, `ru`, `tr`) lo fija solo para este
plugin. Un servidor que usaba el plugin antes de que existieran los idiomas conserva sus archivos, movidos
a `lang/custom/`. Cómo se escribe y actualiza cada tipo de archivo está en
[Configuración](/docs/exyliasurvivalcore/configuracion).

<Callout type="danger" title="No edites nada bajo `menus/admin/`">
Ese directorio se reemplaza desde el jar cada vez que el plugin se activa **y** cada vez que ejecutas
`/survivalcoreadmin reload`. Las ediciones ahí se pierden, sin aviso.
</Callout>

## Base de datos

Por defecto el plugin usa **H2**: un archivo dentro de la carpeta del plugin, sin servidor y sin
mantenimiento. Para compartir casas, warps, kits, rangos y estadísticas entre servidores, apunta todos a la
misma base de datos:

```yaml title="plugins/ExyliaSurvivalCore/database.yml"
database:
  type: mysql
  mysql:
    host: 127.0.0.1
    port: 3306
    database: minecraft
    username: root
    password: ""
```

Motores admitidos: `h2`, `mysql`, `mariadb`, `postgresql` y `mongodb`. El archivo es de ExyliaLib; su
referencia completa, con el bloque `redis`, está en la [página de base de datos de la
librería](/docs/exylialib/base-de-datos).

Las tablas están en la página [Base de datos](/docs/exyliasurvivalcore/base-de-datos). Un módulo apagado
nunca crea las suyas.

## Recargar

```
/survivalcoreadmin reload
```

Alias `/survivalcore`. Se ejecuta desde la consola y recarga los archivos de configuración, los archivos
propios de cada módulo y los menús. Un paso que falla se informa por su nombre y los siguientes se
ejecutan igualmente.

| Se recarga | No se recarga |
|---|---|
| `config.yml`, incluidos `debug`, `language` y `teleport` | Los interruptores de módulo — un módulo encendido o apagado necesita reinicio |
| Cada archivo de `modules/<id>/` de un módulo encendido | La conexión a la base de datos |
| Los mensajes y los menús — lo que también reemplaza `menus/admin/` desde el jar | Lo guardado en la base de datos, que se lee cuando cambia |

Cuando un interruptor de `config.yml` ya no coincide con lo que está en marcha, la recarga termina con
*"Restart to apply module changes » …"* y los ids de esos módulos.

## Actualizar

Sustituye el jar y reinicia. `menus/admin/` se refresca desde el jar. Todo lo de la base de datos queda
intacto. Todo lo demás conserva tus ediciones:

- `config.yml` y el `config.yml` de cada módulo conservan tus valores.
- Los archivos de escaleras — `ranks.yml`, `categories.yml`, `missions.yml` y el resto — nunca se
  reescriben.
- Los demás menús y `seasons.yml` reciben las claves que añade una versión nueva; un valor por defecto que
  cambió espera en `/exylialib updates` en lugar de sobrescribir el tuyo. Un archivo cuyo `menu-version`
  incluido es mayor que el tuyo se reemplaza, y el tuyo se conserva al lado como `<nombre>.v<versión
  anterior>`.
