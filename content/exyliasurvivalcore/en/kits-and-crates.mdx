## Kits

A kit is a database row, built entirely from `/kitadmin`. There is no kit file.

`/kit` lists them, `/kit <id>` or `/kit claim <id>` takes one, and `/kit preview <id>` shows one without claiming. Buttons in the menus are gated by the same permissions as the commands.

| Field | What it does |
|---|---|
| Icon, name, description | How it looks in the list |
| Permission | Who may see and claim it |
| Enabled | Whether it exists for players at all |
| Items | Edited with ExyliaLib's loadout editor |
| Commands | Run alongside the items |
| Cooldown | Per player, in milliseconds. Default 24 hours |
| Max uses | `-1` for unlimited |
| First-join kit | Given automatically the first time a player joins |
| Auto-equip armour | Armour goes on rather than into the bag |
| Drop when full | On, a claim goes through and what does not fit is kept for the player's next join. Off, a claim that would not fit is refused before anything is given |
| Sort order | Where it sits in the list |

The list draws a kit in one of four states — ready, on cooldown, used up, or locked — each with its own
template in `modules/kits/menus/list.yml`.

The preview is worth knowing about: a shulker box or a bundle inside a kit is **openable in the
preview**, so a player can see what is inside before claiming. `preview.container-hint` in `modules/kits/messages.yml` is the
lore appended to those containers, with `%items%`.

| Setting | Default |
|---|---|
| `default-cooldown-ms` | 86400000 — 24 hours |
| `default-max-uses` | `-1` |
| `show-locked-kits` | `true` |

`exyliasurvivalcore.kits.bypass` skips cooldowns and use limits. `/kitadmin give <player> <kit>` hands the kit over whether or not the player has waited for it, `/kitadmin reset <player> <kit>` forgets that player's cooldown and use count for the kit, and `/kitadmin preview <kit>` shows it without needing the permission. Another plugin can do the same through the [API](/docs/exyliasurvivalcore/api), with or without the
cooldown and the use limit.

Kit permissions: `exyliasurvivalcore.kits` (`/kit`), `.kits.preview`, `.kits.admin` (`/kitadmin`) and `.kits.bypass`.

What does not fit when a kit's **Drop when full** is on goes into ExyliaLib's pending-reward queue and is
handed over the next time the player joins, never dropped on the floor.

Claims count `kits.claimed` and `kits.<kit>.claimed` in the
[stat counters](/docs/exyliasurvivalcore/missions-and-seasons#which-counters-can-be-named).

## Item spawners

A block that drops a glowing item on a random interval, under a countdown hologram. Built from
`/spawnersadmin`: a spawner has a loot table, a minimum and maximum interval, and a list of locations.

| Setting | Default | What it does |
|---|---|---|
| `detection-radius` | 2.0 | How far to look for an item already lying there |
| `hologram-offset-y` | 2 | Height of the countdown |
| `glow-enabled`, `glow-color` | `true`, `gold` | The dropped item's outline. The colour must be one of the sixteen named text colours |
| `particle-type` | `END_ROD` | Drawn at the spawner |
| `sound-radius` | 16.0 | How far the spawn sound carries |

When [ExyliaSpawners](/docs/exyliaspawners/introduction) is installed, this module stays off and
ExyliaSpawners provides item spawners. Its hologram lines (`hologram.ready`, `hologram.countdown`,
`hologram.disabled`, `hologram.no-location`) are in `modules/item-spawners/messages.yml`. Item spawners
belong to the server they were placed on, and each server loads only its own.
