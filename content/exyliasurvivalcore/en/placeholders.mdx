---
title: "Placeholders"
description: "Every placeholder the plugin registers, group by group, written in the PlaceholderAPI form every one of them takes."
---

Every placeholder below is written in full, and clicking one copies it.

They are registered through ExyliaLib as one group per module, so the registered name of a home
count is `homes_count`, and PlaceholderAPI reaches a registered name by putting the plugin in front
of it. So a scoreboard, a hologram or a chat plugin asks for `%exyliasurvivalcore_homes_count%`,
which is the form this page documents throughout; inside an Exylia plugin's own files the registered
name stands on its own, with no plugin in front of it.

The shorter `survivalcore` identifier is gone: `%survivalcore_homes_count%` no longer resolves.

<Callout type="note" title="A disabled module registers no names">
Each module claims its group as it enables. A module turned off in `config.yml` registers nothing,
so its placeholders resolve to nothing at all and the text stays on screen exactly as you wrote it.
Turning the module back on and reloading claims them again.
</Callout>

Durations are written out in full — `1h 5m 3s` — unless a row says they are short. Words such as
`Ready`, `N/A`, `Now` and `—` are the module's own wording, translated with the rest of its messages, so
a server in another language shows its own words. Money is formatted the way the rest of the plugin
formats it.

Placeholders for the plugins that took modules over (economy, market, rewards, combat, protections,
crates, mines and the rest) are on those plugins' own pages.

## Homes

| Placeholder | Description |
|---|---|
| `%exyliasurvivalcore_homes_count%` | Homes the player has set |
| `%exyliasurvivalcore_homes_max%` | How many they may set, permission included |

## Statistics

| Placeholder | Description |
|---|---|
| `%exyliasurvivalcore_stats_kills%` | Kills |
| `%exyliasurvivalcore_stats_deaths%` | Deaths |
| `%exyliasurvivalcore_stats_kdr%` | Kills over deaths, two decimals |
| `%exyliasurvivalcore_stats_streak%` | The streak they are on |
| `%exyliasurvivalcore_stats_best_streak%` | Their best ever |
| `%exyliasurvivalcore_stats_rank_<stat>%` | Their position on that stat's board, or the unknown word |
| `%exyliasurvivalcore_stats_value_<stat>%` | Their value for it, formatted, or the unknown word |
| `%exyliasurvivalcore_stats_counter_<key>%` | A counter read straight through, as a plain number, `0` when nothing has counted it yet |

`<stat>` is a key from `modules/stats/stats.yml`. The shipped keys are `kills`, `deaths`, `kdr`,
`best_kill_streak`, `current_streak`, `duels_won`, `balance`, `bounties_claimed`, `bounties_earned`,
`votes_total`, `votes_best_streak`, `market_sold`, `market_earned`, `blocks_mined`, `farming_harvested`,
`crates_opened`, `missions_completed`, `mobs_killed` and `playtime`. Several of them are filled by
counters that other plugins keep; a stat nobody counts shows `0`.

`<key>` in `stats_counter_` is a counter key such as `crates.opened`, and it does not have to be
declared in `stats.yml`: a counter exists as soon as something counts it, and the file only decides what
the stats screen shows and what is ranked. The key is read case-insensitively.

<Callout type="warning" title="The stat ids are not the same words as the streak placeholders">
`%exyliasurvivalcore_stats_streak%` and `%…_stats_best_streak%` above are placeholder names that read
the counters directly, and they work. They are **not** stat ids: inside `stats_value_`, `stats_rank_`
and `stats_top_*` the ids are `current_streak` and `best_kill_streak`. So
`%…_stats_value_streak%` answers the unknown word, and `%…_stats_value_current_streak%` is the one that
works.

`current_streak` also ships with `leaderboard: false`, so `%…_stats_top_name_1_current_streak%`
answers with a dash by design.
</Callout>

### Leaderboards

```text
%exyliasurvivalcore_stats_top_name_<position>_<stat>%
%exyliasurvivalcore_stats_top_value_<position>_<stat>%
```

The **position comes first** on purpose: a stat id may contain underscores and a position may not,
so the position is the one argument that can be read on its own. A row nobody occupies resolves to
`—`.

```text
#1 %exyliasurvivalcore_stats_top_name_1_kills% — %exyliasurvivalcore_stats_top_value_1_kills%
```

## Player settings

One name per preference, each answering `true` or `false`. Every setting is on until the player
turns it off, so a player nobody has stored anything for answers `true` throughout. The preferences live
in ExyliaLib's settings module, and the names are the setting ids with dashes turned into underscores.

| Placeholder | Description |
|---|---|
| `%exyliasurvivalcore_settings_death_messages%` | Whether other players' death messages reach them |
| `%exyliasurvivalcore_settings_join_leave_messages%` | Whether join and leave broadcasts reach them |
| `%exyliasurvivalcore_settings_rankup_announcements%` | Whether somebody reaching a new rank is announced to them |
| `%exyliasurvivalcore_settings_purchase_announcements%` | Whether somebody claiming a purchase is announced to them |
| `%exyliasurvivalcore_settings_mission_announcements%` | Whether mission announcements reach them |
| `%exyliasurvivalcore_settings_booster_announcements%` | Whether booster announcements reach them |
| `%exyliasurvivalcore_settings_project_announcements%` | Whether community project announcements reach them |
| `%exyliasurvivalcore_settings_season_announcements%` | Whether season announcements reach them |
| `%exyliasurvivalcore_settings_scheduled_announcements%` | Whether scheduled command announcements reach them |
| `%exyliasurvivalcore_settings_tpa_requests%` | Whether teleport requests reach them |
| `%exyliasurvivalcore_settings_tpa_auto_accept%` | Whether a request is accepted without asking |
| `%exyliasurvivalcore_settings_tpa_confirm%` | Whether sending a request asks for a confirmation |
| `%exyliasurvivalcore_settings_protection_messages%` | Protection messages; only applies when ExyliaProtections is installed |
| `%exyliasurvivalcore_settings_raid_announcements%` | Raid announcements; only applies when ExyliaProtections is installed |

The three `tpa_` ones are the same three answers the TPA group gives. They are read straight through to
the tpa module rather than stored twice, so a player never has two answers to one question.

## Scheduled commands

| Placeholder | Description |
|---|---|
| `%exyliasurvivalcore_scheduledcmds_remaining_<section>%` | Time until that section runs again, `Now`, or the unknown word |

This one asks for no viewer: how long until a section runs is the same answer for everybody, so it
works in a console-rendered board as well as in a player's.

## Boosters

| Placeholder | Description |
|---|---|
| `%exyliasurvivalcore_boosters_money%` | The reader's money multiplier, their own boosters and the global ones together — `1`, `1.5`, `2.25` |
| `%exyliasurvivalcore_boosters_xp%` | The same for experience |
| `%exyliasurvivalcore_boosters_drops%` | The same for drops |
| `%exyliasurvivalcore_boosters_active%` | The reader's boosters running right now |
| `%exyliasurvivalcore_boosters_stored%` | The reader's boosters kept but not started yet |
| `%exyliasurvivalcore_boosters_global_money%` | The money multiplier of the global boosters alone |
| `%exyliasurvivalcore_boosters_global_xp%` | The same for experience |
| `%exyliasurvivalcore_boosters_global_drops%` | The same for drops |
| `%exyliasurvivalcore_boosters_global_left%` | Time left on the first running global booster, or `—` |

The `global_` ones ask for no viewer. Every running booster of that type counts, whatever payout
source it is limited to, and they are combined by the module's stacking rule and capped at its maximum
multiplier.
