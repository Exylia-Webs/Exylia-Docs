---
title: "Placeholders"
description: "Every placeholder the plugin registers, group by group, written in the PlaceholderAPI form every one of them takes."
---

Every placeholder below is written in full, and clicking one copies it.

They are registered through ExyliaLib as one group per module, so the registered name of a home
count is `homes_count`, and PlaceholderAPI reaches a registered name by putting the plugin in front
of it. So a scoreboard, a hologram or a chat plugin asks for `%exyliasurvivalcore_homes_count%`,
which is the form this page documents throughout; inside an Exylia plugin's own files the registered
name stands on its own, with no plugin in front of it.

The plugin also answers under the shorter `survivalcore`, for every group on this page:
`%survivalcore_homes_count%` is the same placeholder as `%exyliasurvivalcore_homes_count%`. Nothing is
renamed — the long form keeps working, and it is the one written below.

<Callout type="note" title="A disabled module registers no names">
Each module claims its group as it enables. A module turned off in `config.yml` registers nothing,
so its placeholders resolve to nothing at all and the text stays on screen exactly as you wrote it.
Turning the module back on and reloading claims them again.
</Callout>

Durations are written out in full — `1h 5m 3s` — unless a row says they are short. Money is formatted
the way the rest of the plugin formats it.

## Statistics

| Placeholder | Description |
|---|---|
| `%exyliasurvivalcore_stats_kills%` | Kills |
| `%exyliasurvivalcore_stats_deaths%` | Deaths |
| `%exyliasurvivalcore_stats_kdr%` | Kills over deaths, two decimals |
| `%exyliasurvivalcore_stats_streak%` | The streak they are on |
| `%exyliasurvivalcore_stats_best_streak%` | Their best ever |
| `%exyliasurvivalcore_stats_rank_<stat>%` | Their position on that stat's board, or `N/A` |
| `%exyliasurvivalcore_stats_value_<stat>%` | Their value for it, formatted, or `N/A` |
| `%exyliasurvivalcore_stats_counter_<key>%` | A module counter read straight through, as a plain number, `0` when nothing has counted it yet |

`<stat>` is a key from `modules/stats/stats.yml`. The shipped keys are `kills`, `deaths`,
`best_kill_streak`, `current_streak`, `playtime` and `kdr`.

`<key>` in `stats_counter_` is a counter key such as `crates.opened` or `mines.starter.blocks`, and it
does not have to be declared in `stats.yml`: a counter exists as soon as something counts it, and the
file only decides what the stats screen shows and what is ranked. The key is read case-insensitively.

<Callout type="warning" title="The stat ids are not the same words as the streak placeholders">
`%exyliasurvivalcore_stats_streak%` and `%…_stats_best_streak%` above are placeholder names that read
the counters directly, and they work. They are **not** stat ids: inside `stats_value_`, `stats_rank_`
and `stats_top_*` the ids are `current_streak` and `best_kill_streak`. So
`%…_stats_value_streak%` answers `N/A`, and `%…_stats_value_current_streak%` is the one that works.

`current_streak` also ships with `leaderboard: false`, so `%…_stats_top_name_1_current_streak%`
answers with a dash by design.
</Callout>

### Leaderboards

```text
%exyliasurvivalcore_stats_top_name_<position>_<stat>%
%exyliasurvivalcore_stats_top_value_<position>_<stat>%
```

The **position comes first** on purpose: a stat id may contain underscores and a position may not,
so the position is the one argument that can be read on its own. A row nobody occupies resolves to
`—`.

```text
#1 %exyliasurvivalcore_stats_top_name_1_kills% — %exyliasurvivalcore_stats_top_value_1_kills%
```

## Crates

| Placeholder | Description |
|---|---|
| `%exyliasurvivalcore_crate_keys_<id>%` | Keys the player can spend on that crate: the ones in their inventory plus the balance the plugin holds for them |
| `%exyliasurvivalcore_crate_keys_total%` | The same count added up over every crate that exists |
| `%exyliasurvivalcore_crate_pity_<id>%` | Openings left before that crate has to pay its guaranteed tier |

Keys count what is carried as well as what is banked because that is the number a player can
actually spend, and it is the number the hologram over the crate is written with. A crate id nothing
defines answers nothing at all, and so does `crate_pity` for a crate with no pity threshold set —
the placeholder is left on screen rather than reading `0`, which would mean the next opening is the
guaranteed one.

## Player settings

One name per preference, each answering `true` or `false`. Every setting is on until the player
turns it off, so a player nobody has stored anything for answers `true` throughout.

| Placeholder | Description |
|---|---|
| `%exyliasurvivalcore_settings_death_messages%` | Whether other players' death messages reach them |
| `%exyliasurvivalcore_settings_join_leave_messages%` | Whether join and leave broadcasts reach them |
| `%exyliasurvivalcore_settings_rankup_announcements%` | Whether somebody reaching a new rank is announced to them |
| `%exyliasurvivalcore_settings_kill_announcements%` | Whether kill streak broadcasts reach them |
| `%exyliasurvivalcore_settings_bounty_announcements%` | Whether a bounty placed or claimed is announced to them |
| `%exyliasurvivalcore_settings_crate_announcements%` | Whether somebody winning a rare crate reward is announced to them |
| `%exyliasurvivalcore_settings_purchase_announcements%` | Whether somebody claiming a purchase is announced to them |
| `%exyliasurvivalcore_settings_tpa_requests%` | Whether teleport requests reach them |

## Economy

| Placeholder | Description |
|---|---|
| `%exyliasurvivalcore_economy_balance%` | The reader's balance in the default currency, formatted |
| `%exyliasurvivalcore_economy_balance_<currency>%` | The reader's balance in that currency, formatted |
| `%exyliasurvivalcore_economy_compact_<currency>%` | The same, short |
| `%exyliasurvivalcore_economy_raw_<currency>%` | The number alone |
| `%exyliasurvivalcore_economy_name_<currency>%` | The currency's plural name |
| `%exyliasurvivalcore_economy_symbol_<currency>%` | Its symbol |
| `%exyliasurvivalcore_economy_top_name_<position>_<currency>%` | The player at that position of a stored currency's leaderboard, or `—` |
| `%exyliasurvivalcore_economy_top_amount_<position>_<currency>%` | Their balance, formatted in that currency; a formatted zero when nobody holds the position |

The balances work for any currency ExyliaLib knows, stored here or not — `vault`, `points` — and leaving
the currency off reads the default one. `balance`, `compact` and `raw` read the viewer, so text rendered
with no player shows them empty; `name` and `symbol` ask for no viewer.

For the leaderboards, without a currency the default currency is ranked and without a position the
first place is read. Only a stored currency has a leaderboard; `vault`, named or left as the default,
ranks the stored currency published to Vault when there is one.

Every one reads memory — a loaded balance, the balance cache or the cached leaderboard — never the
database. See [Economy](/docs/exyliasurvivalcore/economy).

<Callout type="warning" title="The balances moved here from ExyliaLib">
Until ExyliaSurvivalCore `v1.2.2` and ExyliaLib `1.162.1` the balance names were ExyliaLib's, written
`%exylialib_economy_balance_<currency>%`. ExyliaLib registers none any more, so that form stays on
screen as written. Change it to `%exyliasurvivalcore_economy_balance_<currency>%` or
`%survivalcore_economy_balance_<currency>%`.
</Callout>

`%exyliasurvivalcore_stats_top_value_<position>_<stat>%`,
`%exyliasurvivalcore_seasons_top_name_<position>_<season>%` and
`%exyliasurvivalcore_seasons_top_value_<position>_<season>%` the position is read first and the id is
everything after it.

The one exception is the currency in the `economy` group. In
`%exyliasurvivalcore_economy_top_name_<position>_<currency>%` and
`%exyliasurvivalcore_economy_top_amount_<position>_<currency>%` only the word straight after the
position is read, and in `balance`, `compact`, `raw`, `name` and `symbol` only the first word after the
name, so a currency id with an underscore in it does not resolve there.
