## Player utilities

Nine commands, one node each, all under `exyliasurvivalcore.playerutils.`:

| Command | Aliases | Node |
|---|---|---|
| `/heal` | — | `.heal` |
| `/feed` | — | `.feed` |
| `/fly` | — | `.fly` |
| `/hat` | — | `.hat` |
| `/craft` | `/workbench`, `/wb` | `.craft` |
| `/anvil` | — | `.anvil` |
| `/ec` | `/enderchest` | `.ec` |
| `/nightvision` | `/nv` | `.nightvision` |
| `/ping` | — | `.ping` |

| Setting | Default |
|---|---|
| `night-vision-amplifier` | 0 |
| `heal-cooldown-seconds` | 0 |
| `feed-cooldown-seconds` | 0 |

`/heal` and `/feed` cooldowns also come per rank: grant `exyliasurvivalcore.playerutils.heal.cooldown.<seconds>`
or `.feed.cooldown.<seconds>` and the **lowest** number a player holds wins over the setting above. The
cooldowns survive a relog and a server switch.

`/fly` is taken away in combat and inside a protection under siege, and is given back afterwards. `/heal` is
refused in combat. `/hat` respects the blocked items list.

Flight and night vision are remembered across sessions.

## Repair

`/repair hand` repairs what the player is holding; `/repair all` repairs everything they carry. `/fix`
and `/reparar` are aliases.

| Setting | Default |
|---|---|
| `default-hand-price` | 75.0 |
| `default-hand-cooldown` | 120 |
| `default-all-price` | 200.0 |
| `default-all-cooldown` | 120 |
| `currency` | empty (the default currency) |

`currency` is any id from ExyliaLib's `economy.yml`, items and experience included.

`modules/repair/groups.yml` overrides those per permission group. It ships **empty**, with a commented
`vip` example:

```yaml
groups:
  vip:
    hand: { price: 2500.0, cooldown-seconds: 60 }
    all:  { price: 5000.0, cooldown-seconds: 60 }
```

A player in that group needs `exyliasurvivalcore.repair.group.vip`.

<Callout type="note" title="The cheapest group wins">
A player holding several groups gets, for each kind of repair, the **cheapest** one; the shorter cooldown
breaks a tie. A group's price replaces the default rather than competing with it, so a group priced above
the defaults makes its players pay more than everybody else.
</Callout>

`/repair hand <player>` and `/repair all <player>` repair somebody else, with `.repair.hand.others` and
`.repair.all.others`. `/repair lock` and `/repair unlock` protect an item from being repaired.
`exyliasurvivalcore.repair.bypass.price` and `.bypass.cooldown` skip the two costs.

Bare `/repair` prints the command framework's usage line — there is no root form. Whoever runs the command
pays and waits, also when repairing somebody else.

## Join and leave

`modules/join-leave/config.yml` holds the default messages and the first-join message; `groups.yml`
holds per-rank versions.

```yaml
settings:
  counter-enabled: true
  hide-vanilla-messages: true
default-join:
  enabled: true
  chat: ""
  sound: ""
  commands: []
  actionbar: ""
  title: ""
default-quit: { … }
first-join:   { … }
```

`%player%` and `%count%` — the join counter — are available. Commands take a `console:` or `player:`
prefix.

```yaml title="modules/join-leave/groups.yml"
groups:
  vip:
    permission: survivalcore.joinleave.vip
    priority: 10
    join: { enabled: true, chat: "", sound: "", actionbar: "", title: "", … }
    quit: { … }
```

The **highest priority** group whose permission the player holds wins. Note that the shipped example
names `survivalcore.joinleave.vip` — the short prefix — so grant it exactly as written or change the
string.

<Callout type="note" title="ExyliaLobby takes over">
When ExyliaLobby is installed and enabled, this module stays off and ExyliaLobby handles join and leave
messages, along with jumpads and portals. Set `defer-to-exylia-lobby: false` in the plugin's `config.yml`
to keep this plugin's own versions, then restart. The spawn module is not affected.
</Callout>

Join and leave messages are one of the broadcasts a player can turn off in [`/settings`](#player-settings).

## Scheduled commands

Console commands and broadcasts on a timer.

```yaml title="modules/scheduled-commands/config.yml"
sections:
  resource_drop:
    enabled: true
    interval: 1800
    network: false
    per-player: false
    commands: []
    broadcast: "{highlight}[Event] {letters}A resource drop is happening now!"
  daily_bonus:
    enabled: false
    interval: 86400
    network: false
    per-player: true
    commands:
      - "eco give %player_name% 50"
    broadcast: "{success}Pay day! {letters}Everyone online gets {highlight}50{letters}."
```

| Key | What it does |
|---|---|
| `interval` | Seconds between runs. The last run is remembered across restarts, and a new section first runs one full interval after it was added |
| `broadcast` | Sent to everybody who has server event announcements on; leave it empty to announce nothing |
| `network` | `true` runs the section once for the whole network, and its broadcast reaches the players of every server. `false` makes each server run it on its own |
| `per-player` | `true` runs the commands once for every online player, filling `%player_name%` (or `%player%`). It turns itself on when a line uses `%player_name%`. With `network: true` that is every player on the server that ran it |

One failing command does not stop the rest of the section. The file is written once, when it is missing:
nothing you add is pruned, nothing you delete comes back. Untouched examples from older releases are
brought up to date.

## Player settings

`/settings` — aliases `/preferences` and `/options` — is a screen every player owns, built on ExyliaLib's
settings module. Thirteen switches decide what reaches them.

| Setting | Id | What it turns off |
|---|---|---|
| Death messages | `death-messages` | The plugin's death broadcast |
| Join and leave messages | `join-leave-messages` | Both directions |
| Rankup announcements | `rankup-announcements` | Somebody else ranking up |
| Purchase announcements | `purchase-announcements` | Reclaim broadcasts |
| Mission announcements | `mission-announcements` | Somebody finishing a weekly [mission](/docs/exyliasurvivalcore/missions-and-seasons) |
| Booster announcements | `booster-announcements` | A global booster starting or ending |
| Project announcements | `project-announcements` | A community project completing and the next one starting |
| Season announcements | `season-announcements` | A [season](/docs/exyliasurvivalcore/missions-and-seasons) closing and who won it |
| Server event announcements | `scheduled-announcements` | What a [scheduled command](#scheduled-commands) section broadcasts |
| Protection messages | `protection-messages` | Titles and greetings walking into and out of protections |
| Raid announcements | `raid-announcements` | A protection raided, and siege windows opening and closing |
| TPA requests | `tpa-requests` | Whether they receive requests at all |
| TPA auto-accept | `tpa-auto-accept` | Accept without asking |
| TPA confirm | `tpa-confirm` | The confirmation before sending one |

<Callout type="note" title="Moved switches">
The kill, bounty, crate, duel, market, auction, vote, trade and autosell switches left with their features.
The old rows are no longer offered here.
</Callout>

Switches whose features live in another plugin (protections, for one) still show here when that module
is loaded. A switch that is on glows. There is no close button.

<Callout type="note" title="Every setting is on by default, and only the exceptions are stored">
The row stores the settings a player has turned **off**, so a preference added in a later release is on
for everybody with no migration to run. The three TPA rows are the tpa module's own — they are not
stored twice.
</Callout>

A setting whose module is off reads as unavailable and does nothing. The node for the command is
`exyliasurvivalcore.settings`.
