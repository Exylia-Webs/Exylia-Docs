You will have the everyday player commands working with permissions, a `/repair` that costs what you decide,
custom join and leave messages, commands that run on a timer, and a `/settings` screen where each player
mutes the announcements they do not want. Each part is its own module in `config.yml`
([Switch modules on and off](/docs/exyliasurvivalcore/modules)): `player-utils`, `repair`, `join-leave`,
`scheduled-commands` and `player-settings`.

## Player utilities

Nine commands, one permission each, all under `exyliasurvivalcore.playerutils.`: `/heal`, `/feed`, `/fly`,
`/hat`, `/craft` (aliases `/workbench`, `/wb`), `/anvil`, `/ec` (alias `/enderchest`), `/nightvision`
(alias `/nv`) and `/ping`. Grant the node to the ranks that should have each one; the table at the end of
this page lists them all.

`/heal` and `/feed` cooldowns also come per rank: grant `exyliasurvivalcore.playerutils.heal.cooldown.<seconds>`
or `.feed.cooldown.<seconds>` and the **lowest** number a player holds wins over the setting. The cooldowns
survive a relog and a server switch.

`/fly` is taken away in combat and inside a protection under siege, and is given back afterwards. `/heal` is
refused in combat. `/hat` respects the blocked items list. Flight and night vision are remembered across
sessions.

<Details title="Player utility settings (modules/player-utils/config.yml, under settings:)">

| Setting | Default | What it does |
|---|---|---|
| `night-vision-amplifier` | `0` | Strength of the `/nightvision` effect |
| `heal-cooldown-seconds` | `0` | Cooldown of `/heal` |
| `feed-cooldown-seconds` | `0` | Cooldown of `/feed` |
</Details>

## Repair

`/repair hand` repairs what the player is holding; `/repair all` repairs everything they carry. `/fix` is an
alias. By default hand repair costs 75 with a 120 second cooldown, and repairing everything costs 200 with a
120 second cooldown, in the default currency.

### Price repairs per rank

<Steps>
  <Step title="Open the groups file">
    Edit `modules/repair/groups.yml`. It ships **empty**, with a commented `vip` example.
  </Step>
  <Step title="Add a group">
    ```yaml
    groups:
      vip:
        hand: { price: 2500.0, cooldown-seconds: 60 }
        all:  { price: 5000.0, cooldown-seconds: 60 }
    ```
  </Step>
  <Step title="Give the permission">
    A player in that group needs `exyliasurvivalcore.repair.group.vip`.
  </Step>
  <Step title="Reload">
    Run `/survivalcoreadmin reload`.
  </Step>
</Steps>

<Callout type="note" title="The cheapest group wins">
A player holding several groups gets, for each kind of repair, the **cheapest** one; the shorter cooldown
breaks a tie. A group's price replaces the default rather than competing with it, so a group priced above the
defaults makes its players pay more than everybody else.
</Callout>

`/repair hand <player>` and `/repair all <player>` repair somebody else, with
`exyliasurvivalcore.repair.hand.others` and `.all.others`; whoever runs the command pays and waits.
`/repair lock` and `/repair unlock` protect an item from being repaired.
`exyliasurvivalcore.repair.bypass.price` and `.bypass.cooldown` skip the two costs. Bare `/repair` prints the
usage line; there is no root form.

<Details title="Repair settings (modules/repair/config.yml, under settings:)">

| Setting | Default |
|---|---|
| `default-hand-price` | `75.0` |
| `default-hand-cooldown` | `120` (seconds) |
| `default-all-price` | `200.0` |
| `default-all-cooldown` | `120` (seconds) |
| `currency` | empty, which means the default currency |

`currency` is any id from ExyliaLib's `economy.yml`, items and experience included. See
[ExyliaLib economy](/docs/exylialib/economy).
</Details>

## Join and leave

Chat lines, titles and action bars live in `modules/join-leave/messages.yml`: `default-join`,
`default-quit` and `first-join`. Sounds, commands and the on/off switch of each are in
`modules/join-leave/config.yml`. `%player%` and `%count%` (the join counter) work in the text.

<Steps>
  <Step title="Edit the default lines">
    Change `default-join.chat`, `default-quit.chat` and `first-join.chat` in `messages.yml`. A line is
    coloured with [ExyliaLib colours](/docs/exylialib/colours).
  </Step>
  <Step title="Add a rank version">
    In `modules/join-leave/groups.yml`, give a group a `permission` and a `priority`, plus its own
    `join` and `quit` text. The shipped `vip` group has only the text: add `permission:` (for example
    `survivalcore.joinleave.vip`) and `priority: 10`, or it never matches.
  </Step>
  <Step title="Reload">
    Run `/survivalcoreadmin reload`.
  </Step>
</Steps>

The **highest priority** group whose permission the player holds wins.

<Callout type="warning" title="ExyliaLobby takes over">
When ExyliaLobby is installed and enabled, this module stays off and ExyliaLobby handles join and leave
messages, along with jump pads and portals. Set `defer-to-exylia-lobby: false` in the plugin's `config.yml`
to keep this plugin's own versions, then restart. The spawn module is not affected.
</Callout>

Join and leave messages are one of the broadcasts a player can turn off in [`/settings`](#player-settings).

<Details title="Join and leave settings (modules/join-leave/config.yml)">

```yaml
settings:
  counter-enabled: true
  hide-vanilla-messages: true
default-join:
  enabled: true
  sound: "BLOCK_NOTE_BLOCK_PLING|0.6|1.4"
  commands: []
default-quit:
  enabled: true
  sound: ""
  commands: []
first-join:
  enabled: true
  sound: "BLOCK_NOTE_BLOCK_CHIME|0.7|1.2"
  commands: []
```

Commands take a `console:` or `player:` prefix. `counter-enabled` shows the player's join number on first
join, and `hide-vanilla-messages` replaces the vanilla lines with these.
</Details>

## Scheduled commands

Console commands and broadcasts on a timer, from `modules/scheduled-commands/config.yml`.

```yaml
sections:
  resource_drop:
    enabled: true
    interval: 1800
    network: false
    per-player: false
    commands: []
    broadcast: "{highlight}[Event] {letters}A resource drop is happening now!"
  daily_bonus:
    enabled: false
    interval: 86400
    network: false
    per-player: true
    commands:
      - "eco give %player_name% 50"
    broadcast: "{success}Pay day! {letters}Everyone online gets {highlight}50{letters}."
```

<Details title="Section keys">

| Key | What it does |
|---|---|
| `interval` | Seconds between runs. The last run is remembered across restarts, and a new section first runs one full interval after it was added |
| `broadcast` | Sent to everybody who has server event announcements on; leave it empty to announce nothing |
| `network` | `true` runs the section once for the whole network, and its broadcast reaches the players of every server. `false` makes each server run it on its own |
| `per-player` | `true` runs the commands once for every online player, filling `%player_name%` (or `%player%`). It turns itself on when a line uses `%player_name%`. With `network: true` that is every player on the server that ran it |

One failing command does not stop the rest of the section. The file is written once, when it is missing:
nothing you add is pruned, nothing you delete comes back. Untouched examples from older releases are
brought up to date.
</Details>

## Player settings

`/settings` (aliases `/preferences`, `/options`, permission `exyliasurvivalcore.settings`) is a screen every
player owns, built on ExyliaLib's settings module. Fourteen switches decide what reaches them. Every one is
on by default, and a player turns off what they do not want.

| Setting | What it turns off |
|---|---|
| Death messages | The plugin's death broadcast |
| Join & leave | Join and leave messages, both directions |
| Rank ups | Somebody else ranking up |
| Purchases | Reclaim broadcasts |
| Missions | Somebody finishing a weekly [mission](/docs/exyliasurvivalcore/missions-and-seasons) |
| Boosters | A global booster starting or ending |
| Projects | A community project completing and the next one starting |
| Seasons | A [season](/docs/exyliasurvivalcore/missions-and-seasons) closing and who won it |
| Server events | What a [scheduled command](#scheduled-commands) section broadcasts |
| Protection messages | Titles and greetings walking into and out of protections |
| Raid announcements | A protection raided, and siege windows opening and closing |
| Teleport requests | Whether they receive requests at all |
| Auto accept | Accept teleport requests without asking |
| Confirm before sending | The confirmation before sending a request |

Switches whose features live in another plugin (protections, for one) still show when that module is loaded.
A setting whose module is off reads as unavailable and does nothing. The three teleport rows are the `tpa`
module's own, so they are not stored twice.

<Callout type="note" title="Moved switches">
The kill, bounty, crate, duel, market, auction, vote, trade and autosell switches left with their features.
</Callout>

### Check that it works

Run `/settings`, turn off Join & leave and have another player join: you should see no join line, while they
still do. Run `/heal` after granting `exyliasurvivalcore.playerutils.heal`.
