<Callout type="note" title="Kill rewards, bounties and graves moved out">
Kill rewards and streak payouts were dropped from this plugin: [ExyliaCombat](/docs/exyliacombat/kill-rewards)
pays for kills. Bounties on players' heads are also ExyliaCombat's now. Graves are
[ExyliaGraves](/docs/exyliagraves/graves). None of them has a module, setting or command here any more. The
`modules/kill-rewards`, `modules/bounties` and `modules/graves` files left over from an older install are not
read.
</Callout>

## Statistics

Everything on the stats screen is a **counter**: kills, deaths, best kill streak, blocks mined, crates opened,
warps taken. Modules here count what their players do, and other Exylia plugins feed the same table through
the survival service. `modules/stats/stats.yml` decides which of them are shown and
ranked.

The shipped file is deliberately short — the stats players compete on:

```yaml
stats:
  kills:              { type: COUNTER, counter: 'kills.players',      format: NUMBER,  leaderboard: true, … }
  deaths:             { type: COUNTER, counter: 'deaths.total',       format: NUMBER,  leaderboard: true, … }
  kdr:                { type: COMPUTED, format: DECIMAL, formula: KILLS_PER_DEATH }
  best_kill_streak:   { type: COUNTER, counter: 'kills.best_streak',  format: NUMBER,  leaderboard: true, … }
  current_streak:     { type: STREAK,  format: NUMBER,  leaderboard: false, … }
  duels_won:          { type: COUNTER, counter: 'duels.wins',         format: NUMBER }
  balance:            { type: VAULT,   format: MONEY }
  bounties_claimed:   { type: COUNTER, counter: 'bounties.claimed',   format: NUMBER }
  bounties_earned:    { type: COUNTER, counter: 'bounties.earned',    format: MONEY }
  votes_total:        { type: COUNTER, counter: 'votes.total',        format: NUMBER }
  votes_best_streak:  { type: COUNTER, counter: 'votes.best_streak',  format: NUMBER }
  market_sold:        { type: COUNTER, counter: 'market.sold',        format: NUMBER }
  market_earned:      { type: COUNTER, counter: 'market.earned',      format: MONEY }
  blocks_mined:       { type: COUNTER, counter: 'mines.blocks',       format: NUMBER }
  farming_harvested:  { type: COUNTER, counter: 'farming.harvested',  format: NUMBER }
  crates_opened:      { type: COUNTER, counter: 'crates.opened',      format: NUMBER }
  missions_completed: { type: COUNTER, counter: 'missions.completed', format: NUMBER }
  mobs_killed:        { type: COUNTER, counter: 'kills.mobs',         format: NUMBER }
  playtime:           { type: PLAYTIME, format: TIME }
```

Every entry ships `enabled: true`, and every one except `current_streak` is ranked. A stat that has no counter feeding it (the bounty, vote or duel ones on a server without the plugin that counts them) simply reads 0.

| `type` | Where the number comes from |
|---|---|
| `COUNTER` | A counter, named by `counter`. Left out, the stat's own id is used as the key |
| `COMPUTED` | A formula over counters (`KILLS_PER_DEATH` reads `kills.players` and `deaths.total`) |
| `STREAK` | The kill streak the player is on now |
| `PLAYTIME` | Time played, from ExyliaLib's playtime service |
| `PAPI` | Any PlaceholderAPI name |
| `VAULT` | The player's balance |

A file that still says `INTERNAL` for `kills`, `deaths`, `best_kill_streak` or `current_streak` is read as the counter or streak that replaced it.

`format` is `NUMBER`, `DECIMAL`, `MONEY` or `TIME`. `leaderboard: false` keeps a stat off the boards
while still showing it on the profile.

<Callout type="note" title="`COMPUTED` has exactly one formula">
`KILLS_PER_DEATH` is the only value `formula` accepts. Anything else silently falls back to it.
</Callout>

| Setting | Default | What it does |
|---|---|---|
| `leaderboard-refresh-interval` | 300 | Seconds between leaderboard rebuilds |
| `papi-sample-interval` | 60 | Seconds between samples of a `PAPI` or `VAULT` stat |
| `leaderboard-size` | 100 | How deep a board goes |
| `counter-flush-interval` | 60 | Seconds between writes of the counters that changed. Anything below 5 is treated as 5 |
| `ignored-mob-spawn-reasons` | `SPAWNER`, `SPAWNER_EGG`, `DISPENSE_EGG` | Mobs that spawned this way do not count as mob kills (`kills.mobs`, missions). Names from Bukkit's `SpawnReason` |

A reload reschedules the timers with the new values.

### Counters

A counter exists the moment a module counts it; nothing has to be declared.
`%exyliasurvivalcore_stats_counter_<key>%` reads any counter by its key, as a plain number, whether or
not `stats.yml` lists it — `%exyliasurvivalcore_stats_counter_mines.blocks%`, for instance. A `COUNTER`
block is only what puts it on the stats screen and gives it a leaderboard. Missions and seasons read the
same counters: see [Missions and seasons](/docs/exyliasurvivalcore/missions-and-seasons).

| Source | Counters |
|---|---|
| Stats (PvP) | `kills.players`, `kills.best_streak`, `kills.mobs`, `kills.mob.<type>`, `deaths.total` |
| Rankup, farming, reclaim | `rankup.ranks`, `rankup.prestiges`, `farming.harvested`, `farming.<category>.harvested`, `reclaim.claimed`, `reclaim.<section>.claimed` |
| Kits | `kits.claimed`, `kits.<kit>.claimed` |
| Warps, homes, spawn, back, tpa, rtp | `warps.used`, `warps.<warp>.used`, `homes.teleports`, `homes.created`, `homes.deleted`, `spawn.teleports`, `back.used`, `tpa.teleports`, `rtp.used`, `rtp.<id>.used` |
| Portals, jump pads | `portals.used`, `portals.<portal>.used`, `jumpads.used`, `jumpads.<jumpad>.used` |
| Repair | `repair.items` |
| Missions | `missions.completed`, `missions.<pool>.completed`, `missions.earned` |
| Fed by other plugins | `mines.blocks`, `crates.opened`, `bounties.*`, `graves.*`, `duels.*`, `votes.*`, `rewards.claimed`, `market.*`, `auctions.*`, `orders.*`, `trade.completed`, `protections.*`, `lootchests.*`, `powerups.picked`, `afkzones.rewards`, `playtime.rewards` |

Market, auction and order money counters also come per currency (`market.<currency>.earned`, `auctions.<currency>.spent`, `orders.<currency>.earned`). The last row is fed by the Exylia plugins that now own those features, where installed; the list at the top of the shipped `stats.yml` documents the keys.

Keys are lower-cased, and one longer than 100 characters is ignored rather than cut short. Money
counters — `.earned`, `.spent` — add whole units. `votes.best_streak` is a best, not a sum: it keeps the
highest streak seen. 

Counting happens in memory. Changed counters are written every `counter-flush-interval` seconds, when a
player leaves and on shutdown, so a crash can lose at most that interval. While the stats module is off
nothing is counted, and what would have been is not kept for later.

<Callout type="danger" title="`/stats` still does not exist at runtime">
The command was rewritten to open anybody's stats, including a player who is offline — their PvP
values, their counters, and the last sample of their `PAPI` and `VAULT` stats — but its method still
carries none of the annotations that make Lamp register a command, so nothing is added to the server.
`exyliasurvivalcore.stats` and `exyliasurvivalcore.stats.others` are therefore unreachable, and so is
looking at another player's stats.

The screens themselves work: bind `survivalcore:stats_open` to a button in any menu, an NPC or a
hotbar item and the viewer's own profile and its leaderboards open normally. Leaderboards include
offline players.
</Callout>

## Death

The death module is three settings.

| Setting | Default | What it does |
|---|---|---|
| `scatter-radius` | 0.3 | How far drops are spread, so a stack is not one pile |
| `fire-protection` | `true` | Drops survive fire — **not** lava |
| `custom-messages` | `true` | The death line comes from `messages.yml` rather than vanilla |

The death broadcast is one of the broadcasts that respect a player's `/settings` preferences.

When a grave plugin such as [ExyliaGraves](/docs/exyliagraves/graves) takes the drops, the death module finds
nothing left to scatter.
