## Rankup

A ladder of ranks in `modules/rankup/ranks.yml`. Each one has requirements to meet and a reward for
meeting them.

```yaml
ranks:
  member:
    display-name: "&7Member"
    icon: COAL
    order: 1
    description: []
    requirements: []
    reward:
      commands: []
      broadcast: ""
      sound: ""
    auto-rankup: false
```

`/rankup` opens the ladder, showing what is met and what is not; `/rankup claim` takes the next rank
when everything is satisfied. `settings.auto-rankup` promotes without asking, and a per-rank
`auto-rankup` does the same for one rung.

### Requirements

A requirement is a `type` and one field. Any entry may also carry `display`, which is the line shown in
the menu instead of a generated one.

| `type` | Field | Meaning |
|---|---|---|
| `money` | `amount` (and an optional `currency`) | A balance, through the economy. `currency` is an id from ExyliaLib's `economy.yml`; left out, the default currency |
| `playtime` | `time` | Time played — `30m`, `1h`, `5h` |
| `placeholder` | `condition` | A PlaceholderAPI comparison |
| `permission` | `node` | A permission node they must hold |

A `money` amount grows with prestige: it is multiplied by `prestige.cost-multiplier` once per prestige
level the player holds, and the menu shows the amount they actually need.

A requirement whose `type` is not one of the four above is reported in the console and ignored, so a rank
whose only requirement has an unknown type costs nothing.

Every rank-up, asked for with `/rankup claim` or automatic (`settings.auto-rankup`, or a rank's own
`auto-rankup`), takes the same path: `RankUpEvent` fires first (a cancelled one costs nothing), then every
`money` requirement is charged, scaled for prestige and one currency after another or none of them, then the
reward runs. If the promotion loses a race, the charge is refunded. The shipped ranks no longer carry
`eco take` lines; a rank's reward commands only hand out the reward.

### Prestige

A player at the top of the ladder can prestige with `/rankup prestige`, or with the star in the corner
of the `/rankup` menu. It charges the prestige cost, takes their rank away, raises their prestige level
by one and runs the prestige rewards. They then climb the ladder again from the first rank, with every
`money` requirement scaled to the new level.

The `prestige` section of `modules/rankup/config.yml`:

| Setting | Default | What it does |
|---|---|---|
| `enabled` | `true` | Whether anyone can prestige |
| `max-level` | 0 | Highest prestige level. `0` means no limit |
| `cost` | 25000 | Money charged to prestige. `0` is free |
| `cost-currency` | empty | The currency `cost` is charged in: an id from ExyliaLib's `economy.yml`. Empty is the default currency |
| `cost-multiplier` | 1.5 | Applied to every `money` requirement once per level: a $1,000 rank costs $1,500 on prestige 1 and $2,250 on prestige 2. `1.0` keeps the ladder the same |
| `reward-commands` | `lp user %player% parent set member` | Console commands. `%player%` is the player, `%level%` the level just reached |
| `reward-broadcast` | `{highlight}✦ {letters}%player% {muted}reached prestige {highlight}%level%{muted}!` | Sent to everyone with rank-up announcements on. Empty for none |
| `reward-sound` | `UI_TOAST_CHALLENGE_COMPLETE\|1.0\|1.0` | Played to the player. Empty for none |

A prestige is refused when it is disabled, when the player is not on the last rank, when they are
already at `max-level`, and when they cannot pay — including when `cost` is above 0 and no economy is
available. The menu's star shows the current and next level, the cost (`Free` at 0) and which of those
applies. `%exyliasurvivalcore_rankup_can_prestige%` answers `yes` or `no`.

`/rankupadmin` (alias `/rua`, `survivalcore.rankup.admin`) has `prestige <player> <level>` to set a prestige
level directly, `set <player> <rank>` to move a player around the ladder, and `info <player>` to report where
they are; `prestige` and `set` need `survivalcore.rankup.admin.set`. A rank id that is not in the file is
refused. Wiping a player's progress is `/exylialib resetplayer`.

`settings.notify-on-login` tells a player on join when they can rank up.

<Callout type="note" title="Playtime rewards moved to ExyliaRewards">
There is no playtime module or `/playtime` command here any more: playtime tiers are
[ExyliaRewards](/docs/exyliarewards/rewards). Time played is tracked by ExyliaLib's playtime service, which the
`playtime` rank requirement and the `PLAYTIME` stat read.
</Callout>

## Farming

<Callout type="note" title="Farming steps aside for ExyliaJobs">
While [ExyliaJobs](/docs/exyliajobs/introduction) is installed, this module stays off and Jobs pays for the same actions. It loads again if Jobs is removed.
</Callout>

Counts blocks broken or mobs killed, and pays per N and at milestones.

```yaml
categories:
  wheat_farming:
    type: BLOCK
    display-name: "&eWheat"
    icon: WHEAT
    tracked: [WHEAT]
    require-max-growth: true
    count-above: false
    reward-every: 50
    reward:      { money: 2, commands: [], message: "", actionbar: "", sound: "" }
    milestones:
      novice: { display-name: "…", required-count: 100, money: 10, … }
    infinite-milestone:
      enabled: true
      interval: 1000
      money: 50
```

| Key | What it does |
|---|---|
| `type` | `BLOCK` for breaking, `ENTITY` for killing |
| `tracked` | The materials or entity types that count |
| `require-max-growth` | Only fully grown crops count |
| `count-above` | For stacking plants — sugar cane, bamboo — count the blocks above too |
| `reward-every` | Pay every N. `0` turns the per-N reward off |
| `milestones` | One-off rewards at a total count |
| `infinite-milestone` | Keeps paying every `interval` after the named milestones run out |

Every reward block — `reward`, each milestone and `infinite-milestone` — takes `money`, `commands`,
`message`, `actionbar` and `sound`. `money` is paid in the default currency and multiplied by money
boosters for `farming` (see [Economy](/docs/exyliasurvivalcore/economy)); `%money%` is what was paid,
after boosters. The shipped categories pay through `money` rather than `eco give` commands.

A reward's `money` can name another currency: `money: {amount: 50, currency: gems}` (an id from ExyliaLib's
`economy.yml`).

`/farming` shows progress. `/farmingadmin` (alias `/fa`) has `set`, `reset` and `info`, all behind
`survivalcore.farming.admin`; the two that write also need `survivalcore.farming.admin.set`.

## Reclaim

`/reclaim` runs a block of commands — a donor kit, a monthly crate, whatever you write. Sections are
defined in `modules/reclaim/config.yml`.

```yaml
sections:
  default:
    permission: exyliasurvivalcore.reclaim.default
    priority: 0
    each: "-1"
    broadcast: ""
    commands: []
  vip:
    permission: exyliasurvivalcore.reclaim.vip
    priority: 1
    each: "7d"
    commands: []
```

Sections are sorted by **priority, highest first**, and the first one whose permission the player holds
is the one that runs. So a VIP gets the VIP section and nothing else, not both.

`each` is how often it may be run: `-1` means once ever, and anything else is a duration — `7d`, `12h`,
`30m`, `45s`. `%player%` is substituted into every command.

`/reclaimadmin resetsection <player> <section>` (`exyliasurvivalcore.reclaim.admin`) clears one section's record.

`/reclaim` needs `exyliasurvivalcore.reclaim` (granted to everyone), and each section also asks for its own
node. A player holding no section node is told there is nothing for them. Grant
`exyliasurvivalcore.reclaim.default` to the group that should have the default section, and nothing wider.

<Callout type="note" title="Four modules used to lose a claim">
Farming, playtime rewards, rankup and reclaim (playtime rewards have since moved to ExyliaRewards) each saved a stale copy of the player's row alongside the
claim's own write, and when the stale save landed second the claim vanished and could be collected
again on the next login. Fixed in 1.1.1; if you are on an older build, that is what you were seeing.
</Callout>

## Counters

These modules count into the stats counters, which leaderboards, missions and seasons read — see
[Statistics](/docs/exyliasurvivalcore/combat#statistics).

| Counter | What it counts |
|---|---|
| `rankup.ranks` | Ranks taken, by hand or automatically |
| `farming.harvested` | Every block or mob a farming category counted |
| `farming.<category>.harvested` | The same, for one category |
| `reclaim.claimed` | Reclaim sections run |
| `reclaim.<section>.claimed` | The same, for one section |
| `rankup.prestiges` | Prestiges taken |
