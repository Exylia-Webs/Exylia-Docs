By the end of this page the spawn, one warp and one kit work in game. A fresh server needs no permission setup: player features are on for everyone and administration is for operators.

<Steps>
  <Step title="Set the spawn">
    Stand where players should arrive and run `/survivalcoreadmin setspawn` (or `/setspawn`). The spawn module settings decide whether players are also sent there on their first join, on every join and when they respawn.
  </Step>
  <Step title="Create a warp">
    Run `/warpadmin`, click **Create ▸ Warp** and type an id in chat. In the warp screen click **Location** to set it where you stand, then set **Display name** and **Icon**. A new warp is enabled, free, and open to everyone. **Cost** and **Permission** are on the same screen if you want to change that.
  </Step>
  <Step title="Create a kit">
    Run `/kitadmin`, click **Create ▸ Kit** and type an id. In the kit screen open **Items** to choose what it gives, then set **Cooldown**, **Max uses** and **Permission** if you need them. A new kit is enabled and uses the default cooldown and use limit.
  </Step>
  <Step title="Check the random teleport world">
    `modules/rtp/worlds.yml` ships `world` enabled and `world_nether` disabled. A world that is not in that file cannot be reached with `/rtp`. Pre-generate the area with Chunky so the teleport finds a spot in seconds.
  </Step>
</Steps>

## Check that it works

Join as a normal player, without operator rights.

1. `/spawn` takes you to the spawn you set. A warmup may apply first; do not move until it ends.
2. `/warp` lists the warps you may use. `/warp <id>` takes you to yours.
3. `/kit` lists the kits. `/kit <id>` gives you the items.
4. `/rtp` sends you to a random spot in the world.

If one fails, see [Common problems](/docs/exyliasurvivalcore/troubleshooting).

<Callout type="note" title="Some admin nodes start with `survivalcore.`">
The older administration nodes keep the short prefix (`survivalcore.admin`, `survivalcore.admin.reload` and a few more). Grant them exactly as spelled; an `exyliasurvivalcore.admin` does nothing. See [Permissions](/docs/exyliasurvivalcore/permissions).
</Callout>

## The ladders worth writing next

Most content is built from in-game menus. These are files, because they are ladders rather than objects:

| File | What it is |
|---|---|
| `modules/rankup/ranks.yml` | The rank ladder: order, requirements, rewards |
| `modules/farming/categories.yml` | What counts as farming, per-N rewards and milestones |
| `modules/repair/groups.yml` | Repair prices and cooldowns per permission group |
| `modules/missions/missions.yml` | The missions a daily or weekly rotation draws from |
| `modules/seasons/seasons.yml` | The rankings: which stat counter, which period, which prizes |

## Good to know

- `/survivalcoreadmin reload` re-reads the configuration and the menus. Module switches need a restart, and the reload names the ones waiting for it.
- `/settings` is where a player turns off the broadcasts and requests they do not want.
- Everything under `menus/admin/` is regenerated from the jar on every start and every reload. Edit the owner menus under `lang/<code>/` instead: those keep your edits when the plugin updates.
- Crates, the shop, protections and the other modules that moved are set up in their own plugins; see [Modules](/docs/exyliasurvivalcore/modules).
