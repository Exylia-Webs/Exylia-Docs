## Permissions

`plugin.yml` declares every node with a default: player features are `true`, administration and bypasses
are `op`. A fresh server therefore works without any permission setup. Take a player node away from your
default group only to turn it into a rank perk, and grant the administration nodes to staff. The full
list is on the [Permissions](/docs/exyliasurvivalcore/permissions) page.

<Callout type="note" title="Some admin nodes start with `survivalcore.`">
The older administration nodes keep the short prefix (`survivalcore.admin`, `survivalcore.admin.reload`
and a few more). Grant them exactly as spelled; an `exyliasurvivalcore.admin` does nothing.
</Callout>

## Setting the world up

<Steps>
  <Step title="Set the spawn">
    `/survivalcoreadmin setspawn` (or `/setspawn`) where you are standing. The spawn module's
    settings decide whether players are also sent there on first join, on every join and on respawn.
  </Step>
  <Step title="Make a warp">
    `/warpadmin` opens the warp editor. Each warp has a display name, an icon, a cost, a permission and
    a location, and `/warp` lists the ones a player may use.
  </Step>
  <Step title="Make a kit">
    `/kitadmin` opens the kit editor. Cooldown, use limit, permission and the items are on the same
    screens.
  </Step>
  <Step title="Point RTP at a world">
    `modules/rtp/worlds.yml` ships `world` enabled and `world_nether` disabled. A world that is not in
    that file cannot be reached with `/rtp`. Pre-generate the area with Chunky and the pool fills in
    seconds instead of minutes.
  </Step>
</Steps>

## The ladders worth writing first

Most content is built from in-game menus and stored in the database. These are files, because they are
ladders rather than objects:

| File | What it is |
|---|---|
| `modules/rankup/ranks.yml` | The rank ladder: order, requirements, rewards |
| `modules/farming/categories.yml` | What counts as farming, per-N rewards and milestones |
| `modules/repair/groups.yml` | Repair prices and cooldowns per permission group |
| `modules/missions/missions.yml` | The missions a daily or weekly rotation draws from |
| `modules/seasons/seasons.yml` | The rankings: which stat counter, which period, which prizes |

## A first look around

- `/survivalcoreadmin` opens the admin hub; `/survivalcoreadmin reload` re-reads the configuration and
  the menus. Module switches need a restart, and the reload names the ones waiting for it.
- `/settings` is what a player uses to turn off the broadcasts and requests they do not want.
- Settings an administrator tunes while the server runs have their own screens in the admin hub.
- Everything under `menus/admin/` is regenerated from the jar on every start **and every reload**. Edit
  the owner menus under `lang/<code>/` instead: those keep your edits when the plugin updates.
- Crates, the shop, protections, bounties and the other modules that moved are set up in their own
  plugins; see [Modules](/docs/exyliasurvivalcore/modules).
