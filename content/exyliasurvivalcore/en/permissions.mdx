---
title: "Permissions"
description: "Every node declared in plugin.yml and its default, the ones that carry a number, and the ones you write yourself."
---

`plugin.yml` declares the nodes below with a default, so nobody has to grant the player features. Three
defaults exist:

- **Players** (`true`): everyone has the node. Take it away from the default group to make it a rank perk.
- **Operators** (`op`): administration, perks and bypasses; only operators pass until you grant them.
- **Numeric or prefix nodes** are not declared; they are explained under
  [Nodes that carry a number](#nodes-that-carry-a-number).

Every node below starts with `exyliasurvivalcore.` unless it is written in full.

<Callout type="warning" title="Some admin nodes start with `survivalcore.`">
The older administration nodes keep the short prefix: `survivalcore.admin`, `survivalcore.admin.reload`,
`survivalcore.admin.homes`, `survivalcore.rankup.admin`, `survivalcore.rankup.admin.set`,
`survivalcore.farming.admin`, `survivalcore.farming.admin.set` and `survivalcore.portals.admin`. Every
other node uses `exyliasurvivalcore.`. Both prefixes are intentional.
</Callout>

### Bypasses

All default to **op**. A bypass skips the warmup, price or cooldown entirely, so the numeric nodes below do
not matter to whoever holds one.

| Permission | Skips |
|---|---|
| `exyliasurvivalcore.spawn.bypass` | The `/spawn` warmup |
| `exyliasurvivalcore.homes.bypass` | The home warmup |
| `exyliasurvivalcore.back.bypass` | The `/back` warmup |
| `exyliasurvivalcore.rtp.bypass` | The RTP cooldown and price (not the warmup) |
| `exyliasurvivalcore.warps.bypass` | A warp's warmup, cooldown and price |
| `exyliasurvivalcore.warps.bypass.cost` | A warp's price |
| `exyliasurvivalcore.warps.bypass.cooldown` | A warp's cooldown |

`combat-blocks-teleports` is not a warmup: no bypass node skips it.

## Nodes that carry a number

These nodes end in a value rather than a word and are not declared in `plugin.yml`. Each is a setting you
grant per rank.

**The highest one a player holds wins**, and none at all falls back to the setting:

| Permission | Effect |
|---|---|
| `exyliasurvivalcore.homes.max_homes.<n>` | How many homes the player may set. With none, `max-homes` in `modules/homes/config.yml` |
| `exyliasurvivalcore.near.radius.<n>` | The radius `/near` searches, still capped by `max-radius` in `modules/near/config.yml` |

**The lowest one a player holds wins**, in seconds:

| Permission | Effect |
|---|---|
| `exyliasurvivalcore.homes.warmup.<n>` | Home warmup |
| `exyliasurvivalcore.tpa.warmup.<n>` | TPA warmup |
| `exyliasurvivalcore.tpa.cooldown.<n>` | TPA cooldown |
| `exyliasurvivalcore.back.warmup.<n>` | `/back` warmup |
| `exyliasurvivalcore.spawn.warmup.<n>` | `/spawn` warmup |
| `exyliasurvivalcore.warps.warmup.<n>` | Warp warmup |
| `exyliasurvivalcore.warps.cooldown.<n>` | Warp cooldown |
| `exyliasurvivalcore.rtp.warmup.<n>` | RTP warmup |
| `exyliasurvivalcore.rtp.cooldown.<n>` | RTP cooldown; it lowers a world's own cooldown and never raises it |
| `exyliasurvivalcore.playerutils.heal.cooldown.<n>` | `/heal` cooldown |
| `exyliasurvivalcore.playerutils.feed.cooldown.<n>` | `/feed` cooldown |

**Prefix nodes** name a group or a section you define:

| Permission | Effect |
|---|---|
| `exyliasurvivalcore.repair.group.<name>` | The repair prices and cooldowns of that group, out of `modules/repair/groups.yml` |
| `exyliasurvivalcore.reclaim.<section>` | The default node of a reclaim section |

```text
/lp group vip permission set exyliasurvivalcore.homes.max_homes.8 true
/lp group vip permission set exyliasurvivalcore.near.radius.500 true
/lp group vip permission set exyliasurvivalcore.tpa.warmup.1 true
/lp group vip permission set exyliasurvivalcore.repair.group.vip true
```

A player holding several repair groups gets, for each repair, the cheapest of them; the shorter cooldown
breaks a tie. `groups.yml` ships empty, so every player pays the defaults in `modules/repair/config.yml`
until you add a group.

## Nodes you write yourself

Several things are gated by a node **you** choose, stored next to the thing it protects rather than
in the plugin's code.

| Where | Key | Default |
|---|---|---|
| A warp | Its `permission`, set through `/warpadmin` | Empty, which falls back to `exyliasurvivalcore.warps.use` |
| A kit | Its `permission`, set through `/kitadmin` | Empty, which means every holder of `exyliasurvivalcore.kits` |
| A portal | Its `permission`, set through `/portalsadmin` | Empty, which means everybody may use it |
| A reclaim section | `sections.<id>.permission` in `modules/reclaim/config.yml` | `exyliasurvivalcore.reclaim.<id>` |
| A join / leave group | `groups.<id>.permission` in `modules/join-leave/groups.yml` | The shipped `vip` group names `survivalcore.joinleave.vip` |
| A rank requirement | A `PERMISSION` requirement's `node`, in `ranks.yml` | None |

The reclaim sections are picked by **priority**: a player is given the highest-priority section whose
permission they hold, so the shipped `vip` at `priority: 1` beats `default` at `priority: 0` for anybody
holding both. In the same way, a join / leave group is the highest-priority one whose permission the
player holds.

### The warmup and RTP bypasses are config keys too

```yaml title="modules/spawn/config.yml"
settings:
  permission-bypass-warmup: exyliasurvivalcore.spawn.bypass
```

The same key exists in `modules/homes/config.yml` and `modules/back/config.yml`, defaulting to
`exyliasurvivalcore.homes.bypass` and `exyliasurvivalcore.back.bypass`. RTP has two of its own, both
defaulting to `exyliasurvivalcore.rtp.bypass`, which always works besides:

```yaml title="modules/rtp/config.yml"
settings:
  bypass-cooldown-permission: exyliasurvivalcore.rtp.bypass
  bypass-price-permission: exyliasurvivalcore.rtp.bypass
```

## A setup to start from

LuckPerms syntax; adapt it to your permission plugin.

```text
# Everybody already has the player features. Take one away from default to make it a perk.
/lp group default permission set exyliasurvivalcore.homes.max_homes.3 true
/lp group default permission set exyliasurvivalcore.tpa.warmup.5 true
/lp group default permission set exyliasurvivalcore.rtp.cooldown.300 true

# VIP, on top of the above
/lp group vip permission set exyliasurvivalcore.homes.max_homes.8 true
/lp group vip permission set exyliasurvivalcore.tpa.warmup.1 true
/lp group vip permission set exyliasurvivalcore.rtp.cooldown.60 true
/lp group vip permission set exyliasurvivalcore.playerutils.hat true
/lp group vip permission set exyliasurvivalcore.playerutils.craft true
/lp group vip permission set exyliasurvivalcore.playerutils.ec true
/lp group vip permission set exyliasurvivalcore.repair.group.vip true
/lp group vip permission set survivalcore.joinleave.vip true

# Staff
/lp group admin permission set survivalcore.admin true
/lp group admin permission set survivalcore.admin.reload true
/lp group admin permission set survivalcore.rankup.admin true
/lp group admin permission set survivalcore.farming.admin true
/lp group admin permission set exyliasurvivalcore.kits.admin true
/lp group admin permission set exyliasurvivalcore.warps.admin true
```

Moved modules (economy, shop, market, trade, vaults, graves, protections, rewards, bounties and the rest)
carry their own permissions on their own plugins' pages, for example
[ExyliaEconomy](/docs/exyliaeconomy/permissions) and [ExyliaMarket](/docs/exyliamarket/permissions).
