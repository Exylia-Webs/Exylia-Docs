---
title: "Permissions"
description: "Every node the plugin checks, module by module, the ones that carry a number, and the ones you write yourself."
---

Nothing is declared in `plugin.yml`. There is no `permissions:` block, so every node below has the
server's default for a node nobody declared: **op**. An operator passes every check, and everybody else
starts with nothing until a node is granted. The one exception is `exyliasurvivalcore.protections.bypass`,
which an operator does not pass unless it is set on them — see [Protections](#protections).

<Callout type="warning" title="Eight nodes still start with `survivalcore.`">
The prefix everywhere else is `exyliasurvivalcore.`, but the administration, rankup admin, farming
admin and portals admin nodes were written without it and are checked exactly as spelled below.
Grant them as they are; a `exyliasurvivalcore.admin` does nothing.
</Callout>

<Callout type="note" title="A disabled module checks nothing">
Modules register their own commands and listeners as they enable. A module turned off in
`config.yml` never registers, so its nodes are never read — granting them is harmless and changes
nothing until the module is back on.
</Callout>

## Nodes that carry a number

These nodes end in a value rather than a word. The **highest** one a player holds wins, and a value of
zero or none at all falls back to the setting.

| Permission | Effect |
|---|---|
| `exyliasurvivalcore.homes.max_homes.<n>` | How many homes the player may set. With none, `max-homes` in `modules/homes/config.yml` |
| `exyliasurvivalcore.near.radius.<n>` | The radius `/near` searches, still capped by `max-radius` in `modules/near/config.yml` |
| `exyliasurvivalcore.market.listings.<n>` | Listings up at once. With none, `settings.max-listings-per-player` in `modules/market/config.yml` (5) |
| `exyliasurvivalcore.auctions.limit.<n>` | Auctions running at once. With none, `settings.max-auctions-per-player` in `modules/auctions/config.yml` (3) |
| `exyliasurvivalcore.orders.limit.<n>` | Open orders at once. With none, `settings.max-orders-per-player` in `modules/orders/config.yml` (5) |
| `exyliasurvivalcore.vaults.amount.<n>` | How many vaults. With none, `settings.default-vaults` (1); never above `settings.max-vaults` (9), both in `modules/vaults/config.yml` |
| `exyliasurvivalcore.protections.limit.<n>` | Protections owned. With none, `settings.default-limit` in `modules/protections/config.yml` (3) |
| `exyliasurvivalcore.shop.sell.<multiplier>` | What the shop pays when you sell, multiplied — `exyliasurvivalcore.shop.sell.1.5` pays half as much again. Anything below 1 is ignored |
| `exyliasurvivalcore.repair.group.<name>` | The repair prices and cooldowns of that group, out of `modules/repair/groups.yml` |

```text
/lp group vip permission set exyliasurvivalcore.homes.max_homes.8 true
/lp group vip permission set exyliasurvivalcore.near.radius.500 true
/lp group vip permission set exyliasurvivalcore.vaults.amount.3 true
/lp group vip permission set exyliasurvivalcore.shop.sell.1.25 true
/lp group vip permission set exyliasurvivalcore.repair.group.vip true
```

The repair groups are read in file order and the first group whose node the player holds is the one
that applies, so a player in two groups gets whichever is written higher in `groups.yml` — not the
cheaper one. The comment at the top of the shipped `groups.yml` says otherwise and writes the node with
the short `survivalcore.` prefix; the code checks `exyliasurvivalcore.repair.group.<name>`.

## Nodes you write yourself

Several things are gated by a node **you** choose, stored next to the thing it protects rather than
in the plugin's code.

| Where | Key | Default |
|---|---|---|
| A warp | Its `permission`, set through `/warpadmin` | Empty, which falls back to `exyliasurvivalcore.warps.use` |
| A kit | Its `permission`, set through `/kitadmin` | Empty, which means every holder of `exyliasurvivalcore.kits` |
| A reward | Its `permission`, set through `/rewardsadmin` | Empty, which means every holder of `exyliasurvivalcore.rewards` |
| A mine | Its `permission`, set through `/minesadmin` | Empty, which means anybody may enter and mine it |
| A portal | Its `permission`, set through `/portalsadmin` | Empty, which means everybody may use it |
| A shop category or product | Its `permission`, set through `/shopadmin` | Empty, which means everybody; `exyliasurvivalcore.shop.admin` always passes |
| A currency | Its `permission`, set through `/economyadmin` | Empty, which means everybody; with one, every command on that currency is refused without it |
| A protection tier | `tiers.<id>.permission` in `modules/protections/config.yml` | Empty — anybody may place that core |
| A protection level | `upgrades.tiers.<tier>.levels.<n>.permission` in `modules/protections/config.yml` | Empty — anybody may upgrade to it |
| A reclaim section | `sections.<id>.permission` in `modules/reclaim/config.yml` | `exyliasurvivalcore.reclaim.<id>` |
| A join / leave group | `groups.<id>.permission` in `modules/join-leave/groups.yml` | The shipped `vip` group names `survivalcore.joinleave.vip` — the short prefix |
| A rank requirement | A `PERMISSION` requirement's `node`, in the rankup config | None |

A mine's permission gates the whole region: without it nothing inside may be broken, minable or
not. `exyliasurvivalcore.mines.admin` passes both that check and the entry check.

The reclaim sections are picked by **priority**: a player is given the highest-priority section
whose permission they hold, so the shipped `vip` at `priority: 1` beats `default` at `priority: 0` for
anybody holding both.

`exyliasurvivalcore.shop.category.` is declared in the code as a prefix and nothing reads it: a category's
node is whatever you type into the editor.

### The warmup and RTP bypasses are config keys too

```yaml title="modules/spawn/config.yml"
settings:
  permission-bypass-warmup: exyliasurvivalcore.spawn.bypass
```

The same key exists in `modules/homes/config.yml` and `modules/back/config.yml`, defaulting to
`exyliasurvivalcore.homes.bypass` and `exyliasurvivalcore.back.bypass`. RTP has two of its own:

```yaml title="modules/rtp/config.yml"
settings:
  bypass-cooldown-permission: survivalcore.rtp.bypass
  bypass-price-permission: survivalcore.rtp.bypass
```

<Callout type="warning" title="Three declared nodes are never checked">
`exyliasurvivalcore.spawn`, `exyliasurvivalcore.rtp.bypass` and the `exyliasurvivalcore.shop.category.`
prefix exist in the code and nothing reads them. `/spawn` is open to everybody, and the RTP bypass that
is actually read is whatever `modules/rtp/config.yml` names — `survivalcore.rtp.bypass` out of the box.
</Callout>
