title: "Commands"
description: "Every command ExyliaSurvivalCore registers, its arguments, its aliases, the node it checks and what it does."
---

Commands are registered at startup by the module that owns them, so a module that is off has no commands
at all. Changing a module switch in `config.yml` takes a restart to add or remove its commands.

`<x>` is required, `[x]` optional. A permission written on a command applies to all its subcommands
unless the subcommand names its own. The nodes themselves are declared in `plugin.yml` and explained on
[Permissions](/docs/exyliasurvivalcore/permissions); a node written here without a prefix starts with
`exyliasurvivalcore.`.

<Callout type="note" title="Admin roots">
The plugin's own staff root is `/survivalcoreadmin`. Each module with staff tools keeps its own admin
command (`/kitadmin`, `/warpadmin`, `/rtpadmin`…), listed under that module below.
</Callout>

Modules that moved to their own plugins no longer appear here: see
[ExyliaEconomy](/docs/exyliaeconomy/introduction), [ExyliaMarket](/docs/exyliamarket/introduction),
[ExyliaProtections](/docs/exyliaprotections/introduction), [ExyliaRewards](/docs/exyliarewards/introduction),
[ExyliaCombat](/docs/exyliacombat/introduction), [ExyliaWarzone](/docs/exyliawarzone/introduction),
[ExyliaCrates](/docs/exyliacrates/introduction), [ExyliaMines](/docs/exyliamines/introduction),
[ExyliaGraves](/docs/exyliagraves/introduction), [ExyliaPlayerVaults](/docs/exyliaplayervaults/introduction)
and [ExyliaMobs](/docs/exyliamobs/introduction).

## Core

| Command | Aliases | Permission | What it does |
|---|---|---|---|
| `/survivalcoreadmin` | `/survivalcore` | `survivalcore.admin` | Opens the admin hub in game, prints the usage line from the console |
| `/survivalcoreadmin reload` | `/survivalcore reload` | `survivalcore.admin.reload` | Reloads this plugin |
| `/survivalcoreadmin setspawn` | `/setspawn` | `spawn.set` | Sets spawn where you stand |
| `/survivalcoreadmin itemupdater` | `/itemupdater`, `/iu` | `itemupdater.admin` | Opens the item updater editor |
| `/survivalcoreadmin itemupdater run` | `/itemupdater run`, `/iu run` | `itemupdater.admin` | Checks every online player right now |

`reload` runs from the console too. It reloads the configs, the module settings and the menus — not the
module switches. When a switch in `config.yml` no longer matches what is running, the reply names those
modules as waiting for a restart.

Deleting a home needs no node of its own: the action never asks for one.

### TPA

| Command | Aliases | Permission | What it does |
|---|---|---|---|
| `/tpa <player>` | | `tpa` | Asks to go to a player, on any server of the network |
| `/tpahere <player>` | | `tpa.here` | Asks a player to come to you |
| `/tpaccept [player]` | `/tpaaccept`, `/tpyes` | `tpa.accept` | Accepts that player's request, or the latest one |
| `/tpadeny [player]` | `/tpdeny`, `/tpno` | none | Denies that player's request, or the latest one |
| `/tpacancel [player]` | | none | Withdraws a request you sent to that player, or your latest one |
| `/tpatoggle` | | `tpa.toggle` | Turns receiving requests on or off |
| `/tpatoggle autoaccept` | | `tpa.autoaccept` | Turns accepting every request automatically on or off |
| `/tpatoggle confirm` | | `tpa.confirm` | Turns the confirmation before sending a request on or off |
| `/autotpaaccept` | | `tpa.autoaccept` | The same as `/tpatoggle autoaccept` |

While `combat-blocks-teleports` is on, `/spawn`, `/home`, `/warp`, `/rtp`, `/back`, `/tpa` and portals are
refused during combat. See [Configuration](/docs/exyliasurvivalcore/configuration#configyml).

<Callout type="danger" title="`/stats` is never registered">
`/stats [player]` exists in the source, but its method still lacks `@CommandPlaceholder`, so Lamp never
registers the command. Statistics reach players through [placeholders](/docs/exyliasurvivalcore/placeholders#statistics).
</Callout>

## Kits and boosters

| Command | Aliases | Permission | What it does |
|---|---|---|---|
| `/kit [id]` | | `kits` | Bare, opens the kit list; with an id, claims that kit |
| `/kit preview [id]` | | `kits.preview` | Shows what a kit contains |
| `/kit claim [id]` | | `kits` | Claims a kit |
| `/kitadmin` | | `kits.admin` | Opens the kit editor |
| `/kitadmin give <player> <kit>` | | `kits.admin` | Gives a kit to a player |
| `/kitadmin preview <kit>` | | `kits.admin` | Previews a kit |
| `/kitadmin reset <player> <kit>` | | `kits.admin` | Forgets one player's cooldown and use count for one kit |
| `/boosters` | | `boosters` | Opens your boosters |
| `/boostersadmin` | `/boostersa` | `boosters.admin` | Opens the boosters admin menu |
| `/boostersadmin give <player> <MONEY\|XP\|DROPS> <multiplier> <duration> [source]` | `/boostersa` | `boosters.admin` | Gives a player a booster |
| `/boostersadmin global <type> <multiplier> <duration> [source]` | `/boostersa` | `boosters.admin` | Starts a booster for everybody |
| `/boostersadmin preset give <player> <preset>` | `/boostersa` | `boosters.admin` | Gives a player a configured preset |
| `/boostersadmin preset global <preset>` | `/boostersa` | `boosters.admin` | Starts a configured preset for everybody |
| `/boostersadmin clear [confirm]` | `/boostersa` | `boosters.admin` | Ends every booster |

The multiplier must be above 1 and no higher than 100. The source defaults to `*` and is lowercased. A
duration is written the way the plugin reads durations everywhere (`30m`, `2h`…). Players are resolved
through ExyliaLib, so anybody the network knows works, online here or not.

[Quality of life](/docs/exyliasurvivalcore/quality-of-life).
