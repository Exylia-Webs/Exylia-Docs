---
title: "Introduction"
description: "What ExyliaSurvivalCore is: fifty modules on one plugin, each one switchable, each one registering nothing when it is off."
---

ExyliaSurvivalCore is the survival server in one jar. Homes, warps, TPA, random teleport, kits, crates,
mines, bounties, rankup, farming milestones and regenerating zones sit next to an economy with its own
currencies, a server shop, a player market with auctions and buy orders, land protections, duel rooms,
missions, seasons and votes. Each of them is a **module** you switch on or off in `config.yml`.

A module that is off registers nothing at all: no commands, no listeners, no database tables, no
placeholders. Turning one off is not a flag the code checks in a hundred places — it is a feature that
never loads.

It is **fifty modules, one hundred and eighteen menus, seventy-two database tables and three hundred and
thirty-seven menu actions**, and almost everything an administrator configures is edited from an in-game
screen rather than a file.

## How a server is set up

<Steps>
  <Step title="Turn off what you do not want">
    All fifty ship as `true`. Set the ones you do not need to `false` in `config.yml` and restart —
    module switches are the one thing a reload does not pick up, and `/sc reload` names the ones still
    waiting for a restart.
  </Step>
  <Step title="Set the spawn">
    `/spawn set`. The spawn module can also force players there on first join, on every join and on
    respawn.
  </Step>
  <Step title="Build the content from menus">
    Mines, crates, warps, kits, loot chests, portals, jump pads, power-ups, AFK zones, regen zones, duel
    rooms, currencies, the shop, menu rewards and item updates are all built from admin screens and
    stored in the database. There is no list to hand-edit.
  </Step>
  <Step title="Write the ladders in YAML">
    Ranks, playtime rewards, farming categories, kill rewards, RTP worlds, repair groups, join groups,
    the stat list, missions, seasons and vote rewards are files, because they are ladders rather than
    objects.
  </Step>
</Steps>

## At a glance

| | |
|---|---|
| Version documented | 1.1.2, source of 14 September 2026 |
| Minecraft | 1.21+ |
| Platforms | Spigot, Paper and Folia |
| Required | `ExyliaLib`, `FastAsyncWorldEdit`, `packetevents` |
| Optional | `PlaceholderAPI`, `WorldGuard`, `BlueMap`, `dynmap`, `Votifier`, `Apollo`, `FeatherServerAPI`, Vault or PlayerPoints, ExyliaClans or SimpleClans, the `Worlds` plugin on Folia |
| Database | H2 by default; MySQL, MariaDB, PostgreSQL and MongoDB through ExyliaLib |

Every default, message, node and rule on these pages was read from the plugin's source as of
14 September 2026 — not from the comments in the generated files, several of which are out of date.
Where a page says something does not work, that is because the code does not do it.
</Callout>
