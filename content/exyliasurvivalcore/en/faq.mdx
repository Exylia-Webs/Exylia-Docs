## `/stats` says unknown command

Because it is. The command class exists, and now reads offline players too, but its method is still
missing the annotation that would register it, so the server never receives it. Bind
`survivalcore:stats_open` to a button in any menu, an NPC or a hotbar item — it opens the viewer's own
profile and its leaderboards.

## My admin menu edits keep disappearing

Everything under `menus/admin/` is replaced from the jar on **every** start and every `/sc reload`, even
though each of those files says the opposite at the top. Edit the menus under `modules/<id>/menus/`
instead — those really are yours. The one editable admin screen is
`modules/warps/menus/warp_setup.yml`.

## A menu I edited did not get the new button

Your edits win. When a new version changes a default you had left alone in a menu under
`modules/<id>/menus/`, the change waits in `/exylialib updates` for you to apply or keep; only keys that
did not exist before are added on their own. A menu whose shipped `menu-version` went up is replaced
whole, and your previous file is kept beside it as `<name>.v<old version>`. See
[Configuration](/docs/exyliasurvivalcore/configuration).

## I turned a module off and nothing changed

Module switches need a restart. `/sc reload` re-reads the configuration files, the module settings and
the menus, but never enables or disables a module — it ends with *"Restart to apply module changes"*
and the ids still waiting.

## Where did the economy go?

Into this plugin. The stored currencies, their balances, the ledger and the Vault bridge used to be
ExyliaLib's and are the `economy` module now. The currencies live in the database and are edited with
`/economyadmin`. A server that had `plugins/ExyliaLib/currencies.yml` gets it copied to
`modules/economy/currencies.yml` once, imported into the tables the first time they are empty, and
renamed to `currencies.yml.imported`. Balances and the ledger are kept in `exylia_balances` and
`exylia_ledger`.

With `economy` off there are no stored currencies, and prices use whatever Vault or PlayerPoints
provides.

## Can this plugin be the server's Vault economy?

Yes, for one stored currency. It is registered beneath any economy plugin you already run — EssentialsX
or CMI keeps serving Vault, and this currency serves only without it — unless the economy settings force
it on top. Without Vault installed, the console says nothing was published. See
[Economy](/docs/exyliasurvivalcore/economy).

## Prices and payouts are skipped

No currency is registered at all: the `economy` module is off and neither Vault nor PlayerPoints provides
one. The console says `No economy is installed: prices and payouts are skipped.` at boot.

## Do protections need WorldGuard?

No. The default backend is `INTERNAL`, which enforces everything itself. WorldGuard is only needed for
the `WORLDGUARD` backend, for refusing land that overlaps somebody else's WorldGuard region, and for the
ProtectionStones import. Set to `WORLDGUARD` without WorldGuard, the module warns and falls back to
`INTERNAL`.

## Votes never arrive

NuVotifier is not installed, and the console says so at boot:
`NuVotifier is not installed: votes only arrive through /voteadmin fake.` Also check that
`modules/votes/votes.yml` points at your server's pages — the shipped site URLs are placeholders.

## Missions never finish, or seasons rank nobody

`stats` is off. Missions measure progress against the stat counters and seasons rank them, and only the
`stats` module keeps those counters. Both modules warn once at boot when it is off.

## A sell wand says the module is disabled

Sell wands sell through the shop. With `shop` off, every wand answers with the module-disabled message
and autosell takes nothing.

## `/autosell` says it is on and nothing changes

`player-settings` is off. Autosell is then on for every player holding
`exyliasurvivalcore.sellwands.autosell`, and `/autosell` has no switch to flip — it answers that autosell
is on every time.

## Duel rooms set clanmates against each other

No clan plugin is installed. Clans are read through ExyliaLib from ExyliaClans or SimpleClans; without
one, nobody is in a clan and everybody counts as an enemy.

## A rank costs nothing

Its requirement was dropped when the file was read. `ranks.yml`'s own header lists `money`, `playtime`,
`kills` and `level` as requirement types, and the last two do not exist — the real set is `money`,
`playtime`, `placeholder` and `permission`. A requirement of any other type is discarded silently, which
leaves the rank free.

## `/bounty cancel` does not cancel

It opens the same list `/bounty` does. Cancel a contribution from the menu.

## Anonymous bounties are not anonymous

`exyliasurvivalcore.bounties.anonymous` has no effect through the normal flow: the confirmation screen
passes the flag as `false` regardless of what `/bounty place` worked out. Every bounty placed that way
carries the placer's name.

## Anybody can run `/reclaim` and `/playtime`

Neither command declares a permission. `/reclaim` runs the commands of the highest-priority section
whose permission the player holds — so the section nodes are the only gate, and a player holding none
is told there is nothing for them. `/playtime <rewardId>` claims that reward, and only the playtime
itself stops anybody. Grant the section nodes narrowly.

## Half the plugin is in Spanish

Eight of the shipped default strings are: the warmup action bars and titles for spawn, homes, back, TPA
and RTP say *Teleportando en %time%*. They are ordinary configuration values in each module's
`config.yml` — edit them.

## A permission does nothing

Check the prefix. Eight nodes still start with `survivalcore.` rather than `exyliasurvivalcore.`: the
core admin nodes (`survivalcore.admin`, `survivalcore.admin.reload`, `survivalcore.admin.homes`), the two
rankup admin nodes, the two farming admin nodes and the portals admin node. Grant them exactly as spelled
on the [Permissions](/docs/exyliasurvivalcore/permissions) page.

Two more are declared and never read: `exyliasurvivalcore.spawn` and `exyliasurvivalcore.rtp.bypass`.
`/spawn` is open to everybody, and the RTP bypasses that are actually checked are the two nodes
`modules/rtp/config.yml` names — one for the cooldown, one for the price, both `survivalcore.rtp.bypass`
out of the box.

## `%exyliasurvivalcore_stats_value_streak%` shows nothing

`streak` is not a stat id. The shipped ids are `kills`, `deaths`, `kdr`, `best_kill_streak`,
`current_streak`, `duels_won`, `balance`, `bounties_claimed`, `bounties_earned`, `votes_total`,
`votes_best_streak`, `market_sold`, `market_earned`, `blocks_mined`, `farming_harvested`,
`crates_opened`, `missions_completed`, `mobs_killed` and `playtime`, so the working forms are
`%exyliasurvivalcore_stats_value_current_streak%` and `%exyliasurvivalcore_stats_rank_best_kill_streak%`.
The placeholders `%exyliasurvivalcore_stats_streak%` and `%exyliasurvivalcore_stats_best_streak%` are
different things and they work as written.

## Regen zones never regenerate

FastAsyncWorldEdit's schematic support is not usable, and the plugin says so once at boot:
`Regen zones are off: <reason>`. The module still enables and the menus still work; nothing is pasted.

## Why does the plugin need FAWE and PacketEvents just for `/home`?

Both are declared as hard dependencies, for regenerating zones and for power-ups respectively. A server
that wants only the teleport modules still cannot start without them.

## `/afkzone` and `/repair` print a usage line

Neither has a root form. `/afkzone preview <id>`, `/repair hand` and `/repair all` are the commands.

## Two players in the same repair group pay different prices

They are not in the same group. Repair groups resolve in **file order**, not by price: the first group
in `groups.yml` whose node a player holds is the one that applies. Write the best group first.

## Can two servers share this?

Yes. Point them at the same database and homes, warps, kits, ranks, balances, statistics and crates are
shared — homes and warps carry the server they were set on, so `/home` and `/warp` cross the network,
and TPA requests reach players on another server.

Some modules also push changes between servers as they happen: `tpa`, `economy`, `votes`, `seasons`,
`boosters` and `protections` talk over ExyliaLib's channels, and item updates, the vote party, seasons,
boosters, buy orders and protection warps, accounts, market listings and rent offers pick up rows another
server writes. Everything else is picked up the next time it is read.
