ExyliaSurvivalCore is a set of 29 modules, each with its own switch. Turn off what you do not use and the
plugin registers nothing for it: no commands, no listeners, no database tables, no placeholders and no
timers.

## Turn a module on or off

<Steps>
  <Step title="Open the settings">
    Run `/survivalcoreadmin`, click **Plugin ▸ Settings**, then **Modules**.
  </Step>
  <Step title="Pick the group">
    Click **Settings ▸ Travel**, **Settings ▸ Players** or **Settings ▸ Server**, then click the module
    you want to switch.
  </Step>
  <Step title="Restart the server">
    A module switch is only read at startup. `/survivalcoreadmin reload` never enables or disables a
    module.
  </Step>
</Steps>

You can also edit `modules:` in `plugins/ExyliaSurvivalCore/config.yml` and restart.

<Callout type="warning" title="A switch needs a restart">
When a switch no longer matches what is running, `/survivalcoreadmin reload` prints *"Restart to apply
module changes » …"* with the ids of those modules. Restart to apply them.
</Callout>

## Check that it works

After the restart, type one of the module's commands. A module that is off has no commands, so the
command is unknown. Turning a module back on brings back everything it had: its own file on disk and its
data in the database are never deleted.

## What "off" means

A module that is off registers nothing, and its own configuration file is left alone. A module id that no
switch declares is simply off, which is not an error.

Two things keep a module off even when its switch says `true`:

- **ExyliaLobby is installed.** `jumpads`, `join-leave` and `portals` stay off and the lobby handles
  them. `spawn` is not affected. To keep this plugin's versions, set `defer-to-exylia-lobby: false` and
  restart.
- **ExyliaJobs is installed.** `farming` does not load, because jobs pay for the same work.

`missions` and `seasons` load after `stats`, whose counters they read.

## Know what depends on what

No module refuses to enable because another is off, but a few read each other.

- **`player-settings` decides who hears a broadcast.** Death, join and leave messages, rankups, reclaim
  purchases, missions, boosters, project milestones, closing seasons and scheduled announcements check
  each receiver's preferences, and so do the TPA switches (requests, auto-accept, confirm). With it off,
  every broadcast reaches everybody and every request arrives.
- **`stats` feeds `missions` and `seasons`.** With `stats` off both still enable and each warns once at
  boot: no mission ever finishes and no season ranks anyone.
- **`boosters` needs an economy.** Money boosters apply to payouts in the server's default currency, which
  ExyliaEconomy or Vault provides. With no economy, prices and payouts are skipped and the console says so
  at boot. See [Economy](/docs/exyliasurvivalcore/economy).

## Moved to other plugins

These used to be modules of this plugin and are gone from it. Their switches no longer exist, and the
data now lives in the plugin named here.

| What | Where it went |
|---|---|
| Currencies, balances, the ledger, the Vault bridge, `/balance`, `/pay`, `/baltop`, `/wallet` | [ExyliaEconomy](/docs/exyliaeconomy/introduction) |
| Shop, player market, auctions, buy orders, trading, sell wands and autosell | [ExyliaMarket](/docs/exyliamarket/introduction) |
| Personal vaults | [ExyliaPlayerVaults](/docs/exyliaplayervaults/introduction) |
| Graves | [ExyliaGraves](/docs/exyliagraves/introduction) |
| Crates and keys | [ExyliaCrates](/docs/exyliacrates/introduction) |
| Land protections, raids, banks, upkeep, rent and the ProtectionStones import | [ExyliaProtections](/docs/exyliaprotections/introduction) |
| Mines | [ExyliaMines](/docs/exyliamines/introduction) |
| Supply drops, power-ups, loot chests, regen zones, duel rooms and banned items (formerly blocked items) | [ExyliaWarzone](/docs/exyliawarzone/introduction) |
| Bounties and kill rewards | [ExyliaCombat](/docs/exyliacombat/introduction) |
| Menu rewards, playtime rewards, votes, referrals and AFK zones | [ExyliaRewards](/docs/exyliarewards/introduction) |
| Custom mobs and generators | [ExyliaMobs](/docs/exyliamobs/introduction) |

If `modules/blocked-items/rules.yml` is still on disk, the plugin prints a warning at boot: ExyliaWarzone
imports that file into its banned items module and nothing here reads it.

<Details title="config.yml: server-wide keys">
`config.yml` holds `language`, `debug`, three server-wide switches, `modules` and the `teleport` section
described on [Configuration](/docs/exyliasurvivalcore/configuration).

```yaml
debug: false
defer-to-exylia-lobby: true
combat-blocks-teleports: true
idle-after-seconds: 300
modules:
  spawn: true
  tpa: true
  # ...one `name: true` line per switch above
```

| Key | Default | What it does |
|---|---|---|
| `debug` | `false` | Extra console detail, including which actor each configured command line runs as. Re-read on `/survivalcoreadmin reload`. |
| `defer-to-exylia-lobby` | `true` | See "What off means". Restart to apply. |
| `combat-blocks-teleports` | `true` | `/spawn`, `/home`, `/warp`, `/rtp`, `/back`, `/tpa` and portal teleports are refused while the player is in combat, whichever plugin tracks it. Permissions that skip a countdown do not skip this. |
| `idle-after-seconds` | `300` | How long a player can stand without moving, looking, typing or clicking before time-played rewards stop counting them. `0` turns it off. |

The file also still accepts a `mobs` switch, but no module reads it: custom mobs are
[ExyliaMobs](/docs/exyliamobs/introduction)'.
</Details>
