`config.yml` holds the `language`, `debug`, three server-wide switches, the module switches and the
`teleport` section described on [Configuration](/docs/exyliasurvivalcore/configuration). The module
switches, in the order the file lists them:

```yaml
debug: false
defer-to-exylia-lobby: true
combat-blocks-teleports: true
idle-after-seconds: 300
modules:
  spawn: true
  tpa: true
  homes: true
  join-leave: true
  rtp: true
  scheduled-commands: true
  rankup: true
  player-utils: true
  back: true
  farming: true
  reclaim: true
  stats: true
  portals: true
  jumpads: true
  kits: true
  item-spawners: true
  warps: true
  near: true
  repair: true
  death: true
  enchantments: true
  player-settings: true
  missions: true
  boosters: true
  seasons: true
  optimization: true
  item-updater: true
  reputation: true
  projects: true
```

`debug` adds console detail, including which actor each configured command line runs as. It is re-read
on `/survivalcoreadmin reload`; the module switches are not.

| Key | Default | What it does |
|---|---|---|
| `defer-to-exylia-lobby` | `true` | When ExyliaLobby is enabled, `jumpads`, `join-leave` and `portals` stay off and the lobby handles them. `spawn` is not affected. Set it to `false` to keep this plugin's versions. Restart to apply. |
| `combat-blocks-teleports` | `true` | `/spawn`, `/home`, `/warp`, `/rtp`, `/back`, `/tpa` and portal teleports are refused while the player is in combat, whichever plugin tracks it. Permissions that skip a countdown do not skip this. |
| `idle-after-seconds` | `300` | How long a player can stand without moving, looking, typing or clicking before rewards for time played stop counting them. `0` turns it off. |

<Callout type="warning" title="A module switch needs a restart">
`/survivalcoreadmin reload` re-reads the configuration files, the module settings and the menus, but it
never enables or disables a module: its commands, listeners and hooks are registered once, at startup.
When a switch no longer matches what is running, the reload says so — *"Restart to apply module
changes » …"* with the ids of those modules. Restart to apply them.
</Callout>

<Callout type="note" title="`mobs` is a leftover switch">
The switch record still carries a `mobs` key, but no module registers it any more: custom mobs and
their generators are [ExyliaMobs](/docs/exyliamobs/introduction)' now. Setting it does nothing.
</Callout>

## What "off" means

A module that is off is never constructed past its own switch. It registers **no commands, no
listeners, no database tables, no placeholders and no timers**. Its own configuration file is left
alone on disk, so turning it back on picks up exactly where you left it.

A module id that nothing declares is simply off, which is not an error.

Two things also keep a module off without touching its switch. With ExyliaLobby enabled and
`defer-to-exylia-lobby` on, `jumpads`, `join-leave` and `portals` do not load. While ExyliaJobs is
installed, `farming` does not load either: jobs pay for the same work.

The modules load in a fixed order, which is not the order of the file: `missions` and `seasons` load
after `stats`, whose counters they read.

## What the switches do to each other

Modules are independent — none of them refuses to enable because another is off — but several read
each other when they are both on, and a few do nothing useful alone.

<Callout type="note" title="`player-settings` decides who hears a broadcast">
Death messages, join and leave messages, rankups, reclaim purchases, missions, boosters starting and
ending, project milestones, seasons closing and scheduled announcements all check each receiver's
preferences before they are sent, and so do the three TPA switches (requests, auto-accept and confirm).
Protection messages and raid announcements are in the same list for servers running
[ExyliaProtections](/docs/exyliaprotections/introduction).

With `player-settings` off, every broadcast goes to everybody and every request arrives.
</Callout>

<Callout type="note" title="`stats` keeps the counters `missions` and `seasons` read">
Missions measure progress against the stat counters, and seasons rank them. With `stats` off, both
modules still enable and each warns once at boot: no mission ever finishes, and no season ranks anyone.
The leaderboards are empty too. The `kdr` stat is computed from kills and deaths, and the shipped
`playtime` stat is read through PlaceholderAPI.
</Callout>

<Callout type="note" title="`boosters` and the economy">
Money boosters apply to the payouts the plugin makes in the server's default currency, which is the one
ExyliaEconomy (or Vault) provides. With no economy at all, prices and payouts are skipped and the
console says so at boot. See [Economy](/docs/exyliasurvivalcore/economy).
</Callout>

Turning off `kits`, `warps`, `portals` and the rest leaves everything they built in the database
untouched. Switching one back on brings its content back exactly as it was.

## Moved to other plugins

These used to be modules of this plugin and are gone from it. Their switches no longer exist, and the
data now lives in the plugin named here.

| What | Where it went |
|---|---|
| Currencies, balances, the ledger, the Vault bridge, `/balance`, `/pay`, `/baltop`, `/wallet` | [ExyliaEconomy](/docs/exyliaeconomy/introduction) |
| Shop, player market, auctions, buy orders, trading, sell wands and autosell | [ExyliaMarket](/docs/exyliamarket/introduction) |
| Personal vaults | [ExyliaPlayerVaults](/docs/exyliaplayervaults/introduction) |
| Graves | [ExyliaGraves](/docs/exyliagraves/introduction) |
| Crates and keys | [ExyliaCrates](/docs/exyliacrates/introduction) |
| Land protections, raids, banks, upkeep, rent and the ProtectionStones import | [ExyliaProtections](/docs/exyliaprotections/introduction) |
| Mines | [ExyliaMines](/docs/exyliamines/introduction) |
| Supply drops, power-ups, loot chests, regen zones, duel rooms and banned items (formerly blocked items) | [ExyliaWarzone](/docs/exyliawarzone/introduction) |
| Bounties | [ExyliaCombat](/docs/exyliacombat/introduction) |
| Kill rewards | Dropped here; [ExyliaCombat](/docs/exyliacombat/introduction) has its own |
| Menu rewards, playtime rewards, votes, referrals and AFK zones | [ExyliaRewards](/docs/exyliarewards/introduction) |
| Custom mobs and generators | [ExyliaMobs](/docs/exyliamobs/introduction) |

<Callout type="note" title="A leftover `blocked-items/rules.yml`">
If `modules/blocked-items/rules.yml` is still on disk, the plugin prints a warning at boot: ExyliaWarzone
imports that file into its banned items module, and nothing here reads it.
</Callout>
