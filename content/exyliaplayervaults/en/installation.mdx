By the end of this page the plugin is running with its default database, ready for `/pv`.

## Before you start

- Paper or Folia 1.21.4 or newer, Java 21.
- [ExyliaLib](/docs/exylialib) in `plugins/`. It is required: menus, database, locks, economy and the audit log come from it.
- Optional: PlaceholderAPI, and an economy plugin only if you will sell vaults.

## Steps

<Steps>
  <Step title="Download">
    ExyliaPlayerVaults is free. Download `ExyliaPlayerVaults.jar` from [Modrinth](https://modrinth.com/plugin/exyliaplayervaults) or the [GitHub releases](https://github.com/Exylia-Plugins/ExyliaPlayerVaults/releases).
  </Step>
  <Step title="Drop it in plugins">
    Copy the jar into the `plugins/` folder, next to ExyliaLib.
  </Step>
  <Step title="Start the server">
    The plugin writes its files in `plugins/ExyliaPlayerVaults/`. Without ExyliaLib it stays off and the console says where to get it. Install ExyliaLib and restart: nothing is downloaded for you.
  </Step>
  <Step title="Open a vault">
    Run `/pv`. A fresh server gives every player one vault of six rows. See [Your first vault](/docs/exyliaplayervaults/first-steps).
  </Step>
</Steps>

## The database

By default the plugin uses H2, a file inside the plugin folder with nothing to install. It is enough for one server.

For a network, point every server at the same database and, if you have one, turn Redis on. The file is `plugins/ExyliaPlayerVaults/database.yml`, written by ExyliaLib. Supported engines are `h2`, `mysql`, `mariadb`, `postgresql` and `mongodb`. The full file is explained in [ExyliaLib database](/docs/exylialib/database), and what a shared database does for vaults is in [Share vaults across servers](/docs/exyliaplayervaults/network).

## Updating

ExyliaLib keeps the plugin up to date. It announces a new release in the console and to admins, and `/exylialib plugins` downloads it; it is applied on the next restart. A new major version waits for you to install it by hand, and a release that needs a newer ExyliaLib waits until the library has updated. To update by hand, replace the jar and restart. Your `config.yml`, messages and vault list keep your edits, and the vaults stay in the database untouched.

<Details title="Files created on first start">
All in `plugins/ExyliaPlayerVaults/`. `<code>` is the language the plugin runs in (`en`, `es`, `pt`, `fr`, `ru` or `tr`), or ExyliaLib's own while `language` in `config.yml` says `default`.

| File | Contents |
|---|---|
| `config.yml` | Amounts, rows, restrictions, purchases, history, names and sounds. See [Configuration](/docs/exyliaplayervaults/configuration). |
| `lang/<code>/messages.yml` | Every chat line and window title. |
| `lang/<code>/menus/user/vaults.yml`, `search.yml`, `toolbar.yml` | The vault list, the search results and the optional row of buttons under a vault. Yours to restyle; kept across updates. |
| `lang/<code>/menus/admin/*.yml` | The staff hub, the settings screens and the history screen. Replaced from the jar on every start. |
| `screens/vaults.html`, `screens/theme.css` | The full-screen look of the list, for servers that use screens. |
| `database.yml` | Database and Redis, H2 by default. |
</Details>
