Every node below is declared in `plugin.yml`, except the two numbered families, which you grant with
whatever number you want.

## Vaults by rank

| Permission | What it sets |
|---|---|
| `exyliaplayervaults.amount.<number>` | How many vaults the player has. The largest number they hold wins; without one, `vaults.default-amount`. Capped at `vaults.max-amount`, bought vaults included. |
| `exyliaplayervaults.rows.<1-6>` | How many rows each of their vaults has. The largest number wins; without one, `vaults.default-rows`. Always 1 to 6. |

See [Vaults](/docs/exyliaplayervaults/vaults#how-many-and-how-big).

## Plugin nodes

| Permission | Default | What it gates |
|---|---|---|
| `exyliaplayervaults.use` | everyone | `/pv`, the list and opening your own vaults. |
| `exyliaplayervaults.search` | everyone | `/pv search`. |
| `exyliaplayervaults.buy` | everyone | Buying vaults from the list, when purchases are on. |
| `exyliaplayervaults.customize.name` | everyone | Renaming your vaults. |
| `exyliaplayervaults.customize.icon` | everyone | Choosing their icons. |
| `exyliaplayervaults.bypass.cooldown` | operators | Opening without waiting for `open-cooldown`, and searching without the search wait. |
| `exyliaplayervaults.bypass.restrictions` | operators | Opening in disabled worlds and game modes, and in combat; a vault open in a fight stays open. |
| `exyliaplayervaults.bypass.blocked` | nobody | Putting blocked items into a vault. |
| `exyliaplayervaults.admin.view` | operators | `/pvadmin`, `/pvadmin list` and `/pvadmin view`. |
| `exyliaplayervaults.admin.edit` | operators | `/pvadmin edit`, editing from somebody's list, renaming their vaults and changing their icons, and putting a history copy back. Child: `admin.view`. |
| `exyliaplayervaults.admin.history` | operators | `/pvadmin history` and looking inside a copy. Putting one back also needs `admin.edit`. Child: `admin.view`. |
| `exyliaplayervaults.admin.clear` | operators | `/pvadmin clear`. |
| `exyliaplayervaults.admin.reload` | operators | `/pvadmin reload`. |
| `exyliaplayervaults.admin` | operators | Every admin command. Children: `admin.view`, `admin.edit`, `admin.history`, `admin.clear`, `admin.reload`. |
| `exyliaplayervaults.*` | operators | Everything except `bypass.blocked`. |

<Callout type="note" title="bypass.blocked is never granted for you">
A blocked list is the owner's decision, so `exyliaplayervaults.bypass.blocked` defaults to nobody,
operators included, and `exyliaplayervaults.*` leaves it out. Grant it by name to whoever should have it.
Staff editing with `/pvadmin edit` are not held to the list anyway.
</Callout>

A missing node on a list button or a purchase answers *"You do not have permission to do that."*; on a
command, the server's own refusal.

## Coming from ExyliaSurvivalCore

The old `exyliasurvivalcore.vaults…` nodes are not declared again and grant nothing here. See
[Network](/docs/exyliaplayervaults/network#permissions) for the new names.

## Examples

Three vaults of six rows for VIPs, one of three rows for everybody else:

```text
/lp group default permission set exyliaplayervaults.rows.3 true
/lp group vip permission set exyliaplayervaults.amount.3 true
/lp group vip permission set exyliaplayervaults.rows.6 true
```

Moderators who may look but not touch:

```text
/lp group mod permission set exyliaplayervaults.admin.view true
/lp group mod permission set exyliaplayervaults.admin.history true
```

Keeping a group from renaming:

```text
/lp group default permission set exyliaplayervaults.customize.name false
```
