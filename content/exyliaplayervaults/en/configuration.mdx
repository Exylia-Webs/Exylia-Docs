Most of what you need is a button, not a file: run `/pvadmin`, open **Settings** and change vault counts, access and purchases in game. Open this page when you want every key, a file's location or a default.

Everything is generated in `plugins/ExyliaPlayerVaults/` on first start, with comments on each key. Edit the files there, never the copies in the jar. `/pvadmin reload` applies an edit to `config.yml`, the messages and the menus (needs `exyliaplayervaults.admin.reload`).

```text
plugins/ExyliaPlayerVaults/
├── config.yml
├── database.yml
├── screens/            (the full-screen vault list)
└── lang/
    └── <code>/
        ├── messages.yml
        ├── screens/vaults.yml
        └── menus/
```

`database.yml` is ExyliaLib's database file; see [Database](/docs/exylialib/database) and [Share vaults across servers](/docs/exyliaplayervaults/network#tables) for the tables.

## Change it in game

Staff with `exyliaplayervaults.admin` open `/pvadmin`, then the **Settings** card. Each value shows its current and default value, and Shift-right-click resets it.

| Page | Keys |
|---|---|
| Vaults | `vaults.default-amount`, `vaults.max-amount`, `vaults.default-rows`, `vaults.toolbar`, `vaults.hidden-slots`, `vaults.blocked-materials`, `history.keep`, `customization.name-max-length` |
| Access | `restrictions.open-cooldown`, `restrictions.block-in-combat`, `restrictions.disabled-worlds`, `restrictions.disabled-game-modes`, `replace-ender-chests` |
| Purchase | `purchase.enabled`, `purchase.currency`, `purchase.base-price`, `purchase.price-multiplier`, `purchase.max-purchases` |

## What most owners change

- **How many vaults and how big.** `vaults.default-amount` (1) is what everyone gets, `vaults.max-amount` (9) is the ceiling, `vaults.default-rows` (6) is the size. Ranks go above the defaults with `exyliaplayervaults.amount.<number>` and `exyliaplayervaults.rows.<1-6>`. See [Vaults](/docs/exyliaplayervaults/vaults).
- **Where vaults can be opened.** `restrictions.open-cooldown`, `block-in-combat`, `disabled-worlds` and `disabled-game-modes`. See [Limit where and when vaults open](/docs/exyliaplayervaults/restrictions).
- **Items that may not go in.** `vaults.blocked-materials`; players with `exyliaplayervaults.bypass.blocked` are exempt.
- **Selling vaults.** The `purchase` section. See [Sell extra vaults](/docs/exyliaplayervaults/purchases).
- **Replacing the ender chest.** `replace-ender-chests: true` opens the vault list instead of the ender chest for players with `exyliaplayervaults.use`.
- **Words and colours.** `lang/<code>/messages.yml`, with [colour tokens](/docs/exylialib/colours); see [Messages and languages](/docs/exylialib/messages-and-languages).
- **How the list looks.** `lang/<code>/menus/user/vaults.yml`; see [Edit menus](/docs/exylialib/edit-menus).

## config.yml

```yaml title="plugins/ExyliaPlayerVaults/config.yml"
language: default
vaults:
  default-amount: 1
  max-amount: 9
  default-rows: 6
  toolbar: false
  hidden-slots: keep
  blocked-materials: []
  checkpoint: 30s
  save-player-on-write: true
restrictions:
  open-cooldown: 500ms
  block-in-combat: true
  disabled-worlds: []
  disabled-game-modes:
    - SPECTATOR
purchase:
  enabled: false
  currency: ''
  base-price: 5000.0
  price-multiplier: 1.5
  max-purchases: 9
history:
  keep: 10
replace-ender-chests: false
customization:
  name-max-length: 24
  default-icon: BARREL
sounds:
  opened: BLOCK_BARREL_OPEN|1.0|1.2
  closed: BLOCK_BARREL_CLOSE|1.0|1.2
```

Lengths of time read like everywhere in Exylia: `500ms`, `30s`, `1m30s`; a bare number is seconds.

<Details title="Every key, with its default">

### language

| Key | Default | What it does |
|---|---|---|
| `language` | `default` | The language of this plugin's menus and messages. `default` follows the language set in ExyliaLib's `config.yml`; `en`, `es`, `pt`, `fr`, `ru` or `tr` set this plugin alone. Each is a folder under `lang/`. |
| `replace-ender-chests` | `false` | Opens the vault list instead of the ender chest, whichever way one is opened: the block, or another plugin's command such as `/enderchest`. Only for players with `exyliaplayervaults.use`, and only their own ender chest; what it already holds stays there, out of reach while this is on. |

### vaults

| Key | Default | What it does |
|---|---|---|
| `default-amount` | `1` | Vaults a player has with no `exyliaplayervaults.amount.<number>` of their own. The largest number a player holds wins. |
| `max-amount` | `9` | The most vaults anybody may have, bought ones included, whatever their permissions. Also how many entries the list draws. |
| `default-rows` | `6` | Rows per vault with no `exyliaplayervaults.rows.<1-6>` of their own. The largest number a player holds wins. Clamped to 1–6. |
| `toolbar` | `false` | <Since v="1.12.0" /> Gives every vault a bottom row of buttons (previous and next vault, the list, search, rename), drawn from `menus/user/toolbar.yml`. The row is taken from the vault: a vault of up to 5 rows gets one more row for it, a vault of 6 rows shows 5. See [Vaults](/docs/exyliaplayervaults/vaults#add-previous-and-next-buttons-under-a-vault). |
| `hidden-slots` | `keep` | What happens to stacks past a smaller vault's last slot: `keep` stores them out of sight, `return` hands them back. See [Vaults](/docs/exyliaplayervaults/vaults#when-a-vault-gets-smaller). |
| `blocked-materials` | `[]` | Materials that may not go into a vault, by name, compared ignoring case. Shulker boxes and bundles holding one are refused too. Skipped with `exyliaplayervaults.bypass.blocked`. |
| `checkpoint` | `30s` | How often an open vault that changed is written while it stays open, so a crash costs at most this much. Never less than one second. |
| `save-player-on-write` | `true` | Saves the player's own inventory file after each write that changed their vault, so a crash right after cannot leave an item in both places. |

### restrictions

None of these apply to staff opening somebody else's vault.

| Key | Default | What it does |
|---|---|---|
| `open-cooldown` | `500ms` | How long a player waits between opening two vaults. `0s` turns it off. `exyliaplayervaults.cooldown.<seconds>` shortens it for a rank; the smallest number a player holds wins. Skipped with `exyliaplayervaults.bypass.cooldown`. |
| `block-in-combat` | `true` | Refuses to open a vault while the player is combat-tagged (any combat plugin ExyliaLib knows), and closes one that is open when they hit or are hit by a player. |
| `disabled-worlds` | `[]` | Worlds in which vaults cannot be opened, by name. |
| `disabled-game-modes` | `[SPECTATOR]` | Game modes in which vaults cannot be opened: `SURVIVAL`, `CREATIVE`, `ADVENTURE`, `SPECTATOR`. |

The last three are skipped with `exyliaplayervaults.bypass.restrictions`.

### purchase

| Key | Default | What it does |
|---|---|---|
| `enabled` | `false` | Lets players buy vaults past what their rank gives them, from the list. |
| `currency` | `''` | The currency they pay in, by id. Empty uses ExyliaLib's default currency. |
| `base-price` | `5000.0` | What the first bought vault costs. |
| `price-multiplier` | `1.5` | Each later vault costs this many times the one before. `1.0` keeps every vault at `base-price`. |
| `max-purchases` | `9` | The most vaults one player may buy. `max-amount` still caps the total. |

See [Sell extra vaults](/docs/exyliaplayervaults/purchases).

### history

| Key | Default | What it does |
|---|---|---|
| `keep` | `10` | How many earlier copies of each vault are kept, newest first. `0` keeps none. A copy is taken when a player closes a vault they changed, and before any admin edit, clear or restore. See [Check and restore vaults](/docs/exyliaplayervaults/staff#history). |

### customization

| Key | Default | What it does |
|---|---|---|
| `name-max-length` | `24` | The longest name a player may give a vault. `exyliaplayervaults.namelength.<n>` sets it per rank; the largest number a player holds wins. Names hold letters, digits, spaces and `- _ ' . ! ? # ( )` only, so a name never carries colours or placeholders. |
| `default-icon` | `BARREL` | What a vault is drawn as in the list until its owner picks an icon: a menu material such as `CHEST`, `playerhead-<name>` or `basehead-<texture>`. |

### sounds

| Key | Default | What it does |
|---|---|---|
| `opened` | `BLOCK_BARREL_OPEN\|1.0\|1.2` | Played when a vault window opens, as `NAME\|volume\|pitch`. Empty plays nothing. |
| `closed` | `BLOCK_BARREL_CLOSE\|1.0\|1.2` | Played when a player closes a vault window. |

</Details>

## messages.yml

`lang/<code>/messages.yml` holds every line the plugin says and every window title. `%prefix%` expands to the `prefix` value at the top, `{primary}&lVAULTS {letters_black}•<reset>` in English. Colours are palette tokens (see [Colours](/docs/exylialib/colours)).

A line may open with an effect tag, which never reaches the screen: `[sound:NAME|volume|pitch]` plays a sound to whoever receives it. An empty line sends nothing at all, which is how a message is turned off. The rest of the format is on [Messages and languages](/docs/exylialib/messages-and-languages).

<Details title="Every message key">

| Keys | What they are |
|---|---|
| `prefix` | Opens every chat line through `%prefix%`. |
| `title`, `admin-title`, `view-title`, `snapshot-title` | Window titles: your own vault, a vault staff are editing, a read-only view, a history copy. `%number%` is the vault, `%player%` its owner, `%name%` its name (in `title` and `admin-title`). |
| `default-name` | What a vault is called until it is renamed: `#%number%`. |
| `in-use`, `not-unlocked`, `unreadable`, `blocked-item`, `lock-lost`, `taken-over`, `taking-over` | Opening and keeping a vault. |
| `hidden-stacks`, `returned`, `rewards-delivered` | A vault that shrank (`%count%` stacks), and items handed back on join (`%amount%`). |
| `cooldown`, `in-combat`, `disabled-world`, `disabled-game-mode` | Restrictions. `%time%` is what is left of the cooldown. |
| `rename-prompt`, `name-invalid`, `renamed`, `rename-reset`, `icon-prompt`, `icon-changed`, `no-permission` | Names and icons. |
| `buy-prompt`, `bought`, `buy-too-poor`, `buy-limit`, `buy-disabled`, `buy-failed` | Purchases. `%price%` is formatted in the currency, `%number%` is the vault bought. |
| `search-prompt`, `search-none` | `/pv search` and the Search button. `%query%` is what was searched; the results are a screen. |
| `admin-usage` | The lines `/pvadmin` prints. |
| `clear-prompt`, `cleared`, `restore-prompt`, `restored`, `history-empty`, `snapshot-missing`, `reloaded` | Staff tools. `%when%` is how long ago a copy was taken. |

</Details>

## Menus

Under `lang/<code>/menus/`.

| File | Opened by | Edits |
|---|---|---|
| `user/vaults.yml` | `/pv`, `/pvadmin list` | Yours. Kept across updates; a release that has to change its layout raises `menu-version`, replaces the file and keeps your previous one next to it. |
| `user/search.yml` | `/pv search`, the Search button | Yours, like the list. Results: `%vault_number%`, `%vault_name%`, `%vault_icon%`, `%vault_owner%`, `%vault_amount%`. |
| `user/toolbar.yml` | Under every vault when `vaults.toolbar` is on | Yours, like the list. Buttons on columns 0 to 8 of the row; values `%vault_owner%`, `%vault_number%`, `%vault_name%`, `%previous_number%`, `%next_number%`, `%vaults_unlocked%`. |
| `admin/players.yml` | `/pvadmin` | Replaced from the jar on every start and every menu reload. The online players, each opening their list. |
| `admin/settings.yml`, `settings_vaults.yml`, `settings_access.yml`, `settings_purchase.yml` | The Settings card of the players hub | Replaced from the jar like the other admin screens. |
| `admin/history.yml` | `/pvadmin history` | Replaced from the jar on every start and every menu reload. |

A menu file that fails to parse is named in the console and that screen does not open; fix it and `/pvadmin reload`. How to edit a menu is on [Edit menus](/docs/exylialib/edit-menus).

On servers using ExyliaLib's full-screen menu style, the vault list and the search results are drawn from `screens/vaults.html`, with its look in `screens/theme.css` (put your own rules in `custom.css` beside it) and its words in `lang/<code>/screens/vaults.yml`. A screen that cannot be read falls back to the chest menu. `/exylialib screens check` lists anything wrong; see [Screens](/docs/exylialib/screens).

### The vault list

`vaults.yml` is a `PAGINATION` menu with three templates: `item_template` for vaults the owner has, `buy_template` for the next one for sale, `locked_template` for the rest.

| Screen values | Each vault |
|---|---|
| `%owner_name%`, `%vaults_unlocked%`, `%vaults_max%`, `%vaults_bought%`, `%vaults_rows%` | `%vault_number%`, `%vault_name%`, `%vault_icon%`, `%vault_used%`, `%vault_size%`, `%vault_free%`, `%vault_owner%`, and on the one for sale `%vault_price%` |

`%vault_owner%` is the owner's UUID, which the buttons pass to the actions. `%vaults_max%` is how many entries are drawn: `max-amount`, or the unlocked count when that is higher.

### The history screen

| Screen values | Each copy |
|---|---|
| `%owner_name%`, `%vault_number%`, `%history_size%` | `%snapshot_id%`, `%snapshot_date%`, `%snapshot_when%`, `%snapshot_cause%`, `%snapshot_actor%`, `%snapshot_used%` |

`%snapshot_cause%` is `CLOSED`, `EDITED`, `CLEARED` or `RESTORED`; `%snapshot_used%` is how many stacks the copy holds.

### Actions

The buttons call these, and any menu of any Exylia plugin can too (see [Actions](/docs/exylialib/actions)):

| Action | What it does |
|---|---|
| `exyliaplayervaults:open <owner> <number>` | Opens a vault. Your own goes through every player check; somebody else's opens to edit with `admin.edit`, read only with `admin.view`, and does nothing otherwise. |
| `exyliaplayervaults:rename <owner> <number>` | Asks for a new name. Your own unlocked vault with `customize.name`, or anybody's with `admin.edit`. |
| `exyliaplayervaults:icon <owner> <number>` | Asks for a new icon, on the same terms with `customize.icon`. |
| `exyliaplayervaults:buy` | Sells the clicker their next vault. |
| `exyliaplayervaults:list <owner>` | Opens that owner's vault list: your own, or anybody's with `admin.view`. |
| `exyliaplayervaults:search <owner>` | Opens the search for that owner's vaults. |
| `exyliaplayervaults:history <owner> <number>` | Opens a vault's history. Needs `admin.history`. |
| `exyliaplayervaults:clear <owner> <number>` | Empties a vault after a confirmation. Needs `admin.clear`. |
| `exyliaplayervaults:snapshot_view <id>` | Shows a history copy, read only. Needs `admin.history`. |
| `exyliaplayervaults:snapshot_restore <id>` | Puts a history copy back after a confirmation. Needs `admin.history` and `admin.edit`. |

`<owner>` is a UUID; the owner is never trusted from the button, so acting on somebody else's vault always asks for the staff permission again.
