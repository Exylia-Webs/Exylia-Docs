## Descarga

ExyliaPlayerVaults es gratuito. Cada versión se publica en
[GitHub](https://github.com/Exylia-Plugins/ExyliaPlayerVaults/releases) con dos copias del mismo jar:
`ExyliaPlayerVaults-<version>.jar` y `ExyliaPlayerVaults.jar`. Cualquiera de los dos sirve; el segundo
conserva el mismo nombre en todas las versiones, y es el que descarga el actualizador.

## Antes de empezar

| Plugin | Para qué |
|---|---|
| `ExyliaLib` | Obligatorio. Configuración, menús, base de datos, bloqueos, Redis, placeholders, preguntas, economía y el registro de auditoría. |
| `PlaceholderAPI` | Opcional. Expone el número de baúles y el precio del siguiente a otros plugins. |
| Una economía | Opcional, solo para vender baúles: `ExyliaEconomy`, o cualquier plugin detrás de `Vault`. Las compras cobran en la moneda que alcance ExyliaLib. |

<Callout type="note" title="ExyliaLib figura como soft, y se instala solo">
`plugin.yml` pone ExyliaLib en `softdepend` a propósito, para que el plugin pueda arrancar sin él. Si falta
ExyliaLib, ExyliaPlayerVaults descarga la última versión de las releases de GitHub de la librería en
`plugins/ExyliaLib.jar` (y, si falla, la versión exacta con la que se compiló), lo avisa en la consola y se
queda desactivado hasta que reinicies. Si ya hay un jar de ExyliaLib en `plugins/` pero no cargó, no se
descarga nada: la consola te pide que arregles primero los errores de la propia librería.
</Callout>

## Instalar

<Steps>
  <Step title="Copia el jar">
    Copia `ExyliaPlayerVaults.jar` en `plugins/`.
  </Step>
  <Step title="Arranca el servidor">
    Sin ExyliaLib, el primer arranque lo descarga y pide un reinicio. Reinicia una vez.
  </Step>
  <Step title="Abre un baúl">
    Ejecuta `/pv`. Un servidor nuevo le da a cada jugador un baúl de seis filas. Ver
    [Primeros pasos](/docs/exyliaplayervaults/primeros-pasos).
  </Step>
</Steps>

<Callout type="warning" title="Junto a ExyliaSurvivalCore">
ExyliaSurvivalCore ya no incluye el módulo `vaults`. Actualízalo a una versión sin el módulo al instalar
este plugin, para que solo un plugin responda a `/pv` y `/vault`. No se copia nada de la carpeta de
ExyliaSurvivalCore: lee [Venir de ExyliaSurvivalCore](/docs/exyliaplayervaults/red#venir-de-exyliasurvivalcore)
antes del primer arranque.
</Callout>

## Archivos generados

Todos están en `plugins/ExyliaPlayerVaults/`.

| Archivo | Contenido |
|---|---|
| `config.yml` | Cantidades y filas, ranuras ocultas, materiales bloqueados, restricciones, compras, historial, personalización y sonidos. Ver [Configuración](/docs/exyliaplayervaults/configuracion). |
| `lang/<code>/messages.yml` | Cada línea que envía el plugin y cada título de ventana. |
| `lang/<code>/menus/user/vaults.yml` | La lista de baúles. Tuya para rediseñar; se conserva entre actualizaciones. |
| `lang/<code>/menus/admin/history.yml` | La pantalla del historial. Se reescribe desde el jar en cada arranque. |
| `database.yml` | Motor de base de datos y Redis, escrito por ExyliaLib. H2 por defecto. |

`<code>` es el idioma en el que funciona el plugin: `en`, `es`, `pt`, `fr`, `ru` o `tr`, o el idioma de
ExyliaLib mientras `config.yml` diga `default`.

<Callout type="warning" title="menus/admin/ se reescribe">
`history.yml` dice "DO NOT EDIT — REGENERATED ON EVERY STARTUP" y va en serio: se reemplaza desde el jar en
cada arranque y en cada recarga de menús. La que está pensada para editarse es la lista de baúles de
`menus/user/`.
</Callout>

## Base de datos

Por defecto el plugin usa **H2**: un archivo dentro de la carpeta del plugin, sin servidor, sin instalación
y sin mantenimiento. Sirve de sobra para un solo servidor.

Para una red, todos los servidores apuntan a la misma base de datos, idealmente con Redis activado:

```yaml title="plugins/ExyliaPlayerVaults/database.yml"
database:
  type: mysql
  mysql:
    host: 127.0.0.1
    port: 3306
    database: minecraft
    username: root
    password: ""
  redis:
    enabled: true
    host: 127.0.0.1
```

Motores admitidos: `h2`, `mysql`, `mariadb`, `postgresql` y `mongodb`. Solo se lee el bloque que coincide
con `type`. El archivo es de ExyliaLib; su referencia completa está en la
[página de base de datos de la librería](/docs/exylialib/base-de-datos). Qué hacen la base de datos compartida y
Redis por los baúles está en [Red](/docs/exyliaplayervaults/red).

## Actualizaciones

ExyliaLib mantiene ExyliaPlayerVaults al día. El plugin indica su repositorio de GitHub en `plugin.yml`
(`exylia-updates: Exylia-Plugins/ExyliaPlayerVaults`) y la ExyliaLib más antigua con la que funciona
(`exylia-lib`); ExyliaLib busca una versión nueva, la descarga en segundo plano y la aplica en el siguiente
reinicio.

- Una versión mayor nueva se anuncia y queda para que la instales a mano.
- Una versión que necesite una ExyliaLib más nueva espera hasta que la librería se haya actualizado.
- `plugin-updates` en `plugins/ExyliaLib/config.yml` lo desactiva o lo ajusta.

Para actualizar a mano, reemplaza el jar y reinicia. `config.yml`, `messages.yml` y la lista de baúles
conservan tus cambios; `menus/admin/` se renueva desde el jar; los baúles están en la base de datos y no se
tocan.
