Al terminar esta página el plugin funciona con su base de datos por defecto, listo para `/pv`.

## Antes de empezar

- Paper o Folia 1.21.4 o superior, Java 21.
- [ExyliaLib](/docs/exylialib) en `plugins/`. Es obligatorio: los menús, la base de datos, los bloqueos, la economía y el registro de auditoría vienen de él.
- Opcional: PlaceholderAPI, y un plugin de economía solo si vas a vender baúles.

## Pasos

<Steps>
  <Step title="Descarga">
    ExyliaPlayerVaults es gratis. Descarga `ExyliaPlayerVaults.jar` desde [Modrinth](https://modrinth.com/plugin/exyliaplayervaults) o las [releases de GitHub](https://github.com/Exylia-Plugins/ExyliaPlayerVaults/releases).
  </Step>
  <Step title="Ponlo en plugins">
    Copia el jar en la carpeta `plugins/`, junto a ExyliaLib.
  </Step>
  <Step title="Arranca el servidor">
    El plugin escribe sus archivos en `plugins/ExyliaPlayerVaults/`. Sin ExyliaLib se queda apagado y la consola dice dónde conseguirlo. Instala ExyliaLib y reinicia: no se descarga nada por ti.
  </Step>
  <Step title="Abre un baúl">
    Ejecuta `/pv`. Un servidor nuevo da a cada jugador un baúl de seis filas. Mira [Tu primer baúl](/docs/exyliaplayervaults/primeros-pasos).
  </Step>
</Steps>

<Callout type="warning" title="Junto a ExyliaSurvivalCore">
ExyliaSurvivalCore ya no incluye el módulo `vaults`. Actualízalo a una versión sin el módulo al instalar este plugin, para que solo un plugin responda a `/pv` y `/vault`. No se copia nada de su carpeta: lee [Si vienes de ExyliaSurvivalCore](/docs/exyliaplayervaults/red#si-vienes-de-exyliasurvivalcore) antes del primer arranque.
</Callout>

## La base de datos

Por defecto el plugin usa H2, un archivo dentro de la carpeta del plugin sin nada que instalar. Basta para un solo servidor.

Para una red, apunta todos los servidores a la misma base de datos y, si tienes Redis, actívalo. El archivo es `plugins/ExyliaPlayerVaults/database.yml`, escrito por ExyliaLib. Los motores soportados son `h2`, `mysql`, `mariadb`, `postgresql` y `mongodb`. El archivo completo se explica en la [base de datos de ExyliaLib](/docs/exylialib/database), y lo que hace una base compartida por los baúles está en [Comparte baúles entre servidores](/docs/exyliaplayervaults/red).

## Actualizar

ExyliaLib mantiene el plugin al día. Anuncia una versión nueva en la consola y a los admins, y `/exylialib plugins` la descarga; se aplica en el siguiente reinicio. Una versión mayor nueva espera a que la instales a mano, y una versión que necesita un ExyliaLib más nuevo espera a que la biblioteca se actualice. Para actualizar a mano, cambia el jar y reinicia. Tu `config.yml`, los mensajes y la lista de baúles conservan tus cambios, y los baúles siguen intactos en la base de datos.

<Details title="Archivos que crea el primer arranque">
Todos en `plugins/ExyliaPlayerVaults/`. `<code>` es el idioma del plugin (`en`, `es`, `pt`, `fr`, `ru` o `tr`), o el de ExyliaLib mientras `language` en `config.yml` diga `default`.

| Archivo | Contenido |
|---|---|
| `config.yml` | Cantidades, filas, restricciones, compras, historial, nombres y sonidos. Mira [Configuración](/docs/exyliaplayervaults/configuracion). |
| `lang/<code>/messages.yml` | Cada línea de chat y cada título de ventana. |
| `lang/<code>/menus/user/vaults.yml`, `search.yml`, `toolbar.yml` | La lista de baúles, los resultados de búsqueda y la fila opcional de botones bajo un baúl. Tuyos para retocar; se conservan al actualizar. |
| `lang/<code>/menus/admin/*.yml` | El panel de staff, las pantallas de ajustes y la de historial. Se reemplazan desde el jar en cada arranque. |
| `screens/vaults.html`, `screens/theme.css` | El aspecto a pantalla completa de la lista, para servidores que usan screens. |
| `database.yml` | Base de datos y Redis, H2 por defecto. |
</Details>
