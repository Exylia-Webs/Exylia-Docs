---
title: "Permisos"
description: "Cada nodo que declara el plugin, qué controla, sus valores por defecto y sus hijos, y los nodos de cantidad y filas que dimensionan los baúles por rango."
---

Todos los nodos de abajo están declarados en `plugin.yml`, salvo las dos familias numeradas, que concedes
con el número que quieras.

## Baúles por rango

| Permiso | Qué decide |
|---|---|
| `exyliaplayervaults.amount.<number>` | Cuántos baúles tiene el jugador. Gana el número más alto que tenga; sin ninguno, `vaults.default-amount`. Con tope en `vaults.max-amount`, contando los comprados. |
| `exyliaplayervaults.rows.<1-6>` | Cuántas filas tiene cada uno de sus baúles. Gana el número más alto; sin ninguno, `vaults.default-rows`. Siempre de 1 a 6. |

Ver [Baúles](/docs/exyliaplayervaults/cofres#cuántos-y-de-qué-tamaño).

## Nodos del plugin

| Permiso | Por defecto | Qué controla |
|---|---|---|
| `exyliaplayervaults.use` | todos | `/pv`, la lista y abrir tus propios baúles. |
| `exyliaplayervaults.search` | todos | `/pv search`. |
| `exyliaplayervaults.buy` | todos | Comprar baúles desde la lista, cuando las compras están activadas. |
| `exyliaplayervaults.customize.name` | todos | Renombrar tus baúles. |
| `exyliaplayervaults.customize.icon` | todos | Elegir sus iconos. |
| `exyliaplayervaults.bypass.cooldown` | operadores | Abrir sin esperar `open-cooldown`, y buscar sin la espera de búsqueda. |
| `exyliaplayervaults.bypass.restrictions` | operadores | Abrir en mundos y modos de juego desactivados, y en combate; un baúl abierto en una pelea sigue abierto. |
| `exyliaplayervaults.bypass.blocked` | nadie | Meter objetos bloqueados en un baúl. |
| `exyliaplayervaults.admin.view` | operadores | `/pvadmin`, `/pvadmin list` y `/pvadmin view`. |
| `exyliaplayervaults.admin.edit` | operadores | `/pvadmin edit`, editar desde la lista de otro, renombrar sus baúles y cambiarles el icono, y restaurar una copia del historial. Hijo: `admin.view`. |
| `exyliaplayervaults.admin.history` | operadores | `/pvadmin history` y mirar dentro de una copia. Restaurarla necesita también `admin.edit`. Hijo: `admin.view`. |
| `exyliaplayervaults.admin.clear` | operadores | `/pvadmin clear`. |
| `exyliaplayervaults.admin.reload` | operadores | `/pvadmin reload`. |
| `exyliaplayervaults.admin` | operadores | Todos los comandos de administración. Hijos: `admin.view`, `admin.edit`, `admin.history`, `admin.clear`, `admin.reload`. |
| `exyliaplayervaults.*` | operadores | Todo menos `bypass.blocked`. |

<Callout type="note" title="bypass.blocked nunca se concede solo">
Una lista de bloqueados es decisión del dueño del servidor, así que `exyliaplayervaults.bypass.blocked` no lo
tiene nadie por defecto, operadores incluidos, y `exyliaplayervaults.*` lo deja fuera. Concédelo por su nombre
a quien deba tenerlo. El staff que edita con `/pvadmin edit` no está sujeto a la lista de todas formas.
</Callout>

Un nodo que falta en un botón de la lista o en una compra responde *"No tienes permiso para hacer eso."*; en
un comando, el rechazo propio del servidor.

## Venir de ExyliaSurvivalCore

Los antiguos nodos `exyliasurvivalcore.vaults…` no se vuelven a declarar y aquí no conceden nada. Ver
[Red](/docs/exyliaplayervaults/red#permisos) para los nombres nuevos.

## Ejemplos

Tres baúles de seis filas para los VIP, uno de tres filas para todos los demás:

```text
/lp group default permission set exyliaplayervaults.rows.3 true
/lp group vip permission set exyliaplayervaults.amount.3 true
/lp group vip permission set exyliaplayervaults.rows.6 true
```

Moderadores que pueden mirar pero no tocar:

```text
/lp group mod permission set exyliaplayervaults.admin.view true
/lp group mod permission set exyliaplayervaults.admin.history true
```

Impedir que un grupo renombre:

```text
/lp group default permission set exyliaplayervaults.customize.name false
```
