title: "Permissions"
description: "Every node plugin.yml declares, its default, what it gates, and how to make a feature a rank perk."
---

Every node below is declared in `plugin.yml` with a default, so a permission plugin sees all of them
and their descriptions. The player nodes default to `true`: out of the box everybody can use every
feature, and a server makes one a rank perk by denying it to the default group.

| Permission | Default | What it gates |
|---|---|---|
| `exyliapracticebot.use` | `true` | `/bot` (and so the main menu), `/bot spawn`, `/bot tpme`, `/bot tpto` and `/bot reset`. |
| `exyliapracticebot.spawn` | `true` | Spawning a bot: `/bot spawn`, the menu's **Spawn** button and any `spawn` action. |
| `exyliapracticebot.teleport` | `true` | Both teleports: `/bot tpto`, `/bot tpme` and the menu's teleport button. |
| `exyliapracticebot.advanced` | `true` | The **Fine tuning** screen: opening it, every slider (`adjust`) and its four toggles (invincible, anti-knockback, slow falling, fire resistance). |
| `exyliapracticebot.mode.<mode>` | `true` | Picking that combat mode: `sword`, `pot_pvp`, `uhc`, `crystal_pvp`, `mace_pvp` or `boxing`. |
| `exyliapracticebot.mode.*` | `true` | Parent of the six mode nodes. |
| `exyliapracticebot.difficulty.<difficulty>` | `true` | Picking that difficulty: `easy`, `normal`, `hard`, `insane` or `extreme`. |
| `exyliapracticebot.difficulty.*` | `true` | Parent of the five difficulty nodes. |
| `exyliapracticebot.bypass.limit` | `op` | Spawning into the slots kept for matches (`reserved-for-matches`). `max-bots` still applies. |
| `exyliapracticebot.admin` | `op` | `/bot reload`, `/bot settings`, `/bot export` and `/bot import`. |

Two things never need a node: **removing your bot** (`/bot remove` and the menu's **Remove** button are
never behind a rank) and picking **no mode** (`NONE`), which is how a player steps out of one.

A command needs `exyliapracticebot.use` **and** the feature node: `/bot spawn` checks `use` and then
`spawn`, the two teleports check `use` and then `teleport`. `exyliapracticebot.admin` does not imply
any player node, but those default to `true`, so a staff member has them unless you deny them.

## When a node is missing

A player who clicks or types something they do not hold gets the `bot.no-permission` line from
`messages.yml` — *You don't have permission to do that.* — and nothing changes.

The **Mode** and **Difficulty** buttons do better than refuse: cycling skips every mode or difficulty
the player cannot pick, so they only ever land on one they hold. `NONE` is always on the mode wheel,
and a player who holds only one difficulty stays on it.

<Callout type="note" title="Denying a mode does not take it off a saved bot">
The nodes gate *picking*. A player whose settings already hold a mode or difficulty you now deny keeps
it until they change it or reset, and **Reset settings** goes back to the server's `bot.mode` and
`bot.difficulty` whatever they hold. Keep those two defaults to a mode and difficulty everybody may use.
</Callout>

## Menus wired into other plugins

The checks live in the plugin's own menu actions, not in the menu files, so they follow the action
wherever you wire it. A `practicebot:spawn` button in a hub menu still needs `exyliapracticebot.spawn`,
and a `practicebot:set_mode crystal_pvp` button still needs `exyliapracticebot.mode.crystal_pvp`.
`remove`, `reset_settings` and the gear buttons (`cycle` for armour, hands and potions, `toggle` for
attack, follow and shield up) check nothing. See [Menus](/docs/exyliapracticebot/menus).

The API does not ask about permissions at all: another plugin that spawns a bot through
`PracticeBotService` decides for itself whether a player may be given one. See
[API](/docs/exyliapracticebot/api).

## Examples

Making the fine-tuning screen a VIP perk:

```text
/lp group default permission set exyliapracticebot.advanced false
/lp group vip permission set exyliapracticebot.advanced true
```

Keeping crystal PvP and the top difficulty for a rank:

```text
/lp group default permission set exyliapracticebot.mode.crystal_pvp false
/lp group default permission set exyliapracticebot.difficulty.extreme false
/lp group vip permission set exyliapracticebot.mode.crystal_pvp true
/lp group vip permission set exyliapracticebot.difficulty.extreme true
```

Taking the plugin away from one group while leaving it for the rest:

```text
/lp group survival permission set exyliapracticebot.use false
```

Restricting *where* bots may be spawned is configuration rather than permissions: `worlds` in
`config.yml` is the list of worlds a spawn is accepted in, and it applies to everybody. See
[Configuration](/docs/exyliapracticebot/configuration).
