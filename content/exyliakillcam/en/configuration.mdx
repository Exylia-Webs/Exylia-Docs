ExyliaKillCam writes its files to `plugins/ExyliaKillCam/` on first start, with comments. Edit them there, never the copies in the jar.

- `config.yml`: how long a killcam is, which deaths get one, the recording.
- `lang/<code>/messages.yml`: every line the plugin says. See [Edit the messages and the skip button](/docs/exyliakillcam/messages).
- `lang/<code>/hotbar.yml`: the skip button shown while watching.

Run `/killcamadmin reload` to apply an edit to any of them. You can also change the main settings in game with `/killcamadmin settings` (needs `exyliakillcam.admin`). Colours in messages are palette tokens: see [Colours](/docs/exylialib/colours) and [Messages and languages](/docs/exylialib/messages-and-languages).

## Make the killcam longer or shorter

`killcam.seconds-before` is how much of the fight is shown before the death (default `6` seconds, at least 1; `10s` also works). `killcam.hold-seconds` is how long the camera stays on the body after the death for the fall and the kill effect (default `3`). The recording keeps `seconds-before` plus three seconds around every player, so a very high value uses more memory.

## Change what players get after dying

`killcam.default-mode` is `AUTO` (starts by itself), `ASK` (a clickable line in chat) or `OFF` until a player chooses with `/killcam mode`. `killcam.auto-respawn` (default `true`) respawns `AUTO` players by themselves so the killcam follows the death. See [Choose what players get after dying](/docs/exyliakillcam/modes).

## Decide which deaths get a killcam

`deaths.mobs` (default `false`) also gives a killcam for a death to a mob. `deaths.disabled-worlds` lists worlds, by name and in any case, where nobody gets one. Keep `deaths.skip-held-players` on so a death another plugin is in charge of (a duel, an event, an FFA arena) waits until that plugin lets the player go. See [Compatibility](/docs/exyliakillcam/compatibility).

## Choose how long a death can be watched again

`killcam.rewatch-minutes` (default `5`, at least 1) is how long `/killcam` can still show a player's last death. Give a rank another time with the permission `exyliakillcam.rewatch.<n>` (minutes); the highest one a player holds wins. See [Permissions](/docs/exyliakillcam/permissions).

## Lower the memory use

Reduce `recording.radius` (blocks around the victim that are shown, default `24`, kept between `8` and `96`) and `killcam.rewatch-minutes` on a very busy server. See the [FAQ](/docs/exyliakillcam/faq).

<Details title="Every config.yml key">

The defaults, with the comments trimmed:

```yaml title="plugins/ExyliaKillCam/config.yml"
config-version: 1
language: default
killcam:
  default-mode: AUTO
  seconds-before: 6
  slow-motion-seconds: 1.0
  slow-motion-speed: 0.35
  first-person: true
  hold-seconds: 3
  auto-respawn: true
  rewatch-minutes: 5
  narrate-hits: true
deaths:
  mobs: false
  disabled-worlds: []
  skip-held-players: true
recording:
  radius: 24.0
  hide-vanished: true
kill-effects:
  replay: true
```

`config-version` is the file's own version, for the plugin to update it; leave it alone.

### language

| Key | Default | What it does |
|---|---|---|
| `language` | `default` | The language of this plugin's messages and hotbar. `default` follows the language set in ExyliaLib's `config.yml`; `en`, `es`, `pt`, `fr`, `ru`, `tr` or `de` set this plugin alone. Each one is a folder under `lang/` you can edit. |

### killcam

| Key | Default | What it does |
|---|---|---|
| `killcam.default-mode` | `AUTO` | What players get until they choose with `/killcam mode`: `AUTO`, `ASK` or `OFF`. |
| `killcam.seconds-before` | `6` | How much of the fight is shown before the death, in seconds, or written out (`10s`). At least 1. |
| `killcam.narrate-hits` | `true` | Whether each hit the victim took is written in their chat as the killcam passes it: who, how much and which hit it was. |
| `killcam.slow-motion-seconds` | `1.0` | How long the last moment before the death plays in slow motion, in seconds. `0` is never. |
| `killcam.slow-motion-speed` | `0.35` | How fast that slow motion plays: `0.5` is half speed. Kept between `0.0625` and `1`. |
| `killcam.first-person` | `true` | Whether the killcam is watched through the killer's eyes. `false` is from behind the victim. |
| `killcam.hold-seconds` | `3` | How long the camera stays on the body after the death, in seconds. At least 1. |
| `killcam.auto-respawn` | `true` | Whether players respawn by themselves. Only for players whose mode is `AUTO`. |
| `killcam.rewatch-minutes` | `5` | How long `/killcam` can still show a player's last death, in minutes, or written out (`10m`). At least 1. `exyliakillcam.rewatch.<n>` overrides it per rank. |

### deaths

| Key | Default | What it does |
|---|---|---|
| `deaths.mobs` | `false` | Whether a death to a mob gets a killcam too, not only a death to a player. |
| `deaths.disabled-worlds` | `[]` | Worlds, by name, where nobody gets a killcam. Any case. |
| `deaths.skip-held-players` | `true` | Whether a death another plugin is in charge of waits until that plugin lets the player go, and plays then. Keep it on. |

### recording

The recording every killcam is cut from: the last seconds around every player, kept in memory.

| Key | Default | What it does |
|---|---|---|
| `recording.radius` | `24.0` | How far around the victim the killcam shows what happened, in blocks. Kept between `8` and `96`. |
| `recording.hide-vanished` | `true` | Whether players in vanish are kept out of every killcam. |

The black box is ExyliaLib's and one serves the whole server: when another plugin opens it too, it keeps the larger of what each one asked for.

### kill-effects

| Key | Default | What it does |
|---|---|---|
| `kill-effects.replay` | `true` | Whether the killer's kill effect plays again, for the viewer alone, when the body falls. Needs ExyliaKillEffect 1.9.0 or newer; older versions are skipped without a word. |

</Details>

<Details title="messages.yml: which line is which">

`lang/<code>/messages.yml` holds every line the plugin says. `%prefix%` expands to the `prefix` value at the top, `{primary}&lKILLCAM {letters_black}•<reset>` by default. A line may open with an effect tag, which never reaches the screen: `[sound:NAME|volume|pitch]` plays a sound to whoever receives it. An empty message is not sent at all; that is how a message is turned off.

| Keys | When | Values |
|---|---|---|
| `prefix` | Opens every chat line through `%prefix%`. | |
| `title`, `subtitle` | The title shown as a killcam starts. | `%killer%` |
| `hud` | The line above the hotbar while it plays. | `%killer%` `%time%` `%length%` `%bar%` |
| `bar-done`, `bar-left` | One step of `%bar%`, played and still to play. The bar is sixteen steps. | |
| `hit` | Each hit the victim took (`killcam.narrate-hits`). | `%player%` `%damage%` `%number%` |
| `summary` | The lines after a killcam. | `%killer%` `%health%` `%weapon%` `%distance%` |
| `fists` | `%weapon%` when the killer's hand was empty. | |
| `offer` | After the respawn, for players whose mode is `ASK`. | `%killer%` |
| `no-recent-death` | `/killcam` with no death kept. | |
| `unsupported` | `/killcam` without PacketEvents. | |
| `busy` | `/killcam` while dead, already watching or held by another plugin. | |
| `failed` | `/killcam` when the killcam could not be shown. | |
| `mode-set` | `/killcam mode`. | `%mode%` |
| `mode-auto`, `mode-ask`, `mode-off` | The names `%mode%` takes, also the labels on `/settings`. | |
| `reloaded` | `/killcamadmin reload`. | |

`%health%` is the killer's hearts with one decimal, `%distance%` blocks with one decimal, and `%time%` and `%length%` the elapsed time and the length of the clip. The `summary` and `offer` lines carry their buttons as MiniMessage `<click>` tags running `/killcam`; keep the tag when restyling them.

</Details>

<Details title="hotbar.yml and storage">

`lang/<code>/hotbar.yml` is the skip button: a barrier in hotbar slot 4, drawn on the client and never put in the inventory. Its keys and default file are on [Edit the messages and the skip button](/docs/exyliakillcam/messages#the-skip-button). Menus follow [Edit menus](/docs/exylialib/edit-menus).

There is no database table. A player's mode is one of ExyliaLib's player settings, stored by the library (see [Database](/docs/exylialib/database)). Recordings and kept deaths live only in memory and are gone on a restart.

</Details>
