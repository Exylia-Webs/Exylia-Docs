Everything is generated in `plugins/ExyliaKillCam/` on first start, with comments. Edit the files there,
never the copies in the jar. `/killcam reload` applies an edit.

## config.yml

The defaults, with the comments trimmed:

```yaml title="plugins/ExyliaKillCam/config.yml"
config-version: 1
language: default
killcam:
  default-mode: AUTO
  seconds-before: 6
  slow-motion-seconds: 1.0
  slow-motion-speed: 0.35
  first-person: true
  hold-seconds: 3
  auto-respawn: true
  rewatch-minutes: 5
deaths:
  mobs: false
  disabled-worlds: []
  skip-held-players: true
recording:
  radius: 24.0
  hide-vanished: true
kill-effects:
  replay: true
```

`config-version` is the file's own version, for the plugin to update it; leave it alone.

### language

| Key | Default | What it does |
|---|---|---|
| `language` | `default` | The language of this plugin's messages and hotbar. `default` follows the language set in ExyliaLib's `config.yml`; `en`, `es`, `pt`, `fr`, `ru` or `tr` set this plugin alone. Each one is a folder under `lang/` you can edit. |

### killcam

What a killcam shows and for how long.

| Key | Default | What it does |
|---|---|---|
| `killcam.default-mode` | `AUTO` | What players get until they choose with `/killcam mode`: `AUTO`, `ASK` or `OFF`. See [Modes](/docs/exyliakillcam/modes). |
| `killcam.seconds-before` | `6` | How much of the fight is shown before the death, in seconds, or written out (`10s`). At least 1. |
| `killcam.slow-motion-seconds` | `1.0` | How long the last moment before the death plays in slow motion, in seconds. `0` is never. |
| `killcam.slow-motion-speed` | `0.35` | How fast that slow motion plays: `0.5` is half speed. Kept between `0.0625` and `1`. |
| `killcam.first-person` | `true` | Whether the killcam is watched through the killer's eyes. `false` is from behind the victim. |
| `killcam.hold-seconds` | `3` | How long the camera stays on the body after the death, for the fall and the kill effect, in seconds. At least 1. |
| `killcam.auto-respawn` | `true` | Whether players respawn by themselves, so the killcam follows the death without a click. Only for players whose mode is `AUTO`. |
| `killcam.rewatch-minutes` | `5` | How long `/killcam` can still show a player's last death, in minutes, or written out (`10m`). At least 1. |

### deaths

Which deaths get a killcam.

| Key | Default | What it does |
|---|---|---|
| `deaths.mobs` | `false` | Whether a death to a mob gets a killcam too, not only a death to a player. |
| `deaths.disabled-worlds` | `[]` | Worlds, by name, where nobody gets a killcam. Any case. |
| `deaths.skip-held-players` | `true` | Whether deaths another plugin is in charge of are left alone: a duel, an event, a match, anything that holds the player or takes over what they drop. Keep it on. See [Compatibility](/docs/exyliakillcam/compatibility). |

### recording

The recording every killcam is cut from: the last seconds around every player, kept in memory.

| Key | Default | What it does |
|---|---|---|
| `recording.radius` | `24.0` | How far around the victim the killcam shows what happened, in blocks. Kept between `8` and `96`. |
| `recording.hide-vanished` | `true` | Whether players in vanish are kept out of every killcam. |

The recording keeps `seconds-before` plus three seconds around every player (never less than ten, never
more than three hundred). The black box is ExyliaLib's and one serves the whole server: when another
plugin opens it too, it keeps the larger of what each one asked for.

### kill-effects

ExyliaKillEffect, when it is installed.

| Key | Default | What it does |
|---|---|---|
| `kill-effects.replay` | `true` | Whether the killer's kill effect plays again, for the viewer alone, when the body falls. Needs ExyliaKillEffect 1.9.0 or newer; older versions are skipped without a word. |

## messages.yml

`lang/<code>/messages.yml` holds every line the plugin says. `%prefix%` expands to the `prefix` value at
the top, `{primary}&lKILLCAM {letters_black}•` in English. Colours are palette tokens, so recolouring the
server never means editing this file.

A line may open with an effect tag, which never reaches the screen: `[sound:NAME|volume|pitch]` plays a
sound to whoever receives it. An empty message is not sent at all — that is how a message is turned off.

| Keys | When | Values |
|---|---|---|
| `prefix` | Opens every chat line through `%prefix%`. | |
| `title`, `subtitle` | The title shown as a killcam starts. | `%killer%` |
| `hud` | The line above the hotbar while it plays. | `%killer%` `%time%` `%length%` `%bar%` |
| `bar-done`, `bar-left` | One step of `%bar%`, played and still to play. The bar is sixteen steps. | |
| `summary` | The lines after a killcam. | `%killer%` `%health%` `%weapon%` `%distance%` |
| `fists` | `%weapon%` when the killer's hand was empty. | |
| `offer` | After the respawn, for players whose mode is `ASK`. | `%killer%` |
| `no-recent-death` | `/killcam` with no death kept. | |
| `unsupported` | `/killcam` without PacketEvents. | |
| `busy` | `/killcam` while dead, already watching or held by another plugin. | |
| `failed` | `/killcam` when the killcam could not be shown. | |
| `mode-set` | `/killcam mode`. | `%mode%` |
| `mode-auto`, `mode-ask`, `mode-off` | The names `%mode%` takes, also the labels on `/settings`. | |
| `reloaded` | `/killcam reload`. | |

`%health%` is the killer's hearts with one decimal, `%distance%` blocks with one decimal, and `%time%` and
`%length%` the elapsed time and the length of the clip.

The `summary` and `offer` lines carry their buttons as MiniMessage `<click>` tags running `/killcam`; keep
the tag when restyling them.

## hotbar.yml

`lang/<code>/hotbar.yml` is the skip button shown while watching. Its keys and the default file are on
[The killcam](/docs/exyliakillcam/killcam#the-skip-button).

## Storage

There is no database table. A player's mode is one of ExyliaLib's player settings, stored by the library.
Recordings and kept deaths live only in memory and are gone on a restart.
