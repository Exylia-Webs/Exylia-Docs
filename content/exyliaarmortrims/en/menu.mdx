title: "The menu"
description: "The classic inventory screen: armor along the top, the patterns and then the materials in the grid, all of it editable in lang/<language>/menus/trims.yml."
---

The classic menu is a single inventory window, drawn from `lang/<language>/menus/trims.yml`. What is
being engraved sits along the top; what can go on it sits below. Nothing is reopened between steps, so
the armor never moves and a half-built choice is never lost.

`/armortrim` opens it while `behaviour.menu-style` is `classic`, the default. With `spatial` it opens
[the 3D wardrobe](/docs/exyliaarmortrims/wardrobe) instead, except for a client older than 1.21.4 or a
player without `exyliaarmortrims.wardrobe`, who always get this screen.

## The two lists

| Section | Default slots | What it holds |
|---|---|---|
| `targets` | `2,3,4,5,6` | FULL SET and the four pieces. The marked row is what is being engraved. |
| `grid` | `10-16,19-25,28-34,37-43` | What can go on it: the patterns, then the materials. |

The grid has **two steps and one section**, because a slot belongs to one list:

<Steps>
  <Step title="Patterns">
    The menu always opens here, never on the materials of a pattern chosen minutes ago.
  </Step>
  <Step title="Materials">
    Once the pattern is picked, the grid moves to the materials, already previewed with that pattern.
    Picking one wears the trim.
  </Step>
</Steps>

The materials are drawn **on the armor the player is really wearing**: a netherite chestplate
previews the trim on netherite. The **patterns** are drawn as their own smithing template instead —
at that point no material has been picked, and the same shape on a helmet the size of an inventory
icon is one picture eighteen times over. Swap `%entry_icon%` back to `%preview_material%`, with an
`armor_trim` block, to preview them on armor too.

## Fixed buttons

| Button | Slot | What it does |
|---|---|---|
| BARE EVERYTHING | `45` | Takes the trim off all four pieces. |
| PATTERN | `49` | The step the grid is on and the pattern chosen; a click goes back to the patterns. |
| TRIM CRATE | `53` | Opens [the crate](/docs/exyliaarmortrims/crate), showing the player's keys and how much of the catalogue they unboxed. |
| Previous / next | `48` / `50` | Grid pagination. |

There is no close button: ESC closes.

## What a click does

| Where | Click | Result |
|---|---|---|
| A piece along the top | Left | Engraves that piece from now on. |
| A piece along the top | Right | Takes its trim off. |
| A pattern in the grid | Left | Takes it as the first half and moves to the materials. |
| A material in the grid | Left | Puts that trim on, or takes it off when it was already the one worn. |

With FULL SET focused, the trim goes on all four pieces.

## Templates

The first template of a list is what a row in no particular state uses, so `item_template` goes first.

| List | Templates |
|---|---|
| `targets` | `item_template`, `focused_template`, `set_template`, `focused_set_template` |
| `grid` · patterns | `pattern_template`, `pattern_selected_template`, `pattern_locked_template`, `pattern_purchasable_template` |
| `grid` · materials | `material_template`, `material_selected_template`, `material_locked_template`, `material_purchasable_template` |

`locked` is a half the player does not own. `purchasable` is a locked one the shop sells to them, with its price; clicking it buys it. A file
edited before the shop existed has no purchasable templates, and draws those entries as `locked`. A
locked entry **looks locked** rather than simply not being there.

## Placeholders in the file

These are the menu's own tokens, filled in while the screen is drawn. They are not PlaceholderAPI
placeholders and only work inside this file.

The `targets` list holds two kinds of row — the full-set row first, then one row per piece — and each
kind carries its own tokens.

| Placeholder | Where | What it draws |
|---|---|---|
| `%target%` | `targets`, anywhere | What is being engraved: a piece key, or `set` for the full set. |
| `%target_name%` | `targets`, anywhere | Its name from `menu`: `full-set`, or the piece's own name. |
| `%engraved%` | `targets`, full-set row | How many of the four pieces carry a trim. |
| `%pieces%` | `targets`, full-set row | How many pieces there are in total — four. |
| `%piece%` | `targets`, piece rows | The piece's key: `helmet`, `chestplate`, `leggings` or `boots`. |
| `%piece_material%` | `targets`, piece rows | The material the player is actually wearing in that slot. |
| `%trim_name%` | `targets`, piece rows | The trim chosen for that piece, or `menu.empty`. |
| `%trim_pattern%` | `targets`, piece rows | That trim's pattern, empty when the piece carries none. |
| `%trim_material%` | `targets`, piece rows | That trim's metal, empty when the piece carries none. |
| `%entry_id%` | `grid` | The row's id: a pattern id, or a `pattern/material` pair. |
| `%entry_name%` | `grid` | Its display name. |
| `%entry_icon%` | `grid` | The material the row is drawn as. |
| `%preview_material%` | `grid` | The armor piece the row is previewed in. |
| `%trim_pattern%` | `grid` | The pattern this row would engrave. |
| `%trim_material%` | `grid` | The metal this row would engrave. |
| `%entry_worn%` | `grid` | The pieces the player already wears it on, empty when none. |
| `%entry_worn_name%` | `grid` | The same, but `menu.empty` when none. |
| `%price%` | `grid` · purchasable | What it costs, written the way its currency writes it. |
| `%entry_buy%` | `grid` · purchasable | The id `armortrim:buy` takes: `pattern:<id>` or `material:<id>`. |
| `%material_name%` | `grid` · materials | The metal's display name. |
| `%pattern_name%` | `grid` · materials, anywhere | The chosen pattern's display name, or `menu.empty` before one is chosen. |
| `%tab%` | Anywhere | The step being shown: `patterns` or `materials`. |
| `%pattern%` | Anywhere | The chosen pattern's id, empty before one is chosen. |
| `%keys%` | Anywhere | The crate keys the player holds. |
| `%unlocked_count%` | Anywhere | How many prizes they unlocked. |
| `%catalogue_count%` | Anywhere | How many prizes the crate holds. |

## Actions

The verbs in the `armortrim` namespace:

| Action | What it does |
|---|---|
| `armortrim:open` | Opens the menu. |
| `armortrim:focus <piece\|set>` | Changes what is being engraved. |
| `armortrim:patterns` | Goes back to the patterns. `armortrim:tab`, which files from before 1.5.0 call, does the same. |
| `armortrim:pattern <id>` | Takes the first half and moves to the materials. |
| `armortrim:wear <pattern/material>` | Puts that trim on, or takes it off. |
| `armortrim:clear <piece\|set>` | Takes the trim off one piece or all of them. |
| `armortrim:buy <id>` | Buys a locked pattern or material: asks to confirm, charges and unlocks it, then reopens the screen. Needs `exyliaarmortrims.buy`. |
| `armortrim:crate` | Opens the crate. |

The screen's own verbs act on the window the click came from, so a player with the menu open twice cannot move the
wrong one.

## Wording

The few strings a template cannot spell out slot by slot live under `menu` in `messages.yml`:

```yaml title="messages.yml"
menu:
  full-set: "{primary}&lFULL SET"
  helmet: "{primary}&lHELMET"
  chestplate: "{primary}&lCHESTPLATE"
  leggings: "{primary}&lLEGGINGS"
  boots: "{primary}&lBOOTS"
  empty: "{muted}Nothing"
  custom-name: "{primary}&l%pattern% {letters_black}» {secondary}&l%material%"
  piece-names:
    helmet: "Helmet"
    chestplate: "Chestplate"
    leggings: "Leggings"
    boots: "Boots"
```

`custom-name` is what every trim is called. `piece-names` is how a piece is written inside a sentence
or a list.

<Callout type="note" title="Updating from 1.4">
The shipped `menus/trims.yml` is now `menu-version: 2`, without the PRESETS and CUSTOM tabs. An
untouched file is replaced on start; an edited one waits in `/exylialib updates`, and its old tab
buttons keep working until it is applied.
</Callout>

<Callout type="note" title="No menu, no screen">
With `mode: item` the trim screen and the wardrobe do not exist: `/armortrim` answers with
`menu-disabled` and nothing opens. The crate's two screens, `menus/crate.yml` and `menus/crate_open.yml`, are there in
every mode — see [The crate](/docs/exyliaarmortrims/crate).
</Callout>
