`config.yml` holds the settings and `lang/<language>/messages.yml` everything a player reads. The
trims themselves live in `trims.yml` — see [Trims](/docs/exyliaarmortrims/trims).

## language

```yaml
language: default
```

Which folder under `lang/` the menus and messages are read from. `default` follows the language set in
ExyliaLib's own `config.yml`; `en`, `es`, `pt`, `fr`, `ru` or `tr` set this plugin alone. A server that ran
the plugin before it was translated has its old `messages` and `menus/` moved to `lang/custom/`, and
`language: custom` is written so nothing it edited is lost.

## behaviour

```yaml
behaviour:
  mode: both
  consume-remover: true
  consume-trim-item: true
  hide-without-permission: true
  disabled-worlds: []
```

| Key | Default | What it does |
|---|---|---|
| `mode` | `both` | Where a trim comes from: `item`, `menu` or `both`. |
| `consume-trim-item` | `true` | Whether the trim item is used up when applied. |
| `consume-remover` | `true` | Whether the remover is used up when it removes a trim. |
| `hide-without-permission` | `true` | Whether armor whose trim the wearer does not own is shown as it really is. |
| `disabled-worlds` | `[]` | Worlds where trims are not shown: armor there looks as it really is. Names are matched ignoring case. |

Covered in [Modes and items](/docs/exyliaarmortrims/modes-and-items).

<Callout type="note" title="require-permission is gone">
The menu always asks whether the player owns a trim, and a trim item never does: holding one is the
proof of ownership. A `require-permission` key left in an older file is dropped on load.
</Callout>

## trim-item and remover-item

How the system's two items are drawn. Their names and lore are in `messages.yml`.

```yaml
trim-item:
  material: NETHERITE_UPGRADE_SMITHING_TEMPLATE
  glow: true

remover-item:
  material: SCRAPE_POTTERY_SHERD
  glow: true
```

| Key | What it does |
|---|---|
| `material` | The icon. A preset with its own `icon` wins over this. |
| `glow` | The enchantment shimmer. |

If the icon is a piece of armor it is painted with the trim it carries, so the item previews itself.

## armor-lore

```yaml
armor-lore:
  enabled: true
```

Whether lines are added under trimmed armor. The lines themselves are `armor-lore` in `messages.yml`.
Only the client sees them: they travel on the visual and are **never written to the real item**, so a
plugin reading the armor's lore finds exactly what it had.

## effects

```yaml
effects:
  on-apply:
    sound:
      name: BLOCK_SMITHING_TABLE_USE
      volume: 1.0
      pitch: 1.2
      category: PLAYERS
  on-remove:
    sound:
      name: BLOCK_GRINDSTONE_USE
```

ExyliaLib effects: `title`, `actionbar`, `bossbar`, `sound`, `particle` and `firework`. They play to
whoever put the trim on or took it off, from the menu or with an item.

## showcase

Places that show trims off on their own, one after another, for whoever walks past: a lobby
centrepiece rather than something a player asked for.

```yaml
showcase:
  locations: []
  pause-seconds: 3.0
  radius: 24.0
  only: []
```

| Key | Default | What it does |
|---|---|---|
| `locations` | `[]` | Where showcases stand. Set them with `/armortrimsadmin showcase add`, which writes where you stand and the way you face. |
| `pause-seconds` | `3.0` | The rest between one turn ending and the next starting. |
| `radius` | `24.0` | How close a player has to be for a showcase to play and to be seen, in blocks. |
| `only` | `[]` | The preset ids a showcase picks from. Empty picks from every preset. |

Each turn a body wearing a watcher's skin stands on the spot in a full diamond set wearing one preset,
turns once on the spot over six seconds and ends facing the crowd, with the preset's name floating
above it. A piece the preset does not fit stays plain. Only the players within `radius` see it, and a
player whose cosmetics are hidden is neither cast as the body nor shown one. With nobody near, nothing
plays.

## crate and shop

The crate's settings — `crate.enabled`, keys, `reward`, the reels, the bound blocks, the key item and
the rarities under `crate.tiers` — and the `shop` block that sells locked entries for currency are
covered in [The crate](/docs/exyliaarmortrims/crate).

## messages.yml

`lang/<language>/messages.yml` holds every line the plugin sends and every word on its items. Chat
lines start with `%prefix%`.

| Key | When it shows |
|---|---|
| `prefix` | The prefix the others use. |
| `applied` · `removed` | A trim put on or taken off. `%trim%`. |
| `not-armor` | An item was dropped onto something that is not armor. |
| `unsupported-piece` | The preset does not fit that piece. |
| `unknown-trim` | The trim no longer exists. |
| `already-trimmed` | The piece already carries a trim: use a remover first. |
| `no-trim` | The piece carries nothing to remove. |
| `inventory-full` | A free slot is needed to hand the item back. |
| `no-permission` | The player does not own that trim. |
| `given` · `given-remover` | `give` and `remover`. `%amount%`, `%trim%`. |
| `list-header` · `list-entry` · `list-empty` | `list`. `%id%` and `%trim%`. |
| `refreshed` | `refresh`. |
| `menu-disabled` | The menu is off because of the mode. |
| `cleared` | `clear` left the armor bare. |
| `nothing-changed` | `set` or `clear` left the player's trims as they were. `%player%`. |
| `rewards-claimed` | Items that were waiting were handed over on join. `%amount%`. |
| `showcase-*` · `showcases-*` | The `showcase` subcommands. `%location%`, `%amount%`. |
| `keys-given` · `keys-taken` | The `keys` subcommands. `%player%`, `%amount%`. |
| `unlock-granted` · `unlock-already` · `unlock-revoked` · `unlock-missing` · `unlocks-cleared` | The `unlocks` subcommands. `%trim%`, `%player%`, `%amount%`. |
| `crate-block-*` · `crate-blocks-*` | The `crate block` subcommands. `%location%`, `%amount%`. |
| `crate-pattern-name` · `crate-material-name` | What the crate calls a pattern or a material it hands out on its own. `%name%`. |
| `crate-preset-description` · `crate-pattern-description` · `crate-material-description` | The line under a prize on the reels. |
| `trim-item` · `remover-item` · `key-item` | Each item's `name` and `lore`. The trim item takes `%trim%`, `%pattern%` and `%material%`. |
| `armor-lore` | The lines under trimmed armor. `%trim%`. |
| `menu` | The words the trim screen fills in — see [The menu](/docs/exyliaarmortrims/menu#wording). |
| `placeholders.none` | What any `%exyliaarmortrims_...%` with nothing to answer returns. `None`. |
| `crate` | The crate's own lines: `won`, `duplicate`, `no-keys`, `busy`, `empty`, `disabled`, `keys-received`. |

English, Spanish, Portuguese, French, Russian and Turkish ship; a line a translation leaves out arrives in
English.

<Callout type="warning" title="Unknown keys are removed">
A key the file does not declare is dropped on load and reported once. It keeps the files clean between
versions, and it is why your own keys do not survive in them.
</Callout>
