## Player

| Command | Aliases | Permission | What it does |
|---|---|---|---|
| `/armortrim` | `/armortrims`, `/trims`, `/trim` | `exyliaarmortrims.command.armortrim` | Opens the trim menu `behaviour.menu-style` picks: the classic one or the 3D wardrobe. |
| `/armortrim wardrobe` | the same | `exyliaarmortrims.command.armortrim` and `exyliaarmortrims.wardrobe` | Opens the [3D wardrobe](/docs/exyliaarmortrims/wardrobe), whatever `menu-style` says. |
| `/armortrim crate` | the same | `exyliaarmortrims.command.armortrim` and `exyliaarmortrims.crate` | Opens the crate, the same screen the button in the corner of the menu opens. |

With `mode: item` the menu is off and `/armortrim` answers with the `menu-disabled` message. The crate
works in every mode. A feature node denied answers with `feature-locked`.

## Admin

Everything under `/armortrimsadmin` — aliased `/armortrimadmin` — needs `exyliaarmortrims.admin`.
Typed bare, it opens the admin hub: the catalogue, players, showcases and crate blocks from one
screen; the subcommands stay as shortcuts. `crate block clear` and `showcase clear` only say what they
would delete until they are run again with `confirm` at the end.

### Items

| Command | What it does |
|---|---|
| `/armortrimsadmin give <player> <pattern/material> [amount]` | Gives trim items. Amount is 1 to 64. |
| `/armortrimsadmin remover <player> [amount]` | Gives removers. |
| `/armortrimsadmin item key <player> [amount]` | Gives crate keys as items, to be right clicked on a crate block. Alias: `key`. |

What does not fit in the inventory waits and is handed over on the player's next join.

### What somebody wears

| Command | What it does |
|---|---|
| `/armortrimsadmin set <player> <pattern/material> [piece]` | Writes that trim into their menu choice. With no piece, every piece. |
| `/armortrimsadmin clear <player> [piece]` | Clears one piece's choice, or all of them. |
| `/armortrimsadmin open <player>` | Opens the trim menu for them, the one `menu-style` picks. |
| `/armortrimsadmin refresh [player]` | Recomputes and re-sends the look. With no player, everybody. |

`set` and `clear` work on a player who is offline too: the choice is a stored row, written the same
way, and the confirmation goes to you instead. When nothing changed — the trim was already there, or
another plugin refused the change — you are told with `nothing-changed`.

### Keys and unlocks

| Command | What it does |
|---|---|
| `/armortrimsadmin keys give <player> [amount]` | Adds crate keys to the player's account. Alias: `keys add`. |
| `/armortrimsadmin keys take <player> [amount]` | Removes crate keys. Alias: `keys remove`. |
| `/armortrimsadmin keys set <player> <amount>` | Sets how many they hold. |
| `/armortrimsadmin keys check <player>` | Prints how many they hold. Alias: `keys`. |
| `/armortrimsadmin unlocks grant <player> <prize>` | Unlocks a prize for good, the way a crate does. Alias: `unlocks give`. |
| `/armortrimsadmin unlocks revoke <player> <prize>` | Takes one back. Alias: `unlocks take`. |

All of them work on players who are offline. `<prize>` is `pattern:<id>` or `material:<id>`; tab
completion suggests them. See [The crate](/docs/exyliaarmortrims/crate).

<Callout type="note" title="unlocks clear moved to ExyliaLib">
Taking back everything a player unlocked is now ExyliaLib's player reset: the unlocks live in an
`@account` table, so `/exylialib resetplayer <player> ExyliaArmorTrims @account` clears them along with
the player's choices. See [Resetting a player](/docs/exylialib/commands#resetting-a-player).
</Callout>

### The crate and showcases

| Command | What it does |
|---|---|
| `/armortrimsadmin crate open <player>` | Opens the crate for someone, without spending anything until they choose. |
| `/armortrimsadmin crate block add` | Binds the block you are looking at, so clicking it opens the crate. |
| `/armortrimsadmin crate block remove` | Unbinds the block you are looking at. |
| `/armortrimsadmin crate block list` | Prints every bound block. |
| `/armortrimsadmin crate block clear [confirm]` | Unbinds all of them. |
| `/armortrimsadmin showcase add` | Shows trims off on a loop where you stand, facing the way you face. |
| `/armortrimsadmin showcase remove` | Removes the showcase nearest you, up to five blocks away. |
| `/armortrimsadmin showcase list` | Prints every showcase. |
| `/armortrimsadmin showcase clear [confirm]` | Removes all of them. |

`wardrobe place`, `crate block add` and `showcase add` open a placement wizard: walk to the spot, confirm with the gesture it asks for (sneak-click to keep your facing, or click the block) and cancel to go back.

Showcases are covered in [Configuration](/docs/exyliaarmortrims/configuration#showcase).

### The 3D wardrobe

| Command | What it does |
|---|---|
| `/armortrimsadmin wardrobe place` | Places a wardrobe where you stand, facing the way you face. Players click its hologram to open it there. |
| `/armortrimsadmin wardrobe remove` | Removes the placed wardrobe nearest you, up to four blocks away. |
| `/armortrimsadmin wardrobe edit` | Opens the wardrobe to move its pieces with the mouse wheel; saved to `spatial/wardrobe.yml`. |
| `/armortrimsadmin wardrobe tour <player>` | Shows the guided tour to an online player again on their next open. |

See [The 3D wardrobe](/docs/exyliaarmortrims/wardrobe).

### The rest

| Command | What it does |
|---|---|
| `/armortrimsadmin reload` | Re-reads every file and redraws everybody online, open wardrobes included. |

A trim is always written `pattern/material` — `sentry/netherite`. Tab completion suggests every
combination the catalogue offers. A preset id from before 1.5.0 is still read as the look it stood
for.

`[piece]` is `helmet`, `chestplate`, `leggings` or `boots`.

<Callout type="note" title="set does not ask about permissions">
`set` writes the choice **even when the player does not own the trim**, which is what an
administrator means by "set": running it twice leaves the same result, where the menu's click would
put the trim on and take it off again.

If `hide-without-permission` is also on, the player will not see what you gave them until they own
it, by node or by unlock.
</Callout>

## What reload covers

It re-reads `config.yml`, `messages.yml` and `trims.yml`, recompiles the menus of the current
language, rebuilds every trim's visual, the crate and the showcases, redraws every open wardrobe, and
refreshes everybody online. A
mode changed from `item` to `menu` or `both` brings up the menu right then, and a changed `language`
is picked up without a restart.

It does not reload ExyliaLib — that is `/exylialib reload` — and does not reopen the database
connection.
