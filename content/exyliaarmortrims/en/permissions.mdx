Players can open the menu, the wardrobe, the crate and the shop with no setup. Patterns and materials are locked until a permission, a crate unlock or a purchase hands them over. Use LuckPerms (or any permission plugin) to hand them out.

## All permissions

<Permissions />

A feature refused by its node answers with `feature-locked` from `messages.yml`. Taking a trim off never needs a permission.

## Sell patterns and materials

A trim is a pattern plus a material, and the player owns each half separately. The ids are lowercase and are the keys of `trims.yml`, for example `sentry` and `netherite`. A trim is worn once the player owns **both** halves.

`exyliaarmortrims.pattern.*` works even though the patterns are not listed in `plugin.yml` one by one: the plugin asks for the node and, failing that, for the wildcard at its level.

```text
# A couple of halves for everybody
/lp group default permission set exyliaarmortrims.pattern.sentry true
/lp group default permission set exyliaarmortrims.material.iron true

# The top rank, with every combination
/lp group mvp permission set exyliaarmortrims.pattern.* true
/lp group mvp permission set exyliaarmortrims.material.* true
```

## Make a feature a rank perk

Every player feature is held by everybody by default. To turn one into a perk, deny it to the default group and grant it to the rank.

```text
# The 3D wardrobe as a VIP perk (everybody else gets the classic menu)
/lp group default permission set exyliaarmortrims.wardrobe false
/lp group vip permission set exyliaarmortrims.wardrobe true

# VIPs open up to five crates at once
/lp group vip permission set exyliaarmortrims.crate.multi.5 true
```

`exyliaarmortrims.crate.multi.<n>` is a number per rank: the highest one a player holds wins. Without one, `crate.max-at-once` from `config.yml` applies, and the screen fits seven at most.

## Permissions and unlocks

A permission is one way to own a half; a crate unlock or a shop purchase is the other. Whatever a crate, a purchase or `/armortrimsadmin unlocks grant` unlocked is owned with no permission at all, and stays owned after a rank runs out. The menu, the wardrobe, `hide-without-permission` and the API all ask both.

## When a permission goes away

Nothing is deleted. What changes is what is seen:

| Where | Effect |
|---|---|
| The menu and the wardrobe | Always ask. A half the player does not own is drawn locked, or for sale when the shop prices it. |
| Trim items | Never ask. Holding one is the proof of ownership. |
| `hide-without-permission: true` | Armor already carrying a trim the wearer does not own is shown bare. |

The value stays on the armor and in the player's row, so the look comes back whole the day the rank does. Commands never look at ownership.

`exyliaarmortrims.trim.<preset>`, its per-piece variants and `exyliaarmortrims.custom` belonged to the presets removed in 1.5.0 and are no longer read. See [Trims](/docs/exyliaarmortrims/trims#coming-from-presets).
</Callout>
