## Features

Every player feature has a node **everybody holds by default**. A server makes one a rank perk by
denying it to the default group and granting it to the rank. Taking a trim off never needs one.

| Permission | Default | What it grants |
|---|---|---|
| `exyliaarmortrims.command.armortrim` | everybody | `/armortrim` and its subcommands. |
| `exyliaarmortrims.wardrobe` | everybody | The [3D wardrobe](/docs/exyliaarmortrims/wardrobe). Without it `/armortrim` opens the classic menu, and `/armortrim wardrobe` answers with `feature-locked`. |
| `exyliaarmortrims.buy` | everybody | Buying patterns and materials in the shop, from the menu or the wardrobe. Without it locked entries show no price. |
| `exyliaarmortrims.crate` | everybody | Opening the crate: the menu's button, `/armortrim crate`, the wardrobe's crate icon and a bound crate block. |
| `exyliaarmortrims.crate.multi.<n>` | — | Opening up to `<n>` crates in one go instead of `crate.max-at-once`. The highest one held wins; the screen fits seven. |
| `exyliaarmortrims.admin` | op | All of `/armortrimsadmin`: trims, crates, keys and wardrobes. |

A feature refused by its node answers with `feature-locked` from `messages.yml`.

## Patterns and materials

What is sold: nobody but op holds these until a rank, a crate or a purchase hands them over.

| Permission | What it grants |
|---|---|
| `exyliaarmortrims.pattern.<pattern>` | That pattern. |
| `exyliaarmortrims.pattern.*` | Every pattern. |
| `exyliaarmortrims.material.<material>` | That material. |
| `exyliaarmortrims.material.*` | Every material. |

Ids are lowercase and are the keys of `trims.yml` — `sentry`, `netherite`. A trim is worn once the
player owns **both** of its halves.

<Callout type="note" title="Preset nodes are gone">
`exyliaarmortrims.trim.<preset>`, its per-piece variants and `exyliaarmortrims.custom` belonged to the
presets removed in 1.5.0 and are no longer read. See
[Trims](/docs/exyliaarmortrims/trims#coming-from-presets).
</Callout>

## Nodes and unlocks

A node is one way to own a half; a crate unlock is the other. Whatever a crate, a purchase or
`/armortrimsadmin unlocks grant` unlocked is owned with no node at all, and it stays owned after a rank
runs out. Every gate asks both: the menu, the wardrobe, `hide-without-permission` and the API.

| Owned through | Covers |
|---|---|
| `exyliaarmortrims.pattern.<pattern>` or `pattern:<pattern>` unlocked | That pattern. |
| `exyliaarmortrims.material.<material>` or `material:<material>` unlocked | That material. |

See [The crate](/docs/exyliaarmortrims/crate).

## Wildcards are asked explicitly

`exyliaarmortrims.pattern.*` works for every pattern even though the patterns are not declared in
`plugin.yml` one by one. The plugin asks for the node and, failing that, for the wildcard at its level —
because a Bukkit wildcard only expands on its own when every child is a registered permission, and these
are named after entries in a file you edit.

## When a permission goes away

Nothing is deleted. What changes is what is seen:

| Where | Effect |
|---|---|
| The menu and the wardrobe | Always ask. A half the player does not own is drawn locked, or for sale when the shop prices it. |
| Trim items | Never ask. Holding one is the proof of ownership: it was bought, traded or won like any other item. |
| `hide-without-permission: true` | Armor already carrying a trim the wearer does not own is shown bare. |

The value stays on the armor and in the player's row, so the look comes back whole the day the rank
does. Commands never look at ownership.

## Examples

```text
# A couple of halves for everybody
/lp group default permission set exyliaarmortrims.pattern.sentry true
/lp group default permission set exyliaarmortrims.material.iron true

# The 3D wardrobe as a VIP perk
/lp group default permission set exyliaarmortrims.wardrobe false
/lp group vip permission set exyliaarmortrims.wardrobe true

# VIPs open up to five crates at once
/lp group vip permission set exyliaarmortrims.crate.multi.5 true

# The top rank, with every combination
/lp group mvp permission set exyliaarmortrims.pattern.* true
/lp group mvp permission set exyliaarmortrims.material.* true
```
