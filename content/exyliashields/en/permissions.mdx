Players can use ExyliaShields without any setup: they open `/shields`, get one slot, and can design with whatever patterns and colours they have unlocked. Only staff get `/shieldsadmin`. Use this page to sell more.

## All permissions

<Permissions />

For the three numbered nodes (`max_slots`, `layers`, `crate.multi`) the highest number a player holds wins, so a rank upgrade never has to revoke the lower one. A pattern or colour a player won from the crate or bought from the shop is theirs without the node, and it stays after a rank runs out.

## Make a feature a rank perk

Players hold every player permission by default. To make one a perk, deny it to the default group and grant it to the rank. With LuckPerms:

```text
/lp group default permission set exyliashields.browser false
/lp group vip permission set exyliashields.browser true
/lp group vip permission set exyliashields.max_slots.5 true
/lp group vip permission set exyliashields.layers.8 true
/lp group vip permission set exyliashields.crate.multi.7 true
/lp group vip permission set exyliashields.color.* true
/lp group mvp permission set exyliashields.pattern.* true
```

A player refused by a feature node sees "Your rank does not include this." (`no_access` in `messages.yml`). Resetting or deleting a design and removing a layer never need a node, so a lapsed rank never traps a player with a design they cannot take off.

<Callout type="warning" title="exyliashields.use strips designs">
With `force_system: true` (the default) a player without `exyliashields.use` has their design removed whenever they equip a shield. That is how an expired rank stops showing a design it no longer owns. Everybody holds the node by default, so deny it only to a group that should not keep designs, or set `force_system: false` in `config.yml`.
</Callout>
