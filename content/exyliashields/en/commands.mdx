## Commands

| Command | Permission | What it does |
|---|---|---|
| `/shields` | `exyliashields.command.shields` | Opens the slot menu. |
| `/shields crate` | `exyliashields.command.shields` | Opens the crate. |
| `/shields reload` | `exyliashields.admin` | Reloads this plugin's files. |

Everything else — the editor, the colour picker, the browser — is reached from inside the menus.

### Admin subcommands

All of them need `exyliashields.admin`.

| Subcommand | What it does |
|---|---|
| `keys give <player> [amount]` | Adds crate keys to their account. Alias `keys add`. |
| `keys take <player> [amount]` | Takes keys away, never below zero. Alias `keys remove`. |
| `keys set <player> <amount>` | Sets how many they hold. |
| `keys check <player>` | Says how many they hold. Also `keys <player>`. |
| `item key <player> [1-64]` | Gives crate keys as items that can be held, traded and dropped. |
| `unlocks grant <player> <id>` | Unlocks a pattern or colour for good, as a crate would. Alias `unlocks give`. |
| `unlocks revoke <player> <id>` | Takes an unlock back. Alias `unlocks take`. |
| `unlocks clear <player>` | Takes every unlock back. |
| `menu crate <player>` | Opens the crate for them, spending nothing. |
| `crate block add` / `remove` | Binds or unbinds the block you are looking at as a crate block. |
| `crate block list` / `clear` | Lists or unbinds every crate block. |
| `showcase add` | Places a showcase where you stand, facing the way you face. |
| `showcase remove` | Removes the showcase within 5 blocks of you. |
| `showcase list` / `clear` | Lists or removes every showcase. |

Unlock ids are `pattern:<id>` and `color:<id>`, and tab completes them.

<Callout type="note" title="A player does not have to be online">
`keys` and `unlocks` take a name or a UUID and write straight to the player's account when they are
offline, wherever on the network they are. `item key` and `menu crate` need them online.
</Callout>

See [The crate and the shop](/docs/exyliashields/crate) and
[Showcases](/docs/exyliashields/community#showcases).

<Callout type="note" title="Opening on a busy join">
If a player's row has not arrived from the database yet, `/shields` reads it and opens the menu when it
does, rather than failing. That is a moment on a busy join, not an error.
</Callout>

## Permissions

| Permission | Description |
|---|---|
| `exyliashields.command.shields` | Opening the menu. |
| `exyliashields.admin` | `/shields reload` and every admin subcommand. |
| `exyliashields.use` | Keeping a design on a shield, when `force_system` is on. |
| `exyliashields.max_slots.<n>` | That many slots. The highest granted wins. |
| `exyliashields.pattern.<id>` | One pattern. |
| `exyliashields.pattern.*` | Every pattern. |
| `exyliashields.color.<id>` | One colour. |
| `exyliashields.color.*` | Every colour. |

A pattern or colour a player won out of the crate or bought from the shop is theirs without the node.

### The three things a player needs

A player who can only open the menu cannot do anything in it. Working access is three nodes:

```text
/lp group default permission set exyliashields.command.shields true
/lp group default permission set exyliashields.use true
/lp group default permission set exyliashields.max_slots.1 true
```

Then sell the palette and the slots:

```text
/lp group vip permission set exyliashields.max_slots.5 true
/lp group vip permission set exyliashields.color.* true
/lp group mvp permission set exyliashields.pattern.* true
```

<Callout type="warning" title="force_system and exyliashields.use">
With `force_system: true` — the default — a player without `exyliashields.use` has their design
**stripped** whenever they equip a shield. Grant it alongside the slots, or turn the system off in
`config.yml` if you do not want designs gated that way.
</Callout>

## What reload covers

`/shields reload` re-reads `config.yml`, `shields.yml`, `messages.yml` and the menus of the language in
use. It does not reload the
library — that is what `/exylialib reload` is for — and it does not touch what players have saved,
which lives in the database.
