## Commands

| Command | Permission | What it does |
|---|---|---|
| `/shields` | `exyliashields.command.shields` | Opens the slot menu, or the 3D shield picker when `menu.style` is `SPATIAL`. |
| `/shields 3d` | `exyliashields.command.shields` | Opens the [3D designer](/docs/exyliashields/3d-menus) on the worn shield, or on a new one. |
| `/shields 3d slots` | `exyliashields.command.shields` | Opens the [3D shield picker](/docs/exyliashields/3d-menus). |
| `/shields crate` | `exyliashields.crate` | Opens the crate. |
| `/shieldsadmin` | `exyliashields.admin` | Opens the admin hub: catalogue, players, showcases, crate blocks and settings. The [subcommands below](#shieldsadmin) stay as shortcuts. |
| `/shieldsadmin reload` | `exyliashields.admin` | Reloads this plugin's files. |

Everything else — the editor, the colour picker, the browser — is reached from inside the menus.
Deleting or resetting a design asks for confirmation first.

On a client older than 1.21.4 the 3D menus cannot be drawn, so `/shields 3d` and `/shields 3d slots`
open the inventory menus instead.

### /shieldsadmin

Every staff command lives under `/shieldsadmin`, and all of them need `exyliashields.admin`. `<menu>`
is `designer`, `wardrobe` (the 3D picker) or `community` (the 3D browser). `showcase add`, `crate block add` and `spatial place` open a placement wizard: walk to the spot and confirm with the gesture it asks for (sneak-click keeps your facing), or cancel.

| Subcommand | What it does |
|---|---|
| `reload` | Reloads this plugin's files. |
| `settings` | Every setting, and the pattern and colour catalogue, in a menu: the same one the hub's settings button opens. |
| `keys give <player> [amount]` | Adds crate keys to their account. Alias `keys add`. |
| `keys take <player> [amount]` | Takes keys away, never below zero. Alias `keys remove`. |
| `keys set <player> <amount>` | Sets how many they hold. |
| `keys check <player>` | Says how many they hold. Also `keys <player>`. |
| `item key <player> [1-64]` | Gives crate keys as items that can be held, traded and dropped. |
| `unlocks grant <player> <id>` | Unlocks a pattern or colour for good, as a crate would. Alias `unlocks give`. |
| `unlocks revoke <player> <id>` | Takes an unlock back. Alias `unlocks take`. |
| `menu crate <player>` | Opens the crate for them, spending nothing. |
| `crate block add` / `remove` | `add` binds a block picked through a wizard as a crate block; `remove` unbinds the one you are looking at. |
| `crate block list` / `clear [confirm]` | Lists or unbinds every crate block. `clear` needs `confirm`. |
| `showcase add` | Places a showcase through a wizard, facing the way you face. |
| `showcase remove` | Removes the showcase within 5 blocks of you. |
| `showcase list` / `clear [confirm]` | Lists or removes every showcase. `clear` needs `confirm`. |

| `spatial place <menu>` | Sets that 3D menu down through a wizard, facing the way you face, for players to walk up to. |
| `spatial remove` | Removes the placed 3D menu within 4 blocks of you. |
| `spatial edit <menu>` | Opens the menu for you to move its pieces with the mouse wheel. |
| `spatial tour <player>` | Shows both 3D menus' guided tours to that player again, the next time they open each. |

Unlock ids are `pattern:<id>` and `color:<id>`, and tab completes them.

<Callout type="warning" title="The old /shields spellings">
Up to 1.4, the hub was `/shields admin` and the other staff commands were subcommands of `/shields`
(`/shields reload`, `/shields keys give`, `/shields crate block add`…). Since 1.5.0 they live under
`/shieldsadmin`. The old spellings still work for now, as deprecated aliases: each one runs and then
tells the staff member the new spelling (`admin_moved` in `messages.yml`). Update scripts, NPCs and
menus that call them.
</Callout>

<Callout type="note" title="A player does not have to be online">
`keys` and `unlocks` take a name or a UUID and write straight to the player's account when they are
offline, wherever on the network they are. `item key` and `menu crate` need them online.
</Callout>

<Callout type="note" title="Taking every unlock back">
`unlocks clear` is gone. Resetting a player is ExyliaLib's job now:
`/exylialib resetplayer <player> ExyliaShields` deletes their slots, designs and crate keys and unlocks,
and `/exylialib wipe` empties the tables by kind. See
[ExyliaLib's commands](/docs/exylialib/commands#resetting-a-player).
</Callout>

See [The crate and the shop](/docs/exyliashields/crate),
[Showcases](/docs/exyliashields/community#showcases) and [3D menus](/docs/exyliashields/3d-menus).

<Callout type="note" title="Opening on a busy join">
If a player's row has not arrived from the database yet, `/shields` reads it and opens the menu when it
does, rather than failing. That is a moment on a busy join, not an error.
</Callout>

## Permissions

| Permission | Default | Description |
|---|---|---|
| `exyliashields.command.shields` | everybody | `/shields` and the 3D menus: designing, buying and wearing shields. |
| `exyliashields.browser` | everybody | Browsing and importing the community's designs. |
| `exyliashields.crate` | everybody | Opening the crate: its button in the slot list, `/shields crate` and a bound crate block. |
| `exyliashields.use` | everybody | Keeping a design on a shield, when `force_system` is on. |
| `exyliashields.admin` | op | `/shieldsadmin` and every staff subcommand, old `/shields` spellings included. |
| `exyliashields.pattern.<id>` | op | One pattern. |
| `exyliashields.pattern.*` | op | Every pattern. |
| `exyliashields.color.<id>` | op | One colour. |
| `exyliashields.color.*` | op | Every colour. |
| `exyliashields.max_slots.<n>` | — | That many slots. Without any, one. |
| `exyliashields.layers.<n>` | — | That many layers per design. Without any, `max_layers` from `shields.yml`. |
| `exyliashields.crate.multi.<n>` | — | That many crates opened in one go. Without any, `crate.max-at-once`; seven at most. |

For the three numbered nodes the highest one a player holds wins, so a rank upgrade never has to
revoke the lower one. A pattern or colour a player won out of the crate or bought from the shop is
theirs without the node.

A player without a feature node is told their rank does not include it (`no_access` in
`messages.yml`). Resetting or deleting a design and removing a layer never need one, so a lapsed rank
never traps a player with a design they cannot take off.

### Ranks

Every player already has the features and one slot. A rank perk is a feature denied to the default
group and granted to a paid one, or a higher number:

```text
/lp group default permission set exyliashields.browser false
/lp group vip permission set exyliashields.browser true
/lp group vip permission set exyliashields.max_slots.5 true
/lp group vip permission set exyliashields.layers.8 true
/lp group vip permission set exyliashields.crate.multi.7 true
/lp group vip permission set exyliashields.color.* true
/lp group mvp permission set exyliashields.pattern.* true
```

<Callout type="warning" title="force_system and exyliashields.use">
With `force_system: true` — the default — a player without `exyliashields.use` has their design
**stripped** whenever they equip a shield. Everybody holds it by default; deny it only to a group
that should not keep designs, or turn the system off in `config.yml`.
</Callout>

## What reload covers

`/shieldsadmin reload` re-reads `config.yml`, `shields.yml`, `messages.yml` and the menus of the language in
use, and open 3D menus redraw with the new catalogue, prices and words. It does not reload the
library — that is what `/exylialib reload` is for — and it does not touch what players have saved,
which lives in the database.
