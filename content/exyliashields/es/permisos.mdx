Los jugadores pueden usar ExyliaShields sin configurar nada: abren `/shields`, tienen una ranura y diseñan con los patrones y colores que tengan desbloqueados. Solo el staff tiene `/shieldsadmin`. Usa esta página para vender más.

## Todos los permisos

<Permissions />

En los tres nodos numerados (`max_slots`, `layers`, `crate.multi`) gana el número más alto que tenga el jugador, así que subir de rango nunca obliga a quitar el anterior. Un patrón o color que el jugador ganó en la caja o compró en la tienda es suyo sin el nodo, y se queda cuando un rango caduca.

## Convierte una función en ventaja de rango

Los jugadores tienen por defecto todos los permisos de jugador. Para hacer de uno una ventaja, niégalo al grupo por defecto y concédelo al rango. Con LuckPerms:

```text
/lp group default permission set exyliashields.browser false
/lp group vip permission set exyliashields.browser true
/lp group vip permission set exyliashields.max_slots.5 true
/lp group vip permission set exyliashields.layers.8 true
/lp group vip permission set exyliashields.crate.multi.7 true
/lp group vip permission set exyliashields.color.* true
/lp group mvp permission set exyliashields.pattern.* true
```

Un jugador al que le falta un nodo de función ve "Tu rango no incluye esto." (`no_access` en `messages.yml`). Restablecer o eliminar un diseño y quitar una capa nunca piden nodo, así que un rango caducado nunca deja a un jugador atrapado con un diseño que no puede quitarse.

<Callout type="warning" title="exyliashields.use quita los diseños">
Con `force_system: true` (el valor por defecto) un jugador sin `exyliashields.use` pierde su diseño cada vez que equipa un escudo. Así un rango caducado deja de mostrar un diseño que ya no le pertenece. Todos tienen el nodo por defecto, así que niégalo solo a un grupo que no deba conservar diseños, o pon `force_system: false` en `config.yml`.
</Callout>
