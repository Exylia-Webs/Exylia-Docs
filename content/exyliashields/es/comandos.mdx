## Comandos

| Comando | Permiso | Qué hace |
|---|---|---|
| `/shields` | `exyliashields.command.shields` | Abre el menú de ranuras. |
| `/shields crate` | `exyliashields.command.shields` | Abre la caja. |
| `/shields reload` | `exyliashields.admin` | Recarga los archivos de este plugin. |

Todo lo demás — el editor, el selector de color, el explorador — se alcanza desde dentro de los menús.

### Subcomandos de admin

Todos necesitan `exyliashields.admin`.

| Subcomando | Qué hace |
|---|---|
| `keys give <player> [amount]` | Añade llaves a su cuenta. Alias `keys add`. |
| `keys take <player> [amount]` | Quita llaves, nunca por debajo de cero. Alias `keys remove`. |
| `keys set <player> <amount>` | Fija cuántas tiene. |
| `keys check <player>` | Dice cuántas tiene. También `keys <player>`. |
| `item key <player> [1-64]` | Da llaves como objetos que se pueden llevar, intercambiar y soltar. |
| `unlocks grant <player> <id>` | Desbloquea un patrón o un color para siempre, como haría una caja. Alias `unlocks give`. |
| `unlocks revoke <player> <id>` | Retira un desbloqueo. Alias `unlocks take`. |
| `unlocks clear <player>` | Retira todos los desbloqueos. |
| `menu crate <player>` | Le abre la caja, sin gastar nada. |
| `crate block add` / `remove` | Ata o desata como bloque de caja el bloque que estás mirando. |
| `crate block list` / `clear` | Lista o desata todos los bloques de caja. |
| `showcase add` | Coloca un showcase donde estás, mirando hacia donde miras. |
| `showcase remove` | Quita el showcase a menos de 5 bloques de ti. |
| `showcase list` / `clear` | Lista o quita todos los showcases. |

Los ids de desbloqueo son `pattern:<id>` y `color:<id>`, y se autocompletan.

<Callout type="note" title="El jugador no tiene que estar conectado">
`keys` y `unlocks` aceptan un nombre o un UUID y escriben directamente en la cuenta del jugador cuando
está desconectado, esté donde esté de la red. `item key` y `menu crate` lo necesitan conectado.
</Callout>

Ver [La caja y la tienda](/docs/exyliashields/caja) y
[Showcases](/docs/exyliashields/comunidad#showcases).

<Callout type="note" title="Abrirlo en una entrada concurrida">
Si la fila del jugador aún no ha llegado de la base de datos, `/shields` la lee y abre el menú cuando
llega, en vez de fallar. Eso es un instante en una entrada concurrida, no un error.
</Callout>

## Permisos

| Permiso | Descripción |
|---|---|
| `exyliashields.command.shields` | Abrir el menú. |
| `exyliashields.admin` | `/shields reload` y todos los subcomandos de admin. |
| `exyliashields.use` | Conservar un diseño en el escudo, con `force_system` activo. |
| `exyliashields.max_slots.<n>` | Esa cantidad de ranuras. Gana el más alto concedido. |
| `exyliashields.pattern.<id>` | Un patrón. |
| `exyliashields.pattern.*` | Todos los patrones. |
| `exyliashields.color.<id>` | Un color. |
| `exyliashields.color.*` | Todos los colores. |

Un patrón o un color que el jugador ganó en la caja o compró en la tienda es suyo sin el nodo.

### Las tres cosas que necesita un jugador

Quien solo puede abrir el menú no puede hacer nada dentro. El acceso que funciona son tres nodos:

```text
/lp group default permission set exyliashields.command.shields true
/lp group default permission set exyliashields.use true
/lp group default permission set exyliashields.max_slots.1 true
```

Y después vendes la paleta y las ranuras:

```text
/lp group vip permission set exyliashields.max_slots.5 true
/lp group vip permission set exyliashields.color.* true
/lp group mvp permission set exyliashields.pattern.* true
```

<Callout type="warning" title="force_system y exyliashields.use">
Con `force_system: true` — el valor por defecto — a un jugador sin `exyliashields.use` se le **retira**
el diseño cada vez que se equipa un escudo. Concédelo junto con las ranuras, o apaga el sistema en
`config.yml` si no quieres los diseños limitados así.
</Callout>

## Qué abarca reload

`/shields reload` relee `config.yml`, `shields.yml`, `messages.yml` y los menús del idioma en uso. No recarga la librería — para
eso está `/exylialib reload` — y no toca lo que los jugadores tengan guardado, que vive en la base de
datos.
