## Comandos

| Comando | Permiso | Qué hace |
|---|---|---|
| `/shields` | `exyliashields.command.shields` | Abre el menú de ranuras, o el selector de escudos 3D cuando `menu.style` es `SPATIAL`. |
| `/shields 3d` | `exyliashields.command.shields` | Abre el [diseñador 3D](/docs/exyliashields/menus-3d) sobre el escudo que lleva, o sobre uno nuevo. |
| `/shields 3d slots` | `exyliashields.command.shields` | Abre el [selector de escudos 3D](/docs/exyliashields/menus-3d). |
| `/shields crate` | `exyliashields.crate` | Abre la caja. |
| `/shieldsadmin` | `exyliashields.admin` | Abre el hub de admin: catálogo, jugadores, showcases, bloques de caja y ajustes. Los [subcomandos de abajo](#shieldsadmin) siguen como atajos. |
| `/shieldsadmin reload` | `exyliashields.admin` | Recarga los archivos de este plugin. |

Todo lo demás — el editor, el selector de color, el explorador — se alcanza desde dentro de los menús.
Borrar o vaciar un diseño pide confirmación antes.

En un cliente anterior a 1.21.4 los menús 3D no se pueden dibujar, así que `/shields 3d` y
`/shields 3d slots` abren los menús de inventario en su lugar.

### /shieldsadmin

Todos los comandos de staff viven bajo `/shieldsadmin`, y todos necesitan `exyliashields.admin`.
`<menu>` es `designer` o `wardrobe` (el selector 3D).

| Subcomando | Qué hace |
|---|---|
| `reload` | Recarga los archivos de este plugin. |
| `settings` | Todos los ajustes, y el catálogo de patrones y colores, en un menú: el mismo que abre el botón de ajustes del hub. |
| `keys give <player> [amount]` | Añade llaves a su cuenta. Alias `keys add`. |
| `keys take <player> [amount]` | Quita llaves, nunca por debajo de cero. Alias `keys remove`. |
| `keys set <player> <amount>` | Fija cuántas tiene. |
| `keys check <player>` | Dice cuántas tiene. También `keys <player>`. |
| `item key <player> [1-64]` | Da llaves como objetos que se pueden llevar, intercambiar y soltar. |
| `unlocks grant <player> <id>` | Desbloquea un patrón o un color para siempre, como haría una caja. Alias `unlocks give`. |
| `unlocks revoke <player> <id>` | Retira un desbloqueo. Alias `unlocks take`. |
| `menu crate <player>` | Le abre la caja, sin gastar nada. |
| `crate block add` / `remove` | Ata o desata como bloque de caja el bloque que estás mirando. |
| `crate block list` / `clear [confirm]` | Lista o desata todos los bloques de caja. `clear` necesita `confirm`. |
| `showcase add` | Coloca un showcase donde estás, mirando hacia donde miras. |
| `showcase remove` | Quita el showcase a menos de 5 bloques de ti. |
| `showcase list` / `clear [confirm]` | Lista o quita todos los showcases. `clear` necesita `confirm`. |

| `spatial place <menu>` | Deja ese menú 3D donde estás, mirando hacia donde miras, para que los jugadores se acerquen. |
| `spatial remove` | Quita el menú 3D colocado a menos de 4 bloques de ti. |
| `spatial edit <menu>` | Te abre el menú para mover sus piezas con la rueda del ratón. |
| `spatial tour <player>` | Vuelve a mostrar a ese jugador el tour guiado de los dos menús 3D, la próxima vez que abra cada uno. |

Los ids de desbloqueo son `pattern:<id>` y `color:<id>`, y se autocompletan.

<Callout type="warning" title="Las formas antiguas con /shields">
Hasta la 1.4, el hub era `/shields admin` y los demás comandos de staff eran subcomandos de `/shields`
(`/shields reload`, `/shields keys give`, `/shields crate block add`…). Desde la 1.5.0 viven bajo
`/shieldsadmin`. Las formas antiguas siguen funcionando por ahora, como alias obsoletos: cada una se
ejecuta y luego le dice al staff la forma nueva (`admin_moved` en `messages.yml`). Actualiza los
scripts, NPCs y menús que las usen.
</Callout>

<Callout type="note" title="El jugador no tiene que estar conectado">
`keys` y `unlocks` aceptan un nombre o un UUID y escriben directamente en la cuenta del jugador cuando
está desconectado, esté donde esté de la red. `item key` y `menu crate` lo necesitan conectado.
</Callout>

<Callout type="note" title="Retirar todos los desbloqueos">
`unlocks clear` ya no existe. Reiniciar a un jugador es cosa de ExyliaLib:
`/exylialib resetplayer <player> ExyliaShields` borra sus ranuras, sus diseños y sus llaves y
desbloqueos de la caja, y `/exylialib wipe` vacía las tablas por tipo. Ver
[los comandos de ExyliaLib](/docs/exylialib/comandos#reiniciar-a-un-jugador).
</Callout>

Ver [La caja y la tienda](/docs/exyliashields/caja),
[Showcases](/docs/exyliashields/comunidad#showcases) y [Menús 3D](/docs/exyliashields/menus-3d).

<Callout type="note" title="Abrirlo en una entrada concurrida">
Si la fila del jugador aún no ha llegado de la base de datos, `/shields` la lee y abre el menú cuando
llega, en vez de fallar. Eso es un instante en una entrada concurrida, no un error.
</Callout>

## Permisos

| Permiso | Por defecto | Descripción |
|---|---|---|
| `exyliashields.command.shields` | todos | `/shields` y los menús 3D: diseñar, comprar y llevar escudos. |
| `exyliashields.browser` | todos | Explorar e importar los diseños de la comunidad. |
| `exyliashields.crate` | todos | Abrir la caja: su botón en la lista de ranuras, `/shields crate` y un bloque de caja atado. |
| `exyliashields.use` | todos | Conservar un diseño en el escudo, con `force_system` activo. |
| `exyliashields.admin` | op | `/shieldsadmin` y todos los subcomandos de staff, incluidas las formas antiguas con `/shields`. |
| `exyliashields.pattern.<id>` | op | Un patrón. |
| `exyliashields.pattern.*` | op | Todos los patrones. |
| `exyliashields.color.<id>` | op | Un color. |
| `exyliashields.color.*` | op | Todos los colores. |
| `exyliashields.max_slots.<n>` | — | Esa cantidad de ranuras. Sin ninguno, una. |
| `exyliashields.layers.<n>` | — | Esa cantidad de capas por diseño. Sin ninguno, `max_layers` de `shields.yml`. |
| `exyliashields.crate.multi.<n>` | — | Esa cantidad de cajas abiertas de una vez. Sin ninguno, `crate.max-at-once`; siete como mucho. |

En los tres nodos numerados gana el más alto que tenga el jugador, así que subir de rango nunca obliga
a revocar el de abajo. Un patrón o un color que el jugador ganó en la caja o compró en la tienda es
suyo sin el nodo.

A un jugador sin un nodo de función se le dice que su rango no lo incluye (`no_access` en
`messages.yml`). Vaciar o borrar un diseño y quitar una capa nunca necesitan uno, así que un rango
caducado nunca deja a un jugador atrapado con un diseño que no puede quitarse.

### Rangos

Todos los jugadores ya tienen las funciones y una ranura. Una ventaja de rango es una función negada al
grupo por defecto y concedida a uno de pago, o un número más alto:

```text
/lp group default permission set exyliashields.browser false
/lp group vip permission set exyliashields.browser true
/lp group vip permission set exyliashields.max_slots.5 true
/lp group vip permission set exyliashields.layers.8 true
/lp group vip permission set exyliashields.crate.multi.7 true
/lp group vip permission set exyliashields.color.* true
/lp group mvp permission set exyliashields.pattern.* true
```

<Callout type="warning" title="force_system y exyliashields.use">
Con `force_system: true` — el valor por defecto — a un jugador sin `exyliashields.use` se le **retira**
el diseño cada vez que se equipa un escudo. Todos lo tienen por defecto; niégalo solo a un grupo que
no deba conservar diseños, o apaga el sistema en `config.yml`.
</Callout>

## Qué abarca reload

`/shieldsadmin reload` relee `config.yml`, `shields.yml`, `messages.yml` y los menús del idioma en uso, y los
menús 3D abiertos se redibujan con el nuevo catálogo, precios y textos. No recarga la librería — para
eso está `/exylialib reload` — y no toca lo que los jugadores tengan guardado, que vive en la base de
datos.
