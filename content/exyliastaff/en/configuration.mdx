Everything is generated in `plugins/ExyliaStaff/` on first boot, with comments. The core keeps
`config.yml`; every module keeps its settings under `modules/<id>/`, so an owner switching a feature
off never scrolls past its settings to find the switch. Text lives apart from settings, under
`lang/<language>/`: see [Languages](/docs/exyliastaff/languages). Colours use palette tokens such as
`{primary}`, `{error}` or `{highlight}`, resolved by the library. A message may open with an effect
tag, `[sound:NAME|volume|pitch]`, that plays to the receiver and never reaches the screen.

`/exyliastaff reload` runs three steps: `configs`, `modules` and `command gate`. The hotbar is
re-read and re-shown, the sidebars rebuilt, the mining ores re-indexed.

<Callout type="note" title="Managed from the web">
A network linked to Exylia Staff Web can hand `config.yml` and the modules' `config.yml` files over to
the web. A managed file says so in its header, and edits on disk are ignored. See
[Exylia Staff Web](/docs/exyliastaff/staff-web#managed-configuration).
</Callout>

### Language

`default` follows the language set in ExyliaLib's `config.yml`; `en`, `es`, `pt` or `fr` set this
plugin alone. See [Languages](/docs/exyliastaff/languages).

### Modules

A module that is off registers nothing: no commands, no listeners, no tables. The ids used by
`/exyliastaff module` are the code names, which do not always match the switch:

| Switch | Id | Page |
|---|---|---|

| `staff-mode` | `staffmode` | [Staff mode](/docs/exyliastaff/staff-mode) |
| `freeze` | `freeze` | [Freeze](/docs/exyliastaff/freeze) |
| `staff-chat`, `global-chat` | `staffchat`, `globalchat` | [Staff chat](/docs/exyliastaff/staff-chat) |
| `inspect` | `inspect` | [Inspect](/docs/exyliastaff/inspect) |
| `teleport` | `teleport` | [Teleport](/docs/exyliastaff/teleport) |

| `reports`, `helpop` | `reports`, `helpop` | [Reports](/docs/exyliastaff/reports), [Helpop](/docs/exyliastaff/helpop) |

| `replays` | `replay` | [Replays](/docs/exyliastaff/replays) |
| `web`, `alts`, `anticheat` | `web`, `alts`, `anticheat` | [Exylia Staff Web](/docs/exyliastaff/staff-web) |

Item revocation is the one module off by default. A module whose dependency is off stays off too:
item revocation needs inventory restore, and alts need web. A module that throws on enable shows as
`failed`, keeps its commands off, and is retried on the next start.

Vanish, freeze, inspect, x-ray vision, reveal and staff mode need PacketEvents and fail without it;
replays need it to be watched. Staff mode looks vanish and the scoreboard up on every call, so
switching either off at runtime simply makes staff mode stop vanishing or stop showing a board.

### Command gate

Commands in `staff-only-commands` may only be run in staff mode. The list is matched against each
command's registered name and every alias, so `tp` also gates `teleport` when that is an alias, and
against the `plugin:name` spellings. Out of staff mode the command is cancelled with
`gate.blocked`, removed from the client's command list and given no tab completions when
`hide-from-tab` is on. Players with `bypass-permission` are never gated. The gate does not check the
command's own permission: it asks only whether the player is in staff mode.

### Disabled commands

`disabled-commands` lists commands this plugin should not register, without the slash, while the rest
of their module keeps working. Each alias counts on its own: listing `top` frees `/top` for another
plugin and keeps `/stafftop`; listing `tp` and `teleport` leaves the vanilla teleport alone while
`/stafftp` still works.

```yaml
disabled-commands:
  - top
  - tp
  - teleport
```

The names are dropped before the server ever sees them, so restart after changing the list: the freed
name then goes to the plugin that also registers it.

## messages.yml

The core's lines, in `lang/<language>/messages.yml`.

```yaml title="plugins/ExyliaStaff/lang/en/messages.yml"
prefix: '{primary}&lSTAFF <#475569>•&r'
no-permission: '[sound:ENTITY_VILLAGER_NO|1.0|1.0]%prefix% {error}You do not have permission to do that.'
player-only: '%prefix% {error}Only a player can run this command.'
player-not-found: '[sound:ENTITY_VILLAGER_NO|1.0|1.0]%prefix% {error}{highlight}%player% {error}is not online.'
world-not-found: '[sound:ENTITY_VILLAGER_NO|1.0|1.0]%prefix% {error}There is no world named {highlight}%world%{error}.'
module-disabled: '[sound:ENTITY_VILLAGER_NO|1.0|1.0]%prefix% {error}The {highlight}%module% {error}module is off on this server.'
reload:
  started: '%prefix% {muted}Reloading…'
  done: '[sound:ENTITY_EXPERIENCE_ORB_PICKUP|1.0|1.2]%prefix% {success}Reloaded {highlight}%steps% {success}steps in {highlight}%ms%ms{success}.'
  failed: '[sound:ENTITY_VILLAGER_NO|1.0|1.0]%prefix% {error}Reload finished with errors. Check the console.'
modules:
  header: '%prefix% {letters}Modules {letters_black}» {highlight}%enabled%{letters_black}/{muted}%total% {letters}running'
  line: ' {muted}❙ %color%%module% {letters_black}» %state%'
  enabled: '[sound:ENTITY_EXPERIENCE_ORB_PICKUP|1.0|1.2]%prefix% {success}Module {highlight}%module% {success}enabled.'
  disabled: '%prefix% {warning}Module {highlight}%module% {warning}disabled.'
  enable-failed: '[sound:ENTITY_VILLAGER_NO|1.0|1.0]%prefix% {error}Module {highlight}%module% {error}could not start: it is already on, it failed, or a dependency is off.'
  disable-failed: '[sound:ENTITY_VILLAGER_NO|1.0|1.0]%prefix% {error}Module {highlight}%module% {error}is not enabled.'
  unknown: '[sound:ENTITY_VILLAGER_NO|1.0|1.0]%prefix% {error}No module named {highlight}%module%{error}.'
gate:
  blocked: '[sound:ENTITY_VILLAGER_NO|1.0|1.0]%prefix% {error}Enable staff mode before using {highlight}/%command%{error}.'
redis:
  server-id: '%prefix% {letters}Server {letters_black}» {highlight}%server%'
  active: ' {muted}❙ {letters}Redis {letters_black}» {success}connected'
  inactive: ' {muted}❙ {letters}Redis {letters_black}» {muted}off, local bus only'
  stats: ' {muted}❙ {letters_black}%stats%'
```

`%prefix%` expands to `prefix` in every message of the plugin, the modules' included. `no-permission`
and `player-only` are what the command framework sends; `player-not-found` is sent for any player
argument that does not resolve, and `world-not-found` for a world argument. The convention across every file: a refusal sounds
`ENTITY_VILLAGER_NO`, a success `ENTITY_EXPERIENCE_ORB_PICKUP`, attention `BLOCK_NOTE_BLOCK_PLING`.

## Module files

Each module page shows its own `config.yml` and lists its message keys.

| Where | Holds |
|---|---|
| `modules/<id>/config.yml` | The module's settings. Every module but the scoreboard and inspect has one. |
| `lang/<language>/modules/<id>/messages.yml` | The module's lines, titles, action bars and sounds. |
| `lang/<language>/modules/scoreboard/config.yml` | The sidebars, which are text. |
| `lang/<language>/modules/inspect/config.yml` | The window titles, which are text. |
| `lang/<language>/modules/staffmode/hotbar.yml` | The staff hotbar. |
| `lang/<language>/modules/replay/hotbar.yml` | The replay controls. |

Effect blocks such as `effects.enter`, `alert` or `reminder` are library effects with the sections
`title`, `action-bar`, `boss-bar`, `sound`, `particle` and `firework`. A section left empty is not
written to the file; add it to use it. Their keys are on the
[library's effects page](/docs/exylialib/effects).

## Sidebars

`lang/<language>/modules/scoreboard/config.yml` holds three boards: `staff-mode`, shown on duty; `frozen`, shown to
a frozen player; `freezing`, shown to the staff member holding one. Each has `enabled`, a `title`
list that animates when it has several entries, up to fifteen `lines`, and `update.interval` in ticks.
Boards stack: a freeze shown over the staff board hides it and gives it back on release.
`{server-ip}` on the last line is the address set once in ExyliaLib's `colors.yml`.

## Menus

Every staff screen is a YAML file under `lang/<language>/menus/<module>/`: `reports/` with
`reasons`, `list`, `player` and `history`; `helpop/list`; `punishments/` with `categories`,
`reasons`, `confirm` and `history`; `mining/` with `suspicious` and `player`; `restore/` with
`servers`, `list`, `backup`, `parts` and `log`; `replay/` with `list` and `players`;
`revoke/quarantine`; `stafflog/` with `sessions`, `summary` and `top`. Their format is the
[library's menu format](/docs/exylialib/menus).

They are yours to restyle. A release only adds what your files are missing; a default that changed on
something you never edited waits in `/exylialib updates`, where you apply it or keep yours.

## database.yml

Engine and Redis, written by ExyliaLib. H2 by default. See [Installation](/docs/exyliastaff/installation#database)
for the engines and the tables, and the [library's database page](/docs/exylialib/database) for every key,
`redis.server-id` among them, which is the name every alert and every staff chat line shows.
