## Before you start

ExyliaStaff needs two plugins in `plugins/` **before** the first boot.

| Plugin | What for |
|---|---|
| `ExyliaLib` | Configuration, menus, database, placeholders, effects, sidebars, inventory snapshots, chat rules, Redis channels. |
| `packetevents` | Vanish, freeze, the silent inventory mirrors, the staff hotbar and x-ray vision are all packet-level. Declared as a hard dependency; without it the plugin does not load. |

Optional:

- **PlaceholderAPI** to use the plugin's placeholders outside it.
- **LuckPerms**, or any permission plugin, for the `exyliastaff.vanish.level.<n>` rank nodes.
- **LiteBans** or **AdvancedBan**. The punishments module runs commands; the defaults are the
  command names both plugins use. Nothing else of theirs is read.
- **Redis**, configured in ExyliaLib's `database.yml`, for the cross-server parts: staff chat,
  network chat, alerts, the staff list and vanish state on the next server. Without Redis every channel
  still delivers on the local server.

<Callout type="note" title="ExyliaLib is listed as soft">
`plugin.yml` names ExyliaLib under `softdepend` on purpose: the loader that installs ExyliaLib is the
one that has to load first for that install to happen. The plugin still needs it to run.
</Callout>

## Installing

<Steps>
  <Step title="Drop in the jars">
    Copy `ExyliaStaff.jar` and its dependencies into the server's `plugins/` folder.
  </Step>
  <Step title="Start the server">
    The first boot generates `config.yml`, one folder per module under `modules/`, the menus and
    messages under `lang/`, and the database tables.
  </Step>
  <Step title="Check the console">
    You should see one `Module enabled: <id>` line per module that is on. A module that threw on
    enable is reported there with its reason and shows as `failed` in `/exyliastaff modules`.
  </Step>
  <Step title="Grant the staff node">
    `exyliastaff.staff` is what makes a player staff for every module. Without it nobody sees vanished
    players, receives alerts or can enter staff mode. See [First steps](/docs/exyliastaff/first-steps).
  </Step>
</Steps>

## Generated files

All of them live in `plugins/ExyliaStaff/`.

| File | Contents |
|---|---|
| `config.yml` | The language, the module switches, the command gate and `disabled-commands`. |
| `modules/<id>/config.yml` | One per module, its settings only. |
| `lang/<language>/messages.yml` | The core's lines: prefix, no-permission, reload, module list, gate, Redis. |
| `lang/<language>/modules/<id>/messages.yml` | One per module that sends messages. |
| `lang/<language>/modules/staffmode/hotbar.yml` | The staff hotbar. |
| `lang/<language>/modules/scoreboard/config.yml` | The three sidebars: staff mode, frozen, freezing. |
| `lang/<language>/menus/<id>/` | The staff screens of each module. |
| `web/managed.json` | The last configuration Exylia Staff Web sent, when the network is linked and the web manages files. |
| `database.yml` | Database engine and Redis, written by ExyliaLib. |

Every file under `lang/` is yours to edit, in every language: see
[Languages](/docs/exyliastaff/languages).

## Database

By default the plugin uses **H2**: a file inside the plugin folder, with no server, no installation
and no maintenance. To share sessions, reports, punishments and the log across servers, point every
server at the same database:

```yaml title="plugins/ExyliaStaff/database.yml"
database:
  type: mysql
  mysql:
    host: 127.0.0.1
    port: 3306
    database: minecraft
    username: root
    password: ""
```

Supported engines: `h2`, `mysql`, `mariadb`, `postgresql` and `mongodb`. The file is ExyliaLib's; its
full reference, including the `redis` block, is in the [library's database page](/docs/exylialib/database).

The tables: `staff_prefs`, `staff_sessions`, `staff_vanish`, `staff_freeze`, `staff_reports`,
`staff_helpop`, `staff_mining`, `staff_punishments`, `staff_log_sessions`, `staff_log_daily`,
`staff_audit`, `staff_notes`, `staff_restores`, `staff_restore_queue`, `staff_restore_log`,
`staff_replays`, `staff_replay_data`, `staff_replay_chunks`, `staff_revoked_items`,
`staff_revoked_hits` and `staff_alts`, plus `web_link`, `web_lease`, `web_outbox` and
`web_commands_done` for Exylia Staff Web. Inventory snapshots for staff mode and freeze use the
library's `exylia_snapshots`.

The link to Exylia Staff Web, replays and the restore queue are read across the network from this
database, which is one more reason to share it between every server.

## Updating

Replace the jar and restart. Your edits are kept: a release only adds the keys and files you are
missing, and a default that changed on something you never edited waits in `/exylialib updates`.

<Callout type="note" title="Updating from 1.3 or older">
The first start of 1.4.0 moves your `messages.yml`, every `modules/<id>/messages.yml`, the sidebars,
the hotbar and `menus/` into `lang/custom/` and sets `language: custom`, so nothing on screen changes.
Switch to `en`, `es`, `pt` or `fr` for the shipped files. See [Languages](/docs/exyliastaff/languages).
</Callout>
