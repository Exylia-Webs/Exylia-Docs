Three jobs live here. The admin hub, `/staffadmin`, switches modules and changes the settings worth tuning without opening a file. The audit records what staff do: every action the modules announce, every command a staff member runs and the items they move on duty. Notes and strikes are the written record you keep on a staff member.

## Before you start

- Opening the hub, the module list and the settings needs `exyliastaff.admin`. Reading notes needs `exyliastaff.admin.panel`, writing them `exyliastaff.admin.notes`. All op by default.
- The audit and notes belong to the `staffadmin` module (`modules.staff-admin`). Turning it off stops the record, which is how an owner who does not want conduct kept says so once.
- The team reads the audit and notes with filters on [Exylia Staff Web](/docs/exyliastaff/staff-web); in game, `/notes` is the quick look before acting on a report.

## Steps

<Steps>
  <Step title="Open the admin hub">
    Run `/staffadmin` in game. The top card shows the open reports, the staff in staff mode and the frozen players on this server. Below it are three buttons: **Modules**, **Settings** and **Reload**. From the console, `/staffadmin` lists the modules in chat instead.
  </Step>
  <Step title="Switch a module">
    Click **Modules**. Every module is one card with its state now (running, stopped, failed) and its switch at startup. Click a stopped one to start it, a running one to stop it. The switch is written to `config.yml`, so it stays after a restart. A module that [Exylia Staff Web](/docs/exyliastaff/staff-web#managed-configuration) manages shows as locked. The same thing from chat: `/staffadmin module enable <module>` and `/staffadmin module disable <module>`.
  </Step>
  <Step title="Change a setting">
    Click **Settings**. One card per theme opens a page of the settings people tune most: **Modules** (every switch, grouped by theme), Vanish, Staff mode, Freeze, Reports, Helpop, Punishments, Replays, Command filter, AFK and Mining alerts. On a card, left click moves a switch or choice to its next value and right click to the previous one, shift multiplies a number by ten, **Q** (drop) lets you type an exact value, and shift right click puts the default back. Every change is saved and applied at once.
  </Step>
  <Step title="Write a note">
    Run `/notes add <player> <text>` for a note or `/notes strike <player> <text>` for a strike. Run `/notes <player>` to read the file: each line has its id, author, date and text. `/notes delete <id>` removes one. The author's name and the date are kept, also when the console writes it.
  </Step>
  <Step title="Read the audit">
    The audit is on [Exylia Staff Web](/docs/exyliastaff/staff-web), where you can filter by staff member, flag and date. Nothing needs switching on: it records from the first start.
  </Step>
</Steps>

## Check that it works

Run `/notes add <some staff member> test`, then `/notes <that member>`: one line with your name and today's date. Delete it with `/notes delete <id>`. Then open `/staffadmin`, click **Modules** and confirm every module shows a state.

## Going further

### What the audit records

Three kinds of rows land in the audit:

- **Actions** the modules announce: a freeze, an inspection, a resolved report, a punishment.
- **Commands** run by anyone holding `exyliastaff.staff`, with the full line, while `log-commands` is on and the command is not in `ignored-commands`.
- **Items** dropped, picked up or taken out of a container by somebody in staff mode, while `log-items` is on.

Rows older than `keep-days` (90) are deleted once a day; `0` keeps everything. With the network linked every row is also sent to the web. Two-factor commands are stored without their arguments, so no [code](/docs/exyliastaff/two-factor) or key is ever kept.

### Flags that make a row easy to find

A command row is flagged by its first word. A flag is not an accusation, only the reason the row is easy to find again.

| Flag | When |
|---|---|
| `self_give` | A `give-commands` command whose item went to the sender, to `@s`, or to no player name. |
| `give` | Any other `give-commands` command. |
| `creative` | A `gamemode-commands` command that sets creative: `gmc`, or an argument of `creative`, `c` or `1`. |
| `revoke` | A `revoke-commands` command. |
| `item` | An item row. |
| `sensitive` | A `sensitive-commands` command. |

Edit the lists in `modules/staffadmin/config.yml` to match the commands your server really uses, then run `/staffadmin reload`.

### Clear a player's data

`/staffadmin history clear <player>`, `/staffadmin reports clear <player>` and `/staffadmin notes clear <player>` empty one kind of record for one player and ask for `confirm` first. See [Commands](/docs/exyliastaff/commands#admin-hub). Notes are never purged on their own.

<Details title="Technical details">

```yaml title="plugins/ExyliaStaff/modules/staffadmin/config.yml"
keep-days: 90
log-commands: true
log-items: true
ignored-commands: [staffadmin, msg, r, tell, helpop, report, list, spawn]
give-commands: [give, i, item]
gamemode-commands: [gamemode, gm, gmc]
revoke-commands: [unban, pardon, unmute, untempban, unpunish, revoke]
sensitive-commands: [op, deop, ban, tempban, mute, kick, clear, setblock, fill, effect, enchant]
```

| Key | Default | What it does |
|---|---|---|
| `keep-days` | `90` | Audit rows older than this are deleted once a day. `0` keeps everything. |
| `log-commands` | `true` | Record every command a staff member runs. Without it the audit only holds what the modules announce. |
| `log-items` | `true` | Record items dropped, picked up or taken from a container on duty. |
| `ignored-commands` | see above | Commands never recorded. |
| `give-commands`, `gamemode-commands`, `revoke-commands`, `sensitive-commands` | see above | The lists the flags read. |

Tables: `staff_audit` and `staff_notes`. Messages: `lang/<language>/modules/staffadmin/messages.yml` (`never-played`, `notes-header`, `note-line` with `%id%`, `%author%`, `%date%`, `%text%` and `%kind%`, `notes-empty`, `notes-usage`, `note-added`, `note-removed`, `note-not-found`). The hub and module list are `lang/<language>/menus/admin/`, rewritten from the jar on every start and reload; edit the settings pages through the hub, not the files.
