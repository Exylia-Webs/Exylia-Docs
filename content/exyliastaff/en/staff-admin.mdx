The audit records what staff do: every action the modules announce, every command a staff member
runs, and the items they move while on duty. Admins keep notes and strikes on a staff member's file.
The team reads both on [Exylia Staff Web](/docs/exyliastaff/staff-web), which shows the activity, the
audit and the notes with filters a menu could not offer; in game, `/notes` is the quick look before
acting on a report.

Module id `staffadmin`, switch `modules.staff-admin`, files under `modules/staffadmin/`. Turning it
off stops the record: an owner who does not want a staff member's conduct kept says so once.

<Callout type="note" title="The in-game panel moved to the web">
`/staffadmin` and its screens — the team board, the audit feed, coverage and the module switches — are
gone since 1.4.0. The team board, audit and notes are on the web; modules are switched with
`/exyliastaff module` or from the web.
</Callout>

## Notes

| Command | Permission | What it does |
|---|---|---|
| `/notes <player>` | `exyliastaff.admin.panel` | Every note and strike on a staff member's file, with its id, author and date. `/staffnotes` is an alias. |
| `/notes add <player> <text>` | `exyliastaff.admin.notes` | Writes a note. |
| `/notes strike <player> <text>` | `exyliastaff.admin.notes` | Writes a strike. |
| `/notes delete <id>` | `exyliastaff.admin.notes` | Removes one. |

Notes are kept with the author's name and the date, also from the console, and are never purged.

## The audit

Three kinds of rows land in `staff_audit`:

- **Actions** the modules announce: a freeze, an inspection, a resolved report, a punishment.
- **Commands** run by anyone holding `exyliastaff.staff`, with the full line, when `log-commands` is
  on and the command is not in `ignored-commands`.
- **Items** dropped, picked up or taken out of a container by somebody in staff mode, when
  `log-items` is on.

Rows older than `keep-days` are deleted once a day. Every row is also sent to the web when the
network is linked.

## Flags

A command row is flagged by its first word. A flag is not an accusation; it is the reason a row is easy
to find again.

| Flag | When |
|---|---|
| `self_give` | A `give-commands` command whose item went to the sender, or to `@s`, or to no player name |
| `give` | Any other `give-commands` command |
| `creative` | A `gamemode-commands` command that sets creative: `gmc`, or an argument of `creative`, `c` or `1` |
| `revoke` | A `revoke-commands` command |
| `item` | An item row |
| `sensitive` | A `sensitive-commands` command |

## Configuration

```yaml title="plugins/ExyliaStaff/modules/staffadmin/config.yml"
keep-days: 90
log-commands: true
log-items: true
ignored-commands:
  - es
  - exyliastaff
  - msg
  - r
  - tell
  - helpop
  - report
  - list
  - spawn
give-commands:
  - give
  - i
  - item
gamemode-commands:
  - gamemode
  - gm
  - gmc
revoke-commands:
  - unban
  - pardon
  - unmute
  - untempban
  - unpunish
  - revoke
sensitive-commands:
  - op
  - deop
  - ban
  - tempban
  - mute
  - kick
  - clear
  - setblock
  - fill
  - effect
  - enchant
```

| Key | Default | What it does |
|---|---|---|
| `keep-days` | `90` | Audit rows older than this are deleted once a day. `0` keeps everything. |
| `log-commands` | `true` | Record every command a staff member runs. Without it the audit only holds what the modules announce. |
| `log-items` | `true` | Record items a staff member drops, picks up or takes out of a container while on duty. |
| `ignored-commands` | | Commands never recorded: the ones staff run constantly and that prove nothing. |
| `give-commands`, `gamemode-commands`, `revoke-commands`, `sensitive-commands` | | The lists the flags read. |

## Messages

`lang/<language>/modules/staffadmin/messages.yml`: `never-played` with `%player%`; `notes-header` with
`%target%` and `%count%`; `note-line` with `%id%`, `%author%`, `%date%`, `%text%` and `%kind%`, which
reads `kind-note` or `kind-strike`; `notes-empty`, `notes-usage`, `note-added` with `%target%`,
`note-removed` and `note-not-found` with `%id%`.

## Storage

`staff_audit` for the rows, `staff_notes` for the notes.
