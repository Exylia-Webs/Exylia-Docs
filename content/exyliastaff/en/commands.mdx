Commands belong to modules. A module that is off has none of its commands on the server: `/freeze`
with freeze disabled is an unknown command, not a refusal. Toggling a module with `/staffadmin module`
re-registers the set and refreshes every client's command list. A single command or alias can be left
unregistered with [`disabled-commands`](/docs/exyliastaff/configuration#disabled-commands).

`<player>` is required, `[player]` optional. Most commands take anybody the network knows, online on
any server or not, and suggest every name connected to the proxy. The ones that act on somebody in
front of you — freezing them, reporting them, switching their vanish, staff mode or x-ray — need them
online on this server, and say so with "is not online".

## Core

| Command | Permission | What it does |
|---|---|---|
| `/staffadmin` | `exyliastaff.admin` | A player gets the [admin hub](#admin-hub); the console gets the module list. Replaces `/exyliastaff` and `/es` since 1.5.0. |
| `/staffadmin settings` | `exyliastaff.admin` | The plugin's settings in a menu. See [Configuration](/docs/exyliastaff/configuration#in-game-settings). |
| `/staffadmin reload` | `exyliastaff.admin.reload` | Reloads every file, the modules and the command gate. |
| `/staffadmin modules` | `exyliastaff.admin.modules` | The same list. |
| `/staffadmin module enable <id>` | `exyliastaff.admin.modules` | Switches a module on, and its commands with it, and writes the switch to `config.yml` so a restart keeps it. |
| `/staffadmin module disable <id>` | `exyliastaff.admin.modules` | Off, together with every module that depends on it, and written to `config.yml` the same way. |
| `/staffadmin redis` | `exyliastaff.admin` | This server's id, whether Redis is connected, and its stats. |
| `/staffadmin info` | `exyliastaff.admin.info` | The plugin version, this server's id, Redis, the web link and how many modules are on. |
| `/staffadmin history clear <player> [reason-id] [confirm]` | `exyliastaff.admin.history.clear` | Deletes a player's punishment history, or only one reason's. Nothing is lifted. |
| `/staffadmin reports clear <player> [confirm]` | `exyliastaff.admin.reports.clear` | Deletes every report against a player. |
| `/staffadmin notes clear <player> [confirm]` | `exyliastaff.admin.notes.clear` | Deletes every note and strike on a staff member's file. |
| `/staffadmin import <plugin>` | `exyliastaff.admin` | Imports a ban plugin's history once. See [Punishments](/docs/exyliastaff/punishments#importing-a-ban-plugin). |
| `/staffadmin weblink` | `exyliastaff.web.link` | Links the network to [Exylia Staff Web](/docs/exyliastaff/staff-web). |

The root itself needs `exyliastaff.admin`. Everything but `settings` works from the console. A clear
typed without `confirm` only says what it would delete and the command to go ahead. Every clear is
written to the [audit](/docs/exyliastaff/staff-admin) when that module is on; a module that is off is
left alone.

On a network whose modules are managed by [Exylia Staff Web](/docs/exyliastaff/staff-web), a module
switched in game is not written to `config.yml`: the command says so, because the web's switches are
written over the file on every start. Switch it on the web too.

### Admin hub

`/staffadmin` typed by a player opens a small hub: open reports, staff in staff mode and frozen players
on this server at the top, then **Modules**, **Settings** and **Reload**. **Modules** lists every module
with its state now and its switch at startup; a click starts or stops it through the same path as
`/staffadmin module enable|disable`. A module the web manages is shown locked. **Settings** opens the
same screens as `/staffadmin settings`. The hub's files under `lang/<language>/menus/admin/` are the
plugin's and are rewritten on every start and reload.

### Wiping a player's data

`/staffadmin wipe` is gone since 1.8.0. Resetting a player, or emptying the plugin's tables, is done
with ExyliaLib's commands, which cover every table of the plugin and write a dump before deleting
anything:

```
/exylialib resetplayer <player> ExyliaStaff @account @history
/exylialib wipe ExyliaStaff <table|*>
```

Punishments, notes, two-factor, vanish and preferences are `@account` data; reports, help requests,
replays, the audit and the staff log are `@history`; mining records, staff sessions and backups are
`@progress`. A plain `resetplayer` only takes the `@progress`, `@world` and `@cache` kinds, so name
`@account` and `@history` to remove what the old wipe removed. Both commands ask for a typed code
first. See the [library's commands](/docs/exylialib/commands).

## Staff mode

| Command | Permission | What it does |
|---|---|---|
| `/staff` | `exyliastaff.staffmode` | Toggles your own staff mode. `/staffmode` and `/mod` are aliases. |
| `/staff toggle [player]`, `/staff on [player]`, `/staff off [player]` | `exyliastaff.staffmode` | Toggles or sets it, for you or somebody else. |
| `/staff spectator` | `exyliastaff.staffmode` | Spectator view. `/staff spec` is the same. |

Another player needs `exyliastaff.staffmode.others`.
