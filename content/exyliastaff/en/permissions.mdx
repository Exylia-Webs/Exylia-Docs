Nodes follow `exyliastaff.<module>.<action>`, and every one of them is declared in `plugin.yml`.
Staff nodes default to `op`: give them to your staff groups through your permission plugin. The
exceptions:

- `exyliastaff.report`, `exyliastaff.helpop` and `exyliastaff.savereplay` default to `true`: every
  player has them, and a server makes one a rank perk by setting it to `false` on the default group.
- `exyliastaff.punish.permanent`, `exyliastaff.punish.edit` and `exyliastaff.punish.revoke` default
  to `true`: they only narrow `exyliastaff.punish` when set to `false`. See
  [Punishment limits](#punishment-limits).
- `exyliastaff.2fa.exempt` and `exyliastaff.replay.rules.exempt` default to `false`, so not even an
  operator holds them unless granted.

## The one that matters

`exyliastaff.staff` marks a player as staff for every module. It decides who is listed in
`/stafflist`, whose commands the audit records, who may enter staff mode, who is skipped by the random
teleport, who cannot be reported, and, with `exyliastaff.vanish.see`, who sees vanished players.
Losing it while online ends a staff session within five seconds.

## Core

| Permission | What it gates |
|---|---|
| `exyliastaff.admin` | The `/staffadmin` root and its admin hub, `/staffadmin settings`, `/staffadmin redis` and `/staffadmin import`. |
| `exyliastaff.admin.reload` | `/staffadmin reload`, and **Reload** in the hub. |
| `exyliastaff.admin.modules` | Listing and switching modules, by command or in the hub. |
| `exyliastaff.admin.info` | `/staffadmin info`. |
| `exyliastaff.admin.history.clear` | `/staffadmin history clear`. |
| `exyliastaff.admin.reports.clear` | `/staffadmin reports clear`. |
| `exyliastaff.admin.notes.clear` | `/staffadmin notes clear`. |
| `exyliastaff.gate.bypass` | Never gated by the command gate. Configurable in `config.yml`. |

`/staffadmin wipe` and its `exyliastaff.admin.wipe` node were removed in 1.8.0: wiping a player's data
is `/exylialib resetplayer`, gated by ExyliaLib's own nodes. See
[Commands](/docs/exyliastaff/commands#wiping-a-players-data).

## Punishment limits

`exyliastaff.punish` lets a staff member punish. These nodes narrow it, and they work the other way
round: each is allowed unless it is explicitly set to `false`, so a server that never sets them sees
no change. A punishment one of them blocks is not refused: it becomes a request a superior approves.
See [Punishments](/docs/exyliastaff/punishments#approvals).

| Permission | Blocks when set to false |
|---|---|
| `exyliastaff.punish.type.<type>` | A step of that type: `ban`, `tempban`, `mute`, `tempmute`, `kick`, `warn` or `ipban`. |
| `exyliastaff.punish.permanent` | A step that never expires: `BAN`, `MUTE`, `IPBAN`, or a temporary one lasting `perm`. |
| `exyliastaff.punish.category.<category-id>` | Every reason of that category. |
| `exyliastaff.punish.reason.<reason-id>` | That reason. |
| `exyliastaff.punish.edit` | Editing a punishment from the web; with `permanent` also false, making one permanent. |
| `exyliastaff.punish.revoke` | Revoking a punishment from the web. |

## Two-factor

| Permission | What it gates |
|---|---|
| `exyliastaff.staff` | Setting [two-factor](/docs/exyliastaff/two-factor) up with `/2fa`. `/2fa` itself needs no node, so a locked staff member can always enter their code. |
| `exyliastaff.2fa.reset` | `/2fa reset <player>`. |
| `exyliastaff.2fa.exempt` | Never forced to set two-factor up when `require-for-staff` is on. Default `false`. |

## Exylia Staff Web

| Permission | What it gates |
|---|---|
| `exyliastaff.web.link` | `/staffadmin weblink`, `/staff web status` and `unlink`, the reminder on join while the network is not linked, and the warning when the web refuses this plugin version. |
| `exyliastaff.alts` | The alert when an account sharing an address with a banned one joins. |
| `exyliastaff.anticheat` | The alert when a player sets off a burst of anticheat alerts. |

`/staff web`, the account link, only needs `exyliastaff.staff`. `/appeal` needs nothing: the players
who use it are ordinary players.

<Callout type="warning" title="The checks live on the commands">
The menus and the hotbar do not repeat every check. The reset button in a mining record does not ask
for `exyliastaff.mining.reset`, the hotbar's ender chest click does not ask for
`exyliastaff.inspect.enderchest`, and the report and helpop screens only require the permission that
opened them. Grant a group the module's manage node or keep them out of it; do not count on a
sub-node alone to hold a button back.
</Callout>

## Hotbar items

An entry in `lang/<language>/modules/staffmode/hotbar.yml` may carry its own `permission:`; the item only shows to
players holding it. The bundled file sets none.
