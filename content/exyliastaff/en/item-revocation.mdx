When a hacker kills somebody and hands the drops to friends, restoring the victim puts a second copy of every item into the world. Item revocation closes that hole: the victim gets clean copies, and the marked ones still out there are taken away wherever they turn up.

<Callout type="warning" title="Off by default">
It changes items on death and takes items from players, so `modules.item-revocation` ships `false`. Turn it on only after reading this page, and consider running `mode: AUDIT` for a few days to see what it would catch before it acts.
</Callout>

## Before you start

- [Inventory restore](/docs/exyliastaff/inventory-restore) must be on: deaths are copied and handed back there.
- Turn on `modules.item-revocation` in `plugins/ExyliaStaff/config.yml`. Settings are in `plugins/ExyliaStaff/modules/revoke/config.yml`.
- Staff who handle the quarantine need `exyliastaff.revoke`. Staff who get alerts need `exyliastaff.revoke.alerts`.

## Steps

<Steps>
  <Step title="Let deaths be marked">
    With the module on, an item that drops on a death gets an id of its own before the death backup is taken. Nothing else to do.
  </Step>
  <Step title="Restore the victim">
    Run `/invrestore <victim>`, open the death backup and click **Backup ▸ Restore**. On a death that dropped marked items, the restore screen shows the switch **Revoke ▸ Revoke circulating copies** (or **Leave circulating copies**). It starts ticked when `default-revoke` is `true`, the default.
  </Step>
  <Step title="Confirm">
    Click **Restore ▸ Confirm**. The victim receives copies with no mark, every marked copy still in circulation is revoked, and you are told how many.
  </Step>
  <Step title="Handle what turns up">
    When somebody holds a revoked item, staff with `exyliastaff.revoke.alerts` are told on every server: who, from whose death, on which server and what was done; a click teleports to the holder. Run `/revokeditems` (alias `/revoked`) to open the **REVOKED ITEMS** screen.
  </Step>
</Steps>

## Check that it works

Set `mode: AUDIT` first. Kill a test account holding a sword, restore it with the **Revoke** switch ticked, then pick up the dropped sword with a second account. Staff with alerts get the message, and `/revokeditems` lists it as **Seen, left with them**. Switch to `QUARANTINE` when you trust it.

## Going further

### What happens when a revoked item is found

A revoked item is noticed when it is picked up, moved, held, worn, swung, used or dropped, when the container it hides in is opened, and when its holder logs in (ender chest included).

| `mode` | What happens |
|---|---|
| `QUARANTINE` (default) | The item is taken into quarantine. With `notify-holder` on, the holder is told why and to open a ticket if they got it fairly. |
| `AUDIT` | The item stays where it is. Staff are told and it is written down. |

The same player holding the same item alerts again only after `alert-cooldown-seconds` (300).

### The quarantine screen

`/revokeditems` needs `exyliastaff.revoke`. Rows and clicks:

| Row | Clicks |
|---|---|
| In quarantine | Left: hand it back to whoever had it (they must be on this server). Right: take it yourself. Q (drop key): throw it away for good. |
| Seen in `AUDIT` mode | Left: go to the player still holding it, on their server if needed. |
| Already handled | Nothing: who handled it and how. |

The **Showing** button at the bottom switches between **In quarantine** and **Everything**.

### Which items are marked

Only items that cannot stack: swords, armour, tools, shulker boxes, totems. An id on a diamond would stop it stacking with every other diamond and break shops, hoppers and inventories. `excluded-materials` leaves more out. A shulker box or a bundle is walked, so what is inside is marked too. An item that dies twice keeps its first id.

What comes out of a crafting grid, anvil, smithing table, grindstone, crafter or villager trade inherits every id that went in, so revoking a sword also reaches the netherite one it was upgraded into. With `villager-trades` on, a marked item also pays a trade that asks for the same item without the mark.

<Details title="Configuration and storage">
```yaml title="plugins/ExyliaStaff/modules/revoke/config.yml"
mode: QUARANTINE
default-revoke: true
excluded-materials: []
alert-cooldown-seconds: 300
notify-holder: true
villager-trades: true
history-keep-days: 90
```

| Key | Default | What it does |
|---|---|---|
| `mode` | `QUARANTINE` | `QUARANTINE` or `AUDIT`. Anything else quarantines. |
| `default-revoke` | `true` | The restore screen's switch starts ticked for a death. |
| `excluded-materials` | `[]` | Materials that never get an id. Unknown names are skipped. |
| `alert-cooldown-seconds` | `300` | Before staff hear again about the same player holding the same item. |
| `notify-holder` | `true` | Tell the player why an item was taken. |
| `villager-trades` | `true` | Let a marked item pay a trade that asks for it without the mark. |
| `history-keep-days` | `90` | Days alerts and handled quarantine entries are kept. `0` keeps everything. |

Items waiting in quarantine and the list of revoked ids are never purged: a sword hidden in a chest for a year is still the same duplicate. Tables: `staff_revoked_items` for the revoked ids, `staff_revoked_hits` for every time one turned up.

Messages are in `lang/<language>/modules/revoke/messages.yml`: `revoked`, `holder-taken`, `alert` (with `%player%`, `%item%`, `%owner%`, `%server%`, `%action%`), `action-quarantined`, `action-seen`, the quarantine button lines (`returned`, `taken`, `discarded`, `follow-started`, and others), `scope-held`, `scope-all`, and the restore switch (`toggle-on`, `toggle-off`, `toggle-note-on`, `toggle-note-off`). See [messages and languages](/docs/exylialib/messages-and-languages).
</Details>
