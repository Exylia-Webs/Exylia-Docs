---
title: "Languages"
description: "Menus, messages, sidebars and hotbars in English, Spanish, Portuguese or French, and where each translated file lives."
---

Every line a player or a staff member reads ships in four languages: English (`en`), Spanish (`es`),
Portuguese (`pt`) and French (`fr`). Each language is a folder of complete files under
`plugins/ExyliaStaff/lang/`, and you can edit any of them.

## Choosing one

`language` at the top of `config.yml` picks the folder:

```yaml title="plugins/ExyliaStaff/config.yml"
language: default
```

| Value | Language |
|---|---|
| `default` | Follows the language set in ExyliaLib's `config.yml`, so one line changes every Exylia plugin. English when that names none. What a fresh install writes. |
| `en`, `es`, `pt`, `fr` | This plugin alone, whatever the library says. |
| `custom` | The files of a server that ran the plugin before languages existed. See below. |

Any other code works too: it starts as a copy of English, yours to rewrite.

Restart after changing it. `/exyliastaff reload` reads the messages in the new language, but menus and
hotbars are read when their module starts.

## What is translated

| File | Contents |
|---|---|
| `lang/<language>/messages.yml` | The core's lines: prefix, no permission, reload, modules, gate, Redis. |
| `lang/<language>/modules/<id>/messages.yml` | Each module's lines, including the titles, action bars and sounds that used to sit in its `config.yml`. |
| `lang/<language>/modules/scoreboard/config.yml` | The three sidebars. |
| `lang/<language>/modules/inspect/config.yml` | The inventory, ender chest and container window titles. |
| `lang/<language>/modules/staffmode/hotbar.yml` | The staff hotbar. |
| `lang/<language>/modules/replay/hotbar.yml` | The replay controls. |
| `lang/<language>/menus/<id>/` | Every staff screen. |

Everything else — `config.yml` and each module's `modules/<id>/config.yml` — holds behaviour, not
text, and is the same whatever the language.

English is the base every language is laid over: a key or a file not translated yet still arrives,
in English, so a new release never leaves a hole on screen.

## Your edits are kept

A release only adds what your files are missing; a line you edited is never touched. In the menus and
the hotbars, a default that changed on something you never edited waits in `/exylialib updates`,
where you apply it or keep yours, so a tool added in a release reaches your hotbar without undoing
your layout.

## Coming from an older version

The first start of a server that already had the plugin moves its files into `lang/custom/` —
`messages.yml`, every `modules/<id>/messages.yml`, the sidebars, the hotbar and `menus/` — and writes
`language: custom` into `config.yml`. Nothing you edited is lost, and nothing changes on screen.
Switch to `en`, `es`, `pt` or `fr` when you want the shipped files instead.

Some text moved out of the modules' `config.yml` into their messages in the same release, and is
carried over by the same migration:

| Module | Moved to `messages.yml` |
|---|---|
| `staffmode` | `effects` |
| `vanish` | `effects` |
| `freeze` | `reminder`, and `look.helmet-name` as `helmet-name` |
| `staffchat` | `format` |
| `globalchat` | `format` |
| `actionbar` | `staff-mode`, `vanish`, `icon-on`, `icon-off` |
