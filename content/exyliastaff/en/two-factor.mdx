A staff account is worth stealing. Two-factor asks a staff member for the six-digit code of an authenticator app (Google Authenticator, Authy, Aegis, 1Password and the like) when they join, so a leaked password alone does not get anybody into staff mode. With ExyliaLink, a linked staff member can also approve the login with a Yes in a Discord message.

## Before you start

- Staff are anyone holding `exyliastaff.staff`. The command needs no other permission.
- The module switch is `modules.two-factor`, on by default. Nobody is asked for anything until they set it up, unless you turn on `require-for-staff` below.
- For Discord approval you also need [ExyliaLink](/docs/exyliastaff/installation) installed and connected, and the staff member's Minecraft account linked to their Discord account there.

## Steps

<Steps>
  <Step title="Set it up as a staff member">
    Run `/2fa` (alias `/totp`). A map with a QR code appears in your hand and the key is written in chat, ready to copy if you cannot scan. Asking again shows the same key, so a code you already scanned keeps working. The map is drawn on your client only and is never put in the inventory.
  </Step>
  <Step title="Scan and confirm">
    Scan the QR with your authenticator app, then type the six digits it shows, in chat or as `/2fa <code>`. The map goes away and the chat says two-factor is on.
  </Step>
  <Step title="Join again">
    Leave and rejoin. You join locked: a short notice and, a second later, a code window titled "TWO-FACTOR" on clients that can show it. Anywhere else, type the six digits in chat; with or without a space in the middle they are taken as the code and never reach other players.
  </Step>
  <Step title="Require it for the whole team (optional)">
    In `plugins/ExyliaStaff/modules/twofactor/config.yml` set `require-for-staff: true` and run `/staffadmin reload`. From then on a staff member with none yet is held at the door and shown the setup: they cannot play until they finish it. Give `exyliastaff.2fa.exempt` (off by default) to a console account or a bot that holds the staff node.
  </Step>
</Steps>

## Check that it works

Join as the staff member after setup. You should be unable to move, chat, open anything or take damage, and every command but `/2fa` and `/totp` is refused. Type a valid code and the staff join runs: staff mode is restored and the staff-only parts of other modules draw. Typing the same code a second time is refused, since a code works once.

## Going further

### Discord approval

With ExyliaLink and `discord-approval` on (the default), a locked staff member whose account is linked also gets a Discord DM from the Link bot with Yes and No. The first answer, the DM or the code, lets them in. With `require-for-staff` on, a Yes also counts as having two-factor, so staff without an authenticator app can use Discord alone until they run `/2fa`. A No kicks the player and refuses their joins, on every server of the network, for `deny-lockout-minutes` (30). If Link is down or the DM cannot be delivered, nothing changes and the code still works. The DM is only sent when a login is locked, so a staff member with no two-factor and no requirement is never asked.

### Skip the code on a trusted address

`remember-ip-hours` lets the same address join without a code for that many hours after a valid one. `0`, the default, asks on every join. The address is stored as a keyed hash, never in the clear.

### Move between servers without a new code

`session-grace-seconds` (120) keeps a verified session alive across the network: moving to another server, or rejoining from the same address within that many seconds, asks for nothing. It works through the shared database, so every server must use the same one, as [Installation](/docs/exyliastaff/installation#database) describes.

### A staff member lost their phone

Run `/2fa reset <player>` with `exyliastaff.2fa.reset`, from the console or in game. Their two-factor is removed and they are told. With `require-for-staff` on they set it up again on their next join. A staff member who still has the app can turn it off with `/2fa disable <code>`; a valid code is needed so a borrowed session cannot do it.

### Wrong codes and timeouts

A staff member is kicked after `max-attempts` (5) wrong codes or `login-timeout-seconds` (120, never under ten) without one. While locked nothing of the staff join has happened: staff mode is not restored and nothing staff-only is drawn for them.

<Callout type="note" title="Codes never reach the audit">
`/2fa` and `/totp` are recorded in the [audit](/docs/exyliastaff/staff-admin) and in the web's command history without their arguments, so no code or key is ever stored there.
</Callout>

<Details title="Technical details">

```yaml title="plugins/ExyliaStaff/modules/twofactor/config.yml"
require-for-staff: false
issuer: Minecraft Staff
remember-ip-hours: 0
session-grace-seconds: 120
login-timeout-seconds: 120
max-attempts: 5
discord-approval: true
deny-lockout-minutes: 30
```

| Key | Default | What it does |
|---|---|---|
| `require-for-staff` | `false` | Every holder of `exyliastaff.staff` without two-factor must set it up on join before playing. |
| `issuer` | `Minecraft Staff` | The name the authenticator app files the code under. |
| `remember-ip-hours` | `0` | Hours the same address skips the code after a valid one. |
| `session-grace-seconds` | `120` | Moving server, or rejoining from the same address within this many seconds, keeps the session verified. `0` turns it off. |
| `login-timeout-seconds` | `120` | Seconds to enter the code before being kicked. Never less than ten. |
| `max-attempts` | `5` | Wrong codes allowed per join. |
| `discord-approval` | `true` | With ExyliaLink, also send linked staff a Yes / No DM. |
| `deny-lockout-minutes` | `30` | How long a login refused in Discord keeps the account out. |

The command has no permission node on purpose: a locked staff member must always be able to run it. Setting it up is checked inside and refused to anybody without `exyliastaff.staff`. The address hash key is sealed with a seal built into the jar: it protects a database dump read on its own, not one read together with the jar.

Messages are in `lang/<language>/modules/twofactor/messages.yml`: `prompt`, `locked`, `setup-required`, `setup` with `%secret%`, `verified`, `wrong-code` with `%left%`, `invalid-code`, `verify-first`, the kick screens `kick-attempts`, `kick-timeout`, `kick-denied` and `kick-locked` (with `%minutes%`), `discord-sent`, `discord-approved`, `discord-unavailable`, `enabled`, `already-enabled`, `disabled`, `not-enabled`, `not-staff`, `reset`, `reset-none`, `reset-notice` and `failed`.

Storage is `staff_2fa`, one row per staff member with two-factor on. `/2fa reset` and `/exylialib resetplayer <player> ExyliaStaff @account` delete it. Edit the messages as described in [Messages and languages](/docs/exylialib/messages-and-languages).
