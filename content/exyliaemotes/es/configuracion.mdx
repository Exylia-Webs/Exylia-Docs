title: "Configuración"
description: "Cada bloque de config.yml y cada línea de messages.yml, con sus valores por defecto."
---

`config.yml` y `messages.yml` se escriben desde un esquema: los comentarios se regeneran en cada
arranque, las claves desconocidas se descartan, y una clave que borres vuelve con su valor por
defecto. El catálogo es `emotes.yml` — ver [Emotes](/docs/exyliaemotes/emotes) — y las pantallas están
en `menus/`.

## `behaviour`

Cuándo puede reproducirse un emote, y qué lo corta.

```yaml
behaviour:
  require-permission: true
  hide-without-permission: false
  cooldown: 3s
  cancel-on-move: true
  move-tolerance: 0.6
  cancel-on-damage: true
  block-in-combat: true
  endless-limit: 5m
  worlds: []
```

| Clave | Por defecto | Qué hace |
|---|---|---|
| `require-permission` | `true` | Si hacer un emote exige tenerlo. Solo `/emotesadmin play` se lo salta. |
| `hide-without-permission` | `false` | Si un emote que el jugador no tiene se oculta en el menú en vez de mostrarse bloqueado. |
| `cooldown` | `3s` | Cuánto tiene que esperar el mismo jugador para hacer cualquier otro emote. Escrito como `3s`, `1m30s`. `0s` lo desactiva. |
| `cancel-on-move` | `true` | Si caminar termina un emote. |
| `move-tolerance` | `0.6` | Cuánto puede desplazarse un jugador antes de que salte `cancel-on-move`, en bloques. Nunca menos de `0.05`: un cliente envía pequeñas correcciones aunque esté quieto. |
| `cancel-on-damage` | `true` | Si recibir un golpe termina un emote, incluido otro jugador dando un puñetazo al cuerpo. |
| `block-in-combat` | `true` | Si un emote se rechaza mientras el jugador está marcado en combate, por el plugin de combate con el que esté conectado ExyliaLib. |
| `endless-limit` | `5m` | Lo máximo que dura un emote sin fin antes de terminar solo. Nunca menos de un segundo. |
| `worlds` | `[]` | Los mundos en los que se pueden hacer emotes, sin distinguir mayúsculas. Vacío significa todos. |

<Callout type="warning" title="Deja cancel-on-damage activado">
Un jugador que hace un emote está congelado y no puede ver quién tiene al lado. El emote no le protege,
así que lo mínimo que puede hacer es quitarse de en medio cuando empieza a doler.
</Callout>

`cancel-on-move` gobierna el movimiento que ve el servidor y las teclas de movimiento que recibe como
su propio evento de entrada. Una tecla de movimiento leída directamente de la conexión termina el emote
diga lo que diga — ver [Hacer un emote](/docs/exyliaemotes/reproducir).

## `camera`

```yaml
camera:
  enabled: true
  hide-body: true
```

| Clave | Por defecto | Qué hace |
|---|---|---|
| `enabled` | `true` | Si al jugador se le muestra su propio emote desde fuera. Desactivado, cada línea `[CAMERA]` se quita al compilar el catálogo: el emote se sigue reproduciendo para todos a su alrededor, él simplemente no lo ve. |
| `hide-body` | `true` | Si el jugador real se oculta mientras su cuerpo hace el emote. Desactivado, el jugador y su cuerpo están en el mismo sitio a la vez. |

Con la cámara desactivada el jugador sí puede caminar, que es para lo que está `move-tolerance`. El log
de arranque lo avisa cuando la cámara está desactivada.

## `duet`

```yaml
duet:
  invite: 20s
  max-distance: 3.0
```

| Clave | Por defecto | Qué hace |
|---|---|---|
| `invite` | `20s` | Cuánto dura una invitación antes de caducar. Nunca menos de un segundo. |
| `max-distance` | `3.0` | A qué distancia pueden estar los dos jugadores, en bloques, tanto al invitar como al empezar. |

La distancia no decide dónde quedan los cuerpos: siempre se colocan en la línea entre los dos
jugadores, a la distancia `gap` del propio emote. Ver [Duetos](/docs/exyliaemotes/duetos).

## `menu`

```yaml
menu:
  tab-open: "{success}✔ You are here"
  tab-closed: "{warning}➥ Click to open"
  favourites-name: "Favourites"
  favourites-icon: "AMETHYST_SHARD"
  favourite-on: "{highlight}★ In your favourites"
  favourite-off: "{muted}☆ Not in your favourites"
  kind-solo: "Solo"
  kind-duet: "With a friend"
```

| Clave | Qué es |
|---|---|
| `tab-open` / `tab-closed` | `%category_status%` en la pestaña que se está mirando, y en las demás. |
| `favourites-name` / `favourites-icon` | Cómo se llama la pestaña de favoritos y con qué se dibuja. |
| `favourite-on` / `favourite-off` | `%emote_favourite%` para un emote marcado y uno sin marcar. |
| `kind-solo` / `kind-duet` | `%emote_kind%` para un emote de un jugador y uno de dos. |

La pantalla en sí es `menus/emotes.yml` — ver [El menú](/docs/exyliaemotes/menu).

## `tiers`

Las rarezas en que se ordenan los emotes, y con qué frecuencia sale cada una de una caja. Añade,
renombra o borra cualquiera — la clave es el id que `emotes.yml` escribe como `tier`. Referencia
completa en [La caja](/docs/exyliaemotes/caja).

```yaml
tiers:
  common: { name: "Common", material: GRAY_DYE, color: "{muted}", chance: 60.0, priority: 1 }
  rare: { name: "Rare", material: LIGHT_BLUE_DYE, color: "{info}", chance: 25.0, priority: 2 }
  epic: { name: "Epic", material: PINK_DYE, color: "{accent}", chance: 12.0, priority: 3 }
  legendary: { name: "Legendary", material: ORANGE_DYE, color: "{highlight}", chance: 3.0, priority: 4 }
```

`chance` es un peso, no un porcentaje.

## `crate`

```yaml
crate:
  enabled: true
  start-keys: 1
  duplicate-refund: 1
  reward: UNLOCK
  blocks: []
  max-at-once: 4
  spin-frames: 34
  stagger-seconds: 2.0
  on-spin:
    sound:
      name: BLOCK_NOTE_BLOCK_HAT
      pitch: 1.6
  on-win:
    sound:
      name: ENTITY_PLAYER_LEVELUP
      pitch: 1.2
  on-duplicate:
    sound:
      name: BLOCK_NOTE_BLOCK_BASS
      pitch: 0.8
```

| Clave | Por defecto | Qué hace |
|---|---|---|
| `enabled` | `true` | Desactivada, la caja lo dice en vez de abrirse. |
| `start-keys` | `1` | Llaves que recibe un jugador la primera vez que se le ve. |
| `duplicate-refund` | `1` | Llaves devueltas por un emote ya desbloqueado. |
| `reward` | `UNLOCK` | `UNLOCK`, `ITEM` o `BOTH`. Un emote no tiene objeto, así que los tres lo desbloquean. |
| `blocks` | `[]` | Los bloques que abren la caja, como `server,world,x,y,z,yaw,pitch`. Vincúlalos con `/emotesadmin crate block add`. |
| `max-at-once` | `4` | Cuántas cajas puede abrir un jugador de una vez, hasta siete. |
| `spin-frames` | `34` | Cuántas caras recorre el primer rodillo. Tope de 200, unos once segundos. |
| `stagger-seconds` | `2.0` | Cuánto después de parar un rodillo para el siguiente. `0` los para a la vez. |
| `on-spin` | Una nota de hi-hat | Se reproduce en cada tick en que un rodillo sigue cayendo. |
| `on-win` | Un level-up | Se reproduce en el momento en que un rodillo para en algo nuevo, una vez por caja. |
| `on-duplicate` | Una nota grave | Se reproduce en su lugar cuando ese rodillo paró en algo ya desbloqueado. |

## `key-item`

Cómo se dibuja una llave de caja que se puede tener en la mano.

```yaml
key-item:
  material: TRIPWIRE_HOOK
  name: "{primary}&lEMOTE KEY"
  lore:
    - "{secondary}Information:"
    - " {letters_black}▎ {letters}Right click the crate holding this"
    - " {letters_black}▎ {letters}to {highlight}open it {letters}once."
    - ""
    - "{secondary}Note:"
    - " {letters_black}▎ {letters}This one can be traded and dropped."
    - ""
    - "{warning}➥ Right click the crate to open"
    - ""
  glow: true
```

Una llave se reconoce por lo que lleva en sus datos, así que renombrarla o recolorearla no cambia nada
para las llaves que ya están repartidas.

## `preview`

Dónde se puede ver un emote sin hacerlo: `/emote preview`, y el clic derecho del menú.

```yaml
preview:
  location: ""
  distance: 5.0
  settle-ticks: 4
  linger-ticks: 20
  max-ticks: 600
```

| Clave | Por defecto | Qué hace |
|---|---|---|
| `location` | Vacío | Dónde está el jugador mientras se reproduce una previsualización. Se fija con `/emotesadmin preview location`. Solo se usa la posición: una previsualización siempre mira al norte. |
| `distance` | `5.0` | A cuántos bloques delante del jugador se reproduce el emote. Nunca menos de `1`. |
| `settle-ticks` | `4` | Cuánto esperar tras el teletransporte antes de reproducir. También lee una duración escrita: `1s`, `500ms`. |
| `linger-ticks` | `20` | Cuánto se mantiene el escenario tras terminar el emote. |
| `max-ticks` | `600` | Lo máximo que puede durar una previsualización, pase lo que pase. |

Vacío significa sin escenario, y las previsualizaciones responden `preview-unavailable`. Dos jugadores
pueden compartirlo a la vez: todos están ocultos para todos, y cada emote se envía a un solo jugador.

## `showcase`

```yaml
showcase:
  locations: []
  pause-seconds: 3.0
  radius: 24.0
  emotes: []
```

| Clave | Por defecto | Qué hace |
|---|---|---|
| `locations` | `[]` | Dónde se reproducen emotes en bucle. Se fijan con `/emotesadmin showcase add`. |
| `pause-seconds` | `3.0` | El descanso entre que termina un emote y empieza el siguiente. |
| `radius` | `24.0` | A qué distancia tiene que estar un jugador para que un showcase se reproduzca y lo vea, en bloques. |
| `emotes` | `[]` | Los ids de los que elige un showcase. Vacío elige de todos. Los duetos nunca se eligen. |

Ver [Showcases](/docs/exyliaemotes/showcases).

## `feedback`

```yaml
feedback:
  on-play:
    sound:
      name: BLOCK_AMETHYST_BLOCK_CHIME
      pitch: 1.4
  on-cancel:
    sound:
      name: BLOCK_GRINDSTONE_USE
      pitch: 0.9
  on-invite:
    sound:
      name: BLOCK_NOTE_BLOCK_BELL
      pitch: 1.6
```

| Clave | Se reproduce |
|---|---|
| `on-play` | Para el jugador en el momento en que empieza su emote — para los dos, en un dueto. |
| `on-cancel` | Para quienes lo hacían cuando un emote termina antes de tiempo. No cuando llega al final. |
| `on-invite` | Para quien es invitado a un dueto. |

Estos y los tres bloques de la caja son bloques de efecto completos de ExyliaLib: título, action bar,
boss bar, sonido, partícula y fuego artificial están disponibles en cada uno. Todos los incluidos son un
solo sonido a volumen `1.0`, en la categoría `PLAYERS`.

## `placeholders`

```yaml
placeholders:
  none: "None"
  unknown: "Unknown"
```

| Clave | La devuelve |
|---|---|
| `none` | Un placeholder de jugador pedido sin jugador, y `playing_id` / `playing_name` cuando no se está haciendo nada. |
| `unknown` | Un placeholder `emote_<id>_<campo>` que nombra un emote o un campo que no existe. |

## `messages.yml`

Cada línea que envía el plugin. `prefix` es `{primary}&lEMOTES &8•&r ` y todos los demás mensajes
empiezan por `%prefix%`.

| Clave | Se envía cuando | Placeholders |
|---|---|---|
| `playing` | Empezó un emote. | `%emote%`, `%id%`, `%player%` |
| `unknown-emote` | El id no nombra nada, o el emote no reproduce nada. | `%emote%`, `%id%` |
| `no-permission` | El jugador no lo tiene. | `%emote%`, `%id%` |
| `on-cooldown` | Corre un cooldown. | `%emote%`, `%time%` |
| `already-playing` | Está haciendo uno. | |
| `in-combat` | Está marcado en combate. | |
| `wrong-world` | Los emotes están desactivados en su mundo. | |
| `needs-partner` | Se pidió un dueto sin nombrar a nadie. | `%emote%`, `%id%` |
| `invite-sent` | A quien invita. | `%player%`, `%emote%` |
| `invite-received` | Al invitado, con los botones Accept y Decline. | `%player%`, `%emote%` |
| `invite-expired` | La invitación caducó, o quien invitó se fue. | |
| `invite-declined` | A quien invitó, cuando se rechazó. | `%player%` |
| `invite-none` | Aceptar o rechazar sin nada pendiente. | |
| `invite-self` | Invitarse a uno mismo. | |
| `partner-too-far` | La pareja está demasiado lejos, o en otro mundo. | `%player%` |
| `partner-busy` | La pareja está haciendo algo, o se fue. | `%player%` |
| `partner-cannot` | La pareja no puede hacerlo, por cualquier motivo. | `%player%` |
| `list-header` / `list-entry` / `list-empty` | `/emote list`. | `%id%`, `%emote%` |
| `favourite-added` / `favourite-removed` | Marcar y desmarcar. | `%emote%` |
| `favourites-cleared` / `favourites-empty` | Vaciar la lista corta, o encontrarla ya vacía. | |
| `crate-won` / `crate-duplicate` | Un rodillo cayó en algo nuevo, o ya desbloqueado. | `%emote%`, `%tier%`, `%refund%` |
| `crate-no-keys` | No hay suficientes llaves. | `%amount%`, `%keys%` |
| `crate-busy` / `crate-empty` / `crate-disabled` | La caja se negó a abrirse. | |
| `given-key` | A un jugador que recibe llaves en forma de objeto. | `%amount%` |
| `rewards-claimed` | Al entrar, cuando le esperaban llaves en forma de objeto. | `%amount%` |
| `keys-received` / `keys-taken` | A un jugador cuyas llaves de la cuenta cambiaron. | `%amount%` |
| `keys-given` | Al admin, tras cualquier subcomando `keys`. | `%player%`, `%amount%` |
| `unlock-granted` / `unlock-already` / `unlock-revoked` / `unlocks-cleared` | Subcomandos `unlocks`. | `%emote%`, `%player%` |
| `crate-block-added` / `crate-block-removed` | Se vinculó o desvinculó un bloque. | `%location%` |
| `crate-block-already` / `crate-block-missing` | Ya lo estaba, o nunca lo estuvo. | |
| `crate-block-none` | No se está mirando ningún bloque a menos de seis bloques. | |
| `crate-blocks-header` / `crate-blocks-entry` / `crate-blocks-empty` | `crate block list`. | `%location%` |
| `crate-blocks-cleared` | `crate block clear`. | `%amount%` |
| `preview-location-set` | Se movió el escenario de previsualización. | `%location%` |
| `preview-unavailable` / `preview-unavailable-admin` | Se pidió una previsualización antes de fijar un escenario; la segunda solo a admins. | |
| `showcase-added` / `showcase-removed` | Se puso o se quitó un showcase. | `%location%` |
| `showcase-missing` | No hay ningún showcase a menos de cinco bloques. | |
| `showcases-header` / `showcases-entry` / `showcases-empty` | `showcase list`. | `%location%` |
| `showcases-cleared` | `showcase clear`. | `%amount%` |

<Callout type="note" title="Tres claves nunca se envían">
`cancelled`, `camera-unavailable` y `refreshed` están en el archivo pero nada las envía: un emote cortado
lo dice con el sonido `on-cancel`, y `/emotesadmin reload` informa con la línea de recarga propia de
ExyliaLib.
</Callout>

Cada rechazo de un emote rellena `%emote%`, `%id%`, `%player%` y `%time%` los use o no la línea, así que
cualquiera de ellos se puede añadir a cualquier línea de rechazo.
