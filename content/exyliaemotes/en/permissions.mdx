Everybody can open `/emote` by default, but nobody except operators owns an emote until you grant one. Use this page to decide who gets what.

## All permissions

<Permissions />

`exyliaemotes.cooldown.<seconds>` and `exyliaemotes.endless.<seconds>` are numbers you write yourself, for example `exyliaemotes.cooldown.1`. They are not declared in `plugin.yml`, so no one holds them until you grant them.

## Sell emotes by permission

The emote id is the node. There is no `permission` key in `emotes.yml`; the key in the file, lowercased, is the id:

```text
wave         ->  exyliaemotes.emote.wave
meme         ->  exyliaemotes.category.meme
legendary    ->  exyliaemotes.tier.legendary
```

A player owns an emote if any of the four emote nodes applies: its own, `exyliaemotes.emote.*`, its tab's or its rarity's. With LuckPerms:

```text
/lp group default permission set exyliaemotes.emote.wave true
/lp group vip     permission set exyliaemotes.category.meme true
/lp group mvp     permission set exyliaemotes.emote.handshake true
/lp group elite   permission set exyliaemotes.tier.legendary true
/lp group legend  permission set exyliaemotes.emote.* true
```

A permission is half of owning an emote. The other half is an unlock won in [the crate](/docs/exyliaemotes/crate) or granted with `/emotesadmin unlocks grant`, which is written to the player's account. The menu, the commands, the placeholders and the preview stage all ask the same question, so they cannot disagree.

Renaming an emote's key gives it a different node, and everybody who had the old one loses it.

<Callout type="tip" title="Keep the menu open to everyone">
Without `exyliaemotes.command.emote` a player cannot open the catalogue, and a player who cannot see what is for sale cannot want it. Locked emotes are shown locked and can be previewed.
</Callout>

## Ranks that play more

Two numbers, in seconds, can ride on a rank:

```text
/lp group vip   permission set exyliaemotes.cooldown.1 true     # 1 second between emotes
/lp group mvp   permission set exyliaemotes.cooldown.0 true     # no shared wait at all
/lp group vip   permission set exyliaemotes.endless.600 true    # endless emotes run up to 10 minutes
```

A player with neither gets `behaviour.cooldown` (3 seconds) and `behaviour.endless-limit` (5 minutes) from `config.yml`. If a player holds several `cooldown` numbers the lowest wins; with several `endless` numbers the highest wins. The cooldown node replaces only the shared wait: an emote's own `cooldown` in `emotes.yml` still applies. In a duet each player waits their own cooldown, and the endless limit is the inviter's.

## What the nodes are checked for

| Moment | Without the node |
|---|---|
| Performing from the menu or `/emote play` | Refused with `no-permission`, while `behaviour.require-permission` is on. |
| Accepting a duet | Both players must own it, or it is refused on accept. |
| The menu | `behaviour.hide-without-permission` decides between hiding the emote or showing it locked. The favourites tab always shows it. |
| Tab completion of `/emote play` | Only owned emotes are offered. |

With `behaviour.require-permission: false` every emote is playable by anyone who can run `/emote`, and nothing in the menu is locked. Previewing and starring never need the emote's node. `/emotesadmin play` does not either.
