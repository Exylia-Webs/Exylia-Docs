## The nodes

| Permission | Grants |
|---|---|
| Permission | Default | Grants |
|---|---|---|
| `exyliaemotes.command.emote` | everyone | `/emote` and everything under it, the classic menu and the 3D selector. |
| `exyliaemotes.admin` | op | Every subcommand of `/emotesadmin`, the admin hub with its SETTINGS button, the catalogue in the editors, and the hint on how to set a preview stage. |
| `exyliaemotes.emote.<id>` | op | One emote, by its id. |
| `exyliaemotes.emote.*` | op | Every emote. |
| `exyliaemotes.category.<id>` | op | Every emote in that tab. |
| `exyliaemotes.tier.<id>` | op | Every emote of that rarity. |
| `exyliaemotes.cooldown.<seconds>` | — | The shared wait between two emotes, instead of `behaviour.cooldown`. The lowest one held wins. |
| `exyliaemotes.endless.<seconds>` | — | How long an endless emote may run, instead of `behaviour.endless-limit`. The highest one held wins. |

`exyliaemotes.command.emote`, `exyliaemotes.admin` and `exyliaemotes.emote.*` are declared in
`plugin.yml`. The emote nodes are sold, so nobody but an operator holds them until a rank or a purchase
grants them.

An emote is owned if **any** of the four emote nodes applies: its own, the wildcard, its tab's or its
rarity's. A permission is only half of owning one — the other half is an unlock from
[the crate](/docs/exyliaemotes/crate), which is written to the player's account instead. The menu, the
commands, the placeholders and the stage all ask the same question, so they cannot disagree.

## The id is the node

There is no `permission` key in `emotes.yml`. The node is the key, lowercased:

```text
wave         →  exyliaemotes.emote.wave
meme         →  exyliaemotes.category.meme
legendary    →  exyliaemotes.tier.legendary
```

Renaming a key is a different node, and everybody who had the old one loses the emote.

## Selling it

```text
/lp group default permission set exyliaemotes.command.emote true
/lp group default permission set exyliaemotes.emote.wave true
/lp group vip     permission set exyliaemotes.category.meme true
/lp group mvp     permission set exyliaemotes.emote.handshake true
/lp group elite   permission set exyliaemotes.tier.legendary true
/lp group legend  permission set exyliaemotes.emote.* true
```

The first line is already the default; it only matters on a server that took it away.

<Callout type="tip" title="Give the menu away">
Without `exyliaemotes.command.emote` the catalogue cannot be opened at all, and a player who cannot see
what is for sale cannot want it. Locked emotes are shown locked, and can be previewed.
</Callout>

## Ranks that play more

Two numbers a rank can carry, in seconds:

```text
/lp group vip   permission set exyliaemotes.cooldown.1 true     # 1 second between emotes
/lp group mvp   permission set exyliaemotes.cooldown.0 true     # no shared wait at all
/lp group vip   permission set exyliaemotes.endless.600 true    # endless emotes run up to 10 minutes
```

A player with neither node gets `behaviour.cooldown` and `behaviour.endless-limit` from `config.yml`.
The cooldown node only replaces the shared wait: an emote's own `cooldown` in `emotes.yml` still
applies. In a duet each player waits their own cooldown, and the endless limit is the inviter's.

## What the nodes are checked for

| Moment | What happens without one |
|---|---|
| Performing, from the menu or `/emote play` | Refused with `no-permission`, while `behaviour.require-permission` is on. |
| Accepting a duet | Both players must own it, or it is refused on accept. |
| Being drawn | `behaviour.hide-without-permission` decides whether a locked emote is hidden in the menu or shown locked. On the favourites tab it is always shown. |
| Tab completion of `/emote play` | Only owned emotes are offered. |

With `behaviour.require-permission: false` every emote is playable by anybody who can run `/emote`, and
nothing in the menu is locked.

Previewing and starring never need the emote's node. `/emotesadmin play` does not either — it reaches
past ownership on purpose.
