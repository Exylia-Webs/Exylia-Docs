## Player commands

`/emote`, alias `/emotes`. Everything under it needs `exyliaemotes.command.emote` and a player to run
it.

| Command | What it does |
|---|---|
| `/emote` | Opens the menu, on the tab it was last left on. |
| `/emote play <emote> [player]` | Performs an emote. For a duet, the player is who to invite; for a solo emote it is ignored. Tab completion offers only the emotes the player owns — every one when `require-permission` is off. |
| `/emote accept [player]` | Accepts the invitation waiting for you. Alias: `yes`. |
| `/emote deny [player]` | Declines it. Aliases: `decline`, `no`. |
| `/emote cancel` | Stops whatever you are performing. Alias: `stop`. |
| `/emote preview <emote>` | Plays an emote on the server's preview stage. Owning it is not required. |
| `/emote crate` | Opens the crate. Aliases: `crates`, `case`. |
| `/emote favourites` | Opens the menu straight onto the shortlist. Aliases: `favorites`, `favs`. |
| `/emote favourite <emote>` | Stars an emote, or unstars it. Aliases: `favorite`, `fav`. |
| `/emote favourites clear` | Empties the shortlist. |
| `/emote list` | Prints every emote you may perform, by id and name. Alias: `mine`. |

<Callout type="note" title="Playing is spelled play">
`/emote` on its own only opens the menu. An emote is performed with `/emote play <emote>`, so an emote
id can never collide with a subcommand such as `accept`.
</Callout>

The name after `accept` and `deny` is accepted for the chat buttons' sake and ignored: a player only
ever has one invitation waiting. See [Duets](/docs/exyliaemotes/duets).

## Admin commands

`/emotesadmin`, alias `/emoteadmin`. Everything under it needs `exyliaemotes.admin`.

### Performing

| Command | What it does |
|---|---|
| `play <player> <emote>` | Makes an online player perform an emote, whether or not they own it. Alias: `force`. |
| `cancel [player]` | Ends what a player is performing. With no player, everybody's. Alias: `stop`. |

`play` reaches past ownership and nothing else: a player already performing, in combat, on cooldown or
in a world where emotes are off is not made to perform anyway, and a duet answers `needs-partner`. The
result is told to the target, not to whoever ran the command.

### `item` — what can be held

| Command | What it does |
|---|---|
| `item key <player> [1-64]` | Gives crate keys as items, to be right clicked on a crate block. Alias: `item keys`. What does not fit is handed over on their next join. |

### `keys` — keys on the account

| Command | What it does |
|---|---|
| `keys give <player> [1-10000]` | Adds keys. Alias: `keys add`. The player is told `keys-received`. |
| `keys take <player> [1-10000]` | Removes keys. Alias: `keys remove`. The player is told `keys-taken`. |
| `keys set <player> <0-100000>` | Sets how many they hold. |
| `keys check <player>` | Prints how many they hold. Alias: `keys`. |

The amount defaults to `1` on `give` and `take`. Every one of them answers the sender with `keys-given`,
naming the new total.

### `unlocks` — what somebody won

| Command | What it does |
|---|---|
| `unlocks grant <player> <emote>` | Unlocks an emote outright, the way a crate does. Alias: `unlocks give`. |
| `unlocks revoke <player> <emote>` | Takes one back. Alias: `unlocks take`. |
| `unlocks clear <player>` | Takes back everything they won. |

### `player`

| Command | What it does |
|---|---|
| `player favourites clear <player>` | Empties a player's shortlist. Alias: `player favorites clear`. |

### `crate` — the blocks that open it

| Command | What it does |
|---|---|
| `crate block add` | Binds the block you are looking at, up to six blocks away. |
| `crate block remove` | Unbinds the block you are looking at. |
| `crate block list` | Prints every bound block. |
| `crate block clear` | Unbinds all of them. |

### `showcase` — emotes on a loop

| Command | What it does |
|---|---|
| `showcase add` | Plays emotes on a loop where you stand. |
| `showcase remove` | Removes the showcase nearest you, up to five blocks away. Alias: `showcase delete`. |
| `showcase list` | Prints every showcase. |
| `showcase clear` | Removes all of them. |

### `menu` and `preview`

| Command | What it does |
|---|---|
| `menu open <player>` | Opens the emote menu for someone. |
| `menu crate <player>` | Opens the crate screen for someone, without spending anything. |
| `preview play <emote> [player]` | Previews an emote, for yourself or for someone else. |
| `preview location` | Sets the preview stage to where you stand. |

### The rest

| Command | What it does |
|---|---|
| `reload` | Re-reads this plugin's files. |

<Callout type="note" title="A player does not have to be online">
`keys`, `unlocks` and `player favourites clear` take a name and write straight to the player's row when
they are offline, so a reward or a support ticket is settled the moment it is decided. Everything else
that names a player needs them online.
</Callout>

## What each one actually does

### `preview location`

Stores where previews play: where you stand. Only the position is taken — a preview always faces
north, so every emote is seen from the side it was choreographed for, and the north side of the stage
is the one to leave open. The player is lifted onto the stage, hidden from everybody and everybody from
them, shown the emote `preview.distance` blocks in front of them and put back. An endless emote is shown
for six seconds.

Until one is set, `/emote preview` and the menu's right click answer `preview-unavailable`, and a player
with `exyliaemotes.admin` is also told which command sets it.

### `crate block add`

Binds the block you are looking at and writes it to `config.yml` rather than into the world, so it
survives a schematic paste, a world edit and a rollback. While a block is bound it cannot be broken,
blown up or pushed away, and clicking it no longer does what its material does.

### `reload`

Runs one step, `configs`: re-reads `config.yml` and `messages.yml`, reapplies the prefix, re-reads and
recompiles `emotes.yml`, reloads the files in `menus/`, rebuilds the crate and restarts every showcase.
Edits made to the menu and catalogue files survive.

It deliberately does **not** reload ExyliaLib — recolouring every plugin on the server is what
`/exylialib reload` is for.

<Callout type="warning" title="A reload republishes the catalogue">
Emotes are recompiled before the new catalogue is published, so nothing plays a half-compiled
sequence. But an emote whose key you renamed is a new emote: whoever owned the old one does not own the
new one.
</Callout>
