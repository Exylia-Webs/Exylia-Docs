Placeholders need PlaceholderAPI. They are registered under the identifier `exyliaemotes`. Click one to copy it.

<Placeholders />

## Using them

`<id>` is an emote id such as `wave`: `%exyliaemotes_owns_wave%`, `%exyliaemotes_emote_wave_name%`. Player placeholders asked with no player, and `playing_id` or `playing_name` while nothing is playing, answer `None` (the `placeholders.none` line in `messages.yml`). An id that names no emote answers `Unknown` (`placeholders.unknown`). `%exyliaemotes_owns_<id>%` for an unknown id answers `false`.

The server placeholders (`catalogue_count`, `total`, `playing_count`) work without a player, so they fit in a hologram.

<Callout type="warning" title="Ids with an underscore do not work in emote_<id>_<field>">
The id is read up to the first `_` after `emote_`, so `%exyliaemotes_emote_six_seven_name%` asks for an emote called `six` and answers `Unknown`. The 22 shipped emotes with an underscore (`thumbs_up`, `six_seven`, `chill_guy` and so on) have no working `emote_<id>_<field>` placeholder. `owns_<id>` and `favourite_<id>` read the whole rest of the name and are not affected.
</Callout>

```yaml
lines:
  - " {muted}❙ {letters}Emotes: {highlight}%exyliaemotes_owned_count%{muted}/%exyliaemotes_catalogue_count%"
  - " {muted}❙ {letters}Keys: {highlight}%exyliaemotes_keys%"
  - " {muted}❙ {letters}Now: {highlight}%exyliaemotes_playing_name%"
```
