title: "Configuración"
description: "Todas las claves de config.yml con su valor por defecto, y qué vive en messages.yml en vez de aquí."
---

`plugins/ExyliaChatCosmetics/config.yml` se genera a partir del record `Settings` del propio plugin y
lo vuelve a leer `/cca reload`. Eso conviene saberlo por dos motivos:

- **Una clave que el plugin no reconoce se elimina al cargar**, y cada eliminación se reporta una vez
  en la consola. Una errata no se queda ahí calladita sin hacer nada.
- **Un valor que el plugin no puede leer se reporta y se usa el de por defecto.** El servidor arranca
  igual; nunca se niega a cargar por una línea mala.
- **El archivo lleva una versión y se migra en su sitio.** Un archivo escrito por una versión anterior
  conserva sus claves renombradas o movidas en el primer arranque: `chat.module.enabled` pasó a
  `modules.chat`, `rank-colors.repaint` pasó a `rank-colors.keep`, `chat.default-color` dio paso a la
  sección `defaults`, y la sección `menu` se movió a `lang/<idioma>/messages.yml`.

Los cosméticos en sí no están aquí. Viven en `cosmetics/*.yml` y se describen en
[el catálogo](/docs/exyliachatcosmetics/catalogo).

## language

| Clave | Por defecto | Significado |
|---|---|---|
| `language` | `default` | El idioma de los menús y los mensajes. `default` sigue el idioma configurado en el `config.yml` de ExyliaLib; `en`, `es`, `pt`, `fr` o `ru` lo fijan solo para este plugin. Cada uno es una carpeta bajo `lang/` que puedes editar; `custom` guarda los archivos que el servidor tenía antes de que existieran los idiomas. |

## modules

Lo que usa este servidor. Un módulo apagado no registra nada — ni clase de cosmético, ni comando, ni
botón, ni respuesta de placeholder — y lo que los jugadores ya llevan de él se queda en su perfil, así
que volver a encenderlo le devuelve a cada uno sus cosas. Todos los interruptores vienen en `true`.

| Clave | Qué enciende |
|---|---|
| `chat` | El [módulo de chat](/docs/exyliachatcosmetics/chat) integrado: canales, formatos, mensajes privados, el filtro, la moderación. Apagado, el plugin es solo cosméticos y tu plugin de chat sigue entregando a través del hook. **Se aplica con `/cca reload`.** |
| `tags` | Etiquetas delante del nombre |
| `nick-colors` | Colores para el nombre del jugador |
| `rank-colors` | Colores para el prefijo y el sufijo del rango |
| `chat-colors` | Colores para el mensaje |
| `shadows` | Sombras bajo el nombre, el rango y el mensaje; cada una necesita su módulo de color |
| `custom` | Etiquetas y colores que los jugadores crean con tokens; cada uno necesita su módulo de etiqueta o de color |
| `fonts` | Fuentes para el mensaje |
| `modifiers` | Negrita, cursiva y el resto de modificadores del mensaje |
| `presets` | Looks completos que monta el servidor (`cosmetics/presets.yml`) |
| `loadouts` | Looks que los jugadores guardan y se vuelven a poner |

<Callout type="warning" title="Todos menos chat esperan a un reinicio">
Un comando solo se puede añadir mientras el servidor arranca, así que `/cca reload` aplica `chat` y nada
más. Si cambió cualquier otro interruptor, el reload lo dice en la consola — `The modules in config.yml
changed; restart the server to apply them.` — y el conjunto en marcha se queda como arrancó.
</Callout>

## defaults

Lo que lleva un jugador de una clase de la que no ha elegido nada, según su grupo de permisos. Un bloque
por clase, con el grupo como clave y el id de una entrada del catálogo de esa clase como valor:

```yaml title="plugins/ExyliaChatCosmetics/config.yml"
defaults:
  tag:
    owner: staff
    vip: mvp
    default: ''
  chat-color:
    default: ''
```

| Clave | Nombra una entrada de |
|---|---|
| `tag` | `cosmetics/tags.yml` |
| `nick-color` | `cosmetics/nick-colors.yml` |
| `rank-color` | `cosmetics/rank-colors.yml` |
| `chat-color` | `cosmetics/chat-colors.yml` |
| `shadow-color`, `nick-shadow`, `rank-shadow` | `cosmetics/shadow-colors.yml` — las tres sombras son un mismo catálogo que se lleva en tres sitios |
| `font` | `cosmetics/fonts.yml` |
| `modifier` | `cosmetics/modifiers.yml` |

`default` cubre todos los grupos que el bloque no nombra, y gana el primer grupo de la lista en el que
esté el jugador, así que pon primero el rango más alto. Los grupos vienen de LuckPerms; sin él solo se
aplica `default`. Todos los bloques vienen como `default: ''`, que no da nada, así que un servidor
nuevo se ve igual que antes.

Un valor por defecto lo da el servidor, no lo posee el jugador: se lleva sin nodo de permiso y sin
concesión, y en cuanto el jugador elige algo de esa clase, se dibuja lo suyo. Un id que no nombra
ninguna entrada se reporta en la consola al cargar y al recargar, y ese grupo no recibe nada.

## chat

| Clave | Por defecto | Significado |
|---|---|---|
| `hook` | `decorate` | Cómo se estiliza el cuerpo del mensaje. Los cuatro modos están abajo. |
| `priority` | `NORMAL` | Prioridad del evento para `chat_event` y `legacy_event`: `LOWEST`, `LOW`, `NORMAL`, `HIGH`, `HIGHEST`, `MONITOR`. Cualquier otra cosa cae a `NORMAL` con un aviso. |
| `sanitize` | `true` | El formato que escribe un jugador — `&c`, `<red>`, `{primary}` — se muestra como el texto que escribió. `exyliachatcosmetics.chat.format` se lo salta. El `§` se neutraliza siempre, con permiso o sin él. |

El hook solo actúa mientras `modules.chat` está apagado. Con el [módulo de chat](/docs/exyliachatcosmetics/chat)
encendido, el hook se desinstala y el módulo estiliza el cuerpo por su cuenta.

### Los cuatro modos de hook

| Modo | Qué pasa | Elígelo cuando |
|---|---|---|
| `decorate` | `AsyncChatDecorateEvent`: el cuerpo estilizado reemplaza al mensaje decorado antes de que lo vea ningún plugin de chat. No se cancela nada. | Paper, con un plugin de chat que dibuja a través del evento — el chat propio de Paper y cualquier plugin basado en renderer. Recomendado. |
| `chat_event` | `AsyncChatEvent.message(...)`, en la `priority` de arriba. | El plugin de chat ignora la decoración pero lee `message()`. |
| `legacy_event` | `AsyncPlayerChatEvent.setMessage(...)`, escrito con códigos `§` y hex. | El plugin de chat todavía usa el evento de cadena. |
| `off` | El chat no se toca nunca. | Compones la línea tú mismo con la [API](/docs/exyliachatcosmetics/api), o solo quieres los placeholders de identidad. |

Sea cual sea el modo, el mensaje se dibuja únicamente desde estado cacheado. Un dibujo que falla deja
el mensaje exactamente como se escribió y se reporta como mucho una vez por minuto, así que un
cosmético roto no puede convertirse en un muro de consola.

## tags

| Clave | Por defecto | Significado |
|---|---|---|
| `format` | `"%tag% "` | Cómo se sitúa la etiqueta alrededor del nombre; `%tag%` es la etiqueta. El espacio final es la razón por la que `%exyliachatcosmetics_tag%%exyliachatcosmetics_nick%` no necesita nada en medio. Una entrada de etiqueta puede sustituirlo con su propio `format`. |

## rank-colors

| Clave | Por defecto | Significado |
|---|---|---|
| `keep` | `[]()<>{}\|` | Los caracteres que un color de rango nunca repinta: el marco que un rango escribe alrededor de su nombre, así que `&8[&eVIP&8]` conserva sus corchetes grises mientras `VIP` toma el color nuevo. Todo lo demás se repinta — letras, glifos de un resource pack, la estrella de un sufijo. Un carácter que el rango escribió sin color propio se repinta siempre. Vacío lo repinta todo. |

## custom-tags

Las reglas que tiene que pasar una etiqueta que un jugador se escribe. Valen para
`/cc customtag create`, para el botón MAKE ONE y para `/cca customtag set` — un administrador se
salta el token, no las reglas.

| Clave | Por defecto | Significado |
|---|---|---|
| `min-length` | `2` | |
| `max-length` | `16` | |
| `pattern` | `[A-Za-z0-9_\-]+` | Una expresión regular que tiene que cumplir el texto entero. `<>{}&§%\` se rechazan diga lo que diga el patrón. |
| `blacklist` | `[admin, staff, owner]` | Palabras que una etiqueta no puede contener, sin distinguir mayúsculas |
| `unique` | `true` | Dos jugadores no pueden tener el mismo texto |

## custom-colors

| Clave | Por defecto | Significado |
|---|---|---|
| `max-stops` | `4` | Por cuántos colores puede pasar un degradado propio |

## loadouts

| Clave | Por defecto | Significado |
|---|---|---|
| `limit` | `3` | Cuántos looks puede tener guardados un jugador |

<Callout type="note" title="Cuántos personalizados puede crear un jugador no es una clave">
No hay ningún `custom-tags.limit` y no lo va a haber. Cuántas etiquetas y colores propios puede
escribir un jugador es un **saldo**, guardado por jugador y por tipo y repartido con
`/cca tokens give`. Crear uno gasta un token `create`, cambiarlo gasta uno `edit`, y borrarlo no
devuelve nada. Una cuota en `config.yml` sería el mismo número para todo el mundo; un saldo es algo
que puedes vender, premiar o retirar jugador a jugador. Ver
[Tokens](/docs/exyliachatcosmetics/tokens).
</Callout>

| Clave | Por defecto | Significado |
|---|---|---|
| `tick` | `2` | Ticks entre fotogramas de animación. Más bajo va más suave y cuesta más. |

## preview

| Clave | Por defecto | Significado |
|---|---|---|
| `format` | `%tag%%prefix% %name%%suffix%{letters_black}: %message%` | La línea que dibujan `/cc preview` y las vistas previas del menú. `%tag%` ya trae su espacio final de `tags.format`; `%prefix%` y `%suffix%` son los del rango, en el color de rango que se esté mirando. |

## Cómo llaman las cosas los menús

La sección `menu` que antes estaba aquí — el nombre de cada clase, las líneas de estado, la estrella,
`none`, el mensaje y el prefijo de muestra, las indicaciones de las filas propias — es texto que ve el
jugador, así que ahora vive en `lang/<idioma>/messages.yml` bajo `menu`, donde se traduce. Un
`config.yml` de una versión anterior tiene su sección `menu` movida allí en el primer arranque. Ver
[messages.yml](#messagesyml).

|---|---|---|
| `notify-on-join` | `true` | Al entrar: una línea por cada concesión temporal que lleva puesta con el tiempo que le queda, más un recuento de las que se le acabaron mientras no estaba |
| `retention-days` | `30` | Cuánto se queda en la tabla una concesión caducada o revocada, para auditoría, antes de que la barrida diaria la borre |

## shop

Comprar un cosmético bloqueado con moneda, desde el menú. Necesita ExyliaEconomy o Vault; sin ninguno
de los dos, nada muestra un precio.

| Clave | Por defecto | Significado |
|---|---|---|
| `enabled` | `true` | Si un cosmético bloqueado con precio se puede comprar desde el menú |
| `tier-prices` | `common: 500`, `rare: 1500`, `epic: 4000`, `legendary: 10000` | El precio de cada nivel, en la moneda por defecto o como `{amount, currency}` |

Una entrada de `cosmetics/*.yml` entra en un nivel con `tier: rare`, o pone su propio `price`, que gana
al de su nivel. Una entrada sin ninguno de los dos no está a la venta:

```yaml title="plugins/ExyliaChatCosmetics/cosmetics/tags.yml"
tags:
  crown:
    price: {amount: 50, currency: gems}
```

Un precio es un número mayor que cero — `500`, o `2.5k` — o un bloque con `amount` y `currency`.
Cualquier otra cosa, cero y negativos incluidos, se lee como sin precio, así que una errata deja un
cosmético sin poder comprarse en vez de gratis. Un precio en una moneda que ninguna economía acepta
tampoco se muestra. `/cca reload` vuelve a leer los niveles.

## messages.yml

Todas las líneas que ve un jugador viven en `plugins/ExyliaChatCosmetics/lang/<idioma>/messages.yml`, generado a
partir del record `CosmeticMessages` del plugin y recargado con lo demás. `prefix` — por defecto
`{primary}&lE-CHAT &8•&r ` — es a lo que se expande `%prefix%` en este archivo.

Las líneas se escriben con tokens de paleta de ExyliaLib (`{primary}`, `{success}`, `{error}`, …) en
vez de con hex, así que repintar el servidor entero desde `colors.yml` las repinta también. Los
placeholders que acepta cada línea están nombrados en el comentario que tiene encima.

| Sección | Qué hay dentro |
|---|---|
| `general` | recargado, solo-jugador, sin-permiso, cosmético / tipo / jugador desconocido, clave inválida, duración inválida |
| `entitlements` | concedido y sus dos líneas para el destinatario, revocado, las líneas de `list`, las de `check`, caducado, caducado-al-entrar, a-punto-de-caducar |
| `equip` | equipado, desequipado, desequipado-por-tipo, no-poseído, nada-equipado, todo-quitado |
| `favorites` | añadido, quitado |
| `loadouts` | guardado, aplicado, borrado, límite, desconocido, vacío, inválido, las líneas de `list` |
| `custom` | creado y su línea para el destinatario, editado, borrado, ninguno, no-es-tuyo, muy-corto, muy-largo, patrón, en-lista-negra, ocupado, color-inválido, demasiadas-paradas |
| `tokens` | sin-create, sin-edit, gastado, dado, quitado y fijado con sus líneas para el destinatario, las líneas de saldo, clase-desconocida, no-es-personalizado |
| `presets` | aplicado, aplicado-en-parte, no-poseído, desconocido, las líneas de `list` |
| `prompts` | los títulos y las pistas de las entradas de texto: etiqueta propia, color, editar cualquiera de las dos, nombre de loadout |
| `menu` | `types` (cómo se llama cada clase en títulos y lore), `status` (`selected`, `available`, `locked`, `expiring`), `favorite-on`, `favorite-off`, `none`, `sample-message`, `sample-prefix`, `custom-hints` |
| `admin` | las muestras que dibujan `/cca preview`, `render` y `chat line`, `permanent`, y los interruptores ON/OFF de las pantallas de admin del chat |
| `confirm` | las preguntas que se hacen antes de borrar algo, en los menús y en la línea de comandos |

El módulo de chat se queda con su propio `lang/<idioma>/chat/messages.yml`, con su propio prefijo. Un plugin de
chat habla como el chat, no como el plugin de cosméticos, así que el `%prefix%` de allí nunca se
expande a este. Ver [el módulo de chat](/docs/exyliachatcosmetics/chat).
