Every command, with the permission it needs. Players mostly use the menu from `/cc`; the commands are for people who prefer typing and for signs and buttons. Arguments tab-complete.

Three conventions:

- A cosmetic is always written `type:id`, for example `tag:mvp`, `chat_color:aurora` or `customtag:42`.
- `<player>` on an admin command accepts a player who is offline, as long as they have played on the server before.
- A command that deletes things (`delete`, `clear`, `remove`) only asks the first time. Run it again with `confirm` at the end to do it.

## Player commands

`/cc` and `/chatcosmetics` are the same command. Every one of them needs `exyliachatcosmetics.command.cosmetics`, which everybody has by default.

<Commands group="player" />

A command that belongs to a module only exists while that module is on in [Configuration](/docs/exyliachatcosmetics/configuration). With `shadows` off there is no `/cc shadows`, with `loadouts` off there is no `/cc loadout`. `/cc`, `favorites`, `equip`, `unequip`, `favorite` and `preview` always exist.

## Admin commands

`/cca` and `/chatcosmeticsadmin` are the same command. They need `exyliachatcosmetics.admin`, which only operators have until you grant it.

<Commands group="admin" />

`/cca reload` reloads `config.yml`, the catalogue files, the menus and the chat hook. Changing which modules are on needs a restart, because commands can only be added while the server starts.

## Chat module commands

These exist only while the chat module is on, and each one only while its own switch in `chat/config.yml` is on. See [Chat module](/docs/exyliachatcosmetics/chat).
