Find the message your players or your console shows, and follow the fix. For anything else check the [FAQ](/docs/exyliatotemtrainer/faq).

## "No arena is ready. Ask an administrator."

Solo training and duels both need a ready arena: **enabled**, with **both spawns set** in loaded worlds, and not at its `arena.max-matches-per-arena` limit.

1. Run `/totemtraineradmin` and click **Arenas**.
2. An arena marked incomplete is missing a spawn or is disabled. Open it, set **Spawn A** and **Spawn B**, and click **Status** to enable it.
3. If the spawns are in a world that is not loaded, load it or set the spawns again where it is.

Nothing can start in the first moments after boot, before the arenas have been read from the database: wait for `Loaded N arenas` in the console. See [Create and manage arenas](/docs/exyliatotemtrainer/arenas).

## A duel request is refused

- "`<name>` is busy right now": another Exylia plugin holds that player (an FFA arena, an event, a practice match). They have to leave first.
- "`<name>` is `<reason>`" with a reason such as "in a party" or "answering a duel request": nobody holds them, but a plugin asks to leave them alone.
- "Wait ... before challenging again": the request cooldown. It is `match.duel-request-cooldown` (15 seconds by default); set it to `0` to remove it.
- The request disappears: it expires after `match.duel-request-expiry` seconds (30 by default).

See [Set up duels](/docs/exyliatotemtrainer/duels) and [Compatibility](/docs/exyliatotemtrainer/compatibility).

## A command says to leave first

While training or in a duel, only the commands in `match.allowed-commands` run (`totem`, `tt`, `totemtrainer`, `msg`, `r`, `tell` and `w` by default). Anything else answers "Leave with /totem leave before using that command." Add the command's label to the list in `config.yml`, then run `/totemtraineradmin reload`.

## Players in a session cannot read the server chat

That is `chat.isolation`, on by default: the chat of a session or a duel stays inside it, and the rest of the server does not read it. Set it to `false` in `config.yml`, or switch off **Chat isolation** under **Settings**, **Records and chat** in the admin menu, to leave chat as your chat plugin delivers it.

## A player is not on the leaderboard

A board is built from training records, not from duels. A player appears after finishing a session in that mode. Boards are cached for `leaderboard.cache-seconds` (300 by default), so a new record can take a few minutes to show. A player whose profile was reset by an admin loses every record and leaves every board.

## Placeholders show their own name

Inside the plugin's own files they always resolve. In other plugins you need PlaceholderAPI installed. Also check you use `%exyliatotemtrainer_<name>%` and not the 1.0.0 `%exyliatotemtrainer_totem_<name>%`. See [Placeholders](/docs/exyliatotemtrainer/placeholders).

## The plugin does not start

ExyliaLib must be in `plugins/`: the plugin lists it as optional only so the loader can install it, but cannot run without it. PacketEvents is optional. The console should show `ExyliaTotemTrainer enabled`. See [Install ExyliaTotemTrainer](/docs/exyliatotemtrainer/installation).

## A menu does not open

A menu file with a syntax error is reported in the console and only that screen fails. Fix the line it names, or delete the file so the plugin writes a fresh one, then run `/totemtraineradmin reload`. Clicking a button without the matching permission does nothing; see [Permissions](/docs/exyliatotemtrainer/permissions).
