After this page the plugin is running and you can open its admin menu. It takes about two minutes.

## Before you start

You need Paper 1.21.1 or newer (Folia 1.21.4 or newer) and Java 21, plus **ExyliaLib**. The loader that comes with your download installs ExyliaLib for you; if you copy jars by hand, put ExyliaLib in `plugins/` first.

| Plugin | What for |
|---|---|
| ExyliaLib (required) | Menus, database, colours, messages and sidebars shared by every Exylia plugin. |
| PacketEvents (optional) | Hides players of different sessions from each other. Without it the plugin still loads and hides them the older way, with `hidePlayer`. |
| PlaceholderAPI (optional) | Lets other plugins use the [placeholders](/docs/exyliatotemtrainer/placeholders). Everything else works without it. |

## Steps

<Steps>
  <Step title="Add the jars">
    Copy `ExyliaTotemTrainer.jar` into the server's `plugins/` folder, with ExyliaLib if it is not there yet.
  </Step>
  <Step title="Start the server">
    The first boot writes the configuration files, the menus and the database tables.
  </Step>
  <Step title="Check the console">
    You should see `ExyliaTotemTrainer enabled`, then `Loaded 0 arenas`. Nothing can start before that second line appears.
  </Step>
  <Step title="Open the admin menu">
    With the `exyliatotemtrainer.admin` permission (operators have it), run `/totemtraineradmin`. Continue with [Your first arena](/docs/exyliatotemtrainer/first-steps).
  </Step>
</Steps>

## Check that it works

`/totem` opens the main menu with your profile, **Solo training**, **Duels**, **Leaderboards**, **Duel history** and **Leave**. If it says you do not have permission, see [Permissions](/docs/exyliatotemtrainer/permissions).

## The files it creates

Everything is in `plugins/ExyliaTotemTrainer/`.

| File | What it holds |
|---|---|
| `config.yml` | Language, modes, speeds, grading, duel formats and delays, leaderboards, history, arena limit, chat isolation. See [Configuration](/docs/exyliatotemtrainer/configuration). |
| `lang/<language>/messages.yml` | Every line the plugin sends, and the feedback shown per grade. |
| `lang/<language>/scoreboards.yml` | The two sidebars: training and duel. See [Scoreboards](/docs/exyliatotemtrainer/scoreboard). |
| `lang/<language>/menus/` | Every screen a player or admin sees. |
| `database.yml` | The database engine, written by ExyliaLib. H2 by default. |

`<language>` is English, Spanish, Portuguese, French, Russian or Turkish, chosen by `language` in `config.yml`. See [Configuration](/docs/exyliatotemtrainer/configuration#language).

<Callout type="warning" title="Do not edit menus/admin/">
The staff screens in `lang/<language>/menus/admin/` are rewritten from the plugin every time it starts, so a button added in a release reaches your server. Put your own changes in the other menu files.
</Callout>

## Where arenas and stats are kept

Arenas, profiles, training records and duel history are stored in the database, not in YAML. By default that is **H2**: a file inside the plugin folder, with nothing to install, fine for one server. To share arenas and stats between servers, point `database.yml` at MySQL, MariaDB, PostgreSQL or MongoDB. The file belongs to ExyliaLib; see [Database](/docs/exylialib/database).

Nothing waits on the database while the server starts: reads and writes are asynchronous, and a profile loads when its player joins.

## Updating

Replace the jar and restart. Your `config.yml`, `messages.yml`, `scoreboards.yml` and player menus are kept: a missing file or key is added, and a changed default waits in `/exylialib updates` for you to accept. A menu file with a syntax error is reported in the console and only that screen fails to open. Arenas and stats are in the database and are not touched.
