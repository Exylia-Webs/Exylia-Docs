`config.yml` holds every setting except the skins themselves. What a player reads — item names and
lore, the armour lore, the wardrobe wording and every message — lives in
`lang/<language>/messages.yml`. Defaults:

```yaml title="config.yml"
language: default

skin-item:
  material: ARMS_UP_POTTERY_SHERD
  glow: true

remover-item:
  material: SCRAPE_POTTERY_SHERD
  glow: true

armor-lore:
  enabled: true

behaviour:
  mode: both
  consume-remover: true
  consume-skin-item: true
  hide-without-permission: true
  disabled-worlds: []

effects:
  on-apply:
    sound:
      name: BLOCK_SMITHING_TABLE_USE
      volume: 1.0
      pitch: 1.2
      category: PLAYERS
  on-remove:
    sound:
      name: BLOCK_GRINDSTONE_USE
      volume: 1.0
      pitch: 1.0
      category: PLAYERS

showcase:
  locations: []
  pause-seconds: 3.0
  radius: 24.0
  only: []

crate:
  enabled: true
  # ... see The crate

shop:
  enabled: true
  tier-prices:
    common: 500
    rare: 1500
    epic: 4000
    legendary: 10000
```

## `language`

Which folder under `lang/` this plugin's menus and messages are read from.

| Value | What it means |
|---|---|
| `default` | Follow the language set in ExyliaLib's own `config.yml`. What a fresh install writes. |
| `en`, `es`, `pt`, `fr`, `ru`, `tr` | This plugin alone, in that language. All six ship. |
| `custom` | The files this server had before languages existed — see [Installation](/docs/exyliaarmorskin/installation#files). |

Any other code starts from the English files and is yours to rewrite. A line a translation leaves out
arrives in English. `/armorskinsadmin reload` picks a changed language up without a restart.

## `skin-item` and `remover-item`

How the system's two items are drawn. Their name and lore are in `messages.yml`.

| Key | What it does |
|---|---|
| `material` | The item's material. For the skin item this is only used when the skin sets no `icon`. |
| `glow` | Whether the item has the enchantment glint. Attributes are always hidden. |

## `armor-lore`

| Key | Default | What it does |
|---|---|---|
| `enabled` | `true` | Turn it off and skinned armour shows only its own lore. |

The lines themselves are `armor-lore` in `messages.yml`; `%skin%` is the skin's name. They are shown
after the armour's own lore, separated by a blank line.

<Callout type="note" title="These lines never touch the item">
They are written onto the copy that leaves the server, on every packet that carries the piece —
worn, in the hotbar, in a chest or on the cursor. Any plugin reading the armour's lore finds exactly
what the armour had, and `/data get` shows nothing extra.
</Callout>

## `behaviour`

| Key | Default | What it does |
|---|---|---|
| `mode` | `both` | `item`, `wardrobe` or `both`. See [The wardrobe](/docs/exyliaarmorskin/wardrobe). |
| `consume-skin-item` | `true` | Whether the skin item is used up when it is applied. Off means one item skins any number of pieces. |
| `consume-remover` | `true` | Whether the remover is used up when it removes a skin. |
| `hide-without-permission` | `true` | Whether armour whose skin the wearer may no longer use — no node and no unlock — is drawn as the real piece. Checked when the piece is equipped and by `/armorskinsadmin refresh`. |
| `disabled-worlds` | `[]` | Worlds where skins are not shown: armour there is drawn as the real piece. Names are matched ignoring case. |

Neither consume switch takes effect when the operation fails — a remover used on a player with a full
inventory stays on the cursor. See [Permissions](/docs/exyliaarmorskin/permissions) for what
`hide-without-permission` means in practice.

## `effects`

Two moments that belong to the system rather than to a skin. Both are full ExyliaLib effects — title,
action bar, boss bar, sound, particle and firework — and both are played to the player who did it.

| Key | Default | When |
|---|---|---|
| `on-apply` | `BLOCK_SMITHING_TABLE_USE`, volume 1.0, pitch 1.2, category `PLAYERS` | A skin was successfully dragged onto armour. |
| `on-remove` | `BLOCK_GRINDSTONE_USE`, volume 1.0, pitch 1.0, category `PLAYERS` | A skin was successfully taken off with a remover. |

A refused apply plays nothing, and neither does a skin applied through the
[API](/docs/exyliaarmorskin/api). Effects a **skin** declares for itself — equip, unequip, ambient and
the set bonus — live in [`skins.yml`](/docs/exyliaarmorskin/effects).

## `showcase`

Places that show skins off on their own, one after another, for whoever walks past: a lobby
centrepiece. Nobody has to own anything or do anything.

| Key | Default | What it does |
|---|---|---|
| `locations` | `[]` | Where showcases stand, as `server,world,x,y,z,yaw,pitch`. Set them with `/armorskinsadmin showcase add`, which writes where you stand and the way you face. |
| `pause-seconds` | `3.0` | The rest between one skin and the next. |
| `radius` | `24.0` | How close a player has to be for a showcase to play and to see it, in blocks. |
| `only` | `[]` | The skin ids a showcase picks from. Empty picks from every skin. |

Each turn a mannequin stands on the spot wearing the skin of a player watching, dressed in one skin on
every piece it fits — built on plain leather, whatever the watcher really wears — with the skin's name
floating above its head. It turns once, slowly, over six seconds so the skin is seen from every side,
and ends facing the way the showcase was placed. An animated skin keeps animating and the skin's
ambient particles are drawn around it; its sounds, titles and set messages are left out, because a
showcase has no wearer to speak to.

With nobody inside `radius` nothing plays, so an empty lobby costs one distance check a second. A
player whose cosmetics are hidden — staff on duty, for instance — is neither cast as the mannequin nor
shown it.

## `crate` and `shop`

## `messages.yml`

Every line the plugin sends, in `lang/<language>/messages.yml`. `%prefix%` expands to the `prefix`
value; `%skin%` is filled in on every message that names a skin.

| Key | Default | Tokens |
|---|---|---|
| `prefix` | `{primary}&lE-SKINS &8•&r ` | — |
| `applied` | `%prefix%{success}Skin {highlight}%skin% {success}applied.` | `%skin%` |
| `removed` | `%prefix%{success}Skin {highlight}%skin% {success}removed and returned to you.` | `%skin%` |
| `not-armor` | `%prefix%{error}That is not a piece of armor.` | — |
| `unsupported-piece` | `%prefix%{error}The skin {highlight}%skin% {error}does not fit that piece.` | `%skin%` |
| `unknown-skin` | `%prefix%{error}That skin no longer exists.` | `%skin%` |
| `already-skinned` | `%prefix%{warning}That armor already wears a skin. Use a remover first.` | — |
| `no-skin` | `%prefix%{warning}That armor wears no skin.` | — |
| `inventory-full` | `%prefix%{error}You need a free slot in your inventory.` | — |
| `no-permission` | `%prefix%{error}You do not own the skin {highlight}%skin%{error}.` | `%skin%` |
| `given` | `%prefix%{success}You received {highlight}%amount%x %skin%{success}.` | `%skin%`, `%amount%` |
| `given-remover` | `%prefix%{success}You received {highlight}%amount%x skin remover{success}.` | `%amount%` |
| `list-header` | `%prefix%{secondary}Available skins:` | — |
| `list-entry` | ` {letters_black}▎ {info}%id% {letters_black}» {letters}%skin% {letters_black}(%pieces%)` | `%id%`, `%skin%`, `%pieces%` |
| `list-empty` | `%prefix%{muted}No skins are registered.` | — |
| `refreshed` | `%prefix%{success}Appearance synchronised.` | — |
| `wardrobe-disabled` | `%prefix%{error}The wardrobe is off on this server.` | — |
| `wardrobe-cleared` | `%prefix%{success}Your wardrobe is empty again.` | — |
| `rewards-claimed` | Items kept for a player who had no room were handed over on join. | `%amount%` |
| `nothing-changed` | An admin write left the wardrobe as it was. | `%player%` |
| `showcase-added` · `showcase-removed` · `showcase-missing` | `showcase add` and `remove`. | `%location%` |
| `showcases-header` · `showcases-entry` · `showcases-empty` · `showcases-cleared` | `showcase list` and `clear`. | `%location%`, `%amount%` |
| `keys-given` · `keys-taken` | `keys` subcommands: to the admin, and to the player who lost keys. | `%player%`, `%amount%` |
| `unlock-granted` · `unlock-already` · `unlock-revoked` · `unlock-missing` · `unlocks-cleared` | `unlocks` subcommands. | `%skin%`, `%player%` |
| `crate-block-*` · `crate-blocks-*` | `crate block` subcommands. | `%location%`, `%amount%` |
| `crate-description` | The line under a skin on the crate reels: `{letters}Fits {info}%pieces%`. | `%pieces%` |

Then the sections:

| Section | What it holds |
|---|---|
| `skin-item` · `remover-item` | `name` and `lore` of the two items. `%skin%` and `%pieces%` on the skin item. |
| `key-item` | `name` and `lore` of the crate key that can be held. |
| `armor-lore` | The lines under skinned armour. `%skin%`. |
| `wardrobe` | What the wardrobe calls things: `full-set`, `helmet`, `chestplate`, `leggings`, `boots`, `empty`, and `piece-names` — how a piece is written inside a sentence, such as the pieces a skin fits. See [The wardrobe](/docs/exyliaarmorskin/wardrobe#wording). |
| `crate` | The crate's own lines: `won`, `duplicate`, `no-keys`, `busy`, `empty`, `disabled`, `keys-received`, `rewards-claimed`. See [The crate](/docs/exyliaarmorskin/crate). |

What a purchase says — the confirmation, success, not enough money — is ExyliaLib's, under `purchase`
in ExyliaLib's own `messages.yml`.

<Callout type="tip" title="The prefix belongs to this plugin alone">
`prefix` is registered with ExyliaLib on start and on every reload, so `%prefix%` written anywhere in
this plugin's own text resolves to it. Another Exylia plugin using `%prefix%` gets its own — the two
never collide.
</Callout>
