---
title: "Cooldowns"
description: "Cooldowns of special items and of vanilla items such as ender pearls, golden apples and totems: triggers, combat and region times, region use caps, the action bar, and the commands that change them."
---

One store holds every cooldown: those of special items and those the plugin puts on **vanilla items**. Both show
on the item as the vanilla cooldown sweep, on the action bar, and as a HUD cooldown on Lunar and Feather
clients.

Cooldowns of five minutes or more survive a restart; shorter ones are lost.

## Special items

Set with `cooldown:` on the item or on a feature. See [Special items](/docs/exyliaspecials/items#cooldown).

## Vanilla items

`vanilla-cooldowns:` in `config.yml` puts a cooldown on any vanilla material:

```yaml
vanilla-cooldowns:
  ENDER_PEARL:
    trigger: LAUNCH
    cooldown: 4.0
    combat-cooldown: 14.0
    display-name: '{primary}Ender Pearl'
    regions:
      crystal_hole: {cooldown: 1.0}
    worlds: {}
```

| Key | Default | What it does |
|---|---|---|
| `trigger` | see below | What starts the cooldown. |
| `cooldown` | | Seconds. |
| `combat-cooldown` | `-1` | Used instead while tagged; `-1` keeps `cooldown`. |
| `display-name` | the material | How the action bar names it. |
| `regions` | `{}` | Per WorldGuard region: `cooldown` and/or `max-uses`. |
| `worlds` | `{}` | Per world, the same keys. |

| Trigger | Starts when |
|---|---|
| `USE` | Right-clicking with the item. The default for what cannot be eaten. |
| `USE_ON_ELYTRA` | The same, only while gliding. |
| `CONSUME` | Eating or drinking it. The default for food. While cooling, eating does not start. |
| `LAUNCH` | Throwing it: ender pearls, snowballs, eggs and potions. |
| `BOW_SHOOT` | Shooting a `BOW` or `CROSSBOW`. |
| `ELYTRA_BOOST` | Boosting with a firework while gliding. |
| `RESURRECT` | A totem saving its holder. While cooling the totem does not work: the player dies. |

While the item is cooling, using it is refused silently; the action bar shows how long is left. A vanilla
cooldown shorter than the plugin's — the pearl's own — is replaced by the plugin's.

Special items never take vanilla cooldowns, even when they share the material.

### Which time applies

1. A `worlds` entry for the world the player is in.
2. A `regions` entry for a region they stand in, highest WorldGuard priority first.
3. `combat-cooldown` when they are tagged.
4. `cooldown`.

A result of 0 starts nothing. Region ids are case-insensitive; world names are not.

### Region use caps

```yaml
ENCHANTED_GOLDEN_APPLE:
  trigger: CONSUME
  cooldown: 300.0
  regions:
    pot: {max-uses: 1}
```

`max-uses` counts each use while standing in that region; once reached, the item is refused there. The action bar
shows the count, for example `Enchanted Golden Apple 1/1 ⚠`. Counts are kept in memory and start again after a
restart **or** `/specialsadmin reload`.

### The defaults

| Material | Trigger | Cooldown | In combat | Regions |
|---|---|---|---|---|
| `ENCHANTED_GOLDEN_APPLE` | `CONSUME` | 300 s | — | `pot`, `mazoswap`, `mazo`: 1 use |
| `TOTEM_OF_UNDYING` | `RESURRECT` | 0 | — | `pot`, `mace`: 4 uses |
| `ENDER_PEARL` | `LAUNCH` | 4 s | 14 s | `crystal_hole`, `crystal_flat`, `mace`: 1 s |
| `GOLDEN_APPLE` | `CONSUME` | 3 s | — | `crystal_hole`, `crystal_flat`: 2 s |
| `FIREWORK_ROCKET` | `ELYTRA_BOOST` | 12 s | — | `__global__`: 0 |

The region names are examples from a practice server; they do nothing where those regions do not exist. Replace
them with yours.

<Callout type="warning" title="__global__ never matches">
The `__global__` rule on `FIREWORK_ROCKET` is never applied: the plugin only sees regions placed in the world, not
the global one. The 12-second elytra boost cooldown therefore applies everywhere. Remove the entry, or set
`cooldown` itself to what you want.
</Callout>

## The action bar

While anything is cooling the action bar lists it: combat first, then each special item, each vanilla cooldown,
and the use counts of the region the player stands in.

```text
⚔ Combat 12s ⌚ | FREEZE 24s ⌚ | Ender Pearl 3s ⌚
```

| `actionbar.` | Default | |
|---|---|---|
| `enabled` | `true` | |
| `update-ticks` | 2 | |

The layout — `separator`, `format`, `format-limited`, `prefix`, `combat-format` — is under `actionbar` in
`messages.yml`. Lunar and Feather players get the HUD cooldowns instead, and do not see the action bar, so they
never see region use counts.

## Commands

| Command | |
|---|---|
| `/specialsadmin cooldown set <player> <id> <seconds>` | Sets it; 0 clears. Up to 86400. |
| `/specialsadmin cooldown add <player> <id> <seconds>` | Adds to what is left. |
| `/specialsadmin cooldown decrease <player> <id> <seconds>` | Takes from what is left. |
| `/specialsadmin cooldown remove <player> [id]` | Clears it; every cooldown without an id. |

`<id>` is a special item id, `vanilla:<material>` such as `vanilla:ender_pearl`, or `ALL`. All need
`exyliaspecials.admin.cooldown`.

The **Your cooldowns** screen of `/specialsadmin` lists your own special item cooldowns; a click clears one, and
**Clear all** clears every cooldown you have, vanilla ones included.
