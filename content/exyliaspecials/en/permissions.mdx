Every permission is for operators only until you give it to someone. With LuckPerms:
`/lp group admin permission set exyliaspecials.admin.give.item true`.

<Permissions />

`exyliaspecials.admin.combat` is gone: combat moved to ExyliaCombat, which still honours the old
`exyliaspecials.combat.bypass` as `exyliacombat.bypass`. See
[Combat](/docs/exyliaspecials/combat).

## Wildcards

`exyliaspecials.*` includes `exyliaspecials.admin.*` and `exyliaspecials.duel.bypass`. `exyliaspecials.admin.*` and
`exyliaspecials.admin` both include every `exyliaspecials.admin.<something>` node above.

## Using items

No permission is needed to use special items. To restrict one, give it a `permission:` — on the item, or on a
single feature or step. See [Special items](/docs/exyliaspecials/items#permission).

## The menu

`exyliaspecials.admin` opens the admin menu. Each button then checks the node of the matching command:
`exyliaspecials.admin.give.item`, `.give.stattrack`, `.cooldown` and `.arena`. A player given only some of those
nodes can use only those buttons. The menu's actions (`exyliaspecials:admin_*`, `exyliaspecials:settings`) check
the node themselves, so another plugin's menu cannot hand them to players without it. See
[Commands](/docs/exyliaspecials/commands#the-admin-menu).

<Callout type="note" title="Wildcards and the loader jar">
The `plugin.yml` inside `Exylia-Specials-Loader.jar` does not declare `exyliaspecials.admin.arena` or
`exyliaspecials.duel.bypass`, so a wildcard given to a non-operator may not include them. Give those two nodes by
name.
</Callout>
