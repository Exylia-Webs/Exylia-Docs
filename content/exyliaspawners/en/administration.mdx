`/spawnersadmin` opens the admin hub (needs `exyliaspawners.admin`). Its header counts the spawner blocks placed,
the types and the tiers; its cards open the editors and the dashboard. Every admin screen checks the permission
again on each click.

## Editors

Every change an editor makes is written into `types.yml` or `tiers.yml` and applied at once, without a reload.
Hand edits to those files and in-game edits are the same thing.

### Spawner types

`/spawnersadmin editor` (or `editor types`, or **Spawner types** on the hub) lists every type with how many
spawners of it are placed. A type's screen:

| Card | Does |
|---|---|
| Header | Enables or disables the type. |
| **Production mode** | Switches between VIRTUAL, CLASSIC and following the tier. |
| **Experience** | Sets the experience per mob. |
| **Stack limit** | Left-click sets it; shift-left-click makes it follow the tier. |
| **Loot table** | Opens ExyliaLib's loot editor on the type's loot lines. |
| **Take one** | Gives you one spawner of this type at the lowest tier. |
| **Delete type** | Removes it, after a confirmation. Refused while spawners of it are placed. |

**Create type** starts a wizard: an id, then what it makes. A **mob** picks an entity from a searchable list and
starts with its vanilla drops and experience; an **item spawner** asks you to click a chest in the world and turns
each stack in it into a loot line (always dropped, from one up to that stack's size). Nothing is written until the
summary is confirmed. `MOB` types (ExyliaMobs templates) are written in `types.yml` by hand.

### Tiers

`/spawnersadmin editor tiers` (or **Tiers**) lists the tiers. A tier's screen has one card per track: left-click
edits the values per level (typed as `20, 18, 16`), right-click edits the cost formula, checked before it is saved.
Then the production mode, the stack limit, and **Delete tier**, refused for the last tier and while spawners of it
are placed. **Create tier** adds the next number.

### Loot

**Loot** on the hub lists every type; a click opens its loot editor directly.

### Web editor

`/spawnersadmin editor web` opens `types.yml`, `tiers.yml` and every other file of the plugin in the browser,
through [ExyliaLib's web editor](/docs/exylialib/web-editor), when it is set up on the server.

## Economy dashboard

`/spawnersadmin dashboard` (or **Economy dashboard** on the hub) shows what spawners put into the economy, live:

| Card | Shows |
|---|---|
| **Economy** | Money from sales and experience produced in the last hour on this server, spawner blocks and spawners in them. |
| **Top spawners** | The spawners that sold the most in the last hour, with owner, place, tier, stack, money and experience per hour. A click teleports you there. |
| **Top owners** | The players whose spawners sold the most. |
| **By type** | What each type made. |
| **Anti-inflation cap** | The `corruption.cap` in force. See [Corruption](/docs/exyliaspawners/corruption#the-anti-inflation-cap). |
| **Discord alerts** | Whether alerts run, and their two thresholds. |

The figures are a rolling hour kept in memory, in the default currency: they start empty after a restart.

### Discord alerts

An abnormal sell rate is the earliest sign of a dupe or a mispriced item. With a webhook and at least one threshold
set, the plugin posts to Discord when one owner's spawners, or the whole server's, sold more than that in the last
hour:

```yaml
dashboard:
  webhook: 'https://discord.com/api/webhooks/...'
  owner-money-per-hour: 500000
  server-money-per-hour: 5000000
  check-every: 1m
  cooldown: 30m
```

At most one alert per owner, and one for the server, per `cooldown`. The messages are ExyliaLib webhook templates
(`owner-alert`, `server-alert`) with the placeholders `%owner%`, `%owner_head%`, `%money%`, `%threshold%` and
`%spawners%` (the server alert has no owner). See [ExyliaLib Discord webhooks](/docs/exylialib/discord-webhooks).
Alerts are off while the webhook is empty or both thresholds are 0.

## The audit log

Every action on a spawner is written to ExyliaLib's staff log, read with `/exylialib logs <player> ExyliaSpawners`:

| Action | When |
|---|---|
| `spawner-place`, `spawner-stack`, `spawner-break`, `spawner-explode` | Placing, stacking, mining or picking up, and explosions. |
| `spawner-convert`, `spawner-egg` | A vanilla spawner converted, a type changed with eggs. |
| `spawner-give` | `/spawnersadmin give` and the editor's **Take one**. |
| `spawner-item-rejected` | A copied, reused or edited spawner item refused. |
| `spawner-withdraw`, `spawner-xp`, `spawner-sell` | Items taken, experience claimed, storage sold (autosell marked). |
| `spawner-upgrade`, `spawner-booster` | A level bought, a booster given, inserted or taken out. |
| `spawner-trust`, `spawner-untrust` | Trust changes. |
| `spawner-corrupt`, `spawner-repair`, `spawner-corruption-loss` | Corruption. |
| `spawner-import` | An import run. |
| `spawner-removed` | A record dropped because its block is no longer a spawner, with what its storage held. |

## Snapshots

With `snapshots.enabled` on (the default), the plugin copies its whole database into `snapshots/` every
`snapshots.interval` (6 hours), keeping the newest `snapshots.keep` (8). Storage is written first, so a snapshot
holds what players see. Restore one with `/exylialib import ExyliaSpawners <file>`.

## Reloading

`/spawnersadmin reload` reads `config.yml`, the messages, `types.yml`, `tiers.yml`, `boosters.yml`, the items and
the menus again, and restarts the timers. It answers with the number of problems found in the types and tiers,
listed in the console. `network.enabled` needs a restart.
