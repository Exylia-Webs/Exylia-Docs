ExyliaSpawners registers no `%exyliaspawners_...%` placeholders with PlaceholderAPI: its values describe one spawner, so they exist only in the screens, the hologram and the items that show that spawner. Use this page to restyle those files. Values that move (stack, storage, countdowns) update while a screen is open. PlaceholderAPI placeholders still work in the hologram lines.

## Values of a spawner

The hub, the storage and every row of **My spawners** (`menus/hub.yml`, `menus/storage.yml`, `menus/my_spawners.yml`) read the spawner and storage values. Each feature adds its own values by name. The last three rows show the names `hologram.yml` uses in `lines` and `optional-lines`; its lines can also use every value below that is about a feature.

The storage screen adds `%can_sell%` and `%bedrock%` (`true` or `false`) and, on each row, `%item_material%`, `%item_name%`, `%item_amount%` and `%can_sell_line%`. **My spawners** adds `%owned_count%` and, on each row, `%remote_line%`, which hides its line for players without `exyliaspawners.remote`.

The upgrades screen has, per track (`speed`, `amount`, `storage`, `xp`), `%<track>_level%`, `%<track>_max%`, `%<track>_value%`, `%<track>_next%`, `%<track>_cost%` and `%<track>_prompt%`. The boosters screen has, per kind, `%<kind>_state%` and `%<kind>_prompt%`. The corruption screen adds `%corruption_effect_info%`, `%cleanse_cost%`, `%cleanse_range%`, `%cleanse_time%` and `%cleanse_grace%`. The trust screen has `%trusted_count%`, `%can_manage%` and, on each row, `%player_name%`, `%trusted_since%` and `%manage_line%`.

Items: `spawner-item.yml` uses `%type%`, `%type_upper%`, `%tier%`, `%stack%` and `%mode%`. `booster-item.yml` uses `%kind%`, `%kind_upper%`, `%multiplier%` and `%time%`.
</Details>

## Holograms

The hologram (`hologram.yml`) reads the spawner and storage values and every feature value in its `lines` and `optional-lines`. The rows grouped under hologram in the table above are the names it has of its own. See [Holograms and anti-ESP](/docs/exyliaspawners/holograms-and-anti-esp#holograms).

## Show the feature lines

`%feature_lines%` lists every feature value as ready lore lines. Its labels come from `menus.feature-labels` in `messages.yml`, which is empty by default, so each name shows in English title case in every language (`corruption_state` reads "Corruption state"). Add the labels you want, for example `corruption_state: Corruption`, or replace `%feature_lines%` in `hub.yml` with the single values you choose.
