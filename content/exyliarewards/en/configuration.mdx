Most of what you manage is a menu, not a file: rewards, AFK zones, codes, piñatas and battle pass seasons are
created in game and live in the database. Open this page for the few settings that live in files.

Everything sits in `plugins/ExyliaRewards/` and is generated on first start with comments on every key:

```text
plugins/ExyliaRewards/
├── config.yml      settings (this page)
├── discord.yml     webhook announcements (below)
├── votes.yml       vote sites and what votes pay
├── referrals.yml   what referrals pay
└── lang/<code>/    messages.yml and menus/
```

Apply a change with `/rewardsadmin reload`, except where a key says it needs a restart. What votes and referrals
pay is in [Votes](/docs/exyliarewards/votes) and [Referrals](/docs/exyliarewards/referrals). Keys in minutes,
hours or days take a bare number in that unit, or a duration such as `30m`, `2h` or `14d`. Sounds are written
`NAME|volume|pitch`.

## Language

`language: default` follows the language set in ExyliaLib; a code such as `en`, `es`, `fr`, `pt`, `ru` or `tr`
sets this plugin alone. Each is a folder under `lang/` you can edit, and a key a language lacks falls back to
English. See [Messages and languages](/docs/exylialib/messages-and-languages).

## Modules and the clock

Switch a module off under `modules` (rewards, afk-zones, votes, referrals, battle-pass; all on by default). This
needs a restart. The `clock` section is the one calendar every daily, weekly and monthly reward, streak, login
calendar and vote day follows: set `clock.timezone` (such as `Europe/Madrid`; empty uses the server's),
`clock.reset-hour` and `clock.weekly-reset-day`.

<Details title="All keys: language, modules, clock, notifications, freezes, currency">

| Key | Default | What it does |
|---|---|---|
| `language` | `default` | See Language above. |
| `modules.rewards` | `true` | Claimable rewards, login calendars and `/redeem` codes. |
| `modules.afk-zones` | `true` | AFK zones. |
| `modules.votes` | `true` | Votes, vote streaks and the vote party. |
| `modules.referrals` | `true` | Referrals. |
| `modules.battle-pass` | `true` | The battle pass. |
| `clock.timezone` | `''` | The timezone the reset hour is read in. Empty, or an unknown zone, uses the server's. |
| `clock.reset-hour` | `0` | The hour of the day, `0`–`23`, days start at. |
| `clock.weekly-reset-day` | `MONDAY` | The day weekly rewards reset on, `MONDAY` to `SUNDAY`. |
| `notifications.ready-on-join` | `true` | Tells a player on join how many rewards are ready. |
| `notifications.toasts` | `true` | Says "N rewards ready" with an advancement toast instead of chat lines. |
| `notifications.toast-cooldown-minutes` | `30` | Minutes between two toasts to one player. Joining always shows one. |
| `notifications.toast-icon` | `NETHER_STAR` | The toast's icon. |
| `streak-freezes.price` | `0.0` | What one freeze costs with `/rewards freeze buy`, in `currency`. `0` means not for sale. |
| `streak-freezes.max` | `5` | The most one player may hold; buying stops there. `0` for no limit. |
| `currency` | `''` | The currency the plugin's own prices are charged in: freezes, missed calendar days, battle pass skips and premium. Any currency ID from ExyliaLib's `economy.yml`; empty is the default currency. |

Players turn the notices off for themselves in ExyliaLib's `/settings`. Money inside reward lists names its own
currency per entry; see [Economy](/docs/exylialib/economy) and [Rewards in ExyliaLib](/docs/exylialib/rewards).

</Details>

## AFK zones, votes, referrals and codes

The zones themselves are made in game with `/afkzonesadmin`; the vote party is also edited in game with
`/voteadmin`, which writes its keys back to `config.yml`.

<Details title="All keys: afk-zones, votes, votes.party, referrals, redeem">

| Key | Default | What it does |
|---|---|---|
| `afk-zones.enter-sound` | `BLOCK_NOTE_BLOCK_PLING\|0.7\|1.4` | Played on entering a zone. |
| `afk-zones.reward-sound` | `ENTITY_EXPERIENCE_ORB_PICKUP\|0.7\|1.2` | Played on every payout. |
| `votes.reminder-minutes` | `30` | Minutes between reminders to players who have not voted today. `0` never. Needs a restart. |
| `votes.remind-on-join` | `true` | Reminds a player who has not voted today as they join. |
| `votes.remember-votes-days` | `14` | Days a vote is remembered after it arrived, so a copy Votifier forwards late is not paid again. Keep it longer than any server may stay down. |
| `votes.pending-vote-days` | `30` | Days a vote waits for a player who never joins before it is dropped. `0` keeps them for ever. |
| `votes.party.target` | `50` | Votes the whole network needs for a party. `0` turns the party off. |
| `votes.party.bossbar-seconds` | `8` | How long the progress bar stays after a vote, with `bar-mode: AFTER_VOTE`. |
| `votes.party.bar-mode` | `AFTER_VOTE` | `AFTER_VOTE` shows the bar for a moment after each vote; `ALWAYS` keeps it on screen for everybody while there is a target. |
| `votes.party.milestones` | `[10, 5, 1]` | Votes left at which every server tells its players how close the party is. |
| `votes.party.mode` | `REWARDS` | `REWARDS` pays everybody online, `PINATA` sends a piñata to one server, `BOTH` does the two. Without a piñata or a spawn point, it pays. |
| `votes.party.countdown.seconds` | `10` | How long the countdown between the target and the party lasts. `0` starts the party at once. |
| `votes.party.countdown.tick-sound` | `BLOCK_NOTE_BLOCK_HAT\|0.7\|1.2` | Played every second once the melody is over. Empty for none. |
| `votes.party.countdown.end-sound` | `ENTITY_PLAYER_LEVELUP\|0.7\|1.0` | Played as the countdown ends. |
| `votes.party.countdown.melody` | a short bell fanfare | Played as the countdown starts, as ExyliaLib sequence lines (`[DELAY] 0.2`, `[SOUND] NAME;volume;pitch`). See [Sequences](/docs/exylialib/sequences). |
| `referrals.join-window-hours` | `72` | Hours after their first join anywhere on the network during which a player can still name who invited them. |
| `referrals.qualify-minutes` | `60` | Minutes the new player has to play, idle time not counted, before both are rewarded. |
| `referrals.block-same-address` | `true` | Refuses a referral between two accounts that used the same address within the last 30 days, on any server, or are online from it now. |
| `redeem.max-failed-attempts` | `5` | Wrong codes in a row before the lockout. `0` never locks. |
| `redeem.lockout-minutes` | `10` | How long the lockout lasts, on every server of the network. |

</Details>

## Battle pass

Seasons, tiers and missions are built in game with `/battlepassadmin`; `battle-pass` holds the defaults a new
season starts with, the prices and the XP rules. See [Battle pass](/docs/exyliarewards/battle-pass).

<Details title="All keys: battle-pass">

| Key | Default | What it does |
|---|---|---|
| `battle-pass.network` | `default` | Which servers share one pass: `default` (ExyliaLib's network group), `global`, `server` or a group's name. Needs a restart. |
| `battle-pass.season-days` | `60` | Days a new season lasts when it is created. |
| `battle-pass.grace-days` | `7` | Days after a season ends in which players may still claim what they earned. |
| `battle-pass.deliver-unclaimed` | `true` | Delivers rewards earned but never claimed when the grace days end. |
| `battle-pass.auto-claim` | `false` | Claims tiers the moment they are reached, instead of from the pass. |
| `battle-pass.default-tiers` | `50` | Tiers a new season has. |
| `battle-pass.default-tier-xp` | `1000` | XP each tier of a new season costs. |
| `battle-pass.highlight-every` | `10` | Every how many tiers one is a highlight, shown as the next goal. `0` none. |
| `battle-pass.playtime-xp` | `10` | XP every minute played, idle minutes not counted. `0` none. |
| `battle-pass.daily-missions` | `3` | Daily missions drawn for each player every day. |
| `battle-pass.spawner-mobs` | `false` | Whether mobs from spawners count towards missions. |
| `battle-pass.same-victim-minutes` | `10` | Minutes in which killing the same player again does not count. |
| `battle-pass.flush-seconds` | `30` | Seconds between writes of mission progress and XP. Players leaving always write. |
| `battle-pass.catch-up` | `1.5` | XP multiplier for a player behind the tier the season expects by this week; it falls linearly to x1 at that tier. `1` is off. |
| `battle-pass.daily-rerolls` | `1` | Daily missions a player may swap for another each day. |
| `battle-pass.premium-rerolls` | `3` | The same, with premium. |
| `battle-pass.bonus-tier-xp` | `2500` | XP each bonus tier past the last tier costs, paid from the season's bonus pool. `0` none. |
| `battle-pass.bonus-weekly-cap` | `7` | Bonus tiers one player may claim each week. `0` no limit. |
| `battle-pass.skip-price` | `0.0` | What skipping one tier costs, in `currency`. `0` not for sale. |
| `battle-pass.skip-cap` | `20` | Tiers one player may skip with money in one season. |
| `battle-pass.premium-price` | `0.0` | What the premium pass costs for one season, in `currency`. `0` not for sale. |
| `battle-pass.booster-cap` | `3.0` | The highest XP multiplier boosters and catch-up reach together. |
| `battle-pass.prestige` | `false` | Lets a player past the last tier start over with one more prestige; they earn the free track again, premium pays once. |
| `battle-pass.vote-xp` | `0` | XP for each vote paid out. |
| `battle-pass.reward-xp` | `0` | XP for each reward claimed in the rewards module. |
| `battle-pass.referral-xp` | `0` | XP for the referrer when someone they invited has played long enough. |

</Details>

## discord.yml

Announcements to a Discord channel through a webhook, off until you set `enabled: true`. Create the webhook in
Discord (channel settings, Integrations, Webhooks) and paste its URL into `webhook`.

<Details title="All keys: discord.yml">

| Key | Default | What it does |
|---|---|---|
| `enabled` | `false` | Whether anything is sent. |
| `webhook` | `''` | The webhook URL, `https://discord.com/api/webhooks/...`. A URL Discord refuses turns the announcements off, said once in the console. |
| `streak-from` | `30` | A streak is announced on this day… |
| `streak-every` | `30` | …and every this many days after it. `0` announces only `streak-from`. |
| `battle-pass-seasons` | `false` | Announces a battle pass season starting and ending. |
| `battle-pass-highlights` | `false` | Announces a player reaching a highlight tier. |
| `vote-party` | | A vote party started. `%target%` is the votes it took, `%mode%` what it does. |
| `streak` | | A streak milestone of a reward or of votes. `%player%`, `%reward%`, `%streak%`, and `%player_head%` for the image. |
| `calendar-complete` | | Every day of a login calendar claimed. `%player%`, `%reward%`. |
| `code-redeemed` | | A redeem code's last use taken. `%code%`, `%uses%`. |
| `season-started` | | A season began. `%season%`, `%tiers%`, `%days%`. |
| `season-ended` | | A season ended. `%season%`, `%days%` (the grace days left to claim). |
| `highlight-tier` | | A player reached a highlight tier. `%player%`, `%tier%`, `%season%`, and `%player_head%` for the image. |

Each message is an ExyliaLib webhook template with its own `enabled` switch, title, description, colour,
fields and buttons; see [Discord webhooks](/docs/exylialib/discord-webhooks).

</Details>

## Messages and menus

Every line a player reads is in `lang/<language>/messages.yml`: the rewards lines at the top, then
`labels`, `prompts`, and a section per module. Colours are palette tokens (see [Colours](/docs/exylialib/colours)),
so recolouring the server never means editing them. A message may open with `[sound:NAME|volume|pitch]`, which
plays a sound and never reaches the screen, and a line may open with `[center]`. `%prefix%` is replaced by the
`prefix` value; an empty message is not sent.

The player screens in `lang/<language>/menus/user/` are yours to restyle: an update only adds what is missing.
The editors in `menus/admin/` are regenerated from the jar on every start. See
[Edit menus](/docs/exylialib/edit-menus).
