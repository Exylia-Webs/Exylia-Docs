Make a code such as `SUMMER` that players type with `/redeem SUMMER` to receive a reward list, with limits per player and for the whole network, an expiry and an optional permission. Codes are stored in the database, so a code made on one server works on all of them.

## Before you start

- You hold `exyliarewards.admin`. Players need `exyliarewards.redeem`, which everyone has by default.
- Decide what the code gives. It uses ExyliaLib's [reward editor](/docs/exylialib/rewards).

## Steps

<Steps>
  <Step title="Open the codes screen">
    Run `/rewardsadmin codes`, or click **Redeem codes** in `/rewardsadmin`.
  </Step>
  <Step title="Create the code">
    Click **Codes ▸ Create code**. It asks four things in order:

    - **The code**: 3 to 32 letters, digits, `-` or `_`, not already taken. Case does not matter when a player types it.
    - **Uses across the network**: how many redemptions in total. `-1` for unlimited.
    - **Uses per player**: how many times one player may redeem it. `-1` for unlimited.
    - **Expires in**: a duration such as `7d` or `12h`, counted from now. `0` for never.
  </Step>
  <Step title="Fill in what it gives">
    A new code is enabled and gives nothing. Right-click it to open its reward list and add items, money, commands and the rest.
  </Step>
  <Step title="Lock it to a permission (optional)">
    Shift + left-click the code and type a permission node; leave it blank for none. A player without it is refused without using one of the code's uses.
  </Step>
</Steps>

## Check that it works

Ask a player (or use another account) to run `/redeem <code>`. They get a confirmation and the reward list. Run it a second time: with one use per player they are told they already redeemed it. The code's card in the screen shows whether it is active, expired or used up.

## Going further

### What each click does

| Click on a code | Does |
|---|---|
| Left | Enables or disables it. |
| Right | Edits its rewards. |
| Shift + left | Sets a permission needed to redeem it; blank for none. |
| Shift + right | Deletes it, after asking. Who redeemed it is forgotten. |

### Stop code guessing

A disabled code and a code that does not exist read the same to the player: "not a valid code". Each counts as a wrong code. After `redeem.max-failed-attempts` wrong codes in a row (default `5`), the player is locked out of `/redeem` for `redeem.lockout-minutes` (default `10`), on every server of the network. A working code resets the count. `0` attempts never locks. You can change both in `/rewardsadmin`, **Plugin ▸ Settings**, **Redeem codes**.

### Announce the last use

A redemption that takes a code's last use can be announced on Discord with `code-redeemed` in `discord.yml`. See [Discord webhooks](/docs/exylialib/discord-webhooks).

<Details title="Technical details">

`/redeem <code>` checks, in order: a player locked out is told how long is left; a code with a permission the player lacks is refused; the code is redeemed if it exists, is enabled, has not expired, has uses left on the network and the player has uses left. When several servers try the last use at once, exactly one wins. What it gives is delivered by id, boosted for the `rewards` source like any reward.

The wrong-code count is kept by the server the player is on, until a redemption or a lockout; the lockout itself is shared by the network.

</Details>
