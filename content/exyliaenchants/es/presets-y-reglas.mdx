Dos herramientas deciden qué hace un encantamiento y dónde. Un **preset** decide qué encantamientos existen en el servidor. Las **reglas** (`rules.yml`) deciden dónde y para quién un encantamiento que existe es más débil o está desactivado.

## Presets

Define `preset` en `config.yml`:

| Preset | Qué existe | Economía |
|---|---|---|
| `survival` | Todo | Activada |
| `pvp` | Sin encantamientos solo PvE ni maldiciones | Activada |
| `vanilla-plus` | Solo encantamientos comunes y raros | Desactivada: sin libros, pergaminos ni encantador |
| `auto` | Se resuelve una vez en el primer arranque | |

`auto` elige `pvp` cuando está instalado ExyliaPracticeCore, ExyliaFFA o ExyliaPracticeBotV3 y no lo está ninguno de ExyliaMines, ExyliaSurvivalCore o ExyliaEconomy. En caso contrario elige `survival`. El resultado se escribe en el archivo, así que añadir un plugin más tarde no lo cambia.

Para quitar un encantamiento, no un grupo, usa `disabled-enchants`. Consulta [Obtener encantamientos](/docs/exyliaenchants/obtener-encantamientos).

## Reglas

`rules.yml` contiene reglas con nombre. Una regla se aplica cuando se cumplen todas las condiciones que define. Una lista vacía coincide con cualquier cosa.

| Clave | Significado |
|---|---|
| `worlds` | Nombres de mundo |
| `regions` | Políticas de región de ExyliaLib o regiones de WorldGuard. Consulta [Regiones](/docs/exylialib/regiones) |
| `modes` | Modos: un id de Modes de ExyliaLib, o `duels-ranked`, `duels`, `duels-bot`, `ffa`, `event` |
| `permission` | Se aplica solo a quien tiene este permiso |
| `only` | Los encantamientos que toca la regla. `*` para todos |
| `disable` | Encantamientos desactivados mientras se aplica la regla |
| `scale` | Multiplicadores. `all: 0.75` es el 75% |

Selectores para `only` y `disable`:

| Selector | Coincide con |
|---|---|
| `*` | Todos los encantamientos |
| `bleed` | Un encantamiento por id |
| `rarity:epic` | Una rareza: common, rare, epic, legendary o curse |
| `mode:pvp` | El modo de un encantamiento: pvp, pve o both |
| `area` | Encantamientos que rompen bloques o golpean a muchas entidades |
| `file:melee` | Todos los encantamientos de `enchants/melee.yml` |

Se aplican todas las reglas que coinciden: sus factores se multiplican y cualquier `disable` que coincida gana. Una regla se comprueba cuando una habilidad se va a ejecutar, así que basta con `/enchantsadmin reload`.

El archivo incluye dos reglas:

```yaml
rules:
  duels-ranked:
    modes: [duels-ranked]
    only: ["*"]
    disable: ["rarity:legendary"]
    scale: { all: 0.75 }
  spawn:
    regions: [spawn]
    only: ["*"]
    disable: [area]
```

Los encantamientos legendarios están desactivados en los duelos clasificatorios y todos los demás encantamientos hacen el 75% de sus números. Los encantamientos de área están desactivados en una política de región llamada `spawn`.

<Callout type="note" title="Claves de scale">
En la 1.1.0 solo se aplica `scale: { all: ... }`. Escala los números del encantamiento, como el daño y la curación, y no su probabilidad ni su enfriamiento. Las claves por número que menciona el comentario del archivo (`damage`, `chance`, `duration`, `radius`) se aceptan, pero todavía no se leen.
</Callout>

### Los límites propios de un encantamiento

El mismo motor ejecuta las claves `worlds`, `regions` y `permission` en el archivo de un encantamiento, solo para ese encantamiento:

```yaml
frostbite:
  worlds: { allow: [world_pvp] }
  regions: { deny: [spawn] }
  permission: vip.enchants
```

`allow` significa solo esos mundos, `deny` significa nunca esos. Quien no tiene el permiso lleva el encantamiento, pero sus habilidades no se ejecutan.

### Modos

Los modos vienen de otros plugins: una reclamación de Modes de ExyliaLib, luego las partidas de ExyliaPracticeCore (`duels-bot`, `duels-ranked`, `duels`), un duelo de ExyliaDuels (`duels`), una arena de ExyliaFFA (`ffa`) y jugar un evento de ExyliaEvents (`event`). Consulta [Integraciones](/docs/exyliaenchants/integraciones).
