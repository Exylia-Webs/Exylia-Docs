ExyliaEnchants guarda sus archivos en `plugins/ExyliaEnchants/`. Edítalos y ejecuta `/enchantsadmin reload`, salvo donde una sección diga que hace falta un reinicio. La mayoría de los ajustes que un administrador toca también tienen pantallas: ejecuta `/enchantsadmin` y abre **Ajustes** (Visualización, Economía, Integraciones, Obtención y Presupuesto de poder). Cómo funcionan esas pantallas está en [Pantallas de ajustes](/docs/exylialib/config-menus).

| Archivo | Qué contiene |
|---|---|
| `config.yml` | Idioma, preset, modo de visualización, tooltip, presupuesto, interruptores de obtención |
| `economy.yml` | Probabilidades de libros, polvo, gemas, el encantador |
| `rules.yml` | Reglas por mundo, región, modo y permiso |
| `integrations.yml` | Integraciones con la suite |
| `balance.yml` | Muñeco, simulación, métricas, umbrales de valores atípicos |
| `menus.yml` | Vistas previas del catálogo |
| `sets.yml` | Bonus de conjuntos de armadura |
| `sequences.yml` | Los efectos visuales que reproducen los encantamientos |
| `enchants/*.yml` | El catálogo de encantamientos |
| `lang/<code>/` | Mensajes, menús, pantallas y objetos de apoyo |

## config.yml

| Clave | Por defecto | Significado |
|---|---|---|
| `language` | sigue a ExyliaLib | Idioma de mensajes y menús |
| `debug` | `false` | Salida extra en la consola |
| `preset` | `auto` | `auto`, `pvp`, `survival` o `vanilla-plus`. Consulta [Presets y reglas](/docs/exyliaenchants/presets-y-reglas) |
| `display-mode` | `native` | `native` o `lore`. `lore` escribe una línea por encantamiento en el objeto para Bedrock mediante Geyser; los jugadores de Java las ven entonces dos veces |
| `tooltip.enabled` | `true` | Líneas de descripción y estadísticas bajo cada encantamiento. Necesita PacketEvents |
| `tooltip.in-menus` | `true` | Las mismas líneas en los menús |
| `tooltip.description` / `tooltip.stats` | `true` | Qué líneas se dibujan |
| `tooltip.player-default` | `true` | Lo que ve un jugador hasta que elige |
| `budget.enabled` | `true` | El [presupuesto de poder](/docs/exyliaenchants/presupuesto-de-poder) |
| `budget.rarity-cost` | common 1, rare 2, epic 3, legendary 5, curse 0 | Poder por nivel cuando un encantamiento no fija `power-cost` |
| `budget.weapons` / `armour` / `tools` | 12 / 12 / 10 | El límite por categoría de objeto |
| `economy` | `true` | Libros, objetos de apoyo y el encantador. Desactivado con `vanilla-plus` |
| `purged` | vacío | Encantamientos en purga; lo escribe `/enchantsadmin purge` |
| `disabled-enchants` | vacío | Encantamientos desactivados: los objetos los conservan, pero dejan de funcionar |
| `obtaining.*` | todos `true` | Consulta [Obtén encantamientos](/docs/exyliaenchants/obtener-encantamientos) |
| `obtaining.table-share` | `0.35` | Porción de las ofertas de la mesa que son encantamientos personalizados |

El primer arranque resuelve `preset: auto` una vez y escribe el resultado.

## economy.yml

| Clave | Por defecto |
|---|---|
| `book-mode` | `chance` (el otro valor es `vanilla`: todos los libros tienen éxito) |
| `odds.<rarity>` éxito / destrucción | common 80-100 / 0-10, rare 60-90 / 5-20, epic 40-80 / 10-30, legendary 25-60 / 15-40, curse 100 / 0 |
| `curse-on-fail` | `15.0` por ciento. Solo con el preset survival; `0` lo desactiva |
| `dust-bonus` / `dust-cap` | `10` / `100` |
| `gem-power` / `max-gems` | `2` / `3` |
| `enchanter.enabled` | `true` |
| `enchanter.restock` | `10m` |
| `enchanter.books.<rarity>` | `levels` y `stock`: common 8 / 32, rare 16 / 16, epic 28 / 8, legendary 45 / 2 |
| `enchanter.support.<kind>` | `levels` y `stock` por tipo, mira abajo |

Los precios de apoyo son protección 20 (stock `-1`, ilimitado), polvo 6, transmog 4, desencantar 15 y gema 30 (stock 4). La moneda de un precio es `levels` (niveles de experiencia), un valor vacío (la moneda por defecto del servidor) o un id de moneda de ExyliaLib. Los objetos de apoyo se definen en `lang/<code>/support-items.yml`. Detalles: [Libros y aplicar](/docs/exyliaenchants/libros-y-aplicar) y [El encantador](/docs/exyliaenchants/el-encantador). Las monedas se explican en [Economía](/docs/exylialib/economy).

## Otros archivos

- `rules.yml`: [Presets y reglas](/docs/exyliaenchants/presets-y-reglas).
- `integrations.yml`: `mines.area-break` (por defecto `true`). Consulta [Integraciones](/docs/exyliaenchants/integraciones).
- `balance.yml`: [Ajusta y equilibra](/docs/exyliaenchants/herramientas-de-balance).
- `menus.yml`: `preview.mode` (por defecto `MANNEQUIN`) y `preview-effects`, una [secuencia de ExyliaLib](/docs/exylialib/sequences) por elemento. `default` cubre el resto.
- `sets.yml`: [Bonus de conjunto de armadura](/docs/exyliaenchants/bonus-de-conjunto).

## Archivo de encantamiento

Los encantamientos viven en `enchants/*.yml`: `melee`, `ranged`, `armour`, `mobility`, `tools` y `universal` vienen con el plugin. Añade tus propios archivos `*.yml` en la misma carpeta; se leen por orden de nombre y el primer archivo gana si un id está duplicado. Un id usa `a-z`, `0-9` y `_`, hasta 64 caracteres. Nunca renombres un id incluido.

| Clave | Por defecto | Significado |
|---|---|---|
| `name` | obligatorio | Nombre visible |
| `description` | ninguna | Una línea, mostrada en el tooltip y el catálogo |
| `rarity` | obligatorio | `common`, `rare`, `epic`, `legendary` o `curse` |
| `max-level` | `1` | De 1 a 255 |
| `applies-to` | obligatorio | Familias de objetos, `#tags` o ids de objetos |
| `slots` | de las familias | Dónde está activo: `any`, `mainhand`, `offhand`, `hand`, `head`, `chest`, `legs`, `feet`, `armor`, `body`. Sostenido en cualquier otra ranura no hace nada |
| `conflicts` | ninguno | Encantamientos con los que no puede compartir objeto |
| `mode` | `both` | `pvp`, `pve` o `both`: contra quién está pensado |
| `weight` | por rareza | De 1 a 1024, el peso en la mesa y el botín |
| `anvil-cost` | por rareza | Coste en el yunque de un libro |
| `min-cost` / `max-cost` | por rareza | `base` y `per-level` para la mesa |
| `area` | `false` | Marca un encantamiento que rompe bloques o golpea a muchas entidades, para que las reglas puedan seleccionarlo o desactivarlo |
| `table`, `trade`, `treasure` | por rareza | En la mesa de encantamientos, vendido por aldeanos bibliotecarios, o solo como tesoro |
| `loot` | `false` | En cofres de botín aleatorio, tesoro de pesca y encantamiento aleatorio. También necesita `obtaining.loot` |
| `mob-equipment` / `traded-equipment` | `false` | En el equipo con el que aparecen los mobs / el que venden los aldeanos. El segundo también necesita `obtaining.villager-trades` |
| `grindstone` | `true` (`false` para maldiciones) | Si la piedra de afilar lo quita |
| `enchanter` | `true` | Si el encantador puede sortearlo |
| `books` | `true` | Si `/enchantsadmin give ... -book` lo entrega desde la consola |
| `worlds` | ninguno | Listas `allow` y `deny` |
| `regions` | ninguno | Lista `deny` |
| `permission` | ninguno | Quien lo lleve necesita este nodo para que funcione |
| `power-cost` | por rareza | Poder por nivel, de -10 a 50 |
| `enabled` | `true` | Desactívalo sin borrarlo |
| `abilities` | ninguna | Consulta [Añade tu propio encantamiento](/docs/exyliaenchants/encantamientos-propios) |
| `visuals` | ninguno | `element` e `icon` |

<Callout type="warning" title="Qué necesita un reinicio">
Las claves que forman parte del encantamiento nativo que el servidor registra al arrancar (name, rarity, max-level, applies-to, slots, conflicts, weight, anvil-cost, costs, table, trade, treasure, loot) necesitan un reinicio, y también un encantamiento nuevo. `description`, `power-cost`, `abilities` y `visuals` se recargan en vivo. Los interruptores de `obtaining` que quitan tags necesitan un reinicio; los del yunque, la piedra de afilar y `/enchant` se recargan.
</Callout>
