Two tools decide what an enchant does where. A **preset** decides which enchants exist on the server at all. **Rules** (`rules.yml`) decide where and for whom an enchant that exists is weaker or off.

## Presets

Set `preset` in `config.yml`:

| Preset | What exists | Economy |
|---|---|---|
| `survival` | Everything | On |
| `pvp` | No PvE-only enchants and no curses | On |
| `vanilla-plus` | Common and rare enchants only | Off: no books, scrolls or enchanter |
| `auto` | Resolved once on the first start | |

`auto` chooses `pvp` when ExyliaPracticeCore, ExyliaFFA or ExyliaPracticeBotV3 is installed and none of ExyliaMines, ExyliaSurvivalCore or ExyliaEconomy is. Otherwise it chooses `survival`. The result is written to the file, so adding a plugin later does not change it.

To drop one enchant, not a group, use `disabled-enchants` instead. See [Obtain enchants](/docs/exyliaenchants/obtaining).

## Rules

`rules.yml` holds named rules. A rule applies when every condition it sets matches. An empty list matches anything.

| Key | Meaning |
|---|---|
| `worlds` | World names |
| `regions` | ExyliaLib region policies or WorldGuard regions. See [Regions](/docs/exylialib/regions) |
| `modes` | Modes: an ExyliaLib Modes id, or `duels-ranked`, `duels`, `duels-bot`, `ffa`, `event` |
| `permission` | Applies only to holders of this permission |
| `only` | The enchants the rule touches. `*` for all |
| `disable` | Enchants switched off while the rule applies |
| `scale` | Multipliers. `all: 0.75` is 75% |

Selectors for `only` and `disable`:

| Selector | Matches |
|---|---|
| `*` | Every enchant |
| `bleed` | One enchant by id |
| `rarity:epic` | A rarity: common, rare, epic, legendary or curse |
| `mode:pvp` | An enchant's mode: pvp, pve or both |
| `area` | Enchants that break blocks or hit many entities |
| `file:melee` | Every enchant of `enchants/melee.yml` |

Every matching rule applies: their factors multiply, and any `disable` that matches wins. A rule gate runs when an ability would run, so `/enchantsadmin reload` is enough.

The file ships with two rules:

```yaml
rules:
  duels-ranked:
    modes: [duels-ranked]
    only: ["*"]
    disable: ["rarity:legendary"]
    scale: { all: 0.75 }
  spawn:
    regions: [spawn]
    only: ["*"]
    disable: [area]
```

Legendary enchants are off in ranked duels and every other enchant does 75% of its numbers. Area enchants are off in a region policy named `spawn`.

<Callout type="note" title="Scale keys">
In 1.1.0 only `scale: { all: ... }` is applied. It scales the numbers of the enchant, such as damage and healing, and not its chance or cooldown. The per-number keys the file comment mentions (`damage`, `chance`, `duration`, `radius`) are accepted but not read yet.
</Callout>

### An enchant's own limits

The same engine runs the `worlds`, `regions` and `permission` keys in an enchant's file, for that enchant only:

```yaml
frostbite:
  worlds: { allow: [world_pvp] }
  regions: { deny: [spawn] }
  permission: vip.enchants
```

`allow` means only those worlds, `deny` means never those. Holders without the permission wear the enchant but its abilities do not run.

### Modes

Modes come from other plugins: an ExyliaLib Modes claim, then ExyliaPracticeCore matches (`duels-bot`, `duels-ranked`, `duels`), an ExyliaDuels duel (`duels`), an ExyliaFFA arena (`ffa`) and playing an ExyliaEvents event (`event`). See [Integrations](/docs/exyliaenchants/integrations).
