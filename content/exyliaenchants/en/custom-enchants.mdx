You will add a new enchant, or edit a shipped one, in a file in `plugins/ExyliaEnchants/enchants/`. Only three keys are required: `name`, `rarity` and `applies-to`. Everything else has a default from the rarity.

## Before you start

The shipped enchants are in `melee.yml`, `ranged.yml`, `armour.yml`, `mobility.yml`, `tools.yml` and `universal.yml`. You can edit those, or add your own `*.yml` file to the same folder. Files are read in name order. The full list of keys is in [Configuration](/docs/exyliaenchants/configuration#enchant-file).

## Steps

<Steps>
  <Step title="Create a file">
    Add `plugins/ExyliaEnchants/enchants/mine.yml`. The top-level key of each section is the enchant's id: lowercase letters, numbers and `_` only, at most 64 characters.
  </Step>
  <Step title="Write the enchant">
    Start from this example and change it.

    ```yaml
    spark:
      name: Spark
      description: Sometimes sets the target alight.
      rarity: rare
      max-level: 3
      applies-to: [swords]
      abilities:
        - trigger: ATTACK
          chance: 8 + level * 4
          cooldown: 6s
          effects:
            - damage: { target: victim, amount: 1 * level, every: 1s, times: 3 }
    ```
  </Step>
  <Step title="Restart the server">
    A new enchant is part of the game's registry, so it needs a restart. Until then `/enchantsadmin give` answers that the enchant is new.
  </Step>
  <Step title="Check the console">
    Mistakes are logged at startup with the file name. A mistake costs that one enchant, never the whole file.
  </Step>
</Steps>

## Check that it works

Run `/enchantsadmin give <your name> spark 2` while holding a sword. Run `/enchants` and find Spark in its section. Test the numbers with the [training dummy and tuner](/docs/exyliaenchants/balance-tools).

## Going further

### Change a shipped enchant

Edit its section in place. Descriptions, `power-cost`, `abilities` and `visuals` reload with `/enchantsadmin reload`. Every other key (rarity, max level, items it applies to, costs, obtaining keys) needs a restart.

### Remove or switch off an enchant

Never delete a shipped enchant from the files: if the server stops knowing an enchant that is on an item, Minecraft drops every enchant on that item. ExyliaEnchants keeps the key registered as a placeholder, but the safe way is:

- `enabled: false` in the enchant's section, or its id in `disabled-enchants` in `config.yml`: items keep it, it stops working.
- `/enchantsadmin purge <enchant>` to strip it from items as they load. See [Obtain enchants](/docs/exyliaenchants/obtaining#switch-one-enchant-off).

Do not rename an id that you have used: items keep the old one.

### Translate it

Names and descriptions in the server's language go in `lang/<code>/enchants.yml`, keyed by id:

```yaml
spark:
  name: Chispa
  description: A veces prende fuego al objetivo.
```

Missing keys fall back to the English in the enchant file. See [Messages and languages](/docs/exylialib/messages-and-languages).

### Edit in game

`/enchantsadmin` opens the enchant list. Click an enchant to edit it by area: General, Abilities, Visuals, Obtaining, Rules and Live tuner. A **Web editor** card in that list opens ExyliaLib's browser editor.

<Details title="Technical details">
- `abilities` use ExyliaLib's ability engine: a `trigger`, optional `chance` (a formula in `level`, percent), `cooldown` (`8s`, `500ms`, `2m`), `conditions` and `effects`. Ability `i` of enchant `spark` has the id `spark.i`, which is its cooldown key, so add new abilities at the end.
- Formulas know only `level`. An unknown effect does nothing and an unknown condition holds: read the console after a reload.
- Named sequences for effects live in `sequences.yml`; `visuals.element` (fire, frost, bleed, lightning, earth, arcane, holy, poison, water, wind) picks the preview effect and the set it counts for.
- `applies-to` takes families (`swords`, `axes`, `mace`, `trident`, `bow`, `crossbow`, `weapons`, `pickaxes`, `shovels`, `hoes`, `fishing-rod`, `tools`, `gear`, `helmet`, `chestplate`, `leggings`, `boots`, `armour`, `elytra`, `shield`), item tags (`#minecraft:swords`) and item ids.
- `conflicts` names ours by id and vanilla ones with the namespace (`minecraft:smite`).
</Details>
