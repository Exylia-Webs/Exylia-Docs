## Descargar

ExyliaEconomy es gratuito. Cada versión se publica en [Modrinth](https://modrinth.com/plugin/exyliaeconomy) como `ExyliaEconomy-<version>.jar`.

## Antes de empezar

| Plugin | Para qué |
|---|---|
| `ExyliaLib` | Obligatorio. Configuración, menús, base de datos, Redis, placeholders, los editores y la fachada de economía. 1.595.0 o superior. |
| Servidor | Paper 1.21.1 o superior, Folia 1.21.4 o superior. Java 21. |
| `Vault` | Opcional. Sin él no se publica nada como economía de Vault, y los plugins que solo hablan Vault no ven dinero. |
| `PlaceholderAPI` | Opcional. Expone los saldos y las clasificaciones a otros plugins. |
| `ExyliaAnalytics` | Opcional. Recibe el dinero en circulación de cada moneda almacenada. |

<Callout type="note" title="ExyliaLib figura como soft, y no se descarga por ti">
`plugin.yml` pone ExyliaLib en `softdepend` a propósito, para que el plugin pueda arrancar sin ella y
decir qué pasa. Sin ExyliaLib, ExyliaEconomy se queda apagado y la consola dice dónde conseguirla
([Modrinth](https://modrinth.com/plugin/exylialib) o las releases de la librería en GitHub): pon el jar en
`plugins/` y reinicia. Si ya hay un jar de ExyliaLib en `plugins/` pero no cargó, la consola te pide que
arregles primero los errores de la propia librería.
</Callout>

ExyliaEconomy no necesita packetevents por sí mismo. ExyliaLib sí: instálalo junto a la librería como
explica la [página de instalación de la librería](/docs/exylialib/instalacion).

## Instalar

<Steps>
  <Step title="Coloca el jar">
    Copia `ExyliaEconomy.jar` en `plugins/`, junto con Vault si quieres que los plugins que usan Vault vean
    las monedas.
  </Step>
  <Step title="Arranca el servidor">
    Sin ExyliaLib el plugin se queda apagado y la consola dice dónde conseguirla; instálala y reinicia.
  </Step>
  <Step title="Revisa la consola">
    Cuando se leen las monedas aparece una línea como
    `Economy: 2 stored, 1 item and 1 experience currencies.`, y después qué moneda sirve a Vault. Nada
    relacionado con el dinero funciona antes de esa primera línea, un instante después de que el servidor
    termina de arrancar.
  </Step>
  <Step title="Abre el editor">
    Con `exyliaeconomy.admin`, ejecuta `/economyadmin` para ver las monedas con las que empieza el
    servidor. Ver [Primeros pasos](/docs/exyliaeconomy/primeros-pasos).
  </Step>
</Steps>

<Callout type="warning" title="Si vienes de ExyliaSurvivalCore">
La importación automática de la economía del survival core se quitó en la 1.2.1. Un servidor que aún usa
el módulo debe pasarse antes con una versión anterior a esa. Ver [Migración](/docs/exyliaeconomy/migracion).
</Callout>

## Archivos generados

Todos viven en `plugins/ExyliaEconomy/`.

| Archivo | Contenido |
|---|---|
| `lang/<code>/messages.yml` | Cada línea que envía el plugin, el aspecto del billete y los textos del editor de monedas. |
| `lang/<code>/menus/user/` | Las pantallas de los jugadores: `wallet.yml`, `top.yml`, `history.yml`. Se escriben si faltan y nunca se sobrescriben. |
| `lang/<code>/menus/admin/` | Las pantallas del editor: la lista de monedas, una moneda y sus páginas, los ajustes de economía y el registro de administración. |
| `screens/economy.html`, `screens/theme.css` | La billetera, la clasificación y el historial como una sola pantalla. |
| `database.yml` | Motor de base de datos y Redis, escrito por ExyliaLib. H2 por defecto. |
| `currencies.yml.imported` | El archivo de monedas que importó el primer arranque, apartado. No se vuelve a leer. |
| `exports/` | Las exportaciones del registro hechas con `/economyadmin export`. |
| `config.yml.migrated` | Un `config.yml` antiguo importado a la base de datos, apartado. Solo en un servidor actualizado desde una versión anterior. |

`<code>` es el idioma en el que funciona el plugin: `en`, `es`, `pt`, `fr`, `ru` o `tr`, o el propio idioma de
ExyliaLib mientras **Ajustes de economía** diga `default`. Ver [Configuración](/docs/exyliaeconomy/configuracion).

<Callout type="warning" title="menus/admin/ se reescribe">
Las tres pantallas del editor se reemplazan desde el jar cada vez que arranca el plugin y cada vez que
se recargan sus menús — `/economyadmin reload`, y una recarga de la propia ExyliaLib. Su cabecera dice
"regenerado en cada arranque"; también ocurre al recargar. Ahí no vive nada que un dueño deba editar.
</Callout>

<Callout type="note" title="Las monedas no están en un archivo">
Las monedas y los ajustes generales de la economía viven en la base de datos, en `exylia_currencies` y
`exylia_economy_settings`, y se editan con `/economyadmin`. El primer arranque importa `currencies.yml` —
el tuyo o el de serie — y le cambia el nombre. Un `currencies.yml` encontrado en
un arranque posterior se avisa en consola y se ignora.
</Callout>

## Base de datos

Por defecto el plugin usa **H2**: un archivo dentro de la carpeta del plugin, sin servidor, sin
instalación y sin mantenimiento. Para un único servidor es perfectamente válido.

Para compartir saldos entre servidores, todos apuntan a la misma base de datos:

```yaml title="plugins/ExyliaEconomy/database.yml"
database:
  type: mysql
  settings:
    pool-size: 0
  mysql:
    host: 127.0.0.1
    port: 3306
    database: minecraft
    username: root
    password: ""
  redis:
    enabled: true
    host: 127.0.0.1
    server-id: survival-1
```

Motores soportados: `h2`, `mysql`, `mariadb`, `postgresql` y `mongodb`. Solo se lee el bloque que coincide
con `type`. El archivo es de ExyliaLib; su referencia completa está en la
[página de base de datos de la librería](/docs/exylialib/base-de-datos).

<Callout type="danger" title="Dale a cada servidor su propio server-id">
Quién tiene un saldo lo decide `server-id`, que vale `server-1` si no lo cambias. Dos servidores que
comparten base de datos con el mismo ID creen ambos que tienen al jugador y se pisan los saldos. La
consola avisa una vez cuando ve el ID por defecto en una base de datos compartida. Ver
[Red](/docs/exyliaeconomy/red).
</Callout>

Nada espera a la base de datos mientras el plugin se activa. Las monedas se leen en el primer tick; los
saldos de un jugador se reclaman cuando entra, y cada escritura es asíncrona.

## Actualizar

ExyliaLib mantiene ExyliaEconomy al día. El plugin indica su repositorio de GitHub en `plugin.yml`
(`exylia-updates: Exylia-Plugins/ExyliaEconomy`) y la versión mínima de la librería con la que funciona
(`exylia-lib: 1.595.0`); ExyliaLib busca una versión más nueva al arrancar y cada cierto tiempo, la
descarga, la comprueba y la deja preparada para el siguiente reinicio.

- Solo se instalan solas las versiones menores y los parches. Una versión mayor nueva se anuncia y se deja
  en tus manos.
- Una versión que necesita una ExyliaLib más nueva que la que estará funcionando se retiene hasta que la
  librería se ponga al día.
- `/exylialib plugins` lo comprueba en el momento. `plugin-updates` en `plugins/ExyliaLib/config.yml` lo
  apaga (`enabled: false`), permite versiones mayores o excluye este plugin por su nombre.

Para actualizar a mano, reemplaza el jar y reinicia. `messages.yml` y los menús de los
jugadores conservan tus cambios; `menus/admin/` se refresca desde el jar; las monedas, los saldos y el
registro viven en la base de datos y no se tocan.
