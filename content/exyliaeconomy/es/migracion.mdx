## Desde ExyliaSurvivalCore

ExyliaEconomy es el módulo `economy` de ExyliaSurvivalCore convertido en plugin propio. Los saldos, los
cambios en cola y el registro ya vivían en tablas con nombres neutros (`exylia_balances`,
`exylia_balance_pending`, `exylia_ledger`), así que pasarse consiste en abrir la misma base de datos.

<Callout type="warning" title="La importación automática ya no existe">
Desde la 1.2.1 el plugin ya no copia el `database.yml` del survival core, ni sus monedas, ajustes,
mensajes o menús, y los nombres de permiso `exyliasurvivalcore.economy…` ya no conceden nada. Pásate con
una versión anterior a la 1.2.1 en todos los servidores de la red a la vez y después actualiza; o copia a
mano `plugins/ExyliaSurvivalCore/database.yml` aquí, para que el plugin abra la base de datos donde están
los saldos, y vuelve a crear las monedas en `/economyadmin`. Concede los nodos `exyliaeconomy.…` en lugar
de los antiguos.
</Callout>

Actualiza todos los servidores a la vez: los servidores se avisan de los cambios de saldo por un canal de
Redis cuya clave incluye el nombre del plugin, así que un servidor que aún usa el módulo antiguo no oye a
uno con ExyliaEconomy, ni al revés.

## Un config.yml antiguo

Una versión anterior a la 1.2.0 guardaba en `config.yml` el idioma, la depuración, la confirmación de
`/pay`, el aviso de pagos sin conexión, `banknotes` e `interest`. El primer arranque de una más nueva los
importa a la base de datos donde todavía no hay nada fijado — el idioma y los interruptores a **Ajustes de
economía**, las cantidades de confirmación, la lista de billetes y los bloques de intereses a cada moneda —
y renombra el archivo a `config.yml.migrated`. Un `config.yml` que solo contenga `language` se importa
igual. Desde entonces se editan en `/economyadmin`; el plugin ya no escribe `config.yml`.

### Comandos y placeholders

Los comandos conservan sus nombres — `/balance`, `/pay`, `/baltop`, `/wallet`, `/economy`, `/economyadmin` y
los comandos de las monedas —, igual que las antiguas formas de administración `/eco give`, `/eco take`,
`/eco set`, `/eco reset` y `/eco import`, con las que están escritos los archivos de recompensas y cajas de
los servidores en marcha.

Los placeholders pertenecen ahora a este plugin: `%exyliasurvivalcore_economy_balance_<currency>%` pasa a ser
`%exyliaeconomy_economy_balance_<currency>%`, y lo mismo para el resto. Ver
[Placeholders](/docs/exyliaeconomy/placeholders).

## El archivo de monedas del primer arranque

Las monedas viven en la base de datos. La primera vez que las tablas están vacías — un servidor nuevo, o uno
cuyo survival core no tenía monedas que copiar —, el plugin importa un `currencies.yml`, en este orden:

1. `plugins/ExyliaEconomy/currencies.yml`, si pusiste uno ahí;
2. las monedas de serie: `dollars`, `shards`, `netherite_ingots`, y las superposiciones `vault` y `points`.

Después el archivo se renombra a `currencies.yml.imported` y no se vuelve a leer. Su formato, para un
servidor que quiera preparar uno:

```yaml title="plugins/ExyliaEconomy/currencies.yml"
stored:
  gems:
    name: Gem
    plural: Gems
    symbol: "◆"
    icon: EMERALD
    decimals: 0
    format: "%amount% %symbol%"
    compact-format: "%amount%%symbol%"
    aliases: [gems, gem]
    start: 0
    max: -1
    permission: ""
    transfer:
      enabled: true
      minimum: 1
      tax-percent: 0
    exchange:
      enabled: false
      rates: {}
    leaderboard: true
    scope: global          # global, group o server; el antiguo 'networked: true/false' se sigue leyendo
    available-on: []       # grupos o IDs de servidor donde existe; [] es todos
    commands: true
items:
  emeralds:
    item: EMERALD          # o una instantánea 'bytes:' de un ítem personalizado
    name: Emerald
    plural: Emeralds
    icon: EMERALD
    format: "%amount% %name%"
    aliases: []
experience:
  levels: false
  points: true
display:
  vault:
    name: Dollar
    plural: Dollars
    symbol: "$"
    decimals: 2
    format: "%symbol%%amount%"
vault:
  provide: gems
  force: true
ledger:
  enabled: true
```

Un ID de moneda almacenada que no sea `a-z`, `0-9` y `_` hasta 32, o una moneda de ítem sin ítem, se omite
con un aviso. Un bloque almacenado sin `exchange.enabled` lo lee como **activado**.

## Desde Vault o PlayerPoints

`/economyadmin import <from> <into>` suma el saldo de cada jugador en una moneda a una moneda almacenada.
`from` puede ser cualquier moneda del servidor, incluida `vault` mientras EssentialsX o CMI la sigan
sirviendo, o `points` para PlayerPoints.

<Steps>
  <Step title="Deja la economía antigua sirviendo por ahora">
    Mantén instalados EssentialsX, CMI o PlayerPoints, para que `vault` o `points` sigan leyendo sus
    saldos.
  </Step>
  <Step title="Importa">
    `/economyadmin import vault dollars`. Recorre cada jugador que haya entrado alguna vez a este servidor,
    lee su saldo de uno en uno e ingresa lo que sea positivo. Los jugadores de este servidor cobran al
    momento; los demás reciben un cambio en cola. La consola nombra cualquier saldo por encima del máximo
    del destino, que se omite.
  </Step>
  <Step title="Cambia Vault">
    Quita el plugin de economía antiguo, o activa **Vault por encima**, para que la moneda almacenada sirva
    Vault.
  </Step>
</Steps>

Una importación **suma**, nunca fija, así que se ejecuta una vez:

- una segunda importación del mismo par se rechaza salvo que añadas `again`;
- con `again`, solo cobran los jugadores que aún no se importaron — nadie cobra dos veces, ni tras una
  importación que se quedó a medias ni con una lanzada en dos servidores a la vez;
- una importación entre una moneda y ella misma se rechaza, incluido `vault` hacia la moneda que sirve
  `vault`;
- una segunda ejecución escrita mientras otra está leyendo se rechaza: *"That import is already running."*

Cada jugador importado se anota en `exylia_balance_imports`, y el registro pone `import:<from>`.

<Callout type="note" title="Solo los jugadores que ha visto este servidor">
Ni Vault ni PlayerPoints pueden listar saldos, así que la importación recorre la lista de jugadores del
propio servidor. Un jugador que nunca entró a este servidor no se importa; ejecuta la importación en el
servidor donde están tus jugadores.
</Callout>
