Al terminar tendrás los saldos de tu economía anterior dentro de una moneda de ExyliaEconomy y Vault servido por ella.

## Antes de empezar

Necesitas una moneda almacenada que reciba los saldos, ver [Crea una moneda](/docs/exyliaeconomy/monedas), y `exyliaeconomy.admin`. Ejecuta la importación en el servidor donde están tus jugadores: ni Vault ni PlayerPoints pueden listar saldos, así que la importación recorre la lista de jugadores del propio servidor, y un jugador que nunca entró en este servidor no se importa.

## Desde Vault o PlayerPoints

`/economyadmin import <from> <into>` suma el saldo de cada jugador en una moneda a una almacenada. `from` puede ser cualquier moneda del servidor, incluida `vault` mientras EssentialsX o CMI aún la sirve, o `points` para PlayerPoints.

<Steps>
  <Step title="Deja la economía antigua sirviendo por ahora">
    Deja EssentialsX, CMI o PlayerPoints instalado, para que `vault` o `points` sigan leyendo sus saldos.
  </Step>
  <Step title="Importa">
    Ejecuta `/economyadmin import vault dollars`. Recorre a cada jugador que ha entrado alguna vez en este servidor, lee su saldo de uno en uno e ingresa lo que sea positivo. A los jugadores de este servidor se les paga al momento; a los demás se les deja un cambio en cola. La consola nombra cualquier saldo por encima del máximo del destino, que se omite.
  </Step>
  <Step title="Pasa Vault a la nueva">
    Quita el plugin de economía antiguo, o activa **Vault por encima** en **Ajustes de economía**, para que la moneda almacenada sirva Vault. Ver [Elige qué ve Vault](/docs/exyliaeconomy/vault).
  </Step>
</Steps>

## Comprueba que funciona

Ejecuta `/balance` como un jugador que tenía dinero antes: muestra la cantidad antigua en la moneda de destino. `/economy history <currency> <jugador>` muestra la línea `import:<from>`, ver [Registro](/docs/exyliaeconomy/registro).

## Ir más allá

### Ejecútala una sola vez

Una importación se **suma**, nunca se fija:

- una segunda importación de la misma pareja se rechaza salvo que añadas `again`: `/economyadmin import <from> <into> again`;
- con `again`, solo se paga a los jugadores aún no importados, así que nadie cobra dos veces, ni siquiera tras una importación que se paró a medias o una iniciada en dos servidores a la vez;
- una importación entre una moneda y ella misma, incluida `vault` en la moneda que sirve `vault`, se rechaza;
- una segunda ejecución escrita mientras otra está leyendo se rechaza: *"That import is already running."*

Cada jugador importado queda anotado en `exylia_balance_imports`, y el registro lee `import:<from>`.

### Un config.yml antiguo

Una versión anterior a la 1.2.0 guardaba el idioma, el interruptor de depuración, la confirmación de `/pay`, el aviso sin conexión, `banknotes` e `interest` en `config.yml`. El primer arranque de una versión más nueva los importa a la base de datos donde aún no hay nada fijado (el idioma y los interruptores a los **Ajustes de economía**, las cantidades de confirmación, la lista de billetes y los bloques de interés a cada moneda) y renombra el archivo a `config.yml.migrated`. Un `config.yml` que solo tenga `language` se importa igual. Edítalos desde `/economyadmin` a partir de entonces; el plugin ya no escribe ningún `config.yml`.

<Details title="El archivo de monedas del primer arranque">
Las monedas viven en la base de datos. La primera vez que las tablas están vacías (un servidor nuevo) el plugin importa un `currencies.yml`, en este orden:

1. `plugins/ExyliaEconomy/currencies.yml`, si pusiste uno;
2. los valores que trae: `dollars`, `shards`, `netherite_ingots`, y las capas `vault` y `points`.

Después el archivo se renombra a `currencies.yml.imported` y no se vuelve a leer. Su estructura, para un servidor que quiera prepararlo:

```yaml title="plugins/ExyliaEconomy/currencies.yml"
stored:
  gems:
    name: Gem
    plural: Gems
    symbol: "◆"
    icon: EMERALD
    decimals: 0
    format: "%amount% %symbol%"
    compact-format: "%amount%%symbol%"
    aliases: [gems, gem]
    start: 0
    max: -1
    permission: ""
    transfer:
      enabled: true
      minimum: 1
      tax-percent: 0
    exchange:
      enabled: false
      rates: {}
    leaderboard: true
    scope: global          # global, group o server; el antiguo 'networked: true/false' se sigue leyendo
    available-on: []       # grupos o IDs de servidor donde existe; [] es todos
    commands: true
items:
  emeralds:
    item: EMERALD          # o una instantánea 'bytes:' de un ítem personalizado
    name: Emerald
    plural: Emeralds
    icon: EMERALD
    format: "%amount% %name%"
    aliases: []
experience:
  levels: false
  points: true
display:
  vault:
    name: Dollar
    plural: Dollars
    symbol: "$"
    decimals: 2
    format: "%symbol%%amount%"
vault:
  provide: gems
  force: true
ledger:
  enabled: true
```

Un ID almacenado que no sea `a-z`, `0-9` y `_` de hasta 32, o una moneda de ítem sin ítem, se omite con un aviso. Un bloque almacenado sin `exchange.enabled` lo lee como **activado**.
</Details>
