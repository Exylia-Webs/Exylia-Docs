ExyliaProxyUtils is the plugin you install on your **proxy** so the Exylia plugins on your servers can reach across the network. With it, a reward can run `/server lobby` for a player, a teleport can follow someone onto another server, and ExyliaStaff can kick or ban a player wherever they are. It is free, with its releases on [GitHub](https://github.com/Exylia-Plugins/ExyliaProxyUtils/releases).

One jar works on **Velocity** and on **BungeeCord**. It has no commands, no permissions and no menus: you install it, give it your network's Redis, and the Exylia plugins on the servers do the rest.

You only need it when you run a network behind a proxy. A single server runs every Exylia plugin without it.

## What you will have in 10 minutes

- Servers that answer to the proxy: [`player-proxy:` and `console-proxy:` commands](/docs/exyliaproxyutils/commands) work in any Exylia command list.
- [Teleports across servers](/docs/exyliaproxyutils/first-steps) that land next to the person.
- [Bans the proxy enforces at login](/docs/exyliaproxyutils/login-bans), before a player reaches any server.
- [Punishments from LiteBans, LibertyBans, AdvancedBan or BanManager](/docs/exyliaproxyutils/punishments) shown in ExyliaStaff.
- A jar that [updates itself](/docs/exyliaproxyutils/updates).

## What you need

| You need | Detail |
|---|---|
| A proxy | Velocity 3.4 or newer, or BungeeCord (built against the 1.21 API) and its forks. |
| Java | 21 |
| Redis | The Redis your servers use, reachable from the proxy. Without Redis, the shared database works too: [Run without Redis](/docs/exyliaproxyutils/without-redis). |
| On every server | ExyliaLib 1.106.0 or newer with Redis on in a `database.yml`. ExyliaLib 1.x-era plugin-message setups cannot talk to 2.x. |
| Optional, on the proxy | LiteBans, LibertyBans, AdvancedBan (BungeeCord only), BanManager. PacketEvents on Velocity, to hold proxy chat over open ExyliaLib screens. |

<Callout type="note" title="Why Redis and not plugin messages">
A plugin message travels down a player's connection, and a modified client can write one. Redis sits on your network's own side of the wall: only your servers can publish there, and it works with nobody online. Versions 1.x used plugin messages; 2.0.0 does not.
</Callout>
