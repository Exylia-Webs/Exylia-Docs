If your servers share a database but you run no Redis, the proxy can talk to them through that database instead. Everything works the same: requests, pushes, the ban mirror and the punishment stream.

## Before you start

Your servers need ExyliaLib 1.555.0 or newer, with `cross-server: database` set in their `database.yml`. Redis stays the recommended setup, because the database is slower (see below).

## Steps

<Steps>
  <Step title="Open config.properties">
    On the proxy, open `plugins/ExyliaProxyUtils/config.properties` (`plugins/exyliaproxyutils/` on Velocity).
  </Step>
  <Step title="Switch the transport">
    Set `transport=database`.
  </Step>
  <Step title="Copy the database the servers use">
    Fill in `database.type` (`mysql`, `mariadb`, `postgresql` or `mongodb`), `database.host`, `database.port` (`0` is the engine's default), `database.name`, `database.username` and `database.password`. For MongoDB you can use `database.connection-string` instead, a full `mongodb://` URI, which wins over the fields. Keep `redis.key-prefix`: it still names the network.
  </Step>
  <Step title="Restart the proxy">
    The file is read at startup only.
  </Step>
</Steps>

## Check that it works

The startup log says the proxy is talking to the servers through the database. On a server, `/exylialib status` names ExyliaProxyUtils.

## What it costs

A message takes up to a quarter of a second (PostgreSQL wakes at once through `LISTEN/NOTIFY`), and every server polls the database a few times a second. The tables are the ones ExyliaLib's database bus keeps (`exylia_bus_*`). The MariaDB driver (which also speaks MySQL), PostgreSQL's and MongoDB's are bundled in the jar.

A file written by a version before 2.3.0 gets the `transport` section appended on the next start, with `transport=redis`, and keeps working as it did.
