At the end of this page the proxy is running ExyliaProxyUtils and connected to the same Redis as your servers.

## Before you start

Every server that should reach the proxy needs:

| On each server | Why |
|---|---|
| ExyliaLib 1.106.0 or newer | It is the side that asks. |
| `database.redis.enabled: true` in a `database.yml` | ExyliaLib uses the first Redis it finds: its own `plugins/ExyliaLib/database.yml` first, otherwise the first plugin whose `database.yml` has Redis on. |
| A unique `server-id` under `database.redis` | It is the address the answers go back to. |
| The same `key-prefix` as the proxy | Two networks on one Redis must not answer each other. |

<Callout type="danger" title="Server names on the proxy must equal the server-ids">
The name a server has in `velocity.toml` (or BungeeCord's `config.yml`) has to be exactly the `server-id` that server has in its `database.yml`. With different names, teleports fail with `no server "<name>"`.
</Callout>

## Steps

<Steps>
  <Step title="Download the jar">
    On the [GitHub releases](https://github.com/Exylia-Plugins/ExyliaProxyUtils/releases) page, download `ExyliaProxyUtils.jar`. Prefer it to `ExyliaProxyUtils-<version>.jar`: the proxy [updates itself](/docs/exyliaproxyutils/updates) over the file it runs, so a versioned name stops being true after the first update. The same file works on both proxies.
  </Step>
  <Step title="Drop it in the proxy">
    Copy it into the proxy's `plugins/`, next to any ban plugin you run there.
  </Step>
  <Step title="Start the proxy once">
    This writes `plugins/ExyliaProxyUtils/config.properties` (`plugins/exyliaproxyutils/` on Velocity, which names the folder after the plugin id). With the default `localhost`, it starts only if Redis runs on the proxy machine.
  </Step>
  <Step title="Point it at your Redis">
    Fill in the same host, port, password, database and key prefix every server has under `database.redis`. Every key is explained in [Configuration](/docs/exyliaproxyutils/configuration).
  </Step>
  <Step title="Restart the proxy">
    There is no reload: the file is read once, at startup.
  </Step>
</Steps>

## Check that it works

The console shows:

```text
ExyliaProxyUtils 2.4.0 ready on Redis 10.0.0.6:6379; modules: [chat-hold, commands, connect, kick, ping, player, players, punish-import, punish-sources, servers]
```

You also see one `Recording <ORIGIN> punishments made on this proxy.` line for each ban plugin it found (see [Punishments](/docs/exyliaproxyutils/punishments)). If you see `ExyliaProxyUtils could not start; check plugins/ExyliaProxyUtils/config.properties: <reason>`, see [Common problems](/docs/exyliaproxyutils/troubleshooting).

<Callout type="warning" title="A failed start stays failed">
The connection is tested once, when the proxy starts. If Redis is down at that moment the plugin stays loaded but does nothing until you restart the proxy. A connection that drops after a good start is retried every two seconds.
</Callout>

## Files it creates

`config.properties` is the only file. It is written once and never overwritten. The plugin keeps no data of its own: everything it hears goes straight back out over Redis.
