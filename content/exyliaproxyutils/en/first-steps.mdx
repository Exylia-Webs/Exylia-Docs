At the end of this page you have seen a server talk to the proxy and run a command on it.

## Before you start

The proxy runs ExyliaProxyUtils and shows the `ready on Redis` line ([Install ExyliaProxyUtils](/docs/exyliaproxyutils/installation)). Your servers run ExyliaLib 1.106.0 or newer with Redis on.

## Steps

<Steps>
  <Step title="Look at a server's console">
    About a second after a server starts, ExyliaLib pings the proxy, and again every ten seconds until it gets an answer. Look for:

    ```text
    Proxy bridge listening on Redis 10.0.0.6:6379 as "survival-1" (settings from ExyliaLib/database.yml).
    ```
  </Step>
  <Step title="Ask the proxy to answer">
    On that server run `/exylialib status`. It sends a fresh ping and shows what answered, such as `ExyliaProxyUtils 2.4.0 on Velocity`.
  </Step>
  <Step title="Run a command on the proxy">
    In any Exylia command list (a reward, a menu action) add a line that starts with `player-proxy:` or `console-proxy:`:

    ```yaml
    commands:
      - "player-proxy:server lobby"                    # as the player
      - "console-proxy:alert An event is starting!"    # as the proxy console
    ```

    Trigger it. The player moves to `lobby`, and the proxy log shows `[survival-1] console: /alert An event is starting! (for Steve)`. More in [Run proxy commands from a server](/docs/exyliaproxyutils/commands).
  </Step>
  <Step title="Try a cross-server teleport">
    With a plugin that offers one (ExyliaStaff's `/tp` or a cross-server TPA), teleport to somebody on another server. The server finds the target through the proxy, the proxy moves the player, and the destination server puts them next to the target.
  </Step>
</Steps>

## Check that it works

`/exylialib status` names ExyliaProxyUtils, the `player-proxy:server` line moves the player, and the teleport lands next to the target instead of at spawn. If a move is refused, the reason comes back to the server: an unknown server, a connection already in progress, a proxy plugin that cancelled it, or the destination refusing the player.

If the proxy never answers, the server says so once:

```text
No proxy bridge answered on Redis channel "exylia:bridge:proxy". Install ExyliaProxyUtils on the proxy with the same Redis and key-prefix, or player-proxy: and console-proxy: commands and cross-server teleports will not run.
```

That almost always means a different Redis, a different `database` number or a different `key-prefix` on the two sides. See [Common problems](/docs/exyliaproxyutils/troubleshooting).
