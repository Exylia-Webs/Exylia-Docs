The whole configuration is one file, written on the first start and never overwritten:

| Proxy | Path |
|---|---|
| Velocity | `plugins/exyliaproxyutils/config.properties` |
| BungeeCord | `plugins/ExyliaProxyUtils/config.properties` |

```properties title="config.properties"
# ExyliaProxyUtils talks to the backends over Redis, so nothing a player
# sends can ever reach it. Point this at the same Redis every backend has
# under database.redis in plugins/ExyliaLib/database.yml, with the same
# key-prefix. Server names on this proxy must equal the backends' server-id.
redis.host=localhost
redis.port=6379
redis.password=
# ACL user (Redis 6+), empty for the default user.
redis.username=
# true for a Redis with TLS on (rediss://), like the backends' database.redis.ssl.
redis.ssl=false
redis.database=0
redis.key-prefix=exylia
# New releases download at start and stop and load on the next restart.
updates.enabled=true
# redis (recommended), or database when the backends have cross-server: database.
transport=redis
# mysql, mariadb, postgresql or mongodb
database.type=mysql
database.host=localhost
# 0 uses the engine's default port.
database.port=0
database.name=minecraft
database.username=root
database.password=
# mongodb only: a full mongodb:// URI, which wins over the fields above.
database.connection-string=
```

It is read once, at startup. Restart the proxy after editing it.

| Key | Default | What it does |
|---|---|---|
| `redis.host` | `localhost` | The Redis host. |
| `redis.port` | `6379` | The Redis port. Must be a number, or the plugin does not start. |
| `redis.password` | empty | The password; empty for none. Taken as written, spaces included. |
| `redis.database` | `0` | Which numbered Redis database. Must match the backends'. |
| `redis.key-prefix` | `exylia` | What every key and channel starts with. Must match the backends' `key-prefix`. Empty falls back to `exylia`. |
| `redis.username` | empty | The Redis ACL user (Redis 6+); empty for the default user. |
| `redis.ssl` | `false` | `true` connects over TLS (`rediss://`) to a Redis that has it on, with a certificate Java trusts. Needs ExyliaLib 1.484.0 or newer on the backends, with `database.redis.ssl: true`. |
| `transport` | `redis` | `redis` or `database`. See [Without Redis](#without-redis-transportdatabase). |
| `database.type` | `mysql` | `mysql`, `mariadb`, `postgresql` or `mongodb`. Read only with `transport=database`. |
| `database.host` / `database.port` | `localhost` / `0` | The database server; port `0` is the engine's default. |
| `database.name` | `minecraft` | The database the backends use. |
| `database.username` / `database.password` | `root` / empty | Its credentials. |
| `database.connection-string` | empty | MongoDB only: a full `mongodb://` URI, which wins over the fields above. |
| `updates.enabled` | `true` | Installs new releases of the same major at start and stop. Only `false` turns it off. See [Updates](/docs/exyliaproxyutils/updates). |

A key left out of the file takes its default. Values other than the password are trimmed. A file written by an older version lacks the Redis user, TLS and `transport` keys and keeps the old behaviour: the `transport` section is appended to it on the next start, with `transport=redis`.

## Matching the backends

The values are the ones every backend has in its `database.yml`:

```yaml title="plugins/ExyliaLib/database.yml (on a backend)"
database:
  redis:
    enabled: true
    host: 10.0.0.6
    port: 6379
    password: ""
    database: 0
    key-prefix: exylia
    server-id: survival-1
```

```properties title="config.properties (on the proxy)"
redis.host=10.0.0.6
redis.port=6379
redis.password=
redis.database=0
redis.key-prefix=exylia
```

`server-id` has no counterpart here: it lives in the proxy's own server list, where the backend's name
must be that same `server-id`.

<Callout type="warning" title="Two networks, one Redis">
The key prefix is what keeps them apart. Two networks with the same prefix on the same Redis answer
each other's servers and read each other's bans.
</Callout>

## Without Redis: `transport=database`

A network whose backends share a database but run no Redis sets `cross-server: database` in their
`database.yml` (ExyliaLib 1.555.0 or newer), and the proxy follows with `transport=database` and the same
database in `database.type`, `database.host`, `database.port`, `database.name`, `database.username` and
`database.password` (or `database.connection-string` for MongoDB). `redis.key-prefix` still names the
network.

Everything works the same over it: requests, pushes, the ban mirror and the punishment stream, through the
tables ExyliaLib's database bus keeps (`exylia_bus_*`). The cost is latency: a message takes up to a
quarter of a second (PostgreSQL wakes at once through `LISTEN/NOTIFY`), and every server polls the
database a few times a second, so Redis stays the recommended setup. The MariaDB driver (which also
speaks MySQL), PostgreSQL's and MongoDB's are bundled in the jar. The startup log says the proxy is
talking to the backends through the database.

## Connection

The plugin opens a small pool (at most four connections, a 200 ms wait for a free one) for answers and
writes, and one dedicated connection for listening, with a two-second connect and read timeout. It
identifies itself to Redis as `exylia-proxyutils`.

## Redis keys and channels

| Name | Kind | Direction |
|---|---|---|
| `<prefix>:bridge:proxy` | Pub/sub channel | Backends to the proxy: requests. |
| `<prefix>:bridge:<server-id>` | Pub/sub channel | Proxy to one backend: answers and pushes. |
| `<prefix>:punish:external` | Stream | Proxy to ExyliaStaff: punishments from ban plugins on the proxy. |
| `<prefix>:punish:ban:<uuid>` | String | Read by the proxy at login; written by ExyliaStaff. |
| `<prefix>:punish:ipban:<sha256>` | String | Read by the proxy at login; written by ExyliaStaff. |

See [Protocol](/docs/exyliaproxyutils/protocol) for the message format.
