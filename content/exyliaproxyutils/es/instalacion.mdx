Al final de esta página el proxy ejecuta ExyliaProxyUtils y está conectado al mismo Redis que tus servidores.

## Antes de empezar

Cada servidor que deba llegar al proxy necesita:

| En cada servidor | Por qué |
|---|---|
| ExyliaLib 1.106.0 o superior | Es el lado que pregunta. |
| `database.redis.enabled: true` en un `database.yml` | ExyliaLib usa el primer Redis que encuentra: primero su propio `plugins/ExyliaLib/database.yml`, y si no, el primer plugin cuyo `database.yml` tenga Redis activado. |
| Un `server-id` único bajo `database.redis` | Es la dirección a la que vuelven las respuestas. |
| El mismo `key-prefix` que el proxy | Dos redes en un mismo Redis no deben responderse entre sí. |

<Callout type="danger" title="Los nombres en el proxy deben ser iguales a los server-id">
El nombre que tiene un servidor en `velocity.toml` (o en el `config.yml` de BungeeCord) debe ser exactamente el `server-id` que ese servidor tiene en su `database.yml`. Con nombres distintos, los teletransportes fallan con `no server "<nombre>"`.
</Callout>

## Pasos

<Steps>
  <Step title="Descarga el jar">
    En la página de [versiones de GitHub](https://github.com/Exylia-Plugins/ExyliaProxyUtils/releases) descarga `ExyliaProxyUtils.jar`. Mejor que `ExyliaProxyUtils-<versión>.jar`: el proxy [se actualiza solo](/docs/exyliaproxyutils/actualizaciones) escribiendo sobre el archivo que ejecuta, así que un nombre con versión deja de ser cierto tras la primera actualización. El mismo archivo sirve para los dos proxies.
  </Step>
  <Step title="Ponlo en el proxy">
    Cópialo en `plugins/` del proxy, junto a cualquier plugin de sanciones que uses.
  </Step>
  <Step title="Arranca el proxy una vez">
    Se escribe `plugins/ExyliaProxyUtils/config.properties` (`plugins/exyliaproxyutils/` en Velocity, que nombra la carpeta con el id del plugin). Con el `localhost` por defecto, solo arranca si Redis corre en la máquina del proxy.
  </Step>
  <Step title="Apúntalo a tu Redis">
    Rellena el mismo host, puerto, contraseña, base de datos y prefijo que tienen tus servidores bajo `database.redis`. Cada clave está explicada en [Configuración](/docs/exyliaproxyutils/configuracion).
  </Step>
  <Step title="Reinicia el proxy">
    No hay recarga: el archivo se lee una sola vez, al arrancar.
  </Step>
</Steps>

## Comprueba que funciona

La consola muestra:

```text
ExyliaProxyUtils 2.4.0 ready on Redis 10.0.0.6:6379; modules: [chat-hold, commands, connect, kick, ping, player, players, punish-import, punish-sources, servers]
```

Además verás una línea `Recording <ORIGIN> punishments made on this proxy.` por cada plugin de sanciones que encuentre (mira [Sanciones](/docs/exyliaproxyutils/sanciones)). Si ves `ExyliaProxyUtils could not start; check plugins/ExyliaProxyUtils/config.properties: <motivo>`, mira [Problemas comunes](/docs/exyliaproxyutils/problemas-comunes).

<Callout type="warning" title="Un arranque fallido se queda fallido">
La conexión se prueba una sola vez, al arrancar el proxy. Si Redis está caído en ese momento, el plugin se queda cargado pero sin hacer nada hasta que reinicies el proxy. Una conexión que se cae después de un buen arranque se reintenta cada dos segundos.
</Callout>

## Archivos que crea

`config.properties` es el único. Se escribe una vez y nunca se sobrescribe. El plugin no guarda datos propios: todo lo que oye vuelve a salir por Redis.
