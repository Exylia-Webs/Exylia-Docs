Players cannot spam ender pearls, golden apples or totems: each item gets a cooldown, longer while they are in combat, and different per world or region if you want. The cooldown shows on the item in the hotbar, in the [action bar](/docs/exyliacombat/combat-tag#action-bar), and on the HUD of clients that draw cooldowns. An item on cooldown does nothing when used. Items made by ExyliaSpecials are left alone: they have cooldowns of their own.

## Before you start

The `vanilla-cooldowns` module is on by default, with five items ready (see [defaults](#defaults)). To see it working you only need a test account. For per-region values you need WorldGuard or ExyliaLib regions.

## Steps

<Steps>
  <Step title="Open the file">
    Open `modules/vanilla-cooldowns/config.yml`. Each item is one entry under `cooldowns`, named by its material in capitals.
  </Step>
  <Step title="Add or change an item">
    Copy the `ENDER_PEARL` entry, rename it (for example `CHORUS_FRUIT`), and set `trigger` and `cooldown` in seconds. Set `combat-cooldown` for a longer wait while tagged, or `-1.0` to keep `cooldown`.
  </Step>
  <Step title="Name it">
    Set `display-name` to how the item should read in the action bar, such as `'{primary}Ender Pearl'`.
  </Step>
  <Step title="Reload">
    Run `/combatadmin reload`.
  </Step>
</Steps>

## Check that it works

Throw an ender pearl, then another at once: the second does nothing and the action bar counts the cooldown down. Get tagged with `/combatadmin settag 15 <player>` and throw again: the wait is `combat-cooldown`. Clear it with `/combatadmin cooldown remove <player> ender_pearl`.

## Going further

### Different values per world or region

Under an item, `worlds.<world>.cooldown` and `regions.<region>.cooldown` override the cooldown there; `-1` keeps the item's value. `regions.<region>.max-uses` limits how many times the item can be used while the player is in that region: the count starts over when they leave it (or on a restart or reload), and the action bar shows `actionbar.format-limited` with the uses so far.

Which value applies, where the player stands: the world's value first, then the highest priority region's, then `combat-cooldown` while tagged, then `cooldown`. Regions are WorldGuard regions and ExyliaLib regions, by id, when those [safe-zone sources](/docs/exyliacombat/restrictions#safe-zones) are on.

### Clear or change a cooldown as staff

`/combatadmin cooldown set|add|decrease <player> <id|ALL> <seconds>` and `/combatadmin cooldown remove <player> [id]` change a player's cooldowns, up to 86400 seconds. An id is the material in lower case, such as `ender_pearl` (`vanilla:ender_pearl` also works); `ALL` is every configured item. In the admin panel, open **Cooldowns** on a player: left click sets, right click adds, shift-left click decreases and shift-right click removes. **Remove all** clears them. See [Commands](/docs/exyliacombat/commands).

### Show a cooldown in other plugins

`%exyliacombat_cooldown_<material>%` and `%exyliacombat_oncooldown_<material>%`, such as `%exyliacombat_cooldown_ender_pearl%`.

<Details title="Example file and keys">
```yaml
cooldowns:
  ENDER_PEARL:
    trigger: LAUNCH
    cooldown: 4.0
    combat-cooldown: 14.0
    display-name: '{primary}Ender Pearl'
    regions:
      crystal_hole:
        cooldown: 1.0
    worlds: {}
  ENCHANTED_GOLDEN_APPLE:
    trigger: CONSUME
    cooldown: 300.0
    combat-cooldown: -1.0
    display-name: '{secondary}Enchanted Golden Apple'
    regions:
      pot:
        max-uses: 1
```

| Key | What it does |
|---|---|
| `trigger` | What starts the cooldown, see below. Left out, an edible item is `CONSUME` and anything else `USE`. |
| `cooldown` | Seconds. |
| `combat-cooldown` | Seconds while the player is tagged. `-1` keeps `cooldown`. |
| `display-name` | How the item is named in the action bar and the admin panel. Empty: the material name. |
| `worlds.<world>.cooldown` | Seconds in that world. `-1` keeps the item's value. |
| `regions.<region>.cooldown` | Seconds in that region. `-1` keeps the item's value. |
| `regions.<region>.max-uses` | Uses allowed each time the player is in that region: the count starts over when they walk or teleport out (or on a restart or reload). `-1`: no limit. |
</Details>

### Triggers

<Details title="Triggers">
| Trigger | Checked and started when |
|---|---|
| `USE` | The item is right-clicked. |
| `USE_ON_ELYTRA` | The item is right-clicked while gliding. |
| `CONSUME` | The item is eaten or drunk. |
| `LAUNCH` | The item is thrown: ender pearls, splash and lingering potions (configured as `SPLASH_POTION`), snowballs, eggs. |
| `BOW_SHOOT` | A bow or crossbow of that material is shot. |
| `ELYTRA_BOOST` | A firework boosts an elytra flight. |
| `RESURRECT` | A totem saves the player from death. While on cooldown, the totem does not save them. |
</Details>

### Defaults

<Details title="Items in the default file">
| Material | Trigger | Cooldown | In combat | Regions in the default file |
|---|---|---|---|---|
| `ENCHANTED_GOLDEN_APPLE` | `CONSUME` | 300s | same | `pot`, `mazoswap`, `mazo`: 1 use |
| `TOTEM_OF_UNDYING` | `RESURRECT` | 0s | same | `pot`, `mace`: 4 uses |
| `ENDER_PEARL` | `LAUNCH` | 4s | 14s | `crystal_hole`, `crystal_flat`, `mace`: 1s |
| `GOLDEN_APPLE` | `CONSUME` | 3s | same | `crystal_hole`, `crystal_flat`: 2s |
| `FIREWORK_ROCKET` | `ELYTRA_BOOST` | 12s | same | `__global__`: 0s |

The region names are examples from a practice server: rename them to your own regions or remove them.
</Details>
