Todos los comandos, con el permiso que necesita cada uno. Los ids de cajas y de llaves se autocompletan al escribir.

Hay dos comandos: `/crates` para jugadores y `/cratesadmin` (también `/cratesa`) para el staff. Las cajas se construyen en los menús que abre `/cratesadmin`, no con subcomandos. Los subcomandos existen para las llaves, para que una tienda o un script lleguen a ellas sin menú.

<Commands />

## Qué comandos funcionan desde la consola

`reload`, `key give`, `key giveall`, `key virtual`, `key take`, `key set`, `key create`, `key delete` y `key list` se ejecutan desde la consola. El resto abre un menú y necesita un jugador. `key give` necesita que el objetivo esté conectado; `key virtual`, `key take` y `key set` también funcionan con jugadores desconectados.

## Qué puedes escribir en `<key>`

`<key>` se autocompleta con el id de cada llave. También acepta el id de una caja: el plugin lo lee como la llave de esa caja, así que un comando de tienda puede nombrar la caja. Ver [Llaves y precios](/docs/exyliacrates/llaves).

## Ítems de llave o saldo de llaves

`key give` y `key giveall` entregan **ítems** de llave, que el jugador puede intercambiar o tirar. `key virtual` suma al **saldo**, que se comparte en toda tu red y no se puede perder. Usa `key virtual` para las compras de una tienda web. `key take` y `key set` solo cambian el saldo, nunca los ítems de llave. Si el inventario del jugador está lleno, los ítems de llave esperan a su próxima conexión.

No hay comando para crear, editar o colocar una caja. Eso se hace en la lista de cajas que abre `/cratesadmin` y con la varita de cajas: ver [Crear una caja](/docs/exyliacrates/cajas). Tampoco hay comando para borrar datos: `/exylialib wipe` y `/exylialib resetplayer` de ExyliaLib cubren los datos de este plugin, ver [Instalación](/docs/exyliacrates/instalacion#borrar-y-reiniciar-datos).

## Qué hace reload

`/cratesadmin reload` vuelve a leer `config.yml`, `tiers.yml`, `messages.yml`, cada archivo de animación y los menús, y reinicia la animación en reposo. Las aperturas que ya están en marcha terminan como empezaron. No redibuja los hologramas que ya están puestos (ver [Crear una caja](/docs/exyliacrates/cajas#el-holograma)), y las cajas y llaves no se releen de la base de datos: se cargan al arrancar.
