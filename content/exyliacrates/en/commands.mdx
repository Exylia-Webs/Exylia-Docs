Every command, with the permission it needs. Crate ids and key ids complete as you type.

There are two commands: `/crates` for players and `/cratesadmin` (also `/cratesa`) for staff. Crates themselves are built in the menus that `/cratesadmin` opens, not with subcommands. The subcommands exist for keys, so a store or a script can reach them without a menu.

<Commands />

## Which commands work from the console

`reload`, `key give`, `key giveall`, `key virtual`, `key take`, `key set`, `key create`, `key delete` and `key list` run from the console. The rest open a menu and need a player. `key give` needs the target to be online; `key virtual`, `key take` and `key set` also work on players who are offline.

## Names you can type in `<key>`

`<key>` completes with every key id. It also accepts a crate id: the plugin reads it as that crate's key, so a store command can name the crate. See [Keys and costs](/docs/exyliacrates/keys).

## Key items or key balance

`key give` and `key giveall` hand over key **items**, which a player can trade or drop. `key virtual` adds to the **balance**, which is shared across your network and cannot be lost. Use `key virtual` for web store purchases. `key take` and `key set` only change the balance, never key items. If a player's inventory is full, key items wait for their next join.

There is no command to create, edit or place a crate. That happens in the crate list that `/cratesadmin` opens and with the crate wand: see [Create a crate](/docs/exyliacrates/crates). There is no wipe command either: ExyliaLib's `/exylialib wipe` and `/exylialib resetplayer` cover this plugin's data, see [Installation](/docs/exyliacrates/installation#wiping-and-resetting-data).

## What reload does

`/cratesadmin reload` reads `config.yml`, `tiers.yml`, `messages.yml`, every animation file and the menus again, and restarts the idle animation. Openings already playing finish as they started. It does not redraw holograms already standing (see [Create a crate](/docs/exyliacrates/crates#the-hologram)), and it reads crates and keys from the database again, so a row edited outside the game or by another server takes effect without a restart. <Since v="1.2.0" />
