Two roots: `/crates` for players and `/cratesadmin`, also `/cratesa`, for staff. Building and editing crates
happens in the menus `/cratesadmin` opens; the subcommands are for keys, which a store or a script has to
reach without a menu.

## Player commands

Every command here needs `exyliacrates.use`, which everybody has by default, and runs for players only.

| Command | What it does |
|---|---|
| `/crates` | Lists the keys you hold, items and balance together, with the crates each one opens. |
| `/crates preview <crate>` | Opens the crate's contents with the real odds for you. |
| `/crates open <crate> [true]` | Opens the crate in front of you, wherever you are. With `true`, as many times as you can pay for, up to `settings.max-multi-open`. |
| `/crates history` | Your latest openings. |

`<crate>` suggests every crate's id. An unknown one answers "That crate does not exist."

`/crates open` follows every rule of opening at the block — costs, the crate being enabled, one opening at a
time — and is open to every player for every crate. See [Openings](/docs/exyliacrates/openings#opening-away-from-the-block).

## Admin commands

Every command here needs `exyliacrates.admin`, operators by default. The **Console** column says which also
run from the console.

| Command | Console | What it does |
|---|---|---|
| `/cratesadmin` | | Opens the crate list. See [Crates](/docs/exyliacrates/crates). |
| `/cratesadmin keys` | | Opens the key list. See [Keys and costs](/docs/exyliacrates/keys#the-keys-screen). |
| `/cratesadmin history` | | The latest openings of every crate on the server. |
| `/cratesadmin reload` | yes | Reads the files, the animations and the menus again. |
| `/cratesadmin key give <player> <key> <amount>` | yes | Hands an online player key items. |
| `/cratesadmin key giveall <key> <amount>` | yes | Hands everybody online on this server key items. |
| `/cratesadmin key virtual <player> <key> <amount>` | yes | Adds to a player's key balance, online or not. What a web store should call. |
| `/cratesadmin key take <player> <key> <amount>` | yes | Takes from a player's key balance, never below 0. |
| `/cratesadmin key set <player> <key> <amount>` | yes | Sets a player's key balance; a negative amount sets 0. |
| `/cratesadmin key create <id>` | yes | Creates a key no crate takes yet. Ids are lowercase letters, numbers, `-` and `_`, up to 64 characters. |
| `/cratesadmin key delete <key>` | yes | Deletes a key and takes it out of every crate's costs. A player is asked to confirm, with how many crates take it; the console is not. |
| `/cratesadmin key list` | yes | Every key, its name and how many crates take it. |

`<key>` suggests every key's id. It also accepts a crate's id, read as that crate's key — the first key its
cost lists — so a store command can name the crate.

`take` and `set` act on the balance only, never on key items. What each give, take or set tells the player,
and how key items reach a full inventory, is on [Keys and costs](/docs/exyliacrates/keys#giving-and-taking-keys).

There is no command to create, edit or place a crate: that is the crate list's job, and the wand's.

## What reload does

`/cratesadmin reload` reads `config.yml`, `tiers.yml`, `messages.yml` and every animation file again, throws
away the compiled effect lines so edited ones play next time, restarts the idle loop with its new interval,
and recompiles the menus. Openings already playing finish as they started.

It does not redraw holograms already standing; see [Crates](/docs/exyliacrates/crates#the-hologram). Crates
and keys are not re-read from the database: they are only ever loaded at startup.
