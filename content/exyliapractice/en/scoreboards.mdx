ExyliaPracticeCore draws a sidebar for every state a player can be in: lobby, party, queue, each kind of match, and each kind of spectating. They all live in one file, `scoreboards.yml`. This guide shows how to change a line, which of the twenty sidebars to edit, and which tokens each one can use. It also covers the match action bar and the titles shown at the start and end of a match.

## Before you start

- ExyliaPracticeCore is installed and has booted once, so the file exists: see [Installation](/docs/exyliapractice/installation).
- You know the language folder in use: `plugins/ExyliaPracticeCore/lang/<language>/`, where `<language>` is the `language` setting in `config.yml`. See [Configuration](/docs/exyliapractice/configuration#language).
- Colour tokens such as `{primary}` and `{success}` are the shared ExyliaLib ones: see [Colours](/docs/exylialib/colours).

## Steps

<Steps>
  <Step title="Pick the sidebar">
    Find the state you want to change in the table below. A 1v1 with no points and no hit target shows `game`; with `points-to-win` it shows `game-points`.
  </Step>
  <Step title="Open scoreboards.yml">
    Edit `plugins/ExyliaPracticeCore/lang/<language>/scoreboards.yml`. Every sidebar sits under the top-level `scoreboards:` key and has the same shape:

    ```yaml
    scoreboards:
      lobby:
        enabled: true
        title:
          - "{primary}&lPRACTICE"
        lines:
          - ""
          - " {info}🌎 {letters}Online: {success}%server_online%"
          - " {highlight}{server-ip}"
        update:
          interval: 20
          smart: true
          cache: true
    ```

    `title` is a list: several entries animate through them. `update.interval` is in **ticks** (20 is one second). Set `enabled: false` to hide that sidebar.
  </Step>
  <Step title="Change the lines">
    Edit, add or remove lines. Use the tokens of the matching sidebar from the lists further down; every [placeholder](/docs/exyliapractice/placeholders) and every other plugin's PlaceholderAPI placeholders also resolve inside a line.
  </Step>
  <Step title="Reload">
    Run `/epc reload` (or `/epc` and click **Reload**). Open sidebars are drawn again from the new file for everyone online.
  </Step>
</Steps>

## The twenty sidebars

| Key | Shown to |
|---|---|
| `lobby` | A player in the lobby with no party |
| `party` | A player in the lobby who is in a party |
| `queue` | A queued player |
| `game` | A 1v1 with no points and no hit target |
| `game-points` | A 1v1 with `points-to-win` |
| `game-hits` | A 1v1 with `hits-to-win` |
| `duel` | A multi-round duel |
| `duel-points` | A multi-round duel with points |
| `duel-hits` | A multi-round duel with a hit target |
| `party-ffa` | A party free-for-all |
| `party-team` | A party split or party duel |
| `bot-practice` | A fight against bots, alone or as a party. See [Bot PvP](/docs/exyliapractice/bot-pvp) |
| `spec-game` | Spectating a plain 1v1 |
| `spec-game-points` | Spectating a 1v1 with points |
| `spec-game-hits` | Spectating a 1v1 with hits |
| `spec-duel` | Spectating a duel |
| `spec-duel-points` | Spectating a duel with points |
| `spec-duel-hits` | Spectating a duel with hits |
| `spec-party-ffa` | Spectating a party FFA |
| `spec-party-team` | Spectating a party team match |

The right one is picked automatically from the match mode, whether the kit has `points-to-win`, and whether it has `hits-to-win`. Points win the tie when both are set. Those are kit rules, see [Kit rules](/docs/exyliapractice/kit-rules). Spectating is covered in [Spectating](/docs/exyliapractice/spectating).

## Check that it works

- Join the lobby: the lobby sidebar shows your edit. If nothing changed, the `language` setting may point at a different folder than the one you edited.
- Queue for a kit and start a match: the matching `game*` sidebar appears in the match.
- A player who has turned the scoreboard off in `/settings` (the **Scoreboard** setting) sees none of them. Test with it on.

## Going further

### Change the server address

The last line of every shipped sidebar is `{server-ip}`. It is not a placeholder but a library token, like the colour tokens: it writes the `server-ip` value of ExyliaLib's `colors.yml`, so changing the address there updates every sidebar at once. See [Colours](/docs/exylialib/colours).

### Show the rank and rating

Use `%rank_name%` (rank and division, `Copper II`), `%rank_lp%`, `%rank_lp_max%`, `%rank_icon%` and `%mmr%`. What they mean depends on the sidebar: in the lobby the global rating, in the queue the first kit queued for, in a match the kit being played. See [ELO and ranks](/docs/exyliapractice/elo).

### Edit the match action bar

Separate from the sidebar, the combat readout above the hotbar is configured under `effects.match-actionbar` in the language's `messages.yml`. The default is:

```
%opponent_health% | %hits_dealt%↑%my_combo% %hits_received%↓%combo_received%
| %damage_dealt%⚔ / %damage_received%⚔ | %accuracy% / %opponent_accuracy%🎯
| %my_ping%ms / %opponent_ping%ms
```

See [Messages and languages](/docs/exylialib/messages-and-languages) for how that file works.

### Change titles and sounds

The match's other visuals live in the `effects` section of the language's `messages.yml` rather than in `scoreboards.yml`:

| Key | When |
|---|---|
| `effects.countdown-title` | Each second of the pre-match countdown, with `%time%` |
| `effects.fight-title` | The moment the match starts |
| `effects.you-won-title`, `effects.you-lost-title`, `effects.draw-title` | The result |
| `effects.round-won-title`, `effects.round-lost-title`, `effects.round-draw-title` | Between rounds, with `%my_wins%` and `%their_wins%` |
| `effects.match-actionbar`, `effects.bot-actionbar` | The live combat readout, against players and against bots |
| `effects.match-found-title`, `effects.match-found-actionbar` | While the arena is being prepared |
| `effects.in-queue-actionbar` | While queued, with `%kits%`, `%time%` and `%elo%` |
| `effects.teaser-bossbar` | The rotating queue advertisement |
| `effects.combat-tag-bossbar` | While combat-tagged in a PvP zone, with `%time%` |
| `effects.season-progress-bossbar` | During a season rotation, with `%phase%` and `%percent%` |

The sounds stay in `config.yml`, under `game`. Each of those blocks is a full effect definition (a title, an action bar, a boss bar, a sound and a particle), so any of them can carry more than the one thing its name suggests.

## Tokens by sidebar

<Details title="Lobby and party tokens">

| Token | Answers |
|---|---|
| `%server_online%` | Players online on the server |
| `%queue%` | Players queued server-wide |
| `%fighting%` | Players in a match server-wide |
| `%wins%` | The reader's global wins |
| `%kdr%` | Their global kill/death ratio, one decimal |
| `%win_rate%` | Their global win rate as a percentage |
| `%mmr%` | Their global rating |
| `%rank%` | The rank's name on its own: `Copper` |
| `%rank_division%` | The division on its own: `II`. Empty for a rank that has none |
| `%rank_name%` | The rank and its division together: `Copper II` |
| `%rank_lp%` | LP inside the current division |
| `%rank_lp_max%` | The division's width in LP |
| `%rank_icon%` | The rank's icon |
| `%members%` | How many players are in the party. `party` only |
| `%max%` | The party's maximum size. `party` only |
| `%leader%` | The party leader's name. `party` only |
</Details>

<Details title="Queue tokens">

| Token | Answers |
|---|---|
| `%kit%` | The first kit queued for, with `+N` when there are more |
| `%time%` | How long they have been waiting |
| `%queue%` | Players queued server-wide |
| `%fighting%` | Players in a match server-wide |
| `%wins%` | The reader's global wins |
| `%kdr%` | Their global kill/death ratio, one decimal |
| `%win_rate%` | Their global win rate as a percentage |
| `%mmr%` | Their rating on the first kit queued for |
| `%rank%` | That kit's rank name on its own |
| `%rank_division%` | That rank's division on its own |
| `%rank_name%` | That rank and its division together |
| `%rank_lp%` | LP inside that division |
| `%rank_lp_max%` | That division's width in LP |
| `%rank_icon%` | That rank's icon |

The rank tokens here are the rating on **that first kit**, not the global one. `%server_online%` is not filled in on this sidebar; the queue board is built without it.
</Details>

<Details title="In-match tokens">

| Token | Answers |
|---|---|
| `%kit%` | The kit's name |
| `%arena%` | The arena's name |
| `%time%` | Match duration |
| `%my_points%` | The reader's points |
| `%their_points%` | The opponent's points |
| `%points_to_win%` | The kit's `points-to-win` |
| `%hits%` | Hits **received** by the reader |
| `%opp_hits%` | Hits **received** by the opponent |
| `%hits_to_win%` | The kit's `hits-to-win` |
| `%round%` | The current duel round |
| `%total_rounds%` | How many rounds the duel is played over |
| `%my_wins%` | Rounds the reader has won |
| `%their_wins%` | Rounds the opponent has won |
| `%my_ping%` | The reader's latency |
| `%opp_ping%` | The opponent's latency |
| `%alive%` | Players still alive |
| `%total%` | Players the match started with |
| `%team_a_alive%` | Team A survivors |
| `%team_b_alive%` | Team B survivors |
| `%mmr%` | The reader's rating on the kit being played |
| `%rank%` | Their rank name on that kit, on its own |
| `%rank_division%` | That rank's division on its own |
| `%rank_name%` | That rank and its division together |
| `%rank_lp%` | LP inside that division |
| `%rank_lp_max%` | That division's width in LP |
| `%rank_icon%` | That rank's icon |
| `%opponent%` | The opponent's name, 1v1 only |
| `%opp_mmr%` | The opponent's rating on the kit, 1v1 only |
| `%opp_rank%` | The opponent's rank name on its own |
| `%opp_rank_division%` | Their division on its own |
| `%opp_rank_name%` | Their rank and division together |
| `%opp_rank_lp%` | Their LP inside that division |
| `%opp_rank_lp_max%` | That division's width in LP |
| `%opp_rank_icon%` | Their rank's icon |

The reader's own rank tokens in a match are their rating **on the kit being played**. The opponent tokens are filled in for a 1v1 and answer `?` or `0` in every other mode.

Three more are filled in only when the match is against bots:

| Token | Answers |
|---|---|
| `%bot_mode%` | The combat mode the bots are fighting in |
| `%bot_difficulty%` | The difficulty they were spawned at |
| `%bots_alive%` | How many bots are still alive |
</Details>

| Token | Answers |

| `%time%` | Match duration |

| `%team_b_alive%` | Team B survivors |
| `%player1_name%` | The first player's name |
| `%player1_ping%` | Their latency |
| `%player1_points%` | Their points |
| `%player1_hits%` | Hits they have **received** |
| `%player1_wins%` | Rounds they have won |

| `%player1_rank_name%` | Their rank and division together |

| `%player1_rank_lp_max%` | That division's width in LP |
| `%player1_rank_icon%` | Their rank's icon |
| `%player2_name%` | The second player's name |

</Details>
