ExyliaPracticeCore keeps a set of counters for every player on every kit (wins, kills, damage, streaks, rating and more), plus an overall "global" ladder. This page explains where those numbers live, when a match writes them, how `/stats` ranks players and how an admin corrects them. You do not need to set anything up: stats are counted from the first match.

## Three tiers

| Tier | Table | Scope |
|---|---|---|
| **Season** | `practice_player_season_stats` | One row per player, per kit, per season |
| **Lifetime** | `practice_player_lifetime_stats` | One row per player, per kit, across every season |
| **Match** | `practice_match_history` | One row per player, per match |

Every ladder, sidebar, placeholder and menu reads the **season** tier. The lifetime tier is the permanent record and survives every season rotation, see [Seasons](/docs/exyliapractice/seasons). The match tier is the [match history](/docs/exyliapractice/match-history).

The **global** ladder is not a separate table: it is one more row in the same tables, stored under the kit id `global`. That is what lets one query answer both "top on Sumo" and "top overall".

<Details title="What a row holds">

| Group | Fields |
|---|---|
| Result | `wins`, `losses`, `draws`, `winRate` |
| Combat | `kills`, `deaths`, `kdr`, `damageDealt`, `damageTaken` |
| Accuracy | `hitsDealt`, `hitsReceived`, `totalSwings` |
| Combo | `bestCombo`, `comboSum`, `comboSamples` |
| Streaks | `currentStreak`, `bestStreak` |
| Rating | `elo`, `peakElo`, `lowElo`, `rankedGamesPlayed` |
| Time | `timePlayed`, `firstMatchAt`, `lastMatchAt` |

`winRate` and `kdr` are stored, not computed on read, so a leaderboard can order by them in the database.
</Details>

## When a match writes its numbers

Kills and deaths are recorded **as they happen**, so a live sidebar and a kill streak stay accurate mid-match. Everything else (the result, damage dealt and taken, hits, swings, best combo and time played) is committed **once**, when the match ends, as a single delta per player.

A match that is `CANCELLED`, or that never left the countdown, writes nothing at all.

<Callout type="note" title="Damage taken is derived from what the others dealt">
There is no separate damage-taken accumulator. Your damage taken is the sum of everybody else's damage dealt in that match, which in a 1v1 is exactly your opponent's output.
</Callout>

## Leaderboards

A player runs `/stats`, `/lb` or `/leaderboard`. The menu opens on the category list, then the kits (the global card is **Global stats**), then a per-kit leaderboard. Each kit card shows the reader's own rank, LP, position and counters. The leaderboard can be sorted by eleven counters, picked with the buttons along the bottom:

`rank`, `kills`, `deaths`, `kdr`, `wins`, `losses`, `win rate`, `best streak`, `current streak`, `damage dealt`, `time played`.

`/stats <player>` opens somebody else's stats; if they are offline, their UUID is looked up by name. Both commands need `exyliapractice.stats`, which everyone has by default. See [Commands](/docs/exyliapractice/commands) and [Permissions](/docs/exyliapractice/permissions).

Leaderboards are cached for **5 minutes** and ordered by the database against a season-scoped index. A board that has gone stale is served from the last copy while a fresh one loads in the background, so a menu never blocks on a query. A match result and an admin edit (`/epc stats set`, `add`, `remove`) both clear the cache, so the next time a player opens the board it already shows the change. If a correction seems to have no effect, check that you edited the right kit id (or `global`) and that you are looking at the current season: lifetime numbers are not touched.

<Details title="Leaderboard settings and rank text">

| Setting | Default | What it does |
|---|---|---|
| `leaderboard.max-entries` | `50` | How many rows a leaderboard holds |

On the `rank` board, each row's value comes from the language's `messages.yml`, so every part can be coloured (see [Colours](/docs/exylialib/colours) and [Messages and languages](/docs/exylialib/messages-and-languages)):

| Key | Default | Used for |
|---|---|---|
| `leaderboard.rank.value` | `%rank% %lp%/%lp_max%` | A rank with divisions. `%rank%` is the name and division, `%lp%` the LP, `%lp_max%` the division's width, `%elo%` the ELO. |
| `leaderboard.rank.value-top` | `%rank% %elo%` | A rank without LP (the top tier). Same placeholders. |

The menus themselves are `menus/player/leaderboard.yml`, `stats_category.yml` and `stats_kit.yml` in the language folder; see [Edit menus](/docs/exylialib/edit-menus).
</Details>

## Admin commands

All of these need `exyliapractice.admin` and take `global` in place of a kit id to reach the overall ladder.

<Commands group="data" />

The editable fields are:

```
kills  deaths  wins  losses  elo
best-streak  current-streak  damage  time
```

`best-streak` and `current-streak` also accept `beststreak` and `currentstreak`. Every field is clamped at zero: `add` and `remove` cannot take a counter negative. `time` is in milliseconds.

<Callout type="note" title="These edit the current season only">
The lifetime tier is not touched by `stats set` or `stats add`, so a correction to a season row does not rewrite the permanent record.
</Callout>

## Bulk operations

Run `/epc`, click **Data management**. Every action asks for confirmation first and none can be undone:

| Button | What it does |
|---|---|
| **Clear kit stats** | Deletes every current-season row for one kit |
| **Clear all stats** | Deletes every current-season row |
| **Reset kit ELO** | Sets every current-season rating on one kit back to `elo.starting-mmr` |
| **Reset all ELO** | The same for every kit |
| **Clear kit loadouts** | Deletes every player's saved loadouts for one kit |
| **Export database** / **Import database** | A full database dump, through ExyliaLib's transfer module |
| **Player data** | One player's data, see ExyliaLib's `/exylialib resetplayer` below |

To start a fresh competitive period without losing the lifetime record, use **New season** in the same screen; see [Seasons](/docs/exyliapractice/seasons).

Wiping every loadout or the whole match history, and resetting one player, are ExyliaLib's `/exylialib wipe` and `/exylialib resetplayer`; see [Database](/docs/exyliapractice/database).
