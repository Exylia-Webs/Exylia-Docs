You will change how one kit plays: whether players can build, how a match is won, which cooldowns apply, what effects and attributes they start with. The rules are stored as JSON on the kit row. Most become policies on the arena's region for the length of the match; the rest are enforced by the plugin's own match listener.

## Before you start

- The kit exists: see [Create kits and categories](/docs/exyliapractice/kits).
- You have `exyliapractice.admin` (operators do).

## Steps

<Steps>
  <Step title="Open the rules screen">
    Run `/epc`, click **Manage kits** → **All kits** → your kit → **Kit rules**. The screen is a hub of seven cards: **Arena flags**, **Combat**, **Win conditions**, **Cooldowns**, **Potion effects**, **Attributes** and **Special conditions**.
  </Step>
  <Step title="Open the card for what you want to change">
    Building and item rules are in **Arena flags**; hit delay, build height and damage in **Combat**; hits, points, revives and rounds in **Win conditions**; pearl, golden apple and arrow cooldowns plus the start countdown in **Cooldowns**.
  </Step>
  <Step title="Change the value">
    Toggles flip with one click. Numbers use left click for +1 and right click for -1 (Shift for 5). Durations are typed in chat as a length of time, such as `250ms`, `3s` or `1m30s`.
  </Step>
  <Step title="Go back and test">
    Each click updates the kit straight away. Start a match with the kit to see the rule at work.
  </Step>
</Steps>

<Callout type="tip" title="Times are typed, not clicked">
Every duration on these screens is asked for as a length of time (`250ms`, `3s`, `1m30s`) instead of being clicked up one second at a time. Anything the plugin writes back reads the same way, so `0s` means off wherever a rule takes a time.
</Callout>

## Recipes

### A boxing kit

Open **Win conditions** and set **Hits to win** to `100`. Nothing else is needed: the first player to take 100 hits loses. The sidebar's `%hits%` is your own hits received and `%opp_hits%` is your opponent's.

### First to 3 points

In **Win conditions** set **Points to win** to `3`, leave **Kills give points** on and set **Revive time** to `5s`. An elimination scores, the loser is revived after the revive time, and **Regenerate after point** optionally restores the arena between points. To score another way, see [Special conditions](/docs/exyliapractice/special-conditions).

### A building kit

Open **Arena flags** and set **build** and **block-break** on. To stop players tearing up the map, also turn on **player-build-only** so only blocks players placed can be broken. Set a **Build height limit** in **Combat** to stop towering. Block placing and breaking is also blocked inside the arena's [spawn protection and extra region protection radii](/docs/exyliapractice/arenas#protection-radii), whatever these rules say.

### Best of 3 in the queue

**Win conditions** → **Queue rounds**: `2` is best of 3, `3` is best of 5. `0` follows the server setting `queue.rounds-to-win` (`1` by default, a single fight) from [Configuration](/docs/exyliapractice/configuration).

### Give players potion effects

Left click **Potion effects** to open the effect editor. Each entry is an effect name, a level and a duration in seconds; a duration of infinite lasts the whole match. Every existing effect on the player is stripped first, so what a kit grants is exactly what the player has. Right click the card to toggle whether the effects come back after a Totem of Undying pops.

### Change health, damage or speed

Open **Attributes**. Left click an attribute to type its value, right click to reset it to vanilla.

## Check that it works

- Start a match with the kit and try the rule: place a block, take the number of hits, throw a pearl twice.
- The cards on the rules screen summarise the current values (for example `Hits`, `Points`, `Pearl`, `Gapple`, `Arrow`, active effects, active triggers), so you can read them back without opening each one.

## Going further

<Details title="Arena flags: building and items">
Set from **Arena flags**, the shared flag editor, where **Default** stores the value in the table below.

| Rule | Default | What it does |
|---|---|---|
| `build` | off | Players may place blocks |
| `block-break` | off | Players may break blocks |
| `interact` | on | Players may interact with blocks |
| `player-build-only` | off | Only blocks players placed may be broken |
| `disappearing-blocks-delay` | `0` | Seconds before a placed block vanishes. `0` disables it. |
| `re-give-blocks` | off | The block is handed back when it disappears |
| `item-drop` | on | Players may drop items |
| `item-pickup` | on | Players may pick items up |
| `pvp` | on | Players may damage each other |
| `fall-damage` | on | Fall damage applies |

A player is put in adventure mode when `build`, `block-break` and `player-build-only` are all off, and in survival otherwise. There is no game-mode setting.
</Details>

<Details title="Combat: damage and health">
| Rule | Default | What it does |
|---|---|---|
| `disabled-damage` | off | All damage is off |
| `health-regeneration` | on | Natural regeneration |
| `food-decreasing` | on | Hunger drains |
| `hit-delay` | `20` | The player's `maximumNoDamageTicks`, the invulnerability window after a hit, in ticks. `20` is vanilla; lower it for combo kits. Typed in chat as `250ms`, `1s` or `0s`. |
| `build-height-limit` | `0` | How many blocks above the arena's highest spawn (either team's, or the party FFA one) players may place blocks, the same ceiling for everybody. Higher is refused with `game.build-height-limit`. `0` means no limit beyond the arena's region. |
</Details>

<Details title="Win conditions">
| Rule | Default | What it does |
|---|---|---|
| `hits-to-win` | `0` | A player who has *received* this many hits is eliminated. `0` disables it. |
| `points-to-win` | `-1` | Points needed to win. `-1` disables it. |
| `kills-give-points` | on | An elimination awards a point |
| `revive-time` | `0` | Seconds an eliminated player spectates before respawning. `0` disables revives. |
| `rounds-to-win` | `0` | Rounds a player must win to take a queue match, ranked or unranked. `0` follows the server's `queue.rounds-to-win`. |
| `bed-respawn` | off | Killed players respawn, after `revive-time`, while their team's bed stands. Once an enemy breaks it, their next death is final. |
| `iron-plate-checkpoints` | off | Heavy weighted pressure plates set a checkpoint. Dying or leaving the arena returns you there instead of eliminating you. |
| `regenerate-after-point` | off | The arena is restored from its schematic between points |

Points and revives together turn a 1v1 into a first-to-N.

**Bed respawn.** With `bed-respawn` on, a bed belongs to the team whose spawn it is closest to. An enemy can always break it, whatever the kit's break rules or the arena's protection say, and nobody can break their own. The whole match is told whose bed fell and who broke it. While the bed stands a death never ends the match, and points are not scored from kills. It applies to team and 1v1 fights, not to a party FFA or a fight against bots, and the arena is regenerated after the match.

**Checkpoints.** A player sent back to a checkpoint gets no invulnerability on arrival. Checkpoints are per plate and one-shot: standing on the same block again does not re-arm it, but a new plate does. They reset at the start of every round and every point.
</Details>

<Details title="Cooldowns and the start countdown">
| Rule | Default | What it does |
|---|---|---|
| `ender-pearl-cooldown` | `0` | Cooldown between pearls. `0` uses the server default. |
| `golden-apple-cooldown` | `0` | Cooldown on both golden apple types, in seconds. `0` disables it. |
| `arrow-cooldown` | `0` | Seconds a bow or crossbow waits between shots. A player left with no arrows gets one back when the wait ends. `0` disables it. |
| `start-countdown` | on | The match opens with the start countdown. Off, the fight starts as soon as the arena is ready, with no skip vote. |

These three cooldowns are stored in seconds, unlike `hit-delay`, which is in ticks. Older builds mislabelled the pearl one as `ticks` in the rules menu; the value it stored was always seconds, so an existing kit needs no change.
</Details>

<Details title="Attributes and starting state">
Set from **Attributes**. `-1` on any of them means leave the vanilla value alone. Attributes are applied as base values at the start of a match and again after every point reset.

| Attribute | Vanilla | Range |
|---|---|---|
| `max-health` | 20 | |
| `attack-damage` | 2 | |
| `movement-speed` | 0.1 | |
| `knockback-resistance` | 0 | up to 1 |
| `start-health` | full | capped at max health |
| `start-food` | 20 | 0 to 20 |
| `start-saturation` | 20 | 0 to 20 |
</Details>

<Details title="Potion effects and totems">
Each effect is stored as an effect name, an amplifier and a duration in seconds (`-1` lasts the whole match), plus the particles, icon and ambient flags the editor shows.

A Totem of Undying clears the kit's effects, as it does in vanilla. The `keep_effects_on_totem` rule (off by default, and off for kits saved before it existed) gives them back after the totem pops, with a timed effect returning only the time it had left. Potions the player drank go with the totem either way.
</Details>
