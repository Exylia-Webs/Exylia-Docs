Most settings are a button, not a file: run `/epc` and click **Settings**. Open this page when you want a file's location, a default, or every key at once.

The files live in `plugins/ExyliaPracticeCore/`: `config.yml` for the settings below, `ranks.yml` for the [ranks](/docs/exyliapractice/elo), and a `lang/<code>/` folder with the messages, sidebars and menus a player reads. All of them are generated on first boot with their defaults.

## Editing in game and reloading

`/epc` → **Settings** (needs `exyliapractice.admin`), or `/exylialib config ExyliaPracticeCore`, opens ExyliaLib's settings screens for `config.yml`, one page per group: Lobby, Matches, Parties & queue, Ranked, Seasons & replays. What you change there is checked and written back to the file. `messages.yml` and `scoreboards.yml` are not on those screens.

Editing the file by hand works too: save it and run `/epc reload`. Values are read fresh on each use, with one exception, `duel.request-expiry-seconds`, which needs a restart. To translate or recolour text, see [messages and languages](/docs/exylialib/messages-and-languages) and [colours](/docs/exylialib/colours).

<Callout type="note" title="The text a player reads lives in messages.yml">
Titles, action bars, boss bars and item names are not in `config.yml`. They sit in the language's `messages.yml`, under `effects` (`countdown-title`, `fight-title`, `you-won-title`, `you-lost-title`, `draw-title`, `match-actionbar`, `bot-actionbar`, `in-queue-actionbar`, `match-found-title`, `match-found-actionbar`, `teaser-bossbar`, `round-won-title`, `round-lost-title`, `round-draw-title`, `combat-tag-bossbar`, `season-progress-bossbar`) and `labels` (`spectators-hidden`, `spectators-visible`). A server coming from version 2 has its edited blocks moved there on the first start, so nothing it wrote is lost.
</Callout>

## `language`

```yaml
language: default
```

Which folder under `plugins/ExyliaPracticeCore/lang/` the menus, messages, scoreboards, hotbar items and replay controls are read from. `default` follows the `language` set in ExyliaLib's own `config.yml`; `en`, `es`, `pt`, `fr`, `ru` or `tr` set this plugin alone. A server that ran the plugin before languages existed has its own files moved to `lang/custom/` and is pointed at it with `language: custom`, so nothing it edited is lost.

### Top level

| Key | Default | What it does |
|---|---|---|
| `language` | `default` | See above |
| `defer-to-exylia-lobby` | `true` | With ExyliaLobby installed, the lobby jump pads, the portal and PvP regions, the double jump and the show/hide-players toggle are left to it. Queues, parties and matches are untouched. `false` keeps this plugin's own lobby features. |
| `places-scope` | `default` | Which servers share the arenas, jump pads and the PvP and portal regions. `default` follows the network group set in ExyliaLib's `config.yml` (identical servers of a pool share them; no group means every server shares), `server` gives each server its own, `global` shares them with all. |

## Version 5 sounds

Version 5 swaps the long, loud match and double-jump sounds for short, quiet ones. On the first start after the update, `game.countdown-fight-sound`, `game.you-won-sound`, `game.you-lost-sound` and `lobby.double-jump-sound` are replaced only where they still hold the old shipped value; a sound you picked yourself is kept. `messages.yml` (version 3) does the same for the leading sound tags of `game.bed-destroyed`, `elo.rank-up`, the season start and end lines, `link-profile.success` and the two `bot-pvp` lines.

## Migration from ExyliaCommons

A `config.yml` with no `config-version` is treated as version 1, the ExyliaCommons layout, and migrated in place. Every title, action bar and boss bar block is moved into the nested section the library expects, title durations are converted from ticks to seconds, and the obsolete `%time_decimal%` token is rewritten to `%time%`.

The six sections ExyliaCommons registered against this same file (`debug`, `formatters`, `text`, `tasks`, `chat-input`, `discord`) were the library's own settings and are removed on first load, each reported once as `UNKNOWN_KEY`. They live in ExyliaLib's files now.
