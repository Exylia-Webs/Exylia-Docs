Every node below is declared in `plugin.yml` (both the loader's and the plugin's), so the defaults shown
are what a player holds before a permissions plugin says otherwise.

## Staff and perks

Operators only until you grant them.

| Permission | Default | Description |
|---|---|---|
| `exyliapractice.admin` | op | The admin menu, `/epc` and every one of its subcommands, and every admin button in every menu, **Settings** included |
| `exyliapractice.bypass.command-whitelist` | op | Run any command while in a match, in a queue or in a PvP zone |
| `exyliapractice.lobby.fly` | op | Flight in the lobby. Also disables double jump, since flying replaces it. |
| `exyliapractice.lobby.bypass` | op | Always visible to everybody in the lobby, whatever their visibility settings say |
| `exyliapractice.lobby.vip` | op | Counted as a VIP by the **Show VIP** visibility setting |
| `exyliapractice.party.max_slots.*` | op | A party of up to `party.max-size` |

## Player features

Every player feature has a node of its own that **everybody holds by default**. A server turns one into a
rank perk by denying it to the default group and granting it to the rank: for example
`exyliapractice.duel.arena` set to `false` on `default` and `true` on `vip`. A player without the node is
told they lack permission when they try.

| Permission | Default | Description |
|---|---|---|
| `exyliapractice.duel` | true | Send a duel request |
| `exyliapractice.duel.arena` | true | Choose the arena of a duel. Without it the arena step is skipped and the duel goes to a random arena. |
| `exyliapractice.duel.rounds` | true | The **Custom** button of a duel's rounds step. 1, 3 and 5 rounds need no node. |
| `exyliapractice.party` | true | Create a party |
| `exyliapractice.party.open` | true | Open a party to anyone (`/party open` and the party menu toggle) |
| `exyliapractice.party.announce` | true | `/party announce` |
| `exyliapractice.queue.ranked` | true | Join ranked queues. Without it a ranked kit is refused and quick queue skips ranked kits. |
| `exyliapractice.kiteditor` | true | Open the kit editor |
| `exyliapractice.spectate` | true | Watch other players' matches |
| `exyliapractice.spectate.bypass` | op | Watch a match even when its fighters turned spectators off |
| `exyliapractice.replay` | true | Watch match replays |
| `exyliapractice.history` | true | Browse match history |
| `exyliapractice.stats` | true | Open stats and leaderboards |
| `exyliapractice.settings` | true | Open the personal `/settings` menu |
| `exyliapractice.lobby.doublejump` | true | Double jump in the lobby |
| `exyliapractice.botpvp` | true | `/botpvp`, the party menu's **Bots** button, and opening the bot menu through the API. See [Bot PvP](/docs/exyliapractice/bot-pvp) |

Getting out is never behind a node: leaving a match, a queue or a party, and declining a duel, keep
working whatever the player holds.

## The numbered nodes

None of these needs registering; any whole number works.

| Permission | Which one counts | With no node |
|---|---|---|
| `exyliapractice.party.max_slots.<n>` | The highest, capped at `party.max-size` (100 by default) | `party.default-max-size`, 10 by default |
| `exyliapractice.kits.max_slots.<n>` | The highest | **1** saved loadout per kit, so the kit editor works for everybody |
| `exyliapractice.party.announce.cooldown.<n>` | The lowest | `party.announce-cooldown-seconds`, 60 by default |

- For the two `max_slots` nodes, giving `max_slots.5` on top of `max_slots.1` is an **upgrade**, not a
  conflict. A rank ladder can add nodes without removing the ones below.
- For the cooldown, less is the perk: a leader holding `cooldown.30` and `cooldown.10` waits ten seconds
  between announcements. A node replaces the configured value outright, so one above it makes the wait
  longer.
- A node set to `false` grants nothing, and a node whose tail is not a number is ignored.

<Callout type="note" title="Party size is the leader's permission">
The ceiling is checked against whoever is leader when the size is changed, not against the member
joining. Handing leadership to somebody with a lower ceiling does not shrink an already-large party.
</Callout>

## Suggested setup

```yaml
default:
  # every player feature is already granted; set one to false here to make it a perk
  # exyliapractice.duel.arena: false

vip:
  - exyliapractice.duel.arena
  - exyliapractice.lobby.vip
  - exyliapractice.kits.max_slots.3
  - exyliapractice.party.max_slots.15
  - exyliapractice.party.announce.cooldown.30

premium:
  - exyliapractice.lobby.fly
  - exyliapractice.kits.max_slots.10
  - exyliapractice.party.max_slots.30
  - exyliapractice.party.announce.cooldown.10

staff:
  - exyliapractice.lobby.bypass
  - exyliapractice.bypass.command-whitelist

admin:
  - exyliapractice.admin
```

<Callout type="warning" title="`exyliapractice.admin` is all or nothing">
Every admin action — creating arenas, editing kits, rotating seasons, clearing every player's stats,
importing a database dump, changing settings in game — is behind that one node. There is no split
between a builder who sets up arenas and an operator who can wipe the ladder.
</Callout>
