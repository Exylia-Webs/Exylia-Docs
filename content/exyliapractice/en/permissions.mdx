Every node below is declared in `plugin.yml`, so the default shown is what a player holds before a permissions plugin says otherwise. Give nodes with your permissions plugin, for example `/lp group vip permission set exyliapractice.duel.arena true`.

## Staff and perks

Operators only until you grant them.

<Permissions group="admin" />

<Permissions group="lobby" />

<Callout type="warning" title="`exyliapractice.admin` is all or nothing">
Every admin action (creating arenas, editing kits, rotating seasons, clearing stats, importing a database dump, changing settings in game) is behind that one node. There is no split between a builder who sets up arenas and an operator who can wipe the ladder.
</Callout>

## Player features

Every player feature has a node of its own that **everybody holds by default**. To turn one into a rank perk, deny it to the default group and grant it to the rank: for example `exyliapractice.duel.arena` set to `false` on `default` and `true` on `vip`. A player without the node is told they lack permission when they try.

<Permissions group="player" />

<Permissions group="party" />

Getting out is never behind a node: leaving a match, a queue or a party, and declining a duel, keep working whatever the player holds.

## The numbered nodes

None of these needs registering; any whole number works.

<Permissions group="numbered" />

- For the two `max_slots` nodes, giving `max_slots.5` on top of `max_slots.1` is an **upgrade**, not a conflict. A rank ladder can add nodes without removing the ones below.
- For the cooldown, less is the perk: a leader holding `cooldown.30` and `cooldown.10` waits ten seconds between announcements. A node replaces the configured value outright, so one above it makes the wait longer.
- `party.max-size` is 100 by default and `party.default-max-size` is 10.
- A node set to `false` grants nothing, and a node whose tail is not a number is ignored.

<Callout type="note" title="Party size is the leader's permission">
The ceiling is checked against whoever is leader when the size is changed, not against the member joining. Handing leadership to somebody with a lower ceiling does not shrink an already-large party.
</Callout>

## Suggested setup

```yaml
default:
  # every player feature is already granted; set one to false here to make it a perk
  # exyliapractice.duel.arena: false

vip:
  - exyliapractice.duel.arena
  - exyliapractice.lobby.vip
  - exyliapractice.kits.max_slots.3
  - exyliapractice.party.max_slots.15
  - exyliapractice.party.announce.cooldown.30

premium:
  - exyliapractice.lobby.fly
  - exyliapractice.kits.max_slots.10
  - exyliapractice.party.max_slots.30
  - exyliapractice.party.announce.cooldown.10

staff:
  - exyliapractice.lobby.bypass
  - exyliapractice.bypass.command-whitelist

admin:
  - exyliapractice.admin
```
