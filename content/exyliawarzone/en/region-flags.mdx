Stop players from building, dropping items or taking fall damage inside a [regen zone](/docs/exyliawarzone/regen-zones) or a [duel room](/docs/exyliawarzone/duel-rooms), or let them keep their inventory when they die there. Each area carries **flags**, rules that hold for the players inside it. ExyliaWarzone applies them itself through ExyliaLib's region module, so no WorldGuard region is needed.

## Before you start

- A regen zone or duel room with its region already selected: the flags apply to that area. See [Regen zones](/docs/exyliawarzone/regen-zones) and [Duel rooms](/docs/exyliawarzone/duel-rooms).
- Your permission for that module's admin command.
- Nothing else: no WorldGuard region is needed.

## Steps

<Steps>
  <Step title="Open the flag editor">
    In the zone's or room's screen, click **Region flags** (zones) or **Room flags** (rooms).
  </Step>
  <Step title="Set the flags">
    Click a flag to cycle **Default**, **Allow**, **Deny**. Right-click returns it to **Default**.
  </Step>
  <Step title="Save">
    Nothing is written until you save. Closing, cancelling or leaving discards the changes.
  </Step>
</Steps>

## Check that it works

Stand in the area in survival with a non-op account and try what you denied, such as placing a block under `BUILD`. It is refused. Creative players are never held by these flags, so test in survival.

## Going further

### What the editor shows

Each flag is a card named **Flag**, then the flag in words (for example **Flag ▸ Player blocks only**), with its state in brackets: **DEFAULT**, **ALLOW** or **DENY**. The top card counts the flags set here.

- **A flag**: click cycles **Default**, **Allow**, **Deny**; right-click goes back to **Default**.
- **BLOCK LIST**: click opens a list of materials; right-click goes back to **Default**.
- **Block lifetime**: click asks for a whole number of seconds; right-click goes back to **Default**.

**Default** means the area says nothing about that flag, so the flag's own default applies (the Default column below). Only the flags you set to Allow or Deny are stored. Names read as plain words: `PLAYER_BUILD_ONLY` is **Player blocks only**, `EXPLOSION_PLAYER_BLOCKS_ONLY` is **Explosion-proof map**, `RE_GIVE_BLOCKS` is **Return blocks**, `ALLOWED_BLOCKS_ONLY` is **Allowed blocks only**, `BREAKABLE_BLOCKS_ONLY` is **Breakable blocks only**; the others are their name with spaces (**Item drop**, **Fall damage**). `KEEP_INVENTORY` is **KEEP INVENTORY**.

<Details title="All flags and their defaults">

| Flag | Default | When set to Deny, inside the area |
|---|---|---|
| `PVP` | Allow | Players cannot hurt players, directly or through arrows, TNT, crystals, harmful potions or tamed pets. |
| `BUILD` | Allow | Blocks cannot be placed (both halves of a door or bed) and buckets cannot be emptied. |
| `BREAK` | Allow | Blocks cannot be broken and buckets cannot be filled from them. |
| `INTERACT` | Allow | Clicked blocks cannot be used, pressure plates and farmland do nothing, and entities other than players (armour stands, frames, villagers, mounts) cannot be right-clicked. The item in hand still works, so eating, pearls and bows go through. |
| `ITEM_DROP` | Allow | Items cannot be dropped. |
| `ITEM_PICKUP` | Allow | Items cannot be picked up. |
| `FALL_DAMAGE` | Allow | Nobody takes fall damage. |

These flags do something when set to **Allow**:

| Flag | Default | When set to Allow, inside the area |
|---|---|---|
| `PLAYER_BUILD_ONLY` | Deny | Only blocks a player placed can be broken; the map itself stays. |
| `ALLOWED_BLOCKS_ONLY` | Deny | Only the materials on the block list can be placed. A bucket counts as its item, such as `WATER_BUCKET`. |
| `BREAKABLE_BLOCKS_ONLY` | Deny | Only the materials on the block list can be broken, even where `BREAK` is denied. |
| `EXPLOSION_PLAYER_BLOCKS_ONLY` | Deny | Explosions only break blocks a player placed; the map itself survives them. The explosion still happens: players and entities still take its damage and knockback. |
| `TEMPORARY_BLOCKS` | Deny | Every block a player places disappears again after the temporary block time. |
| `RE_GIVE_BLOCKS` | Deny | A temporary block goes back to the player's inventory when it disappears. |
| `KEEP_INVENTORY` | Deny | A player who dies inside keeps their items and levels: nothing drops and no experience is left behind. |

</Details>

<Callout type="note" title="One block list for both">
`ALLOWED_BLOCKS_ONLY` and `BREAKABLE_BLOCKS_ONLY` share the same block list. With both on, players can place and
break exactly the listed materials, which is what a bridging or building area needs.
</Callout>

#### Temporary blocks

With `TEMPORARY_BLOCKS` allowed, each block a player places is removed after **30 seconds** unless you set another
number on the **Block lifetime** row. Add `RE_GIVE_BLOCKS` to hand each block back as it goes, so players
never run out while they build.

Saving the flags, or selecting the area again, registers the area anew, and the record of which blocks players have
placed so far starts over: from then on `PLAYER_BUILD_ONLY` treats the earlier ones as part of the map.

#### Keep inventory

`KEEP_INVENTORY` is the plugin's own flag. It acts when a player dies inside the area and another plugin has not
already kept the inventory. It runs early, so a plugin that decides a death's drops later, such as a combat or
graves plugin, still has the last word.

### Who the rules hold

- **Everybody in survival or adventure.** Players in **creative mode** are never held by these flags, so staff can
  build and fix an area without changing anything.
- **Only Warzone's own areas.** The flags of a zone or a room decide only inside it. A WorldGuard region, a claim or
  another Exylia plugin's area at the same place keeps its own rules: the action is refused when any of them refuses
  it.
- **Explosions are covered by one flag only.** The flags judge what a player does; creepers and TNT going off on their
  own are not stopped by them, except that `EXPLOSION_PLAYER_BLOCKS_ONLY` keeps the map from being blown away.

Older rows may still name `ENTRY`, `EXIT` or `REGION_MEMBERS_ONLY`. Nothing applies
those three, so the editor does not show them and they are dropped the next time the area is saved.

<Details title="Technical details">

Flags are stored per area as explicit Allow or Deny rows (`temporary_blocks_seconds` defaults to 30 and is stored only when you change it); only those are saved, and the rest follow the flag's default. They are enforced by ExyliaLib's region module, not by WorldGuard, and `KEEP_INVENTORY` by the plugin's own listener. See [Selecting regions](/docs/exylialib/regions) for how areas are registered.

</Details>
