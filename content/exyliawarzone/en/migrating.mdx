Keep your supply drop tiers, power-up zones, loot chests, regen zones, duel rooms and banned items when you move from ExyliaSurvivalCore to ExyliaWarzone. They used to be modules of ExyliaSurvivalCore, which no longer ships them; nothing has to be rebuilt.

## Before you start

- Stop the server and back up `plugins/ExyliaSurvivalCore/` and its database.
- ExyliaLib and ExyliaWarzone installed, with the modules you want switched on.
- Know which database ExyliaSurvivalCore used: the old rows are found only there.

## Steps

<Steps>
  <Step title="Point at the same database">
    MySQL, MariaDB, PostgreSQL or MongoDB: copy the connection block of `plugins/ExyliaSurvivalCore/database.yml` into `plugins/ExyliaWarzone/database.yml`, so both read the same database.
  </Step>
  <Step title="Or copy the H2 file">
    With the default H2 file, stop the server and, before ExyliaWarzone's first start, copy `plugins/ExyliaSurvivalCore/database/h2.mv.db` to `plugins/ExyliaWarzone/database/h2.mv.db`. ExyliaWarzone reads its own tables from the copy and leaves the rest alone.
  </Step>
  <Step title="Start the server">
    Schematics are copied and banned items are imported on this start. The console names each file it copies and says how many banned-item rules it imported.
  </Step>
</Steps>

## Check that it works

Open `/warzoneadmin`: your supply drop tiers, power-up zones, loot chests, regen zones and duel rooms are listed. Banned items appear in `/banneditemsadmin`. Once the schematics are copied, the old files can be deleted.

## Going further

### What carries over

ExyliaWarzone reads the tables ExyliaSurvivalCore wrote, under the same names.

<Details title="Tables read">

| Module | Tables |
|---|---|
| Supply drops | `sc_supply_drop_tiers`, `sc_envoys`, `sc_supply_drop_crates` |
| Power-ups | `sc_powerup_zones` |
| Loot chests | `sc_loot_chests`, `sc_loot_chest_templates` |
| Regen zones | `sc_regen_zones` |
| Duel rooms | `sc_duel_rooms`, `sc_duel_room_borders` |

</Details>

Rows written by the older region format are read as they are and rewritten in the new one the first time you save
that zone or room, so nothing has to be converted first.

### Schematics

On every start, each regen zone and duel room whose schematic is missing from `plugins/ExyliaWarzone/schematics/` is given a copy of the one in `plugins/ExyliaSurvivalCore/schematics/` (or its `regions/` subfolder) when it exists there.

### What starts again

| | |
|---|---|
| Settings and messages | Not imported. Every module starts from its defaults in `plugins/ExyliaWarzone/modules/` and `lang/`. |
| Permissions | Renamed to `exyliawarzone.*`; see the table below. Grant the new nodes before players need them. |
| Muted announcements | Players who had muted supply drop or duel announcements in `/settings` hear them again until they mute them once more. |

| ExyliaSurvivalCore | ExyliaWarzone |
|---|---|
| `exyliasurvivalcore.supplydrops` | `exyliawarzone.supplydrops.use` |
| `exyliasurvivalcore.supplydrops.admin` | `exyliawarzone.supplydrops.admin` |
| `exyliasurvivalcore.powerups.admin` | `exyliawarzone.powerups.admin` |
| `exyliasurvivalcore.lootchests.admin` | `exyliawarzone.lootchests.admin` |
| `exyliasurvivalcore.lootchests.bypass` | `exyliawarzone.lootchests.bypass` (now: opening a chest that is still refilling) |
| `exyliasurvivalcore.regenzones.admin` | `exyliawarzone.regenzones.admin` |
| `exyliasurvivalcore.duelrooms.admin` | `exyliawarzone.duelrooms.admin` |
| `exyliasurvivalcore.duelrooms.bypass` | `exyliawarzone.duelrooms.bypass` |
| `exyliasurvivalcore.blockeditems.bypass` | `exyliawarzone.banneditems.bypass` |

`exyliawarzone.admin` holds every module's admin node, so one grant covers the whole plugin. See
[Permissions](/docs/exyliawarzone/permissions).

<Callout type="note" title="Statistics keep counting">
With ExyliaSurvivalCore still installed, ExyliaWarzone reports picked power-ups, opened loot chests, reached supply
drops and duel wins to it, so missions, leaderboards and seasons built on those statistics keep working. See
[Integrations](/docs/exyliawarzone/integrations#exyliasurvivalcore-statistics).
</Callout>

<Details title="Technical details">

Banned items (SurvivalCore's `blocked-items`, file `plugins/ExyliaSurvivalCore/modules/blocked-items/rules.yml`) are imported from that file, not from the database, and the file is renamed `rules.yml.imported` afterwards. See [Banned items](/docs/exyliawarzone/banned-items#coming-from-exyliasurvivalcore).

</Details>
