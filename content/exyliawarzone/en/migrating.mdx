---
title: "Moving from ExyliaSurvivalCore"
description: "What carries over from ExyliaSurvivalCore's supply drops, power-ups, loot chests, regen zones and duel rooms, and what starts again."
---

Supply drops, power-ups, loot chests, regen zones, duel rooms and banned items used to be modules of ExyliaSurvivalCore. They now
live in ExyliaWarzone, and ExyliaSurvivalCore no longer ships them. Everything you built with them can come along.

Banned items (SurvivalCore's `blocked-items`) are imported from its file, not from the database: see
[Banned items](/docs/exyliawarzone/banned-items#coming-from-exyliasurvivalcore).

## What carries over

ExyliaWarzone reads the tables ExyliaSurvivalCore wrote, under the same names:

| Module | Tables |
|---|---|
| Supply drops | `sc_supply_drop_tiers`, `sc_envoys`, `sc_supply_drop_crates` |
| Power-ups | `sc_powerup_zones` |
| Loot chests | `sc_loot_chests`, `sc_loot_chest_templates` |
| Regen zones | `sc_regen_zones` |
| Duel rooms | `sc_duel_rooms`, `sc_duel_room_borders` |

Rows written by the older region format are read as they are and rewritten in the new one the first time you save
that zone or room, so nothing has to be converted first.

### Pointing at the same database

Each plugin reads its own `database.yml`, so ExyliaWarzone finds the old rows only when it uses the database
ExyliaSurvivalCore used.

<Steps>
  <Step title="MySQL, MariaDB, PostgreSQL or MongoDB">
    Copy the connection block of `plugins/ExyliaSurvivalCore/database.yml` into `plugins/ExyliaWarzone/database.yml`
    and restart. Both plugins then share one connection pool.
  </Step>
  <Step title="The default H2 file">
    Each plugin has its own file (`plugins/<Plugin>/database/h2.mv.db`). With the server stopped and before
    ExyliaWarzone's first start, copy `plugins/ExyliaSurvivalCore/database/h2.mv.db` to
    `plugins/ExyliaWarzone/database/h2.mv.db`. ExyliaWarzone reads its own tables from the copy and leaves the rest
    alone.
  </Step>
</Steps>

### Schematics

Schematics are kept per plugin. On every start, each regen zone and duel room whose schematic is missing from
`plugins/ExyliaWarzone/schematics/` is given a copy of the one in `plugins/ExyliaSurvivalCore/schematics/` (or its
`regions/` subfolder) when it exists there. The console names each file it copies. Once they are copied, the old files
can be deleted.

## What starts again

| | |
|---|---|
| Settings and messages | Not imported. Every module starts from its defaults in `plugins/ExyliaWarzone/modules/` and `lang/`. |
| Permissions | Renamed to `exyliawarzone.*`; see the table below. |
| Muted announcements | Players who had muted supply drop or duel announcements in `/settings` hear them again until they mute them once more. |

| ExyliaSurvivalCore | ExyliaWarzone |
|---|---|
| `exyliasurvivalcore.supplydrops` | `exyliawarzone.supplydrops.use` |
| `exyliasurvivalcore.supplydrops.admin` | `exyliawarzone.supplydrops.admin` |
| `exyliasurvivalcore.powerups.admin` | `exyliawarzone.powerups.admin` |
| `exyliasurvivalcore.lootchests.admin` | `exyliawarzone.lootchests.admin` |
| `exyliasurvivalcore.lootchests.bypass` | `exyliawarzone.lootchests.bypass` (now: opening a chest that is still refilling) |
| `exyliasurvivalcore.regenzones.admin` | `exyliawarzone.regenzones.admin` |
| `exyliasurvivalcore.duelrooms.admin` | `exyliawarzone.duelrooms.admin` |
| `exyliasurvivalcore.duelrooms.bypass` | `exyliawarzone.duelrooms.bypass` |

`exyliawarzone.admin` holds every module's admin node, so one grant covers the whole plugin. See
[Permissions](/docs/exyliawarzone/permissions).

<Callout type="note" title="Statistics keep counting">
With ExyliaSurvivalCore still installed, ExyliaWarzone reports picked power-ups, opened loot chests, reached supply
drops and duel wins to it, so missions, leaderboards and seasons built on those statistics keep working. See
[Integrations](/docs/exyliawarzone/integrations#exyliasurvivalcore-statistics).
</Callout>
