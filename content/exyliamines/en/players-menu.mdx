Players reach the mines through two commands, both granted to everybody by default.

| Command | Permission | What it does |
|---|---|---|
| `/mines` | `exyliamines.menu` | Opens the list of mines. |
| `/mine <id>` | `exyliamines.teleport` | Sends the player to that mine's entry point. Tab completion offers every enabled mine. |

## The list

`/mines` shows every **enabled** mine of the server, sorted by id, each with its icon and name and:

| Line | What it says |
|---|---|
| Type | Classic or Realistic. |
| Access | Open, or Locked for a mine whose permission the player lacks. |
| Remaining | The share still standing. |
| Next reset | Time until the next refill; "Per block" for a realistic mine. |
| Boost | The drop multiplier and time left of a running boost, or None. |
| Mined by you | How many blocks this player has mined there. |

A pickaxe at the bottom adds up the player's blocks across every mine. Clicking a mine sends them there.

Locked mines are listed too, so players see what they can work towards; clicking one says they have no
access.

## Going to a mine

`/mine <id>` and a click in the menu run the same checks, in this order:

1. The mine exists and is enabled — otherwise "Mine not found."
2. The player has `exyliamines.teleport` and the mine's own permission, if it has one — otherwise
   "You don't have access to this mine."
3. The mine has an entry point — otherwise "This mine has no entry point."
4. The player is not in combat — otherwise they are told how long is left. A mine is not a way out of a
   fight. Combat is read from ExyliaLib's combat module, which follows DeluxeCombat or PvPManager when one
   is installed.

The teleport itself goes through ExyliaLib's teleports, and the `teleported` line confirms it.

<Callout type="note" title="Realistic mines and the entry point">
Only classic mines have a **Teleports** section, so a realistic mine built in the editor has no entry
point and answers "This mine has no entry point." See [Realistic mines](/docs/exyliamines/realistic-mines).
</Callout>

## Restyling it

The menu is `lang/<language>/menus/user/mines.yml`, and it is yours: a release only adds what is missing
from it and never overwrites your edits. It is an ExyliaLib pagination menu — see the
[library's menus page](/docs/exylialib/menus) for every key.

Each mine's entry is the `item_template`, and can use:

| Value | What it is |
|---|---|
| `%mine_id%`, `%mine_name%`, `%mine_icon%` | Id, display name, icon material. |
| `%mine_type%`, `%remaining%`, `%next_reset%`, `%total_blocks%`, `%boost%` | As on the [hologram](/docs/exyliamines/holograms#its-lines). |
| `%access%` | `access-open` or `access-locked` from `messages.yml`. |
| `%player_blocks%` | Blocks the viewer mined in this mine. |

`%player_blocks_total%` is available to every other item of the menu. The button action that sends a
player to a mine is `exyliamines:teleport <id>`. It is the one action of the plugin that does not need
`exyliamines.admin`, so it can go on any item of this menu — a featured mine, say — and it still runs every
check above.
