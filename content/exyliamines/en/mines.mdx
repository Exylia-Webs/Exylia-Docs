Every mine is created and edited from `/minesadmin`. A change is saved the moment you make it — there is
no save button — and applies at once to the running mine.

## The list

`/minesadmin` opens every mine of this server, sorted by id. Each one shows its id, its type, whether its
region is set, whether it is enabled and when it resets next (`Per block` for a realistic mine).

| Click | What it does |
|---|---|
| Left-click a mine | Opens its setup screen. |
| Right-click a mine | Deletes it, after a confirmation. |
| **Create classic mine** | Asks for an id and creates an empty classic mine. |
| **Create realistic mine** | The same, for a realistic mine. |
| **Create from template** | Opens the templates of `templates.yml`. |

An id is lowercase letters, digits, `_` and `-`, up to 64 characters. It is checked against the whole
database, not only this server's mines: on a network sharing one database, an id another server already
uses is refused with "A mine with ID … already exists", because creating it here would overwrite that
server's mine.

A new mine starts **enabled**, with its id as its name, auto-pickup on, restrict-breaking off, lifting of
buried players on, and the reset interval and warning from `config.yml` (5 minutes and 10 seconds by
default).

## The setup screen

Opening a mine shows an overview: one button per section, each with the state of what it holds, so a
glance says what is still missing. A section is a sub-menu; its **Back** button returns to the overview,
and every editor opened from a section returns to that section.

| Section | Classic | Realistic | What is in it |
|---|---|---|---|
| **Status** | ✓ | ✓ | Enables or disables the mine. A click toggles it. |
| **General** | ✓ | ✓ | Display name, icon, access permission. |
| **Area** | ✓ | ✓ | Region, shape, hologram. See [Area and shapes](/docs/exyliamines/area) and [Holograms](/docs/exyliamines/holograms). |
| **Block composition** | ✓ | | What the mine is refilled from. See [Classic mines](/docs/exyliamines/classic-mines). |
| **Resets** | ✓ | | Interval, warning, threshold, force reset. |
| **Teleports** | ✓ | | Entry teleport, safe teleport, lifting buried players. |
| **Regen levels** | | ✓ | The blocks that grow back. See [Realistic mines](/docs/exyliamines/realistic-mines). |
| **Rewards** | ✓ | ✓ | Lucky rewards, Fortune, and the boost running on it. |
| **Mining** | ✓ | ✓ | Auto-pickup, restrict breaking, break effects, potion effects. |
| **Clone mine** | ✓ | ✓ | Copies it under a new id. |
| **Delete mine** | ✓ | ✓ | Deletes it, after a confirmation. |

## General

| Button | Click | What it does |
|---|---|---|
| **Display name** | click | Asks for the name players read in titles, menus, holograms and announcements. Colours are allowed. |
| **Icon** | left / shift-left | Picks the item the mine shows in the menus, or clears it. Without one, a classic mine shows a beacon and a realistic one a diamond ore. |
| **Access permission** | left / shift-left | Asks for a permission node, or clears it. |

### The access permission

A mine with no permission is open to everyone. With one, a player who lacks it:

- is told "You don't have access to this mine." when they walk in, and gets nothing of the mine — no
  title, no boss bars, no potion effects. The area itself is not a wall.
- **cannot break anything inside the area**, whether it is one of the mine's blocks or not;
- cannot be sent there with `/mine <id>` or from the `/mines` menu, which shows the mine as locked.

`exyliamines.admin` passes all three. The node can be anything you like: `mines.vip`, `rank.miner`.

## Status

A disabled mine is not a mine as far as players are concerned. It leaves the `/mines` menu and
`/mine` answers "Mine not found"; its hologram is taken down; anybody inside has their session closed;
it stops resetting. Its area is plain ground again, so breaking there is up to the server and your
protection plugins, as anywhere else. Its settings are all kept, and enabling it again takes up from
there.

## Mining

| Button | Default | What it does |
|---|---|---|
| **Auto-pickup** | on | Drops and item loot go straight into the miner's inventory; what does not fit falls on the ground. |
| **Restrict breaking** | off | Whether blocks that are not the mine's may be broken inside its area. |
| **Break effects** | none | Sounds, particles and titles played on every block broken here. See [Loot and effects](/docs/exyliamines/loot-and-effects#break-effects). |
| **Mine effects** | none | Potion effects kept on players while they are inside. See [Loot and effects](/docs/exyliamines/loot-and-effects#potion-effects). |

A mine owns the blocks it is made of — its composition, or its levels and their degrade stages — and
nothing else. With **restrict breaking** off, a lamp, a sign or a chest inside the area is left to the
server and your other plugins, exactly as if the mine were not there. With it on, breaking any other
block inside the area is refused with "This block can't be mined here.", except for admins.

## Rewards

| Button | Click | What it does |
|---|---|---|
| **Lucky rewards** | click | Opens the editor of rare prizes any block may give. See [Lucky rewards](/docs/exyliamines/lucky-rewards). |
| **Fortune** | left / right / shift-left | Steps through the mine's Fortune mode, highest level and Silk Touch. See [Fortune](/docs/exyliamines/fortune). |
| **Boost** | — | Shows the boost running on this mine. Boosts are started by command or by schedule; see [Boosts](/docs/exyliamines/boosts). |

## Templates

**Create from template** lists the templates of `templates.yml` in the order the file writes them.
Clicking one asks for an id and creates a mine of that template's type, already carrying its name, its
icon and its blocks:

- a **classic** template becomes a composition, each block with its weight;
- a **realistic** template becomes one level per block, each with the template's `regen` time. Weights
  are ignored.

The area, teleports and everything else are set afterwards, as for any mine.

```yaml title="plugins/ExyliaMines/templates.yml"
templates:
  coal:
    name: Coal
    icon: COAL_ORE
    type: CLASSIC
    blocks:
      STONE: 70.0
      COAL_ORE: 25.0
      IRON_ORE: 5.0
    regen: 60
  ores:
    name: Natural ores
    icon: DIAMOND_ORE
    type: REALISTIC
    blocks:
      COAL_ORE: 1.0
      IRON_ORE: 1.0
      GOLD_ORE: 1.0
      DIAMOND_ORE: 1.0
    regen: 120
```

Six ship by default: `coal`, `iron`, `gold`, `diamond`, `nether` and `ores`. Add your own the same way and
run `/minesadmin reload`. A block name that is not a block, or a weight of zero or less, is skipped.

## Cloning

**Clone mine** asks for a new id and creates a copy on this server with everything the mine is made of
and how it behaves: type, name, icon, permission, every switch, the composition or levels with their loot
and effects, lucky rewards, potion effects, Fortune settings and reset times.

What belongs to the place the original stands is **not** copied: the area, the entry and safe teleports
and the hologram. The copy's setup screen opens straight away so you can select its region.

## Deleting

**Delete mine**, or right-clicking it on the list, asks for a confirmation first. Confirmed, it removes
the mine and everything kept about it: its cycle, the blocks it was regrowing, its hologram, and **every
player's count of blocks mined there**. Players standing inside lose their session and its potion
effects. There is no undo.

<Callout type="note" title="Two admins on the same mine">
Every edit made after a prompt or an editor reads the mine as it is saved at that moment, so one admin's
edit never silently undoes another's made in the meantime.
</Callout>
