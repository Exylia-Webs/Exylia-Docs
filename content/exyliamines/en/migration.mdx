## From ExyliaSurvivalCore

Mines used to be a module of ExyliaSurvivalCore. They are now this plugin, and since **1.6.0** ExyliaMines
no longer imports anything from there: the mines, the blocks they were regrowing, the settings, the
messages and the mining history are only brought over by an earlier release.

<Steps>
  <Step title="Import with a 1.5 release">
    A server still running the survival core's mines installs an ExyliaMines release before 1.6.0 next to
    it, with the survival core's `mines` module off, and starts once. That release reads the mines from the
    survival core's database and writes `plugins/ExyliaMines/.imported-survivalcore` when they are in.
  </Step>
  <Step title="Update to the current release">
    With the mines in ExyliaMines' own tables, replace the jar with the current one. Nothing is read from
    the survival core again.
  </Step>
</Steps>

### What else changes

- **Permissions.** `exyliasurvivalcore.mines.admin` is no longer declared. Staff who had it need
  `exyliamines.admin`. Mine permissions are stored on each mine and came over with it.
- **Commands.** `/minesadmin` keeps its name.
- **Placeholders.** Inside Exylia plugins' own files the names are the same, `%mine_reset_<id>%`. Through
  PlaceholderAPI the plugin in front changes: `%exyliasurvivalcore_mine_reset_<id>%` becomes
  `%exyliamines_mine_reset_<id>%`. See [Placeholders](/docs/exyliamines/placeholders).
- **The API.** Plugins that broke mine blocks through ExyliaSurvivalCore move to `MinesService`. See
  [API](/docs/exyliamines/api).

## From CataMines or RealMines

```text
/minesadmin import catamines
/minesadmin import realmines
```

The mines are read straight from the other plugin's folder, `plugins/CataMines/mines/` or
`plugins/RealMines/mines/`, one `.yml` file per mine. That plugin does **not** have to be installed, and
nothing in its files is changed.

Every mine comes over as a **classic** mine of this server, enabled. Its id is its name in lower case, with
anything other than letters, digits, `_` and `-` turned into `_`. A mine whose id is already taken — on any
server of the database — is skipped, so running an import again only adds what is new. The answer says how
many were imported and how many skipped; a file that could not be read is named in the console.

Imported mines are set up at once and refill on their first interval. Their holograms, loot tables and
everything else this plugin adds are set afterwards from `/minesadmin`.

### CataMines 2.x

| CataMines | ExyliaMines |
|---|---|
| `name` | Id and display name |
| `region` (world, `p1`, `p2`) | The area. Only cuboid regions; any other region type is skipped. |
| `composition` (`block`, `chance`) | The composition, each chance as a weight |
| `resetDelay` | Reset interval; the default from `config.yml` when it is not set |
| `resetMode` with `PERCENTAGE`, and `resetPercentage` | Threshold: CataMines resets when the share **left** falls to its value, ExyliaMines when the share **mined** reaches it, so `100 − resetPercentage` |
| `warn.enableWarn`, `warn.warnSeconds` | Reset warning: the longest of the warning seconds |
| `teleportLocation` | Entry teleport |
| `teleportResetLocation`, with `teleportPlayersToResetLocation` | Safe teleport |

CataMines loot tables are not imported.

### RealMines 1.x

| RealMines | ExyliaMines |
|---|---|
| `type` | Only `BLOCKS` mines. Schematic and farm mines have no counterpart and are skipped. |
| `name`, `displayName` | Id, and display name with its `&` colour codes removed |
| `world`, `pos1`, `pos2` | The area |
| `block-sets` (`default`, or the first set), or `blocks` | The composition, each `percentage` as a weight |
| `reset.time.active`, `reset.time.value` | Reset interval, at least 5 seconds; the default from `config.yml` when time resets are off |
| `reset.percentage.active`, `reset.percentage.value` | Threshold, as `100 − value` |
| `settings.send-mined-items-to-inventory` | Auto-pickup |
| `settings.break-permission` | Mine permission `realmines.<name>.break` |
| `icon` | Icon, when it names a material |
| `teleport` | Entry teleport, centred on the block |

Locations are only imported in worlds that are loaded when the import runs; load the worlds first.
