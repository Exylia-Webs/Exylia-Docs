## Desde ExyliaSurvivalCore

Las minas eran antes un módulo de ExyliaSurvivalCore. Ahora son este plugin, y un servidor que las tenía
allí se lo trae todo por sí solo: las minas, los bloques que estaban regenerando, los ajustes, los mensajes
y el historial de minado.

<Steps>
  <Step title="Actualiza ExyliaSurvivalCore">
    Usa una versión sin el módulo de minas, o apaga su módulo `mines`. Mientras el survival core siga
    llevando sus propias minas no se importa nada, y la consola lo avisa.
  </Step>
  <Step title="Instala ExyliaMines a su lado">
    Coloca `ExyliaMines.jar` en `plugins/` y deja ExyliaSurvivalCore instalado: las minas se leen de la
    base de datos del propio survival core, use el motor que use, así que tiene que estar en marcha.
  </Step>
  <Step title="Arranca el servidor una vez">
    La consola lista lo que se ha importado. A partir de ahí ExyliaMines lleva las minas, y `/minesadmin`
    las abre.
  </Step>
</Steps>

### Qué se trae

| Qué | Desde | Hacia |
|---|---|---|
| Ajustes | Las secciones `settings` y `sounds` de `plugins/ExyliaSurvivalCore/modules/mines/config.yml` | `config.yml`, escrito con ellas — solo cuando ExyliaMines aún no tiene `config.yml`. Las claves son las mismas. |
| Mensajes | `plugins/ExyliaSurvivalCore/lang/<idioma>/modules/mines/messages.yml`, de cada idioma | `lang/<idioma>/messages.yml`, donde todavía no existe. Las claves son las mismas. |
| Minas | La tabla `sc_mines` | `mines`. Área, tipo, composición, niveles, botín, efectos, permiso, interruptores, tiempos de reinicio y teletransportes. |
| Bloques rotos | La tabla `sc_mine_broken_blocks` | `mines_broken_blocks`, para que un hueco anterior al cambio siga regenerándose. |
| Historial de minado | Las filas `mines.<id>.blocks` de `sc_stat_counters`, por jugador | `mines_stats`. Ver más abajo. |

Una mina cuyo id ya tiene ExyliaMines se deja tal cual. En una red que comparte una base de datos, eso es lo
que hace que cada fila llegue una sola vez, arranque primero el servidor que arranque.

Lo que no existía en el survival core — el holograma, los premios de suerte, los efectos de poción, los
ajustes de Fortune — empieza vacío en una mina importada.

### Historial de minado

Cuántos bloques minó cada jugador en cada mina, tal como lo contaba el módulo de estadísticas del survival
core, se importa una vez que las minas están dentro, para las minas que tiene este servidor. El contador de
cada jugador se **sube** hasta el número del survival core, nunca se baja, así que una tabla de
clasificación arranca desde el historial y no desde cero, y ejecutar la importación dos veces no cambia nada.

### Ocurre una sola vez

Cuando las minas están dentro se escribe el archivo `plugins/ExyliaMines/.imported-survivalcore`; el
historial escribe `.imported-survivalcore-stats`. Desde entonces no se vuelve a leer nada del survival
core, así que una mina que borres aquí no vuelve nunca. Borrar un archivo marcador repite esa parte en el
siguiente arranque.

La importación **espera**, sin escribir su marcador, mientras:

- la carpeta del survival core está pero el plugin no está en marcha — "ExyliaSurvivalCore left mines
  behind but is not running";
- el survival core sigue llevando su propio módulo de minas.

Un servidor que nunca tuvo el survival core — sin carpeta `plugins/ExyliaSurvivalCore/` — no tiene nada que
esperar, y los marcadores se escriben en el primer arranque.

### Qué más se conserva

- **Permisos.** `exyliasurvivalcore.mines.admin` sigue funcionando: ExyliaMines lo declara y concede
  `exyliamines.admin`. Los permisos de cada mina se guardan en la propia mina y viajan con ella.
- **Comandos.** `/minesadmin` mantiene su nombre.
- **Placeholders.** Dentro de los archivos de los plugins de Exylia los nombres son los mismos,
  `%mine_reset_<id>%`. A través de PlaceholderAPI cambia el plugin que va delante:
  `%exyliasurvivalcore_mine_reset_<id>%` pasa a ser `%exyliamines_mine_reset_<id>%`. Ver
  [Placeholders](/docs/exyliamines/placeholders).
- **La API.** Los plugins que rompían bloques de mina a través de ExyliaSurvivalCore pasan a `MinesService`.
  Ver [API](/docs/exyliamines/api).

## Desde CataMines o RealMines

```text
/minesadmin import catamines
/minesadmin import realmines
```

Las minas se leen directamente de la carpeta del otro plugin, `plugins/CataMines/mines/` o
`plugins/RealMines/mines/`, un archivo `.yml` por mina. Ese plugin **no** tiene que estar instalado, y no se
modifica nada en sus archivos.

Cada mina llega como mina **clásica** de este servidor, activada. Su id es su nombre en minúsculas, con todo
lo que no sean letras, dígitos, `_` y `-` convertido en `_`. Una mina cuyo id ya está ocupado — en cualquier
servidor de la base de datos — se omite, así que repetir una importación solo añade lo nuevo. La respuesta
dice cuántas se importaron y cuántas se omitieron; un archivo que no se pudo leer se nombra en consola.

Las minas importadas se ponen en marcha al momento y se rellenan en su primer intervalo. Sus hologramas,
tablas de botín y todo lo demás que añade este plugin se configuran después desde `/minesadmin`.

### CataMines 2.x

| CataMines | ExyliaMines |
|---|---|
| `name` | Id y nombre visible |
| `region` (mundo, `p1`, `p2`) | El área. Solo regiones cúbicas; cualquier otro tipo de región se omite. |
| `composition` (`block`, `chance`) | La composición, cada probabilidad como peso |
| `resetDelay` | Intervalo de reinicio; el de `config.yml` cuando no está puesto |
| `resetMode` con `PERCENTAGE`, y `resetPercentage` | Umbral: CataMines reinicia cuando la parte que **queda** baja hasta su valor, ExyliaMines cuando la parte **minada** lo alcanza, así que `100 − resetPercentage` |
| `warn.enableWarn`, `warn.warnSeconds` | Aviso de reinicio: el mayor de los segundos de aviso |
| `teleportLocation` | Teletransporte de entrada |
| `teleportResetLocation`, con `teleportPlayersToResetLocation` | Teletransporte seguro |

Las tablas de botín de CataMines no se importan.

### RealMines 1.x

| RealMines | ExyliaMines |
|---|---|
| `type` | Solo minas `BLOCKS`. Las minas de schematic y de granja no tienen equivalente y se omiten. |
| `name`, `displayName` | Id, y nombre visible sin sus códigos de color `&` |
| `world`, `pos1`, `pos2` | El área |
| `block-sets` (`default`, o el primer conjunto), o `blocks` | La composición, cada `percentage` como peso |
| `reset.time.active`, `reset.time.value` | Intervalo de reinicio, mínimo 5 segundos; el de `config.yml` cuando los reinicios por tiempo están apagados |
| `reset.percentage.active`, `reset.percentage.value` | Umbral, como `100 − value` |
| `settings.send-mined-items-to-inventory` | Autorrecoger |
| `settings.break-permission` | Permiso de mina `realmines.<name>.break` |
| `icon` | Icono, cuando nombra un material |
| `teleport` | Teletransporte de entrada, centrado en el bloque |

Las ubicaciones solo se importan en mundos que estén cargados cuando se ejecuta la importación; carga los
mundos antes.
