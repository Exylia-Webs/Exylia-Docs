---
title: "Permissions"
description: "The nine nodes the plugin declares, what each one gates in commands and menus, and their defaults."
---

Nine nodes, all declared in the plugin. Eight are granted to everyone by default; the admin node is for
operators.

## Plugin nodes

| Permission | Default | What it gates |
|---|---|---|
| `exyliaaimtrainer.use` | everyone | `/aim`, the main menu. |
| `exyliaaimtrainer.train` | everyone | `/aim train` and `/aim drills`. |
| `exyliaaimtrainer.settings` | everyone | `/aim settings`. |
| `exyliaaimtrainer.duel` | everyone | `/aim duel`, `/aim accept` and `/aim deny`: sending, accepting and declining requests. |
| `exyliaaimtrainer.leave` | everyone | `/aim leave` and `/aim stop`. |
| `exyliaaimtrainer.profile` | everyone | `/aim profile` and `/aim stats`, own and others'. |
| `exyliaaimtrainer.leaderboard` | everyone | `/aim leaderboard` and `/aim top`. |
| `exyliaaimtrainer.history` | everyone | `/aim history` and `/aim sessions`. |
| `exyliaaimtrainer.admin` | operators | `/aimtraineradmin`, `/aimadmin` and `reload`. |

## Menus check the same nodes

A menu file can be edited to show any button to anybody, so the check lives behind the click, not in the
file. Every `aimtrainer:` action carries the node of the command it stands for, in the menus and on the
in-drill hotbar alike. A click without the node does nothing.

| Node | Actions |
|---|---|
| `exyliaaimtrainer.train` | `train`, `replay`, and opening the drill list |
| `exyliaaimtrainer.settings` | `setting`, `setting_input`, `toggle`, and opening the settings screen |
| `exyliaaimtrainer.duel` | `duel_open`, `duel_send`, `select_format`, `rematch`, and opening the opponent picker |
| `exyliaaimtrainer.leave` | `leave` |
| `exyliaaimtrainer.profile` | Opening the profile and the records |
| `exyliaaimtrainer.leaderboard` | `leaderboard_drill`, `leaderboard_category`, `leaderboard_edition`, and opening the boards |
| `exyliaaimtrainer.history` | Opening the session and duel history |
| `exyliaaimtrainer.use` | Opening the main menu, and any other screen `open` names |
| `exyliaaimtrainer.admin` | Every `admin_*` action |

The **Accept** and **Decline** buttons in a duel request run `/aim accept` and `/aim deny`, so they check
`exyliaaimtrainer.duel` as commands. A player without `exyliaaimtrainer.train` can neither type
`/aim train` nor click a drill; an `aimtrainer:admin_*` action bound to an item in a player-facing menu
does nothing for whoever lacks `exyliaaimtrainer.admin`.

<Callout type="note" title="Nothing per drill, nothing per arena">
There are no permission nodes for individual drills, formats, colours, styles or arenas, and none that
lets a player run blocked commands while inside a drill. A player who may train may train every
configured drill at any size and distance inside the configured range.
</Callout>

## Examples

Taking duels away from a group while leaving drills in place:

```text
/lp group default permission set exyliaaimtrainer.duel false
```

Handing the admin screens to staff who are not operators:

```text
/lp group staff permission set exyliaaimtrainer.admin true
```

Without the permission, a command answers with the configured `no-permission` line from `messages.yml`.
