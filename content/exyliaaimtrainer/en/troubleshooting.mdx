Find the message or symptom, then follow the fix. For longer answers see the [FAQ](/docs/exyliaaimtrainer/faq).

## "No arena is ready. Ask an administrator."

Every drill and duel needs a ready arena. An arena is ready when it is **enabled** and has a **spawn** in a loaded world.

1. Run `/aimtraineradmin` and click **Arenas**. A row marked **[NO SPAWN]** is missing its spawn or is disabled; open it to see which (**Spawn**, **Status**).
2. Open the arena, click **Spawn** and set it. See [Your first arena and drill](/docs/exyliaaimtrainer/first-steps).

The same message appears when every ready arena is full. `arena.max-players-per-arena` in `config.yml` caps it; `0`, the default, is no cap. Right after boot, wait for the console line `Loaded N arenas and M drills`: until then arenas are not read yet.

## "Targets need PacketEvents, which this server does not have."

The targets are drawn with packets. Install `packetevents` in `plugins/` and restart. The console says so at startup: `PacketEvents is missing: targets cannot be drawn and no drill can start`. Menus, profiles and boards still work meanwhile. See [Install ExyliaAimTrainer](/docs/exyliaaimtrainer/installation).

## The plugin does not load

`packetevents` is a hard dependency, and ExyliaLib is needed to run. Check both jars are in `plugins/`. The server must be Paper 1.21.1 or newer (Folia 1.21.4 or newer) on Java 21.

## "Finish what you are doing first."

The player is already in a drill or a duel. They leave with `/aim leave`. "You are busy in `<plugin>`" means another Exylia plugin (an FFA arena, an event, a practice match) holds them. See [Compatibility](/docs/exyliaaimtrainer/compatibility).

## A player cannot send a duel

- "Wait `<time>` before challenging again": the request cooldown, `match.duel-request-cooldown` seconds, or the rank value from `exyliaaimtrainer.duelcooldown.<n>`. See [Permissions](/docs/exyliaaimtrainer/permissions).
- The other player is busy, in a practice queue, or already has a request waiting. A newer request replaces an older one.
- The player lacks `exyliaaimtrainer.duel`, or the drill's node `exyliaaimtrainer.drill.<id>`.

## "Leave with /aim leave before using that command."

Inside a drill or a duel only the commands in `training.allowed-commands` work (`aim`, `aimtrainer`, `at`, `msg`, `r`, `tell` and `w` by default). Add a command to that list to allow it. No permission bypasses it, so staff leave first. See [Commands](/docs/exyliaaimtrainer/commands).

## A player is not on a leaderboard

A player appears once they have a stored run of that drill. Runs cut short are not stored, and Java and Bedrock players are on separate boards. See [Read leaderboards and player stats](/docs/exyliaaimtrainer/stats).

## My edits to a menu or message do not show

Run `/aimtraineradmin reload`. Files under `menus/admin/` are replaced from the jar on every start and reload, so edit the other files. See [Install ExyliaAimTrainer](/docs/exyliaaimtrainer/installation#which-menu-files-are-yours).

## Placeholders show up as text

Placeholders outside the plugin need PlaceholderAPI. The name is `%exyliaaimtrainer_<name>%` with no `aim_` group. See [Placeholders](/docs/exyliaaimtrainer/placeholders).
