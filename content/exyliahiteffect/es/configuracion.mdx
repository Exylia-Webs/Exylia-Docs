title: "Configuración"
description: "Cada bloque de config.yml y messages.yml, con sus valores por defecto."
---

`config.yml` se escribe desde un esquema: los comentarios se regeneran en cada arranque, las claves
desconocidas se descartan y una clave que borres vuelve con su valor por defecto. Guarda cómo se
comporta el plugin; cada palabra que lee un jugador está en `lang/<code>/messages.yml`, al final de
esta página.

## `language`

```yaml
language: default
```

De qué carpeta de `plugins/ExyliaHitEffect/lang/` se leen los menús y los mensajes. `default` sigue
el `language` del propio `config.yml` de ExyliaLib, así que una línea allí cambia todos los plugins de
Exylia; `en`, `es`, `pt`, `fr`, `ru` o `tr` fijan solo este plugin. Cada idioma es una carpeta completa que
puedes editar:

```
plugins/ExyliaHitEffect/
  config.yml
  effects.yml
  lang/es/messages.yml
  lang/es/menus/effects.yml
  lang/es/menus/crate.yml
  lang/es/menus/crate_open.yml
```

El inglés es la base sobre la que se ponen los demás, así que una línea aún sin traducir llega en
inglés. Un `language` cambiado entra con `/hiteffectsadmin reload`.

<Callout type="note" title="Los servidores que venían de 1.2.0 conservan sus menús">
En el primer arranque de 1.4.0 los antiguos `menus/` se mueven a `lang/custom/`, los nombres y el lore
de los objetos, las líneas del arma, los textos del menú, los nombres de visibilidad y las respuestas
de placeholder que guardaba `config.yml` pasan a `lang/custom/messages.yml`, y `config.yml` apunta ahí
con `language: custom`. Las líneas de chat del antiguo bloque `messages` de `config.yml` no se
trasladan: vuelve a aplicar en `messages.yml` las que hubieras editado. Pon `language` en `default` o
en un código para pasar a las traducciones que vienen.
</Callout>

## `behaviour`

```yaml
behaviour:
  mode: both
  consume-token: true
  consume-remover: true
  hide-without-permission: false
```

| Clave | Por defecto | Qué hace |
|---|---|---|
| `mode` | `both` | `player`, `weapon` o `both`. Ver [Modos y fichas](/docs/exyliahiteffect/modos-y-fichas). |
| `consume-token` | `true` | Si la ficha se gasta al atarla. |
| `consume-remover` | `true` | Si el removedor se gasta al quitar un efecto. |
| `hide-without-permission` | `false` | Si los efectos bloqueados se esconden en el menú en vez de mostrarse bloqueados. |

Elegir un efecto en el menú siempre necesita su nodo o un desbloqueo; una ficha, un arma atada, un
comando y la API nunca. Ver [Permisos](/docs/exyliahiteffect/permisos).

## `effects`

Qué golpes lanzan algo.

```yaml
effects:
  all-mobs: false
  allowed-mobs:
    - PLAYER
    - MANNEQUIN
    - ZOMBIE
  disabled-worlds: []
```

`disabled-worlds` lista los mundos donde los efectos de golpe nunca se reproducen. Viene vacía; los
nombres se comparan sin distinguir mayúsculas.

<Callout type="tip" title="all-mobs en un servidor de granjas">
`all-mobs: true` significa que cada zombie de una granja lanza un efecto en cada golpe que recibe.
Los efectos de golpe suelen ser para PvP: deja la lista salvo que quieras chispas en cada mob que
pegues. En cualquier caso un jugador lanza como mucho cinco efectos por segundo; un barrido entre
varios reproduce los cinco primeros y descarta el resto.
</Callout>

## `token-item`, `remover-item` y `key-item`

```yaml
token-item:
  material: FIREWORK_STAR
  glow: true

remover-item:
  material: SCRAPE_POTTERY_SHERD
  glow: true

key-item:
  material: TRIPWIRE_HOOK
  glow: true
```

`material` solo se usa cuando el efecto no trae icono propio — normalmente la ficha se dibuja con el
material del efecto. Cómo se llama cada objeto y qué dice su lore está en `messages.yml`.

`key-item` es la llave que se lleva en la mano: click derecho a un bloque de caja y se abre. Ver
[La caja](/docs/exyliahiteffect/caja).

## `weapon-lore`

```yaml
weapon-lore:
  enabled: true
```

Si se dibujan las líneas bajo un arma atada. Se dibujan solo en paquetes — el objeto nunca las lleva —
y las líneas en sí son `weapon-lore` en `messages.yml`.

## `menu`

```yaml
menu:
  favourites-icon: "AMETHYST_SHARD"
```

El material con el que se dibuja la pestaña de favoritos. Cómo llama el menú a las cosas está en
`messages.yml`, y la pantalla en sí es `menus/effects.yml` — ver [El menú](/docs/exyliahiteffect/menu).

## `tiers`

Las rarezas en las que se ordenan los efectos, y con qué frecuencia sale cada una de una caja.

```yaml
tiers:
  common:
    name: "Common"
    material: GRAY_DYE
    color: "{muted}"
    chance: 60.0
    priority: 1
  rare: { name: "Rare", material: LIGHT_BLUE_DYE, color: "{info}", chance: 25.0, priority: 2 }
  epic: { name: "Epic", material: PINK_DYE, color: "{accent}", chance: 12.0, priority: 3 }
  legendary: { name: "Legendary", material: ORANGE_DYE, color: "{highlight}", chance: 3.0, priority: 4 }
```

La clave es el id de rareza que `effects.yml` escribe como `tier`. Agregá, renombrá o borrá las que
quieras — nada está fijo en el código, y `chance` es un peso, no un porcentaje. El detalle completo
está en [La caja](/docs/exyliahiteffect/caja).

## `crate`

```yaml
crate:
  enabled: true
  start-keys: 0
  duplicate-refund: 1
  reward: UNLOCK
  blocks: []
  max-at-once: 4
  spin-frames: 34
  stagger-seconds: 2.0
  on-spin:
    sound:
      name: BLOCK_NOTE_BLOCK_HAT
      pitch: 1.6
  on-win:
    sound:
      name: ENTITY_PLAYER_LEVELUP
      pitch: 1.2
  on-duplicate:
    sound:
      name: BLOCK_NOTE_BLOCK_BASS
      pitch: 0.8
```

| Clave | Por defecto | Qué hace |
|---|---|---|
| `enabled` | `true` | Si la caja se abre. Apagada, su botón lo dice. |
| `start-keys` | `0` | Llaves que recibe un jugador la primera vez que se lo ve. |
| `duplicate-refund` | `1` | Llaves que se devuelven cuando la caja cae en algo que ya tenía. |
| `reward` | `UNLOCK` | Qué entrega una ganancia: `UNLOCK`, `ITEM` o `BOTH`. |
| `blocks` | vacío | Bloques que abren la caja, como `server,world,x,y,z,yaw,pitch`. |
| `max-at-once` | `4` | Cuántas cajas se pueden abrir de una vez. La pantalla la limita a siete. |
| `spin-frames` | `34` | Caras por las que pasa el primer carrete. Tope 200, unos once segundos. |
| `stagger-seconds` | `2.0` | Cuánto después de un carrete se detiene el siguiente. `0` los para juntos. |
| `on-spin` | note block hat | Suena mientras caen los carretes. |
| `on-win` | level up | Suena en el momento en que un carrete cae en algo nuevo, una vez por caja. |
| `on-duplicate` | note block bass | Suena en cambio cuando ese carrete cayó en algo que ya se tenía. |

<Callout type="tip" title="Atá los bloques en el juego">
`/hiteffectsadmin crate block add` escribe el bloque que estás mirando. Un bloque atado no se puede
romper, volar ni empujar mientras esté en la lista — que es lo que editar esta clave a mano no te da.
</Callout>

## `preview`

Dónde se muestran las previsualizaciones.

```yaml
preview:
  location: ""
  distance: 5.0
  settle-ticks: 4
  linger-ticks: 20
  max-ticks: 600
```

Una previsualización lleva al jugador al escenario, lanza el efecto delante de él donde solo él lo ve,
y lo devuelve exactamente a donde estaba. Hasta que `location` esté puesta, no hay previsualización y
se dice. Ponela en el juego con `/hiteffectsadmin preview location`, no a mano.

| Clave | Por defecto | Qué hace |
|---|---|---|
| `location` | vacío | Dónde se para el jugador mientras corre la previsualización. |
| `distance` | `5.0` | A cuántos bloques delante de él se lanza el efecto. |
| `settle-ticks` | `4` | Cuánto esperar tras el teleport, para que el cliente tenga la posición nueva. |
| `linger-ticks` | `20` | Cuánto se sostiene el escenario después de que el efecto termina. |
| `max-ticks` | `600` | Lo máximo que puede durar una previsualización, pase lo que pase. |

<Callout type="note" title="Dos jugadores pueden compartir un escenario">
Todos los que están en el escenario están ocultos entre sí, y cada efecto se envía a un solo jugador,
así que una sola ubicación sirve para el servidor entero.
</Callout>

## `showcase`

Sitios que reproducen efectos de golpe solos, una y otra vez, para quien pase por delante: una pieza
central del lobby en vez de una pelea. Dos cuerpos se colocan a cada lado del punto, de través a hacia
donde mirabas al ponerlo, y uno golpea al otro tres veces, con el efecto cayendo en cada golpe. Llevan
las skins de los jugadores que están cerca, así que el público que mira es el reparto.

```yaml
showcase:
  locations: []
  pause-seconds: 3.0
  radius: 24.0
  only: []
```

| Clave | Por defecto | Qué hace |
|---|---|---|
| `locations` | `[]` | Dónde se reproducen efectos en bucle. Se fijan con `/hiteffectsadmin showcase add`. |
| `pause-seconds` | `3.0` | El descanso entre que termina un efecto y empieza el siguiente. |
| `radius` | `24.0` | Lo cerca que tiene que estar un jugador para que un showcase se reproduzca y se vea, en bloques. |
| `only` | `[]` | Los ids de efecto entre los que elige un showcase. Vacío elige entre todos. |

Sin nadie dentro de `radius` no se reproduce nada, así que un lobby vacío no cuesta nada. Un jugador
con visibilidad `NONE` o `SELF_ONLY` no ve los showcases: no son el golpe propio de nadie.

## `feedback`

```yaml
feedback:
  on-bind:
    sound:
      name: BLOCK_ENCHANTMENT_TABLE_USE
      volume: 1.0
      pitch: 1.2
  on-unbind:
    sound:
      name: BLOCK_GRINDSTONE_USE
```

Son bloques de efecto completos de ExyliaLib: título, action bar, boss bar, sonido, partícula y
firework están disponibles en cada uno. `on-bind` suena al atar un efecto a un arma **o** al elegirlo
en el menú.

## `particles`

```yaml
particles:
  default-visibility: "ALL"
```

La visibilidad con la que empieza un jugador: `ALL`, `NONE`, `SELF_ONLY` u `OTHERS_ONLY`. Cómo llaman
los menús y los placeholders a cada modo está en `messages.yml`.

## `shop`

Un efecto bloqueado se puede comprar directamente desde el menú con moneda. La fila dibuja su precio y
un click izquierdo pide al jugador que confirme antes de cobrar nada.

```yaml
shop:
  enabled: true
  tier-prices:
    common: 500
    rare: 1500
    epic: 4000
    legendary: 10000
```

| Clave | Por defecto | Qué hace |
|---|---|---|
| `enabled` | `true` | Si un efecto bloqueado se puede comprar desde el menú. |
| `tier-prices` | `500` / `1500` / `4000` / `10000` | Lo que cuesta un efecto según su rareza, en la moneda por defecto. Una rareza que no aparece no está a la venta. |

Un precio es un número (`500`, `2.5k`) o un bloque que nombra una moneda: `{amount: 50, currency: gems}`.
Un efecto en `effects.yml` puede poner su propio `price`, que gana al de su rareza. El dinero lo cobra
ExyliaEconomy o Vault; sin ninguno instalado, o con la tienda apagada, los efectos bloqueados se ven
exactamente como siempre.

Un efecto comprado queda desbloqueado en la cuenta, igual que uno ganado en [la caja](/docs/exyliahiteffect/caja):
sobrevive a un rango y no se puede intercambiar. Una compra que no se pudo entregar devuelve el dinero.
La confirmación y cada respuesta que envía son líneas propias de ExyliaLib, bajo `purchase` en el
`messages.yml` de ExyliaLib, compartidas por todos los plugins de cosméticos.

## `messages.yml`

Todas las líneas que envía el plugin, y cada palabra que dibuja un objeto o el menú, en
`lang/<code>/messages.yml`. `prefix` es `{primary}&lE-HITS &8•&r ` y el resto de mensajes empieza con
`%prefix%`.

| Clave | Cuándo se envía |
|---|---|
| `bound` | Se ató un efecto a un arma. |
| `unbound` | Se desató y se devolvió. |
| `chosen` | Se eligió un efecto en el menú. |
| `cleared` | Se quitó el efecto. |
| `not-a-weapon` | El objeto no puede llevar un efecto. |
| `wrong-weapon` | El efecto no encaja en esa arma. |
| `unknown-effect` | El id no nombra nada declarado. |
| `already-bound` | El arma ya lleva un efecto. |
| `no-effect` | El arma no lleva ninguno. |
| `inventory-full` | Un removedor necesita un hueco libre. |
| `no-permission` | El jugador no tiene el efecto. |
| `empty-hand` | Un subcomando de mano con la mano vacía. |
| `given` / `given-remover` / `given-key` | Se dieron fichas, removedores o llaves. |
| `rewards-claimed` | Un jugador entra y se le entregan las recompensas que le esperaban. |
| `list-header` / `list-entry` / `list-empty` | `/hiteffectsadmin list`. |
| `visibility-set` | Cambió la visibilidad. |
| `refreshed` | Terminó `refresh` o `validate`. |
| `menu-disabled` | Se abrió el menú en un servidor `weapon`. |
| `favourite-added` / `favourite-removed` / `favourites-cleared` / `favourites-empty` | La lista de favoritos. |
| `random-chosen` | Se activó la elección aleatoria. |
| `crate-won` / `crate-duplicate` | La caja cayó en algo nuevo, o en algo que ya tenía. |
| `crate-no-keys` / `crate-busy` / `crate-empty` / `crate-disabled` | La caja negándose a abrir. |
| `keys-received` / `keys-taken` / `keys-given` | Cambió el saldo de llaves. |
| `unlock-granted` / `unlock-already` / `unlock-revoked` / `unlocks-cleared` | Los subcomandos `unlocks`. |
| `crate-block-*` / `crate-blocks-*` | Los subcomandos `crate block`. |
| `preview-location-set` | Se movió el escenario de previsualización. |
| `preview-unavailable` / `preview-unavailable-admin` | Una previsualización en un servidor sin escenario. |
| `showcase-*` / `showcases-*` | Los subcomandos `showcase`. |

Placeholders en los mensajes: `%effect%`, `%amount%`, `%id%`, `%visibility%`, `%player%`, `%keys%`,
`%location%` y `%prefix%`.

Debajo de los mensajes, las palabras que se dibujan en vez de enviarse:

| Clave | Qué es |
|---|---|
| `token-item`, `remover-item`, `key-item` | El `name` y el `lore` de cada objeto. En la ficha, `%effect%` es el nombre del efecto y `%weapons%` a qué encaja. |
| `weapon-lore` | Las líneas bajo un arma atada. `%effect%` es el nombre del efecto. |
| `menu` | Cómo llama el menú a las cosas: `empty`, `tab-open`, `tab-closed`, `weapons-any`, `weapon-names`, `favourites-name`, `favourite-on`, `favourite-off`, `random-name`, `random-on`, `random-off`. |
| `particles` | Cómo se llama cada modo de visibilidad: `name-all`, `name-none`, `name-self-only`, `name-others-only`. |
| `placeholders` | `none`, lo que responde cualquier `%exyliahiteffect_...%` cuando no hay valor, y `unknown`, lo que responde uno que nombra algo que ya no existe. |

`menu.weapon-names` es cómo se escribe un arma allí donde se dibuja `%weapons%`, por familia
(`sword`, `axe`, `trident`, `mace`, `bow`, `crossbow`, `melee`, `ranged`) o por id de objeto
(`netherite_sword`). Lo que falte se deletrea a partir de su id.
