Find your symptom, then follow the fix.

## The plugin does not start

The console names what is missing. ExyliaLib and `packetevents` are both needed. The server must be Paper 1.21.1 or newer, or Folia 1.21.4 or newer. See [Install ExyliaHitEffect](/docs/exyliahiteffect/installation).

## Nothing plays when I hit something

Check, in this order:

- The victim counts. By default only `PLAYER`, `MANNEQUIN` and `ZOMBIE` do: a cow plays nothing. Change `effects.all-mobs` or `effects.allowed-mobs` in `config.yml`.
- The world is not listed in `effects.disabled-worlds`.
- You wear an effect: `/hiteffect` shows it on the **Your effect** button. `/hiteffect clear` also stops a rank default, so pick one again.
- The mode allows it. With `behaviour.mode: weapon` only a bound weapon plays an effect, and the menu choice is ignored. With `player` a weapon's effect is ignored. See [Modes and tokens](/docs/exyliahiteffect/modes-and-tokens).
- The weapon fits the effect. An effect that only fits swords says so in its lore, and the token refuses a wrong weapon.

## Players see the effects locked

Effects are unlocked by permission, and players own none by default. Give a rank a category or a rarity, for example `exyliahiteffect.category.impact`. See [Permissions](/docs/exyliahiteffect/permissions). Operators own everything through `exyliahiteffect.effect.*`, so a test as an operator proves nothing about a rank: test with a normal account.

## An effect disappeared from a player's menu

If `behaviour.hide-without-permission` is `true`, an effect the player may no longer use is hidden instead of drawn locked. It is `false` by default, so check that setting first, and set it back to `false` to show the effect locked. To take a lost effect off a player now rather than at their next join, run `/hiteffectsadmin player validate <player>`.

## `/hiteffect` says the menu is off

`behaviour.mode` is `weapon`, so the menu has nothing to choose. Set it to `player` or `both`. See [Modes and tokens](/docs/exyliahiteffect/modes-and-tokens).

## The menu opens the 3D selector, or the other way round

`menu.style` in `config.yml` picks what `/hiteffect` opens: `CLASSIC` for the inventory menu, `SPATIAL` for the 3D selector. `/hiteffect classic` and `/hiteffect 3d` always open their own. See [The menu](/docs/exyliahiteffect/menu).

## Preview says it is not set up

No preview stage is saved. Stand where previews should play and run `/hiteffectsadmin preview location`. See [Your first hit effect](/docs/exyliahiteffect/first-steps).

## A token does not go onto my weapon

Drop it onto a weapon in your own inventory, not in a chest or another menu. The weapon must be one the effect fits and must not already carry an effect: use a remover first. With `behaviour.mode: player`, tokens do nothing.

## The crate says I have no keys

Keys are a number on the player's account. Give some with `/hiteffectsadmin keys give <player> [amount]`, or set `crate.start-keys` for new players. See [The crate](/docs/exyliahiteffect/crate).

## A placeholder shows as text

- PlaceholderAPI is not installed.
- The id in `%exyliahiteffect_favourite_<id>%` or `unlocked_<id>` is misspelled.

See [Placeholders](/docs/exyliahiteffect/placeholders).

## I edited a file and nothing changed

Run `/hiteffectsadmin reload`. It re-reads this plugin's files, not ExyliaLib's. A changed language or colour is shared: see [Messages and languages](/docs/exylialib/messages-and-languages).
