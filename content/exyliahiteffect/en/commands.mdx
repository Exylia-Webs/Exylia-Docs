## Player commands

`/hiteffect`, with the alias `hiteffects`. Everything under it
needs `exyliahiteffect.command.hiteffect`, which everybody holds by default; previews, random,
favourites, visibility, the shop and the crate each have a node of their own too (see
[Permissions](/docs/exyliahiteffect/permissions)).

| Command | What it does |
|---|---|
| `/hiteffect` | Opens the effect selector `menu.style` picks: the inventory menu, on the tab it was last left on, or the 3D selector. |
| `/hiteffect 3d` | Opens the [3D selector](/docs/exyliahiteffect/menu#the-3d-selector) whatever `menu.style` says. Alias: `showroom`. |
| `/hiteffect classic` | Opens the inventory menu whatever `menu.style` says. |
| `/hiteffect preview <effect>` | Plays an effect on the server's preview stage, or lends it to try on the mannequins. Owning it is not required. |
| `/hiteffect crate` | Opens the crate. Aliases: `crates`, `case`. |
| `/hiteffect random` | Draws a different effect out of what they own on every hit. Alias: `shuffle`. |
| `/hiteffect visibility [mode]` | Sets who sees hit effects for them. With no mode it steps to the next one. |
| `/hiteffect favourites` | Opens the menu straight onto the shortlist. Aliases: `favorites`, `favs`. |
| `/hiteffect favourite <effect>` | Stars an effect, or unstars it. Aliases: `favorite`, `fav`. |
| `/hiteffect favourites clear` | Empties the shortlist. |
| `/hiteffect clear` | Takes the effect off. |

## Admin commands

`/hiteffectsadmin`, alias `/hiteffectadmin`. Everything under it needs `exyliahiteffect.admin`.
Typed bare, it opens the admin hub: the catalogue, players, showcases and crate blocks from one
screen; the subcommands stay as shortcuts. `player clear`, `crate block clear` and `showcase clear` only say what they would delete until they are run again with `confirm` at the end.

| Command | What it does |
|---|---|
| `item give <player> <effect> [1-64]` | Gives effect tokens. |
| `item remover <player> [1-64]` | Gives effect removers. |
| `item key <player> [1-64]` | Gives crate keys as items, to be right clicked on a crate block. Alias: `item keys`. |
| `weapon bind <effect> [player]` | Binds an effect to the weapon in hand, replacing whatever it carried. |
| `weapon unbind [player]` | Strips the effect from the weapon in hand, giving nothing back. |
| `player set <player> <effect>` | Sets what a player wears. |
| `player clear <player> [confirm]` | Resets a player\'s choice: they go back to the default their rank gives, if any. |
| `player favourites clear <player>` | Empties a player's shortlist. |
| `player validate [player]` | Takes off an effect the target may no longer use. With no player, everyone online. |
| `keys give <player> <amount>` | Adds crate keys to the player's row. Alias: `keys add`. The keys that can be held are `item key`. |
| `keys take <player> <amount>` | Removes crate keys. Alias: `keys remove`. |
| `keys set <player> <amount>` | Sets the balance outright. |
| `keys check <player>` | Prints what they hold. Written as `keys <player>` too. |
| `unlocks grant <player> <effect>` | Writes an effect onto their row, as a crate win does. Alias: `unlocks give`. |
| `unlocks revoke <player> <effect>` | Takes one back off. Alias: `unlocks take`. |
| `crate block add` | Binds the block you are looking at as a crate opener. Opens a placement wizard: walk there and confirm. |
| `crate block remove` | Unbinds the block you are looking at. |
| `crate block list` | Prints every bound block. |
| `crate block clear [confirm]` | Unbinds all of them. |
| `menu open <player>` | Opens the effect selector `menu.style` picks for someone. |
| `menu crate <player>` | Opens the crate for someone. |
| `preview play <effect> [player]` | Previews an effect, for yourself or for someone else. |
| `preview location` | Sets the preview stage to where you stand. Opens a placement wizard: walk there and confirm. |
| `preview mode <teleport\|mannequin>` | Picks how previews are shown. |
| `preview mannequin add` | Places a mannequin where you stand, facing the way you face. Opens a placement wizard: walk there and confirm. |
| `preview mannequin remove` | Removes the mannequin nearest you, up to five blocks away. |
| `preview mannequin clear` | Removes all of them. |
| `spatial place` | Sets a 3D selector down where you stand, facing the way you face. Opens a placement wizard: walk there and confirm. |
| `spatial remove` | Removes the 3D selector nearest you, up to four blocks away. |
| `spatial edit` | Opens the 3D selector to move its pieces: aim, click, then the mouse wheel moves it. |
| `spatial tour <player>` | Shows that player the 3D selector's guided tour again on their next open. |
| `showcase add` | Plays hit effects on a loop where you stand, over and over. Opens a placement wizard: walk there and confirm. |
| `showcase remove` | Removes the showcase nearest you, up to five blocks away. |
| `showcase list` | Prints every showcase. |
| `showcase clear [confirm]` | Removes all of them. |
| `list [category]` | Prints every effect, or just one category's. |
| `refresh [player]` | Redraws what a player is holding. With no player, everyone online. |
| `reload` | Re-reads this plugin's files. |

Every verb is a group: `keys` on its own completes to `give`, `take`, `set` and `check`, and `crate`
completes to `block`. Nothing is spelled out twice.

<Callout type="note" title="A player does not have to be online">
`player`, `keys` and `unlocks` take a name or a UUID and write straight to the player's row when
they are offline, so a support ticket, a rank reward or a wiped season is settled the moment it is
decided rather than the next time they log in. The exceptions are the ones that need a body to act
on: the whole `item` group, `weapon bind`, `weapon unbind`, `player validate`, `menu open`,
`menu crate`, `preview play`, `spatial tour` and `refresh`.
</Callout>

<Callout type="note" title="Resetting a player is ExyliaLib's">
There is no plugin command that wipes a player any more. Both tables this plugin keeps a player in are
classified as `@account` data, so ExyliaLib's
[`/exylialib resetplayer <player> ExyliaHitEffect @account`](/docs/exylialib/commands#resetting-a-player)
clears their choice, favourites, keys and every effect they won or bought, and
[`/exylialib wipe`](/docs/exylialib/commands#wiping-by-kind) covers them by kind. A plain
`resetplayer` with no kinds leaves them alone: `@account` is only removed when named.
</Callout>

<Callout type="note" title="bind, set and unlocks ignore permissions">
They are admin verbs: a crate, a rank reward or a support ticket has already decided the player may
have the effect. Permissions govern what a **player** chooses in the menu, never what an admin or the
API does.
</Callout>

## What each one actually does

### `weapon bind`

Acts on the target's main hand. An empty hand answers `empty-hand`. A weapon that already carries an
effect has it replaced — the old one is dropped, not returned as a token. The weapon that does not fit
the effect's `weapons` list is refused.

### `weapon unbind`

Strips the value and hands nothing back, which is the difference from a remover item. For giving the
token back, have the player use a remover.

### `player validate`

Re-checks the target's choice against their permissions and takes it off if it no longer holds. The
same check runs on join, on the next hit and on every menu open — `player validate` is how you make it
immediate after changing a rank. An effect won out of the crate is never taken off by it: it is on the
player's row rather than on a node.

### `preview location`

Previews play on a stage rather than on top of the player: they are moved there, the effect plays in
front of them where only they can see it, and they are put back exactly where they were. Until a stage
is set, `/hiteffect preview` says previews are unavailable — and tells an admin how to set one.

Stand where the preview should happen and run it. Only the position is taken: a preview always faces
north, so every effect is seen from the side it was drawn for — leave the north side of the room open.
The location is written to `config.yml` as `preview.location`.

### `preview mode`

`teleport` is the stage above. `mannequin` moves nobody: the player is lent the effect for
`preview.mannequin.trial-seconds` (30 by default) and hits the mannequins placed with
`preview mannequin add` as often as they like, with a boss bar counting down. The lent effect plays
on the mannequins only, never in a real fight. Until a mannequin is placed, a preview says there is
none, and tells an admin how to place one.

### `spatial place`

Leaves a small clickable hologram in front of where you stand, kept in `spatial/spots.yml`. A player
who clicks it is walked onto the spot and the 3D selector opens there, facing the way you faced; they
stay where they are when it closes. It asks for `exyliahiteffect.command.hiteffect` like the command
does. What it looks like,
for every selector, is `spatial/effects.yml`; `spatial edit` writes the pieces you move there.

### `showcase add`

Writes where you stand, and the way you face, to `config.yml` as a place that plays a random effect
over and over for whoever walks past — a lobby centrepiece rather than a fight. Two bodies stand
either side of the spot, across the way you faced, so the crowd in front sees both in profile; they
wear the skins of the players standing nearby, and with nobody inside `showcase.radius` nothing plays
at all. The rest between effects, the radius and which effects a showcase picks from are in
[Configuration](/docs/exyliahiteffect/configuration).

### `refresh`

Re-sends the player's inventory so the lines under a bound weapon are redrawn. It touches no file and
plays no effect: it is the answer to a weapon whose line went stale.

### `reload`

Runs one step, `configs`, which re-reads `config.yml`, `effects.yml`, `messages.yml`,
`spatial/effects.yml` and every file under `menus/` of the language in use, recompiles every sequence,
reapplies the message prefix and redraws any 3D selector that is open. Edits made to the menu file survive.

It deliberately does **not** reload ExyliaLib — recolouring every plugin on the server is what
`/exylialib reload` is for.

<Callout type="warning" title="A reload republishes the catalogue">
Effects are recompiled before the new catalogue is published, so nothing plays a half-compiled
sequence. But an effect whose key you renamed is a new effect: anyone wearing the old one loses it,
and any weapon bound to it now carries an id the file no longer declares.
</Callout>
