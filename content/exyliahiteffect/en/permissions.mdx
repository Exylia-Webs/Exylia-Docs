## The nodes

Every node is declared in `plugin.yml`, so a permissions plugin lists and completes all of them.

### Features

Everybody holds these by default. A server turns one into a rank perk by denying it to the default
group and granting it to the rank. Taking an effect off, turning random off, unstarring and emptying
the favourites never need one: giving something back is never locked.

| Permission | Default | Grants |
|---|---|---|
| `exyliahiteffect.command.hiteffect` | everyone | `/hiteffect` and everything under it, and the 3D selectors placed in the world. |
| `exyliahiteffect.preview` | everyone | Watching an effect on the preview stage or on the mannequins. |
| `exyliahiteffect.random` | everyone | The random choice: a different effect on every hit. |
| `exyliahiteffect.favourites` | everyone | Starring effects and opening the favourites tab. |
| `exyliahiteffect.visibility` | everyone | Choosing whose hit effects they see. |
| `exyliahiteffect.buy` | everyone | Buying effects in the shop. Without it, prices are not shown at all. |
| `exyliahiteffect.crate` | everyone | Opening the crate: its menu button, `/hiteffect crate` and a bound crate block. |
| `exyliahiteffect.crate.multi.<n>` | nobody | Opening up to `<n>` crates in one go instead of `crate.max-at-once`. The highest one held wins, seven at most. |

A player missing one is told `feature-locked` ("Your rank does not include that feature.") instead of
the action silently doing nothing.

### Admin

| Permission | Default | Grants |
|---|---|---|
| `exyliahiteffect.admin` | op | Every subcommand of `/hiteffectsadmin`, the admin hub and the `effects.yml` editor. |

### Effects

These are what a server sells, so nobody but op holds them until a rank or a purchase grants them.

| Permission | Default | Grants |
|---|---|---|
| `exyliahiteffect.effect.<id>` | nobody | One effect, by its id in lowercase. |
| `exyliahiteffect.effect.*` | op | Every effect. |
| `exyliahiteffect.category.<id>` | nobody | Every effect in that category. |
| `exyliahiteffect.tier.<id>` | nobody | Every effect of that rarity. |

An effect is owned if **any** of the four effect nodes applies: its own, the wildcard, its category's,
or its rarity's.

<Callout type="note" title="Or if it was won">
An effect out of the crate, or bought from the menu's [shop](/docs/exyliahiteffect/configuration#shop),
is written to the player's own row, not granted as a node. Ownership is read as "a permission grants
it **or** their row says they unlocked it", which is what lets a win outlive the rank that paid for the
key. See [The crate](/docs/exyliahiteffect/crate).
</Callout>

## The id is the node

There is no `permission` key in `effects.yml`. The node is derived from the key, lowercased:

```text
CRIT_SPARK  →  exyliahiteffect.effect.crit_spark
impact      →  exyliahiteffect.category.impact
legendary   →  exyliahiteffect.tier.legendary
```

Case is not part of it, so recapitalising a key changes nothing. Renaming one changes everything: it
is a different node, and everybody who had the old one loses the effect.

## Selling it

```text
/lp group vip     permission set exyliahiteffect.category.impact true
/lp group mvp     permission set exyliahiteffect.effect.crit_spark true
/lp group elite   permission set exyliahiteffect.tier.legendary true
/lp group legend  permission set exyliahiteffect.effect.* true
```

Six categories of fifteen is what makes a category node worth selling: "every Impact effect" is one
line instead of fifteen. A rarity node cuts the other way — "every Legendary" is a rank sold on how
rare its effects are rather than on what they look like.

A feature is sold the other way round: take it from everybody, give it back to the rank.

```text
/lp group default permission set exyliahiteffect.random false
/lp group vip     permission set exyliahiteffect.random true
/lp group vip     permission set exyliahiteffect.crate.multi.7 true
```

<Callout type="tip" title="Give the menu away">
`exyliahiteffect.command.hiteffect` is on for everybody out of the box. Leave it that way: a player
who cannot see what is for sale cannot want it.
</Callout>

## What the node is checked for

<Steps>
  <Step title="Wearing">
    Choosing an effect in the menu without its node, an unlock from the crate or a purchase is refused
    with `no-permission`. There is no switch to turn this off.
  </Step>
  <Step title="Playing what the menu chose">
    The choice is re-checked at the moment of the hit. One that no longer holds is taken off there
    and then, rather than left sitting in the menu until the next relog.
  </Step>
  <Step title="Being drawn">
    `behaviour.hide-without-permission` decides whether a locked effect is hidden in the menu or shown
    locked. Either way it can be previewed, and on the favourites tab it is always shown.
  </Step>
</Steps>

<Callout type="note" title="Tokens and weapons are never checked">
A token is a real item: it is bought, traded and lost like any other, and holding one is the proof.
Binding it asks for no node, and a bound weapon plays its effect for whoever is holding it — which is
the point of an effect you can trade. Permissions govern what a player wears out of the menu, not what
they carry in their hands.
</Callout>
