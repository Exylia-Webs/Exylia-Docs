Every ExyliaCapture command, with the permission it needs. Event ids complete as you type: `start` suggests the configured events, `stop` suggests the ones running.

<Commands />

## Start and stop an event

`/captureadmin start <configId>` starts an event now, even when it also has a schedule. When it cannot start, the chat gives one line per reason: it is switched off, where it runs is not set, its type is unknown, or another plugin cancelled the start. Fix it in `/captureadmin`, **Configurations**, your event. See [Your first event](/docs/exyliacapture/first-steps).

`/captureadmin list` opens the running events menu. Click an event to see it, right-click to stop it; stopping always asks you to confirm. From the console, the command prints the running events as text.

## What reload does

`/captureadmin reload` re-reads `config.yml`, `messages.yml` and `scoreboards.yml`, the event configurations and the menus. It also registers the placeholders of a new event and restarts the scheduler with the current schedules. If a step fails, the console names it and you are told how many worked.

It does not reopen the database. After changing `database.yml`, restart the server.

<Callout type="note" title="The old /cadmin alias is gone">
The admin command is only `/captureadmin`. Update any menu, hologram or rank-up command that still uses `/cadmin`.
</Callout>
