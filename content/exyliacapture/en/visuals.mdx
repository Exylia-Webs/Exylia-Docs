By the end of this page you have changed what players see during an event: the boss bar at the top, the hologram over the zone and the sidebar. Waypoints need no setup.

## Before you start

- An event that exists. See [Your first event](/docs/exyliacapture/first-steps).
- Access to `plugins/ExyliaCapture/lang/<code>/messages.yml` and `scoreboards.yml`, where `<code>` is your language. Text and colours use ExyliaLib's tags: see [Colours](/docs/exylialib/colours) and [Messages and languages](/docs/exylialib/messages-and-languages).

## Steps

<Steps>
  <Step title="Turn the boss bar or sidebar on or off for one event">
    Run `/captureadmin`, click **Configurations**, click the event, then **Bossbar** or **Scoreboard**. Each click toggles it. Everything below only applies to events where they are on.
  </Step>
  <Step title="Edit the boss bar text">
    Open `lang/<code>/messages.yml`, find `boss-bars`, then your event type's id (`koth`, `conquest`, `payload`...), and change `text`, `colour` or `overlay`.
  </Step>
  <Step title="Edit the hologram lines">
    In the same file, find `hologram-lines` and the type's id. Each list entry is one line.
  </Step>
  <Step title="Edit the sidebar">
    Open `lang/<code>/scoreboards.yml`, find the type's id under `scoreboards`, and change its lines.
  </Step>
  <Step title="Reload">
    Run `/captureadmin reload`, or click **Reload** in `/captureadmin`.
  </Step>
</Steps>

## Check that it works

Start the event with `/captureadmin start <id>`. You should see the boss bar with your text and colour, the hologram over the zone and the sidebar on the right. A hologram is visible even when the event is not running: its last line then reads inactive or scheduled.

## Going further

Four independent layers, each with its own configuration and its own tokens, plus what a supported client draws on top. Tokens look like `%event_name%`; they are the plugin's own, not PlaceholderAPI placeholders, and only work in the file they are listed for. For PlaceholderAPI values see [Placeholders](/docs/exyliacapture/placeholders).

## Boss bar

One per event type, in `messages.yml`, under `boss-bars` and that type's id, so it follows the
plugin's language:

```yaml title="lang/<code>/messages.yml"
boss-bars:
  koth:
    text: "{highlight}&l%capture_event_name%&r {muted}| {success}⚑ %capture_koth_capturer% {muted}| {info}%capture_koth_player_time% ⌚"
    colour: RED
    overlay: NOTCHED_20
```

`colour` takes `PINK`, `BLUE`, `RED`, `GREEN`, `YELLOW`, `PURPLE` or `WHITE`; `overlay` takes
`PROGRESS`, `NOTCHED_6`, `NOTCHED_10`, `NOTCHED_12` or `NOTCHED_20`.

The fill is the event's own progress, written every second — there is no countdown timer on the bar
itself, because it would fight the progress the event is writing.

Default colours: KOTH red, both KOTH Points types blue, KOTH Capture Points purple, Conquest green,
Payload yellow, DTC red, Bounty red. Every shipped bar uses `NOTCHED_20`. Bounty's bar names the
target and their health, and empties as the target is worn down.

A single event can turn its bar off with the `bossbar-enabled` setting.

## Holograms

Also one per event type, and unlike the boss bar it is shown **even when the event is not
running**: the last line, `%event_status%`, reads inactive, scheduled or running. What it says is in
`messages.yml`, under `hologram-lines` and the type's id; how it is drawn — `enabled`, size, offsets,
view distance — stays in `config.yml`, under `event-visuals.<type>.hologram`.

```yaml title="lang/<code>/messages.yml"
hologram-lines:
  koth:
    - "{warning}⚔ {highlight}&l%event_name%"
    - " "
    - "{letters}Time: {info}%event_time%"
    - "{letters}Capturing: {highlight}%koth_capturer%"
    - "{letters}Cap. time: {info}%koth_player_time%"
    - " "
    - "%event_status%"
```

Conquest draws one hologram per zone, each with that zone's own name and progress. Payload's follows
the cart. Bounty has nowhere to put one and draws none, although its block is still written.

Two events with a zone in the same place stack their holograms instead of drawing through each other, and a disabled event shows no hologram.

## Sidebars

`scoreboards.yml` holds three things:

| Section | Used when |
|---|---|
| `scoreboards` | Exactly one event is running. One sidebar per type id. |
| `compact-lines` | The `lines` one event contributes to the shared sidebar, two by default, per type id. |
| `multi-event` | Two or more events are running. |

Both per-type sections are keyed by the type id, and every type has its own entry — `koth_points_multi`
and `koth_capture_points` included, which no longer borrow another type's board.

With several events running, each contributes its two compact lines to one shared sidebar, up to
**four events**. The multi-event section decides the title, the separator, the two line templates —
where `{n}` becomes the event's index, 0 to 3 — and the footer.

```yaml title="scoreboards.yml"
multi-event:
  title: "{warning}&l⚡ EVENTS"
  separator: ""
  line1-format: " %e{n}_l1%"
  line2-format: " %e{n}_l2%"
  footer:
    - ""
    - " {highlight}ᴇxʏʟɪᴀ.ɴᴇᴛ"
  update-interval: 2
```

Single-event sidebars refresh every 2 ticks by default, which is what a live capture timer needs.

Each event type fills its own sidebar tokens. They are the plugin's own, not PlaceholderAPI
placeholders, and they only resolve inside `scoreboards.yml`.

## Client waypoints

If the player's client is Lunar with Apollo, or Feather, the running event's zone is marked on their
screen in the event's own colour. The marker is added when the event starts and removed when it ends.
Payload's follows the cart; DTC marks the core block; Bounty's follows the target, for every player
but them, while `track-target` is on.

Nothing needs configuring: without a supported client, no waypoint is sent and nothing else changes.
