Four independent layers, each with its own configuration and its own tokens.

## Boss bar

One per event type, in `config.yml`, under `event-visuals` and that type's id:

```yaml title="config.yml"
event-visuals:
  koth:
    boss-bar:
      text: "{highlight}&l%capture_event_name%&r {muted}| {success}⚑ %capture_koth_capturer% {muted}| {info}%capture_koth_player_time% ⌚"
      colour: RED
      overlay: NOTCHED_20
```

`colour` takes `PINK`, `BLUE`, `RED`, `GREEN`, `YELLOW`, `PURPLE` or `WHITE`; `overlay` takes
`PROGRESS`, `NOTCHED_6`, `NOTCHED_10`, `NOTCHED_12` or `NOTCHED_20`.

The fill is the event's own progress, written every second — there is no countdown timer on the bar
itself, because it would fight the progress the event is writing.

Default colours: KOTH red, both KOTH Points types blue, KOTH Capture Points purple, Conquest green,
Payload yellow, DTC red, Bounty red. Every shipped bar uses `NOTCHED_20`. Bounty's bar names the
target and their health, and empties as the target is worn down.

A single event can turn its bar off with the `bossbar-enabled` setting.

## Holograms

Also one per event type in `config.yml`, and unlike the boss bar it is shown **even when the event is
not running**: the last line, `%event_status%`, reads inactive, scheduled or running.

```yaml title="config.yml"
event-visuals:
  koth:
    hologram:
      enabled: true
      lines:
        - "{warning}⚔ {highlight}&l%event_name%"
        - " "
        - "{letters}Time: {info}%event_time%"
        - "{letters}Capturing: {highlight}%koth_capturer%"
        - "{letters}Cap. time: {info}%koth_player_time%"
        - " "
        - "%event_status%"
```

Conquest draws one hologram per zone, each with that zone's own name and progress. Payload's follows
the cart. Bounty has nowhere to put one and draws none, although its block is still written.

## Sidebars

`scoreboards.yml` holds three things:

| Section | Used when |
|---|---|
| `scoreboards` | Exactly one event is running. One sidebar per type id. |
| `compact-lines` | The `lines` one event contributes to the shared sidebar, two by default, per type id. |
| `multi-event` | Two or more events are running. |

Both per-type sections are keyed by the type id, and every type has its own entry — `koth_points_multi`
and `koth_capture_points` included, which no longer borrow another type's board.

With several events running, each contributes its two compact lines to one shared sidebar, up to
**four events**. The multi-event section decides the title, the separator, the two line templates —
where `{n}` becomes the event's index, 0 to 3 — and the footer.

```yaml title="scoreboards.yml"
multi-event:
  title: "{warning}&l⚡ EVENTS"
  separator: ""
  line1-format: " %e{n}_l1%"
  line2-format: " %e{n}_l2%"
  footer:
    - ""
    - " {highlight}ᴇxʏʟɪᴀ.ɴᴇᴛ"
  update-interval: 2
```

Single-event sidebars refresh every 2 ticks by default, which is what a live capture timer needs.

## Client waypoints

If the player's client is Lunar with Apollo, or Feather, the running event's zone is marked on their
screen in the event's own colour. The marker is added when the event starts and removed when it ends.
Payload's follows the cart; DTC marks the core block; Bounty's follows the target, for every player
but them, while `track-target` is on.

Nothing needs configuring: without a supported client, no waypoint is sent and nothing else changes.
