By the end of this page the event has the place it happens in: a box for a KOTH, several boxes for Conquest, two rail points for a Payload, or a block for Destroy The Core. Zones are boxes (cuboids) picked in game, with no WorldEdit needed. There are no round or polygon zones.

## Before you start

You need an event. Create one with `/captureadmin`, **Configurations**, **Create**, as in [Your first event](/docs/exyliacapture/first-steps). Which of the steps below you follow depends on its type:

| Type | What you mark |
|---|---|
| KOTH, KOTH Points, KOTH Capture Points | One box |
| Conquest | One box per zone |
| Payload | A start point and an end point, both on rails |
| Destroy The Core | One block |
| Bounty | Nothing. The hunt happens wherever the target runs. |

## Steps

### Mark a box (KOTH types)

<Steps>
  <Step title="Open the event">
    Run `/captureadmin`, click **Configurations**, then click your event (left-click edits it).
  </Step>
  <Step title="Start the zone selection">
    Click **Capture zone**. The menu closes and a guide gives you the selection wand.
  </Step>
  <Step title="Mark two corners">
    Left-click one corner and right-click the opposite one. The box between them is the zone, so pick corners at different heights if you want it tall.
  </Step>
  <Step title="Confirm">
    The chat says the zone is set and the setup screen reopens. The zone is already saved, and **Capture zone** now shows its coordinates. Selecting again later replaces it, and backing out keeps the old one.
  </Step>
</Steps>

### Conquest zones

<Steps>
  <Step title="Open the zone list">
    In the event's setup screen click **Capture zone** (it reads "Click to manage zones"). You can also go through **Type settings**, then **Manage zones**.
  </Step>
  <Step title="Add a zone">
    Click **Add zone** and mark two corners as above. It is added with the name `Zone`, white, 1 point and 30 seconds.
  </Step>
  <Step title="Name and tune it">
    Click the zone to open **Edit zone**. Use **Rename**, **Color** (a hex code like `#FF5500`), **Points per capture**, **Capture time**, and **Re-select area** to move it. **Delete** removes it.
  </Step>
</Steps>

### Payload rails

Payload does not use a box. It takes two points and scans the rail path between them.

<Steps>
  <Step title="Lay the rails">
    Build one connected line of rails from where the cart waits to where it must arrive. Both ends must be rails, and a gap means the cart has nowhere to go.
  </Step>
  <Step title="Set both ends">
    Click **Capture zone** in the setup screen (it opens the Payload settings), then **Spawn location** and **End location**. Each one asks you to click a rail block.
  </Step>
</Steps>

Players push the cart by standing within the **Capture radius** of the cart itself as it moves, not near a fixed zone.

### Destroy The Core block

Click **Capture zone** (it opens the DTC settings), click **Core block**, then click the block in the world.

## Check that it works

Back in the setup screen, **Capture zone** shows its coordinates instead of "not configured". Enable the event and run `/captureadmin start <id>`: the zone is drawn with particles for as long as the event runs. If the chat says the event is not configured well enough when you enable it, a zone is missing.

## Going further

### Who counts as inside

Presence is rechecked as players move, and also when they join, respawn, die, change game mode, or when [ExyliaStaff](/docs/exyliastaff/introduction) staff mode or vanish is switched.

| Situation | Counts |
|---|---|
| Alive, survival or adventure, inside the zone | Yes |
| Creative | No |
| Spectator | No |
| Dead | No |
| In ExyliaStaff staff mode, or vanished | No, and not warned either |

A player who switches to creative inside a zone stops counting at once, and starts counting again on switching back without leaving the zone.

### The outline

While an event runs, its zones are outlined with particles. This is global, not per event. In game, run `/captureadmin`, click **Settings**, then **Zone outline** to switch it off or change **View range**. The rest is in `config.yml`:

```yaml title="config.yml"
particles:
  enabled: true
  interval-ticks: 40
  particle: WAX_ON
  view-distance: 48.0
```

| Key | Default | What it does |
|---|---|---|
| `enabled` | `true` | Draw the outline at all. |
| `interval-ticks` | `40` | Ticks between frames. 20 ticks is one second. |
| `particle` | `WAX_ON` | Any Bukkit particle name. |
| `view-distance` | `48.0` | Beyond this many blocks nothing is sent. The menu allows 8 to 256. |

<Callout type="tip">
`interval-ticks` is the cost knob. A large arena with several running events redraws every outline on each frame. Doubling the interval halves that work and is barely noticeable.
</Callout>
