By the end of this page ExyliaCapture posts a card in a Discord channel when an event starts and when it ends, with the winner, the podium and the rewards. Messages are sent off the main thread, Discord's rate limits are respected, and player names are escaped so they can never ping anyone.

## Before you start

- A Discord channel where you can manage webhooks.
- Access to `plugins/ExyliaCapture/config.yml`. The webhook URL is the one value you cannot type in the in-game menu, because it is a secret.

## Steps

<Steps>
  <Step title="Create the webhook">
    In Discord open **Channel settings ▸ Integrations ▸ Webhooks**, create a webhook and click **Copy Webhook URL**. Keep it private: anyone who has it can post as the webhook.
  </Step>
  <Step title="Paste it in config.yml">
    Open `plugins/ExyliaCapture/config.yml` and fill the `webhooks` block. Never share or publish this file with the URL in it.
    ```yaml title="plugins/ExyliaCapture/config.yml"
    webhooks:
      enabled: true
      url: "https://discord.com/api/webhooks/<id>/<token>"
      server-name: "My Server"
    ```
  </Step>
  <Step title="Or switch it on in game">
    Run `/captureadmin`, click **Settings**, then **Discord**. **Announcements** turns posting on or off and **Server name** sets the name used in the footer.
  </Step>
  <Step title="Reload">
    Run `/captureadmin reload`, or click **Reload** in `/captureadmin`.
  </Step>
</Steps>

## Check that it works

Start any event with `/captureadmin start <id>`. A "started" card should appear in the channel within a few seconds. Stop it with `/captureadmin stop <id>` and a "stopped" card follows. If nothing arrives, read the console after the reload: a URL that is not a Discord webhook URL is refused with one warning that says why, and nothing is sent. See [Common problems](/docs/exyliacapture/troubleshooting).

<Callout type="warning" title="A deleted webhook stops sending">
If Discord reports the webhook as deleted or its token as wrong, a warning is logged and nothing more is sent until the next reload.
</Callout>

## Going further

### Change what the messages say

The messages live under `webhooks` in `lang/<code>/messages.yml`, so they follow the plugin's language. Edit the `title`, `description` and `fields` of the one you want, then reload. Set `enabled: false` on a message to silence it. Colours and the language system are explained in [Colours](/docs/exylialib/colours) and [Messages and languages](/docs/exylialib/messages-and-languages).

| Message | Posted when |
|---|---|
| `started` | An event begins. |
| `won` | One player or one clan won: KOTH, Payload, Bounty. |
| `podium` | A scored event ends: the points KOTHs, Capture Points, Destroy The Core, Conquest. |
| `no-winner` | The clock ran out with nobody winning. |
| `stopped` | An operator stopped the event before anyone won. |

### Ping a role

Only the `message` line above the card can ping, and only with what you write in the template yourself:

```yaml title="lang/en/messages.yml"
webhooks:
  started:
    message: "<@&ROLE_ID> A capture just started!"
```

Replace `ROLE_ID` with your role's id (Discord developer mode, right-click the role, **Copy Role ID**).

### Add a link button

Link buttons are written `label|url` or `label|url|emoji`:

```yaml title="lang/en/messages.yml"
webhooks:
  started:
    buttons:
      - "Live map|https://map.example.com|🗺️"
```

<Details title="Fields, placeholders and every template key">
`url` is the webhook address; if it is empty or not a Discord webhook URL the plugin sends nothing. `enabled` defaults to `false`. `server-name` defaults to empty and fills `%server%`, which the shipped messages use as their footer; Discord markdown works there.

Each message is a full ExyliaLib webhook template sent as a Discord Components V2 card: `enabled`, `message`, `color`, `title`, `description`, `author`, `thumbnail`, `image`, `fields`, `buttons`, `footer`, `timestamp`, `coalesce` and the rest. They are all described in [Discord webhooks](/docs/exylialib/discord-webhooks).

| Message | Its own placeholders |
|---|---|
| `started` | `%time_limit%`, `%rewards%` |
| `won` | `%winner%`, `%clan%`, `%winner_head%`, `%rewards%` |
| `podium` | `%top1_name%`, `%top1_pts%` up to `%top3_name%`, `%top3_pts%` |
| `no-winner`, `stopped` | none |

Every message also fills `%event_name%`, `%event_type%`, `%duration%` (how long the event has run) and `%server%`. `%winner_head%` is the winner's head as an image URL and is empty when a clan won.
</Details>
