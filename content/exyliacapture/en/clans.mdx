By the end of this page your events score for clans instead of single players, and `/capture clantop` ranks the clans. ExyliaCapture does not ship its own clans: it reads them from the clan plugin you already run, through ExyliaLib.

## Before you start

- A supported clan plugin installed and loaded (list below). There is no setting that names which one to use; it is detected at startup.
- An event of a type that supports clan mode: KOTH Points, KOTH Capture Points, Payload or Destroy The Core. Conquest is always clan-based. See [Event types](/docs/exyliacapture/event-types).

## Steps

<Steps>
  <Step title="Check that a clan plugin was found">
    Restart the server and read the console. You should see `Clans: detected '<name>'`, or `Clans: using registered bridge '<name>'`. If neither line appears, no provider was found and clan mode will do nothing.
  </Step>
  <Step title="Open the event">
    Run `/captureadmin`, click **Configurations**, then click your event.
  </Step>
  <Step title="Turn clan mode on">
    Click **Type settings**, then the **Clan mode** button so its state reads on. Conquest has no such button because it is always played by clans.
  </Step>
  <Step title="Save and run it">
    Run `/captureadmin start <id>` with your event's id.
  </Step>
</Steps>

## Check that it works

Join a clan, stand in the zone and score. The chat announcement shows your clan tag next to your name, the zone is held by the clan (it survives you leaving while a clanmate stays), and after the event `/capture clantop` lists your clan. Open `/capture`, then the clans tab, for the same screen.

<Callout type="note" title="No clan plugin, no clan mode">
With clan mode on and no provider detected, the event falls back to individual scoring instead of refusing to run. Conquest is the exception: its zones cannot register a capturer without a clan, so it never gives points. A player without a clan is skipped in clan mode: they cannot hold the zone and their points are not attributed.
</Callout>

## What clan mode changes

| Behaviour | Individual | Clan mode |
|---|---|---|
| Who holds a zone | One player | The clan |
| Who scores | The player | The clan's total |
| Who wins | The player who reached the target | The clan that reached it |
| Who is paid | The player | One representative of the clan |
| Whose stats go up | The player | Every participating member of the clan |

## Going further

### Clan statistics

Clan statistics are tracked next to player statistics, globally and per event: wins, points, captures and leaderboard points. They feed `/capture clantop` and the `%exyliacapture_top_clan_<position>_<stat>%` placeholders. A win is also recorded for the clan whenever the winning player belongs to one, even in an event that was scored per player. See [Show statistics and leaderboards](/docs/exyliacapture/stats).

### A clan plugin that is not listed

Any plugin can register a bridge with ExyliaLib, and a registered bridge beats automatic detection. That is the supported route for a clan plugin that is not in the list below.

<Details title="Detected clan plugins and their order">
ExyliaLib probes these in this order and uses the first one that is present and reachable:

1. FactionsUUID / Factions
2. HuskTowns
3. ZelTeams
4. RunithClans
5. UltimateClans
6. Kingdoms / KingdomsX
7. SimpleClans
8. ExyliaClans

The order is priority, not preference: a server running two clan plugins gets the one higher in the list. Every provider reaches its plugin by reflection, so a clan plugin that is installed but whose API cannot be reached is skipped with a console warning.
</Details>
