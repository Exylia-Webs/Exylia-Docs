Every placeholder below is written in full, and clicking one copies it.

## How many events are running

```text
%exyliacapture_active_events%
```

How many events are running across the whole server at that moment. It counts events, not the players
inside them, and it reads `0` when nothing is running.

## Per event

Where `<id>` is the event configuration's id:

```text
%exyliacapture_<id>_<stat>%
```

Each configured event registers its id as a placeholder family of its own, so an event called
`koth1` answers `%exyliacapture_koth1_status%`. The families are re-registered on
`/captureadmin reload`, which is how a newly created event becomes readable without a restart.

| Placeholder | Description |
|---|---|
| `%exyliacapture_<id>_display_name%` | The name players read |
| `%exyliacapture_<id>_id%` | The configuration id |
| `%exyliacapture_<id>_type%` | The type id, such as `koth` or `payload` |
| `%exyliacapture_<id>_color%` | The configured hex colour |
| `%exyliacapture_<id>_max_duration%` | The duration, or `∞` when unlimited |
| `%exyliacapture_<id>_status%` | `RUNNING`, `SCHEDULED` or `INACTIVE` |
| `%exyliacapture_<id>_time_remaining%` | Time left in the running event |
| `%exyliacapture_<id>_time_until_start%` | Time until the next scheduled start |
| `%exyliacapture_<id>_target_points%` | Points needed to win |
| `%exyliacapture_<id>_points_per_second%` | Points per second, KOTH Points only |
| `%exyliacapture_<id>_clan_mode%` | `true` or `false` |
| `%exyliacapture_<id>_leader%` | The leading player or clan |
| `%exyliacapture_<id>_leader_pts%` | The leader's points |
| `%exyliacapture_<id>_top1_name%` | The live podium's first name |
| `%exyliacapture_<id>_top1_pts%` | Its points |
| `%exyliacapture_<id>_top2_name%` | The second name |
| `%exyliacapture_<id>_top2_pts%` | Its points |
| `%exyliacapture_<id>_top3_name%` | The third name |
| `%exyliacapture_<id>_top3_pts%` | Its points |
| `%exyliacapture_<id>_capturer%` | Who is capturing right now |
| `%exyliacapture_<id>_capturer_clan%` | That capturer's clan |
| `%exyliacapture_<id>_cap_time_remaining%` | Time left to complete the current capture |
| `%exyliacapture_<id>_zone_x%` | The zone centre's X |
| `%exyliacapture_<id>_zone_y%` | The zone centre's Y |
| `%exyliacapture_<id>_zone_z%` | The zone centre's Z |
| `%exyliacapture_<id>_target%` | The target's name, Bounty only |
| `%exyliacapture_<id>_target_health%` | The target's health in hearts, Bounty only |
| `%exyliacapture_<id>_target_position%` | Where the target is, as `X, Z`, Bounty only |

Anything with no value returns an em dash rather than an empty string. In a Bounty, `capturer` is the target and
`cap_time_remaining` is the time left in the hunt; the three `target` stats only answer while it runs.

## The next scheduled event

```text
%exyliacapture_next_event_time_until_start%
%exyliacapture_next_event_display_name%
%exyliacapture_next_event_type%
```

It resolves against whichever configured event starts soonest across the whole server, and accepts
the same stats as the per-event family above.

## The reader's own statistics

```text
%exyliacapture_stats_wins%
%exyliacapture_stats_captures%
%exyliacapture_stats_points%
%exyliacapture_stats_leaderboard_points%
%exyliacapture_stats_time_captured%
```

These are the player's global totals, not per event.

## Leaderboard rows

```text
%exyliacapture_top_player_<position>_<stat>%
%exyliacapture_top_clan_<position>_<stat>%
```

Positions start at `1`. Stats for a player: `name`, `wins`, `points`, `leaderboard_points`,
`captures`, `time_captured`. For a clan the same, without `time_captured`.

```text
%exyliacapture_top_player_1_name%
%exyliacapture_top_player_1_leaderboard_points%
%exyliacapture_top_clan_3_wins%
```

A position past the end of the list returns an em dash for `name` and `0` for the numbers.

<Callout type="note" title="These come from the cache">
Leaderboard rows are served from the snapshot refreshed every 60 seconds, which is what keeps a
sidebar full of them from querying the database on every refresh.
</Callout>

## Not the same as the sidebar and hologram tokens

The `%capture_...%` tokens in `scoreboards.yml` and the `%event_...%` tokens in the hologram lines are
not PlaceholderAPI placeholders. They are values the plugin fills in while rendering its own screens,
and they only work there. See [On-screen visuals](/docs/exyliacapture/visuals).
