ExyliaGraves gives every death a grave: a player head with the dead player's face, standing where they
fell, holding exactly what they dropped. One click on the head hands everything back. It is free and open
source, published under the GNU General Public License v3.0 on
[GitHub](https://github.com/Exylia-Plugins/ExyliaGraves/releases).

It is built so a grave can never duplicate an item. The drops leave the death and go into one database
row, and only there; a grave is taken by deleting that row, and only whoever deleted it gets the items.
Two players clicking the same head, two servers, an expiry and a staff action racing for one grave: it is
handed over once.

It used to be the `graves` module of ExyliaSurvivalCore. It is its own plugin now, and it keeps the same
table, `sc_graves` — see [Network](/docs/exyliagraves/network#coming-from-exyliasurvivalcore).

## Requirements

| Requirement | Detail |
|---|---|
| Server | Paper 1.21.4 or newer. Folia supported. |
| Java | 21 |
| Required dependency | `ExyliaLib` — installed automatically when missing |
| Optional dependencies | `PlaceholderAPI`; an economy (`ExyliaEconomy` or `Vault`) only for a paid teleport |

<Callout type="note" title="About ExyliaLib">
The configuration files, the menus, the database and Redis, the holograms, the reward store that hands a
grave's contents over, the offline notices, the audit log and the teleports all come from ExyliaLib.
ExyliaGraves is the part that decides what goes into a grave and who may take it.
</Callout>

## Conventions

- Values marked as **default** are what the plugin writes the first time it starts. If the file already
  exists, your value is kept.
- Identifiers between `<` and `>` are variables. `/gravesadmin list <player>` means
  `/gravesadmin list Steve`.
- Times in `config.yml` are minutes as a bare number, or written out: `30m`, `2h`, `1d`.
- Colours use ExyliaLib palette tokens (`{primary}`, `{success}`, `{highlight}`), so recolouring the
  server never means editing these files.
