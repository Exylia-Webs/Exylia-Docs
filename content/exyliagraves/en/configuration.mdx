Every setting is a file in `plugins/ExyliaGraves/`, written with comments on the first start. Edit the
files there, never the copies in the jar, then run `/gravesadmin reload` (permission
`exyliagraves.admin.reload`) to apply it. A reload reads `config.yml`, `messages.yml` and the menus again;
graves already standing are not touched.

```text
plugins/ExyliaGraves/
├── config.yml
├── database.yml            (ExyliaLib's database file)
├── screens/graves.html     (the /graves screen for players on the SCREEN menu style)
└── lang/
    └── <code>/
        ├── messages.yml
        ├── screens/graves.yml
        └── menus/
            ├── user/graves.yml
            └── admin/*.yml
```

`<code>` is `en`, `es`, `pt`, `fr`, `ru` or `tr`, or ExyliaLib's own language while `language` in
`config.yml` says `default`. Colours, effect tags and translations work as in
[Messages and languages](/docs/exylialib/messages-and-languages); the menu files follow
[Edit menus](/docs/exylialib/edit-menus).

## Change settings in game

`/gravesadmin`, then the **Settings** card (permission `exyliagraves.admin`), edits the keys of
`config.yml` with clicks and writes the file for you. See
[Hand back or remove graves](/docs/exyliagraves/staff#settings). Messages and menus are not on those
pages: edit them in `lang/<code>/`.

## config.yml

The settings owners change most, in plain words. The key names are in brackets; the full table with
every default is further down.

- **How long a grave stands** (`graves.expire-time`, 60 minutes). `-1` keeps it until somebody collects
  it. What happens then is `graves.on-expire`: `DROP` leaves the items where it stood, `DELETE` removes
  them. A rank can have longer with `exyliagraves.expire.<minutes>`. See [Expiry](/docs/exyliagraves/expiry).
- **Who can open it** (`graves.protection-time`, 15 minutes; `graves.killer-can-loot`, on). `-1` keeps it
  its owner's for good. See [Protection](/docs/exyliagraves/protection).
- **How many a player can have** (`graves.max-per-player`, 5). Dying over the limit tips the oldest one
  out where it stands. See [Limits](/docs/exyliagraves/expiry#limits).
- **What goes in** (`contents.*`). Experience mode and share, items that never go in, items the player
  keeps. See [What a grave holds](/docs/exyliagraves/contents).
- **What a click does** (`collect.*`). Open the window, collect everything, preview, or nothing, for each
  of the four clicks. See [Collecting](/docs/exyliagraves/graves#collecting).
- **Teleport back** (`teleport.*`, off by default). See [The /graves menu](/docs/exyliagraves/teleport).
- **Hologram and respawn help** (`hologram.*`, `respawn.*`). The text itself is `hologram-lines` in
  `messages.yml`.
- **Language** (`language`, `default`). `default` follows ExyliaLib; set `en`, `es`, `pt`, `fr`, `ru` or
  `tr` to give this plugin its own.

<Details title="Every key of config.yml, with its default">

The defaults, with the comments trimmed:

```yaml title="plugins/ExyliaGraves/config.yml"
config-version: 1
language: default
graves:
  expire-time: 60
  on-expire: DROP
  protection-time: 15
  killer-can-loot: true
  max-per-player: 5
  disabled-worlds: []
contents:
  experience: VANILLA
  experience-percent: 100
  ignored-materials: []
  kept-materials: []
collect:
  auto-equip: true
  right-click: OPEN
  sneak-right-click: COLLECT
  left-click: OPEN
  sneak-left-click: COLLECT
  shared-window: true
  take-all-button: true
teleport:
  enabled: false
  cost: 0.0
  currency: ''
hologram:
  enabled: true
  offset: 1.4
respawn:
  point-compass: true
  remind: true
```

`config-version` is the file's own version, for the plugin to update it; leave it alone.

**language**

| Key | Default | What it does |
|---|---|---|
| `language` | `default` | The language of this plugin's menus and messages. `default` follows the language set in ExyliaLib's `config.yml`; `en`, `es`, `pt`, `fr`, `ru` or `tr` set this plugin alone. Each one is a folder under `lang/` you can edit. |

**graves**

| Key | Default | What it does |
|---|---|---|
| `graves.expire-time` | `60` | How long a grave stands, in minutes, or written out: `30m`, `2h`, `1d`. `-1` keeps it until it is collected. `exyliagraves.expire.<minutes>` gives a rank longer; the largest number a player holds wins. |
| `graves.on-expire` | `DROP` | What happens to the contents when a grave expires: `DROP` them where it stood, or `DELETE` them. Anything other than `DELETE` drops. |
| `graves.protection-time` | `15` | How long, in minutes, only the owner may open it (`exyliagraves.protection.<minutes>` gives a rank longer). `0` is anybody from the start, `-1` only ever the owner. |
| `graves.killer-can-loot` | `true` | Whether the player who made the kill may open it while it is protected. Not with a protection of `-1`. |
| `graves.max-per-player` | `5` | How many graves one player may have standing on this server. Dying with this many tips the oldest out where it stands. `-1` is no limit. `exyliagraves.limit.<n>` raises it. |
| `graves.disabled-worlds` | `[]` | Worlds, by name, where nobody gets a grave. Any case. |

A permission number can only raise a setting: with `-1` in the file, nothing changes it.

**contents**

| Key | Default | What it does |
|---|---|---|
| `contents.experience` | `VANILLA` | `NONE` (the orbs drop as usual), `VANILLA` (what would have dropped as orbs, at most 100 points) or `ALL` (every point the player had, levels included). An unknown value reads as `VANILLA`. See [Experience](/docs/exyliagraves/contents#experience). |
| `contents.experience-percent` | `100` | Of that experience, the percentage the grave keeps, 0 to 100 (`exyliagraves.experience.<percent>` gives a rank more). The rest is lost. |
| `contents.ignored-materials` | `[]` | Materials that never go into a grave: they drop on the floor as usual. |
| `contents.kept-materials` | `[]` | Materials the player keeps through death, in their inventory. |

**collect**

| Key | Default | What it does |
|---|---|---|
| `collect.auto-equip` | `true` | Whether the owner's armour and offhand go straight back on, into empty slots, when they collect their grave themselves. |
| `collect.right-click`, `collect.sneak-right-click`, `collect.left-click`, `collect.sneak-left-click` | `OPEN`, `COLLECT`, `OPEN`, `COLLECT` | What each click on a grave head does: `OPEN` its window, `COLLECT` everything at once, `PREVIEW` a copy (needs `exyliagraves.preview`) or `NONE`. Only the main hand counts. |
| `collect.shared-window` | `true` | Whether several players may have the same grave open at once, all seeing the same contents. `false` is one at a time. |
| `collect.take-all-button` | `true` | Whether the window has a button that takes everything left in one click. |

**teleport**

| Key | Default | What it does |
|---|---|---|
| `teleport.enabled` | `false` | Whether `/graves` lets a player go to one of theirs. Needs `exyliagraves.teleport`. |
| `teleport.cost` | `0.0` | What that teleport costs, in `teleport.currency`. `0` is free; `exyliagraves.teleport.free` skips it; `exyliagraves.teleport.cost.<amount>` makes it cheaper for a rank (the smallest number a player holds wins). See [The cost](/docs/exyliagraves/teleport#the-cost). |
| `teleport.currency` | empty | The ExyliaLib currency id the cost is paid in (Vault money, gems, an item or XP currency). Empty is ExyliaLib's default currency. See [Economy](/docs/exylialib/economy). |

**hologram and respawn**

| Key | Default | What it does |
|---|---|---|
| `hologram.enabled` | `true` | Whether a grave has floating text above it. Turned off, every hologram comes down within a second; turned back on, they return as their chunks load again or on the next start. |
| `hologram.offset` | `1.4` | How far above the block the text floats. |
| `respawn.point-compass` | `true` | Whether the player's compass points to their newest grave after they respawn, when it is in the same world. |
| `respawn.remind` | `true` | Whether they are reminded where their newest grave is after they respawn. |

</Details>

## messages.yml

`lang/<code>/messages.yml` holds every line the plugin says. `%prefix%` expands to the `prefix` value at
the top, `{primary}&lGRAVES {letters_black}•<reset>` in English. Colours are palette tokens, so
recolouring the server never means editing this file: see [Colours](/docs/exylialib/colours).

A line may open with an effect tag, which never reaches the screen. `[sound:NAME|volume|pitch]` plays a
sound to whoever receives it, and `[hud:name]` shows the line on the HUD instead of in chat; tags go
together, as in `[hud:grave-new;sound:BLOCK_BELL_RESONATE|0.8|0.6]`. An empty line is not sent at all,
which is how a message is turned off.

<Details title="Every message and the values it receives">

| Keys | When | Values |
|---|---|---|
| `prefix` | Opens every chat line through `%prefix%`. | |
| `created` | A death made a grave. | `%x%` `%y%` `%z%` `%world%` `%items%` `%time_left%` |
| `collected` | The owner collected it. | `%items%` `%experience%` `%player%` |
| `looted` | Somebody else collected it. | `%items%` `%experience%` `%player%` (the owner) |
| `protected-grave`, `protected-grave-forever` | A player who may not open it clicked it. | `%player%` `%time_left%` |
| `gone` | The grave was already taken. | |
| `cannot-break` | Somebody tried to mine it. | |
| `claim-failed` | The database could not be reached; the grave is still there. | |
| `rewards-delivered` | Contents kept for a player were handed over on join. | `%amount%` |
| `respawn-reminder` | After respawning. | `%x%` `%y%` `%z%` `%world%` |
| `looted-notice` | Left for the owner when somebody looted their grave. | `%player%` `%items%` `%world%` |
| `expired-dropped`, `expired-deleted` | Left for the owner when a grave expired. | `%items%` |
| `preview-title` | The title of a grave's window and of the preview copy. | `%player%` |
| `window-busy`, `inventory-full` | A grave already being looked at with `shared-window` off; a stack that does not fit the taker's inventory. | |
| `window-experience-name`, `window-experience-lore`, `window-take-all-name`, `window-take-all-lore` | The experience bottle and the take-all chest in the window. | `%items%` `%experience%` |
| `cannot-preview` | A preview that is not allowed. | |
| `teleported`, `teleport-disabled`, `not-enough-money`, `teleport-refunded` | The teleport from `/graves`. | `%cost%`, formatted in the currency |
| `in-combat` | A teleport refused in combat. | `%time%` |
| `server-unreachable`, `world-not-loaded`, `teleport-failed` | Why a teleport did not arrive. | |
| `no-permission` | A missing node. | |
| `hologram-protected`, `hologram-open`, `hologram-forever`, `hologram-protected-for` | The words of `%protection%` and of a never-ending `%time_left%`. | `%time_left%` in `hologram-protected-for` |
| `hologram-lines` | The lines above a grave, top to bottom. | `%player%` `%items%` `%time_left%` `%protection%` |
| `menu-teleport`, `menu-preview`, `menu-restore`, `menu-remove` | The click hints of a grave in the menus. Empty hides one. | |
| `admin-usage` | `/gravesadmin` on its own from the console. | |
| `restore-prompt`, `restored`, `restored-all` | Handing graves back. | `%player%` `%count%` |
| `remove-prompt`, `removed` | Removing a grave. | `%player%` |
| `no-graves` | `/gravesadmin restore` on a player with none. | `%player%` |
| `reloaded` | `/gravesadmin reload`. | |

`%items%` is always a number of stacks, and `%experience%` a number of points.

</Details>

## Menus

`/graves` is a menu you can restyle; the staff screens belong to the plugin. All of them are under
`lang/<code>/menus/`:

| File | Opened by | Edits |
|---|---|---|
| `user/graves.yml` | `/graves` | Yours. A release only adds what is missing, unless it raises `menu-version`, which replaces the file and keeps your previous one next to it. |
| `admin/graves.yml` | `/gravesadmin list <player>` | Replaced from the jar on every start and every menu reload. |
| `admin/players.yml` | `/gravesadmin` | Replaced the same way. The online players and the Settings card. |
| `admin/settings*.yml` | The Settings card | Replaced on every start (marked "do not edit"). |

Copy an admin file under another name if you want to keep a restyle. A menu file that fails to parse is
named in the console and that screen does not open; fix it and `/gravesadmin reload`.

`/graves` can also open as a full screen with a cursor for players on the SCREEN menu style: the layout
is `screens/graves.html`, its words are `lang/<code>/screens/graves.yml`, and your own CSS goes in
`screens/custom.css`, which updates never touch. See [Screens](/docs/exylialib/screens).

<Details title="Menu layout, values and actions">

The `/graves` menu has 54 slots, with the graves in slots `10-16`, `19-25`, `28-34` and `37-43`
(28 per page), previous and next page at `48` and `50`, and the header at `49`. The staff screens put
graves (or players) in slots `0-35` instead, with the same page buttons and header, and one button at
slot `45`: Restore all on the graves screen, the Settings card on the players screen.

| Where | Values |
|---|---|
| The screen | `%owner_name%`, `%graves%` (how many) |
| Each grave | `%grave_id%`, `%grave_owner%`, `%grave_items%`, `%grave_experience%`, `%grave_server%`, `%grave_world%`, `%grave_x%`, `%grave_y%`, `%grave_z%`, `%grave_age%`, `%grave_time_left%`, `%grave_protection%`, `%grave_actions%` |

The staff graves screen also has `%owner_id%`. `%grave_age%`, `%grave_time_left%` and `%grave_protection%`
keep ticking while the screen is open. `%grave_actions%` is the click hints this viewer may use, from the
`menu-…` messages, each on its own line.

The grave buttons call these actions. Each one checks again, on the click, against the grave as it is
stored.

| Action | What it does |
|---|---|
| `exyliagraves:teleport <id>` | Teleports to the grave: the owner under the teleport rules, staff with `exyliagraves.admin.view` to any. |
| `exyliagraves:preview <id>` | Opens the preview. |
| `exyliagraves:restore <id>` | Hands it back after a confirmation. Needs `exyliagraves.admin.restore`. |
| `exyliagraves:remove <id>` | Removes it after a confirmation. Needs `exyliagraves.admin.remove`. |
| `exyliagraves:restore_all <owner id> <name>` | Hands back every grave of that player, after a confirmation. Needs `exyliagraves.admin.restore`. |

The Settings screens use `exyliagraves:settings`, `settings_hub`, `settings_page` and `setting`
(all need `exyliagraves.admin`), the players hub `admin_players`, and `admin_graves` opens a player's
graves for staff.

</Details>

## Database

| Table | Holds |
|---|---|
| `sc_graves` | One row per grave standing, on every server. See [Network](/docs/exyliagraves/network#the-database). |

Contents waiting for a player's join are kept in ExyliaLib's pending rewards, and notices waiting for a
join in ExyliaLib's `exylia_notices`, in the same database. See [Database](/docs/exylialib/database).
