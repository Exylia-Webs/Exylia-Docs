---
title: "Vincular un servidor"
description: "Del código en la consola al servidor enviando datos a tu espacio de trabajo: entrar, espacios de trabajo, el código de vinculación, y mover o retirar un servidor."
---

Un servidor está **vinculado** cuando tiene un token de un espacio de trabajo. El agente nunca pide una
contraseña ni una clave de API: muestra un código corto, un miembro del espacio de trabajo lo aprueba en
el navegador y el agente recoge su token por su cuenta.

## Antes del primer servidor

<Steps>
  <Step title="Entra">
    Abre [analytics.exylia.net](https://analytics.exylia.net) y continúa con Discord. El panel lee tu
    nombre y tu avatar de Discord, nada más.
  </Step>
  <Step title="Crea un espacio de trabajo">
    Un espacio de trabajo es una red: su proxy, lobbies y servidores de juego, las personas que pueden
    verlos y sus ajustes. Dale un nombre (de 2 a 48 caracteres); la zona horaria y la moneda se eligen
    después en **Ajustes**. Si te invitaron a un espacio que ya existe, abre la invitación en su lugar.
  </Step>
</Steps>

Hasta que un servidor envíe datos, el Resumen del espacio muestra estos mismos pasos como lista.

## Vincular

<Steps>
  <Step title="Arranca el servidor">
    Un agente sin vincular pide un código en cuanto arranca, y lo muestra:

    ```text
    [ExyliaAnalytics] Link this server at https://analytics.exylia.net/link — code K7QM-2XPA (expires in 10 min)
    ```

    `/analytics link` (en Velocity `/analyticsv link`) pide uno nuevo en cualquier momento, y lo muestra
    a quien ejecutó el comando además de en la consola.
  </Step>
  <Step title="Introduce el código">
    Ve a `analytics.exylia.net/link`, o **Servidores → Vincular un servidor**. Escribe el código, elige
    el espacio de trabajo y, si quieres, un nombre para el servidor.
  </Step>
  <Step title="Espera unos segundos">
    El agente pregunta cada cinco segundos si su código se aprobó. Cuando lo está, guarda su token,
    descarga los ajustes del espacio, muestra *"Linked to the workspace …"* y empieza a enviar. El
    servidor aparece en la página **Servidores** como **En espera** hasta su primer latido, y después
    **En línea**.
  </Step>
</Steps>

| Sobre el código | |
|---|---|
| Forma | Ocho caracteres como `XXXX-XXXX`. Se omiten los que se confunden: nunca `0`, `O`, `1`, `I` ni `L`. |
| Duración | Diez minutos. Al caducar, la consola dice *"The link code expired"*; reinicia o ejecuta el comando de vinculación para obtener otro. |
| Uso | Una vez. Un código usado, caducado o inexistente se rechaza con el mismo mensaje. |
| Quién lo aprueba | Un miembro cuyo rol tenga **Vincular, renombrar, desactivar y revocar servidores** (`manage_servers`). La página de vinculación solo ofrece esos espacios. |
| Nombre | Hasta 40 caracteres, y se puede cambiar después. Si se deja vacío, un servidor Paper se llama como la carpeta en la que se ejecuta y un proxy se llama `proxy`. |

Si no se puede llegar al ingest, el agente lo dice una vez (*"Could not reach Exylia Analytics; retrying
in the background"*) y sigue preguntando, esperando más cada vez hasta cinco minutos.

<Callout type="note" title="Un panel puede limitar los servidores por espacio">
Los operadores del panel pueden limitar cuántos servidores vincula un espacio de trabajo. Pasado ese
límite la página de vinculación responde *"Este workspace puede vincular N servidores. Revoca uno para
vincular otro"*. Los servidores revocados no cuentan.
</Callout>

## Una red

Vincula el proxy y cada backend al mismo espacio de trabajo, cada uno con su propio código. Después
confirma el **mapeo del proxy** en la página Servidores, para que el panel sepa qué entrada de la lista
de servidores del proxy es cada backend: ver
[Servidores y rendimiento](/docs/exyliaanalytics/servidores#mapeo-del-proxy).

## Después de vincular

- **Ajustes → Agente** decide qué recoge cada servidor y cada cuánto. El agente aplica los cambios sin
  reiniciar. Ver [Configuración remota](/docs/exyliaanalytics/configuracion-remota).
- `/analytics status` muestra el estado, el espacio de trabajo, el papel, lo pendiente de enviar y cómo
  fue el último envío. Ver [Comandos y permisos](/docs/exyliaanalytics/comandos).

## Mover o retirar un servidor

| Para | Haz |
|---|---|
| Que un servidor deje de recoger un tiempo | **Servidores → Pausar**. El agente deja de recoger y de enviar. Ver [Servidores](/docs/exyliaanalytics/servidores#pausar-y-reanudar). |
| Retirar un servidor para siempre | **Servidores → Revocar**. Su token deja de funcionar en 30 segundos y el agente vuelve a estar sin vincular. Lo que ya envió se queda. |
| Mover un servidor a otro espacio de trabajo | Revócalo en el espacio antiguo, después `/analytics link` en el servidor y aprueba el código en el nuevo. |
| Desvincular desde el servidor | `/analytics unlink`. El agente olvida su token y descarta lo que aún no había enviado. El token en sí sigue funcionando hasta que revoques el servidor en el panel. |

Volver a vincular siempre crea un servidor **nuevo** en el panel. El historial del anterior se queda en
su entrada antigua.
