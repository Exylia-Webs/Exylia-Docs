El agente tiene un único archivo local, `config.yml`, y es corto a propósito: solo guarda lo que un
servidor tiene que decidir **antes** de poder llegar al panel. Cada cuánto enviar, qué recoger y si
recoger o no se ajusta por espacio de trabajo en el panel — ver
[Configuración remota](/docs/exyliaanalytics/configuracion-remota).

## `config.yml`

Se escribe en el primer arranque en `plugins/ExyliaAnalytics/` (Velocity: `plugins/exyliaanalytics/`):

```yaml
# Exylia Analytics — https://analytics.exylia.net
# Almost everything is configured from the dashboard; this file only holds
# what the server must decide before it can reach it.

mode: auto

placeholders: []

vault-wrapper: true

debug: false
```

| Clave | Por defecto | Plataformas | Qué hace |
|---|---|---|---|
| `mode` | `auto` | Paper, Spigot | El papel del servidor: `auto`, `backend` o `standalone`. `auto` lo detecta (ver [Instalación](/docs/exyliaanalytics/instalacion#el-papel-del-servidor)); cualquier otro valor se trata como `auto`. Un proxy es siempre `proxy`, diga lo que diga. **Necesita reiniciar.** |
| `placeholders` | `[]` | Paper, Spigot | Placeholders de PlaceholderAPI cuyos valores se envían cada vez que un jugador sale de este servidor. Hasta 16; los demás se ignoran, y uno repetido cuenta una vez. Con o sin los signos `%`. |
| `vault-wrapper` | `true` | Paper, Spigot | Si el agente se pone delante de las economías de Vault y VaultUnlocked para ver qué plugin crea o destruye dinero. Cada llamada pasa intacta. Desactívalo si un plugin de economía se porta mal con él. Ver [Economía](/docs/exyliaanalytics/economia#el-proxy-de-vault). Se lee cuando se registra una economía, así que en la práctica **necesita reiniciar**. |
| `debug` | `false` | Todas | Registra cada petición al ingest (`[debug] POST /v1/events … -> 200`) y cada evento personalizado descartado por romper los límites. |

`placeholders` se escribe como lista o en línea:

```yaml
placeholders:
  - '%vault_eco_balance%'
  - '%statistic_mob_kills%'
```

```yaml
placeholders: [vault_eco_balance, statistic_mob_kills]
```

<Callout type="note" title="Un lector sencillo, no una librería de YAML">
El archivo se lee línea a línea, así que el agente no necesita la librería de YAML de ninguna plataforma.
Deja cada clave en su propia línea en el nivel superior, como arriba. Las comillas son opcionales, lo que
va tras `#` es un comentario y las claves desconocidas se ignoran.
</Callout>

`/analytics reload` vuelve a leer el archivo: la lista de placeholders y `debug` se aplican al momento,
`mode` y `vault-wrapper` tras reiniciar. También hace que el agente vuelva a descargar los ajustes del
panel.

## La carpeta data

Nada de `data/` está pensado para editarse a mano.

| Ruta | Contenido |
|---|---|
| `data/credentials.json` | El token del servidor, sus ids de servidor y de espacio de trabajo, y el nombre del espacio. Se escribe al aprobar una vinculación y se borra con `/analytics unlink` y cuando se revoca el token. |
| `data/remote-config.json` | Los últimos ajustes que envió el panel. Se usan al arrancar hasta que llegan otros; una copia ilegible se ignora con un aviso. |
| `data/spool/*.json.gz` | Lotes pendientes de entrega, del más antiguo al más nuevo por nombre. Límite de 50 MiB. |

## `loader.yml`

Lo escribe el loader, no el agente: guarda tu clave de licencia. El agente no arranca hasta que la clave
está puesta.
