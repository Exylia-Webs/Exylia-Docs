Cada integración es opcional y se busca al arrancar el agente. Un plugin que no está instalado no cuesta
nada, y ninguno es necesario para que el agente funcione. Cada uno informa a través de un evento genérico,
así que a los gráficos del panel les da igual qué plugin los alimentó.

| Plugin | Paper / Spigot | Velocity | Aporta | Módulo |
|---|---|---|---|---|
| LiteBans | ✓ | ✓ | Sanciones impuestas y levantadas | Sanciones |
| LibertyBans | ✓ | ✓ | Sanciones impuestas y levantadas | Sanciones |
| AdvancedBan | ✓ | — | Sanciones impuestas y levantadas | Sanciones |
| NuVotifier | ✓ (también el Votifier clásico) | ✓ | Votos | Votos |
| LuckPerms | ✓ | ✓ | Cambios de rango, y el grupo con el que empieza una sesión | Rangos, Sesiones |
| PlaceholderAPI | ✓ | — | Valores de los placeholders que indiques | Placeholders |
| ViaVersion | ✓ | — | La versión real del cliente en un servidor independiente | Sesiones |
| Floodgate | ✓ | ✓ | Jugadores de Bedrock, incluidas las cuentas vinculadas | Sesiones |
| ExyliaLib | ✓ | — | Cambios de saldo y lo que se tiene en cada moneda de ExyliaLib | Economía |

## Sanciones

LiteBans, LibertyBans y AdvancedBan informan de cada sanción cuando se **impone** y cuando se **levanta**:
el jugador, el tipo (baneo, muteo, expulsión, aviso), quién la puso, el motivo, la duración y si es un
baneo de IP, además del id de entrada del propio plugin.

- **¿En el proxy y en los backends a la vez?** Los dos envían la misma entrada; el panel cuenta el id de
  cada plugin una vez.
- **La consola** se envía como ningún miembro del staff, y aparece como **Consola**.
- **Las sanciones solo de dirección** — un baneo de IP que no nombra a ningún jugador — no las envía
  ninguno de los tres.
- **LibertyBans** da un baneo de IP sobre un jugador (una víctima compuesta) como ese jugador, marcado como
  baneo de IP.
- **AdvancedBan** solo se lee en Paper y Spigot. Sus eventos no dicen quién levantó una sanción, así que un
  levantamiento nunca tiene miembro del staff, y nombra al staff por su nombre: un miembro del staff que
  está desconectado cuando se dispara queda registrado como la consola. Las notas no son sanciones y no se
  envían. Los tipos temporales cuentan como su tipo base (un baneo temporal es un baneo).

## Votos

El evento de voto de NuVotifier, en el lado que lo ejecute: el proxy o un servidor. Cada voto lleva el
nombre de la web tal como lo da Votifier y el nombre de usuario. El UUID del jugador se añade cuando está
conectado en el lado que recibió el voto; si no, el voto se guarda solo con el nombre. Los votos aparecen
en Adquisición y en la cronología de un jugador.

## LuckPerms

- **El grupo con el que empieza una sesión.** Cada `session.start` lleva el **grupo principal** de
  LuckPerms del jugador en ese momento. La página Rangos lo usa para repartir a los jugadores activos por
  rango.
- **Cambios de rango.** El agente compara los grupos de un jugador antes y después de cada cambio, así que
  `parent set` (vaciar y añadir) sale como una concesión y una retirada, y renovar un grupo temporal cuenta
  como una concesión nueva. El mismo grupo en varios contextos cuenta una vez, con su caducidad más tardía.
- Un cambio se envía donde se hizo — el proxy o el servidor donde se ejecutó el comando —, así que una red
  lo envía una vez.
- Un grupo temporal que caduca solo no se envía.

## PlaceholderAPI

Solo Paper y Spigot. Ver [Placeholders](/docs/exyliaanalytics/comunidad#placeholders) para cómo
indicarlos y cómo los dibuja el panel.

## ViaVersion

En un servidor Paper independiente, ViaVersion deja entrar clientes de otras versiones, y Paper da entonces
su propia versión para todos. Cuando ViaVersion está instalado el agente le pregunta la versión real de
cada jugador. En una red la versión la envía el proxy, así que ViaVersion en un backend no cambia nada.

## Floodgate

Cuando la API de Floodgate está presente, el agente le pregunta si cada jugador está en Bedrock. Sin ella,
un jugador de Bedrock sin vincular se sigue reconociendo por su UUID (`00000000-0000-0000-…`); un jugador de
Bedrock vinculado a una cuenta Java conserva el UUID de Java, y solo Floodgate puede reconocerlo.

## Anticheats

Solo en Paper y Spigot. Los avisos se suman por jugador, anticheat y check en un `anticheat.flag` por
minuto, con el nivel de violación más alto de ese minuto.

| Anticheat | Check | Tipo | Nivel de violación |
|---|---|---|---|
| Vulcan | El nombre visible (`Reach`) | La letra (`A`) | El VL del check |
| Grim (2.3.71+) | El nombre del check | — | Las violaciones del check |
| Matrix | El tipo de hack (`KILLAURA`) | — | El VL de Matrix para ese tipo de hack |
| Spartan | El tipo de hack (`KillAura`) | — | El nivel de violación, cuando la versión aún lo da |
| Intave | El nombre del check | — | El VL tras el aviso |
| LightAntiCheat | El nombre del check | — | — |

<Callout type="warning" title="La API de Vulcan">
Vulcan solo lanza sus eventos con `settings.enable-api: true` en su propio `config.yml`. Si está apagada,
el agente avisa en consola, porque no puede enviar ninguno de sus avisos.
</Callout>

Polar y Themis no están enganchados.

## Vínculos de Discord

En Paper y Spigot, la cuenta de Discord vinculada a cada jugador se lee de **DiscordSRV**
(`/discord link`) o de **EssentialsX Discord Link** (`/link`), el que esté instalado, y se envía como
`player.discord` (id, nombre y avatar), para que el panel la muestre en la página del jugador y permita
buscar por ella. Se lee fuera del hilo principal al entrar y al salir, y solo se envía un cambio. El proxy
no envía ninguna: ambos plugins se ejecutan en los backends.
