In a few minutes you can make the dashboard show punishments, votes, rank changes, Bedrock players, anticheat flags and
linked Discord accounts, just by having the right plugin installed next to ExyliaAnalytics. There is nothing to
configure in the agent: it looks for each supported plugin when it starts.

Every integration is optional. A plugin that is not installed costs nothing, and none is needed for the agent to run.
Each one reports into a generic event, so the dashboard's charts do not care which plugin fed them.

## Before you start

- ExyliaAnalytics installed and linked, see [Install the plugin](/docs/exyliaanalytics/installation) and
  [Connect your server](/docs/exyliaanalytics/linking).
- The plugin you want to read from, installed on the **same server** that runs the agent (the proxy for punishments of
  a network, a game server for anticheats and economy). The table below says where each one works.
- The module for it switched on under **Settings**, **What the plugin collects**. The modules are on by default; see
  [Remote configuration](/docs/exyliaanalytics/remote-config).

## Steps

<Steps>
  <Step title="Pick what you want to see">
    Find your plugin in the table below. Check that its platform column matches where you run it. A cross (—) means the
    agent does not read it on that platform.
  </Step>
  <Step title="Install it and restart">
    Install the plugin on that server as usual and restart the server. The agent looks for supported plugins on start,
    so a plugin added while the server runs is picked up on the next restart.
  </Step>
  <Step title="Check the agent saw it">
    Run `/analytics status` on a Paper or Spigot server, or `/analyticsv status` on Velocity. Economy plugins are
    listed there; for the others, read the module row below.
  </Step>
  <Step title="Make something happen">
    Issue a test punishment, cast a vote, change a group, or trigger a check, depending on the plugin. Data is sent
    in batches, so give it about a minute.
  </Step>
</Steps>

## Check that it works

Open the page the module feeds: a new punishment under **Moderation** and **Punishments**, a vote under **Player
sources** and in the player's timeline, a rank change under **Ranks**, an anticheat flag under **Anticheat**, the Discord
name on the player's page. If nothing shows after a few minutes, see
[Common problems](/docs/exyliaanalytics/troubleshooting).

## Going further

| LibertyBans | ✓ | ✓ | Punishments issued and lifted | Punishments |
| AdvancedBan | ✓ | — | Punishments issued and lifted | Punishments |
| NuVotifier | ✓ (classic Votifier too) | ✓ | Votes | Votes |
| LuckPerms | ✓ | ✓ | Rank changes, and the group a session starts with | Ranks, Sessions |

| Floodgate | ✓ | ✓ | Bedrock players, including linked accounts | Sessions |

### Punishments

LiteBans, LibertyBans and AdvancedBan all report each punishment as it is **issued** and as it is **lifted**: the
player, the kind (ban, mute, kick, warn), who did it, the reason, the duration and whether it is an IP ban, plus the
plugin's own entry id. The console shows as **Console**.

<Details title="Punishment edge cases">

- **Run on the proxy and the backends at once?** Both report the same entry; the dashboard counts each plugin's id
  once.
- **The console** is reported as no staff member, and shows as **Console**.
- **Address-only punishments**, an IP ban that names no player, are not reported by any of the three.
- **LibertyBans** gives an IP ban on a player (a composite victim) as that player, marked as an IP ban.
- **AdvancedBan** is read on Paper and Spigot only. Its events do not say who lifted a punishment, so a revoke never
  has a staff member, and it names staff by name: a staff member who is offline when it fires is recorded as the
  console. Notes are not punishments and are not reported. Temporary kinds count as their base kind (a temp-ban is a
  ban).

</Details>

### Votes

NuVotifier's vote event, on whichever side runs it: the proxy or a server. Each vote carries the site name as Votifier
reports it and the username. The player's UUID is attached when they are online on the side that received the vote;
otherwise the vote is kept with the name alone. Votes appear under **Player sources** and in a player's timeline.

### LuckPerms

- **The group a session starts with.** Every `session.start` carries the player's LuckPerms **primary group** at that
  moment. The **Ranks** page uses it to split active players by rank.
- **Rank changes.** The agent compares a player's groups before and after every change, so `parent set` (a clear and
  an add) comes out as one add and one removal, and renewing a temporary group counts as a new add. The same group
  held in several contexts counts once, with its latest expiry.
- A change is reported where it was made, the proxy or the server where the command ran, so a network reports it
  once.
- A temporary group that expires on its own is not reported.

### PlaceholderAPI

Paper and Spigot only. See [Placeholders](/docs/exyliaanalytics/community#placeholders) for how to list them and how
the dashboard charts them.

### ViaVersion

On a standalone Paper server, ViaVersion lets in clients of other versions, and Paper then reports its own version for
all of them. When ViaVersion is installed the agent asks it for each player's real version instead. On a network the
proxy reports the version, so ViaVersion on a backend changes nothing.

### Floodgate

When the Floodgate API is present, the agent asks it whether each player is on Bedrock. Without it, an unlinked
Bedrock player is still recognised by their UUID (`00000000-0000-0000-…`); a Bedrock player linked to a Java account
keeps the Java UUID, and only Floodgate can recognise them.

### Anticheats

Paper and Spigot only. Flags are summed per player, anticheat and check into one `anticheat.flag` a minute, with the
highest violation level of that minute.

| Anticheat | Check | Type | Violation level |
|---|---|---|---|
| Vulcan | The display name (`Reach`) | The letter (`A`) | The check's VL |
| Grim (2.3.71+) | The check name | — | The check's violations |
| Matrix | The hack type (`KILLAURA`) | — | Matrix's VL for that hack type |
| Spartan | The hack type (`KillAura`) | — | The violation level, when the build still reports it |
| Intave | The check name | — | The VL after the flag |
| LightAntiCheat | The check name | — | — |

<Callout type="warning" title="Vulcan's API">
Vulcan fires its events only with `settings.enable-api: true` in its own `config.yml`. When it is off the agent logs a
warning, because none of its flags can be reported.
</Callout>

Polar and Themis are not hooked.

### Discord links

On Paper and Spigot, the Discord account linked to each player is read from **DiscordSRV** (`/discord link`) or
**EssentialsX Discord Link** (`/link`), whichever is installed, and sent as `player.discord` (id, name and avatar), so
the dashboard shows it on the player's page and finds players by it. It is read off the main thread on join and on
quit, and only a change is sent. The proxy sends none: both plugins run on the backends.
