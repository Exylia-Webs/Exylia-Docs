The agent has one command, with a different name on each platform so the proxy's never hides the
backends':

| Platform | Command |
|---|---|
| Paper, Spigot, Folia | `/analytics` |
| Velocity | `/analyticsv` |

Both take the same subcommands and tab-complete them.

## Subcommands

| Command | What it does |
|---|---|
| `/analytics` or `/analytics status` | Prints the agent's state. Any unknown subcommand prints it too. |
| `/analytics link` | Asks for a link code and shows it to you and in the console. Refused, with the workspace's name, when the server is already linked. See [Linking a server](/docs/exyliaanalytics/linking). |
| `/analytics unlink` | Forgets the token: deletes `data/credentials.json`, the queue and the spool. Nothing more is sent. The token keeps working until the server is revoked in the dashboard. |
| `/analytics reload` | Re-reads `config.yml` and fetches the dashboard's settings again. Mode changes still need a restart. |

## The status readout

```text
EXYLIA ANALYTICS v1.1.0
 ▎ State » Active
 ▎ Workspace » ExyliaMC
 ▎ Mode » standalone
 ▎ Waiting » 12 events · 0 batches
 ▎ Last send » ok at 18:42:07
 ▎ Economy » ExyliaLib, PlayerPoints
```

| Line | Values |
|---|---|
| State | **Active**; **Not linked** — run the link command; **Waiting** — another server holds this token; **Disabled from the dashboard** — the server is paused. |
| Workspace | The workspace it is linked to. Absent when not linked. |
| Mode | `proxy`, `backend` or `standalone`. |
| Waiting | Events in memory and batches in the spool, not yet delivered. |
| Last send | `ok at` a time; `retrying in Ns:` and why; `paused: workspace suspended or over quota`; `waiting: another server holds this token`; `not linked`; or `nothing sent yet`. |
| Economy | Paper and Spigot. The economy sources hooked: ExyliaLib (or *ExyliaLib (flows only)* when it is too old to count holdings), Vault, VaultUnlocked, PlayerPoints, ExcellentEconomy — or *no sources*. |
| Vault, VaultUnlocked | Paper and Spigot, when that economy is installed: *watching* the plugin behind it, or why it is not watched (off in `config.yml`, ExyliaSurvivalCore reports through ExyliaLib, or the economy holds the highest priority). |

## Permission

| Permission | Default | Grants |
|---|---|---|
| `exyliaanalytics.admin` | op | Every subcommand of `/analytics` and `/analyticsv`. |

On Velocity nobody but the console has it until a permissions plugin such as LuckPerms grants it.

## Console messages worth knowing

| Message | Meaning |
|---|---|
| `Link this server at https://analytics.exylia.net/link — code …` | Not linked; enter the code. |
| `The link code expired. Run /analytics link for a new one.` | The ten minutes ran out. |
| `Linked to the workspace ….` | The code was approved. |
| `Could not reach Exylia Analytics (…); events are kept and retried.` | The ingest is unreachable. Logged once per outage. |
| `This server's token was revoked. Run /analytics link to link it again.` | Revoked in the dashboard. |
| `The workspace is suspended or over its plan quota; events are kept and retried every 15 minutes.` | The workspace is suspended. |
| `Another running server holds this token (a copied plugin folder?)…` | Two processes share one token. See [Installation](/docs/exyliaanalytics/installation#copying-a-server-folder). |
| `The spool is full (50 MiB); dropped the N oldest batch(es).` | The ingest has been unreachable for a long time. |
| `The installed loader is outdated: the economy API is disabled until it is updated.` | Replace the loader jar. Custom events keep working. |
| `More than 100000 events are waiting; new events are dropped until the queue drains.` | Something floods the agent faster than it can send. |
