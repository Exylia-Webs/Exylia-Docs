Los jugadores pueden usar ExyliaSandBox sin configurar nada: todas las funciones de jugador están permitidas por defecto y solo los admins tienen `/sandboxadmin`. Usa esta página para restringir cosas o para dar más a los rangos.

## Convierte una función en ventaja de rango

Un comando y el botón de menú que hace lo mismo comprueban el mismo permiso. Para convertir una función en ventaja, niégala al grupo por defecto y dásela al rango. Con LuckPerms:

```text
/lp group default permission set exyliasandbox.command.rtpqueuefast false
/lp group vip permission set exyliasandbox.command.rtpqueuefast true
```

Un jugador sin el permiso recibe el mensaje `general.no-permission` de `messages.yml`. Salir de un sandbox, salir de una cola, rechazar una petición de teletransporte y `/kitsave` nunca necesitan permiso, así que un jugador siempre puede echarse atrás.

## Ranuras de kit por rango

Todos los jugadores tienen una ranura de kit. Un rango tiene más con `exyliasandbox.max_kits.<n>`, donde `<n>` es el número de ranuras:

```text
/lp group vip permission set exyliasandbox.max_kits.3 true
/lp group mvp permission set exyliasandbox.max_kits.5 true
```

Si un jugador tiene varios, cuenta el más alto, así que `.3` y `.5` juntos dan cinco. Da uno por grupo para que sea fácil de leer.

## Enfriamiento de `/rekit` más corto

Todos esperan 30 segundos entre dos usos de `/rekit` (`rekit.cooldown-seconds` en `config.yml`). Da a un rango `exyliasandbox.rekit.cooldown.<segundos>` para acortarlo; si un jugador tiene varios, gana el más bajo:

```text
/lp group vip permission set exyliasandbox.rekit.cooldown.10 true
```

<Callout type="note" title="Dos permisos se mantienen solo por configuraciones antiguas">
`exyliasandbox.command.leavesandbox` y `exyliasandbox.command.leavertpqueue` siguen declarados para que los archivos de permisos existentes carguen, pero ya no los comprueba nada.
</Callout>
