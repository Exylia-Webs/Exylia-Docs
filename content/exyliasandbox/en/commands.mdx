## Reload

`/sandboxadmin reload` re-reads the config files and rebuilds the menus. Worlds, kits, TP regions and stats live in the database and need no reload. It also works from the console.

Exporting and importing the plugin's data is not a command of ExyliaSandBox: use ExyliaLib's `/exylialib export` and `/exylialib import`. See [ExyliaLib commands](/docs/exylialib/commands).

## The command whitelist

While a player is inside a sandbox world or waiting in a queue, only the commands listed in `config.yml` under `command-whitelist.commands` work. Anything else is refused with the `general.command-blocked` message. Players with `exyliasandbox.bypass.blocked-commands` skip the list.

To allow one more command, add its name (without the slash) to that list and run `/sandboxadmin reload`. A `plugin:` prefix is ignored, so `minecraft:tp` is blocked exactly like `tp`.

<Callout type="note" title="`/predefinedkits` is not on the list">
The shipped list does not include `predefinedkits`, `predefinedkit` or `pkits`, so they are blocked inside a sandbox. Players copy templates in the lobby, so this is usually fine. Add them if you want the command reachable from inside.
</Callout>

<Details title="The shipped list">
```yaml
command-whitelist:
  enabled: true
  commands:
    - msg
    - message
    - tell
    - w
    - whisper
    - reply
    - r
    - respond
    - sandbox
    - rtp
    - rtpqueue
    - rtpqueuefast
    - back
    - tpa
    - tpaccept
    - tpdeny
    - rekit
    - leavesandbox
    - leavertpqueue
    - kitcreator
    - kitsave
    - kitroom
    - bot
    - leave
```

Set `enabled: false` to turn the whitelist off for everyone. Matching is on the first word, lowercased. Note that the list contains `sandbox` but not `sandboxadmin`: admins with the bypass permission are not affected.
</Details>
