title: "The admin panel"
description: "`/sandboxadmin` screen by screen: worlds, gamerules, players, teleport pads, predefined kits, the kit room, settings and the lobby."
---

`/sandboxadmin` opens everything an administrator owns. It needs `exyliasandbox.admin`, and every button
behind it re-checks that node, so a player who somehow reaches a screen still cannot press anything.

## The hub

| Button | Opens |
|---|---|
| **MANAGE WORLDS** | The world list, with the world count and the players inside them |
| **KIT ROOM** | ExyliaLib's kit-room editor |
| **PREDEFINED KITS** | The admin kit templates |
| **TP REGIONS** | The teleport pads |
| **SET LOBBY** | Starts a wizard that stores a spawn as the lobby |
| **SET KIT CREATOR** | Starts a wizard that stores a spawn as the kit-creator room |
| **Settings** | The few `config.yml` values worth changing in game |
| **RELOAD CONFIGS** | Re-reads the config files and recompiles the menus |

**SET LOBBY** and **SET KIT CREATOR** do not save your position on the click. Each starts an ExyliaLib
wizard (`LOBBY SPAWN`, `KIT CREATOR SPAWN`, both texts in `messages.yml` → `lobby`): walk to the spot,
sneak-click to confirm it with the way you face, or cancel to return to the panel. **RELOAD CONFIGS**
acts on the spot, with no confirmation.

## Settings

**Settings** opens a hub with two pages. Each card shows the value and its default; clicking edits it
(numbers and times are typed, shift-right-click resets it).

| Page | Values |
|---|---|
| Teleports | `tpa.request-timeout-seconds`, `rtp.search-attempts` |
| Rules | `rekit.cooldown-seconds`, `command-whitelist.enabled` and the `command-whitelist.commands` list |

Everything else in `config.yml` stays in the file.

## Worlds

The world list pages through every configured world. Each row shows its id, whether it is managed or
imported, its status, the players inside, its biome and its border radius; a `READY` world glows.

| Click | What it does |
|---|---|
| Left | Opens the world screen |
| Right | Teleports you into that world, without claiming a session |

**CREATE WORLD** and **IMPORT WORLD** each start a short chat wizard and end on the world screen with
nothing yet written. **Reset to Defaults** puts the five shipped worlds back, through a confirmation.

### The world screen

Everything here edits a draft. Nothing reaches the database until **SAVE WORLD**; the back button
discards it.

| Button | What it does |
|---|---|
| **ICON** | Opens an icon picker |
| **NAME** | Chat prompt for the display name |
| **BIOME** | Chat prompt for a biome id. `N/A` on an imported world |
| **GENERATION** | Cycles the five presets. `N/A` on an imported world |
| **BORDER** | Left +500, right −500 with a floor of 100, shift-left types a number. It is the diameter |
| **GAMERULES** | The thirteen toggles and the difficulty |
| **TELEPORT** | Sends you into the world |
| **PLAYERS** | The players inside it |
| **SAVE WORLD** | Writes the row, creates the folder and queues the pre-generation |
| The last slot | Deletes the world, through a confirmation. A world that has never been saved shows a grey pane instead |

The border shown next to a world is its **radius**; the button edits the diameter.

### Gamerules

Thirteen toggles, each drawn `ENABLED` or `DISABLED`, plus a difficulty that cycles
`PEACEFUL → EASY → NORMAL → HARD`. The full list and what each maps to is on the
[Worlds](/docs/exyliasandbox/worlds#gamerules-and-difficulty) page.

### Players

One head per player in the world, showing their game mode, health, level and coordinates. Clicking one
teleports you to them.

## Teleport pads

The pad list, the pad editor and their two delete buttons are covered on the
[Teleport pads](/docs/exyliasandbox/tp-regions) page. Deleting a pad from either place asks you to confirm first.

## Predefined kits

The template list, its create button and the per-kit editor are covered on the
[Kits](/docs/exyliasandbox/kits#predefined-kits) page. `/sandboxadmin predefinedkits` opens the list
directly.

## The kit room

**KIT ROOM** opens ExyliaLib's own editor for the shelf; it is covered on the
[Kit room](/docs/exyliasandbox/kit-room#editing-it) page.

## Reloading

**RELOAD CONFIGS**, and `/sandboxadmin reload` from the console, both re-read `config.yml`, `messages.yml`
and `scoreboards.yml` and recompile the menus. Worlds, kits, pads and statistics are not touched: they
live in the database and are read when they change.

<Callout type="note" title="The admin screens are rewritten on every start">
Everything under `lang/<language>/menus/admin/` is refreshed from the jar each time the plugin enables, and each of
those files says so at the top. Edit `menus/user/` freely; edits under `menus/admin/` are undone by the
next restart.
</Callout>
