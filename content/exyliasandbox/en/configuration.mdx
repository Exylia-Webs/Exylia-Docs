---

Three files are generated on the first run. None of them exists inside the jar: they are written from
the plugin's own schema, comments included, which is why an unknown key is reported once and then
removed from the file. `config.yml` sits in `plugins/ExyliaSandBox/`; the text a player reads sits in
the language folder, `plugins/ExyliaSandBox/lang/<language>/`, next to the menus.

| File | What is in it |
|---|---|
| `config.yml` | The language, RTP and queue numbers, the TPA timeout, the rekit cooldown, the pad hologram's settings, the command whitelist |
| `lang/<language>/messages.yml` | Every line the plugin sends, the queue action bars, the pad visuals and every label the screens draw |
| `lang/<language>/scoreboards.yml` | The one sidebar |

Everything else — worlds, kits, templates, kit-room categories, teleport pads, the lobby and the
kit-creator room — lives in the database and is edited from `/sandbox`.

## `config.yml`

### `language`

```yaml
language: default
```

Which folder under `plugins/ExyliaSandBox/lang/` the menus, messages and sidebar are read from.
`default` follows the `language` set in ExyliaLib's own `config.yml`, so one line there switches every
Exylia plugin; `en`, `es`, `pt`, `fr` or `ru` set this plugin alone. Each language is a complete
folder you can edit. A changed `language` takes effect on `/sandbox reload`.

<Callout type="note" title="Servers that ran 1.0.x keep their edits">
On the first start of 1.1.0 the existing `messages.yml`, `scoreboards.yml` and `menus/` are adopted as
`lang/custom/`, and `config.yml` is pointed at it with `language: custom`, so nothing a server edited is
lost. The player-facing blocks that used to be in `config.yml` — the two queue action bars, the pad's
boss bar, title and hologram lines, and the kit-creator titles — move into that `messages.yml`. Set
`language` to `default` or a code to switch to the shipped translations.
</Callout>

### `rtp`

| Key | Default | What it does |
|---|---|---|
| `queue-pair-distance` | `10` | Blocks between the two players a queue pair drops in |
| `search-attempts` | `50` | Random spots tried before giving up on a safe location |
| `border-margin` | `20` | Blocks kept clear of the border, subtracted from the **radius** |
| `rotative-queue-actionbar-time` | `2.0` | Seconds each waiting player is advertised for |

The two queue action bars are text, so they live in `messages.yml` under `queue`.

```yaml title="plugins/ExyliaSandBox/config.yml"
rtp:
  queue-pair-distance: 10
  search-attempts: 50
  border-margin: 20
  rotative-queue-actionbar-time: 2.0
```

### `tpa`

| Key | Default | What it does |
|---|---|---|
| `request-timeout-seconds` | `60` | How long a `/tpa` request lives |

### `rekit`

| Key | Default | What it does |
|---|---|---|
| `cooldown-seconds` | `30` | Seconds a player waits between two `/rekit` uses |

### `tp-region`

`hologram` — scale, billboard, alignment, view distance, offsets, and a `config.update-interval` that
is a **tick** count. Its lines, the boss bar and the countdown title are text, so they live in
`messages.yml` under `tp-region`; all of them are covered on the
[Teleport pads](/docs/exyliasandbox/tp-regions#the-visuals) page.

### `command-whitelist`

`enabled` and a list of command names. See [Commands](/docs/exyliasandbox/commands#the-command-whitelist).

## `messages.yml`

`lang/<language>/messages.yml`: one `prefix` and fifteen sections. Every line takes `%prefix%`, and most
take one or two of `%world%`, `%player%`, `%region%`, `%name%`, `%slot%`, `%max%` and `%percent%`.

| Section | Covers |
|---|---|
| `world` | Created, saved, deleted, imported, not found |
| `queue` | Joining, leaving, pairing, teleporting, no kit, no safe location, the join broadcast, and the two action bars `in-queue-actionbar` and `rotative-queue-actionbar` |
| `tpa` | Sent, received, accepted, denied, expired, and the refusals. `received` is a list: the centred request with clickable **ACCEPT** and **DECLINE** buttons |
| `back` | No location, teleporting |
| `lobby` | Lobby set, kit-creator room set, not set |
| `kitroom` | No space, and the category create, delete and icon lines |
| `kit-creator` | Entering, saving, renaming, deleting, the icon, the slot limit, and three title blocks |
| `predefined-kit` | Saving, renaming, deleting, copying, the two refusals and the invalid slot |
| `rekit` | Applied, no kit, not in a world, and `cooldown` with `%time%` |
| `tp-region` | No favourite kit, teleported, the wand, the create, save and delete lines, and the pad's `bossbar`, `countdown-title` and `hologram-lines` |
| `general` | Not available, command blocked, `in-combat` |
| `screens` | Every label the screens draw: the `PREGEN %percent%` label, the world statuses, the favourite toggle's `Active` / `Inactive`, the five preset names, the enabled and disabled states, and the `N/A` the queue placeholder shows while nobody waits |
| `prompts` | What a player is asked to type or pick: names, icons, the biome, the border, the pad interval |
| `wizards` | The world creation and import wizards |
| `confirm` | The four confirmation screens, a title and two lines each |

`queue.in-queue-actionbar` and `queue.rotative-queue-actionbar` are effect blocks. Their `text` takes
`%world%`, `%time%` and, on the rotative one, `%player%`. A `duration` of `0` means the bar stays until
the queue tick replaces or stops it.

A line may open with an effect tag such as `[sound:ENTITY_VILLAGER_NO|1.0|1.0]`, several separated by
`;`. The tag is an instruction and never reaches the screen. Colours are palette tokens — `{primary}`,
`{success}`, `{error}`, `{warning}`, `{info}`, `{highlight}`, `{muted}`, `{letters}`, `{accent}`,
`{secondary}` — resolved from ExyliaLib's shared `colors.yml`.

`back.outside-world`, `queue.select-kit` and the three `kit-creator` title blocks are generated into the
file but never sent: the kit creator's prompts come from `prompts`.

## `scoreboards.yml`

One board, `sandbox`, shown to anybody standing in a sandbox world. `title` is a list: several entries
animate one per refresh, one entry stands still. At most fifteen lines are drawn.

```yaml title="plugins/ExyliaSandBox/lang/en/scoreboards.yml"
scoreboards:
  sandbox:
    enabled: true
    title: ["{primary}&lSANDBOX"]
    lines:
      - ""
      - " {muted}❙ {letters}World: {highlight}%world%"
      - " {muted}❙ {letters}Players: {success}%players%"
      - ""
      - " {muted}❙ {letters}Kills: {success}%kills%"
      - " {muted}❙ {letters}Deaths: {error}%deaths%"
      - " {muted}❙ {letters}KDR: {highlight}%kdr%"
      - " {muted}❙ {letters}Playtime: {info}%sandbox_playtime%"
      - ""
      - " {muted}❙ {letters}Border: {info}%border%"
      - ""
      - " {highlight}{server-ip}"
    update:
      interval: 10
      smart: true
      cache: true
```

`{server-ip}` is the address from ExyliaLib's shared `colors.yml`, next to the palette. `update.interval` is in **ticks**, not seconds. `smart` sends only the lines that changed. The names
available inside those lines are on the
[Placeholders](/docs/exyliasandbox/placeholders#the-sidebar-names-are-different) page.

## Reloading

`/sandbox reload`, and **RELOAD CONFIGS** in the admin panel, re-read all three files, from the language
now named, and recompile the menus. The database is not touched.
