By the end of this page winners get a prize, other players get a smaller one, and you know what happens to a player who disconnects before it arrives.

## Before you start

- An event configuration exists. See [Your first event](/docs/exyliaevents/first-steps).
- You have `exyliaevents.admin`. See [Permissions](/docs/exyliaevents/permissions).

## Steps

<Steps>
  <Step title="Open the event">
    Run `/eventsadmin`, click **Configurations**, open the category and click your event. The setup screen opens.
  </Step>
  <Step title="Set the winner prize">
    Click **Winner rewards**. Add what the winner receives: items, commands, money, experience, messages or potion effects, with optional odds. The editor is ExyliaLib's reward editor, described in [Rewards](/docs/exylialib/rewards).
  </Step>
  <Step title="Set the participant prize">
    Click **Participant rewards** and add what everyone else who played receives.
  </Step>
  <Step title="Reward 2nd place and below (optional)">
    Click **Place rewards**, then a place (`#2` to `#10`) and add its prize. A place you leave empty pays the participant rewards instead.
  </Step>
</Steps>

Prizes are handed over a moment after the event ends, so items land after the player is back in the lobby and not in an inventory that is about to be cleared.

## Check that it works

Run `/eventsadmin forcestart <id>`, join with a second account and finish the game. The winner receives the winner rewards and the other player the participant rewards. If nothing arrives, see [Common problems](/docs/exyliaevents/troubleshooting).

## Going further

### Reward the same thing in every event

`config.yml` carries console commands run for every event, whichever configuration it is. Edit them in `/eventsadmin`, **Settings**, **Rewards** (**Winner commands**, **Player commands**) or in the file:

```yaml title="config.yml"
reward-commands:
  only-on-random-events: false
  participant:
    - "console: give %player% coal 1"
  winner:
    - "console: give %player% diamond 1"
```

Both layers run for the same event: a configuration with its own rewards and global commands pays both. Use the global commands for server-wide prizes (a crate key for every winner) and the configuration's lists for prizes that differ per event or contain exact items.

<Callout type="tip" title="Do not pay for staff tests">
Turn on **Random only** (`only-on-random-events`) and the global commands pay only for events the scheduler started. Prizes in a configuration's own lists are not affected by it. See [Game flow](/docs/exyliaevents/game-flow#automatic-events).
</Callout>

### Which games have places

Only games that rank players behind the winner show **Place rewards**. Team games (a winning team, nothing else to rank) and the role games Hide and Seek, Block Morph Hunt, King Kong, Infection and Murder Mystery do not: their players are paid as winners or participants. Nobody places when an event is stopped or has no winner.

### Boost the prizes

Prizes go through ExyliaLib's [modifiers](/docs/exylialib/economy#modifiers) under the source `events`: money lines are boosted as `money`, experience as `xp` and items as `drops`; commands are paid as written. A boost can cover every event or one type through the scope `event:<type>`, such as `event:koth`. The permission `exylia.modifier.money.events.2` doubles money from every event prize. The global reward commands are never boosted.

### Players who are offline

If a player is offline when prizes are handed out, their configuration rewards are queued and delivered when they next join, with the boost they earned. `/exylialib pendingrewards` lists what is still owed across every plugin; each batch is named after its event, with `(winner)` when the player won, and staff can hand it over or cancel it. It needs `exylialib.pendingrewards`.

<Details title="Technical details">

| Key (`config.yml`) | Default | What it does |
|---|---|---|
| `reward-commands.only-on-random-events` | `false` | When `true`, the global commands only run for events the scheduler started. |
| `reward-commands.participant` | one example | Commands run for each participant. `%player%` is the player. |
| `reward-commands.winner` | one example | Commands run for each winner. |

- Who gets what: a winner gets the winner rewards; anyone else who played gets their place's rewards (places 2 to 10) when that place has any, otherwise the participant rewards.
- Offline prizes are stored in the table `event_pending_rewards` with the event name and whether the player won.
- Reward lines can use `%player%` and the event's name; the full list of reward types and their fields is in ExyliaLib's [Rewards](/docs/exylialib/rewards).
</Details>
