Every command and the permission it needs. Event ids, arena ids and player names complete as you type. Players use `/events` (aliases `/event` and `/ev`); staff use `/eventsadmin`.

<Commands />

## Start an event

`/events start <config>` is the start a rank can have. A player who runs it joins the event at once, is subject to the start cooldown and the per-player limit, and picks a kit from a menu when the configuration has two or more kits. The console skips all of that and, with two or more kits, starts with no kit. See [Game flow](/docs/exyliaevents/game-flow#limits) and [Teams, kits and loot](/docs/exyliaevents/teams-and-kits#kits).

`/eventsadmin forcestart <event>` starts an event ignoring the usual gate. Use it to test an arena.

The host of an event can run `/events hold` while it is joinable to keep the countdown from starting, and `/events begin` to release it.

## Play from a pool of arenas

`/events play` takes an event type or a comma-separated list of arena ids, mixed freely. `/events play pillarsoffortune` stands for every Pillars of Fortune arena and `/events play pillars_1,pillars_2` for those two. The player joins the open game of that pool with the most players, on this server or another one of the [network](/docs/exyliaevents/network), so games fill before new ones open. With no game open, it starts a random free arena of the pool.

That start has no host: it needs no `exyliaevents.start` and no cooldown applies. An arena whose sign-up list is open only takes the players on it. Bind it to a short alias, such as `/pillars`.

## Reload, export and import

`/eventsadmin reload` reloads the configuration files and menus, the event configurations, both schedulers and the sidebars of running events, and reports each step. It does not reopen the database: changing `database.yml` needs a restart.

`/eventsadmin export` writes every table into `plugins/ExyliaEvents/dumps/`. `/eventsadmin import <file>` reads one of those files back.

Every `/eventsadmin` subcommand except the bare `/eventsadmin` also runs from the console.

## Settings in game

**Settings** on the `/eventsadmin` panel opens ExyliaLib's settings menus over the plugin's files, so every value in `config.yml` and the other files can be changed in game as well as in YAML. It needs `exyliaevents.admin`, and **Back** returns to the panel.

## Reset player data

ExyliaEvents has no reset command of its own. Use ExyliaLib's `/exylialib wipe` and `/exylialib resetplayer`: see [ExyliaLib commands](/docs/exylialib/commands).
