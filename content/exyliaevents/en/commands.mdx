## Player

| Command | Aliases | Permission |
|---|---|---|
| `/events` | `/event`, `/ev` | `exyliaevents.commands.events` |
| `/events join [eventId]` | | `exyliaevents.commands.join`; with no id, also `exyliaevents.join.random` |
| `/events play <type\|arenas>` | | `exyliaevents.commands.play` |
| `/events list` | | `exyliaevents.commands.list` |
| `/events leave` | | None: leaving is never checked |
| `/events start <configId>` | | `exyliaevents.start` or `exyliaevents.start.<configId>` |
| `/events hold` | | Only for the player who started the event, while it is joinable. Keeps the countdown from starting until they say so. |
| `/events begin` | | Releases a held start; the countdown begins as soon as enough players are in. |
| `/events stats` | | `exyliaevents.commands.stats` |
| `/events stats <player>` | | `exyliaevents.commands.stats.others` |
| `/events music` | | `exyliaevents.commands.music` |

`/events start` is the player-facing start: it is what makes an event something a rank can open,
subject to the limits and cooldowns in [Game flow](/docs/exyliaevents/game-flow#limits).

Run in game and from the console, `/events start <configId>` opens the same configuration, but not
the same way. A player who starts it joins it at once, is subject to the start cooldown and the
per-player limit, and, when the configuration has two or more kits, picks the kit from a menu before
the event opens. The console skips all of that and, with two or more kits, starts with no kit. See
[Teams, kits and loot · Kits](/docs/exyliaevents/teams-and-kits#kits).

`/events join` with no id puts the player in a random open event, which, like the random-join button
in the menu, also needs `exyliaevents.join.random`.

`/events list` opens the menu of events running right now, where a player picks one to join. A server
running the same game in several arenas shows one row per game first, with its arenas behind it.

## Playing from a pool of arenas

`/events play` takes an event type or a comma-separated list of arena ids, mixed freely:
`/events play pillarsoffortune` stands for every Pillars of Fortune arena, and
`/events play pillars_1,pillars_2` for those two. It puts the player in the open game of that pool
with the most players, on this server or another backend of the [network](/docs/exyliaevents/network),
so games fill before new ones open. With no game open, it starts a random free arena of the pool and
puts the player in it.

That start is the scheduler's kind of start, with no player as its host: it needs no
`exyliaevents.start` and no start cooldown applies. An arena whose sign-up list is open only takes the
players on it. Built to sit behind a short alias, such as `/pillars`.

## Administration

Everything under `/eventsadmin` needs `exyliaevents.admin`.

| Command | What it does |
|---|---|
| `/eventsadmin` | Opens the admin panel. Left-clicking a running event in its list opens that event's screen: its state, its participants (revive or add a player there), force start, force join all, and stop. |
| `/eventsadmin reload` | Reloads the configuration files. |
| `/eventsadmin network` | Checks the [network](/docs/exyliaevents/network#checking-the-network): this server's name, whether network events are on, which servers answer, and how many arenas belong to other servers. |
| `/eventsadmin forcestart <eventId>` | Starts an event, ignoring the usual gate. |
| `/eventsadmin forcejoin <player> <eventId>` | Puts a player into an event. |
| `/eventsadmin forcejoinall <eventId>` | Puts every online player into an event, reporting how many joined and how many were skipped. Players in a world listed in `world-restrictions.force-join-all-skip-worlds`, and those the access rules refuse, are left alone. |
| `/eventsadmin forcestop <eventId>` | Stops and removes a running event. |
| `/eventsadmin revive <eventId> <player>` | Brings an eliminated player back into a running event. |
| `/eventsadmin gauntlet start <series>` | Starts a saved series with every free player online. |
| `/eventsadmin gauntlet stop` | Cuts the running series short, along with the stage it is playing. |
| `/eventsadmin access ...` | Who may join: private mode, whitelist, blacklist and blocked ranks, per configuration or `global`. See [Sign-ups · Access rules](/docs/exyliaevents/inscriptions#access-rules). |
| `/eventsadmin export` | Dumps every table into `dumps/`. |
| `/eventsadmin import <filename>` | Reads a dump back. |

Every subcommand but the bare `/eventsadmin` also runs from the console, `forcestop` included.

Series of events are put together in the menus and covered in
[Gauntlets](/docs/exyliaevents/gauntlets).

Sign-up and access commands live under `/eventsadmin inscriptions` and `/eventsadmin access` and need their own node; the same lists are
managed from **Inscriptions** on each configuration's setup screen — see
[Sign-ups](/docs/exyliaevents/inscriptions).

### Settings in game

**Settings** (the comparator) on the `/eventsadmin` panel opens ExyliaLib's settings menus over the
plugin's files, so every value in `config.yml` and the other files can be changed in game as well as
in YAML. It needs `exyliaevents.admin`, and **Back** returns to the panel.

### Wiping and resetting data

The plugin has no reset command of its own. ExyliaLib's `/exylialib wipe ExyliaEvents <table|*> [code]`
and `/exylialib resetplayer <player> [ExyliaEvents|all] [@kind ...] [code]` cover its tables: statistics
and owed rewards are progress, the music preference is account data, sign-up lists are world data,
and configurations, kits, gauntlets and settings rows are setup, which a player reset never touches.
A reset player's counters and preferences are also dropped from memory at once. See
[ExyliaLib · Commands](/docs/exylialib/commands).

## Permissions

Every node below is declared in `plugin.yml`. Player features default to everyone, so a server makes
one a rank perk by denying it to the default group and granting it to the rank:
`exyliaevents.spectate: false` there, `true` for VIP.

| Permission | Default | Description |
|---|---|---|
| `exyliaevents.commands.events` | everyone | `/events`, the events menu. |
| `exyliaevents.commands.join` | everyone | `/events join` and joining from a menu. |
| `exyliaevents.join.random` | everyone | Joining a random open event: `/events join` with no id, or the menu button. |
| `exyliaevents.commands.play` | everyone | `/events play`. |
| `exyliaevents.commands.list` | everyone | `/events list`, browsing the running events. |
| `exyliaevents.commands.leave` | everyone | Kept for compatibility: leaving an event is never checked. |
| `exyliaevents.commands.music` | everyone | `/events music`. |
| `exyliaevents.commands.stats` | everyone | Your own statistics. |
| `exyliaevents.spectate` | everyone | Watching an event that is already being played. |
| `exyliaevents.team.choose` | everyone | Picking a team in team events. |
| `exyliaevents.start` | op | `/events start`, the gauntlet builder in the menus, and the start actions, for every configuration. |
| `exyliaevents.start.<configId>` | — | The same, for that one configuration only. |
| `exyliaevents.commands.stats.others` | op | `/events stats <player>`. |
| `exyliaevents.cooldown.bypass` | op | Start events with no cooldown. |
| `exyliaevents.world.bypass` | op | Join events from a world the world rules would refuse. |
| `exyliaevents.bypass.blocked-commands` | op | Run commands the whitelist would block inside an event. |
| `exyliaevents.admin` | op | The whole `/eventsadmin` command, the setup menus, the settings and every admin menu action. |
| `exyliaevents.admin.inscriptions` | op | The sign-up and access subcommands and screens. |

### Per-rank numbers

| Pattern | What it sets |
|---|---|
| `exyliaevents.cooldown.<seconds>` | The start cooldown, such as `exyliaevents.cooldown.60`. The lowest wins, together with any match in `start-cooldown-permissions`; without one, `start-cooldown` applies. |
| `exyliaevents.max-events.<n>` | Events one player may have started at once. The highest wins and `0` is unlimited; without one, `max-events-per-player` applies. |
| `exyliaevents.cooldown.<name>` | Any other node you list in `start-cooldown-permissions` as `permission:seconds`. |

See [Game flow · Limits](/docs/exyliaevents/game-flow#limits).

<Callout type="warning" title="exyliaevents.start is not exyliaevents.admin">
`start` lets a player open an event from the menu, which is usually a rank perk. `admin` lets them
create, edit and delete configurations. Do not merge them.
</Callout>

A rank that should only host some events gets `exyliaevents.start.<configId>` for each of them instead
of `exyliaevents.start`. The start menu and tab completion then offer that player only those
configurations, `/events start` refuses the rest, and the gauntlet builder only starts a series whose
every stage they may host.

<Callout type="tip" title="Rank perks">
Every player node is granted to everyone out of the box. To make one a perk, such as spectating or
choosing a team, deny it to the default group and grant it to the rank.
</Callout>

## What reload covers

`/eventsadmin reload` runs four steps and reports on each: the configuration files and menus, the
event configurations, both schedulers, and the sidebars of every running event. A step that fails is
named rather than swallowed.

An edited prefix applies without a restart, and a running event picks up an edited sidebar in place.

It does not reopen the database connection: changing `database.yml` needs a restart.
