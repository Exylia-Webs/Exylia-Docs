Instala ExyliaEvents junto a ExyliaLib, arranca el servidor una vez y define el lobby al que vuelven los jugadores. Después ya puedes [crear tu primer evento](/docs/exyliaevents/primeros-pasos).

## Antes de empezar

Necesitas Paper 1.21.1 o superior, o Folia 1.21.4 o superior, con Java 21. ExyliaLib debe estar en `plugins/` **antes** del primer arranque: aporta la configuración, la base de datos, los menús, hologramas, scoreboards, placeholders, recompensas y esquemáticas.

Todo lo demás es opcional y solo añade algo:

- **packetevents**: los efectos de cliente dibujados con paquetes. Sin él el plugin funciona y solo esos extras quedan desactivados.
- **FastAsyncWorldEdit**: guarda, restaura y clona las esquemáticas de arena si está instalado. Sin él, el motor propio de ExyliaLib hace lo mismo con los mismos archivos `.schem`.
- **PlaceholderAPI**: leer los contadores del plugin desde fuera. Ver [Placeholders](/docs/exyliaevents/placeholders).
- **ExyliaProxyUtils**: solo para una red, para mover al jugador al servidor donde está el evento. Ver [Red](/docs/exyliaevents/red).
- **Worlds**: es como se crea el mundo temporal donde van las copias de arena **en Folia**. Fuera de Folia el plugin lo crea con Bukkit y no hace falta.
- **ExyliaPracticeCore**, **ExyliaFFA**, **ExyliaSandBox**: un jugador ocupado en uno de ellos no puede ser metido en un evento, y al revés. ExyliaPracticeCore además presta sus kits a cualquier evento y sus arenas a Brackets, Sumo y Tournament: ver [Equipos, kits y loot · Kits de PracticeCore](/docs/exyliaevents/equipos-y-kits#kits-de-practicecore).
- **AuraSkills**, **mcMMO**: quedan en pausa durante los eventos salvo que una arena los permita, con el [flag de arena](/docs/exyliaevents/arenas#flags-de-la-arena) `skills`.
- **ViaVersion**, **WorldGuard**, **TAB**, **floodgate**, **Apollo**, **Feather**: declaraciones de orden de carga para servidores que los usen.

## Pasos

<Steps>
  <Step title="Coloca los jars">
    Pon `ExyliaEvents.jar` y ExyliaLib en `plugins/`.
  </Step>
  <Step title="Arranca el servidor">
    El primer arranque escribe los archivos de configuración y crea las tablas de la base de datos.
  </Step>
  <Step title="Define el lobby principal">
    Ejecuta `/eventsadmin` y define el lobby al que vuelven los jugadores al salir de un evento.
  </Step>
  <Step title="Crea tu primer evento">
    Sigue [Tu primer evento](/docs/exyliaevents/primeros-pasos).
  </Step>
</Steps>

## Comprueba que funciona

Tras el primer arranque, `plugins/ExyliaEvents/` contiene `config.yml` y una carpeta `lang/<code>/`, y la consola no muestra errores de ExyliaEvents. `/eventsadmin` abre el panel de administración a quien tenga el permiso de admin (ver [Permisos](/docs/exyliaevents/permisos)). Si no se abre, mira [Problemas comunes](/docs/exyliaevents/problemas-comunes).

## Ir más lejos

### Guardar los datos en MySQL u otra base de datos

Por defecto se usa H2, embebido. Para compartir configuraciones y estadísticas entre servidores, apunta `database.yml` a una base de datos real:

```yaml title="plugins/ExyliaEvents/database.yml"
database:
  type: mysql
  mysql:
    host: 127.0.0.1
    port: 3306
    database: minecraft
    username: root
    password: ""
```

Motores: `h2`, `mysql`, `mariadb`, `postgresql`, `mongodb`. Las opciones comunes están en [Base de datos](/docs/exylialib/base-de-datos).

<Callout type="warning" title="Las esquemáticas son de cada servidor">
Las configuraciones viajan por la base de datos, pero los archivos `.schem` viven en el disco de cada servidor. Un segundo servidor leyendo la misma base de datos sigue necesitando esos archivos para restaurar o clonar una arena.
</Callout>

### Copia de seguridad y mover tus eventos

`/eventsadmin export` vuelca todas las tablas en `plugins/ExyliaEvents/dumps/` e informa de cuántas filas escribió. `/eventsadmin import <archivo>` lee uno de esos archivos desde la misma carpeta. Hazlo antes de un cambio arriesgado en producción; también es la forma de mover un conjunto de configuraciones entre motores.

### Actualizar

Reemplaza el jar y reinicia. `config.yml` está versionado y migra solo: ver [Configuración · Migraciones](/docs/exyliaevents/configuracion#migraciones).

<Details title="Archivos generados y tablas">

En `plugins/ExyliaEvents/`:

| Archivo | Contenido |
|---|---|
| `config.yml` | Idioma, límites, cooldowns, temporizadores, lista blanca de comandos, reglas de mundo, eventos aleatorios, música. |
| `lang/<code>/messages.yml` | Todos los mensajes, con una sección por tipo de evento, boss bars y títulos incluidos. |
| `lang/<code>/scoreboards.yml` | Un sidebar por tipo de evento, más el del lobby. |
| `lang/<code>/buildbattle-themes.yml` | Los temas que se votan en Build Battle. |
| `lang/<code>/trivia-questions.yml` | Las preguntas de Trivia. |
| `lang/<code>/menus/` | Diseño de los menús: panel de administración, una pantalla de ajustes por tipo, y los menús de jugador. |

`<code>` es el idioma en el que corre el plugin: `en`, `es`, `pt`, `fr`, `tr` o `ru`, o el idioma de ExyliaLib mientras `config.yml` diga `language: default`. Ver [Configuración · language](/docs/exyliaevents/configuracion#language).

Tablas:

| Tabla | Contiene |
|---|---|
| `event_configurations` | Los eventos configurados, con sus ajustes, recompensas y tablas de loot. |
| `events_player_stats` | Estadísticas globales de jugador. |
| `events_player_event_stats` | Estadísticas por jugador y arena. |
| `events_player_type_stats` | Estadísticas por jugador y minijuego, sumando todas sus arenas. |
| `events_player_preferences` | Preferencias por jugador, hoy el interruptor de música. |
| `events_settings` | La fila única de ajustes que escribió una versión anterior, leída una vez y adoptada. |
| `events_server_settings` | Ajustes por backend, hoy la ubicación del lobby principal de cada servidor. |
| `event_kits` | Kits de una configuración, y sus enlaces a kits de PracticeCore. |
| `event_gauntlets` | Series de gauntlet guardadas. |
| `event_inscriptions` | Listas de inscripción. |
| `event_pending_rewards` | Recompensas pendientes de jugadores desconectados. |

</Details>
