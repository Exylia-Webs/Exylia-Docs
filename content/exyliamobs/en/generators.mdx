You end up with an area that keeps a number of your mobs alive while somebody is near. Nobody near, nothing spawns; mobs already out stay.

## Before you start

Create at least one mob. See [Create a mob](/docs/exyliamobs/building-mobs).

## Steps

<Steps>
  <Step title="Create the generator">
    Run `/mobsadmin`, click **Generators**, then **Create generator**. Type an id of up to 64 characters, unique across the network, for example `crypt`.
  </Step>
  <Step title="Select the area">
    Click **Area** and left-click. ExyliaLib's shared selector gives you the wand: mark two corners. The box between them, floor to ceiling, is the area. See [Walking somebody through a setup](/docs/exylialib/input-and-editors#walking-somebody-through-a-setup).
  </Step>
  <Step title="Give it mobs">
    Click **Mobs**, add mobs from the ones that exist and click one to set its weight.
  </Step>
  <Step title="Tune the numbers">
    **Max alive**, **Per wave**, **Interval**, **Activation** and **Per player**. A new generator is already enabled.
  </Step>
</Steps>

## Check that it works

Walk close to the area. After one interval, mobs appear on the ground inside it. The list shows **No area** until the area is set, **No mobs** until it has one, then **Enabled** or **Disabled**.

If nothing appears, see [Common problems](/docs/exyliamobs/troubleshooting#a-generator-spawns-nothing).

## The generator list

| Click | What it does |
|---|---|
| Left-click | Opens its screen. |
| Shift-click | Teleports you there. |
| Right-click | Deletes it after a confirmation. Its live mobs are removed. |

## The generator screen

Edits apply on the next pass of the generator timer.

| Button | Default | What it sets |
|---|---|---|
| **Status** | Enabled | Toggles it. A disabled generator spawns nothing; its live mobs stay. |
| **Area** | none | Left-click selects it again, right-click teleports you there. |
| **Activation** | 24 blocks | How close a player has to be, `0` to `256`. `0` means inside the area. Distance is to the nearest block of the area; spectators do not count. |
| **Per player** | 0 | Each player near beyond the first adds this many to the max alive and to each wave, `0` to `100`. |
| **Mobs** | none | Which mobs it spawns, each with a weight. |
| **Max alive** | 6 | It stops spawning once this many of its mobs are alive, `1` to `500`. |
| **Interval** | 20 seconds | How often a wave spawns, typed like `10s`, `30s` or `1m`. At least one second. |
| **Per wave** | 2 | How many appear in each wave, up to the max alive, `1` to `100`. |
| **Remove its mobs** | | Removes the mobs it keeps alive. It refills on its next wave. |
| **Delete** | | Deletes it after a confirmation and removes its live mobs. |

### Weights

A mob's chance per spawn is its weight over the total, shown in its lore. A weight of `0` never spawns it, and a list where every weight is `0` spawns nothing. A deleted mob is skipped.

## WorldGuard

A spawn the server cancels is nearly always WorldGuard: with `mobs.block-plugin-spawning` on (its default), the `mob-spawning` and `deny-spawn` flags cancel plugin spawns too. ExyliaMobs leaves that to the region owner and says so in the console, once per generator. Allow spawning in that region, or set `mobs.block-plugin-spawning: false` in WorldGuard's world config.

## On a network

| What | How |
|---|---|
| Mobs | Shared. Every server spawns from the same mobs. |
| Generators | Each belongs to the server it was created on and only that server runs it. Its id is still unique across the network. |
| Changes | With Redis on, a mob or generator saved on one server is read again on the others at once. Without Redis, other servers pick it up on their next restart; `/mobsadmin reload` does not read them again. See [Redis](/docs/exylialib/database#redis). |

<Details title="Technical details">
Every 2 seconds by default (`tick-seconds`) one timer walks this server's generators. One spawns when it is enabled, has an area, its interval has passed and a player is within its activation radius. With N players near, the room is max alive plus (N − 1) times per player, less its mobs already alive. The wave is per wave plus the same extra, cut to that room and to what is left of the server-wide cap (`max-alive` in `config.yml`, 200 by default, all generators together; mobs spawned by hand do not count). For each mob it picks one by weight and a random column of the area. The spot is the highest solid floor in that column inside the area's height with two open, dry blocks above. A column in an unloaded chunk or with no such floor is retried up to four times, then skipped until the next wave. Generators never load a chunk, and each spawn runs on the thread that owns its spot, so it works on Folia.
</Details>
