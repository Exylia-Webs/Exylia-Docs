You end up with a menu drawn as panels standing in the world in front of the player, opened by a command. It needs a **Java 1.21.4 or newer** client, so give it a chest [fallback](/docs/exyliascreens/opening-and-fallbacks) for everyone else.

## Before you start

The layout (panels, grids, lists, carousels, theme) is ExyliaLib's spatial format, see [ExyliaLib: Menus](/docs/exylialib/menus). ExyliaScreens adds a `menu` block that holds what the menu contains. The first load writes every layout key the file left out, with comments. Write a [chest menu](/docs/exyliascreens/chest-menus) first if you want a fallback.

## Steps

<Steps>
  <Step title="Create the file">
    Make `plugins/ExyliaScreens/spatial/warps3d.yml`. The file name is its id.
  </Step>
  <Step title="Write the layout and the menu block">
    ```yaml
    title: "{primary}&lWARPS"
    panels:
      warps:
        at: [0, 0, 0]
        size: [3.6, 1.5]
        title: "{secondary}&lWHERE TO?"
        content: {type: GRID, source: warps, columns: 4, rows: 2}
        footers:
          - {label: "{success}Shop", action: shop}
          - {label: "{error}Leave", action: leave}   # leave closes it
    preview: {visible: false}
    carousel: {source: ""}
    menu:
      command: warps3d
      fallback: hub_chest
      lists:
        warps:                                       # what source reads
          entries:
            spawn:
              priority: 1
              if: "perm('warp.spawn')"
              material: COMPASS
              name: "{info}Spawn"
              subtitle: "{letters_black}Safe zone"
              require: "balance() >= 10"
              deny: ["[MESSAGE] {error}You need 10 coins."]
              click: ["[MONEY] take 10", "[CLOSE]", "[PLAYER] spawn"]
      buttons:
        shop: ["[SCREEN] shop"]                      # what action reads
    ```
  </Step>
  <Step title="Save and check">
    It loads within two seconds. Run `/screensadmin check`: it says when a panel reads a list that `menu.lists` does not have, and when an entry's expression does not read.
  </Step>
</Steps>

## Check that it works

Run `/warps3d` on a 1.21.4 or newer Java client. The panels stand in front of you; look at an entry and click it, or sneak to leave. On an older client or Bedrock you get `hub_chest` instead. A 3D entry has one click, so `right:` filters never run.

<Details title="The menu block">

| Key | Does |
|---|---|
| `command`, `aliases`, `permission`, `require`, `deny`, `fallback`, `min-client`, `args`, `on-open` | The opening keys, here under `menu:`. See [Open a menu and set its fallback](/docs/exyliascreens/opening-and-fallbacks). |
| `lists.<name>.entries` | The entries a panel's `source: <name>` reads. Each takes the keys of a chest slot (`priority`, `if`, `material`, `name`, `require`, `deny`, `click`) and a `subtitle`. |
| `buttons.<name>` | The interaction lines a panel's `action: <name>` runs. |

The shipped example is `spatial/warps_3d.yml`, opened with `/warps3d`; a client that cannot draw it gets `hub_chest`. Panels, anchor, `freeze` and `hide-others` are ExyliaLib's spatial layout.

</Details>
