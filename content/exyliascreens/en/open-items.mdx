You end up with a lobby compass (or a profile head) in the hotbar that opens a menu when used. Players cannot drop, move, place or lose it on death; it comes back on join, respawn and world change, and is taken away when the file no longer names it. A slot already holding something of the player's is left alone.

## Before you start

Have the menu it opens (a screen, chest or 3D menu: its id is the file name). See [Opening and fallbacks](/docs/exyliascreens/opening-and-fallbacks).

## Steps

<Steps>
  <Step title="Add the item to open-items.yml">
    ```yaml
    items:
      hub:
        menu: hub
        slot: 4                  # 0-8 the hotbar
        material: COMPASS
        name: "{info}Navigator"
        permission: ""           # '' for everybody
        worlds: [lobby]          # empty for every world
    ```
  </Step>
  <Step title="Limit who gets it (optional)">
    `permission` hands it to players who hold that permission; `worlds` limits it to the named worlds.
  </Step>
</Steps>

## Check that it works

Save the file (it reloads within 2 seconds) and rejoin or change world: the compass is in slot 4 and using it opens `hub`. `/screensadmin check` lists entries with a bad slot, a missing menu, or a menu that does not exist.

<Details title="Every key of an open item">

| Key | Does |
|---|---|
| `menu` | The id of the menu it opens, of any form. Required. |
| `slot` | 0 to 35: 0-8 is the hotbar, 9-35 the rest of the inventory. Required. |
| `permission` | Who gets the item; empty for everybody. |
| `worlds` | The worlds it is given in; empty for all. |
| `enabled` | `false` skips the entry. |

Every key of a menu item works too (`playerhead-`, `nexo:`, `custom-model-data`, `name`, `lore`, `glow`...).

</Details>

The file can also be edited in the browser through ExyliaLib's [web editor](/docs/exylialib/web-editor), which refuses a version with problems.
