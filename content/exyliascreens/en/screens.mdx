You end up with a menu that fills the player's screen, has a mouse cursor and opens with a command. It is one HTML file in `plugins/ExyliaScreens/screens/`; no Java and no resource pack.

## Before you start

- The player needs a **Java client on 1.20.2 or newer**, and the server needs PacketEvents (ExyliaLib installs and checks it). Bedrock players and older clients cannot draw screens, so give the screen a [fallback](/docs/exyliascreens/opening-and-fallbacks) written as a [chest menu](/docs/exyliascreens/chest-menus).
- The markup, the CSS subset, components and pictures belong to ExyliaLib, see [ExyliaLib: Screens](/docs/exylialib/screens) and [Screen markup](/docs/exylialib/screen-markup). This page covers what a server owner needs to build menus.

## Steps

<Steps>
  <Step title="Create the file">
    Make `plugins/ExyliaScreens/screens/rules.html`. The file name is the screen's id.
  </Step>
  <Step title="Write the screen">
    ```html
    <screen command="rules" aliases="r">
      <panel>
        <h1>{primary}Rules</h1>
        <p>Be kind. No cheating. Have fun.</p>
        <button action="close">Got it</button>
      </panel>
    </screen>
    ```
  </Step>
  <Step title="Save it">
    A saved, added or removed file is read again within two seconds. You do not need `/screensadmin reload`.
  </Step>
  <Step title="Look for mistakes">
    Run `/screensadmin check`. It lists anything the file does not understand, with the line and column.
  </Step>
</Steps>

## Check that it works

Type `/rules` (or `/r`) in game. The panel opens in front of you with a cursor; click **Got it** to close it. Sneaking closes any screen too, and so do the `close` and `back` actions. If it says the menu does not work on your client, see [Common problems](/docs/exyliascreens/troubleshooting).

## What a screen is made of

**Tags.** The ones you will use most (ExyliaLib has the full list):

- Boxes: `panel` (a themed column), `column`, `row`, `box`.
- Text: `h1`, `h2`, `b`, `small`, `p`, `span`, `text`.
- Clickable: `button`, and `card`, usually a cell of a grid.
- Choices: `tabs`/`tab` and `chips`/`chip` set a state value on click.
- Repeaters: `grid`, `list`, `pager` repeat children over a source, with pages.
- Pictures: `item` draws a real item model without a resource pack (`material`, `head`, `texture` or `url`); `img` draws a file from the screen's folder, or a player with `skin="%player_name%"` or `face="%player_name%"`.
- Others: `toggle`, `progress`, `modal`, `search`.

Any tag takes `id`, `class`, `style`, `if`/`else`, `action`, `action-right`, `action-shift`, `require`/`deny`, `cooldown` and `t="key"`. `%placeholders%` and `${expressions}` work in any text. Write colours as palette tokens such as `{primary}` so `colors.yml` recolours everything, see [ExyliaLib: Colours](/docs/exylialib/colours).

**State.** A screen remembers small values while it is open: `set tab food`, `toggle open` and `clear tab` change them, and you read them as `%tab%` or `tab` in expressions. `<tabs state="tab" default="play">` and `<chips>` set one on click. `open shop tab=food` opens another screen with its state already set.

**Look at what exists.** Six example screens ship with the plugin, see [Start from the example screens](/docs/exyliascreens/examples). `/exylialib screens gallery` shows every element in game.

## Stand a screen in the world

A screen can also stand in the world for everyone, drawn as packets (nothing is saved in the world's blocks). Run `/screensadmin world place <screen> [width]` as a player: a wizard asks you to walk to the spot and sneak-click. The width is in blocks (3 by default, from 0.5 to 32) and the height follows the screen's size. `/screensadmin world move <id>` moves one, `/screensadmin world remove <id>` removes it and `/screensadmin world list` lists them.

They are saved in `world-screens.yml` (`screen`, `world`, `x`, `y`, `z`, `yaw`, `width` and `range`, the blocks within which players see it, 32 by default). Hand-editing is possible: `yaw` is the way its front faces (0 south, 90 west, 180 north, -90 east).

<Details title="The screen element: every attribute">

| Attribute | Does |
|---|---|
| `command`, `aliases` | The commands that open it, installed on load and on `/screensadmin reload`. Aliases are separated by spaces. |
| `permission` | Who may open it. Without it, everybody. |
| `require`, `deny` | An [expression](/docs/exyliascreens/actions-and-requirements#requirements) checked before opening, and the lines run when it fails. Without `deny` the player gets the "You cannot open this screen" message. |
| `fallback`, `min-client`, `args`, `on-open` | See [Open a menu and set its fallback](/docs/exyliascreens/opening-and-fallbacks). |
| `form` | `board`, `screen` or `follow` (the default). `follow` takes the form the player chose in their settings; `board` and `screen` force one of the two. |
| `size`, `backdrop`, `scene`, `keys="navigate"`, `wheel` | ExyliaLib's: size in pixels (`400x225`), background, picture, keyboard focus, mouse wheel. |

</Details>
