You end up with a menu that opens the way you want and that every player can use: screens and 3D menus point at a chest menu that clients who cannot draw them get instead. All three forms open the same way, with the same keys.

## Before you start

Have the menu file ready: a [screen](/docs/exyliascreens/screens), a [chest menu](/docs/exyliascreens/chest-menus) or a [3D menu](/docs/exyliascreens/3d-menus). For a fallback, write the chest menu first.

## Steps

<Steps>
  <Step title="Name the command">
    In a screen, put `command="hub" aliases="warps"` on the `<screen>` tag. In a chest menu write `command: hub` and `aliases: [warps]`. In a 3D menu the same keys go under `menu:`.
  </Step>
  <Step title="Limit who opens it (optional)">
    `permission` names the node a player needs; without it everybody can open it. `require` is an [expression](/docs/exyliascreens/actions-and-requirements#requirements) checked at the same time, and `deny` lists what to run when it fails; without `deny` the player gets the "You cannot open this screen" message.
  </Step>
  <Step title="Link a fallback">
    Add `fallback="hub_chest"` (screens) or `fallback: hub_chest` (chest and 3D) naming the id of a menu you wrote.
  </Step>
  <Step title="Reload">
    The files reload within two seconds, and the commands are installed on load and on `/screensadmin reload`. Run `/screensadmin check`: it names a fallback that does not exist or leads in a circle.
  </Step>
</Steps>

## Check that it works

Run `/screensadmin list`: each menu shows its command and its form. Open it with `/hub`. To see the fallback, run `/screensadmin open hub <player>` for a Bedrock player or an old client; they get `menus/hub_chest.yml`. Commands are for players only; the console gets a "Only players can open screens" message.

## Fallbacks are links, never copies

`hub.html` with `fallback="hub_chest"` opens as a screen, and a client that cannot draw screens gets `menus/hub_chest.yml`, which **you wrote**. The plugin never makes one for you, except when an [importer](/docs/exyliascreens/importer) writes it.

- A fallback may have its own: `hub_3d` goes to `hub`, which goes to `hub_chest`.
- A menu with no fallback tells such a client "This menu does not work on your client".
- A chest menu is drawn by every client, so its `fallback` is never taken.
- A player who chose chest windows in `/settings` also takes the fallback of a screen or 3D menu that has one, unless `follow-player-style: false` in `config.yml`. A menu with no fallback still opens.

Screens need Java 1.20.2 or newer (not Bedrock), 3D menus need Java 1.21.4 or newer, and `min-client` can raise either.

## Pass words to a menu

`args="player"` (a list, `args: [player]`, in chest and 3D menus) makes `/stats Bob` fill `%player%` in a chest or 3D menu and `${player}` in a screen. An argument is letters, digits and `_.:-`, up to 64 characters; anything else, or too few words, answers with the usage line.

## Other ways to open a menu

| From | How |
|---|---|
| A command | The menu's `command` and `aliases`. |
| A screen | `action="open shop"`, or `open shop tab=food` to set its state. |
| A chest or 3D click, a hologram, an NPC, a clickable block | Any ExyliaLib interaction line: `[SCREEN] shop`. |
| Another plugin's actions | `exyliascreens:open shop`. |
| Joining | `open-on-join: hub` in `config.yml`, after `open-on-join-delay` ticks (40 by default). |
| A held item | [Items that open a menu](/docs/exyliascreens/open-items). |
| Staff | `/screensadmin open shop <player>`. |
| In the world | A [world screen](/docs/exyliascreens/screens#stand-a-screen-in-the-world) placed with `/screensadmin world place`. |

Opening goes through the menu's permission and requirement every time, whichever way it was reached.

<Details title="Opening keys side by side">

| Screen attribute | Chest key, or 3D key under `menu:` | Does |
|---|---|---|
| `command`, `aliases` | `command`, `aliases` (a list) | The commands that open it. |
| `permission` | `permission` | Who may open it. |
| `require`, `deny` | `require`, `deny` | Expression checked before opening, and the lines run when it fails. |
| `fallback` | `fallback` | The id of the menu a client gets when it cannot draw this one. |
| `min-client` | `min-client` | The oldest client that gets this menu (`1.21.4`); older ones take the fallback. An unknown version is reported by `/screensadmin check` and ignored. |
| `args` | `args` (a list) | The words after the command, by name. |
| `on-open` | `on-open` | Interaction lines run as it opens. |

</Details>
