description: "The theme.css cascade: ExyliaLib's base theme, the network theme, theme.css, per-screen CSS and custom.css."
---

Screens are styled with a subset of CSS. The sheets are read in this order, later ones winning:

1. ExyliaLib's base theme (inside the library).
2. `plugins/ExyliaLib/screens/theme.css`: the network theme, restyling **every** plugin's screens at once.
3. `plugins/ExyliaScreens/screens/theme.css`: shared by every ExyliaScreens screen.
4. `plugins/ExyliaScreens/screens/<id>.css`: one screen's.
5. `plugins/ExyliaScreens/screens/custom.css`: yours; the plugin never ships it, so it wins over everything above.

Within a sheet, rules are resolved by specificity, then order. Changes show on open screens within two seconds.

```css
.tile { width: 80px; height: 64px; padding: 6px; gap: 2px; }
.tile:hover { outline: 1px {secondary}; }
.price-short { color: {error_light}; }
```

Use palette tokens (`{primary}`, `{success}`, `{error_light}`...) instead of hex colours, so `colors.yml` recolours everything. The shipped files do the same.

The properties and selectors (`:hover`, `[selected]`, `:nth-child`, custom properties with `var(--name)`, motion with `transition` and `animation`, gradients) are ExyliaLib's: see its screens
reference, and `/exylialib screens gallery` for every element to copy from.

## Imported screens

The importer's screens use the classes `.chest`, `.chest-title`, `.chest-row`, `.slot`, `.slot.empty` and `.amount`; the shipped `theme.css` styles them.
