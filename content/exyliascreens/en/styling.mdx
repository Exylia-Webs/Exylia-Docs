You end up with screens that match your server's look: one file that restyles them all, or a change for a single screen, without touching the HTML of the examples.

## Before you start

Screens use a subset of CSS. The properties and selectors (`:hover`, `[selected]`, `:nth-child`, `var(--name)`, gradients) are ExyliaLib's, see [ExyliaLib: Screens](/docs/exylialib/screens); `/exylialib screens gallery` shows every element to copy from. Use palette tokens (`{primary}`, `{success}`, `{error_light}`...) instead of hex colours, so `colors.yml` recolours everything, see [ExyliaLib: Colours](/docs/exylialib/colours). The shipped files do the same.

## Steps

<Steps>
  <Step title="Pick where the change goes">
    One screen: `plugins/ExyliaScreens/screens/<id>.css`. All ExyliaScreens screens: `plugins/ExyliaScreens/screens/theme.css`. Every Exylia plugin's screens: `plugins/ExyliaLib/screens/theme.css`. Your own changes that survive any update: `plugins/ExyliaScreens/screens/custom.css`, which the plugin never ships.
  </Step>
  <Step title="Write the rule">
    ```css
    .tile { width: 80px; height: 64px; padding: 6px; gap: 2px; }
    .tile:hover { outline: 1px {secondary}; }
    .price-short { color: {error_light}; }
    ```
  </Step>
  <Step title="Save and look">
    Changes show on open screens within two seconds. `/screensadmin check` reports a property it does not know.
  </Step>
</Steps>

## Check that it works

Open a screen that uses the class you styled (for example `/shop`) and the change is there. If it is not, a later sheet or a `style` attribute is overriding it; see the order below.

## Which sheet wins

The sheets are read in this order, later ones winning:

1. ExyliaLib's base theme (inside the library).
2. `plugins/ExyliaLib/screens/theme.css`: the network theme.
3. `plugins/ExyliaScreens/screens/theme.css`: shared by every ExyliaScreens screen.
4. `plugins/ExyliaScreens/screens/<id>.css`: one screen's.
5. `plugins/ExyliaScreens/screens/custom.css`: yours; it wins over everything above.

Within a sheet, rules are resolved by specificity, then order.

## Style one element

`style="..."` on any element sets declarations for that element alone, over every rule in every sheet, as in a web page. Placeholders and `${...}` work inside it.

```html
<card style="width: 120px; background: {success}20">...</card>
<small style="color: ${balance() >= 50 ? '{success}' : '{error_light}'}">50 coins</small>
```

Its best use is a **custom property** that the sheet reads, so one line recolours a whole card and everything in it. The [server selector](/docs/exyliascreens/examples) does this:

```css
.mode { --tone: {primary}; }
.mode:hover { outline: 1px var(--tone); background: var(--tone)16; }
.mode-name { color: var(--tone); }
```

```html
<card class="mode" style="--tone: {success}">...</card>
<card class="mode" style="--tone: {info}">...</card>
```

`var(--tone)16` is the tone with transparency, like `{success}16`.

<Details title="Motion and imported screens">

`transition`, `enter`, `leave`, `animation`, `stagger` and `text-reveal` are styling too: see [Animate a screen](/docs/exyliascreens/motion).

The screens the [importer](/docs/exyliascreens/importer) writes use the classes `.chest`, `.chest-title`, `.chest-row`, `.slot`, `.slot.empty` and `.amount`; the shipped `theme.css` styles them.

</Details>
