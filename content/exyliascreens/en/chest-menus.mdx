You end up with a chest window opened by a command, whose items can depend on permissions, level or money. Every client can draw it, so it is also the safe fallback for [screens](/docs/exyliascreens/screens) and [3D menus](/docs/exyliascreens/3d-menus).

## Before you start

The format is ExyliaLib's (lists, pages, fillers and groups are on [ExyliaLib: Menus](/docs/exylialib/menus)), plus the conditions and click lines below. Colours are palette tokens, see [ExyliaLib: Colours](/docs/exylialib/colours). The id of a menu is its file name, and it is shared with `screens/` and `spatial/`: two files with the same id means the second never opens, and `/screensadmin check` says so.

## Steps

<Steps>
  <Step title="Create the file">
    Make `plugins/ExyliaScreens/menus/kits.yml`.
  </Step>
  <Step title="Write the menu">
    ```yaml
    command: kits
    title: "{primary}&lKITS"
    size: 27
    items:
      vip_kit:
        slot: 13
        priority: 1                               # lowest first among the items of a slot
        if: "perm('kits.vip') and level() >= 5"   # the item is only there while this holds
        material: DIAMOND_SWORD
        name: "{letters}Kit {letters_black}▸ <gradient:{highlight}:{warning_light}>VIP</gradient>"
        require: "balance() >= 100"               # must hold for a click to run
        deny: ["[MESSAGE] {error}You need $100."] # run when it does not
        click:
          - "left: [MONEY] take 100"
          - "left: [CONSOLE] kit give vip %player_name%"
          - "right: [MESSAGE] {letters}The VIP kit."
          - "shift_left: [SCREEN] kit_preview"
      member_kit:
        slot: 13                                  # shown when vip_kit is not
        priority: 2
        material: IRON_SWORD
    ```
  </Step>
  <Step title="Save and test">
    The file loads within two seconds. Run `/screensadmin check` for mistakes.
  </Step>
</Steps>

## Check that it works

Run `/kits`. A player with `kits.vip` and level 5 sees the diamond sword; everyone else sees the iron sword in the same slot. Left-click the sword without $100 and the `deny` line answers instead of taking anything.

## Show items only when they apply

Several items may share a slot: the one with the lowest `priority` whose `if` holds is drawn. `require` and `deny` decide what a click does, and `click` lists the [actions](/docs/exyliascreens/actions-and-requirements#actions) to run, each optionally prefixed by `left:`, `right:` or `shift_left:`. `[CLOSE]` closes the menu and `[SCREEN] <id>` opens any menu, whatever its form. The `actions:` entries `next_page`, `previous_page`, `back` and `refresh` stay for the menu's own buttons.

## Lists that fill themselves

A `pagination` block can list its own rows, paged by the arrows under `navigation`, with no Java:

```yaml
pagination:
  slots: "10-16,19-25"
  entries:                                  # one card per entry, in priority order
    spawn:
      priority: 1
      if: "perm('warp.spawn')"              # left out of the list (not a gap) while false
      material: COMPASS
      name: "{info}Spawn"
      click: ["[CLOSE]", "[PLAYER] warp spawn"]
    mine:
      material: IRON_PICKAXE
      name: "{info}Mine"
      require: "level() >= 10"
      deny: ["[MESSAGE] {error}You need level 10."]
      click: ["[CLOSE]", "[PLAYER] warp mine"]
  navigation:
    previous: { slot: 30 }
    next: { slot: 32 }
```

An entry takes every key a slot does. A menu has one list.

### Online players

`source: online-players` lists everybody the viewer can see instead of written entries, sorted by name and drawn by `item_template` with `%target_name%` and `%target_uuid%`. `skip-viewer: true` leaves the viewer out. The list follows players joining and leaving while it is open. Any other `source` value is reported by `/screensadmin check`. `menus/players.yml` (`/players`) is a full example.

```yaml
pagination:
  slots: "10-16,19-25"
  source: online-players
  skip-viewer: true
  item_template:
    material: "playerhead-%target_name%"
    name: "{info}%target_name%"
```

<Details title="Item keys that ExyliaScreens adds">

| Key | Does |
|---|---|
| `slot`, `slots` | Where the item goes. |
| `priority` | Order among the items of a slot; lowest first. |
| `if` | An [expression](/docs/exyliascreens/actions-and-requirements#requirements); the item exists only while it is true. |
| `require`, `deny` | Checked on a click. Also `require-left`, `-right`, `-middle`, `-shift-left`, `-shift-right` with matching `deny-...`. |
| `click` | A list of interaction lines, each optionally prefixed by `left:`, `right:`, `shift_left:`, `shift_right:`. |

These keys live in ExyliaLib, so the menus of every Exylia plugin can use them.

</Details>
