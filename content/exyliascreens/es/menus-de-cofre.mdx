`menus/<id>.yml` es una ventana de cofre normal, que dibuja todo cliente. El formato es el de ExyliaLib (las listas, páginas, rellenos y grupos están en [ExyliaLib: Menús](/docs/exylialib/menus)), más
lo que hace un archivo de DeluxeMenus. Las claves de apertura (`command`, `permission`, `fallback`...) están en [Apertura y alternativas](/docs/exyliascreens/apertura-y-alternativas).

```yaml
command: kits
title: "{primary}&lKITS"
size: 27
items:
  vip_kit:
    slot: 13
    priority: 1                               # primero el más bajo entre los objetos de una ranura
    if: "perm('kits.vip') and level() >= 5"   # el objeto solo está mientras esto se cumpla
    material: DIAMOND_SWORD
    name: "{letters}Kit {letters_black}▸ <gradient:{highlight}:{warning_light}>VIP</gradient>"
    require: "balance() >= 100"               # debe cumplirse para que el clic se ejecute
    deny: ["[MESSAGE] {error}Necesitas $100."] # se ejecutan cuando no se cumple
    click:
      - "left: [MONEY] take 100"
      - "left: [CONSOLE] kit give vip %player_name%"
      - "right: [MESSAGE] {letters}El kit VIP."
      - "shift_left: [SCREEN] kit_preview"
  member_kit:
    slot: 13                                  # se muestra cuando vip_kit no
    priority: 2
    material: IRON_SWORD
```

## Ranuras

| Clave | Qué hace |
|---|---|
| `slot`, `slots` | Dónde va el objeto. |
| `priority` | Varios objetos pueden compartir ranura; se muestra el de prioridad más baja cuyo `if` se cumpla. |
| `if` | Una [expresión](/docs/exyliascreens/acciones-y-requisitos#requisitos); el objeto existe solo mientras sea verdadera. |
| `require`, `deny` | Se comprueban al hacer clic. También `require-left`, `-right`, `-middle`, `-shift-left`, `-shift-right` con sus `deny-...`. |
| `click` | Una lista de [líneas de interacción](/docs/exyliascreens/acciones-y-requisitos#acciones), cada una con prefijo opcional `left:`, `right:`, `shift_left:`... |

`[CLOSE]` cierra el menú y `[SCREEN] <id>` abre un menú de cualquier forma. Todo lo que hace un paso de pantalla escrito entre corchetes funciona aquí. `actions:` (`next_page`, `previous_page`, `back`,
`refresh`) se mantienen para los botones propios del menú. Estas claves viven en ExyliaLib, así que los menús de cualquier plugin de Exylia pueden usarlas.

## Listas que se rellenan solas

Un bloque `pagination` puede listar sus propias filas, paginadas con las flechas de `navigation`, sin Java.

```yaml
pagination:
  slots: "10-16,19-25"
  entries:                                  # una tarjeta por entrada, por orden de prioridad
    spawn:
      priority: 1
      if: "perm('warp.spawn')"              # se quita de la lista (sin dejar hueco) mientras sea falso
      material: COMPASS
      name: "{info}Spawn"
      click: ["[CLOSE]", "[PLAYER] warp spawn"]
    mine:
      material: IRON_PICKAXE
      name: "{info}Mina"
      require: "level() >= 10"
      deny: ["[MESSAGE] {error}Necesitas nivel 10."]
      click: ["[CLOSE]", "[PLAYER] warp mine"]
  navigation:
    previous: { slot: 30 }
    next: { slot: 32 }
```

Una entrada admite todas las claves de una ranura. Hay una lista por menú.

### Jugadores conectados

`source: online-players` lista en su lugar a todos los que el espectador puede ver, dibujados con `item_template` usando `%target_name%` y `%target_uuid%`. `skip-viewer: true` deja fuera al espectador. La
lista sigue las entradas y salidas de jugadores mientras está abierta. `menus/players.yml` es un ejemplo completo.

```yaml
pagination:
  slots: "10-16,19-25"
  source: online-players
  skip-viewer: true
  item_template:
    material: "playerhead-%target_name%"
    name: "{info}%target_name%"
```
