Al terminar tendrás una ventana de cofre que se abre con un comando y cuyos objetos pueden depender de permisos, nivel o dinero. Todos los clientes pueden dibujarla, así que también es la alternativa segura de las [pantallas](/docs/exyliascreens/pantallas) y los [menús 3D](/docs/exyliascreens/menus-3d).

## Antes de empezar

El formato es el de ExyliaLib (las listas, páginas, rellenos y grupos están en [ExyliaLib: Menús](/docs/exylialib/menus)), más las condiciones y líneas de clic de abajo. Los colores son tokens de la paleta, mira [ExyliaLib: Colores](/docs/exylialib/colours). El id de un menú es el nombre de su archivo y se comparte con `screens/` y `spatial/`: si dos archivos tienen el mismo id, el segundo nunca se abre, y `/screensadmin check` te lo dice.

## Pasos

<Steps>
  <Step title="Crea el archivo">
    Crea `plugins/ExyliaScreens/menus/kits.yml`.
  </Step>
  <Step title="Escribe el menú">
    ```yaml
    command: kits
    title: "{primary}&lKITS"
    size: 27
    items:
      vip_kit:
        slot: 13
        priority: 1                               # primero el más bajo entre los objetos de una ranura
        if: "perm('kits.vip') and level() >= 5"   # el objeto solo está mientras esto se cumpla
        material: DIAMOND_SWORD
        name: "{letters}Kit {letters_black}▸ <gradient:{highlight}:{warning_light}>VIP</gradient>"
        require: "balance() >= 100"               # debe cumplirse para que el clic se ejecute
        deny: ["[MESSAGE] {error}Necesitas $100."] # se ejecutan cuando no se cumple
        click:
          - "left: [MONEY] take 100"
          - "left: [CONSOLE] kit give vip %player_name%"
          - "right: [MESSAGE] {letters}El kit VIP."
          - "shift_left: [SCREEN] kit_preview"
      member_kit:
        slot: 13                                  # se muestra cuando vip_kit no
        priority: 2
        material: IRON_SWORD
    ```
  </Step>
  <Step title="Guarda y prueba">
    El archivo se carga en menos de dos segundos. Ejecuta `/screensadmin check` para ver errores.
  </Step>
</Steps>

## Comprueba que funciona

Ejecuta `/kits`. Un jugador con `kits.vip` y nivel 5 ve la espada de diamante; todos los demás ven la espada de hierro en la misma ranura. Haz clic izquierdo en la espada sin tener $100 y responde la línea de `deny` en lugar de cobrar nada.

## Muestra objetos solo cuando corresponda

Varios objetos pueden compartir ranura: se dibuja el de `priority` más baja cuyo `if` se cumpla. `require` y `deny` deciden qué hace un clic, y `click` lista las [acciones](/docs/exyliascreens/acciones-y-requisitos#acciones) que se ejecutan, cada una con prefijo opcional `left:`, `right:` o `shift_left:`. `[CLOSE]` cierra el menú y `[SCREEN] <id>` abre un menú de cualquier forma. Las entradas de `actions:` `next_page`, `previous_page`, `back` y `refresh` se mantienen para los botones propios del menú.

## Listas que se rellenan solas

Un bloque `pagination` puede listar sus propias filas, paginadas con las flechas de `navigation`, sin Java:

```yaml
pagination:
  slots: "10-16,19-25"
  entries:                                  # una tarjeta por entrada, por orden de prioridad
    spawn:
      priority: 1
      if: "perm('warp.spawn')"              # se quita de la lista (sin dejar hueco) mientras sea falso
      material: COMPASS
      name: "{info}Spawn"
      click: ["[CLOSE]", "[PLAYER] warp spawn"]
    mine:
      material: IRON_PICKAXE
      name: "{info}Mina"
      require: "level() >= 10"
      deny: ["[MESSAGE] {error}Necesitas nivel 10."]
      click: ["[CLOSE]", "[PLAYER] warp mine"]
  navigation:
    previous: { slot: 30 }
    next: { slot: 32 }
```

Una entrada admite todas las claves de una ranura. Un menú tiene una lista.

### Jugadores conectados

`source: online-players` lista a todos los que el espectador puede ver en lugar de entradas escritas, ordenados por nombre y dibujados con `item_template` usando `%target_name%` y `%target_uuid%`. `skip-viewer: true` deja fuera al espectador. La lista sigue las entradas y salidas de jugadores mientras está abierta. Cualquier otro valor de `source` lo señala `/screensadmin check`. `menus/players.yml` (`/players`) es un ejemplo completo.

```yaml
pagination:
  slots: "10-16,19-25"
  source: online-players
  skip-viewer: true
  item_template:
    material: "playerhead-%target_name%"
    name: "{info}%target_name%"
```

<Details title="Claves de objeto que añade ExyliaScreens">

| Clave | Qué hace |
|---|---|
| `slot`, `slots` | Dónde va el objeto. |
| `priority` | Orden entre los objetos de una ranura; primero el más bajo. |
| `if` | Una [expresión](/docs/exyliascreens/acciones-y-requisitos#requisitos); el objeto existe solo mientras sea verdadera. |
| `require`, `deny` | Se comprueban al hacer clic. También `require-left`, `-right`, `-middle`, `-shift-left`, `-shift-right` con sus `deny-...`. |
| `click` | Una lista de líneas de interacción, cada una con prefijo opcional `left:`, `right:`, `shift_left:`, `shift_right:`. |

Estas claves viven en ExyliaLib, así que los menús de cualquier plugin de Exylia pueden usarlas.

</Details>
