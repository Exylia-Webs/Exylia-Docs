## Is ExyliaProtections free?

No. It is a premium plugin, bought on [BuiltByBit](https://builtbybit.com/resources/exylia-protections.129494/) and
installed as a loader jar that checks the licence on every start. Bought on BuiltByBit, the licence is
embedded in the jar. See [Installation](/docs/exyliaprotections/installation).

## I used the protections of ExyliaSurvivalCore. What do I do?

Update ExyliaSurvivalCore to a release without the protections module, install ExyliaProtections next to
it and follow [Migration](/docs/exyliaprotections/migration). Nothing is imported: since 1.0.2 the
survival core's files, tables and old `exyliasurvivalcore.protections*` permission nodes are not read.
Copy the settings you changed and grant the `exyliaprotections.*` nodes. `/protections`, `/ps` and
`/claims` keep their names.

## The plugin does not start

`packetevents` is a hard dependency: without it the server never loads the plugin. ExyliaLib 1.296.0 or
newer is needed too; the loader installs it, or stages a newer one, and asks for a restart — restart once
more. If the console reports a licence error, check that `Exylia-Protections-Loader.jar` is the jar from your
purchase, and contact support if it is.

## Players are told "Protections are still loading"

The plugin could not read its protections from the database yet. Until it does, it refuses building and
other changes in every world where land can be protected, so an unreadable database never leaves land
open. The console shows the database error and it tries again every 30 seconds. Fix the connection in
`database.yml`. Players holding `exyliaprotections.bypass` are not held back.

## As an operator I cannot build in other players' land

That is intended. `exyliaprotections.bypass` defaults to nobody, operators included, so an operator can test
their own land. Grant the node to staff who must build anywhere. `exyliaprotections.admin`, which operators
do have, lets them manage and enter every protection but not build in it. See
[Permissions](/docs/exyliaprotections/permissions).

## The protection shop button is missing

The shop lists tiers with a `price` above 0, and the hub hides the button when there is none, or while
`cores.enabled` is off. Give a tier a price in `config.yml` or in the
[tier editor](/docs/exyliaprotections/administration).

## The select land button is missing

It shows only with `selection.enabled` on, which is **off** by default, and the
`exyliaprotections.select` node, which everybody has by default. Turn it on in `config.yml` or from
`/protectionsadmin settings general`. If it shows but answers "Protecting land by selection is not available.", one of the two changed
since the menu opened.

## "You need … for that." although the player has the money

Every price goes through ExyliaLib's economy. With no economy installed — ExyliaEconomy, Vault with an
economy behind it, or PlayerPoints — every price above 0 is refused. A tier's or the selector's `currency`
must also be a currency that exists; blank uses the default one. To hand cores out without an economy, use
`/protectionsadmin give <player> <tier> [amount]`.

## A core cannot be placed

The core stays in the hand and the chat says why:

| Message | Cause |
|---|---|
| Protection cores are turned off on this server. | `cores.enabled` is off. |
| Land cannot be protected in this world. | The world is in `settings.disabled-worlds`, `world_the_end` by default. |
| You already own *n* protection(s), your limit. | The player's limit, counted on every server. |
| You already own *n* of this tier. | The tier's own `limit`. |
| You already own *n* protection(s) in this world. | `settings.world-limits` for this world. |
| That land overlaps another protection. | Any protection of this server, whoever owns it. |
| Keep at least *n* blocks from other players' protections. | `settings.min-distance`, 8 by default. The player's own protections may touch. |
| That land overlaps a protected server area. | A WorldGuard region other than this plugin's own, the global region and `settings.allowed-world-guard-regions`. |
| You cannot use this protection tier. | The tier names a `permission` the player lacks. |

See [Creating protections](/docs/exyliaprotections/creating-protections).

## How do I let players own more protections?

Grant `exyliaprotections.limit.<n>`, such as `exyliaprotections.limit.10`. The highest one a player holds
is their limit; without one it is `settings.default-limit`, 3. `exyliaprotections.limit.0` is a limit like
any other and allows none. See
[Permissions](/docs/exyliaprotections/permissions).

## The overview has only a few sections

**Economy**, **Growth** and **Extras** appear only while one of their features is on, and **Defense**
while raids or logs are. Raids, the bank, upkeep, the market, rent, plots, upgrades, warps, perks, time
and weather and merging are all off after a fresh install. Turn them on with
`/protectionsadmin feature <name> on`, from `/protectionsadmin settings features`, or in `submodules`
followed by `/protectionsadmin reload`. See
[Configuration](/docs/exyliaprotections/configuration).

## I changed the roles in config.yml and old protections did not change

A protection copies the `roles` section and its tier's `flags` when it is made. Editing them changes the
protections made afterwards. Existing ones are edited from their **People** → **Roles** screen. See
[People and access](/docs/exyliaprotections/people-and-access).

## A member cannot open chests

What a member may do is their role's permissions, plus any personal override. Open **People** →
**Roles**, left-click their role and turn **Containers** on, or shift-click them in **Members** to give
them alone access.

## How do I reload the plugin?

`/protectionsadmin reload` (also `/protections admin reload`, or **Reload** in the admin hub) re-reads
`config.yml`, the messages and the menus. `/exylialib reload` re-reads the menu files too. Edits under `menus/admin/` never stick: those screens are rewritten from the jar on every start.

## Do I need WorldGuard?

No. The default `INTERNAL` backend enforces everything itself. WorldGuard adds the `WORLDGUARD` backend,
which mirrors each protection as a region other plugins can read, keeps new land off other WorldGuard
regions, and is needed for the ProtectionStones import. See [Backends](/docs/exyliaprotections/backends).

## A protection made on another server is not protected here

Each protection belongs to the server it was made on, and only that server enforces it. Other servers on
the same database list it, count it towards limits and teleport members to it.

## A protection made on one server does not show up on another

Every server keeps the protections in memory. Without Redis in `database.yml` a server only learns of
another server's changes when it restarts. Turn Redis on, on every server, with a different `server-id`
on each. See [Installation](/docs/exyliaprotections/installation#a-network).

## Can I bring over ProtectionStones regions?

Yes, with `/protectionsadmin import protectionstones`, WorldGuard installed and ProtectionStones
optional. Run it with `--dry-run` first. See [Migration](/docs/exyliaprotections/migration#from-protectionstones).

## `/ps` opens ProtectionStones

Both plugins register `/ps`. Remove ProtectionStones once its regions are imported, or use `/protections`
or `/claims`.
