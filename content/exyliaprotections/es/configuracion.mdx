Todo se genera en `plugins/ExyliaProtections/` en el primer arranque, con comentarios. Edita los archivos de
ahí, nunca las copias del jar, y reinicia el servidor para aplicarlos: el plugin no tiene comando de recarga.

Las protecciones en sí no están en ningún archivo. Viven en la base de datos y se editan desde los menús.

| Archivo | Qué contiene |
|---|---|
| `config.yml` | Todos los ajustes de abajo. |
| `database.yml` | La conexión a la base de datos de ExyliaLib. |
| `lang/<idioma>/messages.yml` | Cada línea que envía el plugin. |
| `lang/<idioma>/menus/user/*.yml` | Las pantallas de los jugadores. |
| `lang/<idioma>/menus/admin/*.yml` | Las pantallas del staff. |

<Callout type="note" title="Si vienes de ExyliaSurvivalCore">
Si `plugins/ExyliaSurvivalCore/` existe en el primer arranque, su `modules/protections/config.yml`, el
`modules/protections/messages.yml` de cada idioma y su `database.yml` se copian aquí allí donde este plugin
aún no tiene un archivo propio, así que no hay que configurar nada otra vez. Ver
[Migración](/docs/exyliaprotections/migracion).
</Callout>

## config.yml

Cada función tiene su propia sección, y después vienen los roles iniciales y los tiers. La clave
`config-version` es del plugin; no la toques. El archivo está en la versión 5, y los archivos más antiguos se
actualizan al arrancar.

### settings

```yaml
settings:
  backend: INTERNAL
  worldguard-priority: 10
  default-limit: 3
  world-limits: {}
  min-distance: 8
  disabled-worlds:
  - world_the_end
  allowed-world-guard-regions: []
  move-price: 1000.0
  move-currency: ''
  home-warmup-seconds: 3
  deny-message-cooldown-millis: 1500
```

| Clave | Por defecto | Qué hace |
|---|---|---|
| `backend` | `INTERNAL` | `INTERNAL`: el plugin lo aplica todo por sí mismo. `WORLDGUARD`: cada protección es además una región de WorldGuard con flags nativas. Se cambia con `/protections admin migrate`, no aquí. Ver [Backends](/docs/exyliaprotections/backends). |
| `worldguard-priority` | `10` | Prioridad de las regiones de WorldGuard que crea el plugin. |
| `default-limit` | `3` | Protecciones que puede tener un jugador sin ningún `exyliaprotections.limit.<n>`. |
| `world-limits` | `{}` | Protecciones que puede tener un jugador por mundo, como `mundo: número`. Un mundo que no aparece no tiene límite propio. |
| `min-distance` | `8` | Bloques que deben separar protecciones de dueños distintos. |
| `disabled-worlds` | `[world_the_end]` | Mundos donde no se puede proteger terreno. |
| `allowed-world-guard-regions` | `[]` | Regiones de WorldGuard con las que una protección puede superponerse. Cualquier otra región la bloquea. |
| `move-price` | `1000.0` | Lo que cuesta mover un núcleo. |
| `move-currency` | `''` | Su moneda; vacío es la moneda por defecto. |
| `home-warmup-seconds` | `3` | Segundos quieto antes de teletransportarse al hogar. |
| `deny-message-cooldown-millis` | `1500` | Milisegundos entre dos mensajes de "este terreno está protegido" al mismo jugador. |

El comentario sobre `default-limit` todavía nombra `exyliasurvivalcore.protections.limit.<n>`; se leen los
dos prefijos. Ver [Permisos](/docs/exyliaprotections/permisos#cuántas-protecciones-puede-tener-un-jugador).

### submodules

Apaga funciones enteras. Una función apagada oculta sus botones, rechaza sus comandos y deja de actuar.

| Clave | Por defecto | Función |
|---|---|---|
| `bans` | `true` | Los dueños banean jugadores de sus protecciones. |
| `lock` | `true` | Los dueños cierran una protección a los miembros. Cerrarla apaga `visitor-entry`. |
| `enter-leave` | `true` | Títulos y sonidos al entrar y salir, y los saludos y despedidas de los dueños. |
| `logs` | `true` | Registros de bloques, contenedores y cada cambio. |
| `raids` | `false` | Vidas, salud del núcleo, ventanas de asedio, escudos sin conexión. Ver [Asaltos](/docs/exyliaprotections/asaltos). |
| `upkeep` | `false` | Las protecciones pagan cada periodo, y se abandonan y borran cuando dejan de hacerlo. |
| `bank` | `false` | Un banco compartido por protección. |
| `market` | `false` | Vender protecciones y regalarlas. |
| `subregions` | `false` | Parcelas dentro de las protecciones con sus propios miembros y flags. |
| `rent` | `false` | Alquilar parcelas y protecciones a otros jugadores. |
| `upgrades` | `false` | Niveles por los que se mejora una protección. |
| `warps` | `false` | Protecciones publicadas como warps públicos con visitas y valoraciones. |
| `visualization` | `true` | Dibujar bordes, y marcadores en BlueMap y Dynmap. |
| `effects` | `false` | Ventajas para los miembros dentro de su protección. |
| `environment` | `false` | Una hora del día y un clima propios dentro de una protección. |
| `merge` | `false` | Fusionar dos protecciones que se tocan en una. |

### selection

```yaml
selection:
  enabled: true
  tier: medium
  height: FULL
  price-per-block: 5.0
  currency: ''
  min-side: 9
  max-area: 10000
  full-height-tool: GOLDEN_HOE
  normal-height-tool: GOLDEN_AXE
```

| Clave | Por defecto | Qué hace |
|---|---|---|
| `enabled` | `true` | Si los jugadores pueden proteger terreno seleccionando dos esquinas. También necesita `exyliaprotections.select`. |
| `tier` | `medium` | El tier que cuenta una protección seleccionada, para su límite y sus flags iniciales. |
| `height` | `FULL` | `FULL`: las esquinas protegen toda su columna. `NORMAL`: solo los bloques entre las alturas de las dos esquinas. |
| `price-per-block` | `5.0` | Precio por bloque de área protegida. |
| `currency` | `''` | Su moneda; vacío es la moneda por defecto. |
| `min-side` | `9` | El lado más corto que puede tener una selección. |
| `max-area` | `10000` | El área más grande que puede cubrir una selección. |
| `full-height-tool` | `GOLDEN_HOE` | El selector para selecciones y parcelas de altura completa. |
| `normal-height-tool` | `GOLDEN_AXE` | El selector en los demás casos. |

El selector es un objeto que solo ve el cliente del jugador, gracias a PacketEvents, así que no se puede
tirar, guardar ni vender. Un nombre de herramienta que no es un objeto vuelve al de por defecto. Ver
[Crear protecciones](/docs/exyliaprotections/crear-protecciones).

### bans y enter-leave

```yaml
bans:
  reason-max-length: 64
enter-leave:
  enter-sound: BLOCK_AMETHYST_BLOCK_CHIME|0.6|1.4
  leave-sound: ''
  message-max-length: 64
  cooldown-millis: 1500
  show-to-members: true
```

| Clave | Por defecto | Qué hace |
|---|---|---|
| `bans.reason-max-length` | `64` | El motivo más largo que puede llevar un baneo. |
| `enter-leave.enter-sound` | `BLOCK_AMETHYST_BLOCK_CHIME\|0.6\|1.4` | Suena al entrar, como `NOMBRE\|volumen\|tono`. Vacío no suena nada. |
| `enter-leave.leave-sound` | `''` | Suena al salir. |
| `enter-leave.message-max-length` | `64` | El saludo o la despedida más largos que puede escribir un dueño. |
| `enter-leave.cooldown-millis` | `1500` | Milisegundos antes de que volver a cruzar un borde muestre algo, para que caminar a lo largo de uno no haga ruido. |
| `enter-leave.show-to-members` | `true` | Si los miembros también ven los títulos, o solo los visitantes. |

Los títulos y barras de acción en sí están en `enter-leave` de `messages.yml`.

### logs

```yaml
logs:
  retention-days: 14
  flush-seconds: 10
  skip-actions: []
  owner-blocks: false
  menu-rows: 500
```

| Clave | Por defecto | Qué hace |
|---|---|---|
| `retention-days` | `14` | Días que se guarda una entrada. `0` las guarda para siempre. |
| `flush-seconds` | `10` | Segundos entre dos escrituras de las entradas pendientes de guardar. |
| `skip-actions` | `[]` | Acciones que **no** se registran; todo lo demás sí, incluidas acciones que se añadan más adelante. Acciones: `break`, `place`, `container`, `member`, `role`, `flag`, `ban`, `lock`, `core`, `settings`, `raid`, `bank`, `upkeep`, `market`, `subregion`, `rent`, `upgrade`, `warp`, `merge`. |
| `owner-blocks` | `false` | Si también se registran los bloques y contenedores del propio dueño. |
| `menu-rows` | `500` | Las entradas más recientes que lee el menú de registros. |

### raids

Solo se lee con `submodules.raids` activado. Ver [Asaltos](/docs/exyliaprotections/asaltos) para cómo se juegan.

```yaml
raids:
  tier-lives:
    small: 3
    medium: 4
    large: 5
  default-lives: 3
  core-health: 150
  tool-damage:
    NETHERITE_PICKAXE: 4
    DIAMOND_PICKAXE: 3
    IRON_PICKAXE: 2
  default-damage: 1
  hit-cooldown-millis: 500
  core-heal-seconds: 30
  hit-sound: BLOCK_ANVIL_LAND|0.4|1.6
  lives-per-kill: 1
  kill-cooldown-minutes: 10
  allies-are-friends: true
  raidable-minutes: 30
  lives-after-raid: 1
  cooldown-minutes: 120
  raidable-permissions:
  - break
  - place
  - containers
  - doors
  - redstone
  - buckets
  explosions-while-raidable: false
  regen-minutes: 60
  restore-price: 5000.0
  restore-currency: ''
  allow-hidden-core: false
  siege-windows:
    enabled: false
    timezone: ''
    windows:
    - SATURDAY 18:00-22:00
    - SUNDAY 18:00-22:00
  offline-shield:
    enabled: true
    grace-minutes: 10
    clan-members-count: false
```

| Clave | Por defecto | Qué hace |
|---|---|---|
| `tier-lives` | small 3, medium 4, large 5 | Vidas que tiene una protección de cada tier. |
| `default-lives` | `3` | Vidas de un tier que no aparece en `tier-lives`. |
| `core-health` | `150` | Salud del núcleo por vida. |
| `tool-damage` | tres picos | Daño de un golpe con cada objeto en la mano. |
| `default-damage` | `1` | Daño de cualquier otra cosa. |
| `hit-cooldown-millis` | `500` | Milisegundos que espera un jugador entre dos golpes a un núcleo. |
| `core-heal-seconds` | `30` | Segundos sin golpes antes de que un núcleo dañado se cure del todo. |
| `hit-sound` | `BLOCK_ANVIL_LAND\|0.4\|1.6` | Suena con cada golpe. |
| `lives-per-kill` | `1` | Vidas que quita un enemigo al matar a un miembro dentro. `0` lo apaga. |
| `kill-cooldown-minutes` | `10` | Minutos antes de que matar allí al mismo miembro vuelva a costar una vida. |
| `allies-are-friends` | `true` | Si los aliados de clan del dueño cuentan como amigos. |
| `raidable-minutes` | `30` | Minutos que una protección sigue asaltable tras perder su última vida. |
| `lives-after-raid` | `1` | Vidas que tiene cuando termina el asalto. |
| `cooldown-minutes` | `120` | Minutos tras un asalto durante los que no puede perder vidas. |
| `raidable-permissions` | `break`, `place`, `containers`, `doors`, `redstone`, `buckets` | Lo que pueden hacer los enemigos mientras es asaltable. También lo que puede hacer cualquiera en una protección abandonada. |
| `explosions-while-raidable` | `false` | Si las explosiones rompen bloques en una protección asaltable aunque su flag `explosions` esté apagada. |
| `regen-minutes` | `60` | Minutos para que vuelva a crecer una vida. `0` lo apaga. |
| `restore-price` | `5000.0` | Lo que cuesta recomprar una vida desde el menú. `0` lo apaga. |
| `restore-currency` | `''` | Su moneda; vacío es la moneda por defecto. |
| `allow-hidden-core` | `false` | Si se pueden ocultar los núcleos con los asaltos activados. Un núcleo oculto no se puede atacar. |
| `siege-windows.enabled` | `false` | Si solo se pueden perder vidas dentro de las ventanas. Apagado: a cualquier hora. |
| `siege-windows.timezone` | `''` | La zona horaria en la que se leen las ventanas, como `Europe/Madrid`. Vacío: la del servidor. |
| `siege-windows.windows` | sábado y domingo 18:00-22:00 | `DÍA HH:MM-HH:MM`, o `DAILY` para todos los días, con el día en inglés (`SATURDAY`). Una ventana que termina antes de empezar pasa la medianoche. |
| `offline-shield.enabled` | `true` | Si una protección no puede perder vidas mientras su dueño y todos sus miembros están desconectados. |
| `offline-shield.grace-minutes` | `10` | Minutos que espera el escudo después de que el último de ellos se desconecte en este servidor. |
| `offline-shield.clan-members-count` | `false` | Si los miembros de un clan añadido también cuentan como defensores. |

La barra de acción del golpe y la barra de jefe de asaltable están en `raids` de `messages.yml`.

### bank, upkeep y market

```yaml
bank:
  currency: ''
  max-balance: 0.0
upkeep:
  period-hours: 24
  tier-costs:
    small: 15.0
    medium: 40.0
    large: 100.0
  default-cost: 15.0
  cost-per-block: 0.0
  charge-owner: true
  grace-periods: 3
  inactive-days: 30
  abandoned-days: 3
  warn-hours: 12
  check-minutes: 10
  announce: false
market:
  currency: ''
  tax-percent: 5.0
  max-price: 500000.0
  keep-members: false
```

| Clave | Por defecto | Qué hace |
|---|---|---|
| `bank.currency` | `''` | La moneda que guardan los bancos y en la que se paga el mantenimiento. Vacío: la moneda por defecto. |
| `bank.max-balance` | `0.0` | Lo máximo que puede guardar un banco. `0` sin límite. |
| `upkeep.period-hours` | `24` | Horas entre dos pagos. |
| `upkeep.tier-costs` | small 15, medium 40, large 100 | Lo que cuesta un periodo por tier. |
| `upkeep.default-cost` | `15.0` | El coste de un tier que no aparece. |
| `upkeep.cost-per-block` | `0.0` | Se suma a cada periodo por bloque de área protegida. |
| `upkeep.charge-owner` | `true` | Si un dueño conectado en el servidor de la protección paga lo que su banco no cubre. |
| `upkeep.grace-periods` | `3` | Periodos sin pagar que abandonan una protección. |
| `upkeep.inactive-days` | `30` | Días sin que el dueño ni ningún miembro jueguen que la abandonan. `0` lo apaga. |
| `upkeep.abandoned-days` | `3` | Días que una protección abandonada queda abierta a todos antes de borrarse. |
| `upkeep.warn-hours` | `12` | Horas antes de un pago que el banco no puede cubrir en que se avisa a los miembros. |
| `upkeep.check-minutes` | `10` | Minutos entre dos revisiones de las protecciones de este servidor. |
| `upkeep.announce` | `false` | Si se anuncia a todos los que tienen activados los anuncios de asaltos que una protección ha quedado abandonada. |
| `market.currency` | `''` | La moneda en la que se venden las protecciones. |
| `market.tax-percent` | `5.0` | Porcentaje del precio que se cobra como impuesto; el vendedor recibe el resto. |
| `market.max-price` | `500000.0` | El precio más alto al que se puede poner a la venta una protección. `0` sin límite. |
| `market.keep-members` | `false` | Si los miembros, clanes y excepciones se mantienen cuando una protección cambia de dueño. |

Ver [Economía](/docs/exyliaprotections/economia).

### subregions, rent y upgrades

```yaml
subregions:
  max-per-protection: 3
  min-side: 3
  full-height: true
rent:
  whole-protection: false
  currency: ''
  max-price: 50000.0
  min-period-minutes: 60
  max-periods: 4
  tenant-role: tenant
  tenant-permissions:
  - break
  - place
  - containers
  - doors
  - redstone
  - buckets
  - animals
  - ride
  - decorations
  - trade
  - leash
  pay-to-bank: true
  owner-can-evict: false
  relist: true
upgrades:
  pay-from-bank: false
  currency: ''
  base-max-members: 8
  base-max-subregions: 2
  tiers:
    small:
      levels:
        '1':
          cost: 3000.0
          radius-bonus: 5
          max-members: 12
          max-subregions: 3
          bonus-lives: 1
          permission: ''
        '2':
          cost: 6000.0
          radius-bonus: 10
          max-members: 16
          max-subregions: 4
          bonus-lives: 2
          permission: ''
    medium: ...
    large: ...
```

| Clave | Por defecto | Qué hace |
|---|---|---|
| `subregions.max-per-protection` | `3` | Parcelas que puede tener una protección mientras las mejoras están apagadas. `0` sin límite. |
| `subregions.min-side` | `3` | El lado más corto que puede tener una parcela. |
| `subregions.full-height` | `true` | Si una parcela ocupa toda la altura de la protección, o solo la altura seleccionada. |
| `rent.whole-protection` | `false` | Si se pueden alquilar protecciones enteras, no solo sus parcelas. |
| `rent.currency` | `''` | La moneda en la que se paga el alquiler. |
| `rent.max-price` | `50000.0` | El alquiler más alto por periodo. `0` sin límite. |
| `rent.min-period-minutes` | `60` | El periodo más corto que puede tener una oferta. |
| `rent.max-periods` | `4` | Los periodos que un inquilino puede pagar de una vez como máximo, renovaciones incluidas. |
| `rent.tenant-role` | `tenant` | El rol que tienen los inquilinos. Una protección que no lo tiene lo recibe, con `tenant-permissions`. |
| `rent.tenant-permissions` | construir y usar | Con lo que empieza ese rol. |
| `rent.pay-to-bank` | `true` | Si el alquiler va al banco de la protección cuando los bancos están activados y la moneda coincide. Si no, va al dueño. |
| `rent.owner-can-evict` | `false` | Si se puede desalojar antes de tiempo a un inquilino; quien desaloja devuelve el tiempo que queda. |
| `rent.relist` | `true` | Si una parcela se vuelve a ofrecer, en las mismas condiciones, cuando termina su alquiler. |
| `upgrades.pay-from-bank` | `false` | Si el banco paga las mejoras cuando los bancos están activados y la moneda coincide. Si no, paga el dueño. |
| `upgrades.currency` | `''` | La moneda en la que cuestan las mejoras. |
| `upgrades.base-max-members` | `8` | Miembros (jugadores y clanes) que admite una protección antes de cualquier mejora. `0` sin límite. |
| `upgrades.base-max-subregions` | `2` | Parcelas que admite antes de cualquier mejora. `0` sin límite. |
| `upgrades.tiers.<tier>.levels.<n>` | dos niveles por tier | Cada nivel desde `1`: su `cost`, los totales de `radius-bonus` y `bonus-lives` en ese nivel, sus `max-members` y `max-subregions` (`0` sin límite), y un `permission` necesario para alcanzarlo (vacío para ninguno). |

Niveles de serie: small 3000 / 6000, medium 8000 / 16000, large 20000 / 40000, cada uno sumando 5 y luego 10
bloques de radio y 1 y luego 2 vidas. Ver [Herramientas](/docs/exyliaprotections/herramientas).

### warps, visualization y effects

```yaml
warps:
  name-max-length: 24
  description-max-length: 64
  hide-unavailable: true
  default-icon: LODESTONE
visualization:
  seconds: 10
  particle: END_ROD
  plot-particle: WAX_OFF
  show-on-create: true
  bluemap: true
  dynmap: true
  map-refresh-minutes: 5
  map-colors:
    normal: '#8a51c4'
    for-sale: '#8fffc1'
    for-rent: '#59a4ff'
    raidable: '#a33b53'
    abandoned: '#6c757d'
effects:
  tenants: false
  fall-protection-seconds: 5
  no-flight-during-siege: true
  potions:
    night-vision: NIGHT_VISION 0
    haste: HASTE 0
    speed: SPEED 0
    jump-boost: JUMP_BOOST 0
  tiers:
    small:
      levels:
        '0':
          perks:
          - night-vision
        '1':
          perks:
          - haste
          - no-hunger
        '2':
          perks:
          - speed
          - fly
    medium: ...
    large: ...
```

| Clave | Por defecto | Qué hace |
|---|---|---|
| `warps.name-max-length` | `24` | El nombre más largo que puede tener un warp. |
| `warps.description-max-length` | `64` | La descripción más larga. |
| `warps.hide-unavailable` | `true` | Si se ocultan a un jugador los warps en los que ahora no puede entrar (cerrados, baneado, asaltables, abandonados). Apagado: aparecen, y la visita se rechaza. |
| `warps.default-icon` | `LODESTONE` | El icono con el que empieza un warp nuevo. |
| `visualization.seconds` | `10` | Segundos que se queda dibujado un borde. |
| `visualization.particle` | `END_ROD` | La partícula que dibuja el borde de una protección. |
| `visualization.plot-particle` | `WAX_OFF` | La partícula que dibuja el borde de una parcela. |
| `visualization.show-on-create` | `true` | Si se dibuja el borde a quien protege terreno nuevo. |
| `visualization.bluemap` | `true` | Si las protecciones se dibujan en BlueMap, cuando está instalado. |
| `visualization.dynmap` | `true` | Lo mismo para Dynmap. |
| `visualization.map-refresh-minutes` | `5` | Minutos entre dos redibujados de todos los marcadores, que recogen ventas, alquileres y asaltos. |
| `visualization.map-colors` | cinco estados | Colores de los marcadores por estado, en hex: los mapas web no leen tokens de color. Un estado que falta o está mal escrito usa `normal`. |
| `effects.tenants` | `false` | Si los inquilinos reciben las ventajas de lo que alquilan, no solo los miembros. |
| `effects.fall-protection-seconds` | `5` | Segundos sin daño de caída para un jugador que deja de volar. |
| `effects.no-flight-during-siege` | `true` | Si el vuelo se corta mientras una protección está bajo asedio o es asaltable. |
| `effects.potions` | cuatro pociones | Ventajas de poción: una clave a tu elección a `EFECTO amplificador`, con el amplificador contando desde 0. |
| `effects.tiers.<tier>.levels.<n>.perks` | por tier | Las ventajas que desbloquea cada nivel, desde el nivel `0`. Un nivel tiene todas las ventajas de los niveles inferiores. Ventajas: `fly`, `no-hunger`, `keep-inventory` y las claves de `potions`. |

Ver [Warps](/docs/exyliaprotections/warps) y [Herramientas](/docs/exyliaprotections/herramientas).

### import y cleanup

```yaml
import:
  tier-map: {}
  default-tier: small
  owner-role: trusted
  member-role: member
  remove-source-regions: false
cleanup:
  default-days: 30
  skip-with-tenants: true
  skip-with-bank: false
  batch-size: 20
```

| Clave | Por defecto | Qué hace |
|---|---|---|
| `import.tier-map` | `{}` | Bloque de ProtectionStones (su `ps-block-material`, como `EMERALD_ORE`) al tier en que se convierte. Un bloque que no aparece se convierte en el tier que se coloca con el mismo bloque, o si no en `default-tier`. |
| `import.default-tier` | `small` | El tier para los bloques que no coinciden con nada. Vacío se salta esas regiones. |
| `import.owner-role` | `trusted` | El rol que reciben los dueños aparte del primero. |
| `import.member-role` | `member` | El rol que reciben los miembros. |
| `import.remove-source-regions` | `false` | Si cada región importada se borra de WorldGuard, para que deje de aplicar sus antiguos dueños y miembros. Haz primero la importación con `--dry-run`. |
| `cleanup.default-days` | `30` | Los días que el botón de limpieza propone primero. |
| `cleanup.skip-with-tenants` | `true` | Si se conservan las protecciones que tienen ahora un inquilino. |
| `cleanup.skip-with-bank` | `false` | Si se conservan las protecciones cuyo banco tiene dinero. Apagado: el dinero se paga al dueño. |
| `cleanup.batch-size` | `20` | Protecciones borradas por tick mientras corre una limpieza. |

Ver [Migración](/docs/exyliaprotections/migracion) y [Administración](/docs/exyliaprotections/administracion).

### roles

Los roles con los que empieza una protección **nueva**. Después cada protección guarda su propia copia, que
se edita desde su menú; cambiar esta sección no toca las protecciones existentes.

```yaml
roles:
  member:
    permissions: [break, place, containers, doors, redstone, buckets, animals, ride, decorations, trade, leash, bank-deposit]
  trusted:
    permissions: [break, place, containers, doors, redstone, buckets, animals, ride, decorations, trade, leash, manage-members, set-home, bank-deposit]
  visitor:
    permissions: []
```

`visitor` es todo el que no es miembro. Permisos: `break`, `place`, `containers`, `doors`, `redstone`,
`buckets`, `animals`, `ride`, `decorations`, `trade`, `leash`, `manage-members`, `manage-roles`,
`edit-flags`, `rename`, `set-home`, `manage-core`, `manage-bans`, `toggle-lock`, `view-logs`,
`bank-deposit`, `bank-withdraw`, `manage-subregions`, `manage-rent`, `manage-warp`, `edit-environment`. Una
clave desconocida se ignora. Ver [Personas y acceso](/docs/exyliaprotections/personas-y-acceso).

### tiers

Los núcleos de protección que se venden y se dan, por id de tier. Vienen tres: `small` (`AMETHYST_BLOCK`,
radio 10, 2500), `medium` (`PURPUR_BLOCK`, radio 20, 10000) y `large` (`CRYING_OBSIDIAN`, radio 35, 40000).

```yaml
tiers:
  small:
    material: AMETHYST_BLOCK
    name: '{primary}&lPROTECTION CORE &8[{info}SMALL&8]'
    lore: [...]
    radius: 10
    height: FULL
    y-radius: 10
    price: 2500.0
    currency: ''
    permission: ''
    limit: 0
    flags: [mob-spawning, crop-growth, leaf-decay, liquid-flow, visitor-entry]
```

| Clave | Qué hace |
|---|---|
| `material` | El bloque del núcleo. |
| `name`, `lore` | El nombre y la descripción del objeto del núcleo. |
| `radius` | Bloques protegidos alrededor del núcleo hacia cada lado. |
| `height` | `FULL` protege toda la columna; `CUBOID` solo `y-radius` bloques por encima y por debajo del núcleo. |
| `y-radius` | La altura que usa `CUBOID`. |
| `price` | Su precio en la tienda. `0` lo deja fuera de la tienda. |
| `currency` | Su moneda; vacío es la moneda por defecto. |
| `permission` | Necesario para colocarlo, comprarlo o recibir uno; vacío para ninguno. |
| `limit` | Cuántas de este tier puede tener un jugador. `0` sin límite propio. |
| `flags` | Las flags que empiezan activadas. Flags: `pvp`, `mob-spawning`, `explosions`, `fire-spread`, `liquid-flow`, `crop-growth`, `leaf-decay`, `visitor-entry`. |

Los tiers también se editan en el juego desde el editor de tiers del menú de administración, que escribe esta
sección junto con las vidas y el coste de mantenimiento del tier. Ver
[Administración](/docs/exyliaprotections/administracion).

## messages.yml

`lang/<idioma>/messages.yml` contiene cada línea que envía el plugin. El idioma es el que esté puesto en el
`config.yml` de ExyliaLib: a diferencia de la mayoría de plugins de Exylia, el `config.yml` de
ExyliaProtections no tiene clave `language` propia. `es`, `pt` y `fr` vienen traducidos; el inglés se escribe a
partir de los valores por defecto del plugin, y una línea que una traducción no incluye llega en inglés.

Las claves de primer nivel son líneas de chat, preguntas y las palabras que muestran los menús, como los
estados de asalto y de alquiler. Después vienen las secciones:

| Sección | Qué contiene |
|---|---|
| `utility` | Warps, bordes, ventajas, hora y clima, fusiones. |
| `utility.admin` | El menú de administración, el editor de tiers, la limpieza y la importación de ProtectionStones. |
| `utility.notices` | Rechazos y confirmaciones, las líneas de `/protections help`, y `labels`: los nombres y descripciones de cada permiso de rol y flag, de las acciones del registro y de las ventajas. |
| `raids` | La barra de acción del golpe al núcleo y la barra de jefe de asaltable. |
| `enter-leave` | Los títulos y barras de acción al entrar y salir. `%message%` es el saludo o la despedida del dueño, o el de por defecto. |
| `visualization` | La etiqueta de los marcadores y el nombre de la capa en BlueMap y Dynmap. Texto plano: los mapas web no leen tokens de color. |
| `general` | Líneas compartidas por todas las partes del plugin. |

Los colores usan tokens de la paleta como `{primary}`, `{error}` o `{highlight}`, así que recolorear el
servidor nunca obliga a editar este archivo. `%prefix%` se sustituye por el valor `prefix` de arriba. Una
línea puede empezar con una etiqueta de efecto que nunca llega a la pantalla: `[sound:NOMBRE|volumen|tono]`
reproduce un sonido a quien la recibe. Los valores que puede usar cada línea están en el comentario de
encima.

`general.reloaded` nunca se envía: no hay comando de recarga.

## Menús

| Carpeta | Qué contiene |
|---|---|
| `lang/<idioma>/menus/user/` | Las pantallas de los jugadores: el menú principal, la lista, la vista de una protección y sus siete secciones, miembros, roles, permisos, tienda, baneos, registros, mercado, parcelas, alquiler, warps, ventajas, fusión. Tuyas para cambiarles el estilo; una actualización solo añade los archivos que faltan. |
| `lang/<idioma>/menus/admin/` | Las pantallas del staff: búsqueda, una protección, tiers, un tier, limpieza. Se reescriben desde el jar en cada arranque; lo que se edite ahí se pierde. |

Un archivo de menú que no se puede leer se nombra en la consola y se deja fuera, en vez de abrirse vacío. Ver
[Menús](/docs/exyliaprotections/menus) para cada archivo y las acciones que ejecutan sus botones.

## Base de datos

`database.yml` es el de ExyliaLib: H2 por defecto, o `mysql`, `mariadb`, `postgresql` y `mongodb`. Ver la
[página de base de datos de la librería](/docs/exylialib/base-de-datos) para cada clave. Los servidores que
comparten una base de datos comparten sus protecciones.

Las tablas del plugin son `protections`, `protections_accounts`, `protections_listings`,
`protections_rent_offers`, `protections_logs`, `protections_seen`, `protections_warps`,
`protections_warp_ratings`, `protections_warp_visits` y `protections_warp_totals`, más la tabla de ExyliaLib
de objetos pendientes de entregar.
