`ProtectionsService` responde las preguntas que otros plugins hacen sobre el terreno: si este punto está
dentro de una protección, si este jugador puede construir, romper o usar bloques allí, y si esa protección
impide volar ahora mismo.

```java
boolean claimed = ExyliaAPI.get(ProtectionsService.class)
        .map(protections -> protections.protectionAt(location).isPresent())
        .orElse(false);
```

<Callout type="note" title="Añadirla a tu proyecto">
El artefacto, el repositorio y la línea de `plugin.yml` son los mismos para todos los plugins de Exylia y
están en la [página de la API pública](/docs/exylialib/api). El contrato de protecciones llegó en la API
pública **1.9.0**, que viene con ExyliaLib **1.238.0**, en el paquete `net.exylia.lib.api.protections`.
</Callout>

Un `Optional` vacío de `ExyliaAPI.get` significa que el servidor no tiene ExyliaProtections. El servicio se
registra cuando el plugin ha arrancado y desaparece cuando se desactiva.

## Métodos

| Método | Qué hace |
|---|---|
| `Optional<String> protectionAt(Location location)` | El id de la protección cuyo terreno contiene ese punto, o vacío si ninguna lo cubre. |
| `boolean canBuild(Player player, Location location)` | Si el jugador puede colocar bloques allí: el permiso de rol `place`, como lo deciden los listeners de bloques. `true` fuera de toda protección. |
| `boolean canBreak(Player player, Location location)` | Lo mismo para romper, con el permiso de rol `break`. |
| `boolean canInteract(Player player, Location location)` | Lo mismo para usar un bloque, con el permiso de rol `containers`. |
| `boolean deniesFlight(Location location)` | Si hay que cortar el vuelo en ese punto: `submodules.raids` y `effects.no-flight-during-siege` están activados y la protección de allí está bajo asedio o asaltable. Con los asaltos apagados siempre responde `false`. |

Todos leen las protecciones que este servidor tiene cargadas en memoria, sin tocar la base de datos. Justo
después de un reinicio, antes de que las protecciones terminen de cargar, `protectionAt` no encuentra
ninguna, y los tres métodos `can` lo rechazan en los mundos donde se puede proteger terreno, salvo a un
jugador con el bypass.

Los tres métodos `can` llegaron con ExyliaLib **1.432.0** y son lo que preguntan las zonas de construcción de
ExyliaLib, así que cualquier plugin de Exylia que compruebe si un jugador puede construir en un punto respeta
las protecciones sin código propio. No avisan al jugador; díselo tú cuando lo rechaces.

El id es una cadena opaca. Guárdalo para comparar dos respuestas; no lo analices ni se lo enseñes a los
jugadores.

`deniesFlight` es lo que pregunta el `/fly` de ExyliaSurvivalCore antes de dejar volar a un jugador, y una
vez por segundo para todos los que ya vuelan. Úsalo igual para cualquier vuelo propio.

## Lo que no hay

El servicio es de solo lectura y deliberadamente pequeño. No hay ningún método para crear, borrar o editar
una protección ni leer sus miembros, roles, flags o banco; y el plugin no lanza eventos propios. Los placeholders cubren las lecturas que quieren la
mayoría de integraciones: ver [Placeholders](/docs/exyliaprotections/placeholders).
