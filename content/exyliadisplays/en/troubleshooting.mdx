Find your symptom, then follow the fix.

## The plugin does not start

ExyliaDisplays needs **packetevents** and **ExyliaLib**. Without packetevents it does not load at all. Without ExyliaLib it starts, tells the console where to download it and stays off until you install it and restart. It never downloads anything itself. See [Installation](/docs/exyliadisplays/installation).

## I cannot open /holoadmin or /npcadmin

You need `exyliadisplays.holograms` for holograms or `exyliadisplays.npcs` for NPCs (`exyliadisplays.admin` gives both). Operators have them by default. See [Permissions](/docs/exyliadisplays/permissions).

If the command says it does not exist, the module is switched off: run `/displaysadmin modules`. A change of `modules` in `config.yml` needs a restart.

## A hologram or NPC does not show

- It is disabled: run `/holo <name> enable` or `/npc <name> enable`.
- You are too far away: raise its view distance with `/holo <name> viewdistance <blocks>` or `/npc <name> viewdistance <blocks>`.
- It has a permission or a viewer list that leaves you out. See [Visibility and attaching](/docs/exyliadisplays/visibility).
- It is in another world than you think: `/holoadmin near` and `/npcadmin near` list the ones around you.

## /npc opens Citizens instead

Both plugins register `/npc`. Use `/npcs <name>` or `/exylianpc <name>`; `/npcadmin` never clashes. After you [import your Citizens NPCs](/docs/exyliadisplays/migration) and remove Citizens, `/npc` works again.

## A placeholder shows as written

- **In a hologram**: PlaceholderAPI and the expansion that owns the placeholder must be installed. A hologram with a placeholder is drawn per viewer.
- **In an NPC label**: labels are drawn once for everybody, so player placeholders are not filled per viewer. Put a hologram above the NPC with `/npc <name> link <hologram>` instead.
- **In a click action such as `[SAY]`**: placeholders resolve for the player who clicked.
- **A leaderboard placeholder**: check the stat id exists in `leaderboards.yml` and that the leaderboards module runs. See [Placeholders](/docs/exyliadisplays/placeholders).

## An NPC does nothing when clicked

Set `debug: true` in `config.yml`, run `/displaysadmin reload` and click it. The console says whether the click ran, was ignored (no line answers that click, for example a sneaking click on `left:` lines), was denied by `interactions.permission`, or is cooling down. A line the plugin could not understand is reported once, when the NPC is loaded. See [Interactions](/docs/exyliadisplays/interactions).

## Holograms or NPCs disappeared after I edited the file

The file no longer parses (indentation, an unclosed quote). A file that cannot be read is taken as empty, so everything in it disappears until it is fixed. The console says so and admins online get the mistakes message. Fix the YAML and save again; `/holo <name> undo` also puts back a hologram's previous state. See [Edit the files](/docs/exyliadisplays/editing-files#mistakes).

## Every hologram shows twice

ExyliaHolograms is still installed next to ExyliaDisplays. Remove the old jar. See [Migration](/docs/exyliadisplays/migration).

## A linked hologram stopped following its NPC

The hologram was renamed or deleted and the NPC still names the old one. Link it again with `/npc <name> link <hologram>`. See [NPCs](/docs/exyliadisplays/npcs#a-linked-hologram).

## An animated NPC flashes between loops

The clip does not loop. Set the clip to loop in Blockbench, or write the line `loop:true;anim:<clip>`. `/npcadmin animations` says which clips loop. See [NPCs](/docs/exyliadisplays/npcs).
