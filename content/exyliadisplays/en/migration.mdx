## From ExyliaHolograms

ExyliaDisplays is ExyliaHolograms renamed, now that it does NPCs too.

<Steps>
  <Step title="Swap the jar">
    Put `ExyliaDisplays.jar` in `plugins/` and remove the ExyliaHolograms jar. If both stay, both draw
    every hologram; the console warns while the old one is installed.
  </Step>
  <Step title="Start the server">
    On its first start, `plugins/ExyliaHolograms/holograms.yml` is **copied** to
    `plugins/ExyliaDisplays/holograms.yml`. The old folder is left untouched, so putting the old jar
    back loses nothing. The copy only happens while `plugins/ExyliaDisplays/holograms.yml` does not
    exist yet.
  </Step>
  <Step title="Keep the permission">
    `exyliaholograms.admin` still works: it grants `exyliadisplays.holograms`.
  </Step>
</Steps>

The commands changed home: `/holo` and `/holoadmin` are the same, and `/displays` is new.

## From other plugins

```text
/holoadmin import <decentholograms|holographicdisplays|fancyholograms> [replace]
/npcadmin import <citizens|fancynpcs> [replace]
```

The other plugin's files are **read and never changed**, so trying an import costs nothing: the old
plugin keeps working until you remove it. Its folder is looked for next to this one's, under
`plugins/`, and the plugin itself does not need to be running.

| Source | Reads |
|---|---|
| DecentHolograms | `plugins/DecentHolograms/holograms/*.yml`, the 2.10 display holograms in `displays/`, and its `config.yml` for defaults and symbols. |
| HolographicDisplays | `plugins/HolographicDisplays/database.yml`. |
| FancyHolograms | `plugins/FancyHolograms/`: the 2.x YAML and the 3.x JSON holograms. |
| Citizens | `plugins/Citizens/saves.yml`. |
| FancyNpcs | `plugins/FancyNpcs/npcs.yml`. |

The reply tells how many came across and how many were skipped. With nothing found, it names the folder
it looked in.

### Names

Names are made usable here: lowercased, with spaces and symbols turned into `_`, cut to 32 characters. A
name already taken gets `_2`, `_3`… so an import never overwrites what you have. The suffix is added after
the cut, so a long name that collides can end up a little over 32 characters; it still works, but
`rename` it if you want to type it.

`replace` overwrites instead: an entry with the same name is replaced. Use it to run the same import
again after fixing something in the source, rather than getting copies next to the first import.

### What comes across

**Holograms**: text, item and head lines, pages, colours and placeholders, animations where a line tag
matches, places, view distances, permissions, click actions and display settings (billboard, scale,
background, shadow, see-through, brightness, glow, opacity, refresh).

**NPCs**: place and facing, whether it is shown, skin, the name and lines above it, pose, size, glow, held
and worn items, turning to players, who sees it, and click actions with their cooldown.

What has no counterpart is left out:

- entity lines (a mob standing in a hologram), a line's sideways offset or own facing, and custom or
  scrolling animations;
- a DecentHolograms hologram's placement is adjusted: there the location is the top line's, here it is the
  bottom's, so the top lines up where it was;
- a click action behind a permission check, a price or a use limit is **left out** rather than run for
  everyone, and so is everything after a DecentHolograms `PERMISSION` action;
- a head drawn per viewer or from HeadDatabase stays a plain head;
- a non-player NPC (a Citizens zombie, a FancyNpcs villager) is skipped, not imported as a person.

<Callout type="tip" title="Import NPCs before holograms">
A FancyHolograms hologram that stood over an NPC is linked to the NPC of that name here — but only if the
NPC is already imported. Run `/npcadmin import fancynpcs` (or `citizens`) first, then
`/holoadmin import fancyholograms`.
</Callout>

### After an import

Check a few of them in game, then remove the old plugin. If something looks off, fix it in the source and
run the import again with `replace`, or delete the entries and import again.
