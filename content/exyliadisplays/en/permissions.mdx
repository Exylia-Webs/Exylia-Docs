Players need no permission to see holograms and NPCs or to click them. The nodes below are for staff who build them; the permissions you set on each hologram or NPC restrict who sees or uses it.

## All permissions

Every node is declared in `plugin.yml` and defaults to operators.

<Permissions />

There is no split between viewing and editing: whoever can open a hologram's editor can change or delete it, and the same goes for NPCs.

Give a node with your permission plugin, for example LuckPerms. A staff group that edits holograms but not NPCs:

```text
/lp group builder permission set exyliadisplays.holograms true
```

## Permissions you set on a hologram or NPC

| Where | Set with | Effect |
|---|---|---|
| A hologram's `permission` | `/holo <name> permission <node>` | Only players with it see the hologram. |
| A line's `<perm:node>` / `<perm:!node>` | `/holo <name> line <n> permission <node>` | Only players with (or without) it see that line. |
| An NPC's `permission` | `/npc <name> permission <node>` | Only players with it see the NPC and its label. |
| An NPC's `interactions.permission` | `/npc <name> action permission <node>` | Everyone sees it; only players with the node can use it. The rest get the refusal message. |

These are any node you choose; nothing has to declare them. A hologram's clicks have no permission of their own: use the hologram's `permission`, a `<perm>` line, or gate the command the click runs.

An NPC only VIPs can use, visible to everyone:

```text
/npc vip_shop action permission group.vip
/npc vip_shop action denymessage {error}This shop is for VIPs.
```
